# استعادة الشيفرة الأصلية والمصادر في iOS

[← فهرس التوثيق](README.md) · [نظرة عامة على الأجهزة المحمولة](../mobile.md)

يقبل `neverd mobile` مدخلات IPA و`.app` وMach-O، ويصدر C أصلياً وبيانات وقت التشغيل، إضافة إلى مصادر Objective-C بصيغة `.m` وSwift بصيغة `.swift` بصورة تجريبية للأجسام الأصلية المدعومة. قد تتضمن النتيجة المنشورة طرائق لم تُستعد؛ راجع تقرير التغطية قبل الاستخدام. معالجة الحاويات المحمولة تخص CLI، بينما يحمل SDK الأصلي بلغة C ملف Mach-O المحدد بصورة منفصلة.

يزيل التجميع التعليقات والتنسيق والمعرّفات وبنى اللغة المصدرية. يعيد هذا المسار بناء تمثيل مصدري، ولا يسترجع النص الأصلي أو يثبت تكافؤ سلوك تطبيق عشوائي. كما أنه لا يشغل التطبيق الجاري تحليله.

## البدء والاعتماديات

```sh
cmake --build build --target neverd
python3 --version
neverd mobile App.ipa -o recovered-ios
neverd mobile App.app -o recovered-arm64 --arch=arm64
neverd mobile executable -o metadata --metadata-only
neverd mobile App.app -o recovered-framework --artifact Frameworks/Example.framework/Example
```

ابنِ NeverD بالطريقة المعتادة واحتفظ بدليل `mobile/` المجاور عند توزيع الملف التنفيذي. يلزم Python 3.10+، بالترتيب `--python PATH` ثم `NEVERD_PYTHON` ثم `python3`/`python` في PATH. لا تُنزّل الاعتماديات تلقائياً. تحتاج إعادة تجميع المصادر المولدة للغات Apple بصورة مستقلة على macOS إلى Apple Clang وSDK وأدوات Swift؛ وهذه متطلبات منفصلة عن التحليل الأصلي الساكن.

تختار استعادة تواقيع Swift الأداة من `--swift-demangle PATH`، ثم `NEVERD_SWIFT_DEMANGLE`، ثم `swift-demangle` في PATH. على macOS تكون المحاولة التلقائية الأخيرة `xcrun --find swift-demangle` بمهلة محدودة. غياب أداة محددة صراحة يؤدي إلى الفشل، بينما فشل البحث التلقائي يبقي الرموز غير مصنفة ويبلغ `unavailable`. لا يلزم demangler إذا لم توجد رموز Swift. لا يستدعي `--metadata-only` الخلفية الأصلية أو demangler.

```sh
neverd mobile App.ipa -o recovered-swift \
  --python python3 --swift-demangle /path/to/swift-demangle --timeout=600 --json
```

## المدخلات والاختيار

يجب أن تحتوي IPA على `Payload/*.app` واحد بالضبط في المستوى الأعلى. يحدد `CFBundleExecutable` في `Info.plist` البرنامج الرئيسي لكل من IPA و`.app`. يكون `--artifact` نسبياً إلى حزمة التطبيق في الصيغتين، ويختار ملفاً تنفيذياً مضمناً واحداً، دون تحليل جميع frameworks والامتدادات تكرارياً. لا يقبل إدخال Mach-O المباشر الخيار `--artifact`.

للملفات fat، يفضل `--arch=auto` الترتيب arm64 ثم arm ثم x86_64 ثم i386. تفشل الشرائح الغائبة أو غير المدعومة بوضوح. يستهدف إخراج اللغة المصدرية حالياً arm64/x86_64؛ اختيار معمارية أخرى لا يعني دعم Objective-C/Swift. تُرفض الشريحة المحددة إذا كان `cryptid != 0`؛ قدم مدخلاً مقروءاً فُك تشفيره مسبقاً. ترفض الأرشيفات والأدلة المسارات الخطرة والروابط الرمزية والملفات الخاصة والمدخلات المتعارضة.

## الخيارات وحدود الموارد

| الخيار | الافتراضي | المعنى |
|--------|-----------|--------|
| `-o DIRECTORY` | مطلوب | دليل جديد خارج دليل الإدخال؛ يُحفظ الإخراج الموجود |
| `--platform=auto\|ios` | `auto` | استنتاج المنصة أو اختيار iOS |
| `--arch=auto\|arm64\|arm\|x86_64\|i386` | `auto` | اختيار شريحة Mach-O واحدة |
| `--artifact PATH` | البرنامج الرئيسي | مسار تنفيذي نسبي إلى التطبيق |
| `--metadata-only` | معطل | قراءة البيانات الوصفية دون استعادة المصدر أو استدعاء أدوات |
| `--max-func N` | `0` | حد الدوال الأصلية؛ الصفر يعني جميع المكتشفة؛ يُتجاهل في وضع البيانات الوصفية |
| `--python PATH` | البيئة/PATH | مفسر Python 3.10+ للمساعد |
| `--swift-demangle PATH` | البيئة/PATH/الأدوات | أداة تحليل أسماء تواقيع Swift |
| `--timeout N` | `300` | عدد موجب من الثواني لكل عملية خلفية |
| `--max-files N` | `20000` | ميزانية موجبة للمدخلات؛ قائمة رموز Swift محدودة أيضاً |
| `--max-bytes N` | `2147483648` | ميزانية بايتات موجبة للإدخال والاستخراج والإخراج النهائي |
| `--json` | معطل | طباعة تقرير JSON ذي إصدار |

تُراقب مساحة العمل، ويُسمح بما يصل إلى ثلاثة أضعاف ميزانيتي المدخلات والبايتات للنسخ المؤقتة والنتائج الوسيطة. تُحد السجلات بـ16 MiB لكل عملية، وJSON تواقيع Swift بـ32 MiB إضافياً. هذه ضوابط موارد وليست عزلاً للعمليات. زيادة المهلة لا تلغي الحدود الأخرى. تبقى الطرائق المستبعدة بسبب `--max-func` غير مستعادة إذا كانت موجودة في قائمة البيانات الوصفية.

## مصدر Objective-C وبنية وقت التشغيل

يربط المحمل الأصلي سجل الطريقة وعنوان IMP القابل للتنفيذ وترميز النوع المدعوم بمواضع ABI مصدرية صريحة. تحافظ معاملات القيم المفردة والمؤشرات الثابتة على `self`/`_cmd` المخفيين والمعاملات غير المستخدمة ومجموعات سجلات الأعداد الصحيحة والعائمة المنفصلة ومواضع المكدس المدعومة. إعادة تفسير بتات float/double منفصلة عن التحويل العددي. تلميحات الأنواع مدخلات لإخراج المصدر، وليست أدلة ABI موثقة أو إذناً بتعديل الشيفرة التنفيذية.

يضع `sources/objc.m` العبارات المستعادة فعلياً في أجسام `@implementation`، ويحفظ مساعدات C والاستدعاءات ذات الأنواع اللازمة. تحتاج أهداف الاستدعاء إلى ارتباط مصدري مدعوم؛ تبقى الأهداف المجهولة ومجموعات الاعتماديات الناقصة غير مستعادة. لا تتحول التعريفات المفقودة والعناوين غير التنفيذية والترميزات المتضاربة وABI غير المدعوم وفك الترميز الناقص وIR المرفوض إلى طرائق مستعادة لمجرد وجود تصريح.

تحفظ بيانات الصنف هوية الصنف الأب وبداية الكائن وحجمه وivars القيم المفردة والمؤشرات مع تحقق الإزاحات والأحجام والمحاذاة، وتضيف التصريحات الحشو اللازم. تبقى الطريقة التي تحتاج تخطيط كائن مجهول غير مستعادة. تحافظ الفئات الإضافية على هويات الصنف/الفئة/العنوان والتنفيذ المنفصل؛ السجلات المتطابقة تماماً المكررة بين القائمتين تُحسب مرة واحدة. تستخدم الفئات الخارجية المدعومة تصريحات Foundation الموجودة. تُبلغ الترويسات الخارجية المجهولة كاعتماديات ناقصة، دون اختراع تخطيط صنف بديل.

إعادة بناء معلومات وقت التشغيل محدودة. لا توجد وعود باستعادة الخصائص والبروتوكولات كاملة أو تعليقات الملكية الأصلية أو الأنواع التجميعية الاعتباطية أو ذيول المعاملات المتغيرة أو الأجسام المعتمدة على الاستثناءات أو تخطيطات Block والالتقاط غير الممثلة. يصف الترميز المعاملات الثابتة ولا يثبت غياب نقاط الحذف في التصريح الأصلي. تُستخدم المؤشرات المتسلسلة فقط للمواضع التي حلها المحمل، مع إبقاء تشخيصات الصيغ الأخرى.

## مصدر Swift والتخزين

يفصل خرج demangler المنظم بين التواقيع القابلة للاستدعاء والبيانات غير القابلة له. قبل إخراج الجسم الأصلي تُربط التواقيع المدعومة برموز الملف المختار ومداخله وABI آلة صريح. تتبع مستقبلات Swift قواعد Swift ABI ولا تُستبدل بمعاملات Objective-C المخفية. ملف التواقيع المقدم من المستخدم يظل تلميحاً يحتاج تحققاً.

يمكن للمصدر التجريبي إنشاء الدوال الحرة وطرائق الأصناف والمهيئات المعينة وطرائق struct ذات التخطيط الثابت المدعومة، ومنها أشكال mutating الممثلة. تحتاج تصريحات الأصناف والبنى والحقول المخزنة إلى بيانات تخطيط مستعادة. لا تُصدر الاستدعاءات الأصلية إلا إذا شكلت التصريحات والأجسام المطلوبة مجموعة اعتماديات كاملة ومدعومة. تجمع وحدات المصدر التصريحات والطرائق معاً دون جسر يستدعي الملف الثنائي الأصلي.

تبقى التخطيطات العامة أو resilient ودوال async/throwing واتفاقيات الاستدعاء المجهولة وأشكال accessor/allocator/thunk غير المدعومة والتهيئة الناقصة والاعتماديات الأصلية أو التشغيلية غير المرتبطة `unrecovered` بصورة فردية. الرمز المشوه الاسم أو اسم النوع وحده ليس طريقة مستعادة. تجعل الرموز المحذوفة وعقد demangler غير المصنفة التغطية ناقصة أو مجهولة.

## الإخراج والتغطية

```text
recovered-ios/
  artifacts/selected.macho
  sources/native.c
  sources/objc.m
  sources/swift.swift
  metadata/objc.h
  metadata/objc.json
  metadata/objc-methods.json
  metadata/swift.json
  metadata/swift-signatures.json
  metadata/swift-methods.json
  logs/
  report.json
```

توجد ملفات اللغة المصدرية فقط إذا أمكن إخراج الشيفرة. يحتوي `objc.json` على الأصناف والفئات وivars والترميزات الخام، و`objc.h` على التصريحات المدعومة. يحوي `swift.json` بيانات الأنواع الاسمية والرموز المشوهة الأسماء. تحفظ ملفات JSON للتواقيع والطرائق التصنيف والحذف والأسباب والعدادات. تشمل السجلات التشخيص الأصلي، وعند استخدامها، البحث عن أدوات Swift وتحليل الأسماء والتصدير الأصلي لـSwift. المسارات في `report.json` نسبية إلى دليله. الملف الثنائي المحدد ناتج تحليل، ولا تربطه المصادر المولدة كجسر استعادة.

تُحذف نسخ الحزمة المؤقتة وتقارير JSON الوسيطة. يفشل التشغيل العادي دون أجسام دوال أصلية حتى لو توفرت بيانات وصفية. ينتج وضع البيانات الوصفية الملف المختار و`objc.h` و`objc.json` و`swift.json` و`report.json` فقط، دون مصادر أو ملفات تواقيع وتغطية، وتكون `native_function_count` و`objc_method_recovery` و`swift_method_recovery` بقيمة `null`. لا يحل قارئ Objective-C المكتوب بـPython المؤشرات المتسلسلة أو مؤشرات الكائنات القابلة لإعادة التموضع. تستخدم الاستعادة الكاملة بيانات المحمل الأصلي المحلولة. قد يظل قارئ Swift الخام يبلغ المراجع غير المدعومة كاستعادة جزئية.

يوضح المثال المختصر التالي استعادة جزئية عمداً:

```json
{
  "schema_version": 1,
  "status": "success",
  "platform": "ios",
  "architecture": "arm64",
  "objc_method_recovery": {
    "status": "partial",
    "method_count": 3,
    "recovered_method_count": 2,
    "unrecovered_method_count": 1
  },
  "swift_method_recovery": {
    "status": "partial",
    "coverage_status": "partial",
    "method_count": 4,
    "recovered_method_count": 2,
    "unrecovered_method_count": 2,
    "metadata_symbol_count": 5,
    "unclassified_symbol_count": 1
  }
}
```

تعني `status: "success"` الخارجية نشر إخراج جرى التحقق منه. تصف `recovered` و`partial` و`unrecovered` و`no-methods` القائمة المكتشفة، لا التكافؤ الدلالي أو اكتمال البرنامج الأصلي. لكل طريقة غير مستعادة سبب. تتطلب `recovered` في Objective-C بيانات تشغيل كاملة أيضاً. القائمة الفارغة لا تثبت عدم وجود طرائق.

تحسب `coverage_status` في Swift العناصر القابلة للاستدعاء المصنفة فقط. تراعي `status` الكلية الرموز المجهولة وقد تكون `unavailable` أو `unclassified` أو `unsupported-architecture` أو `no-symbols`. تظهر البيانات غير القابلة للاستدعاء في `non_method_symbols` بالحالة `not-callable`، والمجهولة بالحالة `unclassified`. تحسب `types` و`type_metadata_count` و`source_type_count` بيانات الأنواع ووحداتها المخرجة بصورة مستقلة، ولا يجوز تضخيم عدد الطرائق بها.

تحتوي `source_units` في دفعة Swift على `{kind, module, name, source, method_entries, method_identities}`؛ kind هو `function` أو `type`، وكل هوية هي `{entry, mangled_symbol}`. قد تتشارك رموز مختلفة المدخل نفسه مع الاحتفاظ بإسقاطات ABI مختلفة. يجب أن تظهر كل هوية مستعادة مرة واحدة تماماً، وألا تظهر هوية غير مستعادة. يجب أن تساوي `method_entries` إسقاط المداخل المرتب من `method_identities`، بما فيه العناوين المكررة. لا يجوز دمج الهويات المتطابقة المكررة بصمت. تجمع `source` مصادر الوحدات بالترتيب مع سطر جديد بعد كل وحدة. يحفظ Mobile المصدر الكامل في `sources/swift.swift` ووصف الوحدات في JSON التغطية. حقل `source` الفردي للفحص؛ جمع صفوف الطرائق لا يعيد تصريحات الأصناف بصورة صحيحة.

## التصدير الأصلي المباشر وSDK

```sh
neverd export recovered-ios/artifacts/selected.macho \
  --format=objc-methods --max-func=20 -o objc-batch.json
neverd export recovered-ios/artifacts/selected.macho \
  --format=swift-methods \
  --source-signatures=recovered-ios/metadata/swift-signatures.json -o swift-batch.json
```

يستهلك تصدير Swift قائمة التواقيع المنظمة الناتجة عن تشغيل mobile عادي باستخدام demangler. تتضمن دفعة Objective-C الحقول `native_source` و`native_function_count` و`objc_metadata`، ومصدر C واسم الدالة ونوع الإرجاع والمعاملات لكل طريقة. يتحقق Mobile أيضاً من التصريحات والأجسام والتخطيطات قبل `.m`، لذا قد تكون تغطيته النهائية أضيق من دفعة C. قد ينجح التصدير الأصلي دون أي طريقة مستعادة.

للجلسة التي حملت Mach-O مسبقاً، تعيد `neverd_objc_methods_json(session, max_functions)` و`neverd_swift_methods_json(session, signatures_json, max_functions)` التقارير. يختار الصفر جميع الدوال المكتشفة. حرر النصوص الناجحة باستخدام `neverd_free_string`؛ تعني `NULL` فشلاً يشرحه خطأ الجلسة. لا تحمل هذه الواجهات حاويات IPA أو `.app`.

## التحقق واستكشاف الأخطاء

```sh
NEVERD_BUILD_DIR=build python3 -m unittest discover -s scripts/tests -p 'test_mobile_*.py' -v
python3 scripts/test_mobile_ios_backend.py --neverd build/bin/neverd
python3 scripts/test_mobile_swift_backend.py --neverd build/bin/neverd
```

على macOS يجمع مشغل Objective-C عيناته الذاتية الأصلية، ويستعيد `.m`، ثم يربط المصدر المولد فقط ببرنامج استدعاء مستقل. يغطي حدود الأعداد والفروع والحلقات وقراءة المؤشرات وكتابتها والمعاملات المخفية وهوية بتات float/double والمعاملات المختلطة والمكدسية. يعيد مشغل Swift تجميع `.swift` مع برنامج الاختبار دون dylib أو وحدة أصلية أو جسر أو تصريحات بديلة مكتوبة يدوياً. يفحص القيم المفردة والاستدعاءات الأصلية وتهيئة الأصناف وتخزينها وطرائق struct بالقيمة أو mutating والعوامات والمكدس والمؤشرات والحلقات. قد تكشف هذه الفحوص الصارمة حالات غير مدعومة؛ وجود السكربت ليس دليلاً على نجاح كل الحالات في كل بناء.

يدعم السكربتان `--arch all|arm64|x86_64` و`--fixups both|classic|default` و`--timeout N` و`--work-dir NEW_DIRECTORY`. يتحقق `--setup-only` من الأصل فقط، لا الاستعادة. تُتخطى المعماريات التي لا يستطيع المضيف تنفيذها صراحة حيث يُسمح؛ التخطي ليس نجاحاً. تحفظ نواتج الفشل للتمييز بين تغطية ناقصة وخطأ تجميع واختلاف سلوك. راجع نتائج الاختبار الحالية قبل الادعاء بدعم موثق.

النشر معاملاتي: اختر دليلاً جديداً وافحص حالة الخروج أولاً واحفظ JSON المعاد توجيهه خارجه. تحذف الأخطاء الإخراج المؤقت وتحفظ الموجود. تتضمن نهاية الخلفية برمز غير صفري ذيلاً محدوداً للسجل، وللمهلات والميزانيات رسائل منفصلة. مع `--json` تعطي أخطاء المساعد المعالجة `status: "error"`؛ قد يفشل تحليل المعاملات أو غياب المساعد والمفسر أو Python أقدم من 3.10 أو المقاطعة مبكراً عبر stderr.

للشريحة المشفرة قدم مدخلاً مقروءاً، وللمعمارية الغائبة افحص الشرائح المتوفرة، ولأدوات Swift حدد demangler الحقيقي. اقرأ الأسباب الدقيقة وتشخيصات الطرائق المحذوفة. تفيد زيادة `--max-func` الدوال المستبعدة بهذا الحد فقط. تحتاج التخطيطات والتواقيع والترويسات الخارجية والاستثناءات وABI المفقودة إلى تنفيذ أو بيانات صحيحة إضافية، لا إلى ادعاء الاستعادة الكاملة. حافظ على إشعارات تراخيص الاعتماديات الواجبة عند توزيع الأدوات أو الحزم المولدة.
