# استعادة تطبيقات الأجهزة المحمولة

[← فهرس التوثيق](README.md) · [دليل Android الكامل](android.md) · [دليل iOS الكامل](ios.md)

يستعيد `neverd mobile` شيفرة Java مقروءة من مدخلات Android بصيغ APK وDEX وsmali. وللمدخلات iOS بصيغ IPA و`.app` وMach-O، يصدّر شيفرة C أصلية ويعيد بناء أجسام أساليب Objective-C المدعومة في ملفات مصدر `.m`، إلى جانب شيفرة Swift التجريبية والبيانات الوصفية لبيئة التشغيل. هذا مسار عمل تجريبي لواجهة CLI؛ ولا يقبل SDK الأصلي للغة C أو محمّل الواجهة الرسومية حاويات الأجهزة المحمولة.

## الإعداد

ابنِ الهدف `neverd` مع دعم C++20. يُضمَّن مسار عمل الأجهزة المحمولة في واجهة CLI الأصلية ولا يستخدم مفسر Python. وزّع الملف التنفيذي مع المكتبات الأصلية التي يحتاجها بناؤك.

تستخدم معالجة ZIP الأصلية مكتبة zlib من أجل CRC-32 وDEFLATE. يفضّل CMake مكتبة مثبتة عبر `find_package`؛ وإلا فإنه ينزّل zlib 1.3.2 ببصمة SHA256 مثبتة ويبنيها بصورة ثابتة. لا يحتاج تنفيذ ZIP الخاص بالأجهزة المحمولة إلى أدوات مساعدة Python على Windows. احتفظ بإشعارات التبعيات الواردة في [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md).

نُفّذ المحرك الافتراضي بلغة C++20 ولا يحتاج إلى بيئة تشغيل Python أو Java أو JADX. لا يُختار محوّل التوافق المثبت بصورة منفصلة إلا عند تمرير `--jadx PATH` صراحةً؛ ولا يختاره `NEVERD_JADX` أو PATH تلقائيًا، ولا يوجد انتقال احتياطي تلقائي إليه. يتطلب المحوّل الاختياري JADX 1.5.6+ مع إضافات الإدخال القياسية لـDEX/smali وJava 11+. يذكر تقريره محرك `jadx` الفعلي وإصداره. تبقى تعليمات التثبيت وتراخيص التبعيات موثقة في [دليل Android](android.md#محوّل-توافق-jadx-الاختياري).

## Android

للحصول على قائمة سريعة بالفئات دون استعادة Java، استخدم
`neverd mobile app.apk --list-classes`، ويمكن إضافة
`--class-prefix com.example` أو `--json`. يصف
[عقد الجرد](android.md#جرد-سريع-للفئات) الترتيب والحدود والتحقق من المحتويات
المحددة. لا يحتاج وضع الاستعلام إلى مجلد إخراج؛ ويشير `-o` الاختياري فيه إلى
ملف جديد.

للمراجع المباشرة في البايت كود، استخدم
`neverd mobile app.apk --find-refs string --query 'example' --json`.
يغطي [عقد استعلام المراجع](android.md#استعلامات-المراجع-في-الشفرة) أيضًا معاملات
الأنواع والأساليب والحقول، والمطابقة الحرفية/التامة، ومواقع كل ظهور، والحفاظ
على UTF-16، ونطاق التحقق من الشفرة. دون `--json`، تُخرج هذه العملية JSON Lines.
وتشارك سلوك `-o` الذي يشير إلى ملف جديد.

تصف الأمثلة والمخرجات التالية الاستعادة.

```sh
neverd mobile app.apk -o recovered-app
neverd mobile classes.dex -o recovered-dex
neverd mobile MainActivity.smali -o recovered-class
neverd mobile decoded/smali -o recovered-java
```

تُحلل معًا جميع ملفات `classes.dex` و`classes2.dex` وملفات DEX المرقمة التالية الموجودة في جذر APK. يُبحث في مجلد smali تكراريًا وتُحلل جميع فئاته في استدعاء واحد، بما فيها الفئات المتداخلة والمجاورة. استخدم مجلدًا عند استعادة فئات تشير إلى بعضها. أما ملف smali منفرد فلا يوفّر إلا فئته.

تحتوي مخرجات الاستعادة المدمجة على `sources/` و`metadata/android-methods.json` و`report.json`، مع `backend: {"name": "neverd", "version": "1", "execution": "builtin"}`. يضمّن التقرير `android_method_recovery`: `method_count = recovered_method_count + declaration_only_method_count`، ويجب أن تكون قيمة `unrecovered_method_count` صفرًا قبل النشر. تُحتسب تصريحات `native`/`abstract` الأصلية بصورة منفصلة عن الأجسام المستعادة. يحتفظ المحوّل الخارجي المختار صراحةً بسجلات الخلفية الخاصة به. تقع موارد APK والبيانات التعريفية للتطبيق والمكتبات الأصلية والشفرة المحمّلة ديناميكيًا خارج مسار Java هذا؛ ويمكن تحليل المكتبات الأصلية بصورة منفصلة باستخدام `neverd decompile`.

تشترك قارئات الاستعادة المدمجة في نموذج Dalvik ذي أنواع محددة، مطوّر بصورة مستقلة، ومولّد Java محدود العمل للشفرة العادية القابلة للتمثيل من DEX 035/037–040 وsmali. تفشل صراحةً DEX 041 والاستدعاءات الديناميكية مثل `invoke-custom` وبعض مسارات التهيئة والعمليات المجهولة والمعرّفات التي لا يمكن تمثيلها في Java. قد تستخدم Java المولّدة حلقة توزيع؛ لكنها لا تنفذ DEX الأصلي ولا تستدعيه عبر جسر وقت التشغيل. لا يمكن استرجاع التعليقات الأصلية أو التنسيق أو الأسماء المحذوفة. لا يعد المحرك التجريبي بتكافؤ الوظائف مع JADX أو بالتكافؤ الدلالي أو بالاستعادة الكاملة لأي APK.

## iOS

يوثّق [دليل iOS الكامل](ios.md) اختيار IPA و`.app` وMach-O، والإعداد، وجميع خيارات CLI، ومخططات المصدر، والتغطية، والتحقق.

```sh
neverd mobile App.ipa -o recovered-ios
neverd mobile App.app -o recovered-arm64 --arch=arm64
neverd mobile App.app -o framework-analysis --artifact Frameworks/Example.framework/Example
neverd mobile executable -o metadata --metadata-only
```

يختار كل تشغيل ملفًا تنفيذيًا واحدًا. يكون `--artifact` نسبيًا إلى حزمة التطبيق في كل من IPA و`.app`. يفضّل اختيار شرائح الملفات متعددة المعماريات arm64 ثم arm ثم x86_64 ثم i386؛ ويستهدف الإسقاط إلى لغة المصدر arm64/x86_64. تُرفض الشرائح المحددة المشفرة. يصدر المسار الأصلي التجريبي C وأجسام أساليب Objective-C المدعومة، بما فيها ارتباطات ABI للقيم المفردة/المؤشرات والأعداد العائمة والمعاملات المختلطة والمكدس. تُحفظ تخطيطات الفئات/متغيرات النسخة ivar في وقت التشغيل والفئات التوسعية المنفصلة عند التحقق منها؛ وتبقى التخطيطات والتواقيع والاستدعاءات والتبعيات الأخرى غير المحلولة نواقص صريحة.

تصنّف استعادة Swift التواقيع داخل عملية C++ باستخدام `LLVMSwiftDemangle` من تفرع LLVM الخاص بـNeverD. ولا تشغّل أداة خارجية لفك الأسماء المرمّزة أو أمرًا لاكتشاف سلسلة الأدوات، ولا تحتاج إلى مترجم Swift مثبت لبناء NeverD أو تشغيله. تتضمن عمليات البناء من مصدر التفرع وحزم LLVM المطابقة هذا المكوّن؛ ولا يجلب NeverD تبعية منفصلة لمصدر Swift. يسجل جرد التواقيع `demangler: {"name": "llvm-swift-demangle", "execution": "builtin", "version": "6.3.3"}`. تُربط التواقيع المدعومة بالمداخل الأصلية ومواقع ABI قبل إصدار دوال `.swift` فعلية وأساليب/مهيئات الفئات وأساليب البنى ذات التخطيط الثابت. تظل الصيغ المعممة/المرنة أمام تغيير التخطيط، وغير المتزامنة/التي ترمي أخطاء، والصيغ القابلة للاستدعاء المولّدة وقت التشغيل وغير المدعومة، ومجموعات تبعيات المصدر غير المكتملة، دون استعادة.

تتضمن المخرجات المعتادة `sources/native.c` وملفي `sources/objc.m` و`sources/swift.swift` الاختياريين، والتصريحات والبيانات الوصفية لوقت التشغيل، وJSON لتغطية الأساليب/التواقيع، والسجلات، و`artifacts/selected.macho`، و`report.json`. لا توجد سجلات لاكتشاف سلسلة أدوات Swift خارجية أو لفك الأسماء بأداة خارجية. لا يستدعي المصدر المولّد الملف الثنائي الأصلي كجسر للاستعادة. تجمع `source_units` في Swift تصريحات الأنواع والأساليب؛ ولا يجوز وصل صفوف الأساليب المنفردة لإعادة بناء الفئات. تعني الحالة الخارجية `status: "success"` نشر المخرجات، لا التغطية الكاملة للأساليب ولا التكافؤ الدلالي.

لا يشغّل `--metadata-only` مصدّر المصدر الأصلي ولا فك ترميز أسماء التواقيع، ولا يصدر مصدرًا أو تغطية أساليب. تستخدم جميع الأوضاع بيانات Objective-C الوصفية المحلولة بواسطة المحمّل الأصلي. تستخدم بيانات Swift الوصفية قراءات محدودة للصورة الأصلية؛ وتحتفظ الإصلاحات غير المدعومة والتخطيطات القابلة لإعادة التمركز أو المراجع بتشخيصات جزئية. يحد `--max-func` استعادة الدوال الأصلية ويُتجاهل في وضع البيانات الوصفية فقط. تؤدي أجسام الدوال الأصلية المفقودة إلى فشل التشغيل العادي. تُحذف المدخلات المؤقتة المفكوكة.

لا يمكن إعادة بناء التعليقات الأصلية والتنسيق والمعرّفات المحذوفة وبنى المصدر المفقودة أثناء الترجمة بدقة تامة. اقرأ حالة استعادة كل أسلوب وسببها، والأعداد المنفصلة لكيانات Swift القابلة للاستدعاء/غير القابلة للاستدعاء/غير المصنفة، والقيود الموثقة قبل استخدام المخرجات.

## الحدود والإخفاقات

في الاستعادة، يجب أن يشير `-o` إلى مجلد جديد خارج أي مجلد إدخال. تقبل أوضاع الاستعلام بدلًا من ذلك ملف إخراج جديدًا اختياريًا. لا تُستبدل المخرجات الموجودة مطلقًا. يُجهّز عمل الاستعادة في منطقة مؤقتة ولا يُنشر إلا بعد نجاح الاستعادة والتحقق من المخرجات. تُخزّن نتائج الاستعلام مؤقتًا حتى تنجح جميع ملفات DEX المحددة. تعيد عمليات تشغيل CLI الأصلية الناجحة صفرًا. تعيد إخفاقات الاستعادة قيمة غير صفرية؛ ويبلّغ `--json` عن الإخفاقات المعالجة عبر `schema_version` و`status: "error"` و`error`. وقد تُبلّغ إخفاقات تحليل المعاملات أو بدء الملف التنفيذي الأصلي أو المكتبات، والمقاطعات، عبر stderr بدلًا من ذلك. يجب على مستهلكي النتائج فحص حالة الخروج أولًا.

القيم الافتراضية هي 20 000 مدخل، و2 GiB من بيانات الإدخال/البيانات المستخرجة أو المخرجات النهائية، و300 ثانية لتحليل Android/iOS المدمج أو لكل عملية JADX مختارة صراحةً. تتلقى عمليات iOS الابنة ما تبقى من ميزانية التحليل الكلية. يفرض القارئ والمولّد المدمجان أيضًا ميزانية عمل محدودة. اضبط `--max-files` و`--max-bytes` و`--timeout` لتغيير هذه الحدود الموجبة. تُراقب منطقة العمل المؤقتة أثناء تشغيل الخلفيات، ويسمح بما يصل إلى ثلاثة أضعاف حدود المدخلات/البايتات كي تتعايش المدخلات المجهّزة والمخرجات الوسيطة. تُحد التشخيصات بـ16 MiB لكل عملية.

أثناء الاستعادة، لا يكتب تجهيز APK إلا `classes.dex` و`classes2.dex` وملفات DEX المرقمة التالية الموجودة في الجذر. يظل كل مدخل ZIP خاضعًا لفحوص الرأس/النطاق وفك الضغط والتحقق من الطول وCRC، ويُحتسب ضمن حدود عدد مدخلات الأرشيف والبايتات غير المضغوطة. قد تحمل الموارد التي لا تُكتب أسماء مختلفة بحسب حالة الأحرف، مثل `res/-A.xml` و`res/-a.xml`. تظل أسماء ZIP المكررة تمامًا وتعارضات هوية الملف/المجلد أخطاء؛ وتُطبّق فحوص تضارب حالة الأحرف المحمولة بين أنظمة الملفات على المدخلات المكتوبة فعليًا. يظل الاستخراج الكامل، بما فيه مدخل IPA، يرفض مثل هذه التضاربات في المخرجات. وتظل مسارات اجتياز المجلدات والروابط والملفات الخاصة ومدخلات ZIP المشفرة مرفوضة في الأرشيف كله. كما ترفض مدخلات المجلدات الروابط الرمزية والملفات الخاصة.

هذه الحدود ضوابط للمتانة وليست بيئة عزل لشفرة خلفية خارجية. تعمل أوامر JADX الصريحة وتصدير المصدر الأصلي كعمليات ابنة محلية. تُحذف مخرجات التجهيز الفاشلة. تتضمن حالات الخروج غير الصفرية للخلفيات ذيلًا تشخيصيًا محدودًا. تحتفظ مهلات الخلفيات برسالة انتهاء المهلة وتضيف ذيلًا محدودًا حين يتوفر نص سجل ملتقط. وتحتفظ إخفاقات التشغيل وتجاوزات الميزانيات برسائل الخطأ الخاصة بها.

## التحقق

يقتصر استخدام Python على أدوات اختبار التطوير أدناه؛ أما استعادة الأجهزة المحمولة المدمجة فتعمل داخل واجهة CLI الأصلية بلغة C++20.

```sh
cmake --build build --target check-neverd-mobile
ctest --test-dir build -L NeverDMobileTests --output-on-failure
python3 scripts/test_mobile_android_internal.py --d8 PATH --neverd build/bin/neverd
python3 scripts/test_mobile_android_backend.py --jadx /opt/jadx/bin/jadx --neverd build/bin/neverd
```

تغطي اختبارات المكوّنات التحليل والحاويات غير الآمنة وإخفاقات الخلفيات وتنظيف المخرجات واختيار المعمارية والحفاظ على المخرجات. تستخدم الاختبارات التي تستدعي CLI المبنية `NEVERD_BUILD_DIR`. يستخدم مشغّل Android الداخلي JDK ‏(`java` و`javac`) وD8 لبناء بيانات اختبار DEX/APK مستقلة، ثم لترجمة Java المستعادة وتنفيذها. هذه تبعيات للتحقق، وليست متطلبات للاستعادة المدمجة. شغّل الاختبار على البناء الحالي وافحص نتيجته قبل اعتبار الحالة متحققًا منها. يحتاج مشغّل التوافق المنفصل أيضًا إلى JADX؛ ولا يثبت نجاح بيانات الاختبار استعادة تطبيقات عشوائية.

على macOS مع Apple Clang وحزمة SDK الخاصة به ونسخة مبنية من NeverD، شغّل المقارنة الفعلية لتنفيذ Objective-C:

```sh
python3 scripts/test_mobile_ios_backend.py --neverd build/bin/neverd
cmake --build build --target check-neverd-mobile-ios
```

يبني المشغّل عينة اختبار Objective-C خاصة به، ويستعيد تنفيذات أساليبها، ثم يربط ملف `.m` المستعاد وحده مع أداة الاستدعاء المستقلة نفسها. تقارن عينته ذات 22 أسلوبًا 141 نتيجة قابلة للملاحظة، تغطي حدود الأعداد الصحيحة والتفرعات والحلقات وقراءات/كتابات المؤشرات والمعاملات المخفية وغير المستخدمة وبتات هوية float/double والمعاملات المختلطة ومواضع المكدس. يلزم تشغيل ناجح حالي قبل اعتبار أي حالة متحققًا منها. يجب إكمال كل معمارية وكل صيغة إصلاح مطلوبة؛ ويغطي الإعداد الافتراضي arm64/x86_64 × classic/default. تُعد الصيغة المفقودة أو المعمارية التي لا يستطيع المضيف تنفيذها إخفاقًا، ولا يُسمح بالتخطي. لا تثبت أدلة عينة الاختبار هذه الاكتمال لأي برنامج iOS. يُسجَّل `NeverDMobileIOSBackend` في CTest على macOS، بما في ذلك ملف اختبارات CI الرئيسي.

مشغّل استعادة Swift المستقل هو `python3 scripts/test_mobile_swift_backend.py --neverd build/bin/neverd`. يعيد ترجمة Swift المولّدة وأداة اختبارها دون ربط الملف الثنائي الأصلي؛ وتُعد الكيانات القابلة للاستدعاء غير المدعومة والفروق السلوكية إخفاقات. راجع [دليل iOS](ios.md) لدلالات التغطية وأدلة الإخفاق المحتفظ بها.

يستخدم [سير عمل Mobile Real Applications](../../.github/workflows/mobile-real-apps.yml) تطبيقات عامة مثبتة الإصدارات في [بيان مجموعة الاختبار](../../scripts/mobile_real_apps.json). تتطلب بوابة قبوله جردًا مستقلًا لكل DEX في كل APK ولكل Mach-O في كل حزمة iOS كاملة، وإعادة بناء مستقلة للأصول وللمصدر المولّد، ومقارنات للسلوك. يؤدي غياب المراحل أو جهل تغطية الجرد أو غياب الحالات المطلوبة إلى فشل البوابة. تظل مراحل إعادة ترجمة التطبيقات الحقيقية ومقارنة سلوكها غير مكتملة، لذا يحتفظ الدعم بعلامة Experimental؛ ولا يثبت اجتياز اختبارات ضوابط أداة التحقق النجاح على التطبيقات الحقيقية.

تحاول حالات Android ترجمة كامل مجموعة Java المولّدة المشمولة بالجرد باستخدام javac وD8، اعتمادًا على تصريحات Android SDK وحدها. لا يجوز أن تملأ بايت كود التطبيق الأصلي أو تنفيذات التبعيات أو الدوال البديلة النواقص في الاستعادة. تبقى الاستعادة الجزئية وأخطاء المترجم ضمن الأدلة؛ ولا يزال نجاح الترجمة يتطلب تحققًا مستقلًا وإعادة بناء APK كاملًا ومقارنة سلوك ART. تطابق أداة التحقق المرجعية لـiOS سجلات أساليب Objective-C على القرص مع مخرجات أدوات Apple، مع الحفاظ على هويات الفئة والفئة الوصفية والفئة التوسعية والقائمة والموضع الترتيبي. تبقي المؤشرات غير المحلولة أو الخانات المحذوفة الجرد مجهولًا. تدعم قوائم الجرد المنفصلة لتصريحات SDK الجهاز والمحاكي العمل على استيراد الأطر دون اعتبار ملفات الرؤوس دليلًا على تخطيط النسخ أو السلوك.
