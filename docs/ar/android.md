# استعادة شيفرة Java من Android

[← فهرس التوثيق](README.md)

يستعيد `neverd mobile` شيفرة Java مقروءة من مدخلات APK وDEX وsmali باستخدام أداة JADX مثبّتة بشكل مستقل. يتحقق مسار العمل من البايت كود ويجهّزه، ويحلّل الأصناف المرتبطة معًا، ويفحص المخرجات، ثم ينشر مجلد الشيفرة المصدرية مع تقرير قابل للقراءة آليًا. هذه ميزة تجريبية في واجهة سطر الأوامر. لا تتوفر حاويات APK ومخرجات Java عبر حزمة SDK الأصلية للغة C، أو حزمة SDK لإضافات Python، أو محمّل الواجهة الرسومية، أو `neverd decompile --language`.

شيفرة Java المستعادة هي إعادة بناء للبايت كود. لا تتوفر التعليقات الأصلية والتنسيق واختيارات لغة المصدر والمعرّفات المحذوفة؛ كما ينتج عن بايت كود Kotlin شيفرة Java. لا يثبت نجاح التشغيل التكافؤ الدلالي، ولا يضمن إمكان إعادة ترجمة كل دالة. لا يشغّل مسار العمل هذا أي تطبيق يخضع للتحليل.

## البداية السريعة

بعد إعداد بيئات التشغيل الموضحة أدناه، اختر مجلد إخراج جديدًا:

```sh
neverd mobile app.apk -o recovered-app
neverd mobile classes.dex -o recovered-dex
neverd mobile MainActivity.smali -o recovered-class
neverd mobile decoded/smali -o recovered-java
```

افتح `recovered-app/sources/` لقراءة ملفات Java، و`recovered-app/report.json` لفحص قائمة المدخلات والقيود. يُفضّل استخدام مجلد كمدخل عندما تشير أصناف smali إلى بعضها.

## إعداد بيئات التشغيل

| المكوّن | المتطلب | طريقة الاختيار |
|---------|---------|----------------|
| NeverD | ابنِ الهدف `neverd`؛ ووزّع معه مجلد `mobile/` المجاور للملف التنفيذي | `build/bin/neverd` أو ملف تنفيذي موجود في PATH |
| Python | Python 3.10 أو أحدث، مستقل عن مضيف الإضافات المضمّن | `--python`، ثم `NEVERD_PYTHON`، ثم `python3`/`python` في PATH |
| أداة استعادة Java | JADX 1.5.6 أو أحدث مع إضافات إدخال DEX وsmali القياسية | `--jadx`، ثم `NEVERD_JADX`، ثم `jadx` في PATH |
| بيئة Java | Java 11 أو أحدث؛ ويلزم JDK للتحقق بالترجمة والتشغيل | `JAVA_HOME` أو Java في PATH |

لا ينزّل NeverD الاعتماديات تلقائيًا. احصل على [توزيعة JADX الكاملة](https://github.com/skylot/jadx/releases/tag/v1.5.6)، واحتفظ ببنية `bin/` و`lib/`، وبالتراخيص المرفقة عند إعادة توزيعها. الإصدار المختبَر من الأداة هو 1.5.6؛ ويجب أن تلتزم الإصدارات الأحدث بعقد واجهة سطر الأوامر نفسه. إعداد الاعتماديات منفصل عن بناء خط LLVM في NeverD.

### Linux وmacOS

```sh
cmake --build build --target neverd
python3 --version
java -version
/opt/jadx/bin/jadx --version

./build/bin/neverd mobile app.apk -o recovered-app \
  --python python3 --jadx /opt/jadx/bin/jadx
```

للاستخدام المتكرر، اضبط `NEVERD_JADX=/opt/jadx/bin/jadx`، ويمكنك أيضًا ضبط `NEVERD_PYTHON` على مسار المفسّر. إذا لم تكن Java متاحة بالفعل، فاجعل `JAVA_HOME` يشير إلى مجلد تثبيت JDK. يجب وضع المسارات التي تحتوي على مسافات بين علامتي اقتباس.

### Windows PowerShell

```powershell
$env:JAVA_HOME = 'C:\Tools\jdk'
& .\build\bin\neverd.exe mobile .\app.apk -o .\recovered-app `
  --python 'C:\Tools\Python\python.exe' `
  --jadx 'C:\Tools\jadx\bin\jadx.bat'
```

يُستخدم مسار `.bat`/`.cmd` الخاص بالأداة للعثور على ملف `lib/jadx-*-all.jar` الوحيد في التوزيعة؛ ثم يستدعي NeverD برنامج Java مباشرةً. يمكنك أيضًا تمرير ملف JAR هذا إلى `--jadx`. لا تُدرج مسارات التطبيقات أبدًا في أوامر موجّه الأوامر. قد تضع عمليات البناء متعددة التهيئات الملف التنفيذي داخل `build/bin/Release/` بدلًا من ذلك. نقل الملف التنفيذي وحده دون مجلد `mobile/` يؤدي إلى خطأ يفيد بفقدان البرنامج المساعد.

## المدخلات المدعومة والقيود

| المدخل | السلوك | القيد الأساسي |
|--------|--------|---------------|
| `.apk` | يتحقق من ملف ZIP كاملًا، ثم يحلّل معًا ملفات `classes.dex` و`classes2.dex` والملفات DEX المرقّمة اللاحقة في الجذر | الشيفرة فقط؛ لا يفك الموارد أو ملف البيان |
| `.dex` | يتحقق من التوقيع السحري لصيغة DEX، ثم يترك للأداة فك محتوياته | تغيير اسم ملف أو اقتطاعه لا يجعله بايت كود صالحًا |
| `.smali` | يحلّل الصنف المقدّم | لا يحمّل تلقائيًا الأصناف المجاورة المشار إليها |
| مجلد smali | يجمع ملفات `.smali` تكراريًا ويحلّلها معًا | ضمّن الأصناف المتداخلة وجذور smali التابعة لها داخل مجلد الإدخال |

لتحليل شجرة APK مفكوكة تحتوي على `smali/` و`smali_classes2/`، مرّر المجلد المشترك الذي يحتويهما. لا تصل إلى الأداة إلا ملفات `.smali`، لكن تُفحص الشجرة المقدّمة كاملةً وتُنسخ أولًا؛ لذلك تُحتسب الأصول الكبيرة غير المرتبطة بالشيفرة ضمن حدود الإدخال أيضًا. يقلّ العمل باستخدام مجلد صغير يحتوي فقط على جذور smali المطلوبة.

تُعامل حزم APK المجزأة كمدخلات منفصلة. يمكن معالجة كل APK يحتوي على DEX على حدة، لكن هذا الأمر لا يدمج مجموعة APK؛ وتفشل الأجزاء التي تحتوي على موارد فقط لعدم وجود DEX في الجذر. لا تُقبل `.aab` و`.apks` و`.xapk` و`.odex` و`.oat` و`.vdex` كمدخلات لهذا الأمر. دعم أداة JADX لبعض هذه الصيغ لا يجعلها مدعومة في أمر NeverD هذا.

لا تُستعاد موارد APK أو `AndroidManifest.xml` أو الأصول أو مكتبات JNI/المكتبات الأصلية أو الشيفرة المنزّلة أثناء التشغيل على هيئة Java. استخرج مكتبة `.so` أصلية بشكل منفصل، واستخدم `neverd decompile library.so -o library.c`. يجب أن تكون الحمولة المشفّرة أو المحزّمة متاحة مسبقًا بصيغة DEX/smali عادية كي يعمل هذا المسار الساكن؛ فهو لا يفك حزم الحماية، ولا يتصل بالأجهزة، ولا يتجاوز وسائل الحماية.

## الخيارات وترتيب الأولوية

```sh
neverd mobile app.apk -o recovered-app --platform=android \
  --jadx /opt/jadx/bin/jadx --timeout=600 \
  --max-files=30000 --max-bytes=4294967296 --json
```

| الخيار | القيمة الافتراضية | المعنى |
|--------|-------------------|--------|
| `-o DIRECTORY` | مطلوب | مجلد إخراج جديد خارج أي مجلد إدخال؛ لا يستبدل المخرجات الموجودة مطلقًا |
| `--platform=auto\|android` | `auto` | اختيار Android صراحةً أو استنتاج المنصة من المدخل |
| `--jadx PATH` | متغيرات البيئة/PATH | مشغّل الأداة أو ملف JAR من التوزيعة؛ للخيار الصريح الأولوية |
| `--python PATH` | متغيرات البيئة/PATH | مفسّر البرنامج المساعد المرفق؛ للخيار الصريح الأولوية |
| `--timeout N` | `300` | عدد موجب من الثواني لكل عملية للأداة، بما فيها الاستعلام عن الإصدار |
| `--max-files N` | `20000` | حد موجب لعدد العناصر، بما فيها المجلدات التي تُنشأ |
| `--max-bytes N` | `2147483648` | حد موجب بالبايت للمدخل والبيانات المستخرجة والمخرجات النهائية |
| `--json` | معطّل | طباعة التقرير بصيغة JSON بدلًا من ملخص مقروء للمستخدم |

تخص الخيارات `--arch` عندما تختلف قيمته عن `auto`، و`--artifact` و`--metadata-only`، وكذلك `--max-func` عندما لا تكون قيمته صفرًا، منصة iOS وتُرفض مع Android. أما تمرير `--arch=auto` صراحةً فيُقبل مع Android. لا توجد آلية لتمرير خيارات اعتباطية إلى الأداة الخلفية. تُعزل مجلدات إعداداتها وذاكرتها المؤقتة وملفاتها المؤقتة لكل تشغيل؛ ولا تُستورد إعدادات الأداة أو الإضافات الموجودة خارج هذا التشغيل.

الحدود وسائل للتحكم في الموارد، وليست بيئة احتواء لعملية الأداة الخلفية. تُراقب أيضًا مساحة التجهيز، مع إتاحة مساحة للمدخل والبيانات المستخرجة والمخرجات تصل إلى ثلاثة أمثال الحدود المضبوطة للعناصر والبايتات. يقتصر حجم السجل على 16 MiB لكل عملية. قد تحتاج المدخلات الكبيرة إلى مساحة أكبر لكومة Java أو مهلة أطول؛ ولا تؤدي زيادة حد واحد إلى تعطيل الحدود الأخرى.

## بنية المخرجات وتقرير JSON

```text
recovered-app/
  sources/                 حزم Java وأصنافها المستعادة
  logs/jadx-version.log    الاستعلام عن إصدار الأداة
  logs/jadx.log            المخرجات التشخيصية للأداة
  report.json              قائمة ذات إصدار وحدود الاستعادة
```

تُحذف النسخ المؤقتة وذاكرات الأداة المؤقتة. تعتمد أسماء ملفات Java الدقيقة وعددها على إعادة البناء التي تجريها الأداة؛ وقد تشترك الأصناف المتداخلة في ملف الصنف الخارجي. لذلك لا يساوي عدد ملفات Java المصدرية عدد أصناف DEX.

مثال توضيحي مختصر للتقرير:

```json
{
  "schema_version": 1,
  "status": "success",
  "platform": "android",
  "source": "app.apk",
  "input_kind": "apk",
  "backend": {"name": "jadx", "version": "1.5.6"},
  "input_code_files": ["classes.dex", "classes2.dex"],
  "dex_count": 2,
  "smali_count": 0,
  "java_source_count": 2,
  "java_sources": ["sources/example/Main.java", "sources/example/Peer.java"],
  "logs": ["logs/jadx-version.log", "logs/jadx.log"],
  "limitations": ["Java is reconstructed from bytecode; original comments, formatting, and stripped names cannot be restored."]
}
```

تكون قيمة `input_kind` إحدى القيم `apk` أو `dex` أو `smali` أو `smali-directory`. يسرد `input_code_files` أسماء ملفات البايت كود الداخلة أو مسارات smali، بينما تكون مسارات `java_sources` و`logs` نسبية إلى جذر الإخراج. يمثّل `source` الاسم الأساسي للمدخل. تتضمن التقارير الفعلية قيودًا إضافية لإعادة البناء؛ احتفظ بها عند عرض النتائج على أدوات أخرى.

عند الأتمتة، افحص رمز خروج العملية قبل الاعتماد على `status`، واحفظ التقرير خارج مجلد الإخراج الجديد عند إعادة توجيه stdout:

```sh
neverd mobile app.apk -o recovered-app --json > recovery-result.json
```

تُرجع عمليات البرنامج المساعد الناجحة الرمز صفرًا. وتُرجع إخفاقات الاستعادة رمزًا غير صفري؛ وبعد بدء البرنامج المساعد، ينتج `--json` كائن خطأ يحتوي على `schema_version` و`status: "error"` و`error`. قد يحدث فشل مبكر عند تحليل الوسائط في البرنامج الأصلي، أو عند غياب Python أو استخدام إصدار Python أقدم من 3.10 أو غياب البرنامج المساعد، وعندئذ قد يُكتب الخطأ إلى stderr بدلًا من JSON. وقد تُبلّغ المقاطعة عبر stderr أيضًا. يجب أن تراعي الأدوات المستهلكة للنتائج هذه الحالات.

## معالجة الإخفاقات واستكشاف المشكلات

يتم النشر كوحدة واحدة: تُحفظ المخرجات الموجودة، وتُزال المخرجات المؤقتة عند الفشل. يفشل الأمر إذا أعادت الأداة رمز خروج غير صفري، أو سجّلت أخطاء تجميع smali أو فك ترجمة، أو أسقطت أصنافًا مكررة، أو أدرجت علامات صريحة لشيفرة غير مكتملة، أو أنتجت ملفات Java فارغة أو لم تنتج Java أصلًا. إعلان الأداة نجاحها لا يثبت بمفرده صحة كل دالة.

| العَرَض | الإجراء |
|---------|---------|
| غياب Python أو البرنامج المساعد | ثبّت أو اختر Python 3.10+، واحتفظ بمجلد `mobile/` بجوار NeverD |
| تعذّر تشغيل الأداة أو عدم دعم إصدارها | تحقّق من `--jadx` وبنية التوزيعة الكاملة وJava والحد الأدنى لإصدار الأداة |
| ترويسة DEX غير صالحة أو غياب DEX في الجذر | افحص الصيغة الفعلية للمدخل؛ استخدم APK يحتوي على شيفرة، أو DEX عاديًا، أو smali |
| عدم وجود ملفات smali | اختر مجلدًا يحتوي على ملفات `.smali`، وليس شيفرة Java المصدرية أو شجرة أصول فقط |
| صنف مكرر أو استعادة جزئية | أزل التعريفات المكررة من المدخل أو حلّل مجموعة البايت كود المطلوبة منفردة؛ أصلح smali غير الصالح بدلًا من قبول نتيجة ناقصة |
| تجاوز المهلة أو حد البايتات أو العناصر | استخدم مدخلًا أصغر يضم الشيفرة المطلوبة أو زِد الحد المعني عمدًا |
| مسار أرشيف أو رابط غير آمن | أعد إنشاء مدخل عادي صالح عبر الأنظمة، دون مسارات تتجاوز المجلد أو روابط أو ملفات خاصة أو مسارات متعارضة |
| وجود مجلد الإخراج مسبقًا | اختر مجلد إخراج آخر؛ لا تعِد استخدام مجلد تشغيل ناجح سابق |

تحتفظ عمليات التشغيل الناجحة بسجلات الأداة. أما مجلدات التجهيز الفاشلة، بما فيها سجلاتها، فتُحذف؛ وعند خروج الأداة برمز غير صفري تتضمن رسالة الخطأ جزءًا محدودًا من نهاية المخرجات التشخيصية. ولانتهاء المهلة أو تجاوز حدود الموارد رسائل خطأ منفصلة. للتحقيق في مشكلة تخص الأداة نفسها، أعد إنتاجها على مدخل معزول باستخدام واجهة سطر الأوامر الخاصة بها ومجلد تشخيص منفصل. لا تستنتج النجاح لمجرد ظهور بعض شيفرة Java قبل حدوث الفشل.

## التحقق وعمق الدعم

```sh
cmake --build build --target check-neverd-mobile
NEVERD_BUILD_DIR=build python3 -m unittest discover -s scripts/tests -p 'test_mobile_*.py' -v
python3 scripts/test_mobile_android_backend.py --jadx /opt/jadx/bin/jadx --neverd build/bin/neverd
```

يفحص الأمران الأولان عقود المكونات المحمولة وواجهة سطر الأوامر المبنية؛ وقد تؤدي متطلبات أمثلة الاختبار الخاصة ببعض المنصات إلى تخطٍّ معلن. يحتاج مشغّل اختبار الأداة الفعلية أيضًا إلى JDK، أي `java` و`javac`. ينشئ حالات لملف smali واحد، وأصناف smali مرتبطة ومتداخلة، وDEX، وAPK حقيقي متعدد ملفات DEX، ثم يترجم شيفرة Java المستعادة ويشغّلها. تغطي الحالات التفرعات والحلقات والمصفوفات ومعالجة الاستثناءات ومراجع الأصناف والمدخلات غير الصالحة وإسقاط الأصناف المكررة. هذه أدلة تخص أمثلة الاختبار تلك، وليست وعدًا باستعادة كاملة لأي تطبيق.

يشغّل [مسار Mobile Decompilation](../../.github/workflows/mobile.yml) اختبارات المكونات على Linux وmacOS وWindows باستخدام Python 3.10 و3.13، إضافة إلى مهمة لاختبار أداة Android الفعلية على Linux مع تثبيت التوزيعة بمجموع تحقق. راجع [النظرة العامة على فك ترجمة التطبيقات المحمولة](../mobile.md) للاطلاع على مسار iOS المنفصل وحدوده الحالية.
