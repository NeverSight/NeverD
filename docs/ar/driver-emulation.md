# محاكاة برامج تشغيل Windows

ينفّذ محاكي برامج التشغيل الاختياري في NeverD نقطة دخول PE لبرنامج تشغيل x64 WDM مدعوم، ويمكنه تنفيذ سيناريو صريح من الطلبات المتزامنة قبل إلغاء تحميله. يستخدم Unicorn لتنفيذ تعليمات المعالج، ونموذج NeverD المحدود الخاص لبيئة Windows. لا يحمّل برنامج التشغيل في نواة المضيف، ولا يمرّر استدعاءات واجهات الضيف إلى خدمات نظام تشغيل المضيف.

## البناء والتشغيل

يجب تفعيل هذه الميزة صراحةً، وهي مستقلة عن `BUILD_TESTING`:

```bash
cmake -S . -B build-release -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DNEVERD_ENABLE_DRIVER_EMULATION=ON
cmake --build build-release --target neverd --parallel 4
build-release/bin/neverd emulate-driver path/to/driver.sys \
  --instruction-limit 100000 > driver-report.json
```

يُكتب التقرير دائمًا بصيغة JSON إلى stdout، بينما تُكتب رسائل تشخيص الطلبات والإعداد إلى stderr. الحدود الافتراضية هي 100000 تعليمة ضيف، و64 MiB من ذاكرة الضيف، و10000 حدث مسجّل، و5000 ملّي ثانية. يجب أن يكون حد التعليمات موجبًا. يؤدي نفاد الميزانية إلى إيقاف التنفيذ مع الاحتفاظ بالمشاهدات الجزئية.

| رمز الخروج | المعنى |
|------------|--------|
| `0` | نجحت التهيئة وكل العمليات المطلوبة التي اكتملت |
| `1` | مدخلات/خيارات غير صالحة، أو فشل الإعداد، أو تعطيل الميزة وقت البناء |
| `2` | أعادت التهيئة أو أحد الطلبات المكتملة قيمة `NTSTATUS` تدل على الفشل |
| `3` | توقف التنفيذ قبل اكتمال السيناريو، مثل الوصول إلى API غير مدعوم أو وقوع عطل أو بلوغ حد الميزانية |

تُعد حالة الفشل المعادة مشاهدة مكتملة لتلك العملية. أما العودة الناجحة فتصف هذا التشغيل داخل النموذج فقط؛ ولا تثبت أن برنامج التشغيل يعمل تحت Windows.

## توافق برامج التشغيل

يُحدّد التوافق وفق مسار الشفرة المنفّذ واعتمادياته، لا وفق امتداد `.sys`. تشمل أدلة القبول الحالية fixtures مستقلة أصلية ومسارات buffered وin-direct وout-direct لمثال Microsoft SIOCTL WDM، بما فيها البناء الذي يسجّل رسائل التصحيح، وكذلك القراءة والكتابة المباشرتان في المثال العام Zero لبافل يوسيفوفيتش. ولا يثبت ذلك التوافق مع برامج تشغيل عشوائية من جهات خارجية.

| فئة برنامج التشغيل أو متطلبه | النطاق الحالي | البيئة الناقصة |
|------------------------------|---------------|----------------|
| برنامج تشغيل برمجي x64 WDM يستخدم الواجهات المدرجة | التهيئة ودورات حياة الملفات المتزامنة | يحتاج كل API إضافي يُنفّذ إلى نموذج محدد |
| `METHOD_BUFFERED` IOCTL | مدعوم، مع هويات ملفات مستقلة وطلبات متداخلة الترتيب | الإكمال غير المتزامن غير متاح |
| `METHOD_IN_DIRECT` و`METHOD_OUT_DIRECT` | قوائم MDL مملوكة للطلب وتعيينات في فضاء النظام | هويات الصفحات الفيزيائية وDMA وتعيينات المستخدم |
| قوائم MDL يخصصها برنامج التشغيل | واصفات مستقلة للمجمّع غير القابل للترحيل في النموذج، مع مشاركة عناوين المخازن الأصلية | الربط بطلب IRP وسلاسل MDL والفحص/القفل والصفحات الفيزيائية وتعيينات المستخدم |
| READ/WRITE المتزامنان | Buffered أو direct بحسب أعلام الجهاز | Neither I/O والاختيار الضمني لموضع الملف والإكمال غير المتزامن |
| `METHOD_NEITHER` | مرفوض | سياق فضاء عناوين المستخدم وفحص الوصول ومعالجة استثناءات الضيف |
| برنامج تشغيل KMDF / UMDF | غير مدعوم | ربط إطار العمل وكائناته وطوابيره واستدعاءاته الراجعة وبيئة التنفيذ المضيفة المناسبة |
| برنامج تشغيل ناقل/وظيفة/مرشّح PnP | قد تعمل التهيئة ضمن مجموعة API الفرعية؛ دورة حياة مكدس الأجهزة غير مدعومة | إرفاق الأجهزة والإرسال إلى برنامج تشغيل أدنى وطلبات IRP الخاصة بـPnP والطاقة |
| برامج تشغيل التخزين والشبكة والعرض ونظام الملفات والمرشحات المصغرة | عقود الأنظمة الفرعية غير مدعومة | أطر المنفذ/الفئة/المنفذ المصغّر وخدمات NDIS/WFP والرسومات أو نظام الملفات |
| برنامج تشغيل يستخدم خيوط عمل أو مؤقتات أو DPC أو APC أو انتظارًا أو إلغاءً | غير مدعوم | الجدولة وانتقالات IRQL والمزامنة والملكية غير المتزامنة |
| برنامج تشغيل يستخدم استدعاءات راجعة للعمليات/الخيوط أو مقابض أو عمليات سجل/ملفات أو اكتشاف وحدات النواة | عمليات السجل المدرجة مدعومة ضمن شجرة مضبوطة صراحةً؛ أما العمليات الأخرى فغير مدعومة | مدير الكائنات العام وعمليات الملفات وحالة النظام ومصادر الاستدعاءات الراجعة/الأحداث |
| برنامج تشغيل عتاد أو DMA أو PCI أو مقاطعات أو افتراضية | البيئة غير مدعومة | نماذج الأجهزة والذاكرة الفعلية والنواقل والمقاطعات وحالة المعالج ذات الامتيازات |
| برنامج تشغيل Windows لمعمارية x86 أو ARM64 | يُرفض | التحميل وABI ونموذج التنفيذ الخاص بالمعمارية |
| صورة x64 تتطلب CFG أو إعداد تحميل غير مدعوم أو TLS أو ميزات PE أخرى مرفوضة | تُرفض وقت التحميل | دلالات صريحة للمحمّل/بيئة التنفيذ تغطي هذه المتطلبات |

يمكن أن يظل استيراد غير مدعوم لكنه غير مستخدم مرتبطًا. يؤدي الوصول إلى عملية غير مدعومة إلى التوقف مع رسالة تشخيص والمشاهدات التي جُمعت حتى تلك النقطة. لا يثبت نجاح DriverEntry وحده دعم مسارات الإرسال اللاحقة أو العتاد أو إطار العمل. جدول API أدناه هو المرجع المعتمد للمجموعة الفرعية المدعومة.

## عقد التنفيذ

يمثل ملف التنفيذ هذا دورة حياة واحدة لبرنامج x64 WDM أحادي الخيط عند `PASSIVE_LEVEL`. يبدأ التنفيذ من نقطة دخول PE، مع إبقاء غلاف الدخول الذي أنشأه المترجم إن وُجد. يجب أن يعيد DriverEntry القيمة `STATUS_SUCCESS` لنجاح التهيئة؛ أما حالة نجاح غير صفرية أو حالة pending فتوقف التنفيذ باعتبارها عقد تهيئة غير مدعوم. تُحفظ حالة الفشل بوصفها نتيجة تهيئة مكتملة. تقع كل الكائنات والسلاسل والمكدسات ومؤشرات الدوال والتخصيصات في ذاكرة الضيف. يوفّر النموذج `DRIVER_OBJECT` ومسار سجل لاسم الخدمة المضبوط، وقيمته الافتراضية `NeverDDriver`. يستخدم المهايئ نمط TLB الافتراضي في Unicorn للحفاظ على عناوين الضيف الافتراضية، بما فيها عناوين النواة العليا القياسية (canonical)، من دون تركيب جداول صفحات Windows. قيمة RFLAGS الابتدائية هي `0x202`؛ ويستخدم ملف تعريف الجهاز البرمجي سطر ذاكرة مخبئية ثابتًا بحجم 64 بايت. هذه خصائص صريحة لسيناريو التنفيذ هذا.
تُظهر قراءات x64 المضمّنة لسجل CR8 قيمة `PASSIVE_LEVEL` نفسها؛ وتظل كتابة CR8 والعمليات الأخرى على سجلات التحكم غير مدعومة.

تُربط الاستيرادات المجهولة بمصائد مؤجلة. لا يمنع الاستيراد غير المستخدم التنفيذ؛ لكن تنفيذ thunk الخاص به أو قراءة قيمة بيانات مصدّرة غير ممثلة في النموذج يؤدي إلى `unsupported_api`. تؤدي تأثيرات بيئة المعالج غير المدعومة أيضًا إلى توقف صريح. لا يستبدل NeverD الاستدعاءات غير المنفذة بقيم نجاح. تفشل الصور المشوّهة أو متطلبات التحميل غير المدعومة قبل التنفيذ.

لا ينفّذ هذا الملف نموذج نواة Windows كاملة أو بيئة KMDF أو دورة حياة PnP/الطاقة أو IRP غير متزامن أو معلّق أو IOCTL بأسلوب neither أو المقاطعات أو جدولة متعددة الخيوط. لا تُنفّذ الاستدعاءات الراجعة إلا عندما يطلبها السيناريو صراحةً؛ ويظل طلب التهيئة وحده يتوقف بعد DriverEntry.

تستخدم الصور عنوانها الأساسي المفضّل ما لم يختر السيناريو عنوان نقل صالحًا، ويجب أن تكون ملفات تنفيذية PE32+ x64 ذات نظام فرعي native. يمكن أن تأتي الاستيرادات من `ntoskrnl.exe` أو `ntkrnlmp.exe`. يدعم محمّل التنفيذ عمليات نقل العنوان الأساسي x64 `DIR64` التي اجتازت التحقق، وإعداد تحميل محدودًا لملف تعريف الارتباط الأمني security cookie؛ وتُهيّأ قيمته داخل الضيف بصورة حتمية قبل غلاف الدخول. تُرفض CFG وحقول إعداد التحميل الأخرى غير الممثلة وTLS والاستيرادات المؤجلة/المربوطة والاستيرادات برقم ordinal والصور المُدارة. يجب أن تجتاز الصور أيضًا فحوصًا صارمة للنطاقات والمحاذاة.

يحدد نموذج API الأولي عمدًا عقدًا محدودًا:

| الواجهات | السلوك الممثل والقيود |
|----------|----------------------|
| `RtlInitUnicodeString` | ينشئ `UNICODE_STRING` في الضيف من مصدر محدود منتهٍ بـNUL |
| `RtlCopyUnicodeString` و`RtlCompareUnicodeString` و`RtlEqualUnicodeString` | نسخ UTF-16 محدد الطول ومقارنة حساسة لحالة الأحرف؛ تتطلب المقارنة غير الحساسة جدول حالة أحرف Windows وتوقف التنفيذ |
| `ExAllocatePool2` | تخصيصات paged/nonpaged من نوع NX، تُصفّر افتراضيًا؛ تُنمذج أعلام uninitialized وcache-aligned؛ تعيد الأعلام الإلزامية غير الصالحة NULL، وتوقف مخازن الحصص/المخازن التنفيذية ورفع استثناءات التخصيص التنفيذ |
| `MmGetSystemRoutineAddress` | يحل اسم ضيف محدد الطول عبر سجل الصادرات المشترك |
| `ZwOpenKey`, `ZwCreateKey`, `ZwQueryValueKey`, `ZwSetValueKey`, `ZwDeleteValueKey`, `ZwDeleteKey`, `ZwClose` | شجرة سجل صريحة محلية للجلسة، ومقابض مستقلة وصلاحيات لكل مقبض، واستعلامات بأطوال دقيقة وتغييرات قابلة للمشاهدة؛ دون الوصول إلى سجل المضيف أو تقييم قوائم ACL في Windows |
| `MmMapLockedPagesSpecifyCache` و`MmGetSystemAddressForMdlSafe` و`MmUnmapLockedPages` | قوائم MDL للطلبات مع تعيينات KernelMode مخبأة وصلاحيات؛ تعيد قوائم المجمّع غير القابل للترحيل استخدام التعيين الأصلي عبر المساعد الآمن |
| `IoAllocateMdl`, `MmBuildMdlForNonPagedPool`, `IoFreeMdl` | واصفات مستقلة، ومجال كامل داخل تخصيص صالح واحد في المجمّع غير القابل للترحيل؛ عمر مستقل للواصف والمخزن؛ دون ربط IRP أو سلاسل أو حصص |
| `ExAllocatePoolWithTag` و`ExFreePoolWithTag` و`ExFreePool` | تخصيصات بيانات لأنواع المخزن `0` و`1` و`512`؛ حجم/وسم موجبان، وسم مطابق عند التحرير الموسوم، ومن دون إعادة استخدام العناوين |
| `IoCreateDevice` و`IoDeleteDevice` | نوع جهاز `0x22` وخصائص `0` أو `0x100` وامتدادات محدودة وأسماء ASCII من شكل `\Device\Name` |
| `IoCreateSymbolicLink` و`IoDeleteSymbolicLink` | أسماء ASCII من شكل `\DosDevices\Name` أو `\??\Name` ضمن نطاق أسماء جلسة واحدة، تستهدف `\Device\Name` |
| `DbgPrint` و`DbgPrintEx` | تنسيق وسائط Win64 المتغيرة مع التحقق، بحد أقصى 512 بايت من المخرجات؛ جميع مرشحات المصحح مفعّلة |
| `IoGetCurrentIrpStackLocation` | يعيد موضع المكدس لطلب IRP النشط في النموذج؛ تقرأ وحدات ماكرو WDM المترجمة المعتادة حقل الضيف نفسه |
| `KeGetCurrentIrql` | يعيد `PASSIVE_LEVEL` |
| `IofCompleteRequest` و`IoCompleteRequest` | يكمل IRP المتزامن النشط في النموذج باستخدام `IO_NO_INCREMENT`؛ لا يمكن الوصول مجددًا إلى IRP أو مخزن اكتمل |
| `memcpy` و`memmove` و`memset` و`memcmp` و`RtlCopyMemory` و`RtlMoveMemory` و`RtlFillMemory` و`RtlZeroMemory` و`RtlCompareMemory` | عمليات محدودة على مخازن الضيف، بحد أقصى 1 MiB لكل استدعاء؛ ترفض واجهات النسخ غير المتداخل النطاقات المتداخلة |

يدعم تنسيق `DbgPrint` الأعداد الصحيحة `d/i/u/o/x/X` والمؤشر `p` والنص `s/c` و`%%` وUnicode محدد الطول `wZ/lZ` والنص العريض `ls/ws` والأعلام والعرض/الدقة بما فيهما `*` ومعدّلات طول الأعداد الصحيحة في Windows. تُقرأ 32 وسيطة متغيرة و1024 بايت للتنسيق على الأكثر. يقتصر العرض والدقة على 512. يوقف التنفيذ صراحةً عند الأعداد العائمة و`%n` والتركيبات المجهولة وتحويلات النص غير ASCII؛ ولا يخمّن النموذج صفحة ترميز Windows أو يستدعي printf المضيف على بيانات الضيف.

ينتهي عمر سجل RegistryPath الأصلي ومخزنه عندما يعود DriverEntry. على برامج التشغيل التي تحتاج السلسلة لاحقًا نسخها أثناء التهيئة.

حجم منطقة تخصيص الكائنات/المخزن هو 1 MiB. تستخدم بايتات المخزن غير المهيّأة المحتوى الحتمي `0xCD`، وتستخدم البايتات المحررة `0xDD`. هذا سيناريو تنفيذ محدد واحد. ترفض عمليات وصول المعالج وواجهات المخازن الممثلة الوصول إلى تخصيصات مخزن محررة أو أجهزة محذوفة أو بايتات غير مخصصة في المنطقة أو حقول كائنات معتمة، كما ترفض الكتابة إلى حقول الكائنات المخصصة للقراءة فقط. تغطي هذه الفحوص أعمار كائنات هذا النموذج؛ وليست تحليلًا عامًا لسلامة ذاكرة برنامج التشغيل. تُعرض خانات جدول الإرسال التي لم تُكتب بصفر يعني «غير مسجّلة». يكتمل طلب السيناريو لدالة رئيسية غير مسجلة عبر المعالج الافتراضي الممثل، بالحالة `STATUS_INVALID_DEVICE_REQUEST`؛ ويظل الفشل ظاهرًا في حالة الإرسال وحالة الإدخال/الإخراج معًا. لا يختلق النموذج عنوان دالة داخل الضيف لذلك المعالج، وتظل قراءة الضيف لخانة لم تُكتب غير مدعومة. التسجيل الصريح لاستدعاء راجع بمؤشر null خطأ.

## سيناريوهات الطلبات

مرّر ملف JSON باستخدام `--scenario` لاختيار الطلبات وإلغاء التحميل الاختياري:

```bash
build-release/bin/neverd emulate-driver path/to/driver.sys \
  --scenario scenario.json > driver-report.json
```

لبرنامج تشغيل ينشئ `\Device\NeverDIO` ويقبل IOCTL مخزّنًا مؤقتًا برمز `0x222000`، يكون مثال `scenario.json` كما يلي:

```json
{
  "requests": [
    {"kind": "create", "device": "\\Device\\NeverDIO"},
    {"kind": "ioctl", "code": "0x222000", "input": "00112233", "output_size": 4},
    {"kind": "cleanup"},
    {"kind": "close"}
  ],
  "unload": true
}
```

يجب أن يطابق اسم الجهاز ورمز IOCTL برنامج التشغيل. عند create، يؤدي حذف `device` إلى اختيار الجهاز الحي الوحيد؛ ويفشل الاختيار إن كان ملتبسًا. تستخدم الطلبات اللاحقة جهاز ملفها ما لم يُعطَ اسم مطابق صراحةً. الحقل الاختياري `file` هو هوية سيناريو غير موقّعة من 32 بت، وقيمته الافتراضية صفر. لكل هوية FILE_OBJECT وFsContext خاصان بها، ويجب أن تتبع ترتيب create ثم عمليات النقل ثم cleanup ثم close. يمكن تداخل ترتيب طلبات الملفات المستقلة. ترفض الأجهزة الحصرية عملية فتح ثانية. تمثّل هذه الهويات كائنات ملفات، لا مقابض مكررة. تُدعم طريقة buffered وطريقتا direct في IOCTL. يجب أن يكمل الإرسال كل IRP بصورة متزامنة؛ وتفشل صراحةً إعادة `STATUS_PENDING` أو عدم الإكمال أو أطوال المخرجات غير الصالحة أو الوصول إلى IRP مكتمل. يجب ألا يترك إلغاء التحميل المطلوب أي جهاز حي أو رابط رمزي أو تخصيص مخزن أو كائن ملف.

يطلب الحقل الجذري الاختياري `"load_address": "0x190000000"` تغيير العنوان الأساسي؛ ويؤدي حذفه أو استخدام `"0x0"` إلى اختيار العنوان المفضّل. يجب أن تستوفي الصورة متطلبات النقل. لا يتضمن أمر التهيئة الأصلي أو واجهة C API سيناريو ضمنيًا.

لا تُقبل في الجذر سوى الحقول `load_address` و`requests` و`unload` و`kernel_exports` و`registry`. تقبل جميع الطلبات `kind` والحقلين الاختياريين `device` و`file`. تتطلب طلبات IOCTL الحقل `code` وتقبل `input` و`output_size` و`direct_input`. يقبل `read` الحقلين `output_size` و`byte_offset`؛ ويقبل `write` الحقلين `input` و`byte_offset`. الإزاحات صفر افتراضيًا، وتقبل أعدادًا صحيحة أو سلاسل سداسية عشرية، ويجب أن تلائم قيمة غير سالبة ضمن عدد صحيح موقّع من 64 بت. ترفض طلبات دورة الحياة حقول النقل. تُرفض الحقول المجهولة أو المكررة. يقبل `code` عدد JSON صحيحًا غير موقّع من 32 بت أو سلسلة سداسية عشرية تبدأ بـ`0x`. أما `input` فهو سلسلة بايتات سداسية عشرية بطول زوجي، بلا بادئة أو مسافات؛ وحذفه يعني مدخلًا فارغًا. `output_size` عدد JSON صحيح غير موقّع؛ وحذفه يعني الصفر. تُرفض الكسور وصيغ كتابة الأعداد العائمة.

في طلبات direct IOCTL، يهيّئ `input` مخزن النظام الأول، بينما يهيّئ `direct_input` المخزن الثاني المنفصل الذي تصفه MDL، مع استكماله بأصفار حتى `output_size`. تتطلب `METHOD_IN_DIRECT` صلاحية القراءة، لكنها لا تعني أن تعيين النظام للقراءة فقط. تستخدم الطريقتان مخازن سيناريو قابلة للقراءة والكتابة. يزيل `MdlMappingNoWrite` صلاحية الكتابة للتعيين، ويزيل `MdlMappingNoExecute` صلاحية التنفيذ. يلغي فك التعيين صلاحية العنوان الافتراضي للنظام؛ وتحافظ إعادة التعيين على البيانات المقفلة نفسها. ينهي الإكمال عمر MDL والتعيين. تُنمذج حقول MDL العامة التي تستخدمها وحدات ماكرو WDM؛ وتُرفض حقول process/PFN وقوائم MDL المنشأة يدويًا وتعيينات المستخدم والوصول المباشر عبر UserBuffer الخام. يكون MDL لمخزن direct صفري الطول null.

تخصص `IoAllocateMdl` بيانات وصفية مستقلة لمخزن غير فارغ لا يتجاوز عنوانه المجال ولا يزيد حجمه عن 1 MiB؛ ولا تفحص المخزن أو تقفل صفحاته. يجب أن تكون `Irp` بقيمة NULL وأن تكون `SecondaryBuffer` و`ChargeQuota` بقيمة FALSE. يعيد نفاد الحيّز NULL. تتطلب `MmBuildMdlForNonPagedPool` أن يقع المجال الموصوف بالكامل داخل تخصيص صالح واحد في المجمّع غير القابل للترحيل. يعيد المساعد الآمن ووحدات ماكرو WDM المعتادة استخدام العنوان الأصلي، مع الحفاظ على مشاركة المخزن والصلاحيات الحالية حتى عند إضافة أعلام منع الكتابة أو التنفيذ. تُرفض التعيينات الإضافية في فضاء النظام وفك التعيين. تنهي `IoFreeMdl` عمر الواصف فقط؛ ولمخزن المجمّع عمر مستقل. يُدعم كلا ترتيبي التحرير ما دامت الذاكرة المحررة لا تُستخدم لاحقًا. جميع حقول MDL المنمذجة للقراءة فقط؛ ولا يُدعم الوصول إلى process/PFN أو السلاسل أو تعديل الحقول يدويًا. يجب أن يحرر التفريغ جميع الواصفات التي يملكها برنامج التشغيل.

في كل طرق IOCTL ذات `output_size` غير الصفري، يجب ألا تتجاوز `Information` قيمة `output_size` حتى لو كان مخزن الإدخال أكبر. إذا لم يوجد مخزن إخراج، يمكن أن تتضمن `Information` نتيجة من 64 بت يحددها برنامج التشغيل؛ ولا تُفسَّر على أنها عدد بايتات مطلوب نسخها. يحتفظ التقرير بالقيمة العددية ويضيف `information_hex` كسلسلة سداسية عشرية دقيقة لقارئات JSON التي لا تستطيع تمثيل جميع الأعداد الصحيحة من 64 بت.

في READ/WRITE، يحدد `DO_BUFFERED_IO` أو `DO_DIRECT_IO` أسلوب النقل. يوقف أسلوب neither أو تعارض الأعلام التنفيذ. تُفحص Information مقارنة بطول النقل؛ وتعيد الكتابة عددًا، بينما تعيد القراءة بايتات.

يربط `kernel_exports` أسماء الإجراءات بقيم منطقية صريحة للتوافر، مثل `"kernel_exports": {"OptionalRoutine": false}`. تحصل الصادرات الممثلة والاستيرادات الثابتة على عناوين مستقرة مشتركة مع `MmGetSystemRoutineAddress`. يُحل التصدير الغائب صراحةً إلى NULL، ولا يمكنه تلبية استيراد ثابت. ويُحل التصدير المعلن وجوده دون نموذج API إلى مصيدة مؤجلة. يوقف الاسم الديناميكي المجهول التنفيذ بتشخيص يفيد بأن التوافر غير محدد؛ ولا يُستنتج الغياب أبدًا من عدم وجود التنفيذ. الأسماء محدودة الطول ومكوّنة من ASCII قابل للطباعة، وحلها حساس لحالة الأحرف. السجل خاصية لسيناريو محدد، وليس ادعاءً بمطابقة كل إصدار Windows.
`IoGetCurrentIrpStackLocation` و`MmGetSystemAddressForMdlSafe` دالتان مساعدتان من ترويسات WDM يمثلهما النموذج؛ ولا يعني ذلك الإعلان عنهما كتصديرين افتراضيًا، لذا يتطلب توافرهما كتصديرين استيرادًا ثابتًا أو إعلانًا صريحًا في `kernel_exports`.

يقتصر نص السيناريو على 2 MiB، وبحد أقصى 64 طلبًا، و65536 بايت لكل مخزن إدخال أو إخراج، و512 KiB إجمالًا للبايتات المطلوبة بما فيها محتوى `direct_input`. تسري ميزانيات التعليمات والمشاهدات وذاكرة الضيف والوقت على السيناريو كله. تحتوي منطقة 1 MiB أيضًا على الكائنات والبيانات الوصفية، ولذلك يمكن للصورة استنفاد ذاكرة النموذج قبل استهلاك الحد الأقصى لمخازن السيناريو.

## سيناريوهات السجل

تحدد المصفوفة الاختيارية `registry` شجرة سجل ملموسة محلية للجلسة. لكل مفتاح
حقل `path` مطلوب ومصفوفة `values` اختيارية؛ وتتضمن كل قيمة `name` وعددًا صحيحًا
غير موقّع `type` وبيانات سداسية عشرية `data`. يحدد اسم القيمة الفارغ القيمة
الافتراضية. مثال لقيمة DWORD هو `{"name":"Mode","type":4,"data":"01000000"}`.
تُحفظ بايتات القيم كما هي تمامًا؛ ولا يصلح النموذج محارف نهاية السلاسل أو يوسّع
متغيرات البيئة.

يجب أن تكون المسارات مطلقة ومن أحرف ASCII تحت `\\Registry\\Machine` أو
`\\Registry\\User`. تُنشأ مفاتيح الأسلاف ضمنيًا. تُقارن هويات المفاتيح والقيم
دون حساسية لحالة الأحرف وفق قواعد ASCII؛ وتُرفض الأسماء غير ASCII والهويات
المكررة. عند حذف `registry` يظل توافر السجل غير محدد وتتوقف استدعاءات السجل.
أما `"registry": []` فتصف نطاق أسماء فارغًا صراحةً. لا يُستنتج من برنامج التشغيل
أي مفتاح أو قيمة أو بيانات من سجل المضيف أو إعداد للخدمة.

تعيد `ZwOpenKey` و`ZwCreateKey` مقابض معتمة مستقلة، مع فحص صلاحيات كل مقبض
عند الاستعلام والكتابة وإنشاء المفاتيح الفرعية والحذف. تمنح الشجرة المضبوطة
البتات المدعومة في `KEY_ALL_ACCESS`، بما فيها القناعان المعتادان `KEY_READ`
و`KEY_WRITE`. هذه شجرة اختبار متاحة صراحةً، دون قوائم ACL الخاصة بـWindows أو
تقييم الامتيازات. لا تُدعم الحقوق العامة أو `MAXIMUM_ALLOWED` أو عروض السجل
البديلة أو واصفات الأمان المخصصة أو الفئات أو الروابط الرمزية. يتطلب الإنشاء
بمسار نسبي مقبضًا للأب المباشر مع `KEY_CREATE_SUB_KEY`. مفاتيح الإدخال غير
متطايرة؛ ويمكن إنشاء مفاتيح متطايرة، لكن يُرفض إنشاء مفتاح غير متطاير تحت أب
متطاير. لا يوجد نموذج لإعادة التشغيل أو الحفظ على القرص.

تنفذ `ZwQueryValueKey` فئات المعلومات Basic وFull وPartial وصيغ Align64
المعرّفة لها، بما في ذلك الأطوال الدقيقة والبيانات المحاذاة والإخراج الجزئي
والنتيجتان المختلفتان `STATUS_BUFFER_TOO_SMALL` و`STATUS_BUFFER_OVERFLOW`.
تغيّر `ZwSetValueKey` و`ZwDeleteValueKey` شجرة هذه الجلسة فقط. ترفض `ZwDeleteKey`
حذف مفتاح له مفاتيح فرعية قائمة؛ وتعيد مقابض المفتاح المحذوف
`STATUS_KEY_DELETED` إلى أن تُغلق. تحرر `ZwClose` المقبض بصورة مستقلة عن المفتاح،
ويفشل إلغاء التحميل المطلوب ما دامت هناك مقابض سجل مفتوحة.

الحدود هي 256 مفتاحًا بما فيها الأسلاف، و1024 قيمة إجمالًا، و65536 بايت لكل
قيمة، و512 KiB لمجموع بيانات القيم، و1024 بايت ASCII لمسار المفتاح، و256 بايت
لاسم القيمة، و256 مقبضًا مفتوحًا في الوقت نفسه. تخضع عمليات الإنشاء والتعديل
للحدود نفسها المطبقة في الفحص المسبق للسيناريو. يحتفظ `configuration.registry`
في التقرير بالإدخال الأصلي؛ ويسرد `registry` المسارات والقيم النهائية للمفاتيح
القائمة، بما فيها التعديلات المرصودة قبل التوقف. تُعرض حالة السجل غير المحددة
بالقيمة null. لا تتضمن لقطة القيم هذه خاصية التطاير أو هويات المقابض.

## فحص قبول مثال Microsoft

ينزّل [سكربت التحقق](../../scripts/validate_windows_driver_sample.py)، الذي يُشغّل اختياريًا، مصدر Microsoft SIOCTL عند المراجعة المثبّتة في [بيان التحقق](../../unittests/emulation/fixtures/sioctl-validation.json)، ويتحقق من تجزئات SHA-256، ثم يترجم المصدر غير المعدّل باستخدام ترويسات MinGW-w64 DDK. يحتفظ بالترخيص/المنشأ الأصليين وأوامر البناء والسيناريو والتقارير في مجلد المخرجات المختار. يتطلب وصولًا إلى الشبكة وClang و`lld-link` و`nm` وترويسات DDK الخاصة بـMinGW-w64:

```bash
python3 scripts/validate_windows_driver_sample.py \
  --neverd build-release/bin/neverd \
  --output build-release/driver-validation/sioctl
```

استخدم `--headers` إذا كان مجلد ترويسات MinGW-w64 في موضع غير افتراضي. ينشئ السكربت مكتبة استيراد MS COFF من اعتماديات ملف الكائن المترجم. يشغّل الفحص سيناريوهات buffered وin-direct وout-direct منفصلة عبر DriverEntry وcreate وIOCTL وcleanup وclose وunload. أضف `--debug` واختر مجلد مخرجات منفصلًا للترجمة مع `DBG=1` والتحقق من رسائل سجل الضيف. لا يسجّل المثال الأصلي معالج cleanup؛ لذلك يكمل المعالج الافتراضي في النموذج cleanup بالحالة `STATUS_INVALID_DEVICE_REQUEST` (`0xC0000010`). يستمر برنامج التشغيل في الإغلاق وإلغاء التحميل، ويعيد IOCTL الناجح البايتات المتوقعة. لهذا السيناريو الكامل، يكون رمز خروج CLI المتوقع **2** وتكون `scenario_success` بالقيمة false. ينجح السكربت نفسه فقط عندما تتطابق كل هذه النتائج، بما فيها فشل cleanup الظاهر؛ ولا يعيد كتابة المثال لإخفاء تلك النتيجة.

## التحقق من قبول مثال Zero

يبني [سكربت التحقق من Zero](../../scripts/validate_zero_driver_sample.py)
الإضافي مثال Zero WDM العام لبافل يوسيفوفيتش دون تعديل، باستخدام المراجعة
والتجزئات الموجودة في [ملفه التعريفي](../../unittests/emulation/fixtures/zero-validation.json).
شغّل `python3 scripts/validate_zero_driver_sample.py` مع متطلبات أدوات البناء
نفسها. تُحفظ الشفرة المصدرية ورخصة MIT والأوامر والسيناريو والتقرير افتراضيًا
تحت `build-release/driver-validation/zero`. تختبر تسعة طلبات القراءة المباشرة
عبر حدود الصفحات، وأعداد البايتات المكتوبة، والإحصاءات الذرية داخل الضيف،
وطلب IOCTL بإدخال/إخراج مخزّن مؤقتًا لقراءة الإحصاءات. يظل فشل القراءة ذات
الطول الصفري وغياب معالج CLEANUP في المثال ظاهرين؛ ورمز خروج CLI المتوقع هو
2، مع نجاح close وunload. لا ينجح سكربت التحقق إلا عند التطابق التام لهذه
النتائج وجميع بايتات الإخراج.

## التقارير وSDK

يميز تقرير JSON بين `stop_reason` و`nt_status` و`nt_success` القابلين للقيمة null، وبين PC عند التوقف وعدد التعليمات. ويحفظ استدعاءات API والحالة القابلة للمشاهدة التي جُمعت قبل التوقف، بما فيها كائنات الأجهزة وعناوين الاستدعاءات الراجعة لبرنامج التشغيل. تُمثّل عناوين الضيف بسلاسل سداسية عشرية حتى لا يفقد مستهلكو JSON دقة 64 بت. يسجّل الكائن `configuration` حدود التشغيل واسم الخدمة وتجاوزات `kernel_exports` وإدخال `registry`. اسم ملف التعريف هو `wdm-x64-synchronous-v2`. يظل `nt_status` نتيجة DriverEntry، بينما تصف `scenario_success` التهيئة والطلبات المكتملة معًا. تحدد `phase` و`requests` و`unload_completed` أي أجزاء دورة الحياة المطلوبة قد نُفّذت. يسجّل كل استدعاء API وكل عملية كتابة من المعالج مرحلتها أيضًا: `driver_entry` أو `request:N` أو `unload`. ويعرض كل طلب حالتي الإرسال والإدخال/الإخراج والإكمال وطول المعلومات وبايتات `output_hex` المعادة. يصف `preferred_image_base` العنوان الأساسي الأصلي لـPE. أما `security_cookie` فهو عنوان الضيف لملف تعريف الارتباط المهيّأ، أو `"0x0"` إن لم تكن هناك حاجة إليه. حقول الطلب هي `kind` و`device` و`file` و`byte_offset` و`code` و`irp` و`completed` و`dispatch_status` و`io_status` و`information` و`information_hex` و`output_hex`. يظل الحقل العددي `information` عدد JSON صحيحًا عشريًا دقيقًا؛ وتحفظ `information_hex` البتات نفسها أيضًا للعملاء الذين يقرؤون أعداد JSON بدقة لا تتجاوز 53 بت.

يحفظ الكائن `fault`، الذي يقبل null، أول عطل في الواجهة الخلفية. تميّز حقوله `kind` و`pc` والحقول القابلة للقيمة null، وهي `address` و`size` و`access` و`interrupt`، بين الذاكرة غير المعيّنة أو المحمية والنطاقات غير الصالحة والتعليمات غير الصالحة واستثناءات المعالج. تُستخدم سلاسل سداسية عشرية للعناوين وأعداد صحيحة للأحجام ومتجهات المقاطعة. لا يمكن لقراءات المشاهدة استبدال العطل الأصلي. لا يمكن للواجهة الخلفية المتعطلة استئناف التنفيذ، ولا يعني هذا السجل معالجة SEH داخل الضيف.

يعدّ `instructions` محاولات تنفيذ تعليمات الضيف التي سُمِح بها. لا تُحتسب التعليمة المرفوضة من سياسة التنفيذ؛ أما التعليمة المسموح بها التي تتعطل داخل المعالج فتُحتسب. لا تزيد عمليات إرسال API الاصطناعية أو علامة العودة هذا العداد.

يحمل كل عنصر `writes` القيمة `semantics: "attempted_guest_write"`: فهو يسجّل محاولة كتابة من المعالج خارج المكدس، بما فيها محاولة قد تتعطل لاحقًا أو تتوقف بسبب الميزانية. ولا يضمن اكتمال الكتابة، ولا يشمل الكتابات التي تنفذها نماذج API. تصف لقطات الأجهزة وكائن برنامج التشغيل الحالة المشاهدة عند توقف التنفيذ.

ضمّن `neverd/sdk/NeverDCAPIEmulation.h`، أو الترويسة الجامعة لـC API، وأنشئ جلسة ثم استدعِ `neverd_emulate_driver_json(session, path, options)`. يدخل المسار الصريح غير الفارغ مباشرةً إلى الفحص الصارم السابق للتنفيذ، دون التحميل أولًا عبر واجهة التحليل العامة. تستخدم CLI هذا المسار. يؤدي تمرير `NULL` للخيارات إلى اختيار القيم الافتراضية. تتطلب خيارات `neverd_driver_options_v1` الصريحة قيمة `struct_size` الدقيقة وميزانيات موجبة للتعليمات والذاكرة والأحداث والوقت. حرّر النتيجة باستخدام `neverd_free_string`.

أما تمرير `NULL` للمسار فيتطلب جلسة محمّلة، ويعيد تحليل ملفها بصورة مستقلة عن تحليل IR والتحميل المقيد بدوال محددة. يحافظ المساران على صورة الجلسة. أبقِ ملف الإدخال متاحًا ومن دون تغيير طوال مدة الاستدعاء. تعيد إخفاقات الطلب/الإعداد `NULL` وتضبط `neverd_last_error`؛ أما توقف التنفيذ فيعيد JSON. تظل الواجهة متاحة في البنى التي عُطّلت فيها الميزة، وتوضح طريقة تفعيلها.

تستخدم `neverd_emulate_driver_scenario_json(session, path, scenario_json, options)` خيارات v1 وقواعد الملكية نفسها، مع إضافة إدخال سيناريو صارم. تُطلب سلسلة JSON غير NULL ومنتهية بـNUL. يبقى ABI الأصلي لـ`neverd_emulate_driver_json` دون تغيير، ومقتصرًا على التهيئة. يوفّر محلّل C++ المسمى `driverOptionsFromScenarioJSON` التحقق نفسه من السيناريو لمستدعي `emulateDriver`.

نقطة الدخول الداخلية في C++ هي `neverd::emulation::emulateDriver` في `include/neverd/emulation/DriverSession.h`. تحليل الصيغ مسؤولية المحمّل الموجود؛ وسلوك كائنات/واجهات Windows مسؤولية `lib/emulation/windows`؛ وحالة المعالج وتنفيذه مسؤولية مهايئ Unicorn. يستخدم المهايئ والنموذج واجهة ذاكرة الضيف نفسها. لا ينتمي سلوك Windows API إلى تفريع Unicorn.
