# محاكاة برامج تشغيل Windows

ينفذ محاكي برامج التشغيل الاختياري في NeverD نقطة دخول PE لبرنامج تشغيل WDM x64 مدعوم، ويمكنه تنفيذ سيناريو طلبات صريح قبل إلغاء تحميله. تختار CLI باستخدام `auto` نقل KVM على مضيف Linux المطابق وWHP على Windows. تحتفظ إعدادات C++ الافتراضية السابقة وAPI V1 بـ Unicorn. تشترك جميع وسائل النقل في نموذج Windows المحدود الخاص بـ NeverD، الذي يعالج استدعاءات API الضيف ويعزل برنامج التشغيل عن نواة المضيف.

## محركات التنفيذ

يدعم `driver-strict` كلاً من KVM على مضيف Linux x64 المطابق وWHP على Windows x64 المطابق؛ يختار `auto` هذا النقل الأصلي، وتستخدم ISA المختلفة Unicorn. يحتفظ Unicorn الصريح وAPI V1 السابق بالملف البرمجي المحمول. يتحقق التنفيذ الأصلي من العناوين القانونية والآثار قبل الدخول؛ ويفشل العتاد غير المتاح دون تراجع. التعليمات وسلوك OS غير المدعومين أخطاء صريحة. تجتاز CI الأصلية على Windows x64 مع تعطيل Unicorn جميع الفحوص الإلزامية البالغ عددها 359:‏ 131 فحص CPU و224 نتيجة لبرامج التشغيل من 26 صورة مدمجة و46 صورة WDK و40 حالة سيناريو عند العناوين المفضلة والمعاد تموضعها، إضافة إلى أربعة فحوص لحدود SEH ([`9d4c130c`](https://github.com/NeverSight/NeverD/actions/runs/36981864458)). لا تزال أدلة التشغيل الأصلي ARM64 ناقصة، ولا تثبت هذه القدرة توافق أي برنامج تشغيل أو Android/Darwin.

يغطي التحقق الأصلي أعلاه نقاط دخول برامج التشغيل المعلنة والسيناريوهات المنشورة. وتبقى أدلة اختبارات الانحدار التفصيلية لكل ميزة وفحوص C API/CLI/Python الموضحة أدناه مقتصرة على Linux ما لم يُوثَّق تنفيذ Windows صراحةً؛ ولا يعني نجاح مجموعة الحالات الأصلية التحقق من جميع تنويعات الاختبارات على Windows.

يعلن `DriverImage.def` حدود الحجم والمحاذاة ونصوص التشخيص للتحقق الصارم من PE؛ وتأتي أحجام المؤشرات من `DriverProfile.def`. يتولى `DriverImage.cpp` التحقق وإعادة التموضع دون تغيير الصور المقبولة أو رسائل الخطأ.

على مضيف ARM64 يستخدم `checked-x64-v1` محرك Unicorn لضيف x64. تُفحص كل تعليمة ووصول للذاكرة قبل التنفيذ بخطوة واحدة، مع الحفاظ على فحوص كائنات Windows ومراقبي الكتابة واسماء RAM المستعارة وسياقات CPU فقط. تُقبل حسابات الذاكرة العددية والعمليات المقفلة المحاذاة طبيعياً وSETcc و`BT/BTS/BTR/BTC` ضمن فحوص القراءة/الكتابة؛ ويتولى التنفيذ الأصلي الأعلام. تشمل تعليمات SIMD المحدودة تحريكات ومنطق SSE/SSE2 و`MOVLHPS`/`MOVHLPS` وتحويلات/طرحاً عددياً مقنّعاً. تبقى سجلات XMM الستة عشر وMXCSR محفوظة عند الدخول والاستعادة. تتطلب أخطاء SIMD غير المقنّعة KVM/WHP الأصلي مع `precise_simd_exceptions`. يسجل تخزين XMM الكامل مراقبتي كتابة مرتبتين لكلمتي 8 بايت قبل تعديل أي منهما. تبقى صيغ aligned-vector غير المحاذاة مرفوضة. يمكن لمعاملات RAM العادية عبور صفحات مخصصة بشكل مستقل أو مستعارة؛ تُفحص صلاحيات كامل النطاق قبل الكتابة ويُحدد أول بايت يتعذر الوصول إليه. يحفظ MOVS العناصر المكتملة وسجلات استئناف العنصر المتعثر من دون تثبيت جزء من العنصر.

يسمح مشرف x64 بمعاملة MMIO عددية واحدة محاذاة بعرض 1/2/4 بايت. تبقى صفحات الجهاز خارج RAM الأصلية. ينفذ MOVS/REP MOVS عنصراً واحداً في كل حد استئناف. يلزم المصدر الجهاز معاينة قراءة محضرة بلا آثار قبل أن يستطيع مراقب الوجهة إيقاف التنفيذ؛ وتوفر سجلات Windows هذا التحضير، بينما ترفض الأجهزة الأخرى القراءة النصية قبل الآثار. تبقى RMW للأجهزة وMMIO الأوسع وI/O المنافذ غير مدعومة. تُقارن بايتات الطلبات وحالة الجهاز وأحداث الكتابة مستقلةً عن اختلاف عدد تعليمات REP مع Unicorn. يستخدم KVM واجهة XSAVE القياسية لنقل XMM/MXCSR وبتات FP/SSE. هذا عقد مشرف لا يوفر بيئة مستخدم. لا يوجد إيقاف غير متزامن عام أو تبديل محرك بعد بدء الضيف؛ ويُفحص timeout والإلغاء بين التعليمات المقبولة المحدودة. تُقارن مجموعة برامج التشغيل الأصلية والمتاحة من WDK بـUnicorn، بما فيها صور normal/CFG والمعاد تموضعها؛ اتفاق المجموعة لا يثبت توافق برنامج تشغيل اعتباطي.

يقبل x64 المفحوص أيضاً الأشكال القديمة المقنّعة `SS` و`SD` و`PS` و`PD` للتعليمات `ADD` و`SUB` و`MUL` و`DIV` و`SQRT` و`MIN` و`MAX`. يوحّد `X64SSEInstructions.def` عروض المعاملات والمحاذاة وقواعد القبول. يقارن `MaskedSSEArithmeticMatchesIndependentHostExecution` أشكال السجلات وRAM بمرجع مستقل على CPU المضيف، شاملاً أوضاع التقريب الأربعة وFTZ والأصفار الموقّعة والمدخلات دون الطبيعية وNaN. ويتحقق `SSEMemoryObserverStopsBeforeResultAndStatusChanges` من التوقف قبل الآثار.

خيارات البناء هي `NEVERD_EMULATION_BACKEND_KVM` و`NEVERD_EMULATION_BACKEND_WHP`. يتطلب KVM صلاحية الوصول إلى `/dev/kvm`. يحمّل WHP مكتبة النظام ديناميكياً. تضيف الواجهة `neverd_emulate_driver_backend_json` مع الحفاظ على ABI v1. يسجل التقرير المحرك والعقد وسبب الاختيار.

```bash
build-release/bin/neverd emulate-driver path/to/driver.sys \
  --backend auto --execution-contract checked-x64-v1
```

## البناء والتشغيل

يجب تفعيل هذه الميزة صراحةً، وهي مستقلة عن `BUILD_TESTING`:

```bash
cmake -S . -B build-release -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DNEVERD_ENABLE_DRIVER_EMULATION=ON
cmake --build build-release --target neverd --parallel 4
build-release/bin/neverd emulate-driver path/to/driver.sys \
  --instruction-limit 100000 > driver-report.json
```

يُكتب التقرير دائمًا بصيغة JSON إلى stdout، بينما تُكتب رسائل تشخيص الطلبات والإعداد إلى stderr. الحدود الافتراضية هي 100000 تعليمة ضيف، و64 MiB من ذاكرة الضيف، و10000 حدث مسجّل، و5000 ملّي ثانية. يجب أن يكون حد التعليمات موجبًا. يؤدي نفاد ميزانية التنفيذ إلى إيقافه مع الاحتفاظ بالمشاهدات الجزئية؛ وتحافظ واجهات التخصيص على عقود الإرجاع عند نقص الموارد، بما فيها NULL لتعيينات MMIO الموضحة أدناه.

| رمز الخروج | المعنى |
|------------|--------|
| `0` | نجحت التهيئة وكل العمليات المطلوبة التي اكتملت |
| `1` | مدخلات/خيارات غير صالحة، أو فشل الإعداد، أو تعطيل الميزة وقت البناء |
| `2` | أعادت التهيئة أو أحد الطلبات المكتملة قيمة `NTSTATUS` تدل على الفشل |
| `3` | توقف التنفيذ قبل اكتمال السيناريو، مثل الوصول إلى API غير مدعوم أو وقوع عطل أو بلوغ حد الميزانية |

تُعد حالة الفشل المعادة مشاهدة مكتملة لتلك العملية. أما العودة الناجحة فتصف هذا التشغيل داخل النموذج فقط؛ ولا تثبت أن برنامج التشغيل يعمل تحت Windows.

## توافق برامج التشغيل

يُحدّد التوافق وفق مسار الشفرة المنفّذ واعتمادياته، لا وفق امتداد `.sys`. تشمل أدلة القبول الحالية fixtures مستقلة أصلية ومسارات buffered وin-direct وout-direct لمثال Microsoft SIOCTL WDM، بما فيها البناء الذي يسجّل رسائل التصحيح، وكذلك القراءة والكتابة المباشرتان في المثال العام Zero لبافل يوسيفوفيتش. ولا يثبت ذلك التوافق مع برامج تشغيل عشوائية من جهات خارجية.

| فئة برنامج التشغيل أو متطلبه | النطاق الحالي | البيئة الناقصة |
|------------------------------|---------------|----------------|
| برنامج تشغيل برمجي x64 WDM يستخدم الواجهات المدرجة | تهيئة x64 WDM محدودة وطلبات buffered/direct متسلسلة وعناصر عمل ومؤقتات وDPC وأحداث وانتظار وتقارير وحدود | يحتاج كل API إضافي يُنفّذ إلى نموذج محدد |
| `METHOD_BUFFERED` IOCTL | عمليات buffered/direct متسلسلة مع إكمال بعنصر عمل أو DPC | واجهات المجموعة أدناه فقط؛ دون تقديم متزامن عشوائي لسيناريوهات عامة أو الإلغاء العام لطلبات WDM |
| `METHOD_IN_DIRECT` و`METHOD_OUT_DIRECT` | MDL مملوكة للطلب وتعيينات نظام وهويات PFN مشتركة للقراءة فقط | تعيينات المستخدم وواجهات DMA خارج المجموعة الموضحة أدناه |
| MDL ينشئها برنامج التشغيل | واصفات مستقلة أو مرتبطة بـ IRP، وMDL جزئية، وتعيينات مستخدم/نظام مشتركة، وتحرير عند الإكمال | الحصص وقوائم MDL اليدوية وواجهات تخصيص الذاكرة الافتراضية العامة |
| READ/WRITE | عمليات buffered/direct/neither متسلسلة مع إكمال بعنصر عمل أو DPC | واجهات المجموعة أدناه فقط؛ دون تقديم متزامن عشوائي لسيناريوهات عامة أو الإلغاء العام لـWDM أو موضع ملف ضمني |
| WDM `METHOD_NEITHER` | عناوين مستخدم منفصلة وفحص الوصول وقفل MDL وهوية طالب اصطناعية وإلغاء وصول بعد الإرسال أو خروج العملية وإلغاء WDM محدود | واجهات العمليات وتخصيص الذاكرة الافتراضية العامة غير المذكورة |
| برنامج KMDF 1.33 غير PnP | الربط والكائنات/السياقات وأجهزة التحكم المسماة والطوابير الافتراضية المتسلسلة أو المتوازية ذات الحد المحدود أو غير المحدود والطلبات المخزنة/المباشرة/neither مع تنفيذ الاستدعاءات الراجعة | لا دعم لسلوك PnP خارج المجموعة الموضحة أو الجدولة العامة للطوابير أو امتدادات الفئات أو UMDF |
| برنامج تشغيل ناقل/وظيفة/مرشّح PnP | PDO صريح بلا موارد أو مع بنوك سجلات وAddDevice ضيف وثماني وظائف فرعية شائعة لدورة PnP | عمليات PnP الأخرى وسياسة الطاقة العامة والعتاد/الموارد العامة وKMDF PnP العام |
| برامج تشغيل التخزين والشبكة والعرض ونظام الملفات والمرشحات المصغرة | عقود الأنظمة الفرعية غير مدعومة | أطر المنفذ/الفئة/المنفذ المصغّر وخدمات NDIS/WFP والرسومات أو نظام الملفات |

| برنامج تشغيل عتاد أو DMA أو PCI أو مقاطعات أو افتراضية | بنوك سجلات صريحة وMMIO ومقاطعات latched وlevel_sensitive حصرية أو مشتركة، وDMA متسق محدود للمخازن المشتركة وSG والقنوات | نماذج أجهزة أخرى وRAM مادية اعتباطية وPCI والمنافذ وواجهات DMA الأخرى وحالة CPU ذات الامتيازات |

| x64 CFG | جداول أهداف متحقق منها واستدعاءات check/dispatch؛ تحتفظ الأدوات غير النشطة بدوال الضيف البديلة | يظل XFG وقمع التصدير وإعداد التحميل غير الممثل وTLS مرفوضًا |

يمكن أن يظل استيراد غير مدعوم لكنه غير مستخدم مرتبطًا. يؤدي الوصول إلى عملية غير مدعومة إلى التوقف مع رسالة تشخيص والمشاهدات التي جُمعت حتى تلك النقطة. لا يثبت نجاح DriverEntry وحده دعم مسارات الإرسال اللاحقة أو العتاد أو إطار العمل. جدول API أدناه هو المرجع المعتمد للمجموعة الفرعية المدعومة.

## عقد التنفيذ

يمثل الملف دورة حياة x64 WDM على CPU0 بجدولة تعاونية حتمية افتراضيًا. يبدأ التنفيذ من نقطة دخول PE، مع إبقاء غلاف الدخول الذي أنشأه المترجم إن وُجد. يجب أن يعيد DriverEntry القيمة `STATUS_SUCCESS` لنجاح التهيئة؛ أما حالة نجاح غير صفرية أو حالة pending فتوقف التنفيذ باعتبارها عقد تهيئة غير مدعوم. تُحفظ حالة الفشل بوصفها نتيجة تهيئة مكتملة. تقع كل الكائنات والسلاسل والمكدسات ومؤشرات الدوال والتخصيصات في ذاكرة الضيف. يوفّر النموذج `DRIVER_OBJECT` ومسار سجل لاسم الخدمة المضبوط، وقيمته الافتراضية `NeverDDriver`. يستخدم المهايئ نمط TLB الافتراضي في Unicorn للحفاظ على عناوين الضيف الافتراضية، بما فيها عناوين النواة العليا القياسية (canonical)، من دون تركيب جداول صفحات Windows. قيمة RFLAGS الابتدائية هي `0x202`؛ ويستخدم ملف تعريف الجهاز البرمجي سطر ذاكرة مخبئية ثابتًا بحجم 64 بايت. هذه خصائص صريحة لسيناريو التنفيذ هذا.
تُظهر قراءات x64 المضمّنة لسجل CR8 قيمة `PASSIVE_LEVEL` / `DISPATCH_LEVEL` نفسها؛ وتظل كتابة CR8 والعمليات الأخرى على سجلات التحكم غير مدعومة.

لا يكشف هوية الخيط المنطقي الحالي المعتمة والمستعارة إلا وصول مطلق للقراءة فقط بعرض 8 بايت إلى `GS:[0x188]`. تنفّذ صيغ المترجم مثل `MOV` و`CMP` التعليمة الأصلية في الخلفية مع آثارها الأصلية على السجلات والأعلام. تحافظ الاستدعاءات المتداخلة في الخيط نفسه على الهوية، وتختلف الخيوط المستقلة، وتستخدم خيوط النظام الممثلة كائنها الموجود. يوفّر عرض المعالج الخاص هذا الحقل فقط دون تمثيل KPCR كامل أو منح وصول للبنية أو ملكية مرجع. تبقى إزاحات GS الأخرى وجميع وصولات FS والقراءات المفهرسة أو الجزئية والكتابات غير مدعومة.

تُربط الاستيرادات المجهولة بمصائد مؤجلة. لا يمنع الاستيراد غير المستخدم التنفيذ؛ لكن تنفيذ thunk الخاص به أو قراءة قيمة بيانات مصدّرة غير ممثلة في النموذج يؤدي إلى `unsupported_api`. تؤدي تأثيرات بيئة المعالج غير المدعومة أيضًا إلى توقف صريح. لا يستبدل NeverD الاستدعاءات غير المنفذة بقيم نجاح. تفشل الصور المشوّهة أو متطلبات التحميل غير المدعومة قبل التنفيذ.

تعمل عناصر `DelayedWorkQueue` عند `PASSIVE_LEVEL` واستدعاءات DPC للضيف عند `DISPATCH_LEVEL` مع الوسائط الأربع المحددة. تجري افتراضيًا جدولة تعاونية حتمية على CPU0 عند عودة الاستدعاءات والانتظار الحاجب. تستخدم المؤقتات النسبية والمطلقة والدورية وقتًا افتراضيًا يتقدم إلى موعد المؤقت أو الانتظار أو الإلغاء التالي حين لا يوجد إطار قابل للتنفيذ. تحتفظ أحداث ومؤقتات الإشعار والمزامنة بقواعد استهلاك الإشارة المختلفة. لكل استدعاء راجع مكدس ضيف منفصل؛ وتحفظ إطارات محجوبة متعددة متغيراتها المحلية وسياقات CPU الكاملة مع مشاركة الذاكرة. يمرر Win64 أول أربعة وسائط في السجلات والبقية على المكدس. تكون الطلبات متسلسلة افتراضيًا: على الإرسال الذي يعلّم IRP كمعلّق إرجاع `STATUS_PENDING`، ويُنتظر اكتماله قبل الطلب التالي ما لم يُستخدم `defer_callback_drain: true` صراحةً لتجميع محدود وفق العقد الموضح أدناه. دون مصدر متاح يتوقف الطلب المعلّق أو الانتظار اللانهائي بسبب التعطل مع `model_error`. تبقى ميزانيات التعليمات والذاكرة والملاحظات والوقت الفعلي مشتركة.

هذا نموذج جدولة محدود وليس دعمًا كاملًا لسلوك Windows غير المتزامن. يظل الانتظار القابل للتنبيه أو بنمط المستخدم وAPC والإلغاء العام لطلبات WDM وتقديم السيناريوهات العامة المتزامن وUMDF وعقد KMDF PnP الكامل خارج النطاق الموصوف والجدولة العامة للطوابير وPnP/الطاقة الكامل والعتاد العام وواجهات DMA الأخرى غير مدعوم. تنفذ التهيئة وحدها الاستدعاءات المصطفة صراحةً دون إنشاء طلبات أو إلغاء تحميل ضمنيًا.

يخرج عنصر العمل من الطابور قبل بدء استدعائه الراجع، لذا يمكن للاستدعاء تحرير عنصره الخاص. يفشل صراحةً تحرير عنصر ما زال مصطفًا أو تكرار إدراجه أو استخدام كائنات منتهية الصلاحية أو عنوان استدعاء خارج ذاكرة الضيف القابلة للتنفيذ. يبقى مرجع الجهاز حتى عودة الاستدعاء. يتطلب إلغاء التحميل تحرير جميع العناصر وإكمال العمل المصطف. تحفظ سياقات المعالج السجلات العامة وحالة SIMD وFPU والتحكم؛ وتبقى ذاكرة الضيف مشتركة، ولا تسمح استعادة السياق باستئناف معالج تعرض لعطل.
يؤجّل الحذف ما دامت كائنات الملفات أو مراجع عناصر العمل المصطفة/الجارية موجودة. يعيد تخصيص عنصر العمل NULL عند نفاد مساحة الكائنات.

تستخدم الصور عنوانها الأساسي المفضّل ما لم يختر السيناريو عنوان نقل صالحًا، ويجب أن تكون ملفات تنفيذية PE32+ x64 ذات نظام فرعي native. يمكن أن تأتي الاستيرادات من `ntoskrnl.exe` أو `ntkrnlmp.exe` أو `HAL.dll` أو `WDFLDR.SYS`. يدعم محمّل التنفيذ عمليات نقل العنوان الأساسي x64 `DIR64` التي اجتازت التحقق، وإعداد تحميل محدودًا لملف تعريف الارتباط الأمني security cookie؛ وتُهيّأ قيمته داخل الضيف بصورة حتمية قبل غلاف الدخول. تُرفض حقول إعداد التحميل الأخرى غير الممثلة وTLS والاستيرادات المؤجلة/المربوطة والاستيرادات برقم ordinal والصور المُدارة. يجب أن تجتاز الصور أيضًا فحوصًا صارمة للنطاقات والمحاذاة.

يتحقق Control Flow Guard (CFG) النشط من أعلام PE وخانات المؤشرات والأهداف القابلة للتنفيذ المرتبة. تسمح مساعدات check/dispatch بمداخل الصورة المعلنة أو نقاط API المسجلة فقط، وتحفظ حالة استدعاء Win64 وترفض الأهداف غير المعلنة. تحتفظ الأدوات دون CFG نشط بمؤشرات الضيف البديلة الأصلية. يظل XFG النشط وقمع التصدير وسياسات الحماية غير الممثلة مرفوضًا؛ وجود العنوان في ذاكرة قابلة للتنفيذ لا يجعله هدفًا صالحًا وحده.

يمكن أن تضم مكدسات WDM عدة أجهزة يملكها برنامج التشغيل الضيف نفسه. يربط `IoAttachDeviceToDeviceStack` مصدرًا منفصلًا فوق القمة الحالية للهدف ويعيد القمة السابقة، ويضبط `StackSize` و`AlignmentRequirement` دون تغيير قائمة `NextDevice` أو نسخ أعلام التخزين المؤقت. يتلقى `IoDetachDevice` الجهاز الأدنى المحفوظ ويتطلب `PASSIVE_LEVEL`؛ ويُسمح بالإرفاق حتى `DISPATCH_LEVEL`. فتح جهاز أدنى مسمى يرسل الطلب إلى القمة الحالية، بينما يحتفظ `FILE_OBJECT.DeviceObject` والتقرير بهوية الجهاز المسمى. تستخدم READ/WRITE أعلام القمة المختارة. يحتفظ مسار الطلب بجميع الأجهزة حتى عودة الإرسال، حتى بعد الفصل أو الحذف؛ ولا تزيد المراجع الداخلية `ReferenceCount` الذي يعد المقابض المفتوحة.

يستدعي `IofCallDriver` والمساعد `IoCallDriver` الهدف المحدد بالضبط في المسار المحفوظ. تعمل الدوال المضمنة الحقيقية `IoCopyCurrentIrpStackLocationToNext` و`IoSkipCurrentIrpStackLocation` و`IoSetCompletionRoutine` على IRP الضيف الأصلي، مع التحقق من المؤشر والعدد وأعلام التحكم. يعيد الإرسال الأدنى حالته الفعلية بصورة مستقلة عن `IoStatus` وقيمة عودة دالة الإكمال. يقدم فك الإكمال المؤشر ويختار الاستدعاءات بحسب النجاح أو الخطأ أو الإلغاء وينقل pending إلى الأعلى. تتولى دالة الإكمال المستدعاة هذا النقل، بما في ذلك بعد عودة `STATUS_PENDING` السابقة. يوقف `STATUS_MORE_PROCESSING_REQUIRED` الفك مع إبقاء IRP وMDL والمخازن صالحة، ويستأنفه إكمال لاحق. يتطلب الإكمال المتداخل نتيجة توقف خارجية، ولا تُحرر الذاكرة إلا مرة واحدة عند الفك النهائي. تحتفظ الاستمراريات المحددة بمالك من النظام الفرعي بإطارات WDM/WDF المتداخلة وIRQL الموروث. يُصفّر كل موضع أدنى مستهلك قبل استدعاء دالة الإكمال العليا.

يدعم `IoAllocateIrp` و`IoFreeIrp` طلبات IRP المملوكة للمتصل حتى `DISPATCH_LEVEL` مع `ChargeQuota=FALSE`. يتحقق أول `IoCallDriver` من الطلب ويحفظ المسار الأدنى الدقيق. يدعم هذا النطاق `IRP_MJ_INTERNAL_DEVICE_CONTROL` في النواة بمخازن `METHOD_NEITHER` التي يملكها برنامج التشغيل، دون ملف مستخدم أو نسخ مخازن المستخدم. تُنفّذ دوال الإكمال والإلغاء الحقيقية في الضيف. يتطلب تحرير الطلب داخل الإكمال إرجاع `STATUS_MORE_PROCESSING_REQUIRED`؛ ينتهي الوصول فورًا وتبقى البيانات الوصفية حتى عودة الإطارات. يمكن تحرير الطلب غير المرسل؛ وتفشل صراحةً التسريبات والتحرير المكرر والطلبات الأجنبية أو التي ما زالت مملوكة لعملية جارية. تظل إعادة الاستخدام العامة والصيغ الأخرى و`IoBuildDeviceIoControlRequest` غير مدعومة.

تستخدم المشاهدات `kind: "internal_ioctl"` و`origin: "driver_allocated_irp"` و`file: null` مع حفظ `code` و`irp` والحالات ووقت الإلغاء و`information_hex` الدقيق. ترفض السيناريوهات الأصلية وJSON قيمة `internal_ioctl` قبل التحميل؛ ولا تنشئ هذه الصفوف إلا عمليات تخصيص وإرسال حقيقية من الضيف.

خارج بروتوكول USB idle أدناه، يجب أن يكون الهدف الأدنى جهاز WDM ضيفًا حيًا، وأن تغطي دالة الإكمال النجاح والخطأ والإلغاء. يستخدم المثال الحقيقي `driver_wdm_owned_irp.c` المسارين `NEVERD_WDM_OWNED_IRP_FIXTURE` / `NEVERD_WDM_OWNED_IRP_CFG_FIXTURE`. يتحقق [سيناريو IRP المتصل](../examples/driver-owned-irp-scenario.json) من الإكمال المؤجل. تغطي صور normal/active-CFG العناوين المفضلة/المعاد تموضعها؛ ويحفظ C API/CLI صفوف النواة المستقلة. تُتخطى النتائج المفقودة صراحةً؛ وتظل أدلة التنفيذ مقتصرة على Linux.

يلغي المثال طلبًا فرعيًا واحدًا عمدًا؛ لذا يُتوقع رمز خروج CLI بقيمة 2 و`scenario_success: false` مع `stop_reason: "returned"` وإلغاء تحميل سليم وصفر أخطاء في المثال. يمكن حفظ لقطة من خرج النواة المكتمل في `output_hex`، وتبقى ملكية المخزن المؤقت للسائق.

تبقى وظائف PnP الفرعية الأخرى، ونماذج العتاد والموارد العامة غير مدعومة. يُرفض صراحة تمرير WDF خارج دورة حياة الملف في مسار FDO/PDO المباشر، والإرفاق إلى مكدسات ذات ملفات أو استدعاءات نشطة، وفصل طبقة وسطى، وتغيير الوظيفة الرئيسية، والاستهداف خارج المسار المحفوظ. يستخدم المثال الأصلي الاختياري `driver_wdm_stack.c` المبني بـWDK الحقيقي المسارين `NEVERD_WDM_STACK_FIXTURE` و`NEVERD_WDM_STACK_CFG_FIXTURE`. تشمل الاختبارات الأصلية وC API/CLI إعادة التموضع؛ وتُتخطى المنتجات المفقودة صراحة. تبقى أدلة التنفيذ مقتصرة على Linux.

يمكن أن يحدد السيناريو صراحة حتى 64 عنصرًا في `pnp_devices`. يتطلب كل عنصر `id` و`bus: "resource_free"` / `bus: "register_bank"` و`initial_device_power: "D0"` و`initial_system_power: "working"`؛ ولا تُخمّن الحقائق الغائبة. المعرفات ASCII حساسة لحالة الأحرف بطول 1–64 بايت، تبدأ بحرف أو رقم ولا تحتوي بعده إلا على الحروف والأرقام و`_` و`-` و`.`. يمكن للطلب العادي استخدام `device_id` مهيأ بدل `device`، لا كليهما. يتطلب `kind: "pnp"` الحقول `device_id` و`minor` و`bus_completion`؛ والقيم المدعومة هي `start` و`query_remove` و`cancel_remove` و`remove` و`query_stop` و`stop` و`cancel_stop` و`surprise_removal`. الحقل `bus_completion.status` إلزامي كعدد 32 بت أو نص سداسي عشري؛ و`delay_100ns` اختياري، عدد صحيح غير سالب حتى INT64_MAX من الاستلام الفعلي لدى المزوّد. لا يُقبل `STATUS_PENDING` كحالة نهائية؛ ويتطلب stop/cancel-stop/surprise-removal/cancel-remove/remove القيمة `STATUS_SUCCESS` (0) بالضبط. يرفض PnP حقول الملفات والنقل والإلغاء حتى إذا كانت صفرًا. تطبق واجهة C++ الفحص نفسه.

بعد نجاح DriverEntry ينفذ `AddDevice` مرة لكل PDO مهيأ، مع `DRIVER_OBJECT` مستقل يملكه المزوّد؛ لا يمكن للضيف حذف كائناته أو انتحالها. طلبات PnP IRP هي `KernelMode` بلا ملف وبموارد حسب الناقل المهيأ، وحالتها الأولية `STATUS_NOT_SUPPORTED`. لا تُستهلك استجابة الناقل إلا عند وصول التمرير إلى PDO؛ ويستخدم الإكمال المؤجل الساعة الافتراضية والاستمراريات القائمة. يقرر الإكمال العلوي النهائي تثبيت الحالة أو التراجع مستقلًا عن حالة الناقل. يتطلب نجاح PnP إكمال المزوّد فعليًا؛ وقد يترك فشل START/QUERY_STOP/QUERY_REMOVE المبكر ملاحظات الناقل null. تتطلب الإزالة العادية من Started نجاح query وإغلاق الملفات وانتهاء الطلبات السابقة وفصل/حذف الضيف. تبقى هوية الجهاز/الملف بعد الفصل. فشل AddDevice النظيف يحرر المزوّد فقط؛ وتسرب أجهزة ضيف جديدة، ولو مفصولة، يسبب `model_error`. يجب غياب جميع المزوّدين قبل unload. لا يشمل ذلك بقية PnP أو سياسة الطاقة العامة أو العتاد/الموارد العامة أو KMDF PnP العام.

تحفظ `configuration.pnp_devices` الإعداد الأولي. تحتوي `pnp_devices` المرصودة على `id` و`pdo` و`add_device_status` القابل لـnull و`attached` الحالي و`pnp_state` و`provider_present`؛ وبعد الإزالة يصبح `attached` false. مرحلة AddDevice هي `add_device:<ID>`؛ ويؤثر الفشل في `scenario_success` دون استبدال `nt_status` لـDriverEntry. يضيف كل طلب `device_id` و`pnp` القابلين لـnull؛ ويكون `file` في PnP هو null. يسجل `pnp` الحقول `minor` و`state_before` و`state_after` و`bus_status` القابل لـnull و`bus_received_at_100ns` و`bus_completed_at_100ns`. لا تصبح الحالة المهيأة ملاحظة إلا عند إكمال الناقل فعليًا؛ ووقت الاستلام مستقل. لا تتغير أنواع الحقول السابقة.

يحدد الحقل الاختياري `parent_id` الموفّر الأب بواسطة معرّفه المضبوط. يمكن أن يظهر الأب لاحقًا في المصفوفة؛ وحذف الحقل يعني جذرًا مستقلًا. ترفض الفحوص الأصلية وفحوص JSON الآباء المجهولين والإشارات إلى الذات والدورات والمعرّفات غير الصالحة قبل إنشاء PDO. لا ينشئ هذا الرسم روابط إرفاق WDM أو علاقات أبوة بين كائنات WDF. يحتفظ الحقلان المرصودان `parent_id` و`parent_pdo` بالهوية الأصلية بعد سحب أي من الموفّرين. يتطلب START للجهاز الفرعي أبًا حاضرًا بحالة Started وفي D0 الفيزيائية، دون انتقال معلّق لدورة الحياة أو الطاقة. يتطلب STOP وSurpriseRemoval للأب خروج الأجهزة الفرعية من حالات PnP النشطة وإنهاء الانتقالات وWAIT_WAKE. ويتطلب REMOVE سحب جميع الموفّرين الفرعيين أولًا. لا يحدث تسلسل ضمني للإزالة.

تصل طلبات CREATE/READ/WRITE/IOCTL/CLEANUP/CLOSE العادية إلى إرسال الضيف الحقيقي ما دام الجهاز موجودًا خارج Removing/Removed. لا يختلق النموذج فشلًا بسبب Stopped أو StopPending أو RemovePending أو حالة الطاقة؛ يقرر برنامج التشغيل إكمال I/O البرمجي أو رفضه أو احتجازه. يعمل المنفذ العام تسلسليًا افتراضيًا، مع استثناء التجميع المحدود الصريح باستخدام `defer_callback_drain` الموضح أدناه؛ خارج هذا العقد لا يمكن تحرير IRP محتجز بلا منتج متاح حاليًا عبر start/cleanup لاحق في السيناريو، فيتوقف مع `model_error` بسبب التعطل. إغلاق الملفات وإنهاء الطلبات السابقة قبل Remove قيود خاصة بهذا الملف التعريفي. تُرفض حالة `query_stop` النهائية `STATUS_RESOURCE_REQUIREMENTS_CHANGED` (0x119) في الفحص المسبق والإكمال النهائي للضيف، لأنها تطلب إعادة استعلام موارد غير ممثلة؛ انظر [عقد QUERY_STOP من Microsoft](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/irp-mn-query-stop-device). لا يضيف stop/restart وsurprise-removal إعادة تخصيص الموارد.

يستخدم PnP بلا موارد المثال الأصلي `driver_wdm_pnp.c` مع WDK الحقيقي والمسارين الاختياريين `NEVERD_WDM_PNP_FIXTURE`/`NEVERD_WDM_PNP_CFG_FIXTURE` واختبارات أصلية وC API/CLI. تُتخطى المنتجات المفقودة صراحة؛ وتبقى أدلة التنفيذ مقتصرة على Linux.

تنفذ أقفال إزالة WDM الصادرات الفعلية `IoInitializeRemoveLockEx` و`IoAcquireRemoveLockEx` و`IoReleaseRemoveLockEx` و`IoReleaseRemoveLockAndWaitEx`؛ أسماء WDK دون Ex هي وحدات ماكرو. المالك هو DEVICE_OBJECT المحدد الذي يحتوي امتداده كامل التخزين المحاذى، مستقلاً عن حالة PDO أو شكل Tag. يمكن التهيئة قبل الإرفاق. تدعم أحجام retail 32 وDBG 120 بايت بشرط وسيط حجم مستقل مطابق؛ تصبح المنطقة المسجلة كلها معتمة. تُعد Tags الفارغة NULL والمتكررة لكل قفل ولا تُفك مؤشراتُها، فيصح release بعد إكمال IRP. تتطلب التهيئة وAndWait مستوى `PASSIVE_LEVEL`؛ ويسمح acquire/release بـ`DISPATCH_LEVEL`.

يغلق AndWait قبول الاكتسابات، ويحرر اكتساباً مطابقاً واحداً، ويوقف إطار الضيف الحقيقي حتى تحرر البقية. يعيد acquire اللاحق `STATUS_DELETE_PENDING` بلا التزام release. يثبت آخر release الجاهزية قبل عودة callback، فيمكن للعامل التحرير ثم انتظار حدث من REMOVE المستأنف. لا يُنشأ callback مصطنع أو مهلة أو نجاح دون منتج. يلزم مسار REMOVE نشط مرتبط يحتوي المالك واستلام فعلي لدى المزود (`bus_received_at_100ns` يقبل الصفر)، وليس الإكمال الأدنى. وضع REMOVE في طابور أدنى قبل وصوله للمزود خارج النطاق؛ هذا ليس تحقق OutsideRemoveDevice/Driver Verifier كاملاً. تبقى الملفات المغلقة والطلبات السابقة المكتملة شرطاً قبل REMOVE، لكن يمكن بقاء callbacks التي تحرر الأقفال. يحتفظ المسار بهويته خلال الانتظار والفصل/الحذف وpending الأدنى حتى عودة الإطارات المتبقية.

يفشل التخزين المجهول/غير المطابق وrelease بلا اكتساب وتكرار drain وإعادة التهيئة وحذف الامتداد مع اكتسابات أو انتظار drain غير مستهلك قبل التعديل. يسمح فشل AddDevice النظيف بحذف قفل مهيأ غير مستخدم. لا تستبدل الأقفال مراجع الجهاز/العامل الفعلية؛ يُلغى التسجيل عند تقاعد الامتداد الفعلي فقط. لا تفعل بيانات debug حدود Verifier الزمنية/high-water. يستخدم الأصل `driver_wdm_remove_lock.c` المتغيرات `NEVERD_WDM_REMOVE_LOCK_FIXTURE`/`NEVERD_WDM_REMOVE_LOCK_CFG_FIXTURE`/`NEVERD_WDM_REMOVE_LOCK_DBG_FIXTURE`/`NEVERD_WDM_REMOVE_LOCK_DBG_CFG_FIXTURE`. تُتخطى المنتجات المفقودة صراحة؛ الأدلة الأصلية وC API/CLI مقتصرة على Linux ولا تعني مدير إزالة كاملاً أو تصريف I/O متزامن عاماً.

يضيف الناقل الاصطناعي `bus: "register_bank"` موارد ذاكرة ثابتة ومحددة صراحة إلى PDO. تحتوي مصفوفة `resources` عند وجودها على `id` و`raw_start` و`translated_start` و`length` و`registers`؛ ويتطلب كل سجل `offset` و`width` و`access` ‏(`read_only` أو `read_write`) و`value` ابتدائية. يحدد `DriverResources.h` / `DriverResources.def` عقد C++ وJSON المشترك. تتبع معرفات الموارد قواعد ASCII المحدودة وتكون فريدة داخل كل PDO. الحدود هي 8 موارد لكل PDO / 32 إجمالًا، و256 سجلًا لكل مورد / 4096 إجمالًا، و1–1048576 بايت لكل مورد. لا يُدعم إلا الوصول الدقيق بعرض 1/2/4 بايت مع محاذاة طبيعية؛ ويجب أن تتسع القيم ضمن العرض. يجب ألا يفيض النطاقان الفيزيائيان؛ ولا تتداخل النطاقات الخام داخل PDO أو النطاقات المترجمة على المستوى العام. تجعل `registers` الفارغة البنك كله غير قابل للوصول صراحة. العناوين والقيم الابتدائية تصريحات وليست عتاد المضيف أو ذاكرة مصفّرة افتراضيًا. يظل `resource_free` بلا قائمة موارد وبمؤشرات START فارغة.

يتلقى START تخصيصين منفصلين للقراءة فقط من `CM_RESOURCE_LIST` الخام والمترجم، مع واصفات Memory متقابلة ومرتبة: واصف كامل واحد، وواجهة Internal، وناقل 0، وإصدار/مراجعة 1، ومشاركة DeviceExclusive، وأعلام READ_WRITE للنطاق. تبقى صلاحية RO لكل سجل مستقلة. يتيح نجاح START الأدنى التخصيص قبل الاستدعاءات العليا؛ وينشئ كل START من NotStarted/Stopped جيل موارد جديدًا بالتخصيص الثابت نفسه. تُهيّأ قيم السجلات من تكوين PDO وتبقى بعد إلغاء التعيين وSTOP وإعادة التشغيل. يتطلب فشل START ونجاح STOP/REMOVE أن يحرر برنامج التشغيل التعيينات قبل الإكمال النهائي لـIRP؛ ولا تُنظّف ضمنيًا. تمنع الإزالة المفاجئة التعيينات الجديدة والوصول إلى السجلات فورًا، مع السماح بإلغاء التعيينات الموجودة. يغيّر نجاح إكمال SET الجهاز الفعلي لدى المزوّد إمكانية الوصول الفيزيائي: تمنع D3 الوصول، وتسمح D0 به فقط عند إتاحة التخصيص. تسمح D3 بإنشاء تعيين دون الوصول إلى السجلات؛ وتحفظ D3hot التعيينات والقيم؛ تعيد دورة D3cold الصريحة القيم المكوّنة قبل الوصول في D0.

يدعم `MmMapIoSpace` القيمة NonCached؛ ويدعم `MmMapIoSpaceEx` ‏PAGE_NOCACHE مع PAGE_READONLY أو PAGE_READWRITE. يقبل كلاهما نطاقًا فرعيًا مترجمًا مصرحًا به داخل تخصيص واحد فقط، مع حفظ إزاحة الصفحة. تشترك التعيينات البديلة في بنك واحد وتحتفظ بصلاحيات مستقلة، ويتطلب `MmUnmapIoSpace` العنوان الأساسي والطول الأصليين بالضبط. يعيد نفاد التعيينات أو نافذتها أو ميزانية الذاكرة المحددة NULL؛ وتظل أخطاء الخلفية إخفاقات صريحة. لا يستعيد العنوان الملغى الوصول عبر تعيين لاحق. تمر تعليمات السجلات المفردة وتعليمات REP الحقيقية بفحوص MMIO للمعالج؛ وتفشل الفجوات والعروض الخاطئة وسوء المحاذاة وكتابة RO والعبور بين التعيينات والتنفيذ قبل التأثير على السجلات. يجب أن تندرج عمليات الوصول إلى الذاكرة عبر الواجهات الممثلة أيضًا ضمن معاملة واحدة محاذاة بعرض 1/2/4 بايت؛ وتفشل النطاقات الأكبر بدل تقسيمها إلى عمليات وصول للسجلات. لا يشمل ذلك RAM فيزيائية اعتباطية أو إعادة توزيع الموارد أو المنافذ أو واجهات DMA الأخرى أو سلوك العتاد العام.

يستخدم [سيناريو بنك السجلات القابل للتشغيل](../examples/driver-register-bank-scenario.json) المثال الأصلي `driver_wdm_resources.c` المبني بـWDK الحقيقي عبر `NEVERD_WDM_RESOURCE_FIXTURE` / `NEVERD_WDM_RESOURCE_CFG_FIXTURE`. ينفذ 14 طلبًا تشمل START المؤجل وعمليات الملفات وSTOP وإعادة التشغيل والإزالة، ويرصد القيم المستمرة عبر IOCTL برنامج التشغيل. يسجل `configuration.pnp_devices[].resources` الحقائق الابتدائية بعناوين فيزيائية سداسية عشرية دون فقد دقة؛ وليس تقريرًا ثانيًا عن حالة البنك. تواصل C API وPython استخدام `scenario_json` و`neverd_driver_options_v1` دون تغيير. تُتخطى المنتجات الحقيقية المفقودة صراحة؛ وتظل أدلة التنفيذ خاصة بـLinux.

يمكن لموفّر `register_bank` إعلان `interrupts` وحدها أو مع `resources`، ويجب ألا تكون القائمتان فارغتين معًا. يرفض `resource_free` حقل `interrupts` الصريح حتى لو كان `[]`. لكل مقاطعة `id` و`raw_vector` و`raw_level` و`raw_affinity` و`translated_vector` و`translated_level` و`translated_affinity` و`mode` و`share`. تجمع `DriverInterrupts.h`/`DriverInterrupts.def` الأنواع والتهجئة والحدود: 8 لكل PDO و32 إجمالًا، ومعرّف ASCII محدود الطول وفريد ضمن PDO، وraw level بين 0 و65535، وtranslated DIRQL بين 3 و12. يحتفظ المتجه بكامل 32 بت ولا تُستنتج علاقته بـ IRQL. يجب أن يكون كلا قناعي affinity مساويًا 1؛ يقتصر النموذج على CPU0/group0. يدعم `mode` القيمتين `latched` و`level_sensitive` ويدعم `share` القيمتين `device_exclusive` و`shared`. يجب أن تعلن كل الموارد المشتركة في متجه مترجم واحد shared، وتتطابق في النمط والمستوى المترجم وaffinity وفترة إعادة التحفيز. يتطلب نمط المستوى قيمة موجبة صريحة لـ`retrigger_after_100ns` لا تتجاوز `INT64_MAX`. قيم raw وtranslated مستقلة. يحفظ `CM_RESOURCE_LIST` ترتيب واصفات الذاكرة ثم يضيف واصفات المقاطعة من النوع 2، مع سمات مشاركة وأعلام تحفيز تطابق الإعلان.

تقبل READ/WRITE/IOCTL قائمة `interrupt_events`، ولكل عنصر `after_100ns` و`device_id` و`interrupt_id` و`action` اختيارية. ترفض الأنواع الأخرى حتى القائمة الفارغة. التأخير غير سالب ولا يتجاوز `INT64_MAX`، ويبدأ عند نجاح تقديم الطلب مع التقاط الاتصالات وجيل موارد PDO آنذاك. القيمة الافتراضية في latched هي `action: "pulse"` وتستدعي جميع ISR الملتقطة؛ أما level_sensitive فيقبل `assert`/`deassert` الصريحتين فقط. يُحسب مستوى الخط بعملية OR لحالات المصادر المحددة بـ PDO/المورد/الجيل، ولا يغير assert المتكرر النتيجة. تُطبّق جميع تغييرات الحالة الخارجية عند الحد نفسه قبل أخذ العينة. بعد كل دفعة ISR تؤخذ العينة التالية عند الوقت الافتراضي الحالي زائد `retrigger_after_100ns`، وتُستدعى المعالجات بترتيب التسجيل حتى TRUE. تعني TRUE تولي المقاطعة فقط ولا تلغي تأكيد المصدر. إكمال IRP المصدر لا يلغي الحدث، ولا تُستنتج enable/status/acknowledgment من كتابة السجلات. افتراضيًا يتقدم الوقت عند الخمول؛ ومع `scheduling` تتقدم المواعيد أثناء تنفيذ التعليمات أيضًا. تسبق ISR ‏DPC/العمال عند حدود الاستدعاء المدعومة؛ لا يضمن `after_100ns: 0` استباق التعليمات. الحد 64 حدثًا لكل طلب و1024 حدثًا معلنًا إجمالًا؛ ولدفعات التسليم الفعلية حد مستقل 4096، بحد أقصى 32 معالجًا لكل دفعة، مع استمرار ميزانيات الجدولة والتعليمات. فقد الاتصال أو جيل موارد غير صالح أو D3 المادي يسجل `undelivered_reason` ويوقف التنفيذ بـ`model_error` دون إعادة ربط أو تأجيل صامت.

تستخدم `IoConnectInterrupt` واجهة ABI الفعلية ذات 11 وسيطًا وتطابق الموارد المترجمة بدقة. تدعم `IoConnectInterruptEx` ‏FullySpecified(1) وLineBased(2، خطًا واحدًا لـ PDO صريح) وFullySpecifiedGroup(4، group0)، ويتطلب الفصل إصدارًا وسياقًا مطابقين. يجري الاتصال والفصل عند `PASSIVE_LEVEL`. تستطيع خطوط latched/level_sensitive الحصرية أو المشتركة استخدام قفل خاص أو `KSPIN_LOCK` مشترك هيّأه المستدعي. لا يقل `SynchronizeIrql` المشترك عن DIRQL المخصص لكل اتصال؛ وتختار قيمة LineBased الصفرية المستوى المخصص. تبقى أولوية تسليم ISR بحسب DIRQL المخصص، ويستخدم التنفيذ مستوى قفل المزامنة. كائن `KINTERRUPT` معتم ولا يُعاد استخدام عنوانه. تتلقى ISR ‏`(Interrupt, ServiceContext)` وتعيد BOOLEAN في AL؛ وتعني FALSE عدم تولي المقاطعة لا فشل NTSTATUS. تنفذ `KeSynchronizeExecution` الاستدعاء الحقيقي ذي الوسيط الواحد تحت القفل نفسه، وتعيد BOOLEAN وتستعيد IRQL/CR8 للمستدعي. تشترك ISR واستدعاءات المزامنة و`KeAcquireInterruptSpinLock`/`KeReleaseInterruptSpinLock` اليدوية في ملكية فعلية واحدة للقفل، مع التحقق من عدم التكرار وهوية التنفيذ وIRQL المحفوظ، ولا يجوز الرجوع مع إبقاء القفل. ما زالت الانتظارات داخل المقاطعة وحفظ الفاصلة العائمة لمعالجها وتعشيق المقاطعات العشوائي غير مدعومة. يجب الفصل قبل الإكمال النهائي عند فشل START أو نجاح STOP/REMOVE، ويمكن لاستدعاء الإكمال الأعلى تنظيف الاتصال أولًا؛ ولا يتخلص الفصل من DPC المصطفة.

يفصل التقرير الإعلان عن الرصد: تحفظ `configuration.pnp_devices[].interrupts` الموارد، وتحفظ `configuration.interrupt_events` الأحداث و`action` و`source_request_index`/`event_index` بدءًا من الصفر. تسجل `interrupts` الجذرية الجهاز/المورد والجيل والموعد ووقت تطبيق الحالة؛ وتعني `occurred_at_100ns` أن الحالة الخارجية طُبّقت. تسجل `handlers[]` لكل ISR نُفذت فعليًا كائن المقاطعة ووقتي التسليم والعودة ونتيجة BOOLEAN و`claimed` و`delivery_index`. قد ينتج assert دفعات متعددة. إذا لم ينفذ deassert أو assert أُلغي عند الحد نفسه أي ISR، فلا تُختلق حقول ISR. عدم تولي ISR للمقاطعة نتيجة صالحة، وتظهر آثار DPC في إكمال الطلبات الحقيقي واستدعاءات API والرسائل. تحتفظ الصفوف أيضًا بـ`device_id` و`interrupt_id` و`epoch` و`due_at_100ns` و`occurred_at_100ns` و`interrupt_object` و`undelivered_reason`. يسجل `delivered_at_100ns` دخول المعالج الأول، وتلخص حقول المستوى الأعلى `returned_at_100ns` و`return_value` و`claimed` الدفعة الأحدث؛ وتحفظ `handlers` التاريخ الكامل. يرتبط الرصد بأول assert ما دام المصدر مؤكدًا، لذلك قد لا يملك assert المتكرر سجلات ISR مستقلة. يستخدم [سيناريو المقاطعة](../examples/driver-interrupt-scenario.json) القابل للتشغيل المثال الأصلي `driver_wdm_interrupts.c` المبني بـWDK الحقيقي والمسارين الاختياريين `NEVERD_WDM_INTERRUPT_FIXTURE` / `NEVERD_WDM_INTERRUPT_CFG_FIXTURE`: تشمل طلباته السبعة START مؤجلًا وIOCTL معلقًا تكمله ISR→DPC وتنظيف/إغلاق الملف والإزالة. يظل مدخل C/Python ‏`scenario_json` وتخطيط `neverd_driver_options_v1` دون تغيير. تُتخطى المنتجات الحقيقية المفقودة صراحة؛ والأدلة التنفيذية مقتصرة على Linux.

يضيف `DriverDMA.h` / `DriverDMA.def` كائن `dma` اختياريًا إلى PDO من نوع `register_bank` بجانب موارد الذاكرة والمقاطعات؛ ولا يغني DMA وحده عن هذين النوعين من الموارد. يجب تحديد الحقول السبعة صراحةً: `address_bits` بقيمة 32 أو 64، و`maximum_length` بين 1–1048576 بايت، و`map_registers` بين 1–256، و`alignment` قوة للعدد اثنين بين 1–4096، و`logical_base` غير صفري ومحاذٍ لصفحة، و`logical_length` محاذٍ لصفحة وبين 4096–1073741824 بايت، والقيمة المنطقية `scatter_gather`. يجب ألا يفيض نطاق العناوين وأن يناسب عرض العنوان. لكل PDO نطاق منطقي مستقل؛ فلا تجعل العناوين المتساوية أجهزة مختلفة تشترك في الذاكرة. يجب أن تتجنب جميع موارد MMIO المترجمة نطاق RAM المحجوز للنموذج `[0x1000000000, 0x1004000000)` حتى دون إعداد DMA. هذه حقائق لجهاز اصطناعي متماسك يتحكم بالناقل، وليست ذاكرة المضيف الفيزيائية أو جهاز PCI.

يقبل `IoGetDmaAdapter` حقول `DEVICE_DESCRIPTION` التاريخية للإصدار 0/1 لسيد ناقل Internal، وينشر `DMA_ADAPTER` من الإصدار الأول مع جدول `DMA_OPERATIONS` الفعلي بحجم 104 بايتات. تعيد استعلامات الإصدار 2/3 القيمة NULL دون قراءة ذيل الوصف الحديث. ترتبط كل دالة غير مباشرة بالمحوّل الحي المحدد، مستقلّة عن استيرادات النواة. الدوال المنفذة هي `AllocateCommonBuffer` و`FreeCommonBuffer` و`GetDmaAlignment` و`GetScatterGatherList` و`PutScatterGatherList` و`PutDmaAdapter` و`AllocateAdapterChannel` و`MapTransfer` و`FlushAdapterBuffers` و`FreeMapRegisters`. يبقى `FreeAdapterChannel` و`ReadDmaCounter` مصيدتين مسمّاتين لأن الملف لا ينمذج متحكم DMA تابعًا أو تابعًا للنظام. تتطلب إدارة common buffer واستعلام المحاذاة PASSIVE_LEVEL؛ ويتطلب Get/PutScatterGatherList مستوى DISPATCH_LEVEL، بينما يسمح تحرير المحوّل حتى DISPATCH_LEVEL. يتجاهل x64 الحقل `CacheEnabled`. تعيد استعلامات الإصدارات غير المدعومة والقدرات المعلنة غير المتوافقة ونقص الموارد الموثق NULL؛ أما اختيارات الواجهة المشوهة أو غير المنمذجة وأعطال الخلفية فتبقى أخطاء صريحة.

تسمح أسماء MDL المستعارة للنظام، المدعومة بنطاقات صورة يملكها المحمّل، بالوصول إلى بايتات الصورة المعروفة ضمن الصفحات الموصوفة بحجم 4 KiB. يفشل الوصول إلى الحشو خارج نطاق الصورة المعلن حتى إذا كانت الصفحة الأساسية معيّنة. `ByteOffset` و`ByteCount` بنطاق المخزن المنطقي، ولا يحددان صلاحيات CPU داخل الصفحة. تبقى بايتات الصورة خارج هذا النطاق مشتركة مع العرض الأصلي، بينما تنطبق الحماية وإلغاء التعيين على التعيين الكامل. تحتفظ ذاكرة الكائنات بقيود النموذج على نطاق الحشو.

يخصص `KernelPhysicalMemory` للذاكرة الموجودة حتى 16384 صفحة فيزيائية نموذجية بحجم 4096 بايت. تختلف عناوين CPU الافتراضية وهويات الصفحات الفيزيائية والعناوين المنطقية للجهاز. تكشف مصفوفات PFN للواصفات MDL المبنية الهويات المشتركة للقراءة فقط؛ ولا تملك الواصفات غير المبنية PFN قابلة للاستخدام. قد تتشارك تخصيصات صغيرة متجاورة PFN واحدًا مع الاحتفاظ بنطاقات بايتات وأعمار مستقلة. تستخدم common buffers وذاكرة المجمّع ومخازن الطلبات البايتات نفسها التي تملكها `GuestMemory`، دون نسخة DMA أخرى. يحتفظ تعيين SG الحي بنطاق البيانات الدقيق وواصفه. يرفض الإكمال وتحرير المجمّع/MDL والإزالة التبعيات الحية قبل التحرير. لا يسحب فك تعيين MDL المباشر إلا تعيين CPU في النظام؛ ويستطيع DMA الوصول إلى الذاكرة المقفلة. يسجل `DmaWritable` عقد القفل للكتابة مستقلًا عن صلاحيات تعيين CPU: تتطلب كتابة الجهاز READ/OUT_DIRECT مباشرًا أو ذاكرة غير قابلة للترحيل وقابلة للكتابة؛ ولا يحصل WRITE/IN_DIRECT على هذا الحق لمجرد أن تعيين CPU قابل للكتابة.

تتحقق `GetScatterGatherList` من CurrentVa/Length مقابل نطاق MDL الأصلي، وتنشئ أجزاء صفحات منطقية فوق الذاكرة الموجودة. عند توافر سجلات التعيين، يُنفذ `AdapterListControl` الحقيقي ذو المعاملات الأربعة والعائد void داخل الاستدعاء قبل عودة API؛ وإلا تُحفظ البيانات والواصف وتُحجز سعة الاستدعاء في FIFO الخاص بـPDO حتى تحرير الموارد. لا يملك هذا الملف ملكية StartIo، لذا يكون معامل IRP الثاني للاستدعاء NULL. لا تحرر عودة الاستدعاء التعيين. يمكن تنفيذ `PutScatterGatherList` داخل الاستدعاء؛ وبعد Put يستطيع برنامج التشغيل إكمال الطلب وتحرير آخر محوّل، فيما يستمر عمر متابعة الاستدعاء والاحتفاظ بالجهاز حتى العودة. يتطلب تحرير common buffer المحوّل والطول والعنوان المنطقي وعنوان CPU الأصليين. لا يعاد استخدام العناوين المنطقية طوال الجلسة، حتى بعد إعادة التشغيل. يتوقف انتظار الموارد صراحةً عند غياب منتج حقيقي؛ ولا يختلق إكمالًا أو موعدًا نهائيًا. حين يملك تعيين SG الحي البيانات للجهاز، يتطلب وصول CPU تنفيذ Put أولًا؛ أما الاستدعاء الذي لا يزال ينتظر سجلات التعيين فلم ينقل ملكية البايتات إلى الجهاز بعد.

يتطلب `AllocateAdapterChannel` مستوى DISPATCH_LEVEL ويحجز رمزًا معتمًا غير NULL لسجلات التعيين. تتشارك common buffers وقوائم SG وحجوزات القنوات حصة PDO وطابور FIFO نفسه. يعني النجاح قبول استدعاء `AdapterControl` حقيقي فوري أو مؤجل؛ ويعيد العدد المفرط `STATUS_INSUFFICIENT_RESOURCES` دون استدعاء راجع. يُسمح باستدعاء تخصيص غير منتهٍ واحد لكل جهاز ضيف، ويُرفض استدعاء AllocateAdapterChannel من AdapterControl حتى عبر استدعاء راجع متداخل. تتضمن المعاملات الأربعة اللقطة الفعلية من `DEVICE_OBJECT.CurrentIrp` عند التسجيل. يمكن الكتابة في هذا الحقل المحدد ذي الثمانية بايتات على أجهزة الضيف؛ تُقبل قيمة صفر أو IRP حي يشمل مساره الجهاز. يحتفظ الطابور بالحزمة حتى دخول الاستدعاء الراجع، وبعدها يمكنه إكمالها. ما زال StartIo غير منمذج؛ ومعامل IRP غير المستخدم في استدعاء SG المنفصل يبقى NULL.

يعيد `AdapterControl` قيمة `IO_ALLOCATION_ACTION` من 32 بت؛ تُهمل بتات RAX العليا، ولا يحل الإجراء محل `STATUS_SUCCESS` الخاص بـAllocateAdapterChannel. يحرر `DeallocateObject` عند العودة السجلات غير المستخدمة أو التي اكتمل تفريغها. يحتفظ `DeallocateObjectKeepRegisters` بها حتى استدعاء `FreeMapRegisters` بالمحوّل والرمز والعدد الأصلي المطابقين. تتطلب إعادة `KeepObject` متحكم نظام غير منمذج وتفشل صراحةً. لا يمكن تحرير التخصيص المسلَّم حديثًا بوصفه محتفظًا به قبل عودة استدعائه الراجع؛ يمكن تحرير تخصيص آخر محتفظ به سابقًا عندما يسمح عقده الخاص. لهوية الاستدعاء والسجلات المحتفظ بها والبايتات المعيّنة أعمار مستقلة، وتُفحص جميعها قبل إزالة المحوّل أو الجهاز.

يسمح `MapTransfer` و`FlushAdapterBuffers` بمستوى IRQL حتى DISPATCH_LEVEL؛ ويتطلب تخصيص القناة وتحرير السجلات DISPATCH_LEVEL. يأخذ MapTransfer فهرسًا نسبيًا إلى MDL، ويقرأ طول ULONG فعليًا ويحدّثه، ثم يعيد العنوان المنطقي بالقيمة. يعيد ملف SG المحدود جزء صفحة ذاكرة واحدًا في كل استدعاء؛ وتوسّع الفهارس اللاحقة المتجاورة من MDL نفسه وفي الاتجاه نفسه عملية واحدة. دون SG، يُعيّن كامل النطاق المطلوب في استدعاء واحد إذا اتسع له الحجز، دون تقصير. يحجز التعيين الأول نافذة منطقية لا يعاد استخدامها بحجم حجز السجلات؛ ويمكن تداخل تخصيصات أخرى زمنيًا دون تراكبها. تتشارك الأجزاء تثبيتًا فعليًا واحدًا يتوسع في موضعه. يمكن لمعاملات الجهاز عبور كامل العملية المعيّنة، لكن وصول CPU وتحرير MDL والإكمال الذي يزيل ذاكرة مثبتة تظل ممنوعة حتى التفريغ المجمع. يجب أن يطابق Flush الفهرس الأول وMDL والاتجاه وإجمالي الطول المعيّن فعليًا. يحرر البايتات دون السجلات، فتسمح الرموز المحتفظ بها بعملية أخرى. التفريغ الجزئي وخلط MDL وأنماط MapTransfer الأخرى خارج هذا الملف، دون افتراض أنها غير صالحة في كل أنظمة Windows.

يتحقق `KeFlushIoBuffers` من MDL حي مقفل أو غير قابل للترحيل. المنصة المنمذجة متماسكة؛ لذلك لا تتطلب أي قيمة لـReadOperation أو DmaOperation نسخة ذاكرة مخبأة منفصلة، ولا يحرر الاستدعاء ملكية DMA أو يحل محل FlushAdapterBuffers. يشغّل [سيناريو القناة](../examples/driver-dma-channel-scenario.json) العينة الأصلية `driver_wdm_dma_channel.c` عبر استدعاءَي MapTransfer ومعاملة جهاز واحدة تعبر الصفحة، ثم IRQ/DPC معلن منفصلًا وتفريغ مجمع وتحرير دقيق للسجلات. تستخدم صور normal/CFG الحقيقية `NEVERD_WDM_DMA_CHANNEL_FIXTURE` و`NEVERD_WDM_DMA_CHANNEL_CFG_FIXTURE`.

تقبل READ/WRITE/IOCTL فقط الحقل `dma_events`. يحتاج كل حدث إلى `after_100ns` و`device_id` و`logical_address` و`direction` و`length`؛ ويتطلب `write_memory` أيضًا `data_hex` بالطول الدقيق، بينما يرفض `read_memory` هذا الحقل. تُعرّف الاتجاهات من منظور الجهاز. الحدود هي 64 حدثًا لكل طلب، و1024 إجمالًا، و16 MiB من بايتات المعاملات مجتمعة، و1 MiB لكل معاملة؛ والتأخير غير سالب حتى INT64_MAX. يلتقط التقديم جيل تخصيص PDO الحالي ويحدد أصل الوقت الافتراضي، لكنه لا يشترط وجود تعيين سيُنشئه التوزيع اللاحق. تحل عملية التسليم كامل النطاق المنطقي الحي واتجاهه، وتتطلب D0 الفيزيائي، وتتحقق من جميع البايتات قبل أي أثر. لا يلغي إكمال IRP المصدر الحدث. تسجل التعيينات الغائبة أو المحررة والأجيال القديمة والإزالة المفاجئة وD3 فشلًا وتوقف التنفيذ؛ ولا تعيد الأحداث الارتباط أو تختلق مقاطعة أو بروتوكول سجلات أو إكمال IRP. في حد جدولة واحد، يسبق نشر حالة عتاد المزوّد بايتات DMA، ثم تأتي نبضات المقاطعة المعلنة بصورة مستقلة. يكون الوقت تعاونيًا افتراضيًا؛ ويتيح `scheduling` المواعيد والاستباق المعتمدين على التعليمات.

تحفظ التقارير `configuration.pnp_devices[].dma` و`configuration.dma_events` المسطّح. تسجل صفوف `dma_transfers` الجذرية `source_request_index` و`event_index` و`device_id` و`epoch` و`logical_address` و`direction` و`length` و`due_at_100ns`، مع حقول تقبل null هي `occurred_at_100ns` و`completed_at_100ns` و`mapping` و`adapter` و`failure_reason`؛ ويحتوي `data_hex` على البايتات المنقولة فعليًا. يجب إكمال كل معاملة معلنة دون فشل لتحقيق `scenario_success`. يستخدم [سيناريو DMA](../examples/driver-dma-scenario.json) المثال الأصلي `driver_wdm_dma.c` المبني بـWDK الحقيقي مع المسارين الاختياريين `NEVERD_WDM_DMA_FIXTURE` / `NEVERD_WDM_DMA_CFG_FIXTURE`، ويشغّل common buffer بمؤشرات محوّل حقيقية وإكمال ISR→DPC معلن منفصلًا. تستمر C/Python في استخدام `scenario_json` دون تغيير `neverd_driver_options_v1`. تُتخطى المنتجات الغائبة صراحةً؛ والأدلة محدودة بـLinux. لا يشمل الدعم المتحكمات التابعة أو دوال V2/V3 أو محركات واصفات العتاد أو DMA العام في KMDF أو نماذج الأجهزة الأخرى.

تستخدم طلبات طاقة WDM للناقل الاصطناعي `kind: "power"` مع `device_id` مُعدّ. تتطلب كل حزمة صراحةً `minor` ‏(`query`/`set`) و`power_type` ‏(`device`/`system`) و`power_state` ‏(`D0`/`D2`/`D3` أو `working`/`sleeping3`) و`power_action` ‏(`none`/`sleep`) و`system_context` كعدد32 بت أو سلسلة ست عشرية و`bus_completion`. لا يُدعم System Query إلى Working وتُرفض حقول الملف والنقل والإلغاء. تُحفظ قيمة `system_context` كاملة كحقيقة معتمة دون استنتاج طلب أب أو دعم السبات/بدء التشغيل السريع. تتطلب المسارات `DO_POWER_PAGABLE` دون `DO_POWER_INRUSH`؛ ويجري إرسال الطاقة الفعلي القابل للترحيل عند `PASSIVE_LEVEL`. يمرر `PoCallDriver` نفس IRP المُدار، ويتبع `PoStartNextPowerIrp` عقد Vista+ دون مصافحة تسلسل إضافية. تظل سياسة الطاقة العامة والحالات/الأفعال الأخرى والإيقاف/السبات وتيار البدء والمسارات غير القابلة للترحيل والعتاد العام وKMDF PnP العام خارج النطاق.

تقبل Query/Set `PoRequestPowerIrp` المستدعين حتى `DISPATCH_LEVEL`. عند APC أو DISPATCH تحجز IRP مستقلاً ومعاملة الطاقة وتعيد `STATUS_PENDING`؛ ولا تتغير حالة الجهاز الفعلية حتى الإكمال. يبقى IRQL وCR8 للمستدعي دون تغيير. ينفذ المجدول لاحقاً DispatchPower الحقيقي القابل للترحيل عند `PASSIVE_LEVEL`؛ لذا يستطيع استدعاء إيقاظ DPC طلب D0 مباشرة دون work item ضيف. يحتفظ استدعاء PASSIVE بالإرسال المضمن والإكمال المبكر. لا يستهلك الرفض المسبق FIFO أو صفوف التقرير أو تخزين الطلب أو سعة المجدول. تحتفظ استدعاءات الإكمال بـIRQL لمسار الإكمال الفعلي. يبقى إرسال WAIT_WAKE مقيداً بـ`PASSIVE_LEVEL`. انظر [سيناريو الطاقة عند IRQL مرتفع](../examples/driver-wdm-elevated-power-scenario.json).

يمكن لبرنامج تشغيل WDM الأصلي إرسال `PoRequestPowerIrp(IRP_MN_WAIT_WAKE)` بحالة النظام `Working` أو `Sleeping3`. يلزم `PASSIVE_LEVEL` وD0 فعلي مستقر وعدم وجود معاملة طاقة نشطة وإقرار START سفلي ناجح فعلاً؛ يمكن أن يبقى START العلوي قيد التنفيذ. يُكتب خرج `PIRP` الاختياري قبل الإرسال إلى الضيف، والاستدعاء الراجع اختياري بشكل مستقل. يحفظ فشل التحقق المسبق الخرج وصفوف التقرير وميزانية التخصيص. يعيد الطلب المُرسل `STATUS_PENDING` حتى مع الرفض المتزامن، ويسجل `origin: "PoRequestPowerIrp"` و`response_index: null` دون استهلاك `requested_device_power`. تبقى السيناريوهات العامة Query/Set فقط؛ ويُرفض WAIT_WAKE الأصلي عبر مسار يديره الإطار قبل التخصيص.

يحتفظ كل مزود بطلب WAIT_WAKE واحد، أصلي أو تابع للإطار. تؤدي `wake_capabilities` الغائبة أو الكاذبة كلها إلى `STATUS_NOT_SUPPORTED`، وحد النظام غير المدعوم إلى `STATUS_INVALID_DEVICE_STATE`، والتكرار إلى `STATUS_DEVICE_BUSY`. يمر الإكمال السفلي الحقيقي بسلسلة IoCompletion بما فيها `STATUS_MORE_PROCESSING_REQUIRED` قبل الاستدعاء النهائي void ذي المعاملات الخمسة `REQUEST_POWER_COMPLETE`. تبقى لقطة `IO_STATUS_BLOCK` المستقلة حتى عودته. لا يستطيع الإكمال العلوي اختلاق إيقاظ ناجح. يستدعي `IoCancelIrp` إجراء المزود المثبت وفق بروتوكول قفل الإلغاء الفعلي ويعيد TRUE فقط إذا استدعاه. ويتحقق التسليم الناجح أيضاً من قدرة S0/Sx المستقلة وفق الحالة الفعلية Working/Sleeping3؛ ولا يمنح حد Sleeping3 في IRP قدرة إيقاظ S0.

يلتقط حدث `wake` الأصلي IRP المحتفظ به بالفعل وهوية START الناجحة الدقيقة. لا يعيد الإلغاء/الإرسال أو STOP/إعادة التشغيل توجيه الحدث. يسجل `wake_source_device_id` / `wake_source_pdo` دون تغيير D0/D2/D3 أو Working/Sleeping3؛ إذ تلزم طلبات طاقة منفصلة. يلغي برنامج التشغيل الأصلي WAIT_WAKE وينهيه مع استدعاءاته قبل التفكيك غير المتوافق. لا يعد تدفق تحكم متوقعاً إلا الإلغاء المرصود الذي أكمله المزود فعلاً. نشر الإيقاظ للأبناء عبر WDM الخام ما زال غير مدعوم.

يتطلب USB idle الأصلي عبر WDM إعداد `usb_idle` مستقلاً عن `bus`؛ وتكون `role` إحدى `independent_function` أو `composite_parent` أو `composite_function`. يشير `parent_id` المباشر للدالة المركبة إلى الوالد المركب. القيمة الافتراضية لـ`remote_wake` هي false؛ وتتطلب true أيضاً `wake_capabilities`، ويتطلب إيقاظ USB الفعلي حالة D2. لا تكفي قدرة D3hot وحدها. يستهدف `usb_idle_permission` في `power_policy_events` الدالة المستقلة أو الوالد المركب ويرفض `component` و`state`. يلتقط كل IRP محتفظ به وهوية START الناجحة؛ يمنع العضو المفقود المجموعة كلها ولا يعيد الإلغاء/التسجيل أو إعادة التشغيل توجيه الحدث.

يُرسل `IOCTL_INTERNAL_USB_SUBMIT_IDLE_NOTIFICATION` الحقيقي في S0/D0 مستقر عند `PASSIVE_LEVEL`: يستخدم `METHOD_NEITHER` للنواة وسجل callback info حجمه 16 بايت دون مخرج، مباشرة إلى المزود الصريح أو عبر FDO الضيف. يبقى السجل مستعاراً حتى الإكمال، وcontext معتم ويمكن أن يكون NULL. ينفذ الإذن callback من نوع void بوسيط واحد عند PASSIVE؛ يرسل SET D2 حقيقياً واحداً وينتظر إكماله، ويسمح فشل تخصيص مرصود بالإلغاء والعودة. يبقى idle IRP معلقاً بعد ذلك. يسحب الإلغاء قبل الدخول الاستدعاء من الطابور، وبعد الدخول ينتظر عودته. يُكمل استقبال D0 طلب idle بنجاح قبل تأكيد D0 المستقل؛ ينتج D3 الحالة `STATUS_POWER_STATE_INVALID` ويلغي S3/الإزالة الطلب. يحتفظ التحرير داخل IoCompletion بقاعدة `STATUS_MORE_PROCESSING_REQUIRED`.

يرفض هذا الملف STOP/REMOVE قبل تحرير العتاد إذا كان تأكيد طاقة جهاز PoFx لا يزال معلقًا؛ يجب إكمال انتقال D الفعلي أولًا. يلغي الإيقاف المنظم القرارات التي لم تُصدر فقط، وينتظر الاستدعاءات الحالية للمكوّن قبل D0Exit، ولا يختلق اكتمال الطاقة. هذا حد لتسلسل النموذج، وليس قاعدة عامة في WDK.

ينسخ WDM PoFx v1 وصف المكوّنات وحالات الخمول ويدير المراجع والاستدعاءات الفعلية. يحتفظ الدخول والتأكيد والرجوع بملكية مستقلة؛ وتستمر الاستدعاءات الحاجبة على خيط المستدعي. الواجهات: `PoFxRegisterDevice`, `PoFxUnregisterDevice`, `PoFxStartDevicePowerManagement`, `PoFxActivateComponent`, `PoFxIdleComponent`, `PoFxCompleteIdleCondition`, `PoFxCompleteIdleState`, `PoFxCompleteDevicePowerNotRequired`, `PoFxReportDevicePoweredOn`, `PoFxSetComponentLatency`, `PoFxSetComponentResidency`, `PoFxSetComponentWake`, `PoFxSetDeviceIdleTimeout`. تستخدم `SystemManagedIdleTimeout`/`SystemManagedIdleTimeoutWithHint` افتراضيًا مكوّن F0 واحدًا يملكه الإطار؛ يلغي STOP/REMOVE التسجيل ويعيد التشغيل تسجيلًا جديدًا. لا يختلق idle أو تلميح المهلة قرار نظام التشغيل. تتطلب `component_idle_state` داخل `power_policy_events` الحقلين `component` و`state`، بينما ترفضهما `power_not_required`. يلزم التسجيل الحالي وجيل START الملتقط؛ وتقيّد تلميحات التأخير والمكوث والإيقاظ الانتقالات. لا تُدعم PoFx v2/v3 أو إدارة الطاقة الموجّهة أو طلبات تحكم المنصة الاعتباطية.

يُكمل سجل الإرجاع لاستدعاء void الطلب. يستخدم الإكمال المؤجل المجدول الحالي. عند غياب معالج يكتمل الطلب بـ `STATUS_INVALID_DEVICE_REQUEST`؛ وتكتمل READ/WRITE ذات الطول الصفري دون تسليم ما لم يُفعّل ذلك. تكمل حزمة الملفات الافتراضية CREATE/CLEANUP/CLOSE بنجاح مع Information=0. تدعم الطوابير اليدوية غير الافتراضية نقل الطلبات من الطابور الافتراضي عبر `WdfRequestForwardToIoQueue` واستعادتها بترتيب FIFO عبر `WdfIoQueueRetrieveNextRequest`. يزيل الإطار الطلب الملغى قبل استعادته ويكمله بالحالة `STATUS_CANCELLED`. تسلّم الطوابير التلقائية غير الافتراضية الطلبات المحوّلة إلى استدعاءاتها الخاصة، ويحتفظ الطابور اليدوي الافتراضي بالطلبات الواردة حتى استعادتها. تعمل `WdfIoQueueRetrieveNextRequest` مع الطوابير اليدوية والمتسلسلة، وتعيد الطوابير المتوازية `STATUS_INVALID_DEVICE_STATE`. إذا لم يوجد استدعاء مناسب، يُكمل الطابور التلقائي الطلب بالحالة `STATUS_INVALID_DEVICE_REQUEST` عند توفر موضع للتسليم. تبقى سلوكيات PnP والطاقة الأوسع خارج هذا الملف التعريفي. يمكن لـ `WdfRequestRequeue` إعادة الطلب الذي استُعيد إلى مقدمة الطابور اليدوي نفسه قبل اكتماله. تضبط `NumberOfPresentedRequests` عدد الطلبات المعروضة في الطابور المتوازي؛ تنتظر الطلبات الزائدة حتى يكتمل طلب معروض أو يُلغى. تقبل القائمة الافتراضية التسلسلية طلبات إضافية أثناء تقديم طلب واحد؛ تنتظر الطلبات التالية بترتيب FIFO حتى يكتمل الطلب المعروض أو يغادر القائمة، ويمكن إلغاء الطلب المنتظر قبل تسليمه. يوقف `WdfIoQueueStop` تسليم الطلبات مع الاستمرار في قبولها. يعيد `WdfIoQueueStart` تسليم الطلبات المنتظرة، وتعرض `WdfIoQueueGetState` عدد الطلبات في الطابور وعدد الطلبات المسلّمة. تعيد محاولة الاسترجاع أثناء التوقف `STATUS_WDF_PAUSED`؛ يُنفّذ استدعاء اكتمال الإيقاف مع السياق المعطى بعد انتهاء جميع الطلبات التي سُلّمت إلى برنامج التشغيل؛ الطلبات المنتظرة لا تؤخره، ويُرفض تسجيل استدعاء ثانٍ أثناء انتظاره.

تسجّل `WdfIoQueueReadyNotify` استدعاء `EvtIoQueueState` واحدًا لطابور يدوي. عند انتقال عدد الطلبات المنتظرة من الصفر إلى قيمة موجبة، يتلقى `(WDFQUEUE, WDFCONTEXT)` عند `PASSIVE_LEVEL` حتى إن ظل برنامج التشغيل يملك طلبات سبق استخراجها. قد يُخطر الطابور غير الفارغ فور التسجيل؛ وينتظر الطابور الموقوف `WdfIoQueueStart`. يعيد التسجيل المكرر أو إلغاء التسجيل قبل الإيقاف `STATUS_INVALID_DEVICE_REQUEST`. بعد `WdfIoQueueStop` تلغي القيمة NULL تسجيل الاستدعاء.

يبحث `WdfIoQueueFindRequest` في طابور يدوي دون نقل ملكية معالجة الطلب، ويضيف مرجعًا عند النجاح. يحرر برنامج التشغيل هذا المرجع باستخدام `WdfObjectDereference`. ينقل `WdfIoQueueRetrieveFoundRequest` ملكية طلب ما زال في الطابور؛ أما الطلب الذي أزيل بالإلغاء فيعيد `STATUS_NOT_FOUND`. تستخدم المعلمات الاختيارية تخطيط `WdfRequestGetParameters` نفسه. يمكن ترشيح `WdfIoQueueFindRequest` بكائن ملف حي. يأخذ `WdfIoQueueRetrieveRequestByFileObject` الطلب المطابق التالي من طابور يدوي أو تسلسلي، ولا يغير المخرج إذا لم يجد طلبًا.

ترفض `WdfIoQueueDrain` الطلبات الجديدة بالحالة `STATUS_INVALID_DEVICE_STATE` وتواصل تسليم الطلبات الموجودة. يُنفّذ الاستدعاء عندما يصبح عدد الطلبات في الطابور والطلبات المملوكة لبرنامج التشغيل صفرًا. تعيد إعادة التوجيه `STATUS_WDF_BUSY`، وتستأنف `WdfIoQueueStart` قبول الطلبات.

تلغي `WdfIoQueuePurge` الطلبات التي لم تُسلَّم بالحالة `STATUS_CANCELLED` وتطلب إلغاء الطلبات المسلّمة والقابلة للإلغاء على IRP الأصلي. يسبق التنظيف تحرير IRP. ينتظر استدعاء الحالة اكتمال الطلبات في الطابور والطلبات المملوكة للسائق واستدعاءات الإلغاء النشطة. يُكمل السائق الطلبات غير القابلة للإلغاء.

تعلّق الدوال `WdfIoQueueStopSynchronously` و`WdfIoQueueDrainSynchronously` و`WdfIoQueuePurgeSynchronously` استدعاء الضيف عند `PASSIVE_LEVEL` حتى تنتهي الطلبات المعنية. يستمر الإيقاف في قبول الطلبات لكنه يوقف تسليمها وينتظر الطلبات المسلّمة. يرفض التفريغ الطلبات الجديدة ويسلّم المنتظرة ثم ينتظر اكتمال المجموعتين. يلغي التطهير الطلبات المنتظرة والمعلّمة قابلة للإلغاء وينتظر عودة استدعاءات الإلغاء. إذا لم يوجد مصدر للإكمال، يبلّغ الانتظار عن خطأ نموذج متوقف.

تلغي الدالتان `WdfIoQueueStopAndPurge` و`WdfIoQueueStopAndPurgeSynchronously` الطلبات الموجودة مسبقًا في الطابور والطلبات التي يملكها البرنامج والمعلّمة قابلة للإلغاء، ثم تستمران في قبول طلبات جديدة دون تسليمها حتى `WdfIoQueueStart`. يكتمل استدعاء الحالة غير المتزامن والانتظار المتزامن بعد انتهاء الطلبات الأصلية واستدعاءات إلغائها؛ وتبقى الطلبات الجديدة في الطابور من دون تأخير الإشعار. يعيد شكلا Stop قبول الطلبات بعد Drain أو Purge أيضًا.

تستخدم معاملات الطلب تخطيط `WDF_REQUEST_PARAMETERS` ذا 40 بايت. تعيد دوال الوصول إلى الإدخال/الإخراج الأطوال المنطقية، مع الحفاظ على الأسماء المستعارة للمخازن وتعيينات MDL الحالية للإدخال/الإخراج المباشر؛ ويبقى إدخال IOCTL المباشر مخزنًا مؤقتًا. تعيد الاتجاهات الخاطئة والمخازن غير الكافية الحالات الموثقة. ينفذ الإكمال تنظيف الطلب بينما تظل المخازن صالحة، ثم يكمل IRP ويحرر الصفحات المثبتة للطلب؛ وبعدها يدمر الكائنات التابعة والطلب عندما تسمح المراجع بذلك. تُرفض الاستدعاءات الجديدة لدوال الوصول إلى المخازن والمعاملات بمجرد بدء الإكمال؛ وتظل مؤشرات المخازن المكتسبة مسبقًا قابلة للاستخدام أثناء التنظيف. يحفظ المرجع الخارجي للكائن السياق، ولا يحفظ الوصول إلى IRP المكتمل.

تُمثَّل آلية الإلغاء لطلبات طوابير أجهزة التحكم الموصوفة أعلاه. إذا وقع الإلغاء بالفعل، يعيد `WdfRequestMarkCancelableEx` الحالة `STATUS_CANCELLED` دون استدعاء راجع. يزيل نجاح `WdfRequestUnmarkCancelable` الاستدعاء الراجع؛ وأي إلغاء لاحق يسجّل حالة الإلغاء فقط. يقرأ `WdfRequestIsCanceled` هذه الحالة لطلب حي غير معلّم بأنه قابل للإلغاء. بعد نجاح وضع علامة القابلية للإلغاء، يتطلب الإكمال إزالة العلامة بنجاح أو بدء تسليم استدعاء الإلغاء؛ ولا تكفي إضافته إلى الطابور. بعد بدء التسليم يمكن للاستدعاء وعنصر عمل التنسيق لإكمال الطلب، حتى إن كان الاستدعاء ينتظر. يحتفظ مرجع داخلي مستقل بالطلب حتى عودة استدعاء الإلغاء. مع ذلك يصبح IRP غير صالح أولًا عند الإكمال، ويمكن لاستكمال تدمير الطلب النهائي أن ينتظر أيضًا. تكون الأولوية لـDPC ثم استدعاءات الإلغاء بترتيب FIFO ثم عناصر العمل العادية؛ وتسبق استدعاءات الإلغاء كذلك استئناف إطارات الانتظار الجاهزة ذات المستوى السلبي.

تدعم واجهة void القديمة `WdfRequestMarkCancelable` حتى `DISPATCH_LEVEL`. للطلب الملغى مسبقًا تُنفّذ `EvtRequestCancel` تزامنيًا فقط إذا وافق مستوى الطابور IRQL الحالي ولم يملك الخيط قفل الاستدعاء نفسه. وإلا تُدرج worker أو DPC ثم تعود؛ ويُجدول الإلغاء اللاحق أيضًا. لا تُسجّل delivered إلا عند دخول الاستدعاء الحقيقي بعد اكتساب القفل، ولا يكفي الإدراج لإكمال الطلب مبكرًا. دون مزامنة تلقائية (`WdfSynchronizationScopeNone`) توصي Microsoft بـ Ex. [Microsoft](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdfrequest/nf-wdfrequest-wdfrequestmarkcancelable).

تشترك `WdfRequestGetInformation` و`WdfRequestSetInformation` في حقل `IRP.IoStatus.Information` الأصلي ذي 64 بت، بما يشمل كتابة الضيف المباشرة. تسند Set القيمة فقط؛ ويُفحص طول النقل عند الإكمال. تكتب `WdfRequestCompleteWithInformation` الحقل نفسه قبل التنظيف؛ وتحدد التعديلات أثناء التنظيف عبر IRP محفوظ مسبقًا قيمة Information النهائية، رغم أن GetInformation تعيد صفرًا في هذه المرحلة. تعيد `WdfRequestGetIoQueue` الطابور الأصلي. في تهيئة الملفات الافتراضية تعيد `WdfRequestGetFileObject` القيمة NULL دون اختلاق كائن ملف WDF من FILE_OBJECT الخاص بـWDM. تعيد `WdfRequestWdmGetIrp` حزمة IRP نفسها؛ ولا يمكن لاستدعاءات الضيف `IoCompleteRequest`/`IofCompleteRequest` تجاوز إكمال WDF. ما دام مقبض الطلب صالحًا أثناء الإكمال أو بعده، تعيد GetInformation/GetIoQueue صفرًا، ويمسح استرجاع MDL خانة الخرج الصالحة إلى NULL أولًا ثم يعيد `STATUS_INTERNAL_ERROR`. تبقى SetInformation/GetFileObject/WdmGetIrp مرفوضة حينئذ، ولا تتغير قيود دوال المخازن والمعاملات الحالية.

تصف `WdfRequestRetrieveInputWdmMdl` و`WdfRequestRetrieveOutputWdmMdl` عند الحاجة SystemBuffer الموجود لإدخال WRITE وإخراج READ وإدخال/إخراج IOCTL ذي المخزن. يُتحقق من صلاحية الاتجاه وطوله غير الصفري في كل مرة قبل استخدام الواصف الوحيد المخزّن لكل طلب؛ ويحدد أول استرجاع ناجح ByteCount حتى لو اختلف الطول المنطقي للاتجاه الآخر. تعيد `MmGetSystemAddressForMdlSafe` عنوان VA الأصلي لهذا الواصف؛ وتُرفض التعيينات الإضافية وفك التعيين والتحرير بواسطة برنامج التشغيل. يعيد إخراج READ/IOCTL المباشر وإدخال WRITE المباشر قيمة `IRP.MdlAddress` الموجودة دون إنشاء تعيين بمجرد الاسترجاع؛ ويستخدم إدخال IOCTL المباشر مخزن SystemBuffer. تنتهي صلاحية الواصفات وIRP والمخازن عند الإكمال. تحتفظ مراجع الإلغاء الداخلية أو المراجع الخارجية بسياق WDF فقط. يبقى جلب MDL عبر WDF لـ`METHOD_NEITHER` والوصول إلى PFN غير المبني غير مدعومين؛ تستخدم WDFMEMORY الخاصة بالطلب تعيينًا منفصلًا لصفحات مثبتة.

في طلبات KMDF المخزنة والمباشرة وneither، يعمل `WdfDeviceInitSetIoInCallerContextCallback` قبل الطابور في عملية مقدم الطلب عند `PASSIVE_LEVEL`. يجب إكمال الطلب أو استدعاء `WdfDeviceEnqueueRequest` مرة واحدة؛ ويلتقط الاستدعاء الطابور المحدد لنوع الطلب حينها بواسطة `WdfDeviceConfigureRequestDispatching`، أو الافتراضي إذا لم يوجد ربط. لا تنقل تغييرات الربط اللاحقة الطلب المدرج. في IOCTL من نوع `METHOD_NEITHER` وREAD/WRITE بنمط neither، تعيد `WdfRequestRetrieveUnsafeUserInputBuffer` و`WdfRequestRetrieveUnsafeUserOutputBuffer` عناوين المستخدم الأصلية داخل رد الاتصال هذا فقط. تتحقق `WdfRequestProbeAndLockUserBufferForRead` و`WdfRequestProbeAndLockUserBufferForWrite` من أذونات الصفحات وتثبتها للطلب؛ وتعيد `WdfMemoryGetBuffer` عنوانًا مستعارًا للنظام صالحًا في رد اتصال الطابور خارج سياق مقدم الطلب. يحرر إكمال الطلب التثبيت والعناوين المستعارة. تُدعم المؤشرات المضمنة إلى `user_buffers` المعلنة صراحة؛ وتبقى تعيينات المستخدم العامة غير مدعومة.

استخدام `WDF_REQUEST_SEND_OPTION_SYNCHRONOUS`، وقراءة نتيجة الجهاز الأدنى عبر `WdfRequestGetStatus`، ثم إكمال الطلب الأصلي بالحالة نفسها. يُنسّق الإرسال غير المتزامن الافتراضي الطلب أولًا بواسطة `WdfRequestFormatRequestUsingCurrentType` ويسجّل `WdfRequestSetCompletionRoutine`. تتلقى دالة الإكمال `WDF_REQUEST_COMPLETION_PARAMS`، ويمكنها قراءة نتيجة الجهاز الأدنى عبر `WdfRequestGetCompletionParams` أو `WdfRequestGetStatus` ثم إكمال الطلب الأصلي. يمكن للسائق اختيار حالة نهائية تختلف عن حالة الجهاز الأدنى. عند الإرسال مع دالة إكمال، يبقى الطلب معلقًا حتى موعد استجابة PDO المؤجلة في الوقت الافتراضي، ثم توضع دالة الإكمال في الطابور بالحالة النهائية للجهاز الأدنى. تقبل `WDF_REQUEST_SEND_OPTION_TIMEOUT` لإرسال CREATE غير المتزامن قيمة سالبة لفترة نسبية أو موجبة لموعد مطلق بوحدات 100 ns على الساعة الافتراضية الاصطناعية؛ ويعطّلها الصفر. إذا انتهت المهلة قبل الاستجابة السفلية يُسلّم `STATUS_IO_TIMEOUT`؛ وللإكمال الفوري والاستجابة السفلية المتزامنة مع الموعد الأولوية. خيارات الإرسال الأخرى غير المذكورة غير مدعومة. يحتفظ مقبض WDF و`FILE_OBJECT` الخاص بـ WDM بهويتين منفصلتين يمكن الاستعلام عنهما عبر `WdfRequestGetFileObject` و`WdfFileObjectGetDevice` و`WdfFileObjectWdmGetFileObject` أثناء حياة الكائن. يحذف CREATE الفاشل كائن WDF دون استدعاء تنظيف الملف أو إغلاقه؛ وبعد الفتح الناجح يسبق استدعاءا CLEANUP وCLOSE تنظيف السياق وتدميره.

يحفظ `WdfRequestSend` المتزامن المؤجل إطار استدعاء الضيف الحقيقي ويعلّقه، ثم يستأنفه بنتيجة إرسال منطقية بعد الإكمال. تُقرأ NTSTATUS النهائية عبر `WdfRequestGetStatus`. تدعم `WDF_REQUEST_SEND_OPTION_TIMEOUT` لإرسال CREATE المتزامن أيضًا الفترة النسبية السالبة والموعد الافتراضي المطلق الموجب بوحدات 100 ns؛ ويعطّلها الصفر. تعيد المهلة الأسبق `STATUS_IO_TIMEOUT`، وللإكمال الفوري أو الاستجابة السفلية في الموعد نفسه الأولوية. ينفّذ التمرير التلقائي استدعاءات الملف قبل الإرسال السفلي، ويحفظ IRP وملف WDM أثناء استدعاءات التنظيف والتدمير المطلوبة ضمن الإكمال. تحتفظ مراجع WDF الخارجية بالسياق، لكنها لا تمدد عمر ملف WDM للطلب المكتمل.

تقبل طلبات WDM من نوع CREATE/CLEANUP/CLOSE الممررة إلى PDO مضبوط أيضًا `bus_completion` مؤجلًا صراحةً. تنفّذ دالة إكمال الضيف الحقيقية بعد الموعد السفلي، مع الحفاظ على قواعد نشر حالة الانتظار وملكية الحالة النهائية.

يترجم التحقق الاختياري عبر WDK الحقيقي الملفين `driver_kmdf_lifecycle.c` و`driver_kmdf_control.c` كلًا على حدة باستخدام مكتبة دخول KMDF الحقيقية. يحدد `NEVERD_KMDF_FIXTURE` / `NEVERD_KMDF_CFG_FIXTURE` صور دورة الحياة؛ ويحدد `NEVERD_KMDF_CONTROL_FIXTURE` / `NEVERD_KMDF_CONTROL_CFG_FIXTURE` صور جهاز التحكم العادية وذات CFG النشط. يؤدي غياب المنتجات الخارجية إلى تخطٍ معلن. راجع [الاختبارات](testing.md) للتغطية الأصلية وC API/CLI. تقتصر أدلة التنفيذ الحالية على مضيفي Linux.

تقبل `MmProbeAndLockPages` في `KernelMode` نطاقًا متصلًا من صورة برنامج التشغيل يملكه المحمّل عند IRQL <= APC_LEVEL. يجب أن تكون الصفحات قابلة للقراءة وضمن حصة الصفحات الفيزيائية. التخزين خاص ومقيم أصلًا، لذلك تسمح `IoWriteAccess` و`IoModifyAccess` باسم MDL بديل قابل للكتابة حتى لو كان العرض الأصلي للقراءة فقط؛ وتحتفظ `IoReadAccess` بعرض بديل للقراءة فقط. لا تتغير حماية الصورة الأصلية. تُستبعد الفجوات والتعيينات غير المملوكة، وتحدد الملكية أيضًا الصور تحت حد عناوين المستخدم. يلزم فك القفل وتحرير الواصف. لا تضيف واصفات MDL المؤقتة لصفحات الصورة المملوكة للمحمّل اعتماد استعادة بعد إزالة جميع التعيينات البديلة وفك جميع الأقفال وتحرير جميع الواصفات. يسمح هذا العقد بتعيينات بديلة مخبأة في وضع النواة دون عنوان مطلوب. تبقى واصفات MDL الحية وأنواع الملكية أو التعيين الأخرى وقراءات الضيف لهويات PFN المادية اعتمادات؛ ويشمل ذلك قراءات خدمات النسخ والنقل والمقارنة الممثلة في النموذج.

يفسر `KernelDispatcher` معاملات السيمافور `Count` و`Limit` و`Adjustment` باعتبارها `LONG` موقعة من 32 بت، و`Level` للميوتكس باعتباره `ULONG` من 32 بت، و`Wait` باعتباره `BOOLEAN` من 8 بت، مع تجاهل بتات السجل غير المعرفة وفق [Windows x64 ABI](https://learn.microsoft.com/en-us/cpp/build/x64-calling-convention?view=msvc-170). تُرفض القيم غير الصالحة ضمن العرض المحدد وتجاوزات السيمافور قبل تغيير حالة الكائن.

تأتي حدود IRQL من `KernelAPIIRQL.def` وتتحقق النماذج المسؤولة من الشروط المعتمدة على الوسائط. لا يمكن لـDPC استدعاء واجهات السجل أو تخصيص المخزن المقسّم إلى صفحات أو تحريره أو الوصول إليه. تتطلب تحويلات Unicode في `DbgPrint` مستوى `PASSIVE_LEVEL`، بينما يبقى إخراج ANSI والعمليات غير القابلة للترحيل المدعومة متاحة عند `DISPATCH_LEVEL`. للمكدسات حدود؛ فلا يدخل مؤشر مكدس خارج النطاق مكدس عامل آخر محجوب. تمنع المؤقتات الفعالة في امتداد الجهاز تحريره المبكر.

يلبّي انتهاء المؤقت الانتظارات المسجلة قبل أن يعيد DPC ضبطه أو تشغيله. تنفذ DPC المصطفة قبل استئناف إطارات `PASSIVE_LEVEL` المستيقظة. إذا بقي DPC في الطابور ضمن ذاكرة الطلب، يرفض إكمال IRP تحريرها قبل الإكمال وإبطال المخزن المؤقت.

يدعم تنسيق `DbgPrint` الأعداد الصحيحة `d/i/u/o/x/X` والمؤشر `p` والنص `s/c` و`%%` وUnicode محدد الطول `wZ/lZ` والنص العريض `ls/ws` والأعلام والعرض/الدقة بما فيهما `*` ومعدّلات طول الأعداد الصحيحة في Windows. تُقرأ 32 وسيطة متغيرة و1024 بايت للتنسيق على الأكثر. يقتصر العرض والدقة على 512. يوقف التنفيذ صراحةً عند الأعداد العائمة و`%n` والتركيبات المجهولة وتحويلات النص غير ASCII؛ ولا يخمّن النموذج صفحة ترميز Windows أو يستدعي printf المضيف على بيانات الضيف.

ينتهي عمر سجل RegistryPath الأصلي ومخزنه عندما يعود DriverEntry. على برامج التشغيل التي تحتاج السلسلة لاحقًا نسخها أثناء التهيئة.

حجم منطقة تخصيص الكائنات/المخزن هو 1 MiB. تستخدم بايتات المخزن غير المهيّأة المحتوى الحتمي `0xCD`، وتستخدم البايتات المحررة `0xDD`. هذا سيناريو تنفيذ محدد واحد. ترفض عمليات وصول المعالج وواجهات المخازن الممثلة الوصول إلى تخصيصات مخزن محررة أو أجهزة محذوفة أو بايتات غير مخصصة في المنطقة أو حقول كائنات معتمة، كما ترفض الكتابة إلى حقول الكائنات المخصصة للقراءة فقط. تغطي هذه الفحوص أعمار كائنات هذا النموذج؛ وليست تحليلًا عامًا لسلامة ذاكرة برنامج التشغيل. تُعرض خانات جدول الإرسال التي لم تُكتب بصفر يعني «غير مسجّلة». يكتمل طلب السيناريو لدالة رئيسية غير مسجلة عبر المعالج الافتراضي الممثل، بالحالة `STATUS_INVALID_DEVICE_REQUEST`؛ ويظل الفشل ظاهرًا في حالة الإرسال وحالة الإدخال/الإخراج معًا. لا يختلق النموذج عنوان دالة داخل الضيف لذلك المعالج، وتظل قراءة الضيف لخانة لم تُكتب غير مدعومة. التسجيل الصريح لاستدعاء راجع بمؤشر null خطأ.

## سيناريوهات الطلبات

مرّر ملف JSON باستخدام `--scenario` لاختيار الطلبات وإلغاء التحميل الاختياري:

```bash
build-release/bin/neverd emulate-driver path/to/driver.sys \
  --scenario scenario.json > driver-report.json
```

لبرنامج تشغيل ينشئ `\Device\NeverDIO` ويقبل IOCTL مخزّنًا مؤقتًا برمز `0x222000`، يكون مثال `scenario.json` كما يلي:

```json
{
  "requests": [
    {"kind": "create", "device": "\\Device\\NeverDIO"},
    {"kind": "ioctl", "code": "0x222000", "input": "00112233", "output_size": 4},
    {"kind": "cleanup"},
    {"kind": "close"}
  ],
  "unload": true
}
```

يجب أن يطابق اسم الجهاز ورمز IOCTL برنامج التشغيل. عند create، يؤدي حذف `device` إلى اختيار الجهاز الحي الوحيد؛ ويفشل الاختيار إن كان ملتبسًا. تستخدم الطلبات اللاحقة جهاز ملفها ما لم يُعطَ اسم مطابق صراحةً. الحقل الاختياري `file` هو هوية سيناريو غير موقّعة من 32 بت، وقيمته الافتراضية صفر. لكل هوية FILE_OBJECT وFsContext خاصان بها، ويجب أن تتبع ترتيب create ثم عمليات النقل ثم cleanup ثم close. يمكن تداخل ترتيب طلبات الملفات المستقلة. ترفض الأجهزة الحصرية عملية فتح ثانية. تمثّل هذه الهويات كائنات ملفات، لا مقابض مكررة. تُدعم طريقة buffered وطريقتا direct في IOCTL. يجب أن يكتمل الإرسال بصورة متزامنة أو يتبع عقد الاستدعاءات الراجعة للطلب المعلّق أعلاه. تفشل صراحةً أطوال المخرجات غير الصالحة والوصول إلى IRP مكتمل. يجب ألا يترك إلغاء التحميل المطلوب أي جهاز حي أو رابط رمزي أو تخصيص مخزن أو كائن ملف.

يطلب الحقل الجذري الاختياري `"load_address": "0x190000000"` تغيير العنوان الأساسي؛ ويؤدي حذفه أو استخدام `"0x0"` إلى اختيار العنوان المفضّل. يجب أن تستوفي الصورة متطلبات النقل. لا يتضمن أمر التهيئة الأصلي أو واجهة C API سيناريو ضمنيًا.

لا تُقبل في الجذر سوى الحقول `load_address` و`requests` و`unload` و`kernel_exports` و`registry` و`pnp_devices`. تقبل طلبات الملفات العادية `kind` والحقل الاختياري `device` أو `device_id` (لا كليهما) والحقل الاختياري `file`. تتطلب طلبات IOCTL الحقل `code` وتقبل `input` و`output_size` و`direct_input`. يقبل `read` الحقلين `output_size` و`byte_offset`؛ ويقبل `write` الحقلين `input` و`byte_offset`. الإزاحات صفر افتراضيًا، وتقبل أعدادًا صحيحة أو سلاسل سداسية عشرية، ويجب أن تلائم قيمة غير سالبة ضمن عدد صحيح موقّع من 64 بت. ترفض طلبات دورة الحياة حقول النقل. تُرفض الحقول المجهولة أو المكررة. يقبل `code` عدد JSON صحيحًا غير موقّع من 32 بت أو سلسلة سداسية عشرية تبدأ بـ`0x`. أما `input` فهو سلسلة بايتات سداسية عشرية بطول زوجي، بلا بادئة أو مسافات؛ وحذفه يعني مدخلًا فارغًا. `output_size` عدد JSON صحيح غير موقّع؛ وحذفه يعني الصفر. تُرفض الكسور وصيغ كتابة الأعداد العائمة.

تقبل طلبات READ/WRITE/IOCTL وحدها الحقل الاختياري `cancel_after_100ns`، وهو عدد JSON صحيح من 0 إلى `INT64_MAX` ‏(9223372036854775807). يجدول الإلغاء نسبةً إلى لحظة تقديم الطلب بوحدات افتراضية مقدارها 100 ns، لا بالوقت الفعلي. في KMDF، تطبّق القيمة صفر الإلغاء بعد توجيه الإطار وقبل استدعاء الإدخال/الإخراج الراجع للضيف؛ وإذا كان التوجيه قد أكمل الطلب بالفعل تكون الأولوية للإكمال. في WDM، تطبّق القيمة صفر بعد عودة دالة الإرسال. عند التأخير الموجب لا يتقدم الوقت إلى موعد مؤقت أو انتظار أو إلغاء إلا عند غياب استدعاءات أو إطارات جاهزة. يُلغي طلب WDM المعلّق عبر روتين الإلغاء المسجّل عند `DISPATCH_LEVEL` مع قفل الإلغاء؛ يجب تحرير القفل باستخدام `Irp->CancelIrql` قبل الإكمال. ويظل الإلغاء العام للطوابير وPnP غير مدعوم. يحتوي تقرير كل طلب على `cancel_requested_at_100ns`: الوقت الافتراضي المطلق الذي وقع فيه الإلغاء فعلًا، أو null إن لم يقع، بما في ذلك إذا سبق الإكمال الإلغاء. لا يكمل طلب الإلغاء وحده IRP ولا يحدد حالته النهائية.
تستخدم `IoSetCancelRoutine` و`IoAcquireCancelSpinLock` و`IoReleaseCancelSpinLock` و`IoCancelIrp` حالة IRP وقفل الإلغاء نفسها؛ يستدعي `IoCancelIrp` الروتين المسجّل تزامنيًا ويعيد ما إذا استُدعي.

يتيح الحقل المنطقي الاختياري `user_unmap_after_dispatch` لطلبات WDM غير المخزنة ذات المخزن غير الفارغ إلغاء الوصول إلى عناوين المستخدم الأصلية بعد عودة الإرسال وقبل العمل أو الإلغاء المجدول. تبقى الصفحات المثبتة وأسماء النظام المستعارة صالحة حتى يفكّ السائق القفل، بينما يفشل استخدام مؤشر المستخدم الخام أو قفل جديد. يكون `output_hex` فارغًا إذا أُلغي عنوان الإخراج. لا تُعاد الاستفادة من عناوين تخصيصات السيناريو الأصلية والمعلنة صراحةً ولا تُعاد تعيينها، كما لا تُحاكى أوقات إلغائها الاعتباطية. لا يشمل هذا القيد إعادة استخدام عناوين نطاق عروض MDL للمستخدم الموضح أدناه.

يحدد `requestor_process_id` عملية طلب اصطناعية (الافتراضي 4096؛ المدى 5 إلى `UINT32_MAX`). يعيد `IoGetRequestorProcessId` هويتها لطلب IRP حي، ويعيد `PsGetCurrentProcessId` الهوية في الإرسال المباشر أو 4 في عامل النظام المحاكى. يجعل تبديل العملية عناوين المستخدم لعملية أخرى غير متاحة، بينما تبقى أسماء النظام المستعارة لصفحات MDL المقفلة صالحة. يلغي `requestor_exit_after_dispatch` جميع عناوين المستخدم الأصلية لهذه العملية بعد عودة الإرسال، ويرفض I/O الجديدة منها مع إبقاء CLEANUP وCLOSE الصريحتين؛ لا يُفترض الإلغاء أو إغلاق المقابض تلقائياً.

يمكن لعامل النظام الحصول على كائن العملية المعتم لطلب IRP حي عبر `IoGetRequestorProcess`، ثم استخدام `KeStackAttachProcess` مع `KAPC_STATE` قابل للكتابة في النواة للوصول مؤقتاً إلى عناوين المستخدم الأصلية، وإعادة الحالة نفسها عبر `KeUnstackDetachProcess`. يعكس `IoGetCurrentProcess` و`PsGetProcessId` العملية المرفقة، بينما يظل `PsGetCurrentProcessId` بالقيمة 4، وهي عملية إنشاء العامل. يُرفض صراحةً إرفاق عملية منتهية أو IRP مكتمل أو حالة غير مطابقة، وكذلك الانتظار أو إكمال IRP أثناء الإرفاق.

في طلبات direct IOCTL، يهيّئ `input` مخزن النظام الأول، بينما يهيّئ `direct_input` المخزن الثاني المنفصل الذي تصفه MDL، مع استكماله بأصفار حتى `output_size`. تتطلب `METHOD_IN_DIRECT` صلاحية القراءة، لكنها لا تعني أن تعيين النظام للقراءة فقط. تستخدم الطريقتان مخازن سيناريو قابلة للقراءة والكتابة. يزيل `MdlMappingNoWrite` صلاحية الكتابة للتعيين، ويزيل `MdlMappingNoExecute` صلاحية التنفيذ. يلغي فك التعيين صلاحية العنوان الافتراضي للنظام؛ وتحافظ إعادة التعيين على البيانات المقفلة نفسها. ينهي الإكمال عمر MDL والتعيين. تُنمذج حقول MDL العامة التي تستخدمها وحدات ماكرو WDM؛ وتُرفض حقول process وPFN للواصفات MDL غير المبنية وواصفات MDL المنشأة يدويًا وتعيينات المستخدم خارج نموذج MDL المملوك للعملية الموضح أدناه والوصول المباشر عبر UserBuffer الخام. يكون MDL لمخزن direct صفري الطول null.

يخصص `IoAllocateMdl` بيانات وصفية لمخزن غير فارغ لا يفيض عنوانه، دون فحصه أو قفله. يجب أن يتسع حقل الحجم ذي 16 بت للواصف الممثل ومصفوفة PFN، مع احتساب الإزاحة داخل الصفحة ضمن سعة PFN. مساحة الواصف مستقلة عن حجم المخزن الذي يصفه. يمكن أن يكون `Irp` هو NULL أو IRP ممثلًا حيًا. يستبدل الواصف الأساسي رأس سلسلة المشغّل، وتبقى الواصفات المفصولة ملكًا للمشغّل. يُلحق `SecondaryBuffer` الواصف بالنهاية أو يجعله الرأس إذا كانت السلسلة فارغة. يجب إبقاء MDL الأصلي للطلب ذي direct-I/O قابلًا للوصول؛ لا يمكن للمشغّل استبداله أو تحريره. يجب أن يكون `ChargeQuota` هو FALSE؛ ويعيد نفاد الساحة NULL. يتطلب `MmBuildMdlForNonPagedPool` المجال كله داخل تخصيص حي واحد من المجمّع غير القابل للترحيل. تعيد الدالة الآمنة وماكرو WDM استخدام العنوان والصلاحيات الأصلية حتى مع أعلام جديدة تمنع الكتابة/التنفيذ. تُرفض تعيينات النظام الإضافية وإلغاء التعيين. يحرر `IoFreeMdl` واصف المشغّل المحدد فقط، دون فصله أو اتباع `Next`. يجب فك قفل MDL المستخدم قبل تحريره يدويًا. عمر مخزن المجمّع مستقل، ويُسمح بترتيبي التحرير بشرط عدم استخدام الذاكرة المحررة لاحقًا.

يمكن للمشغّل تعديل `MDL.Next` و`IRP.MdlAddress` لإدراج الواصفات الممثلة أو فصلها. يتحقق الإكمال النهائي لـ IRP من السلسلة الحالية كاملة قبل التعديل، ثم يفك أقفال MDL المستخدم المرتبطة، ويلغي أسماءها البديلة، ويحرر جميع الواصفات المرتبطة. تبقى الواصفات المفصولة وذاكرة المجمّع ملكًا للمشغّل. تفشل صراحةً الدورات والروابط المجهولة أو المحررة والواصفات المشتركة بين IRP حية والواصفات الخاصة بـ WDF المضافة إلى سلسلة WDM. تمنع تبعيات DMA والموزّع النشطة التحرير المبكر. تبقى حقول MDL الممثلة الأخرى وPFN المبنية للقراءة فقط؛ ولا تدعم حقول العملية أو PFN غير المبنية أو MDL المنشأة يدويًا. يجب تحرير كل واصفات المشغّل المتبقية قبل التفريغ.

`IoBuildPartialMdl` يصف نطاقًا فرعيًا غير فارغ من MDL مصدر مبنية؛ يختار الطول صفر بقية النطاق، ويجب أن تتسع MDL الهدف لعدد PFN المطلوب. تشترك الواصفات الجزئية في الصفحات المادية دون قفل إضافي. ترث تعيين النظام الحي للمصدر أو تنشئ تعيينًا مستقلاً عبر `MmGetSystemAddressForMdlSafe`. تحرير MDL جزئية أو تهيئتها لإعادة الاستخدام يحرر فقط التعيين الذي تملكه. يمكن عندئذ تنفيذ دالة WDK المضمنة الحقيقية `MmPrepareMdlForReuse` قبل استدعاء `IoBuildPartialMdl` من جديد. يمكن تحرير واصف المصدر غير القابل للترحيل مستقلاً؛ أما قفل المستخدم الجذري أو اسم النظام البديل المستعار فلا يُحرر ما دامت MDL جزئية تعتمد عليه. يفحص الإكمال السلسلة كاملة قبل تحرير التبعيات، بغض النظر عن ترتيب الواصفات. يمنع DMA النشط إعادة البناء والتحرير المبكر.

تدعم `MmMapLockedPagesSpecifyCache` تعيينات `UserMode` في سياق طالب حي، بما فيه عامل ملحق بعملية ضمن الحدود المدعومة، عند `APC_LEVEL` أو أدنى. القيم `MmNonCached` و`MmCached` و`MmWriteCombined` صالحة، لكن التعيين يرث سمة التخزين المؤقت للصفحات المادية القائمة ولا يغيرها. تستخدم RAM العادية الحالية السمة Cached؛ تُرفض قيم التعداد المحجوزة ولا تُحاكى أزمنة مخبأ CPU. ينشئ كل استدعاء عرضًا مستقلاً للعملية على الذاكرة المادية نفسها دون تغيير `MappedSystemVa`. العروض غير قابلة للتنفيذ دائمًا (NX)، ويجعلها `MdlMappingNoWrite` للقراءة فقط. يجب أن تكون ذاكرة المجمّع غير قابلة للترحيل وتشغل صفحات خاصة كاملة. إعادة القفل عبر `MmProbeAndLockPages` تحافظ على PFN الأصلي. يجب أن يحافظ العنوان المطلوب على إزاحة صفحة MDL وأن يقع في نطاق VA المحدود المخصص للعروض؛ يرفع نفاده `STATUS_INSUFFICIENT_RESOURCES` القابل للالتقاط.

تتطلب `MmUnmapLockedPages` زوج عنوان المستخدم/MDL الدقيق والعملية المنشئة. تُزيل الاسم البديل فعليًا وتعيد ميزانية التعيين؛ لذلك يستطيع التخصيص التلقائي و`RequestedAddress` إعادة استخدام VA المحرر. يستخدم التعيين الجديد ذاكرته المادية وصلاحياته الخاصة، بينما تحتفظ الأقفال وأسماء النظام البديلة السابقة بالصفحات الأصلية. تُعرّف العروض بالزوج `(PID, VA)`، ويمكن لعمليات حية متعددة الاحتفاظ بالعنوان العددي نفسه مع صفحات وصلاحيات مختلفة. يستبدل تبديل العملية الروابط المرئية لـ CPU كمعاملة واحدة؛ ويحافظ فشل الفحص المسبق على الروابط والصلاحيات الأصلية. خروج عملية يزيل عروضها فقط ولا يمس عرض عملية أخرى في العنوان نفسه. إلغاء VA الأصلي للسيناريو لا يمس عروض MDL المستقلة؛ وتظل العروض الحية مانعةً للتحرير المبكر للواصف والقفل الجذري وذاكرة المجمّع أو الطلب. يُرفض تبديل العملية صراحةً عند وجود كائن جدولة معتم نشط في عرض مستخدم، دون اختلاق هوية كائنات نواة لكل عملية. تخصيص الذاكرة الافتراضية العام وواجهات العمليات غير الممثلة ما زالت خارج النطاق.

في كل طرق IOCTL ذات `output_size` غير الصفري، يجب ألا تتجاوز `Information` قيمة `output_size` حتى لو كان مخزن الإدخال أكبر. إذا لم يوجد مخزن إخراج، يمكن أن تتضمن `Information` نتيجة من 64 بت يحددها برنامج التشغيل؛ ولا تُفسَّر على أنها عدد بايتات مطلوب نسخها. يحتفظ التقرير بالقيمة العددية ويضيف `information_hex` كسلسلة سداسية عشرية دقيقة لقارئات JSON التي لا تستطيع تمثيل جميع الأعداد الصحيحة من 64 بت.

في READ/WRITE، يحدد `DO_BUFFERED_IO` أو `DO_DIRECT_IO` النقل المخزن أو المباشر. إذا لم يُضبط أي منهما، يظهر عنوان المستخدم الأصلي في `IRP.UserBuffer` فقط: تستخدم WRITE الإدخال وتستخدم READ الإخراج، دون إنشاء SystemBuffer أو MDL ضمنيًا. يجب على برنامج التشغيل فحص العنوان والوصول إليه في سياق المستدعي أو تثبيت الصفحات قبل تأجيل العمل. ينطبق `user_input_access` على neither WRITE و`user_output_access` على neither READ. تتوقف الطلبات المخزنة أو المباشرة ذات حقوق وصول صريحة، وكذلك الأعلام المتعارضة. تُفحص Information مقارنة بطول النقل؛ وتعيد الكتابة عددًا، بينما تعيد القراءة بايتات.

يربط `kernel_exports` أسماء الإجراءات بقيم منطقية صريحة للتوافر، مثل `"kernel_exports": {"OptionalRoutine": false}`. تحصل الصادرات الممثلة والاستيرادات الثابتة على عناوين مستقرة مشتركة مع `MmGetSystemRoutineAddress`. يُحل التصدير الغائب صراحةً إلى NULL، ولا يمكنه تلبية استيراد ثابت. ويُحل التصدير المعلن وجوده دون نموذج API إلى مصيدة مؤجلة. يوقف الاسم الديناميكي المجهول التنفيذ بتشخيص يفيد بأن التوافر غير محدد؛ ولا يُستنتج الغياب أبدًا من عدم وجود التنفيذ. الأسماء محدودة الطول ومكوّنة من ASCII قابل للطباعة، وحلها حساس لحالة الأحرف. السجل خاصية لسيناريو محدد، وليس ادعاءً بمطابقة كل إصدار Windows.
`IoMarkIrpPending`, `IoGetCurrentIrpStackLocation` و`MmGetSystemAddressForMdlSafe` دوال مساعدة من ترويسات WDM يمثلها النموذج؛ ولا يعني ذلك الإعلان عنها كتصديرات افتراضيًا، لذا يتطلب توافرها كتصديرات استيرادًا ثابتًا أو إعلانًا صريحًا في `kernel_exports`.

يقتصر نص السيناريو على 2 MiB، وبحد أقصى 64 طلبًا، و65536 بايت لكل مخزن إدخال أو إخراج، و512 KiB إجمالًا للبايتات المطلوبة بما فيها محتوى `direct_input`. تسري ميزانيات التعليمات والمشاهدات وذاكرة الضيف والوقت على السيناريو كله. تحتوي منطقة 1 MiB أيضًا على الكائنات والبيانات الوصفية، ولذلك يمكن للصورة استنفاد ذاكرة النموذج قبل استهلاك الحد الأقصى لمخازن السيناريو.

## سيناريوهات السجل

تحدد المصفوفة الاختيارية `registry` شجرة سجل ملموسة محلية للجلسة. لكل مفتاح
حقل `path` مطلوب ومصفوفة `values` اختيارية؛ وتتضمن كل قيمة `name` وعددًا صحيحًا
غير موقّع `type` وبيانات سداسية عشرية `data`. يحدد اسم القيمة الفارغ القيمة
الافتراضية. مثال لقيمة DWORD هو `{"name":"Mode","type":4,"data":"01000000"}`.
تُحفظ بايتات القيم كما هي تمامًا؛ ولا يصلح النموذج محارف نهاية السلاسل أو يوسّع
متغيرات البيئة.

يجب أن تكون المسارات مطلقة ومن أحرف ASCII تحت `\\Registry\\Machine` أو
`\\Registry\\User`. تُنشأ مفاتيح الأسلاف ضمنيًا. تُقارن هويات المفاتيح والقيم
دون حساسية لحالة الأحرف وفق قواعد ASCII؛ وتُرفض الأسماء غير ASCII والهويات
المكررة. عند حذف `registry` يظل توافر السجل غير محدد وتتوقف استدعاءات السجل.
أما `"registry": []` فتصف نطاق أسماء فارغًا صراحةً. لا يُستنتج من برنامج التشغيل
أي مفتاح أو قيمة أو بيانات من سجل المضيف أو إعداد للخدمة.

تعيد `ZwOpenKey` و`ZwCreateKey` مقابض معتمة مستقلة، مع فحص صلاحيات كل مقبض
عند الاستعلام والكتابة وإنشاء المفاتيح الفرعية والحذف. تمنح الشجرة المضبوطة
البتات المدعومة في `KEY_ALL_ACCESS`، بما فيها القناعان المعتادان `KEY_READ`
و`KEY_WRITE`. هذه شجرة اختبار متاحة صراحةً، دون قوائم ACL الخاصة بـWindows أو
تقييم الامتيازات. لا تُدعم الحقوق العامة أو `MAXIMUM_ALLOWED` أو عروض السجل
البديلة أو واصفات الأمان المخصصة أو الفئات أو الروابط الرمزية. يتطلب الإنشاء
بمسار نسبي مقبضًا للأب المباشر مع `KEY_CREATE_SUB_KEY`. مفاتيح الإدخال غير
متطايرة؛ ويمكن إنشاء مفاتيح متطايرة، لكن يُرفض إنشاء مفتاح غير متطاير تحت أب
متطاير. لا يوجد نموذج لإعادة التشغيل أو الحفظ على القرص.

تنفذ `ZwQueryValueKey` فئات المعلومات Basic وFull وPartial وصيغ Align64
المعرّفة لها، بما في ذلك الأطوال الدقيقة والبيانات المحاذاة والإخراج الجزئي
والنتيجتان المختلفتان `STATUS_BUFFER_TOO_SMALL` و`STATUS_BUFFER_OVERFLOW`.
تغيّر `ZwSetValueKey` و`ZwDeleteValueKey` شجرة هذه الجلسة فقط. ترفض `ZwDeleteKey`
حذف مفتاح له مفاتيح فرعية قائمة؛ وتعيد مقابض المفتاح المحذوف
`STATUS_KEY_DELETED` إلى أن تُغلق. تحرر `ZwClose` المقبض بصورة مستقلة عن المفتاح،
ويفشل إلغاء التحميل المطلوب ما دامت هناك مقابض سجل مفتوحة.

الحدود هي 256 مفتاحًا بما فيها الأسلاف، و1024 قيمة إجمالًا، و65536 بايت لكل
قيمة، و512 KiB لمجموع بيانات القيم، و1024 بايت ASCII لمسار المفتاح، و256 بايت
لاسم القيمة، و256 مقبضًا مفتوحًا في الوقت نفسه. تخضع عمليات الإنشاء والتعديل
للحدود نفسها المطبقة في الفحص المسبق للسيناريو. يحتفظ `configuration.registry`
في التقرير بالإدخال الأصلي؛ ويسرد `registry` المسارات والقيم النهائية للمفاتيح
القائمة، بما فيها التعديلات المرصودة قبل التوقف. تُعرض حالة السجل غير المحددة
بالقيمة null. لا تتضمن لقطة القيم هذه خاصية التطاير أو هويات المقابض.

## فحص قبول مثال Microsoft

ينزّل [سكربت التحقق](../../scripts/validate_windows_driver_sample.py)، الذي يُشغّل اختياريًا، مصدر Microsoft SIOCTL عند المراجعة المثبّتة في [بيان التحقق](../../unittests/emulation/fixtures/sioctl-validation.json)، ويتحقق من تجزئات SHA-256، ثم يترجم المصدر غير المعدّل باستخدام ترويسات MinGW-w64 DDK. يحتفظ بالترخيص/المنشأ الأصليين وأوامر البناء والسيناريو والتقارير في مجلد المخرجات المختار. يتطلب وصولًا إلى الشبكة وClang و`lld-link` و`nm` وترويسات DDK الخاصة بـMinGW-w64:

```bash
python3 scripts/validate_windows_driver_sample.py \
  --neverd build-release/bin/neverd \
  --output build-release/driver-validation/sioctl
```

استخدم `--headers` إذا كان مجلد ترويسات MinGW-w64 في موضع غير افتراضي. ينشئ السكربت مكتبة استيراد MS COFF من اعتماديات ملف الكائن المترجم. يشغّل الفحص سيناريوهات buffered وin-direct وout-direct منفصلة عبر DriverEntry وcreate وIOCTL وcleanup وclose وunload. أضف `--debug` واختر مجلد مخرجات منفصلًا للترجمة مع `DBG=1` والتحقق من رسائل سجل الضيف. لا يسجّل المثال الأصلي معالج cleanup؛ لذلك يكمل المعالج الافتراضي في النموذج cleanup بالحالة `STATUS_INVALID_DEVICE_REQUEST` (`0xC0000010`). يستمر برنامج التشغيل في الإغلاق وإلغاء التحميل، ويعيد IOCTL الناجح البايتات المتوقعة. لهذا السيناريو الكامل، يكون رمز خروج CLI المتوقع **2** وتكون `scenario_success` بالقيمة false. ينجح السكربت نفسه فقط عندما تتطابق كل هذه النتائج، بما فيها فشل cleanup الظاهر؛ ولا يعيد كتابة المثال لإخفاء تلك النتيجة.

## التحقق من قبول مثال Zero

يبني [سكربت التحقق من Zero](../../scripts/validate_zero_driver_sample.py)
الإضافي مثال Zero WDM العام لبافل يوسيفوفيتش دون تعديل، باستخدام المراجعة
والتجزئات الموجودة في [ملفه التعريفي](../../unittests/emulation/fixtures/zero-validation.json).
شغّل `python3 scripts/validate_zero_driver_sample.py` مع متطلبات أدوات البناء
نفسها. تُحفظ الشفرة المصدرية ورخصة MIT والأوامر والسيناريو والتقرير افتراضيًا
تحت `build-release/driver-validation/zero`. تختبر تسعة طلبات القراءة المباشرة
عبر حدود الصفحات، وأعداد البايتات المكتوبة، والإحصاءات الذرية داخل الضيف،
وطلب IOCTL بإدخال/إخراج مخزّن مؤقتًا لقراءة الإحصاءات. يظل فشل القراءة ذات
الطول الصفري وغياب معالج CLEANUP في المثال ظاهرين؛ ورمز خروج CLI المتوقع هو
2، مع نجاح close وunload. لا ينجح سكربت التحقق إلا عند التطابق التام لهذه
النتائج وجميع بايتات الإخراج.

## التقارير وSDK

يميز تقرير JSON بين `stop_reason` و`nt_status` و`nt_success` القابلين للقيمة null، وبين PC عند التوقف وعدد التعليمات. ويحفظ استدعاءات API والحالة القابلة للمشاهدة التي جُمعت قبل التوقف، بما فيها كائنات الأجهزة وعناوين الاستدعاءات الراجعة لبرنامج التشغيل. تُمثّل عناوين الضيف بسلاسل سداسية عشرية حتى لا يفقد مستهلكو JSON دقة 64 بت. يسجّل الكائن `configuration` حدود التشغيل واسم الخدمة وتجاوزات `kernel_exports` وإدخال `registry`. اسم ملف التعريف هو `wdm-x64-scheduled-v100`. يظل `nt_status` نتيجة DriverEntry، بينما تصف `scenario_success` التهيئة والطلبات المكتملة معًا. تحدد `phase` و`requests` و`unload_completed` أي أجزاء دورة الحياة المطلوبة قد نُفّذت. يسجّل كل استدعاء API وكل عملية كتابة من المعالج مرحلتها أيضًا: `driver_entry` أو `add_device:<ID>` أو `request:N`, `callback:N` أو `unload`. ويعرض كل طلب حالتي الإرسال والإدخال/الإخراج والإكمال وطول المعلومات وبايتات `output_hex` المعادة. يصف `preferred_image_base` العنوان الأساسي الأصلي لـPE. أما `security_cookie` فهو عنوان الضيف لملف تعريف الارتباط المهيّأ، أو `"0x0"` إن لم تكن هناك حاجة إليه. حقول الطلب هي `kind` و`device` و`device_id` و`pnp` و`file`, `requestor_process_id` و`byte_offset` و`code` و`irp` و`completed` و`cancel_requested_at_100ns` و`dispatch_status` و`io_status` و`information` و`information_hex` و`output_hex`. يظل الحقل العددي `information` عدد JSON صحيحًا عشريًا دقيقًا؛ وتحفظ `information_hex` البتات نفسها أيضًا للعملاء الذين يقرؤون أعداد JSON بدقة لا تتجاوز 53 بت.

تستخدم ملاحظات عناصر العمل المرحلة `callback:N`. يحتفظ الطلب المعلّق بالقيمة `STATUS_PENDING` في `dispatch_status`؛ وتُسجّل حالة الإكمال النهائية منفصلة في `io_status` وتحدد مساهمته في `scenario_success`.

يمرر `ExRaiseStatus` البتات الدنيا الـ32 من NTSTATUS إلى معالج استثناءات الضيف؛ ويرفع `ExRaiseAccessViolation` و`ExRaiseDatatypeMisalignment` الاستثناءين `STATUS_ACCESS_VIOLATION` و`STATUS_DATATYPE_MISALIGNMENT`. يتبع الملف صفحات DDI الفردية لدى Microsoft: يسمح ExRaiseStatus بالمستوى `APC_LEVEL`، بينما تتطلب الدالتان بلا معاملات المستوى `PASSIVE_LEVEL`. تسمح بعض تعليقات SAL في WDK بمستوى APC_LEVEL لهاتين الدالتين؛ ويحتفظ هذا الملف بالقيد الموثق الأشد. يبقي الاستدعاء الذي يرفع استثناءً `result: null` ويسجل الرمز في `detail`؛ ولا يعرض عودة ناجحة مصطنعة من API.

يستخدم تسليم الاستثناءات جداول unwind المفككة لصورة x64 بالإصدار الأول ونطاقات `__C_specific_handler`، وينفّذ مرشحات الضيف ومعالجاته و`__finally` أثناء فك المكدس فعليًا. تعني نتيجة المرشح صفرًا مواصلة البحث، والموجبة اختيار المعالج، والسالبة طلب استئناف التنفيذ. يقتصر الاستئناف السالب على استثناءات وصول CPU إلى ذاكرة المستخدم القابلة للالتقاط؛ ولا يطبّق إلا تعديلات `CONTEXT_INTEGER | CONTEXT_CONTROL` التي اجتازت التحقق، مع حفظ بقية حالة CPU الأصلية كاملة. يدعم فك إطارات الدوال المساعدة العادية واستعادة السجلات العامة غير المتطايرة وحدود المكدس الحالي و`GetExceptionCode()`. ينفّذ finally في المسار الطبيعي وفي فك الاستثناء كود الضيف الحقيقي. ترث المرشحات وfinally هوية العملية/الخيط وصلاحيات وصول المستخدم من التنفيذ الأب، دون ترقية عامل نظام لا يملك تلك الصلاحيات. يستطيع المعالج رفع استثناء جديد إلى نطاق محيط مدعوم. تُدعم الاستثناءات المتداخلة وفك المكدس المتصادم وسلاسل V1 والمقدمات الجزئية والنهايات القياسية واستعادة XMM6–XMM15 كاملة. تحفظ السجلات روابطها ولا يُكرر finally الذي بدأ. تظل شخصيات C++ والبيانات الوصفية الناقصة مرفوضة. يتوقف استثناء API غير المعالج بـ`model_error`، وتظل أخطاء CPU الأخرى خارج استثناءات ذاكرة المستخدم القابلة للالتقاط نهائية. تختار القيمة الثابتة `EXCEPTION_EXECUTE_HANDLER` معالجها مباشرةً. لا ينفّذ فك المكدس finally للنطاقات التي يغادرها إلا بعد اختيار المعالج؛ فلا تُنفّذ أعمال التنظيف أثناء البحث أو عند استئناف التنفيذ الأصلي بواسطة المرشح. تُفحص `EXCEPTION_POINTERS` وسجلات الاستثناء وحقول `CONTEXT` غير المدعومة بعد كل مرشح، ويُرفض تعديلها صراحةً. استئناف استثناء رفعته واجهة API ممثلة بواسطة مرشح سالب غير مدعوم.

ينقل KVM/WHP الأصلي على x64 أخطاء `#XM` الفعلية إلى C SEH في برنامج التشغيل عبر `X64SIMDException`. يحتفظ `CONTEXT` للأخطاء العتادية بسجلات XMM0–15 وMXCSR. تعمل المرشحات وfinally أثناء فك مكدس الاستثناء والمعالجات المختارة مع MXCSR `0x1f80` وعلم DF ممسوح. يستطيع المرشح السالب تعديل XMM و`CONTEXT.MxCsr` العلوي ضمن قناع CPU الضيف ثم إعادة التعليمة الأصلية؛ لا يتحكم `FltSave.MxCsr` في استعادة النواة. تحتفظ استثناءات API النموذجية بحقول الأعداد الصحيحة والتحكم؛ وتبقى تعديلات x87/AVX مرفوضة.

تبقى نطاقات C SEH نصف مفتوحة، فلا تشمل عنوان النهاية. قد تقع نقطة انتقال صالحة لـ `__C_specific_handler` داخل النطاق المحمي: يُصدر [LLVM 20.1.8](https://github.com/llvm/llvm-project/blob/llvmorg-20.1.8/llvm/lib/CodeGen/AsmPrinter/WinException.cpp#L600-L608) القيمة `EndLabel + 1` كحد نهائي. يحتفظ نموذج Windows بالحدود الأصلية ويتحقق بصورة مستقلة من قابلية تنفيذ الهدف وانتمائه إلى الدالة وتطابق عنوان المتابعة، بما في ذلك بعد إعادة التموضع. يحفظ `KernelSEHContinuationCases.def` تخطيط العينة الأصلية، ويختبر `ScopeEndLabelMayOverlapTheHandlerLandingPad` المعالجات الثابتة والمرشحات. تتحقق الاختبارات المصاحبة من استبعاد النهاية ورفض الأهداف غير الصالحة دون استهلاك حالة الإرسال، بحيث يمكن إعادة المحاولة. تعمل هذه الاختبارات الخالصة ضمن `NeverDNativeDriverTests` مع تعطيل Unicorn.

يستخدم فك المكدس نحو الهدف حد النطاق الأصلي أيضًا: لا يغادر نطاق `finally` إذا ظل هدف المعالج داخله. يختبر `FinallyRespectsRawScopeEndAtHandlerTarget` جانبي هذا الحد ويقارنهما مباشرة مع `ntdll.dll!__C_specific_handler` على Windows x64. لا يصلح NeverD النطاقات التي يولدها المترجم. تعيد نسخ العينة الأصلية المبنية بـ Clang 20/21 فشلًا من الضيف في النمطين `T` و`J` لأن النهاية المنحازة تشمل الهدف المختار، بينما ينفذ Clang 23 عمليتي التنظيف. يزيل [تغيير LLVM #144745](https://github.com/llvm/llvm-project/pull/144745) انحياز `+1` القديم. تُسجل هذه النتائج الخاصة بالمترجم بصورة منفصلة عن أعطال الخلفية.

يتحقق `__GSHandlerCheck_SEH` من ملف تعريف الارتباط الأمني الحالي للصورة قبل البحث وأثناء فك المكدس، حتى للإطارات التي لا تحتوي finally. تدعم المواقع الثابتة والمحاذاة الديناميكية إزاحات موقعة مفحوصة وترميزًا بمؤشر الإطار الأصلي. تعمل أعلام معالج C بشكل مستقل عن فحص الحماية. لا تقرأ المقدمات والنهايات قيمة لم تُنشأ بعد. يوقف عدم التطابق التنفيذ قبل المرشح أو التنظيف أو المعالج المعني. يفحص `__GSHandlerCheck` المستقل القيمة أيضًا أثناء البحث وفك المكدس دون اختلاق نطاقات C. يتطلب التعرف هوية رمز أو استيراد دقيقة، ولا يُخمن الكود المجهول من أنماط التعليمات. تظل أغلفة GS/C++ ومعالجات استثناءات C++ غير مدعومة. تنفذ الإطارات الأصلية في `driver_seh_gs.h` أيضًا فاحص WDK المرتبط.

يستخدم المثال الأصلي `driver_wdm_seh.c` رؤوس WDK أصلية والخيار `/GS-`. اضبط `NEVERD_WDM_SEH_FIXTURE` و`NEVERD_WDM_SEH_CFG_FIXTURE` للصورتين العادية وذات CFG النشط. يعيد المثال [driver-seh-scenario.json](../examples/driver-seh-scenario.json) تموضع الصورة، ويلتقط استثناء API داخل DriverEntry، ثم يفرغ برنامج التشغيل. يدعم مسار WDM المنفصل METHOD_NEITHER فحص ذاكرة المستخدم وقفل MDL ومعالجة أعطال الذاكرة ضمن السياق.

يحفظ الكائن `fault`، الذي يقبل null، أول عطل نهائي مسجل في الواجهة الخلفية. تُعالج استثناءات وصول CPU إلى ذاكرة المستخدم القابلة للاستئناف عبر مسار SEH المذكور أعلاه. تميّز حقوله `kind` و`pc` والحقول القابلة للقيمة null، وهي `address` و`size` و`access` و`interrupt`، بين الذاكرة غير المعيّنة أو المحمية والنطاقات غير الصالحة والتعليمات غير الصالحة واستثناءات المعالج. تُستخدم سلاسل سداسية عشرية للعناوين وأعداد صحيحة للأحجام ومتجهات المقاطعة. لا يمكن لقراءات المشاهدة استبدال العطل الأصلي. لا يمكن للواجهة الخلفية المتعطلة استئناف التنفيذ، ولا يعني هذا السجل معالجة SEH داخل الضيف.

يعدّ `instructions` محاولات تنفيذ تعليمات الضيف التي سُمِح بها. لا تُحتسب التعليمة المرفوضة من سياسة التنفيذ؛ أما التعليمة المسموح بها التي تتعطل داخل المعالج فتُحتسب. لا تزيد عمليات إرسال API الاصطناعية أو علامة العودة هذا العداد.

القيمة المنطقية الاختيارية `trace_memory_writes` في السيناريو هي true افتراضياً. عند ضبطها على false تبقى `writes` فارغة وتُحسب استدعاءات API فقط ضمن ميزانية الأحداث. يظل التحقق من الذاكرة ومراقبو عمليات الكتابة المكتملة وحدود التعليمات والوقت فعّالة. يسجل التقرير الاختيار في `configuration.trace_memory_writes`، وتستخدم واجهة C++ الحقل `DriverOptions::TraceMemoryWrites`.

يحمل كل عنصر `writes` القيمة `semantics: "attempted_guest_write"`: فهو يسجّل محاولة كتابة من المعالج خارج المكدس، بما فيها محاولة قد تتعطل لاحقًا أو تتوقف بسبب الميزانية. ولا يضمن اكتمال الكتابة، ولا يشمل الكتابات التي تنفذها نماذج API. تصف لقطات الأجهزة وكائن برنامج التشغيل الحالة المشاهدة عند توقف التنفيذ.

ضمّن `neverd/sdk/NeverDCAPIEmulation.h`، أو الترويسة الجامعة لـC API، وأنشئ جلسة ثم استدعِ `neverd_emulate_driver_json(session, path, options)`. يدخل المسار الصريح غير الفارغ مباشرةً إلى الفحص الصارم السابق للتنفيذ، دون التحميل أولًا عبر واجهة التحليل العامة. تستخدم CLI هذا المسار. يؤدي تمرير `NULL` للخيارات إلى اختيار القيم الافتراضية. تتطلب خيارات `neverd_driver_options_v1` الصريحة قيمة `struct_size` الدقيقة وميزانيات موجبة للتعليمات والذاكرة والأحداث والوقت. حرّر النتيجة باستخدام `neverd_free_string`.

أما تمرير `NULL` للمسار فيتطلب جلسة محمّلة، ويعيد تحليل ملفها بصورة مستقلة عن تحليل IR والتحميل المقيد بدوال محددة. يحافظ المساران على صورة الجلسة. أبقِ ملف الإدخال متاحًا ومن دون تغيير طوال مدة الاستدعاء. تعيد إخفاقات الطلب/الإعداد `NULL` وتضبط `neverd_last_error`؛ أما توقف التنفيذ فيعيد JSON. تظل الواجهة متاحة في البنى التي عُطّلت فيها الميزة، وتوضح طريقة تفعيلها.

تستخدم `neverd_emulate_driver_scenario_json(session, path, scenario_json, options)` خيارات v1 وقواعد الملكية نفسها، مع إضافة إدخال سيناريو صارم. تُطلب سلسلة JSON غير NULL ومنتهية بـNUL. يبقى ABI الأصلي لـ`neverd_emulate_driver_json` دون تغيير، ومقتصرًا على التهيئة. يوفّر محلّل C++ المسمى `driverOptionsFromScenarioJSON` التحقق نفسه من السيناريو لمستدعي `emulateDriver`.

نقطة الدخول الداخلية في C++ هي `neverd::emulation::emulateDriver` في `include/neverd/emulation/DriverSession.h`. تحليل الصيغ مسؤولية المحمّل الموجود؛ وسلوك كائنات/واجهات Windows مسؤولية `lib/emulation/os/windows`؛ وحالة المعالج وتنفيذه مسؤولية مهايئ Unicorn. يستخدم المهايئ والنموذج واجهة ذاكرة الضيف نفسها. لا ينتمي سلوك Windows API إلى تفريع Unicorn.

في مسار WDM `METHOD_NEITHER`، يشير `Type3InputBuffer` و`IRP.UserBuffer` إلى تخصيصين منفصلين للمستخدم. يفحص `ProbeForRead` النطاق والمحاذاة دون لمس الصفحات، بينما يلمس `ProbeForWrite` كل صفحة. يكشف `ExGetPreviousMode` نمط الطلب. يثبّت `MmProbeAndLockPages` صفحات تخصيص مستخدم واحد، ويتيح `MmGetSystemAddressForMdlSafe` تعيينًا مشتركًا، ثم يزيل `MmUnlockPages` القفل والتعيين. لا تزال سياقات العمليات العامة غير ممثلة.

يمكن لطلب WDM `METHOD_NEITHER` IOCTL ذي المخزن غير الفارغ تحديد `user_input_access` و`user_output_access` على نحو مستقل بالقيم `read_write` (افتراضي) أو `read_only` أو `no_access`. يُرفض هذان الحقلان للطرق المخزنة أو المباشرة والمخازن الفارغة؛ لا تعني `no_access` عنوانًا فارغًا بل صفحات يتعذر الوصول إليها.
يسجل `configuration.user_page_access` في التقرير إعدادات الوصول المحددة صراحة فقط، مع `source_request_index` يبدأ من الصفر؛ ويكون الاتجاه غير المحدد `read_write`.

## طلبات WDM المتزامنة المحدودة

يمكن لطلب WDM من نوع READ/WRITE/IOCTL أو لطلب في طابور KMDF افتراضي متوازٍ غير محدود تعيين `defer_callback_drain: true`. لا يُرسل الطلب التالي قبل تنفيذ الاستدعاءات الراجعة إلا إذا أعادت دالة الإرسال `STATUS_PENDING` وظل IRP معلّقًا. بعد الطلب التالي الذي لا يحدد هذا الحقل، تُنفَّذ الاستدعاءات الراجعة وتُستكمل المجموعة؛ وإذا حدده آخر طلب، يحدث ذلك في نهاية السيناريو. يمكن للطلبات المتداخلة استخدام كائنات ملفات مختلفة أو كائن ملف واحد فُتح صراحةً بنمط غير متزامن. لا يُدعم التداخل على ملف متزامن، ولا الاستباق العشوائي أو وصول الطلبات الخارجية.

## كائن الملف غير المتزامن

يمكن لطلب CREATE وحده تعيين القيمة المنطقية `asynchronous_file: true`؛ ويحافظ إغفالها أو ضبطها على false على الفتح المتزامن. يزيل الفتح غير المتزامن `FO_SYNCHRONOUS_IO` من `FILE_OBJECT` الخاص بالضيف، ولا يضع `IRP_SYNCHRONOUS_API` على طلبات IRP اللاحقة للملف. لا تتداخل طلبات READ/WRITE/IOCTL على الملف غير المتزامن نفسه إلا عند تأجيل معالجة الاستدعاءات الراجعة صراحةً. تنتظر CLEANUP/CLOSE اكتمال جميع عمليات النقل السابقة وإنهاءها. لا يُحتفظ بموضع ملف ضمني؛ وتظل `byte_offset` حقيقة مستقلة لكل طلب وقيمتها الافتراضية صفر. ترفض أنواع الطلبات غير CREATE هذا الحقل حتى عندما يكون false.

## دلالات التنفيذ الإضافية

تدير `MmAllocatePagesForMdl` و`MmAllocatePagesForMdlEx` و`MmFreePagesFromMdl` صفحات مستقلة ضمن حدود مادية، مع تخصيص جزئي وكتل متجاورة. تُحرر الصفحات والواصف بشكل منفصل. تغيّر `MmProtectMdlSystemAddress` صلاحيات PAGE للتعيين النظامي الخاص مع حفظ PFN وخصائص التخزين المؤقت وصلاحيات المستخدم. تدعم `MmProbeAndLockPages` تجمعات KernelMode: يُقفل التجمع القابل للترحيل حتى APC_LEVEL ثم يمكن الوصول إليه عند DISPATCH_LEVEL؛ ولا يجوز تحريره قبل فك القفل.

تحدد `messages` صراحة عنوان MSI وبياناته ومتجهه ومستواه وتقاربه وقطبيته. يكون `message_id` محليًا للواصف، بينما يُرقم وسيط ISR الثالث عبر PDO كله. تعيد `CONNECT_MESSAGE_BASED` (3) الجدول الحقيقي. تدعم `CONNECT_MESSAGE_BASED_PASSIVE` (5) والخطوط السلبية انتظار PASSIVE_LEVEL، وتسلسل المقاطعة نفسها مع حفظ إطارات مستقلة. يُسجل الوصول والتسليم منفصلين دون اختلاق بروتوكول PCI.

تحدد `WdfDeviceInitSetPowerPolicyOwnership` ملكية سياسة الطاقة. تُنفذ Init/Suspend/Restart/Flush/Cleanup واستدعاءات D0، وتحفظ D3/D0 الموارد. تربط السياسة الافتراضية Sleeping3/Working مع D3/D0 باستهلاك `requested_device_power` الصريح. لكل IRP فرعي `origin: "framework_power_policy"` و`response_index`. تنتظر S3 الفرع؛ ويمكن إكمال S0 بعد إصدار D0. تظل إعادة التعداد التلقائية غير ممثلة.

ينتظر Query النظام طلب Query الجهاز المقابل وينقل نتيجته دون تغيير حالة الطاقة.

## الاستثناءات المتزامنة الأصلية في x64

تستخدم تعليمات `DIV`/`IDIV` في checked x64 نتائج المعالج الحقيقية و`#DE`. يعتمد KVM على IDT/IST خاصة بالمشرف، ويستخدم WHP خريطة اعتراض صريحة؛ يُحتفظ بالسياق الأصلي وأكواد الخطأ المتاحة بصورة مستقلة عن أخطاء النقل. يستهلك نموذج نظام التشغيل الحدث القابل للاستعادة قبل تثبيت سياق المتابعة. يحوّل نموذج برامج تشغيل Windows القسمة على صفر وفيض خارج القسمة إلى `STATUS_INTEGER_DIVIDE_BY_ZERO` مع تنفيذ مرشحات SEH و`__finally` وإعادة المحاولة فعليًا. يُبنى `NeverDX64ExceptionTests` دون Unicorn، ويتحقق `DriverWDMCPUException` من أمثلة WDK الأصلية. تُتخطى مضيفات ARM64 غير المتاحة صراحةً.

## حالة x87 الكاملة

تملك `NeverDEmulationArch` عقود ISA وجداول الصفحات وتنسيق FP المشترك بين النقل الأصلي وUnicorn. تحفظ سياقات x64 التحكم والحالة وTOP والوسوم الفيزيائية ورمز العملية ومؤشرات التعليمات/البيانات وثمانية سجلات بطول 80 بت. تستخدم `FP0`–`FP7` نوع `RegisterValue` ويرفض الوصول العددي الاقتطاع. يمثل `FPTag` قناع السجلات الفيزيائية غير الفارغة. تتحقق `NeverDX64FPTests` من كل قيم TOP والعمليات الدقيقة بمقارنتها مع FXSAVE/FXRSTOR للمضيف واستعادة السياق. لا يتيح ذلك تعليمات x87 ضمن checked ولا يثبت جميع حالات التقريب. يجري تجاوز المضيفات الأصلية غير المتاحة صراحةً.

يمكن الاستعلام عن الملف المحدد باستخدام `executionCapabilities(Contract, ISA, Backend)`. يصف `NativeLegacyX64` التنفيذ الأصلي لبرامج تشغيل x64. تتحقق اختبارات `NeverDNativeDriverTests` من المجموعة الحالية ويمكن تشغيلها أيضاً في بناء دون Unicorn.

تستخدم checked ARM64 حدّاً موحداً للحالة الكاملة. يحدد `Registers.def` عدد 39 حقلاً عددياً و32 متجهاً بعرض 128 بت؛ يجمع `captureAArch64State` جميع القراءات ويطبق العروض وتطبيع NZCV قبل نشر واحد. تنقل Unicorn وKVM وWHP المجموعة نفسها، بما فيها TPIDR_EL0 وTPIDRRO_EL0 وTPIDR_EL1 وFPCR وFPSR. تفعّل الواجهات الأصلية FP/SIMD عبر CPACR_EL1. فشل أي قراءة أو إلغاء الدخول يحفظ كامل حالة المستدعي.

ينفذ بدء ARM64 KVM/WHP البرنامج الخاص `AArch64MachineProbe.def`: NOP وجمع FP32 بتقريب نحو اللانهاية الموجبة وجمع SIMD بمسارين. تقارن كل خطوة جميع الحقول العددية الـ39 والمتجهات الـ32، بما فيها TLS وNZCV وتصفير البتات العليا للنتيجة وحالة FPCR/FPSR المحفوظة والمتراكمة. يستخدم الفحص ذاكرة مراقب المشرف فقط وموعداً نهائياً إجمالياً واحداً. يثبت النجاح برنامج التهيئة المحدود هذا؛ ولا يزال التحقق المستقل من أحمال ARM64 الأصلية مطلوباً. يتضمن البرنامج أيضًا توقيع عناوين العودة A/B والمصادقة عليها مع تعطيل المفاتيح، وأشكال BTI الأربعة على الصفحات غير المحمية.

ينفذ الفحص أيضًا `MRS CTR_EL0` مرتين، و`DC CVAU` و`DSB ISH` و`IC IVAU` و`ISB`، للتحقق من ثبات بنية الذاكرة المخبئية والحالة الكاملة. تقبل Checked EL0/EL1 التعليمات الأصلية وجميع خيارات DSB الأساسية المسماة وISB SY فقط. تأتي CTR من المعالج الافتراضي المختار وقد تختلف بين وسائل النقل. يجب أن تشير أهداف الصيانة إلى RAM عادية قابلة للقراءة بالصلاحيات الحالية، مع السماح بالعناوين غير المحاذاة والأسماء المستعارة؛ تُرفض الأهداف الأخرى باعتبارها غير مدعومة. لا تنشئ الصيانة أحداث مراقبة لقراءة البيانات أو كتابتها. يحافظ الإسقاط على اتساق تنفيذ التعليمات دون نمذجة محتويات مخابئ خاصة أو SMP عتادي متوازٍ. تختبر `NeverDAArch64CacheTests` الحالة ونهايات الصفحات للقراءة فقط والرفض والتوقف والسياقات والميزانيات وتحديث كود الضيف عبر أسماء RW/RX المستعارة الممتدة بين صفحتين. تُتخطى مضيفات KVM/WHP غير المتاحة صراحةً.

تنفذ تهيئة x64 الأصلية في KVM/WHP برنامج `X64MachineProbe.def` داخل صفحات supervisor خاصة. تشمل مهلة واحدة NOP وجمع FP32 بتقريب نحو اللانهاية الموجبة وجمع SIMD ذي مسارين وتحميل FS/GS وقراءة CS/SS/CR8؛ وتقارن كل خطوة الحالة الكاملة للقيم المفردة وXMM وسجلات x87 الفيزيائية وحقول التحكم. تتطلب اختبارات x64 وARM64 حق التنفيذ الحصري للذاكرة الفيزيائية. يملك `MemoryProjection` هوية التخزين المؤقت (ISA وفضاء العناوين وجيل التعيينات والامتياز ومتغير المراقب) وسجل الجذور المعتمدة لكل ISA. تبطل أدوات البناء التخزين المؤقت قبل إعادة الكتابة، فلا تعيد المحاولة الفاشلة استخدام جداول جزئية ولا يمرر المستدعي جذورًا قديمة. تثبت هذه الاختبارات التهيئة المحدودة فقط؛ ولا يزال التحقق المستقل من أحمال ARM64 الأصلية غير مكتمل.

يميّز مفكك XSAVE المشترك بين حالة SSE الابتدائية في التنسيق القياسي والمضغوط. عندما تكون XSTATE_BV[1] صفراً، يهيّئ كلاهما XMM؛ لكن القياسي يواصل قراءة MXCSR والتحقق منه، بينما يهيّئه المضغوط. يوفر `X64XsaveCases.def` تخطيطات مستقلة وبرامج XRSTOR أصلية للمضيف. يتحقق `X64XsaveTests.cpp` من ذرّية الرفض ويقارن التنسيقين بالتنفيذ الحقيقي مع حفظ حالة FP/SSE للجهة المستدعية. يُعلن صراحةً عن تخطي المقارنة عند غياب معمارية المضيف أو ميزة التعليمات المطلوبة.

يعلن `X64FPState.def` تخطيطات النقل المضغوطة لـ AVX وAVX-512 وCET_U/CET_S وAMX، بما فيها محاذاة المكونات إلى 64 بايت. يجب أن تمثل بيانات الامتداد الحاضرة الحالة الابتدائية المصفّرة؛ ولا تحدد المكونات الغائبة وحشو المحاذاة حالةً. تحدد بتات التخطيط الإزاحات، وتُرفض التخطيطات المجهولة والبيانات غير الابتدائية والأطوال الخاطئة قبل النشر. تغطي `CompactedOffsetsFollowLayoutRatherThanPresentBits` و`WideLayoutIgnoresAbsentComponentsAndAlignmentPadding` و`InitialCETComponentsDoNotHideFPState` و`InitialWideComponentsDoNotHideFPState` حزم WHP ذات 872 و10752 بايت. لا يتيح هذا النقل تنفيذ تعليمات هذه الامتدادات.

يكمل `WhpXsaveRegisters.def` حزم XSAVE الكاملة بسجلات تحكم x87/SSE المسماة. يكتب آخر رمز عملية ومؤشري التعليمة والبيانات صراحة ويقرؤها من المضيف. يمكن استكمال حقول الحزمة الصفرية، لكن تعارض البيانات غير الصفرية أو حقول التحكم المشتركة يفشل قبل نشر الحالة. يتحقق `NamedMetadataRestoresOmittedPacketFields` من الحقول المفقودة مع الاحتفاظ بكل بيانات FP.

تتبع الحقول الأصلية `FOP/FIP/FDP` قواعد حفظ واستعادة x87 للمضيف. قد يصفرها AMD عند غياب استثناء معلق غير مقنّع؛ وتحتفظ اللقطات بالقيم المرصودة. يهيئ `X64MachineProbe.def` واختبارات NOP والسياق الدقيقة استثناءً معلقاً متسقاً ليظل كل حقل صالحاً وتتم مقارنته دون إخفاء الفروق. يتحقق مرجع FXRSTOR64/FXSAVE64 في عملية المضيف من الحالتين؛ ولا تستبدل الخلفيات نتائج المضيف ببيانات الإدخال الوصفية.

يملك المرمز المشترك `encodeX64XsaveState` / `decodeX64XsaveState` حزم FP/SSE القياسية والمضغوطة ودوران TOP الفيزيائي والحالة الأولية للمكونات الغائبة والتحقق الذري. يستخدم WHP واجهات XSAVE الكاملة، مع تفضيل `WHvGetVirtualProcessorState` / `WHvSetVirtualProcessorState` وإبقاء واجهات XSAVE القديمة لمسار التوافق. لا تستبدل واجهة سجلات x87 الفردية القديمة الحزم الكاملة. تفشل صراحة المكونات الموسعة غير الابتدائية والرؤوس المشوهة وقيم التحكم غير الصالحة وقراءات الحالة المبتورة. تحفظ أخطاء تعيين WHP قيم HRESULT وGPA والحجم للتشخيص.

يقبل `CheckedX64Instructions.def` الضرب غير الموقّع `MUL` بعرض 8/16/32/64 بت والتعليمات `CBW/CWDE/CDQE/CWD/CDQ/CQO` عبر ناقل CPU الحالي. يستخدم `NeverDX64IntegerTests` ترميزات وقيماً متوقعة مستقلة من `X64IntegerCases.def` عند مستويَي الامتياز: حفظ أجزاء السجلات غير المتأثرة، والتمديد بالأصفار عند الكتابة بعرض 32 بت، ونصفي حاصل الضرب، ونتائج CF/OF المحددة، وثبات الأعلام عند تمديد الإشارة. يحتفظ الضرب في RAM العادية بفحص صلاحيات نطاق الوصول كاملاً ومراقبي القراءة؛ ويحفظ الخطأ أو توقف المراقب سجلات الخرج الضمنية وPC. تبقى معاملات الأجهزة غير مدعومة. تُنفّذ الحالات أيضاً على checked Unicorn، ويُعلن صراحةً عن تخطي النواقل الأصلية غير المتاحة.

يتيح `X64BitInstructions.def` تعليمات `BT/BTS/BTR/BTC` للسجلات وRAM العادية بعرض 16/32/64 بت. يُفسَّر فهرس السجل كقيمة موقَّعة بعرض المعامل ويختار كلمة كاملة؛ أما الفهرس الفوري فيبقى داخل الكلمة الأساسية. يحدث الاقتطاع إلى عرض العنوان قبل إضافة قاعدة FS/GS. يوفر المعالج CF والقيم المكتوبة، ويبقي `RAMTransaction` النتيجة خاصة حتى تقبلها دوال المراقبة. تُفحص الصلاحيات على النطاق الكامل، بما فيه الصفحات المخصصة منفصلًا والعناوين البديلة. يحافظ التوقف وفشل الاستدعاء الراجع ورفض الوصول على حالة CPU وRAM الأصلية. يقتصر LOCK على تعديل الذاكرة ذي المحاذاة الطبيعية؛ ولا يشمل الدعم MMIO أو SMP العتادي المتوازي. يقارن `X64BitStringTests.cpp` ترميزات مستقلة بالتنفيذ الفعلي على مضيف x64، ويفحص الفهارس السالبة واقتطاع العرض وعبور الصفحات والإلغاء وصيغ LOCK غير الصالحة. راجع [مرجع تعليمات Intel](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html).

يحدد `X64StringInstructions.def` تعليمات `MOVS/STOS/LODS` بعروض 8/16/32/64 بت على RAM العادية؛ ويغيّر `CLD/STD` علم الاتجاه وحده. يتحقق كل عنصر REP من كامل المعامل قبل المراقبة، ثم يثبت أثره عند حد يسمح بالاستئناف. يحافظ العطل اللاحق على العناصر المكتملة، بينما يترك الإيقاف أو استثناء المراقب العنصر الحالي دون تغيير. يضاف FS/GS إلى المصدر فقط بعد اختزال عرض العنوان. تحتفظ عمليات تحميل AL/AX بالبتات العليا، بينما يمدد EAX بالأصفار. تتطلب REP ذات العداد الصفري وعنونة 32 بت أن تكون بتات العداد العليا صفرًا، وكذلك بتات العناوين المشاركة في MOVS/STOS، لأن المعالجات الفعلية تختلف بخلاف ذلك. لا تزال REPNE مع MOVS/STOS/LODS ومعاملات الأجهزة لـ STOS/LODS غير مدعومة. يقارن `X64StringTransferTests.cpp` العروض والاتجاه والتداخل والعداد الصفري بتعليمات مضيف مستقلة، ويختبر الصلاحيات والأسماء البديلة والتفاف العنوان والأعطال والاستئناف. ينفذ برنامج تشغيل موارد WDK الأصلي عروض STOS/LODS الأربعة عبر `driver_resource_strings.def`.

يحدد `X64StringInstructions.def` أيضًا `CMPS/SCAS` على RAM العادية بعروض 8/16/32/64 بت مع `REPE/REPNE`. يتحقق كل عنصر من جميع القراءات قبل المراقبين، ويحدث أعلام الحساب الستة، وينتهي عند أول شرط توقف. يعيد عطل البيانات الأعلام إلى بداية REP المتصلة مع إبقاء تحديثات المؤشرات والعداد المكتملة؛ ويبدأ الاستئناف عبر الواجهة العامة من حالة CPU المنشورة. لا يغير الإيقاف أو استثناء المراقب العنصر الحالي، ولا تقرأ النهاية المبكرة العنصر التالي. يؤثر FS/GS في مصدر CMPS وحده، ويحافظ SCAS على المجمّع وسجل المصدر غير المستخدم. تبقى الأجهزة والبتات العليا الملتبسة عند عداد صفري بعرض 32 بت خارج النطاق. يقارن `X64StringComparisonTests.cpp` تعليمات المضيف المستقلة والأعلام والاتجاه والأسماء البديلة والتفاف العناوين والصلاحيات والاستئناف؛ ويلتقط اختبار إشارات Linux x64 السجلات عند العطل الحقيقي. ينفذ برنامج تشغيل WDK الأصلي شكلي التكرار الشرطي بكل العروض عبر `driver_resource_strings.def`. راجع [مرجع Intel](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html).

تشترك وحدات CPU القائمة في WHP في قسم أصلي واحد؛ ويحمي قفل السجل نفسه الإغلاق النهائي وإعادة الإنشاء. يعيد `WhpResourceCache.h` استخدام VP 0 التعاوني؛ وعند تبديل CPU المنطقي يُحذف ذلك المعالج وتُلغى تعييناته أولًا. تحتفظ الوحدات المتوازية بمعالجات VP ونطاقات GPA مستقلة. تُوجَّه عمليات نقل السجلات وXSAVE والإلغاء إلى VP الخاص بها. يحتفظ x64 بميزات XSAVE الافتراضية للمضيف ويتحقق من الإعداد الفعلي عبر `WHvGetPartitionProperty`. تبقى الجدولة تعاونية افتراضيًا.

يجيز `CheckedAArch64Instructions.def` و`AArch64InstructionEffects` في EL0/EL1 مجموعة محدودة من حساب FP32/FP64 الأساسي والمقارنة والنقل وSIMD ثابت العرض. يحفظ FPCR أنماط التقريب الأربعة وFZ وDN، ويحفظ FPSR الحالة المتراكمة وQC. تُرفض البتات غير المدعومة قبل التعديل. يفشل حساب FP16 وSVE/SME والاستثناء غير المقنّع والامتدادات الاختيارية والأشكال غير المدرجة صراحةً. لا يضيف ذلك تحميل برامج تشغيل Windows ARM64 أو بيئة نظام أخرى.

يمتلك `AArch64InstructionEffects` نطاقات RAM العددية وFP/SIMD الفردية والمزدوجة حتى 128 بت لكل معامل. يتحقق فضاء العناوين المشترك من كل صفحة قبل الدخول، ولا يثبت `RAMTransaction` إلا الكتابات الفيزيائية المعلنة كاملةً. يستقبل مراقب كتابة 128 بت كلمتين مرتبتين من 64 بت قبل الأثر. يحفظ التوقف والعطل RAM والمتجهات وتحديث العنوان. تساوي رقمي Xn/Vn مسموح؛ وتُرفض النطاقات المزدوجة التي تلتف عناوينها. يستخدم `NeverDAArch64MemoryTests` ترميزات مستقلة في `AArch64CrossPageCases.def` و`AArch64VectorMemoryCases.def`.

يستخدم KVM x64/ARM64 المتحكم `KvmRunControl` لتحضير الحالة والدخول إلى `KVM_RUN` وقراءتها على عامل vCPU خاص واحد. يحدث التحضير مرة واحدة حتى مع `EINTR`؛ يمنع الإلغاء وفشل القراءة نشر الحالة. ينفذ `KvmAArch64Machine.cpp` صيانة ترجمة العناوين ونقل الحالة العددية والمتجهية الكاملة بمهلة خطوة واحدة. ينشر المستدعي بعد تأكيد الانتهاء؛ ويبقى فك ISA ومعاملات RAM وسياسة النظام والمراقبون على خيط المستدعي. ما زال إثبات ARM64 الأصلي مطلوباً.

يقارن KVM السجلات العامة وحالة FP/SSE الكاملة بآخر حالة تصحيح جرى تأكيد قراءتها وفق `X64HostRegisters.def` و`X64FPState.def`، ويعيد تثبيت المدخلات المتغيرة. تدخل كتابات المضيف واستعادة السياق في المقارنة؛ وتبطل الاستثناءات والإلغاء والفشل إعادة الاستخدام. يظل إعداد الخطوة الواحدة وقراءة الحالة العامة/FP الفعلية قائمين لكل تعليمة.

التنفيذ العتادي وحده لا يضمن زمناً إجمالياً أقل. يقوم التنفيذ الأصلي الحالي بفحص قبول التعليمة والمراقبة ونقل الحالة والخروج من VM لكل خطوة. قارن الصور والسيناريوهات الأصلية نفسها بميزانيات تعليمات وأحداث متطابقة، وأبلغ عن تطابق النتائج مع الأزمنة؛ وأدرج بدء CLI والتحميل عند قياس زمنه.

تبقى خانات مؤشرات CFG غير المفعّلة صالحة عندما تكون `GuardFlags` صفرًا. يتحقق المحمّل من التخزين وأهداف التنفيذ البديلة وتغطية `DIR64` الكاملة عند تغيير قاعدة التحميل، ويحافظ على مؤشرات الضيف الأصلية. لا يزال CFG المفعّل يتطلب بت التفعيل في الصورة وأعلام التجهيز وجدول الدوال. تغطي `DriverGuardCases.def` و`NeverDDriverGuardMetadataTests` هذه الحالات باستخدام Unicorn وKVM وWHP، بما في ذلك البناء دون Unicorn.

يستخدم Unicorn المتحقق منه `MachineRunControl`: يغطي سماح واحد صيانة ARM64 وتنفيذ الضيف والتقاط الحالة كاملةً. يتحقق `UC_HOOK_CODE` من رمز التوقف المستعار والمهلة عند دخول التعليمة. يحرر استدعاء المحرك المتزامن مرجع hook قبل العودة، لكن خطوة الآلة تحتفظ بالتحكم حتى النشر. يجمع Unicorn وWHP حالة CPU كاملةً بشكل خاص ويتحققان من التحكم نفسه قبل نشر خطوة ناجحة. ينشئ WHP السماح مرة واحدة قبل التحضير. يتقدم استثناء CPU x64 المؤكد على توقف يصل أثناء الالتقاط. تتخلى معاملة RAM المتحقق منها عن الكتابات المؤقتة عند إلغاء الالتقاط، ولا يتغير العقد البرمجي غير المقيد. يميز `MachineInterruptedError` الإلغاء المؤكد عن فشل المضيف أو الالتقاط. تعيد CPU المشتركة المتحقق منها `Stopped` أو `Deadline` وتحفظ CPU/RAM وتسمح بإعادة المحاولة؛ وتظل الأعطال الحقيقية `BackendFailure` حتى مع توقف متزامن.

يرفض `RunDeadline::invoke` دخول WHP المتوقف أو المنتهية مهلته قبل استدعاء المضيف، ويحفظ نتيجة المضيف الفعلية أثناء الإلغاء، ويؤكد انتهاء استدعاءات المقاطعة قبل تحرير رمز التوقف المستعار. يتحقق KVM وWHP من الحالة الخاصة المقروءة بالكامل على خيط الاستدعاء المالك لحق التنفيذ قبل تصنيف توقف أو انتهاء مهلة متزامن. تحتفظ أخطاء المضيف أو قراءة الحالة الفعلية واستثناءات CPU x64 الموثقة بالأولوية. تبقى الحالة الناجحة العادية خاصة حتى تنتهي فحوص الإلغاء؛ وتتخلص المقاطعة المؤكدة من آثار CPU/RAM التخمينية وتسمح بإعادة المحاولة. يشترك التحضير والتنفيذ الأصلي وقراءة الحالة في سماح واحد لكل خطوة. هذا التحكم تعاوني ولا يضمن حدًا صارمًا للوقت الفعلي.

توضح [جدولة التعريفات](driver-scheduling.md) الاستباق الصريح على CPU0 ودلالات الساعة الافتراضية والحدود الحالية.

## تصديرات HAL وعداد الأداء

يمثل `HAL.dll` موفّر استيراد مستقلًا لا يميّز اسم وحدته حالة الأحرف. تشترك الاستيرادات الثابتة و`MmGetSystemRoutineAddress` في هويات التصدير الدقيقة والحساسة لحالة الأحرف للنواة وHAL، وتُرفض الهويات الفعالة المتعارضة. يطبق `kernel_exports` تجاوزات إجراءات HAL المعروفة داخل نطاق HAL، وتظل التصريحات الصريحة الأخرى تصديرات للنواة. تحتفظ استيرادات HAL غير المعروفة بمصائد مؤجلة ولا تكتسب دلالات واجهة النواة بمجرد تطابق الاسم.

يعيد `KeQueryPerformanceCounter` وقت المجدول المشترك بوحدات 100 ns، بتردد ثابت قدره 10,000,000 في الثانية. يُفحص مؤشر الإخراج الاختياري للتحقق من كتابة البايتات الثمانية كاملة وعمر الكائن. يُسمح بالاستدعاء عند كل مستوى x64 IRQL صالح. يتقدم الوقت في الوضع التعاوني عند حدود الجدولة الحالية فقط؛ ويحتفظ وضع ساعة التعليمات بإعداداته. لا تنشئ القراءة ساعة ثانية ولا تقدم الوقت بنفسها. هذا ملف تنفيذ حتمي وليس قياسًا لعتاد المضيف. يتحقق الاختبار المترجم بصورة مستقلة من هوية الاستيراد الثابت والديناميكي والتردد وعدم تناقص العداد في العناوين المفضلة والمعاد تموضعها عبر خلفيات CPU الأصلية.

تقرأ `RDTSC` و`RDTSCP` ساعة المجدول نفسها بتردد 10 MHz المستخدمة في `KeQueryPerformanceCounter`. تعيد `RDTSCP` صفراً في ECX للمعالج الوحيد في النموذج. تُصفّر النصف العلوي من EAX/EDX ومن ECX عند RDTSCP، مع حفظ بقية السجلات والأعلام. لا تقدم القراءة الوقت في الوضع التعاوني. عند جدولة التعليمات صراحة، تُقرأ الساعة بعد احتساب التعليمة نفسها، بغض النظر عن طول الشريحة. يوقف تجاوز السعة التنفيذ قبل نشر نتائج السجلات؛ وتظل ميزانية التعليمات وتوقفات المراقب سارية. لا يقيس النموذج تردد TSC للمضيف ولا يكشف هوية معالجه. تبقى عمليات MSR وRDPMC واستعلامات CPU غير الممثلة غير مدعومة.

تحتفظ قراءة الساعة عبر `KeQueryPerformanceCounter` أو `RDTSC` أو `RDTSCP` باعتماد صريح لاستعادة برنامج التشغيل. لا يوجد عقد لإعادة ربط قيم العداد والتردد الملتقطة ببيئة نواة جديدة. تعيد الاستعادة الافتراضية `unsupported_state`، ويحتفظ `snapshot_only` بالتشخيص.

ينشئ `KernelModuleImages` ترويسات PE وجداول تصدير قابلة للقراءة من `KernelExportRegistry`؛ وتشترك الاستيرادات الثابتة والبحث الديناميكي وتعداد الوحدات في العناوين نفسها. يبقى كود الموفّرين معتماً ويصف الجرد بيئة النموذج لا نواة المضيف. يُفحص المخرجان قبل الكتابة بما يشمل عمر ذاكرة التجمع والتداخل. يتطلب Nt وضع previous-mode معروفاً للنواة، بينما يستخدم Zw عقد النواة. يحتفظ الاستعلام الكامل باعتمادية استعادة صريحة حتى بعد تحرير المخزن، وتُتتبّع مؤشرات صور الموفّرين كحالة مستعارة. يفحص `KernelExportTests.cpp` تحليل PE والصلاحيات وحقول ABI ورفض الكتابة واعتماديات الاستعادة؛ وتجتاز عينة التشغيل الأصلية المترجمة جداول التصدير على خلفيات المعالج.
