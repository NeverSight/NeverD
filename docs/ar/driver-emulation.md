# محاكاة برامج تشغيل Windows

ينفّذ محاكي برامج التشغيل الاختياري في NeverD نقطة دخول PE لبرنامج تشغيل x64 WDM مدعوم، ويمكنه تنفيذ سيناريو صريح من الطلبات المتسلسلة قبل إلغاء تحميله. يستخدم Unicorn لتنفيذ تعليمات المعالج، ونموذج NeverD المحدود الخاص لبيئة Windows. لا يحمّل برنامج التشغيل في نواة المضيف، ولا يمرّر استدعاءات واجهات الضيف إلى خدمات نظام تشغيل المضيف.

## البناء والتشغيل

يجب تفعيل هذه الميزة صراحةً، وهي مستقلة عن `BUILD_TESTING`:

```bash
cmake -S . -B build-release -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DNEVERD_ENABLE_DRIVER_EMULATION=ON
cmake --build build-release --target neverd --parallel 4
build-release/bin/neverd emulate-driver path/to/driver.sys \
  --instruction-limit 100000 > driver-report.json
```

يُكتب التقرير دائمًا بصيغة JSON إلى stdout، بينما تُكتب رسائل تشخيص الطلبات والإعداد إلى stderr. الحدود الافتراضية هي 100000 تعليمة ضيف، و64 MiB من ذاكرة الضيف، و10000 حدث مسجّل، و5000 ملّي ثانية. يجب أن يكون حد التعليمات موجبًا. يؤدي نفاد ميزانية التنفيذ إلى إيقافه مع الاحتفاظ بالمشاهدات الجزئية؛ وتحافظ واجهات التخصيص على عقود الإرجاع عند نقص الموارد، بما فيها NULL لتعيينات MMIO الموضحة أدناه.

| رمز الخروج | المعنى |
|------------|--------|
| `0` | نجحت التهيئة وكل العمليات المطلوبة التي اكتملت |
| `1` | مدخلات/خيارات غير صالحة، أو فشل الإعداد، أو تعطيل الميزة وقت البناء |
| `2` | أعادت التهيئة أو أحد الطلبات المكتملة قيمة `NTSTATUS` تدل على الفشل |
| `3` | توقف التنفيذ قبل اكتمال السيناريو، مثل الوصول إلى API غير مدعوم أو وقوع عطل أو بلوغ حد الميزانية |

تُعد حالة الفشل المعادة مشاهدة مكتملة لتلك العملية. أما العودة الناجحة فتصف هذا التشغيل داخل النموذج فقط؛ ولا تثبت أن برنامج التشغيل يعمل تحت Windows.

## توافق برامج التشغيل

يُحدّد التوافق وفق مسار الشفرة المنفّذ واعتمادياته، لا وفق امتداد `.sys`. تشمل أدلة القبول الحالية fixtures مستقلة أصلية ومسارات buffered وin-direct وout-direct لمثال Microsoft SIOCTL WDM، بما فيها البناء الذي يسجّل رسائل التصحيح، وكذلك القراءة والكتابة المباشرتان في المثال العام Zero لبافل يوسيفوفيتش. ولا يثبت ذلك التوافق مع برامج تشغيل عشوائية من جهات خارجية.

| فئة برنامج التشغيل أو متطلبه | النطاق الحالي | البيئة الناقصة |
|------------------------------|---------------|----------------|
| برنامج تشغيل برمجي x64 WDM يستخدم الواجهات المدرجة | تهيئة x64 WDM محدودة وطلبات buffered/direct متسلسلة وعناصر عمل ومؤقتات وDPC وأحداث وانتظار وتقارير وحدود | يحتاج كل API إضافي يُنفّذ إلى نموذج محدد |
| `METHOD_BUFFERED` IOCTL | عمليات buffered/direct متسلسلة مع إكمال بعنصر عمل أو DPC | واجهات المجموعة أدناه فقط؛ دون IRP متزامنة أو الإلغاء العام لطلبات WDM |
| `METHOD_IN_DIRECT` و`METHOD_OUT_DIRECT` | MDL مملوكة للطلب وتعيينات نظام وهويات PFN مشتركة للقراءة فقط | تعيينات المستخدم وواجهات DMA الأخرى |
| MDL ينشئها برنامج التشغيل | واصفات مستقلة لمخزن kernel غير القابل للترحيل أو تخصيص مستخدم واحد مع صفحات فعلية مشتركة | بلا ربط IRP أو سلاسل MDL أو عمليات مستخدم عامة |
| READ/WRITE | عمليات buffered/direct/neither متسلسلة مع إكمال بعنصر عمل أو DPC | واجهات المجموعة أدناه فقط؛ دون IRP متزامنة أو الإلغاء العام لـWDM أو موضع ملف ضمني |
| WDM `METHOD_NEITHER` | عناوين مستخدم منفصلة وفحص الوصول وقفل MDL وهوية طالب اصطناعية وإلغاء وصول بعد الإرسال أو خروج العملية وإلغاء WDM محدود | دون ربط عمليات عام أو خرائط مستخدم وإعادة تعيين اعتباطية |
| برنامج KMDF 1.33 غير PnP | الربط والكائنات/السياقات وأجهزة التحكم المسماة والطوابير الافتراضية المتسلسلة أو المتوازية ذات الحد المحدود أو غير المحدود والطلبات المخزنة/المباشرة/neither مع تنفيذ الاستدعاءات الراجعة | لا دعم لأجهزة PnP أو الجدولة العامة للطوابير أو امتدادات الفئات أو UMDF |
| برنامج تشغيل ناقل/وظيفة/مرشّح PnP | PDO صريح بلا موارد أو مع بنوك سجلات وAddDevice ضيف وثماني وظائف فرعية شائعة لدورة PnP | عمليات PnP الأخرى وسياسة الطاقة العامة والعتاد/الموارد العامة وKMDF PnP العام |
| برامج تشغيل التخزين والشبكة والعرض ونظام الملفات والمرشحات المصغرة | عقود الأنظمة الفرعية غير مدعومة | أطر المنفذ/الفئة/المنفذ المصغّر وخدمات NDIS/WFP والرسومات أو نظام الملفات |
| عناصر العمل والمؤقتات وDPC والأحداث والانتظار | مستوى IRQL الحالي هو `PASSIVE_LEVEL` للإرسال والعمل و`DISPATCH_LEVEL` لاستدعاءات DPC | واجهات المجموعة أدناه فقط؛ دون IRP متزامنة أو الإلغاء العام لطلبات WDM |
| برنامج تشغيل يستخدم استدعاءات راجعة للعمليات/الخيوط أو مقابض أو عمليات سجل/ملفات أو اكتشاف وحدات النواة | عمليات السجل المدرجة مدعومة ضمن شجرة مضبوطة صراحةً؛ أما العمليات الأخرى فغير مدعومة | مدير الكائنات العام وعمليات الملفات وحالة النظام ومصادر الاستدعاءات الراجعة/الأحداث |
| برنامج تشغيل عتاد أو DMA أو PCI أو مقاطعات أو افتراضية | بنوك سجلات صريحة وMMIO ومقاطعات latched حصرية وDMA متماسك common/SG/channel | نماذج الأجهزة الأخرى وRAM فيزيائية اعتباطية وPCI والمنافذ والمقاطعات المشتركة/المستوية/MSI وواجهات DMA الأخرى وحالة CPU ذات الامتيازات |
| برنامج تشغيل Windows لمعمارية x86 أو ARM64 | يُرفض | التحميل وABI ونموذج التنفيذ الخاص بالمعمارية |
| x64 CFG | جداول أهداف متحقق منها واستدعاءات check/dispatch؛ تحتفظ الأدوات غير النشطة بدوال الضيف البديلة | يظل XFG وقمع التصدير وإعداد التحميل غير الممثل وTLS مرفوضًا |

يمكن أن يظل استيراد غير مدعوم لكنه غير مستخدم مرتبطًا. يؤدي الوصول إلى عملية غير مدعومة إلى التوقف مع رسالة تشخيص والمشاهدات التي جُمعت حتى تلك النقطة. لا يثبت نجاح DriverEntry وحده دعم مسارات الإرسال اللاحقة أو العتاد أو إطار العمل. جدول API أدناه هو المرجع المعتمد للمجموعة الفرعية المدعومة.

## عقد التنفيذ

يمثل الملف دورة حياة x64 WDM على CPU0 بجدولة تعاونية حتمية. يبدأ التنفيذ من نقطة دخول PE، مع إبقاء غلاف الدخول الذي أنشأه المترجم إن وُجد. يجب أن يعيد DriverEntry القيمة `STATUS_SUCCESS` لنجاح التهيئة؛ أما حالة نجاح غير صفرية أو حالة pending فتوقف التنفيذ باعتبارها عقد تهيئة غير مدعوم. تُحفظ حالة الفشل بوصفها نتيجة تهيئة مكتملة. تقع كل الكائنات والسلاسل والمكدسات ومؤشرات الدوال والتخصيصات في ذاكرة الضيف. يوفّر النموذج `DRIVER_OBJECT` ومسار سجل لاسم الخدمة المضبوط، وقيمته الافتراضية `NeverDDriver`. يستخدم المهايئ نمط TLB الافتراضي في Unicorn للحفاظ على عناوين الضيف الافتراضية، بما فيها عناوين النواة العليا القياسية (canonical)، من دون تركيب جداول صفحات Windows. قيمة RFLAGS الابتدائية هي `0x202`؛ ويستخدم ملف تعريف الجهاز البرمجي سطر ذاكرة مخبئية ثابتًا بحجم 64 بايت. هذه خصائص صريحة لسيناريو التنفيذ هذا.
تُظهر قراءات x64 المضمّنة لسجل CR8 قيمة `PASSIVE_LEVEL` / `DISPATCH_LEVEL` نفسها؛ وتظل كتابة CR8 والعمليات الأخرى على سجلات التحكم غير مدعومة.

تُربط الاستيرادات المجهولة بمصائد مؤجلة. لا يمنع الاستيراد غير المستخدم التنفيذ؛ لكن تنفيذ thunk الخاص به أو قراءة قيمة بيانات مصدّرة غير ممثلة في النموذج يؤدي إلى `unsupported_api`. تؤدي تأثيرات بيئة المعالج غير المدعومة أيضًا إلى توقف صريح. لا يستبدل NeverD الاستدعاءات غير المنفذة بقيم نجاح. تفشل الصور المشوّهة أو متطلبات التحميل غير المدعومة قبل التنفيذ.

تعمل عناصر `DelayedWorkQueue` عند `PASSIVE_LEVEL` واستدعاءات DPC للضيف عند `DISPATCH_LEVEL` مع الوسائط الأربع المحددة. تجري جدولة تعاونية حتمية على CPU0 عند عودة الاستدعاءات والانتظار الحاجب. تستخدم المؤقتات النسبية والمطلقة والدورية وقتًا افتراضيًا يتقدم إلى موعد المؤقت أو الانتظار أو الإلغاء التالي حين لا يوجد إطار قابل للتنفيذ. تحتفظ أحداث ومؤقتات الإشعار والمزامنة بقواعد استهلاك الإشارة المختلفة. لكل استدعاء راجع مكدس ضيف منفصل؛ وتحفظ إطارات محجوبة متعددة متغيراتها المحلية وسياقات CPU الكاملة مع مشاركة الذاكرة. يمرر Win64 أول أربعة وسائط في السجلات والبقية على المكدس. تبقى الطلبات متسلسلة: على الإرسال الذي يعلّم IRP كمعلّق إرجاع `STATUS_PENDING` وإكماله قبل الطلب التالي. دون مصدر متاح يتوقف الطلب المعلّق أو الانتظار اللانهائي بسبب التعطل مع `model_error`. تبقى ميزانيات التعليمات والذاكرة والملاحظات والوقت الفعلي مشتركة.

هذا نموذج جدولة محدود وليس دعمًا كاملًا لسلوك Windows غير المتزامن. يظل الانتظار القابل للتنبيه أو بنمط المستخدم وAPC والإلغاء العام لطلبات WDM وتقديم السيناريوهات العامة المتزامن وUMDF وأجهزة PnP في KMDF والجدولة العامة للطوابير وPnP/الطاقة الكامل والعتاد العام وواجهات DMA الأخرى وأنماط المقاطعات الأخرى غير مدعوم. تنفذ التهيئة وحدها الاستدعاءات المصطفة صراحةً دون إنشاء طلبات أو إلغاء تحميل ضمنيًا.

يخرج عنصر العمل من الطابور قبل بدء استدعائه الراجع، لذا يمكن للاستدعاء تحرير عنصره الخاص. يفشل صراحةً تحرير عنصر ما زال مصطفًا أو تكرار إدراجه أو استخدام كائنات منتهية الصلاحية أو عنوان استدعاء خارج ذاكرة الضيف القابلة للتنفيذ. يبقى مرجع الجهاز حتى عودة الاستدعاء. يتطلب إلغاء التحميل تحرير جميع العناصر وإكمال العمل المصطف. تحفظ سياقات المعالج السجلات العامة وحالة SIMD وFPU والتحكم؛ وتبقى ذاكرة الضيف مشتركة، ولا تسمح استعادة السياق باستئناف معالج تعرض لعطل.
يؤجّل الحذف ما دامت كائنات الملفات أو مراجع عناصر العمل المصطفة/الجارية موجودة. يعيد تخصيص عنصر العمل NULL عند نفاد مساحة الكائنات.

تستخدم الصور عنوانها الأساسي المفضّل ما لم يختر السيناريو عنوان نقل صالحًا، ويجب أن تكون ملفات تنفيذية PE32+ x64 ذات نظام فرعي native. يمكن أن تأتي الاستيرادات من `ntoskrnl.exe` أو `ntkrnlmp.exe` أو `WDFLDR.SYS`. يدعم محمّل التنفيذ عمليات نقل العنوان الأساسي x64 `DIR64` التي اجتازت التحقق، وإعداد تحميل محدودًا لملف تعريف الارتباط الأمني security cookie؛ وتُهيّأ قيمته داخل الضيف بصورة حتمية قبل غلاف الدخول. تُرفض حقول إعداد التحميل الأخرى غير الممثلة وTLS والاستيرادات المؤجلة/المربوطة والاستيرادات برقم ordinal والصور المُدارة. يجب أن تجتاز الصور أيضًا فحوصًا صارمة للنطاقات والمحاذاة.

يتحقق Control Flow Guard (CFG) النشط من أعلام PE وخانات المؤشرات والأهداف القابلة للتنفيذ المرتبة. تسمح مساعدات check/dispatch بمداخل الصورة المعلنة أو نقاط API المسجلة فقط، وتحفظ حالة استدعاء Win64 وترفض الأهداف غير المعلنة. تحتفظ الأدوات دون CFG نشط بمؤشرات الضيف البديلة الأصلية. يظل XFG النشط وقمع التصدير وسياسات الحماية غير الممثلة مرفوضًا؛ وجود العنوان في ذاكرة قابلة للتنفيذ لا يجعله هدفًا صالحًا وحده.

يمكن أن تضم مكدسات WDM عدة أجهزة يملكها برنامج التشغيل الضيف نفسه. يربط `IoAttachDeviceToDeviceStack` مصدرًا منفصلًا فوق القمة الحالية للهدف ويعيد القمة السابقة، ويضبط `StackSize` و`AlignmentRequirement` دون تغيير قائمة `NextDevice` أو نسخ أعلام التخزين المؤقت. يتلقى `IoDetachDevice` الجهاز الأدنى المحفوظ ويتطلب `PASSIVE_LEVEL`؛ ويُسمح بالإرفاق حتى `DISPATCH_LEVEL`. فتح جهاز أدنى مسمى يرسل الطلب إلى القمة الحالية، بينما يحتفظ `FILE_OBJECT.DeviceObject` والتقرير بهوية الجهاز المسمى. تستخدم READ/WRITE أعلام القمة المختارة. يحتفظ مسار الطلب بجميع الأجهزة حتى عودة الإرسال، حتى بعد الفصل أو الحذف؛ ولا تزيد المراجع الداخلية `ReferenceCount` الذي يعد المقابض المفتوحة.

يستدعي `IofCallDriver` والمساعد `IoCallDriver` الهدف المحدد بالضبط في المسار المحفوظ. تعمل الدوال المضمنة الحقيقية `IoCopyCurrentIrpStackLocationToNext` و`IoSkipCurrentIrpStackLocation` و`IoSetCompletionRoutine` على IRP الضيف الأصلي، مع التحقق من المؤشر والعدد وأعلام التحكم. يعيد الإرسال الأدنى حالته الفعلية بصورة مستقلة عن `IoStatus` وقيمة عودة دالة الإكمال. يقدم فك الإكمال المؤشر ويختار الاستدعاءات بحسب النجاح أو الخطأ أو الإلغاء وينقل pending إلى الأعلى. تتولى دالة الإكمال المستدعاة هذا النقل، بما في ذلك بعد عودة `STATUS_PENDING` السابقة. يوقف `STATUS_MORE_PROCESSING_REQUIRED` الفك مع إبقاء IRP وMDL والمخازن صالحة، ويستأنفه إكمال لاحق. يتطلب الإكمال المتداخل نتيجة توقف خارجية، ولا تُحرر الذاكرة إلا مرة واحدة عند الفك النهائي. تحتفظ الاستمراريات المحددة بمالك من النظام الفرعي بإطارات WDM/WDF المتداخلة وIRQL الموروث. يُصفّر كل موضع أدنى مستهلك قبل استدعاء دالة الإكمال العليا.

تبقى طلبات IRP التي يخصصها برنامج التشغيل، ووظائف PnP الفرعية الأخرى، ونماذج العتاد والموارد العامة غير مدعومة. يُرفض صراحة إرفاق/تمرير WDF، والإرفاق إلى مكدسات ذات ملفات أو استدعاءات نشطة، وفصل طبقة وسطى، وتغيير الوظيفة الرئيسية، والاستهداف خارج المسار المحفوظ. يستخدم المثال الأصلي الاختياري `driver_wdm_stack.c` المبني بـWDK الحقيقي المسارين `NEVERD_WDM_STACK_FIXTURE` و`NEVERD_WDM_STACK_CFG_FIXTURE`. تشمل الاختبارات الأصلية وC API/CLI إعادة التموضع؛ وتُتخطى المنتجات المفقودة صراحة. تبقى أدلة التنفيذ مقتصرة على Linux.

يمكن أن يحدد السيناريو صراحة حتى 64 عنصرًا في `pnp_devices`. يتطلب كل عنصر `id` و`bus: "resource_free"` / `bus: "register_bank"` و`initial_device_power: "D0"` و`initial_system_power: "working"`؛ ولا تُخمّن الحقائق الغائبة. المعرفات ASCII حساسة لحالة الأحرف بطول 1–64 بايت، تبدأ بحرف أو رقم ولا تحتوي بعده إلا على الحروف والأرقام و`_` و`-` و`.`. يمكن للطلب العادي استخدام `device_id` مهيأ بدل `device`، لا كليهما. يتطلب `kind: "pnp"` الحقول `device_id` و`minor` و`bus_completion`؛ والقيم المدعومة هي `start` و`query_remove` و`cancel_remove` و`remove` و`query_stop` و`stop` و`cancel_stop` و`surprise_removal`. الحقل `bus_completion.status` إلزامي كعدد 32 بت أو نص سداسي عشري؛ و`delay_100ns` اختياري، عدد صحيح غير سالب حتى INT64_MAX من الاستلام الفعلي لدى المزوّد. لا يُقبل `STATUS_PENDING` كحالة نهائية؛ ويتطلب stop/cancel-stop/surprise-removal/cancel-remove/remove القيمة `STATUS_SUCCESS` (0) بالضبط. يرفض PnP حقول الملفات والنقل والإلغاء حتى إذا كانت صفرًا. تطبق واجهة C++ الفحص نفسه.

بعد نجاح DriverEntry ينفذ `AddDevice` مرة لكل PDO مهيأ، مع `DRIVER_OBJECT` مستقل يملكه المزوّد؛ لا يمكن للضيف حذف كائناته أو انتحالها. طلبات PnP IRP هي `KernelMode` بلا ملف وبموارد حسب الناقل المهيأ، وحالتها الأولية `STATUS_NOT_SUPPORTED`. لا تُستهلك استجابة الناقل إلا عند وصول التمرير إلى PDO؛ ويستخدم الإكمال المؤجل الساعة الافتراضية والاستمراريات القائمة. يقرر الإكمال العلوي النهائي تثبيت الحالة أو التراجع مستقلًا عن حالة الناقل. يتطلب نجاح PnP إكمال المزوّد فعليًا؛ وقد يترك فشل START/QUERY_STOP/QUERY_REMOVE المبكر ملاحظات الناقل null. تتطلب الإزالة العادية من Started نجاح query وإغلاق الملفات وانتهاء الطلبات السابقة وفصل/حذف الضيف. تبقى هوية الجهاز/الملف بعد الفصل. فشل AddDevice النظيف يحرر المزوّد فقط؛ وتسرب أجهزة ضيف جديدة، ولو مفصولة، يسبب `model_error`. يجب غياب جميع المزوّدين قبل unload. لا يشمل ذلك بقية PnP أو سياسة الطاقة العامة أو العتاد/الموارد العامة أو KMDF PnP العام.

تحفظ `configuration.pnp_devices` الإعداد الأولي. تحتوي `pnp_devices` المرصودة على `id` و`pdo` و`add_device_status` القابل لـnull و`attached` الحالي و`pnp_state` و`provider_present`؛ وبعد الإزالة يصبح `attached` false. مرحلة AddDevice هي `add_device:<ID>`؛ ويؤثر الفشل في `scenario_success` دون استبدال `nt_status` لـDriverEntry. يضيف كل طلب `device_id` و`pnp` القابلين لـnull؛ ويكون `file` في PnP هو null. يسجل `pnp` الحقول `minor` و`state_before` و`state_after` و`bus_status` القابل لـnull و`bus_received_at_100ns` و`bus_completed_at_100ns`. لا تصبح الحالة المهيأة ملاحظة إلا عند إكمال الناقل فعليًا؛ ووقت الاستلام مستقل. لا تتغير أنواع الحقول السابقة.

تصل طلبات CREATE/READ/WRITE/IOCTL/CLEANUP/CLOSE العادية إلى إرسال الضيف الحقيقي ما دام الجهاز موجودًا خارج Removing/Removed. لا يختلق النموذج فشلًا بسبب Stopped أو StopPending أو RemovePending أو حالة الطاقة؛ يقرر برنامج التشغيل إكمال I/O البرمجي أو رفضه أو احتجازه. يبقى المنفذ العام تسلسليًا؛ لا يمكن تحرير IRP محتجز بلا منتج متاح حاليًا عبر start/cleanup لاحق في السيناريو، فيتوقف مع `model_error` بسبب التعطل. إغلاق الملفات وإنهاء الطلبات السابقة قبل Remove قيود خاصة بهذا الملف التعريفي. تُرفض حالة `query_stop` النهائية `STATUS_RESOURCE_REQUIREMENTS_CHANGED` (0x119) في الفحص المسبق والإكمال النهائي للضيف، لأنها تطلب إعادة استعلام موارد غير ممثلة؛ انظر [عقد QUERY_STOP من Microsoft](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/irp-mn-query-stop-device). لا يضيف stop/restart وsurprise-removal إعادة تخصيص عامة للموارد أو سياسة طاقة عامة أو KMDF PnP العام.

يستخدم PnP بلا موارد المثال الأصلي `driver_wdm_pnp.c` مع WDK الحقيقي والمسارين الاختياريين `NEVERD_WDM_PNP_FIXTURE`/`NEVERD_WDM_PNP_CFG_FIXTURE` واختبارات أصلية وC API/CLI. تُتخطى المنتجات المفقودة صراحة؛ وتبقى أدلة التنفيذ مقتصرة على Linux.

تنفذ أقفال إزالة WDM الصادرات الفعلية `IoInitializeRemoveLockEx` و`IoAcquireRemoveLockEx` و`IoReleaseRemoveLockEx` و`IoReleaseRemoveLockAndWaitEx`؛ أسماء WDK دون Ex هي وحدات ماكرو. المالك هو DEVICE_OBJECT المحدد الذي يحتوي امتداده كامل التخزين المحاذى، مستقلاً عن حالة PDO أو شكل Tag. يمكن التهيئة قبل الإرفاق. تدعم أحجام retail 32 وDBG 120 بايت بشرط وسيط حجم مستقل مطابق؛ تصبح المنطقة المسجلة كلها معتمة. تُعد Tags الفارغة NULL والمتكررة لكل قفل ولا تُفك مؤشراتُها، فيصح release بعد إكمال IRP. تتطلب التهيئة وAndWait مستوى `PASSIVE_LEVEL`؛ ويسمح acquire/release بـ`DISPATCH_LEVEL`.

يغلق AndWait قبول الاكتسابات، ويحرر اكتساباً مطابقاً واحداً، ويوقف إطار الضيف الحقيقي حتى تحرر البقية. يعيد acquire اللاحق `STATUS_DELETE_PENDING` بلا التزام release. يثبت آخر release الجاهزية قبل عودة callback، فيمكن للعامل التحرير ثم انتظار حدث من REMOVE المستأنف. لا يُنشأ callback مصطنع أو مهلة أو نجاح دون منتج. يلزم مسار REMOVE نشط مرتبط يحتوي المالك واستلام فعلي لدى المزود (`bus_received_at_100ns` يقبل الصفر)، وليس الإكمال الأدنى. وضع REMOVE في طابور أدنى قبل وصوله للمزود خارج النطاق؛ هذا ليس تحقق OutsideRemoveDevice/Driver Verifier كاملاً. تبقى الملفات المغلقة والطلبات السابقة المكتملة شرطاً قبل REMOVE، لكن يمكن بقاء callbacks التي تحرر الأقفال. يحتفظ المسار بهويته خلال الانتظار والفصل/الحذف وpending الأدنى حتى عودة الإطارات المتبقية.

يفشل التخزين المجهول/غير المطابق وrelease بلا اكتساب وتكرار drain وإعادة التهيئة وحذف الامتداد مع اكتسابات أو انتظار drain غير مستهلك قبل التعديل. يسمح فشل AddDevice النظيف بحذف قفل مهيأ غير مستخدم. لا تستبدل الأقفال مراجع الجهاز/العامل الفعلية؛ يُلغى التسجيل عند تقاعد الامتداد الفعلي فقط. لا تفعل بيانات debug حدود Verifier الزمنية/high-water. يستخدم الأصل `driver_wdm_remove_lock.c` المتغيرات `NEVERD_WDM_REMOVE_LOCK_FIXTURE`/`NEVERD_WDM_REMOVE_LOCK_CFG_FIXTURE`/`NEVERD_WDM_REMOVE_LOCK_DBG_FIXTURE`/`NEVERD_WDM_REMOVE_LOCK_DBG_CFG_FIXTURE`. تُتخطى المنتجات المفقودة صراحة؛ الأدلة الأصلية وC API/CLI مقتصرة على Linux ولا تعني مدير إزالة كاملاً أو تصريف I/O متزامن عاماً.

يضيف الناقل الاصطناعي `bus: "register_bank"` موارد ذاكرة ثابتة ومحددة صراحة إلى PDO. تحتوي مصفوفة `resources` عند وجودها على `id` و`raw_start` و`translated_start` و`length` و`registers`؛ ويتطلب كل سجل `offset` و`width` و`access` ‏(`read_only` أو `read_write`) و`value` ابتدائية. يحدد `DriverResources.h` / `DriverResources.def` عقد C++ وJSON المشترك. تتبع معرفات الموارد قواعد ASCII المحدودة وتكون فريدة داخل كل PDO. الحدود هي 8 موارد لكل PDO / 32 إجمالًا، و256 سجلًا لكل مورد / 4096 إجمالًا، و1–1048576 بايت لكل مورد. لا يُدعم إلا الوصول الدقيق بعرض 1/2/4 بايت مع محاذاة طبيعية؛ ويجب أن تتسع القيم ضمن العرض. يجب ألا يفيض النطاقان الفيزيائيان؛ ولا تتداخل النطاقات الخام داخل PDO أو النطاقات المترجمة على المستوى العام. تجعل `registers` الفارغة البنك كله غير قابل للوصول صراحة. العناوين والقيم الابتدائية تصريحات وليست عتاد المضيف أو ذاكرة مصفّرة افتراضيًا. يظل `resource_free` بلا قائمة موارد وبمؤشرات START فارغة.

يتلقى START تخصيصين منفصلين للقراءة فقط من `CM_RESOURCE_LIST` الخام والمترجم، مع واصفات Memory متقابلة ومرتبة: واصف كامل واحد، وواجهة Internal، وناقل 0، وإصدار/مراجعة 1، ومشاركة DeviceExclusive، وأعلام READ_WRITE للنطاق. تبقى صلاحية RO لكل سجل مستقلة. يتيح نجاح START الأدنى التخصيص قبل الاستدعاءات العليا؛ وينشئ كل START من NotStarted/Stopped جيل موارد جديدًا بالتخصيص الثابت نفسه. تُهيّأ قيم السجلات مرة واحدة لكل PDO وتبقى بعد إلغاء التعيين وSTOP وإعادة التشغيل. يتطلب فشل START ونجاح STOP/REMOVE أن يحرر برنامج التشغيل التعيينات قبل الإكمال النهائي لـIRP؛ ولا تُنظّف ضمنيًا. تمنع الإزالة المفاجئة التعيينات الجديدة والوصول إلى السجلات فورًا، مع السماح بإلغاء التعيينات الموجودة. يغيّر نجاح إكمال SET الجهاز الفعلي لدى المزوّد إمكانية الوصول الفيزيائي: تمنع D3 الوصول، وتسمح D0 به فقط عند إتاحة التخصيص. تسمح D3 بإنشاء تعيين دون الوصول إلى السجلات؛ ولا تلغي تغييرات الطاقة التعيينات أو تصفّر القيم.

يدعم `MmMapIoSpace` القيمة NonCached؛ ويدعم `MmMapIoSpaceEx` ‏PAGE_NOCACHE مع PAGE_READONLY أو PAGE_READWRITE. يقبل كلاهما نطاقًا فرعيًا مترجمًا مصرحًا به داخل تخصيص واحد فقط، مع حفظ إزاحة الصفحة. تشترك التعيينات البديلة في بنك واحد وتحتفظ بصلاحيات مستقلة، ويتطلب `MmUnmapIoSpace` العنوان الأساسي والطول الأصليين بالضبط. يعيد نفاد التعيينات أو نافذتها أو ميزانية الذاكرة المحددة NULL؛ وتظل أخطاء الخلفية إخفاقات صريحة. لا يستعيد العنوان الملغى الوصول عبر تعيين لاحق. تمر تعليمات السجلات المفردة وتعليمات REP الحقيقية بفحوص MMIO للمعالج؛ وتفشل الفجوات والعروض الخاطئة وسوء المحاذاة وكتابة RO والعبور بين التعيينات والتنفيذ قبل التأثير على السجلات. يجب أن تندرج عمليات الوصول إلى الذاكرة عبر الواجهات الممثلة أيضًا ضمن معاملة واحدة محاذاة بعرض 1/2/4 بايت؛ وتفشل النطاقات الأكبر بدل تقسيمها إلى عمليات وصول للسجلات. لا يشمل ذلك RAM فيزيائية اعتباطية أو إعادة توزيع الموارد أو المنافذ أو أنماط المقاطعات الأخرى أو واجهات DMA الأخرى أو سلوك العتاد العام.

يستخدم [سيناريو بنك السجلات القابل للتشغيل](../examples/driver-register-bank-scenario.json) المثال الأصلي `driver_wdm_resources.c` المبني بـWDK الحقيقي عبر `NEVERD_WDM_RESOURCE_FIXTURE` / `NEVERD_WDM_RESOURCE_CFG_FIXTURE`. ينفذ 14 طلبًا تشمل START المؤجل وعمليات الملفات وSTOP وإعادة التشغيل والإزالة، ويرصد القيم المستمرة عبر IOCTL برنامج التشغيل. يسجل `configuration.pnp_devices[].resources` الحقائق الابتدائية بعناوين فيزيائية سداسية عشرية دون فقد دقة؛ وليس تقريرًا ثانيًا عن حالة البنك. تواصل C API وPython استخدام `scenario_json` و`neverd_driver_options_v1` دون تغيير. تُتخطى المنتجات الحقيقية المفقودة صراحة؛ وتظل أدلة التنفيذ خاصة بـLinux.

يمكن لمزوّد `register_bank` نفسه إعلان `interrupts` وحدها أو إلى جانب `resources`؛ ويجب ألا تكون القائمتان فارغتين معًا. يرفض `resource_free` حقل `interrupts` الصريح حتى إن كان `[]`. تتطلب كل مقاطعة `id` و`raw_vector` و`raw_level` و`raw_affinity` و`translated_vector` و`translated_level` و`translated_affinity` و`mode: "latched"` و`share: "device_exclusive"`. تملك `DriverInterrupts.h` / `DriverInterrupts.def` الأنواع والأسماء والحدود: 8 مقاطعات لكل PDO / 32 إجمالًا، ومعرفات ASCII محدودة وفريدة داخل كل PDO، ومتجهات مترجمة حصرية عالميًا، ومستوى خام 0–65535 وDIRQL مترجم 3–12. تحتفظ المتجهات بكل البتات الـ32 دون تخمين علاقة المتجه بـIRQL. يجب أن يكون قناعا التقارب 1: ‏CPU0 والمجموعة0 حقيقتان صريحتان لدى المزوّد. القيم الخام والمترجمة مستقلة. تحافظ واصفات الذاكرة على ترتيبها، وتليها واصفات المقاطعة المرتبة في `CM_RESOURCE_LIST` نفسها؛ وتستخدم الأخيرة النوع 2 والمشاركة DeviceExclusive والأعلام LATCHED. لا يمثل هذا الملف الاصطناعي المحفّز بالحافة خطوط PCI المشتركة المحفّزة بالمستوى.

يمكن لطلبات READ/WRITE/IOCTL إعلان `interrupt_events`، ولكل حدث `after_100ns` و`device_id` و`interrupt_id` صريحة؛ وترفض أنواع الطلبات الأخرى الحقل حتى لو كان فارغًا. الحد 64 حدثًا لكل طلب / 1024 إجمالًا، وتأخير غير سالب حتى INT64_MAX. يثبت تقديم الطلب بنجاح بداية التأخير ويلتقط مقاطعة متصلة بالفعل وجيل موارد PDO الخاص بها. الأحداث نبضات خارجية مستقلة للخط: إكمال IRP المصدر لا يلغيها، وكتابة السجلات لا تستنتج التمكين أو الحالة أو الإقرار. لا يتقدم الوقت إلا عند الخمول؛ وتنفذ الأحداث المستحقة عند الحد التالي المدعوم للاستدعاءات، لذا لا يَعِد `after_100ns: 0` باستباق التعليمات أو التسليم قبل أول تعليمة للضيف. تُفحص سعات منتجي اللحظة نفسها معًا؛ ويسبق نشر حالة العتاد الأهلية وتسبق ISR كلًا من DPC والعمال. يسجّل فقد الاتصال أو جيل قديم/غير متاح أو D3 الفيزيائي `undelivered_reason` ويوقف التنفيذ بـ`model_error`؛ ولا يُعاد ربط الحدث أو تأخيره بصمت.

تستخدم `IoConnectInterrupt` وسائطها الفعلية الأحد عشر والتخصيص المترجم الدقيق. تدعم `IoConnectInterruptEx` ‏FullySpecified ‏(1) وLineBased ‏(2، خطًا واحدًا مخصصًا في PDO الصريح) وFullySpecifiedGroup ‏(4، المجموعة 0)؛ وتتطلب `IoDisconnectInterruptEx` تطابق الإصدار والسياق. يتطلب التسجيل وفك الاتصال PASSIVE_LEVEL. لا يُدعم إلا قفل خاص بالمقاطعة ووضع latched حصري وCPU0/المجموعة0 ودون حفظ حالة الفاصلة العائمة. يجب أن يساوي IRQL المزامنة DIRQL المخصص؛ وتختار قيمة LineBased الصفرية ذلك المستوى. `KINTERRUPT` معتم ولا يُعاد استخدام عنوانه أبدًا. تتلقى ISR الحقيقية `(Interrupt, ServiceContext)` وترجع BOOLEAN من AL؛ وتعني `FALSE` أن المقاطعة غير متبناة، لا فشل NTSTATUS. تنفذ `KeSynchronizeExecution` الاستدعاء الحقيقي ذي الوسيط الواحد تحت القفل نفسه عند DIRQL، وترجع BOOLEAN مع استعادة IRQL/CR8 للمستدعي. تفرض `KeAcquireInterruptSpinLock` / `KeReleaseInterruptSpinLock` ملكية غير تكرارية والتنفيذ الأصلي وIRQL المحفوظ؛ ولا يجوز أن يبقى قفل ممسوكًا بعد رجوع الاستدعاء. يظل الانتظار داخل المقاطعة والأقفال المشتركة المقدمة من المستدعي والمقاطعات المشتركة/المستوية/MSI/السلبية واستباق التعليمات غير مدعوم. يتطلب START الفاشل وSTOP/REMOVE الناجحان فك الاتصال قبل الإكمال النهائي؛ ويمكن لاستدعاءات الإكمال العليا التنظيف أولًا، ولا يحذف فك الاتصال DPC مصطفة بصمت.

تفصل التقارير التصريحات عن المشاهدات. يحفظ `configuration.pnp_devices[].interrupts` الموارد، ويسطّح `configuration.interrupt_events` أحداث الإدخال مع `source_request_index` (فهرس الطلب المهيأ) و`event_index` اللذين يبدآن من الصفر. تضيف صفوف `interrupts` الجذرية `device_id` و`interrupt_id` و`epoch` و`due_at_100ns` المطلق، والحقول القابلة للقيمة null وهي `occurred_at_100ns` و`delivered_at_100ns` و`returned_at_100ns` و`interrupt_object` و`return_value` و`claimed` و`undelivered_reason`. تُشتق `claimed` من البايت المنخفض للنتيجة الفعلية فقط؛ والطوابع الزمنية مشاهدات وليست نتائج استدعاءات مختلقة. يتطلب `scenario_success` رجوع كل حدث مهيأ دون فشل تسليم؛ وتظل ISR غير المتبنية للمقاطعة صالحة. تظهر آثار DPC عبر إكمال الطلبات الحقيقي واستدعاءات API والرسائل. يستخدم [سيناريو المقاطعة](../examples/driver-interrupt-scenario.json) القابل للتشغيل المثال الأصلي `driver_wdm_interrupts.c` المبني بـWDK الحقيقي والمسارين الاختياريين `NEVERD_WDM_INTERRUPT_FIXTURE` / `NEVERD_WDM_INTERRUPT_CFG_FIXTURE`: تشمل طلباته السبعة START مؤجلًا وIOCTL معلقًا تكمله ISR→DPC وتنظيف/إغلاق الملف والإزالة. يظل مدخل C/Python ‏`scenario_json` وتخطيط `neverd_driver_options_v1` دون تغيير. تُتخطى المنتجات الحقيقية المفقودة صراحة؛ والأدلة التنفيذية مقتصرة على Linux.

يضيف `DriverDMA.h` / `DriverDMA.def` كائن `dma` اختياريًا إلى PDO من نوع `register_bank` بجانب موارد الذاكرة والمقاطعات؛ ولا يغني DMA وحده عن هذين النوعين من الموارد. يجب تحديد الحقول السبعة صراحةً: `address_bits` بقيمة 32 أو 64، و`maximum_length` بين 1–1048576 بايت، و`map_registers` بين 1–256، و`alignment` قوة للعدد اثنين بين 1–4096، و`logical_base` غير صفري ومحاذٍ لصفحة، و`logical_length` محاذٍ لصفحة وبين 4096–1073741824 بايت، والقيمة المنطقية `scatter_gather`. يجب ألا يفيض نطاق العناوين وأن يناسب عرض العنوان. لكل PDO نطاق منطقي مستقل؛ فلا تجعل العناوين المتساوية أجهزة مختلفة تشترك في الذاكرة. يجب أن تتجنب جميع موارد MMIO المترجمة نطاق RAM المحجوز للنموذج `[0x1000000000, 0x1000100000)` حتى دون إعداد DMA. هذه حقائق لجهاز اصطناعي متماسك يتحكم بالناقل، وليست ذاكرة المضيف الفيزيائية أو جهاز PCI.

يقبل `IoGetDmaAdapter` حقول `DEVICE_DESCRIPTION` التاريخية للإصدار 0/1 لسيد ناقل Internal، وينشر `DMA_ADAPTER` من الإصدار الأول مع جدول `DMA_OPERATIONS` الفعلي بحجم 104 بايتات. تعيد استعلامات الإصدار 2/3 القيمة NULL دون قراءة ذيل الوصف الحديث. ترتبط كل دالة غير مباشرة بالمحوّل الحي المحدد، مستقلّة عن استيرادات النواة. الدوال المنفذة هي `AllocateCommonBuffer` و`FreeCommonBuffer` و`GetDmaAlignment` و`GetScatterGatherList` و`PutScatterGatherList` و`PutDmaAdapter` و`AllocateAdapterChannel` و`MapTransfer` و`FlushAdapterBuffers` و`FreeMapRegisters`. يبقى `FreeAdapterChannel` و`ReadDmaCounter` مصيدتين مسمّاتين لأن الملف لا ينمذج متحكم DMA تابعًا أو تابعًا للنظام. تتطلب إدارة common buffer واستعلام المحاذاة PASSIVE_LEVEL؛ ويتطلب Get/PutScatterGatherList مستوى DISPATCH_LEVEL، بينما يسمح تحرير المحوّل حتى DISPATCH_LEVEL. يتجاهل x64 الحقل `CacheEnabled`. تعيد استعلامات الإصدارات غير المدعومة والقدرات المعلنة غير المتوافقة ونقص الموارد الموثق NULL؛ أما اختيارات الواجهة المشوهة أو غير المنمذجة وأعطال الخلفية فتبقى أخطاء صريحة.

يخصص `KernelPhysicalMemory` للذاكرة الموجودة حتى 256 صفحة فيزيائية نموذجية بحجم 4096 بايت. تختلف عناوين CPU الافتراضية وهويات الصفحات الفيزيائية والعناوين المنطقية للجهاز. تكشف مصفوفات PFN للواصفات MDL المبنية الهويات المشتركة للقراءة فقط؛ ولا تملك الواصفات غير المبنية PFN قابلة للاستخدام. قد تتشارك تخصيصات صغيرة متجاورة PFN واحدًا مع الاحتفاظ بنطاقات بايتات وأعمار مستقلة. تستخدم common buffers وذاكرة المجمّع ومخازن الطلبات البايتات نفسها التي تملكها `GuestMemory`، دون نسخة DMA أخرى. يحتفظ تعيين SG الحي بنطاق البيانات الدقيق وواصفه. يرفض الإكمال وتحرير المجمّع/MDL والإزالة التبعيات الحية قبل التحرير. لا يسحب فك تعيين MDL المباشر إلا تعيين CPU في النظام؛ ويستطيع DMA الوصول إلى الذاكرة المقفلة. يسجل `DmaWritable` عقد القفل للكتابة مستقلًا عن صلاحيات تعيين CPU: تتطلب كتابة الجهاز READ/OUT_DIRECT مباشرًا أو ذاكرة غير قابلة للترحيل وقابلة للكتابة؛ ولا يحصل WRITE/IN_DIRECT على هذا الحق لمجرد أن تعيين CPU قابل للكتابة.

تتحقق `GetScatterGatherList` من CurrentVa/Length مقابل نطاق MDL الأصلي، وتنشئ أجزاء صفحات منطقية فوق الذاكرة الموجودة. عند توافر سجلات التعيين، يُنفذ `AdapterListControl` الحقيقي ذو المعاملات الأربعة والعائد void داخل الاستدعاء قبل عودة API؛ وإلا تُحفظ البيانات والواصف وتُحجز سعة الاستدعاء في FIFO الخاص بـPDO حتى تحرير الموارد. لا يملك هذا الملف ملكية StartIo، لذا يكون معامل IRP الثاني للاستدعاء NULL. لا تحرر عودة الاستدعاء التعيين. يمكن تنفيذ `PutScatterGatherList` داخل الاستدعاء؛ وبعد Put يستطيع برنامج التشغيل إكمال الطلب وتحرير آخر محوّل، فيما يستمر عمر متابعة الاستدعاء والاحتفاظ بالجهاز حتى العودة. يتطلب تحرير common buffer المحوّل والطول والعنوان المنطقي وعنوان CPU الأصليين. لا يعاد استخدام العناوين المنطقية طوال الجلسة، حتى بعد إعادة التشغيل. يتوقف انتظار الموارد صراحةً عند غياب منتج حقيقي؛ ولا يختلق إكمالًا أو موعدًا نهائيًا. حين يملك تعيين SG الحي البيانات للجهاز، يتطلب وصول CPU تنفيذ Put أولًا؛ أما الاستدعاء الذي لا يزال ينتظر سجلات التعيين فلم ينقل ملكية البايتات إلى الجهاز بعد.

يتطلب `AllocateAdapterChannel` مستوى DISPATCH_LEVEL ويحجز رمزًا معتمًا غير NULL لسجلات التعيين. تتشارك common buffers وقوائم SG وحجوزات القنوات حصة PDO وطابور FIFO نفسه. يعني النجاح قبول استدعاء `AdapterControl` حقيقي فوري أو مؤجل؛ ويعيد العدد المفرط `STATUS_INSUFFICIENT_RESOURCES` دون استدعاء راجع. يُسمح باستدعاء تخصيص غير منتهٍ واحد لكل جهاز ضيف، ويُرفض استدعاء AllocateAdapterChannel من AdapterControl حتى عبر استدعاء راجع متداخل. تتضمن المعاملات الأربعة اللقطة الفعلية من `DEVICE_OBJECT.CurrentIrp` عند التسجيل. يمكن الكتابة في هذا الحقل المحدد ذي الثمانية بايتات على أجهزة الضيف؛ تُقبل قيمة صفر أو IRP حي يشمل مساره الجهاز. يحتفظ الطابور بالحزمة حتى دخول الاستدعاء الراجع، وبعدها يمكنه إكمالها. ما زال StartIo غير منمذج؛ ومعامل IRP غير المستخدم في استدعاء SG المنفصل يبقى NULL.

يعيد `AdapterControl` قيمة `IO_ALLOCATION_ACTION` من 32 بت؛ تُهمل بتات RAX العليا، ولا يحل الإجراء محل `STATUS_SUCCESS` الخاص بـAllocateAdapterChannel. يحرر `DeallocateObject` عند العودة السجلات غير المستخدمة أو التي اكتمل تفريغها. يحتفظ `DeallocateObjectKeepRegisters` بها حتى استدعاء `FreeMapRegisters` بالمحوّل والرمز والعدد الأصلي المطابقين. تتطلب إعادة `KeepObject` متحكم نظام غير منمذج وتفشل صراحةً. لا يمكن تحرير التخصيص المسلَّم حديثًا بوصفه محتفظًا به قبل عودة استدعائه الراجع؛ يمكن تحرير تخصيص آخر محتفظ به سابقًا عندما يسمح عقده الخاص. لهوية الاستدعاء والسجلات المحتفظ بها والبايتات المعيّنة أعمار مستقلة، وتُفحص جميعها قبل إزالة المحوّل أو الجهاز.

يسمح `MapTransfer` و`FlushAdapterBuffers` بمستوى IRQL حتى DISPATCH_LEVEL؛ ويتطلب تخصيص القناة وتحرير السجلات DISPATCH_LEVEL. يأخذ MapTransfer فهرسًا نسبيًا إلى MDL، ويقرأ طول ULONG فعليًا ويحدّثه، ثم يعيد العنوان المنطقي بالقيمة. يعيد ملف SG المحدود جزء صفحة ذاكرة واحدًا في كل استدعاء؛ وتوسّع الفهارس اللاحقة المتجاورة من MDL نفسه وفي الاتجاه نفسه عملية واحدة. دون SG، يُعيّن كامل النطاق المطلوب في استدعاء واحد إذا اتسع له الحجز، دون تقصير. يحجز التعيين الأول نافذة منطقية لا يعاد استخدامها بحجم حجز السجلات؛ ويمكن تداخل تخصيصات أخرى زمنيًا دون تراكبها. تتشارك الأجزاء تثبيتًا فعليًا واحدًا يتوسع في موضعه. يمكن لمعاملات الجهاز عبور كامل العملية المعيّنة، لكن وصول CPU وتحرير MDL والإكمال الذي يزيل ذاكرة مثبتة تظل ممنوعة حتى التفريغ المجمع. يجب أن يطابق Flush الفهرس الأول وMDL والاتجاه وإجمالي الطول المعيّن فعليًا. يحرر البايتات دون السجلات، فتسمح الرموز المحتفظ بها بعملية أخرى. التفريغ الجزئي وخلط MDL وأنماط MapTransfer الأخرى خارج هذا الملف، دون افتراض أنها غير صالحة في كل أنظمة Windows.

يتحقق `KeFlushIoBuffers` من MDL حي مقفل أو غير قابل للترحيل. المنصة المنمذجة متماسكة؛ لذلك لا تتطلب أي قيمة لـReadOperation أو DmaOperation نسخة ذاكرة مخبأة منفصلة، ولا يحرر الاستدعاء ملكية DMA أو يحل محل FlushAdapterBuffers. يشغّل [سيناريو القناة](../examples/driver-dma-channel-scenario.json) العينة الأصلية `driver_wdm_dma_channel.c` عبر استدعاءَي MapTransfer ومعاملة جهاز واحدة تعبر الصفحة، ثم IRQ/DPC معلن منفصلًا وتفريغ مجمع وتحرير دقيق للسجلات. تستخدم صور normal/CFG الحقيقية `NEVERD_WDM_DMA_CHANNEL_FIXTURE` و`NEVERD_WDM_DMA_CHANNEL_CFG_FIXTURE`.

تقبل READ/WRITE/IOCTL فقط الحقل `dma_events`. يحتاج كل حدث إلى `after_100ns` و`device_id` و`logical_address` و`direction` و`length`؛ ويتطلب `write_memory` أيضًا `data_hex` بالطول الدقيق، بينما يرفض `read_memory` هذا الحقل. تُعرّف الاتجاهات من منظور الجهاز. الحدود هي 64 حدثًا لكل طلب، و1024 إجمالًا، و16 MiB من بايتات المعاملات مجتمعة، و1 MiB لكل معاملة؛ والتأخير غير سالب حتى INT64_MAX. يلتقط التقديم جيل تخصيص PDO الحالي ويحدد أصل الوقت الافتراضي، لكنه لا يشترط وجود تعيين سيُنشئه التوزيع اللاحق. تحل عملية التسليم كامل النطاق المنطقي الحي واتجاهه، وتتطلب D0 الفيزيائي، وتتحقق من جميع البايتات قبل أي أثر. لا يلغي إكمال IRP المصدر الحدث. تسجل التعيينات الغائبة أو المحررة والأجيال القديمة والإزالة المفاجئة وD3 فشلًا وتوقف التنفيذ؛ ولا تعيد الأحداث الارتباط أو تختلق مقاطعة أو بروتوكول سجلات أو إكمال IRP. في حد جدولة واحد، يسبق نشر حالة عتاد المزوّد بايتات DMA، ثم تأتي نبضات المقاطعة المعلنة بصورة مستقلة. يبقى التوقيت تعاونيًا، دون استباق على مستوى التعليمات.

تحفظ التقارير `configuration.pnp_devices[].dma` و`configuration.dma_events` المسطّح. تسجل صفوف `dma_transfers` الجذرية `source_request_index` و`event_index` و`device_id` و`epoch` و`logical_address` و`direction` و`length` و`due_at_100ns`، مع حقول تقبل null هي `occurred_at_100ns` و`completed_at_100ns` و`mapping` و`adapter` و`failure_reason`؛ ويحتوي `data_hex` على البايتات المنقولة فعليًا. يجب إكمال كل معاملة معلنة دون فشل لتحقيق `scenario_success`. يستخدم [سيناريو DMA](../examples/driver-dma-scenario.json) المثال الأصلي `driver_wdm_dma.c` المبني بـWDK الحقيقي مع المسارين الاختياريين `NEVERD_WDM_DMA_FIXTURE` / `NEVERD_WDM_DMA_CFG_FIXTURE`، ويشغّل common buffer بمؤشرات محوّل حقيقية وإكمال ISR→DPC معلن منفصلًا. تستمر C/Python في استخدام `scenario_json` دون تغيير `neverd_driver_options_v1`. تُتخطى المنتجات الغائبة صراحةً؛ والأدلة محدودة بـLinux. لا يشمل الدعم المتحكمات التابعة أو دوال V2/V3 أو محركات واصفات العتاد أو DMA العام في KMDF أو نماذج الأجهزة الأخرى.

تستخدم طلبات طاقة WDM للناقل الاصطناعي `kind: "power"` مع `device_id` مُعدّ. تتطلب كل حزمة صراحةً `minor` ‏(`query`/`set`) و`power_type` ‏(`device`/`system`) و`power_state` ‏(`D0`/`D3` أو `working`/`sleeping3`) و`power_action` ‏(`none`/`sleep`) و`system_context` كعدد32 بت أو سلسلة ست عشرية و`bus_completion`. لا يُدعم System Query إلى Working وتُرفض حقول الملف والنقل والإلغاء. تُحفظ قيمة `system_context` كاملة كحقيقة معتمة دون استنتاج طلب أب أو دعم السبات/بدء التشغيل السريع. تتطلب المسارات `DO_POWER_PAGABLE` دون `DO_POWER_INRUSH`؛ ويجري إرسال الطاقة و`PoRequestPowerIrp` عند `PASSIVE_LEVEL`. يمرر `PoCallDriver` نفس IRP المُدار، ويتبع `PoStartNextPowerIrp` عقد Vista+ دون مصافحة تسلسل إضافية. تظل سياسة الطاقة العامة وWAIT_WAKE والحالات/الأفعال الأخرى والإيقاف/السبات وتيار البدء والمسارات غير القابلة للترحيل والعتاد العام وKMDF PnP العام خارج النطاق.

يمكن لكل عنصر `pnp_devices` تحديد `initial_reported_device_power: "D0"` أو `"D3"` مستقلاً عن دورة الحياة الأولية الإلزامية D0/working. يملك PDO وكل DEVICE_OBJECT ضيف مرتبط لأول مرة حالة إشعار مستقلة؛ يعيد `PoSetPowerState` ويحدّث فقط القيمة السابقة للجهاز المستدعي. عند غياب القيمة الصريحة يفشل الاستدعاء بدلاً من افتراض D0. يحتوي `requested_device_power` الاختياري قوالب device بالحقائق الست نفسها، بحد64 إجمالاً لجميع PDO. لا يُستهلك رأس FIFO الخاص بـPDO إلا باستدعاء `PoRequestPowerIrp` فعلي مطابق للجهاز وminor والهدف. الغياب/عدم التطابق يفشل، والعناصر غير المستهلكة لا تنشئ طلبات، ولا يحدد context طلباً أباً. لكل ابن IRP وصف تقرير مستقلان مع `origin: "PoRequestPowerIrp"` و`response_index` يبدأ بصفر؛ تستخدم صفوف السيناريو `origin: "scenario"` وفهرس null. قد ينفذ الابن المتزامن callback من نوع void بخمسة وسائط قبل عودة `STATUS_PENDING`؛ ويمكن للدالة الانتظار ولـSystem S0 الاكتمال قبل ابن D0 المستقل. تبقى لقطة IO_STATUS_BLOCK صالحة حتى عودة callback.

تضيف التقارير `power` القابل لـnull، ويكون `file` في صفوف الطاقة null. يسجل `power` حقائق الحزمة و`device_state_before`/`device_state_after` و`system_state_before`/`system_state_after` و`requested_device_object` القابل لـnull وملاحظات `bus_status`/`bus_received_at_100ns`/`bus_completed_at_100ns` الفعلية. تضيف أجهزة PnP النهائية `device_power`/`system_power` والأجهزة الحية `reported_device_power` القابل لـnull. يقارن `scenario_success` عدد صفوف السيناريو وحدها بالإعداد، لكنه يشترط نجاح كل طلب فعلي بما فيه الأبناء؛ القوالب غير المستخدمة لا تسبب فشلاً. يستخدم `driver_wdm_power.c` الأصلي `NEVERD_WDM_POWER_FIXTURE`/`NEVERD_WDM_POWER_CFG_FIXTURE` لتغطية native وC API/CLI العادية/active-CFG. تُتخطى الملفات المفقودة صراحةً، وأدلة التنفيذ مقتصرة على Linux.

يمر [سيناريو الطاقة الكامل](../examples/driver-power-scenario.json) عبر البدء واستعلام النظام والنوم والاستيقاظ والإزالة مع ثلاث استجابات أبناء صريحة، باستخدام البرنامج الأصلي وخيار `--scenario`.

يستخدم دعم KMDF 1.33 واجهة ABI للإصدار 1.33.0 بالضبط: تملك 458 خانة دالة هويات ضيف ثابتة، وتتوفر دلالات التنفيذ لواجهات API الإحدى والسبعين أدناه. يدير `WdfVersionBind` و`WdfVersionUnbind` ربط الضيف حول غلاف WDK الحقيقي `FxDriverEntry`. يقرأ `WdfGetDriver` البنية العامة لبيانات البرنامج. تشترك البرامج غير PnP والكائنات العامة وأجهزة التحكم والطوابير والطلبات الواردة في السياقات ذات النوع وعدادات المراجع والاستدعاءات الراجعة المنفذة للتنظيف والتدمير وإلغاء التحميل. تتطلب جميع استدعاءات الإطار واستدعاءاته الراجعة الممثلة حاليًا `PASSIVE_LEVEL`؛ وتبقى إضافة مراجع بعد اكتمال التنظيف خارج هذا الملف التنفيذي. تتوقف الخانات غير الممثلة و`WdfLdrQueryInterface` وامتدادات الفئات وUMDF صراحةً.

تتطلب أجهزة التحكم اسمًا منسوخًا من محارف ASCII القابلة للطباعة وSDDL المطابقة تمامًا لـ `D:P(A;;GA;;;WD)`. يمنح هذا وصولًا للجميع دون اختلاق رمز أمان للجهة المستدعية؛ ولا تدعم واصفات أمان أخرى أو أجهزة بلا أسماء أو أسماء تلقائية. تمتلك تهيئة الجهاز جهاز WDM واحدًا. يمكن للطلبات اختياره عبر نطاق أسماء الجلسة الحالي باستخدام الأسماء المستعارة للروابط الرمزية `\DosDevices\Name` أو `\??\Name`، بينما يحتفظ التقرير بالاسم المعياري للجهاز. يستهلك الإنشاء الناجح كائن التهيئة ويمسح مؤشره، بينما يتراجع الإنشاء الفاشل عن الملكية الجزئية للجهاز. يتيح `WdfControlFinishInitializing` تسليم عمليات الإدخال/الإخراج. لا يزيل الحذف الجهاز وروابطه إلا عندما تسمح الملفات وعناصر العمل والطلبات الممثلة بذلك؛ ولا يدعم إلغاء الطلبات أو تصريفها أثناء الحذف.

تدعم بنية `WDF_IO_QUEUE_CONFIG` ذات 96 بايت الطوابير الافتراضية وغير الافتراضية اليدوية والمتسلسلة والمتوازية ذات الحد المحدود أو غير المحدود مع تنفيذ صريح بالمستوى السلبي ودون مزامنة من الإطار. لا تخضع طوابير أجهزة التحكم لإدارة الطاقة. تكون الأولوية لاستدعاءات READ/WRITE/IOCTL المخصصة على الاستدعاء الافتراضي. تعيد الطلبات المقبولة في الطابور `STATUS_PENDING` حتى عند اكتمالها تزامنيًا؛ ولا يُكمل سجل الإرجاع لاستدعاء void الطلب. يستخدم الإكمال المؤجل المجدول الحالي. عند غياب معالج يكتمل الطلب بـ `STATUS_INVALID_DEVICE_REQUEST`؛ وتكتمل READ/WRITE ذات الطول الصفري دون تسليم ما لم يُفعّل ذلك. تكمل حزمة الملفات الافتراضية CREATE/CLEANUP/CLOSE بنجاح مع Information=0. تدعم الطوابير اليدوية غير الافتراضية نقل الطلبات من الطابور الافتراضي عبر `WdfRequestForwardToIoQueue` واستعادتها بترتيب FIFO عبر `WdfIoQueueRetrieveNextRequest`. يزيل الإطار الطلب الملغى قبل استعادته ويكمله بالحالة `STATUS_CANCELLED`. تسلّم الطوابير التلقائية غير الافتراضية الطلبات المحوّلة إلى استدعاءاتها الخاصة، ويحتفظ الطابور اليدوي الافتراضي بالطلبات الواردة حتى استعادتها. تعمل `WdfIoQueueRetrieveNextRequest` مع الطوابير اليدوية والمتسلسلة، وتعيد الطوابير المتوازية `STATUS_INVALID_DEVICE_STATE`. إذا لم يوجد استدعاء مناسب، يُكمل الطابور التلقائي الطلب بالحالة `STATUS_INVALID_DEVICE_REQUEST` عند توفر موضع للتسليم. تبقى استدعاءات الملفات وأجهزة PnP وPnP/الطاقة الكامل غير مدعومة. يمكن لـ `WdfRequestRequeue` إعادة الطلب الذي استُعيد إلى مقدمة الطابور اليدوي نفسه قبل اكتماله. تضبط `NumberOfPresentedRequests` عدد الطلبات المعروضة في الطابور المتوازي؛ تنتظر الطلبات الزائدة حتى يكتمل طلب معروض أو يُلغى. تقبل القائمة الافتراضية التسلسلية طلبات إضافية أثناء تقديم طلب واحد؛ تنتظر الطلبات التالية بترتيب FIFO حتى يكتمل الطلب المعروض أو يغادر القائمة، ويمكن إلغاء الطلب المنتظر قبل تسليمه. يوقف `WdfIoQueueStop` تسليم الطلبات مع الاستمرار في قبولها. يعيد `WdfIoQueueStart` تسليم الطلبات المنتظرة، وتعرض `WdfIoQueueGetState` عدد الطلبات في الطابور وعدد الطلبات المسلّمة. تعيد محاولة الاسترجاع أثناء التوقف `STATUS_WDF_PAUSED`؛ يُنفّذ استدعاء اكتمال الإيقاف مع السياق المعطى بعد انتهاء جميع الطلبات التي سُلّمت إلى برنامج التشغيل؛ الطلبات المنتظرة لا تؤخره، ويُرفض تسجيل استدعاء ثانٍ أثناء انتظاره.

تسجّل `WdfIoQueueReadyNotify` استدعاء `EvtIoQueueState` واحدًا لطابور يدوي. عند انتقال عدد الطلبات المنتظرة من الصفر إلى قيمة موجبة، يتلقى `(WDFQUEUE, WDFCONTEXT)` عند `PASSIVE_LEVEL` حتى إن ظل برنامج التشغيل يملك طلبات سبق استخراجها. قد يُخطر الطابور غير الفارغ فور التسجيل؛ وينتظر الطابور الموقوف `WdfIoQueueStart`. يعيد التسجيل المكرر أو إلغاء التسجيل قبل الإيقاف `STATUS_INVALID_DEVICE_REQUEST`. بعد `WdfIoQueueStop` تلغي القيمة NULL تسجيل الاستدعاء.

يبحث `WdfIoQueueFindRequest` في طابور يدوي دون نقل ملكية معالجة الطلب، ويضيف مرجعًا عند النجاح. يحرر برنامج التشغيل هذا المرجع باستخدام `WdfObjectDereference`. ينقل `WdfIoQueueRetrieveFoundRequest` ملكية طلب ما زال في الطابور؛ أما الطلب الذي أزيل بالإلغاء فيعيد `STATUS_NOT_FOUND`. تستخدم المعلمات الاختيارية تخطيط `WdfRequestGetParameters` نفسه. ما زال الترشيح بحسب كائن ملف إطار العمل غير مدعوم.

يتلقى `EvtIoCanceledOnQueue` المضبوط `(WDFQUEUE, WDFREQUEST)` فقط للطلب الذي سبق تسليمه إلى برنامج التشغيل ثم أُعيد توجيهه أو إدراجه في الطابور، أو أدرجه استدعاء سياق الطالب صراحةً. يُكمل إطار العمل الطلب الذي لم يُسلَّم إلى برنامج التشغيل قط بالحالة `STATUS_CANCELLED` دون هذا الاستدعاء. يعيد الإخطار ملكية الطلب إلى برنامج التشغيل؛ وعليه إكماله أثناء الاستدعاء أو بعده ولا يجوز إعادة إدراجه في الطابور. ينتظر تطهير الطابور وإخطار الحالة عودة الاستدعاء واكتمال الطلب.

ترفض `WdfIoQueueDrain` الطلبات الجديدة بالحالة `STATUS_INVALID_DEVICE_STATE` وتواصل تسليم الطلبات الموجودة. يُنفّذ الاستدعاء عندما يصبح عدد الطلبات في الطابور والطلبات المملوكة لبرنامج التشغيل صفرًا. تعيد إعادة التوجيه `STATUS_WDF_BUSY`، وتستأنف `WdfIoQueueStart` قبول الطلبات.

تلغي `WdfIoQueuePurge` الطلبات التي لم تُسلَّم بالحالة `STATUS_CANCELLED` وتطلب إلغاء الطلبات المسلّمة والقابلة للإلغاء على IRP الأصلي. يسبق التنظيف تحرير IRP. ينتظر استدعاء الحالة اكتمال الطلبات في الطابور والطلبات المملوكة للسائق واستدعاءات الإلغاء النشطة. يُكمل السائق الطلبات غير القابلة للإلغاء.

تعلّق الدوال `WdfIoQueueStopSynchronously` و`WdfIoQueueDrainSynchronously` و`WdfIoQueuePurgeSynchronously` استدعاء الضيف عند `PASSIVE_LEVEL` حتى تنتهي الطلبات المعنية. يستمر الإيقاف في قبول الطلبات لكنه يوقف تسليمها وينتظر الطلبات المسلّمة. يرفض التفريغ الطلبات الجديدة ويسلّم المنتظرة ثم ينتظر اكتمال المجموعتين. يلغي التطهير الطلبات المنتظرة والمعلّمة قابلة للإلغاء وينتظر عودة استدعاءات الإلغاء. إذا لم يوجد مصدر للإكمال، يبلّغ الانتظار عن خطأ نموذج متوقف.

تلغي الدالتان `WdfIoQueueStopAndPurge` و`WdfIoQueueStopAndPurgeSynchronously` الطلبات الموجودة مسبقًا في الطابور والطلبات التي يملكها البرنامج والمعلّمة قابلة للإلغاء، ثم تستمران في قبول طلبات جديدة دون تسليمها حتى `WdfIoQueueStart`. يكتمل استدعاء الحالة غير المتزامن والانتظار المتزامن بعد انتهاء الطلبات الأصلية واستدعاءات إلغائها؛ وتبقى الطلبات الجديدة في الطابور من دون تأخير الإشعار. يعيد شكلا Stop قبول الطلبات بعد Drain أو Purge أيضًا.

تستخدم معاملات الطلب تخطيط `WDF_REQUEST_PARAMETERS` ذا 40 بايت. تعيد دوال الوصول إلى الإدخال/الإخراج الأطوال المنطقية، مع الحفاظ على الأسماء المستعارة للمخازن وتعيينات MDL الحالية للإدخال/الإخراج المباشر؛ ويبقى إدخال IOCTL المباشر مخزنًا مؤقتًا. تعيد الاتجاهات الخاطئة والمخازن غير الكافية الحالات الموثقة. ينفذ الإكمال تنظيف الطلب بينما تظل المخازن صالحة، ثم يكمل IRP ويحرر الصفحات المثبتة للطلب؛ وبعدها يدمر الكائنات التابعة والطلب عندما تسمح المراجع بذلك. تُرفض الاستدعاءات الجديدة لدوال الوصول إلى المخازن والمعاملات بمجرد بدء الإكمال؛ وتظل مؤشرات المخازن المكتسبة مسبقًا قابلة للاستخدام أثناء التنظيف. يحفظ المرجع الخارجي للكائن السياق، ولا يحفظ الوصول إلى IRP المكتمل.

تُمثَّل آلية الإلغاء لطلبات طوابير أجهزة التحكم الموصوفة أعلاه. إذا وقع الإلغاء بالفعل، يعيد `WdfRequestMarkCancelableEx` الحالة `STATUS_CANCELLED` دون استدعاء راجع. يزيل نجاح `WdfRequestUnmarkCancelable` الاستدعاء الراجع؛ وأي إلغاء لاحق يسجّل حالة الإلغاء فقط. يقرأ `WdfRequestIsCanceled` هذه الحالة لطلب حي غير معلّم بأنه قابل للإلغاء. بعد نجاح وضع علامة القابلية للإلغاء، يتطلب الإكمال إزالة العلامة بنجاح أو بدء تسليم استدعاء الإلغاء؛ ولا تكفي إضافته إلى الطابور. بعد بدء التسليم يمكن للاستدعاء وعنصر عمل التنسيق لإكمال الطلب، حتى إن كان الاستدعاء ينتظر. يحتفظ مرجع داخلي مستقل بالطلب حتى عودة استدعاء الإلغاء. مع ذلك يصبح IRP غير صالح أولًا عند الإكمال، ويمكن لاستكمال تدمير الطلب النهائي أن ينتظر أيضًا. تكون الأولوية لـDPC ثم استدعاءات الإلغاء بترتيب FIFO ثم عناصر العمل العادية؛ وتسبق استدعاءات الإلغاء كذلك استئناف إطارات الانتظار الجاهزة ذات المستوى السلبي.

للطلب الملغى مسبقًا، تنفذ واجهة void القديمة `WdfRequestMarkCancelable` استدعاء إلغاء راجعًا للضيف بصورة متزامنة قبل عودتها. يمكن للاستكمال التابع الانتظار وإكمال الطلب عبر تنظيف متداخل وتنفيذ التدمير النهائي قبل استئناف الواجهة الأصلية. يستخدم الإلغاء اللاحق للتسجيل المسار المجدول أعلاه. يعيد هذا سلوك المصدر العام عند `PASSIVE_LEVEL` مع `WdfSynchronizationScopeNone`؛ وتطلب [Microsoft](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdfrequest/nf-wdfrequest-wdfrequestmarkcancelable) من البرامج التي لا تستخدم المزامنة التلقائية استعمال Ex. هذا سلوك توافق، وليس توصية باستخدام الواجهة القديمة في هذه التهيئة.

تشترك `WdfRequestGetInformation` و`WdfRequestSetInformation` في حقل `IRP.IoStatus.Information` الأصلي ذي 64 بت، بما يشمل كتابة الضيف المباشرة. تسند Set القيمة فقط؛ ويُفحص طول النقل عند الإكمال. تكتب `WdfRequestCompleteWithInformation` الحقل نفسه قبل التنظيف؛ وتحدد التعديلات أثناء التنظيف عبر IRP محفوظ مسبقًا قيمة Information النهائية، رغم أن GetInformation تعيد صفرًا في هذه المرحلة. تعيد `WdfRequestGetIoQueue` الطابور الأصلي. في تهيئة الملفات الافتراضية تعيد `WdfRequestGetFileObject` القيمة NULL دون اختلاق كائن ملف WDF من FILE_OBJECT الخاص بـWDM. تعيد `WdfRequestWdmGetIrp` حزمة IRP نفسها؛ ولا يمكن لاستدعاءات الضيف `IoCompleteRequest`/`IofCompleteRequest` تجاوز إكمال WDF. ما دام مقبض الطلب صالحًا أثناء الإكمال أو بعده، تعيد GetInformation/GetIoQueue صفرًا، ويمسح استرجاع MDL خانة الخرج الصالحة إلى NULL أولًا ثم يعيد `STATUS_INTERNAL_ERROR`. تبقى SetInformation/GetFileObject/WdmGetIrp مرفوضة حينئذ، ولا تتغير قيود دوال المخازن والمعاملات الحالية.

تصف `WdfRequestRetrieveInputWdmMdl` و`WdfRequestRetrieveOutputWdmMdl` عند الحاجة SystemBuffer الموجود لإدخال WRITE وإخراج READ وإدخال/إخراج IOCTL ذي المخزن. يُتحقق من صلاحية الاتجاه وطوله غير الصفري في كل مرة قبل استخدام الواصف الوحيد المخزّن لكل طلب؛ ويحدد أول استرجاع ناجح ByteCount حتى لو اختلف الطول المنطقي للاتجاه الآخر. تعيد `MmGetSystemAddressForMdlSafe` عنوان VA الأصلي لهذا الواصف؛ وتُرفض التعيينات الإضافية وفك التعيين والتحرير بواسطة برنامج التشغيل. يعيد إخراج READ/IOCTL المباشر وإدخال WRITE المباشر قيمة `IRP.MdlAddress` الموجودة دون إنشاء تعيين بمجرد الاسترجاع؛ ويستخدم إدخال IOCTL المباشر مخزن SystemBuffer. تنتهي صلاحية الواصفات وIRP والمخازن عند الإكمال. تحتفظ مراجع الإلغاء الداخلية أو المراجع الخارجية بسياق WDF فقط. يبقى جلب MDL عبر WDF لـ`METHOD_NEITHER` والوصول إلى PFN غير المبني غير مدعومين؛ تستخدم WDFMEMORY الخاصة بالطلب تعيينًا منفصلًا لصفحات مثبتة.

في طلبات KMDF المخزنة والمباشرة وneither، يعمل `WdfDeviceInitSetIoInCallerContextCallback` قبل الطابور في عملية مقدم الطلب عند `PASSIVE_LEVEL`. يجب إكمال الطلب أو استدعاء `WdfDeviceEnqueueRequest` مرة واحدة للطابور الافتراضي. في IOCTL من نوع `METHOD_NEITHER` وREAD/WRITE بنمط neither، تعيد `WdfRequestRetrieveUnsafeUserInputBuffer` و`WdfRequestRetrieveUnsafeUserOutputBuffer` عناوين المستخدم الأصلية داخل رد الاتصال هذا فقط. تتحقق `WdfRequestProbeAndLockUserBufferForRead` و`WdfRequestProbeAndLockUserBufferForWrite` من أذونات الصفحات وتثبتها للطلب؛ وتعيد `WdfMemoryGetBuffer` عنوانًا مستعارًا للنظام صالحًا في رد اتصال الطابور خارج سياق مقدم الطلب. يحرر إكمال الطلب التثبيت والعناوين المستعارة. لا تزال المؤشرات المضمنة وتعيينات المستخدم العامة غير مدعومة.

يدعم الملف المحدود لـ KMDF PnP زوج FDO/PDO متصلاً مباشرة. يتلقى `EvtDriverDeviceAdd` مهيئاً يملكه الإطار؛ ينشئ `WdfDeviceCreate` كائن FDO، وتحافظ `WdfFdoInitWdmGetPhysicalDevice` و`WdfDeviceWdmGetPhysicalDevice` على هوية PDO. بعد فشل AddDevice أو اكتمال Remove ينفذ الإطار استدعاءات التنظيف/التدمير ويحذف الجهاز. تدعم قوائم PnP القيمة الافتراضية `WdfUseDefault` والقيمة الصريحة `WdfTrue` لإدارة الطاقة؛ وتبقى `WdfFalse` بلا إدارة تلقائية. يدعم `WdfDeviceInitSetPnpPowerEventCallbacks` الاستدعاءات `EvtDevicePrepareHardware` و`EvtDeviceD0Entry` و`EvtDeviceD0Exit` و`EvtDeviceReleaseHardware`. يستقبل PrepareHardware قائمتَي موارد منفصلتين قبل D0Entry؛ وتكونان فارغتين للأجهزة التي لا تملك موارد؛ وفي القوائم الفارغة، تعيد `WdfCmResourceListGetCount` صفراً و`WdfCmResourceListGetDescriptor` قيمة NULL. يؤدي فشل PrepareHardware أو D0Entry إلى فشل START، مع استدعاء ReleaseHardware حتى في حالة الفشل. عند الإيقاف أو الإزالة من D0، يسبق D0Exit استدعاء ReleaseHardware قبل اكتمال IRP. تعرض أجهزة `register_bank` أوصاف `CM_PARTIAL_RESOURCE_DESCRIPTOR` للموارد المخصصة للقراءة فقط حتى ReleaseHardware؛ يمكن ربط الذاكرة المترجمة عبر `MmMapIoSpace` ويجب فك ربطها قبل اكتمال STOP أو Remove. تظل أنواع الموارد الأخرى وسياسة الطاقة العامة خارج النطاق. تعرض `WdfIoQueuePnpHeld` حجب التسليم قبل D0 وبعد مغادرته؛ قبل مغادرة D0 يُستدعى `EvtIoStop` لكل طلب تحتفظ به قائمة مُدارة بالطاقة؛ يمكن إكماله أو تأكيد إيقافه بواسطة `WdfRequestStopAcknowledge` أو ترك مصدر إكمال موجود ينهيه. وإذا لم يُسجّل `EvtIoStop`، ينتظر الإطار اكتمال كل الطلبات التي سلّمها. القيمة TRUE تعيد الطلب إلى القائمة لتسليمه بعد إعادة التشغيل، وFALSE تُبقي ملكيته لدى برنامج التشغيل وتستدعي `EvtIoResume` بعد العودة إلى D0. تظل الطلبات المصطفّة معلّقة حتى إعادة التشغيل، إذا لم يبق مصدر إكمال، ينتهي الانتظار بخطأ توقف `model_error`. يستخدم مثال WDK الأصلي `driver_kmdf_pnp.c` المتغيرين `NEVERD_KMDF_PNP_FIXTURE` / `NEVERD_KMDF_PNP_CFG_FIXTURE`.

تأتي حدود IRQL من `KernelAPIIRQL.def` وتتحقق النماذج المسؤولة من الشروط المعتمدة على الوسائط. لا يمكن لـDPC استدعاء واجهات السجل أو تخصيص المخزن المقسّم إلى صفحات أو تحريره أو الوصول إليه. تتطلب تحويلات Unicode في `DbgPrint` مستوى `PASSIVE_LEVEL`، بينما يبقى إخراج ANSI والعمليات غير القابلة للترحيل المدعومة متاحة عند `DISPATCH_LEVEL`. للمكدسات حدود؛ فلا يدخل مؤشر مكدس خارج النطاق مكدس عامل آخر محجوب. تمنع المؤقتات الفعالة في امتداد الجهاز تحريره المبكر.

يلبّي انتهاء المؤقت الانتظارات المسجلة قبل أن يعيد DPC ضبطه أو تشغيله. تنفذ DPC المصطفة قبل استئناف إطارات `PASSIVE_LEVEL` المستيقظة. إذا بقي DPC في الطابور ضمن ذاكرة الطلب، يرفض إكمال IRP تحريرها قبل الإكمال وإبطال المخزن المؤقت.

يدعم تنسيق `DbgPrint` الأعداد الصحيحة `d/i/u/o/x/X` والمؤشر `p` والنص `s/c` و`%%` وUnicode محدد الطول `wZ/lZ` والنص العريض `ls/ws` والأعلام والعرض/الدقة بما فيهما `*` ومعدّلات طول الأعداد الصحيحة في Windows. تُقرأ 32 وسيطة متغيرة و1024 بايت للتنسيق على الأكثر. يقتصر العرض والدقة على 512. يوقف التنفيذ صراحةً عند الأعداد العائمة و`%n` والتركيبات المجهولة وتحويلات النص غير ASCII؛ ولا يخمّن النموذج صفحة ترميز Windows أو يستدعي printf المضيف على بيانات الضيف.

ينتهي عمر سجل RegistryPath الأصلي ومخزنه عندما يعود DriverEntry. على برامج التشغيل التي تحتاج السلسلة لاحقًا نسخها أثناء التهيئة.

حجم منطقة تخصيص الكائنات/المخزن هو 1 MiB. تستخدم بايتات المخزن غير المهيّأة المحتوى الحتمي `0xCD`، وتستخدم البايتات المحررة `0xDD`. هذا سيناريو تنفيذ محدد واحد. ترفض عمليات وصول المعالج وواجهات المخازن الممثلة الوصول إلى تخصيصات مخزن محررة أو أجهزة محذوفة أو بايتات غير مخصصة في المنطقة أو حقول كائنات معتمة، كما ترفض الكتابة إلى حقول الكائنات المخصصة للقراءة فقط. تغطي هذه الفحوص أعمار كائنات هذا النموذج؛ وليست تحليلًا عامًا لسلامة ذاكرة برنامج التشغيل. تُعرض خانات جدول الإرسال التي لم تُكتب بصفر يعني «غير مسجّلة». يكتمل طلب السيناريو لدالة رئيسية غير مسجلة عبر المعالج الافتراضي الممثل، بالحالة `STATUS_INVALID_DEVICE_REQUEST`؛ ويظل الفشل ظاهرًا في حالة الإرسال وحالة الإدخال/الإخراج معًا. لا يختلق النموذج عنوان دالة داخل الضيف لذلك المعالج، وتظل قراءة الضيف لخانة لم تُكتب غير مدعومة. التسجيل الصريح لاستدعاء راجع بمؤشر null خطأ.

## سيناريوهات الطلبات

مرّر ملف JSON باستخدام `--scenario` لاختيار الطلبات وإلغاء التحميل الاختياري:

```bash
build-release/bin/neverd emulate-driver path/to/driver.sys \
  --scenario scenario.json > driver-report.json
```

لبرنامج تشغيل ينشئ `\Device\NeverDIO` ويقبل IOCTL مخزّنًا مؤقتًا برمز `0x222000`، يكون مثال `scenario.json` كما يلي:

```json
{
  "requests": [
    {"kind": "create", "device": "\\Device\\NeverDIO"},
    {"kind": "ioctl", "code": "0x222000", "input": "00112233", "output_size": 4},
    {"kind": "cleanup"},
    {"kind": "close"}
  ],
  "unload": true
}
```

يجب أن يطابق اسم الجهاز ورمز IOCTL برنامج التشغيل. عند create، يؤدي حذف `device` إلى اختيار الجهاز الحي الوحيد؛ ويفشل الاختيار إن كان ملتبسًا. تستخدم الطلبات اللاحقة جهاز ملفها ما لم يُعطَ اسم مطابق صراحةً. الحقل الاختياري `file` هو هوية سيناريو غير موقّعة من 32 بت، وقيمته الافتراضية صفر. لكل هوية FILE_OBJECT وFsContext خاصان بها، ويجب أن تتبع ترتيب create ثم عمليات النقل ثم cleanup ثم close. يمكن تداخل ترتيب طلبات الملفات المستقلة. ترفض الأجهزة الحصرية عملية فتح ثانية. تمثّل هذه الهويات كائنات ملفات، لا مقابض مكررة. تُدعم طريقة buffered وطريقتا direct في IOCTL. يجب أن يكتمل الإرسال بصورة متزامنة أو يتبع عقد الاستدعاءات الراجعة للطلب المعلّق أعلاه. تفشل صراحةً أطوال المخرجات غير الصالحة والوصول إلى IRP مكتمل. يجب ألا يترك إلغاء التحميل المطلوب أي جهاز حي أو رابط رمزي أو تخصيص مخزن أو كائن ملف.

يطلب الحقل الجذري الاختياري `"load_address": "0x190000000"` تغيير العنوان الأساسي؛ ويؤدي حذفه أو استخدام `"0x0"` إلى اختيار العنوان المفضّل. يجب أن تستوفي الصورة متطلبات النقل. لا يتضمن أمر التهيئة الأصلي أو واجهة C API سيناريو ضمنيًا.

لا تُقبل في الجذر سوى الحقول `load_address` و`requests` و`unload` و`kernel_exports` و`registry` و`pnp_devices`. تقبل طلبات الملفات العادية `kind` والحقل الاختياري `device` أو `device_id` (لا كليهما) والحقل الاختياري `file`. تتطلب طلبات IOCTL الحقل `code` وتقبل `input` و`output_size` و`direct_input`. يقبل `read` الحقلين `output_size` و`byte_offset`؛ ويقبل `write` الحقلين `input` و`byte_offset`. الإزاحات صفر افتراضيًا، وتقبل أعدادًا صحيحة أو سلاسل سداسية عشرية، ويجب أن تلائم قيمة غير سالبة ضمن عدد صحيح موقّع من 64 بت. ترفض طلبات دورة الحياة حقول النقل. تُرفض الحقول المجهولة أو المكررة. يقبل `code` عدد JSON صحيحًا غير موقّع من 32 بت أو سلسلة سداسية عشرية تبدأ بـ`0x`. أما `input` فهو سلسلة بايتات سداسية عشرية بطول زوجي، بلا بادئة أو مسافات؛ وحذفه يعني مدخلًا فارغًا. `output_size` عدد JSON صحيح غير موقّع؛ وحذفه يعني الصفر. تُرفض الكسور وصيغ كتابة الأعداد العائمة.

تقبل طلبات READ/WRITE/IOCTL وحدها الحقل الاختياري `cancel_after_100ns`، وهو عدد JSON صحيح من 0 إلى `INT64_MAX` ‏(9223372036854775807). يجدول الإلغاء نسبةً إلى لحظة تقديم الطلب بوحدات افتراضية مقدارها 100 ns، لا بالوقت الفعلي. في KMDF، تطبّق القيمة صفر الإلغاء بعد توجيه الإطار وقبل استدعاء الإدخال/الإخراج الراجع للضيف؛ وإذا كان التوجيه قد أكمل الطلب بالفعل تكون الأولوية للإكمال. في WDM، تطبّق القيمة صفر بعد عودة دالة الإرسال. عند التأخير الموجب لا يتقدم الوقت إلى موعد مؤقت أو انتظار أو إلغاء إلا عند غياب استدعاءات أو إطارات جاهزة. يُلغي طلب WDM المعلّق عبر روتين الإلغاء المسجّل عند `DISPATCH_LEVEL` مع قفل الإلغاء؛ يجب تحرير القفل باستخدام `Irp->CancelIrql` قبل الإكمال. ويظل الإلغاء العام للطوابير وPnP غير مدعوم. يحتوي تقرير كل طلب على `cancel_requested_at_100ns`: الوقت الافتراضي المطلق الذي وقع فيه الإلغاء فعلًا، أو null إن لم يقع، بما في ذلك إذا سبق الإكمال الإلغاء. لا يكمل طلب الإلغاء وحده IRP ولا يحدد حالته النهائية.
تستخدم `IoSetCancelRoutine` و`IoAcquireCancelSpinLock` و`IoReleaseCancelSpinLock` و`IoCancelIrp` حالة IRP وقفل الإلغاء نفسها؛ يستدعي `IoCancelIrp` الروتين المسجّل تزامنيًا ويعيد ما إذا استُدعي.

يتيح الحقل المنطقي الاختياري `user_unmap_after_dispatch` لطلبات WDM غير المخزنة ذات المخزن غير الفارغ إلغاء الوصول إلى عناوين المستخدم الأصلية بعد عودة الإرسال وقبل العمل أو الإلغاء المجدول. تبقى الصفحات المثبتة وأسماء النظام المستعارة صالحة حتى يفكّ السائق القفل، بينما يفشل استخدام مؤشر المستخدم الخام أو قفل جديد. يكون `output_hex` فارغًا إذا أُلغي عنوان الإخراج. لا يُعاد استخدام العنوان في هذا السيناريو، ولا تُنمذج إعادة التعيين أو توقيت الإلغاء العام.

يحدد `requestor_process_id` عملية طلب اصطناعية (الافتراضي 4096؛ المدى 5 إلى `UINT32_MAX`). يعيد `IoGetRequestorProcessId` هويتها لطلب IRP حي، ويعيد `PsGetCurrentProcessId` الهوية في الإرسال المباشر أو 4 في عامل النظام المحاكى. يجعل تبديل العملية عناوين المستخدم لعملية أخرى غير متاحة، بينما تبقى أسماء النظام المستعارة لصفحات MDL المقفلة صالحة. يلغي `requestor_exit_after_dispatch` جميع عناوين المستخدم الأصلية لهذه العملية بعد عودة الإرسال، ويرفض I/O الجديدة منها مع إبقاء CLEANUP وCLOSE الصريحتين؛ لا يُفترض الإلغاء أو إغلاق المقابض تلقائياً.

يمكن لعامل النظام الحصول على كائن العملية المعتم لطلب IRP حي عبر `IoGetRequestorProcess`، ثم استخدام `KeStackAttachProcess` مع `KAPC_STATE` قابل للكتابة في النواة للوصول مؤقتاً إلى عناوين المستخدم الأصلية، وإعادة الحالة نفسها عبر `KeUnstackDetachProcess`. يعكس `IoGetCurrentProcess` و`PsGetProcessId` العملية المرفقة، بينما يظل `PsGetCurrentProcessId` بالقيمة 4، وهي عملية إنشاء العامل. يُرفض صراحةً إرفاق عملية منتهية أو IRP مكتمل أو حالة غير مطابقة، وكذلك الانتظار أو إكمال IRP أثناء الإرفاق.

في طلبات direct IOCTL، يهيّئ `input` مخزن النظام الأول، بينما يهيّئ `direct_input` المخزن الثاني المنفصل الذي تصفه MDL، مع استكماله بأصفار حتى `output_size`. تتطلب `METHOD_IN_DIRECT` صلاحية القراءة، لكنها لا تعني أن تعيين النظام للقراءة فقط. تستخدم الطريقتان مخازن سيناريو قابلة للقراءة والكتابة. يزيل `MdlMappingNoWrite` صلاحية الكتابة للتعيين، ويزيل `MdlMappingNoExecute` صلاحية التنفيذ. يلغي فك التعيين صلاحية العنوان الافتراضي للنظام؛ وتحافظ إعادة التعيين على البيانات المقفلة نفسها. ينهي الإكمال عمر MDL والتعيين. تُنمذج حقول MDL العامة التي تستخدمها وحدات ماكرو WDM؛ وتُرفض حقول process وPFN للواصفات MDL غير المبنية وقوائم MDL المنشأة يدويًا وتعيينات المستخدم والوصول المباشر عبر UserBuffer الخام. يكون MDL لمخزن direct صفري الطول null.

تخصص `IoAllocateMdl` بيانات وصفية مستقلة لمخزن غير فارغ لا يتجاوز عنوانه المجال ولا يزيد حجمه عن 1 MiB؛ ولا تفحص المخزن أو تقفل صفحاته. يجب أن تكون `Irp` بقيمة NULL وأن تكون `SecondaryBuffer` و`ChargeQuota` بقيمة FALSE. يعيد نفاد الحيّز NULL. تتطلب `MmBuildMdlForNonPagedPool` أن يقع المجال الموصوف بالكامل داخل تخصيص صالح واحد في المجمّع غير القابل للترحيل. يعيد المساعد الآمن ووحدات ماكرو WDM المعتادة استخدام العنوان الأصلي، مع الحفاظ على مشاركة المخزن والصلاحيات الحالية حتى عند إضافة أعلام منع الكتابة أو التنفيذ. تُرفض التعيينات الإضافية في فضاء النظام وفك التعيين. تنهي `IoFreeMdl` عمر الواصف فقط؛ ولمخزن المجمّع عمر مستقل. يُدعم كلا ترتيبي التحرير ما دامت الذاكرة المحررة لا تُستخدم لاحقًا. جميع حقول MDL المنمذجة للقراءة فقط؛ ولا يُدعم الوصول إلى process وPFN للواصفات MDL غير المبنية أو السلاسل أو تعديل الحقول يدويًا. يجب أن يحرر التفريغ جميع الواصفات التي يملكها برنامج التشغيل.

في كل طرق IOCTL ذات `output_size` غير الصفري، يجب ألا تتجاوز `Information` قيمة `output_size` حتى لو كان مخزن الإدخال أكبر. إذا لم يوجد مخزن إخراج، يمكن أن تتضمن `Information` نتيجة من 64 بت يحددها برنامج التشغيل؛ ولا تُفسَّر على أنها عدد بايتات مطلوب نسخها. يحتفظ التقرير بالقيمة العددية ويضيف `information_hex` كسلسلة سداسية عشرية دقيقة لقارئات JSON التي لا تستطيع تمثيل جميع الأعداد الصحيحة من 64 بت.

في READ/WRITE، يحدد `DO_BUFFERED_IO` أو `DO_DIRECT_IO` النقل المخزن أو المباشر. إذا لم يُضبط أي منهما، يظهر عنوان المستخدم الأصلي في `IRP.UserBuffer` فقط: تستخدم WRITE الإدخال وتستخدم READ الإخراج، دون إنشاء SystemBuffer أو MDL ضمنيًا. يجب على برنامج التشغيل فحص العنوان والوصول إليه في سياق المستدعي أو تثبيت الصفحات قبل تأجيل العمل. ينطبق `user_input_access` على neither WRITE و`user_output_access` على neither READ. تتوقف الطلبات المخزنة أو المباشرة ذات حقوق وصول صريحة، وكذلك الأعلام المتعارضة. تُفحص Information مقارنة بطول النقل؛ وتعيد الكتابة عددًا، بينما تعيد القراءة بايتات.

يربط `kernel_exports` أسماء الإجراءات بقيم منطقية صريحة للتوافر، مثل `"kernel_exports": {"OptionalRoutine": false}`. تحصل الصادرات الممثلة والاستيرادات الثابتة على عناوين مستقرة مشتركة مع `MmGetSystemRoutineAddress`. يُحل التصدير الغائب صراحةً إلى NULL، ولا يمكنه تلبية استيراد ثابت. ويُحل التصدير المعلن وجوده دون نموذج API إلى مصيدة مؤجلة. يوقف الاسم الديناميكي المجهول التنفيذ بتشخيص يفيد بأن التوافر غير محدد؛ ولا يُستنتج الغياب أبدًا من عدم وجود التنفيذ. الأسماء محدودة الطول ومكوّنة من ASCII قابل للطباعة، وحلها حساس لحالة الأحرف. السجل خاصية لسيناريو محدد، وليس ادعاءً بمطابقة كل إصدار Windows.
`IoMarkIrpPending`, `IoGetCurrentIrpStackLocation` و`MmGetSystemAddressForMdlSafe` دوال مساعدة من ترويسات WDM يمثلها النموذج؛ ولا يعني ذلك الإعلان عنها كتصديرات افتراضيًا، لذا يتطلب توافرها كتصديرات استيرادًا ثابتًا أو إعلانًا صريحًا في `kernel_exports`.

يقتصر نص السيناريو على 2 MiB، وبحد أقصى 64 طلبًا، و65536 بايت لكل مخزن إدخال أو إخراج، و512 KiB إجمالًا للبايتات المطلوبة بما فيها محتوى `direct_input`. تسري ميزانيات التعليمات والمشاهدات وذاكرة الضيف والوقت على السيناريو كله. تحتوي منطقة 1 MiB أيضًا على الكائنات والبيانات الوصفية، ولذلك يمكن للصورة استنفاد ذاكرة النموذج قبل استهلاك الحد الأقصى لمخازن السيناريو.

## سيناريوهات السجل

تحدد المصفوفة الاختيارية `registry` شجرة سجل ملموسة محلية للجلسة. لكل مفتاح
حقل `path` مطلوب ومصفوفة `values` اختيارية؛ وتتضمن كل قيمة `name` وعددًا صحيحًا
غير موقّع `type` وبيانات سداسية عشرية `data`. يحدد اسم القيمة الفارغ القيمة
الافتراضية. مثال لقيمة DWORD هو `{"name":"Mode","type":4,"data":"01000000"}`.
تُحفظ بايتات القيم كما هي تمامًا؛ ولا يصلح النموذج محارف نهاية السلاسل أو يوسّع
متغيرات البيئة.

يجب أن تكون المسارات مطلقة ومن أحرف ASCII تحت `\\Registry\\Machine` أو
`\\Registry\\User`. تُنشأ مفاتيح الأسلاف ضمنيًا. تُقارن هويات المفاتيح والقيم
دون حساسية لحالة الأحرف وفق قواعد ASCII؛ وتُرفض الأسماء غير ASCII والهويات
المكررة. عند حذف `registry` يظل توافر السجل غير محدد وتتوقف استدعاءات السجل.
أما `"registry": []` فتصف نطاق أسماء فارغًا صراحةً. لا يُستنتج من برنامج التشغيل
أي مفتاح أو قيمة أو بيانات من سجل المضيف أو إعداد للخدمة.

تعيد `ZwOpenKey` و`ZwCreateKey` مقابض معتمة مستقلة، مع فحص صلاحيات كل مقبض
عند الاستعلام والكتابة وإنشاء المفاتيح الفرعية والحذف. تمنح الشجرة المضبوطة
البتات المدعومة في `KEY_ALL_ACCESS`، بما فيها القناعان المعتادان `KEY_READ`
و`KEY_WRITE`. هذه شجرة اختبار متاحة صراحةً، دون قوائم ACL الخاصة بـWindows أو
تقييم الامتيازات. لا تُدعم الحقوق العامة أو `MAXIMUM_ALLOWED` أو عروض السجل
البديلة أو واصفات الأمان المخصصة أو الفئات أو الروابط الرمزية. يتطلب الإنشاء
بمسار نسبي مقبضًا للأب المباشر مع `KEY_CREATE_SUB_KEY`. مفاتيح الإدخال غير
متطايرة؛ ويمكن إنشاء مفاتيح متطايرة، لكن يُرفض إنشاء مفتاح غير متطاير تحت أب
متطاير. لا يوجد نموذج لإعادة التشغيل أو الحفظ على القرص.

تنفذ `ZwQueryValueKey` فئات المعلومات Basic وFull وPartial وصيغ Align64
المعرّفة لها، بما في ذلك الأطوال الدقيقة والبيانات المحاذاة والإخراج الجزئي
والنتيجتان المختلفتان `STATUS_BUFFER_TOO_SMALL` و`STATUS_BUFFER_OVERFLOW`.
تغيّر `ZwSetValueKey` و`ZwDeleteValueKey` شجرة هذه الجلسة فقط. ترفض `ZwDeleteKey`
حذف مفتاح له مفاتيح فرعية قائمة؛ وتعيد مقابض المفتاح المحذوف
`STATUS_KEY_DELETED` إلى أن تُغلق. تحرر `ZwClose` المقبض بصورة مستقلة عن المفتاح،
ويفشل إلغاء التحميل المطلوب ما دامت هناك مقابض سجل مفتوحة.

الحدود هي 256 مفتاحًا بما فيها الأسلاف، و1024 قيمة إجمالًا، و65536 بايت لكل
قيمة، و512 KiB لمجموع بيانات القيم، و1024 بايت ASCII لمسار المفتاح، و256 بايت
لاسم القيمة، و256 مقبضًا مفتوحًا في الوقت نفسه. تخضع عمليات الإنشاء والتعديل
للحدود نفسها المطبقة في الفحص المسبق للسيناريو. يحتفظ `configuration.registry`
في التقرير بالإدخال الأصلي؛ ويسرد `registry` المسارات والقيم النهائية للمفاتيح
القائمة، بما فيها التعديلات المرصودة قبل التوقف. تُعرض حالة السجل غير المحددة
بالقيمة null. لا تتضمن لقطة القيم هذه خاصية التطاير أو هويات المقابض.

## فحص قبول مثال Microsoft

ينزّل [سكربت التحقق](../../scripts/validate_windows_driver_sample.py)، الذي يُشغّل اختياريًا، مصدر Microsoft SIOCTL عند المراجعة المثبّتة في [بيان التحقق](../../unittests/emulation/fixtures/sioctl-validation.json)، ويتحقق من تجزئات SHA-256، ثم يترجم المصدر غير المعدّل باستخدام ترويسات MinGW-w64 DDK. يحتفظ بالترخيص/المنشأ الأصليين وأوامر البناء والسيناريو والتقارير في مجلد المخرجات المختار. يتطلب وصولًا إلى الشبكة وClang و`lld-link` و`nm` وترويسات DDK الخاصة بـMinGW-w64:

```bash
python3 scripts/validate_windows_driver_sample.py \
  --neverd build-release/bin/neverd \
  --output build-release/driver-validation/sioctl
```

استخدم `--headers` إذا كان مجلد ترويسات MinGW-w64 في موضع غير افتراضي. ينشئ السكربت مكتبة استيراد MS COFF من اعتماديات ملف الكائن المترجم. يشغّل الفحص سيناريوهات buffered وin-direct وout-direct منفصلة عبر DriverEntry وcreate وIOCTL وcleanup وclose وunload. أضف `--debug` واختر مجلد مخرجات منفصلًا للترجمة مع `DBG=1` والتحقق من رسائل سجل الضيف. لا يسجّل المثال الأصلي معالج cleanup؛ لذلك يكمل المعالج الافتراضي في النموذج cleanup بالحالة `STATUS_INVALID_DEVICE_REQUEST` (`0xC0000010`). يستمر برنامج التشغيل في الإغلاق وإلغاء التحميل، ويعيد IOCTL الناجح البايتات المتوقعة. لهذا السيناريو الكامل، يكون رمز خروج CLI المتوقع **2** وتكون `scenario_success` بالقيمة false. ينجح السكربت نفسه فقط عندما تتطابق كل هذه النتائج، بما فيها فشل cleanup الظاهر؛ ولا يعيد كتابة المثال لإخفاء تلك النتيجة.

## التقارير وSDK

يميز تقرير JSON بين `stop_reason` و`nt_status` و`nt_success` القابلين للقيمة null، وبين PC عند التوقف وعدد التعليمات. ويحفظ استدعاءات API والحالة القابلة للمشاهدة التي جُمعت قبل التوقف، بما فيها كائنات الأجهزة وعناوين الاستدعاءات الراجعة لبرنامج التشغيل. تُمثّل عناوين الضيف بسلاسل سداسية عشرية حتى لا يفقد مستهلكو JSON دقة 64 بت. يسجّل الكائن `configuration` حدود التشغيل واسم الخدمة وتجاوزات `kernel_exports` وإدخال `registry`. اسم ملف التعريف هو `wdm-x64-scheduled-v57`. يظل `nt_status` نتيجة DriverEntry، بينما تصف `scenario_success` التهيئة والطلبات المكتملة معًا. تحدد `phase` و`requests` و`unload_completed` أي أجزاء دورة الحياة المطلوبة قد نُفّذت. يسجّل كل استدعاء API وكل عملية كتابة من المعالج مرحلتها أيضًا: `driver_entry` أو `add_device:<ID>` أو `request:N`, `callback:N` أو `unload`. ويعرض كل طلب حالتي الإرسال والإدخال/الإخراج والإكمال وطول المعلومات وبايتات `output_hex` المعادة. يصف `preferred_image_base` العنوان الأساسي الأصلي لـPE. أما `security_cookie` فهو عنوان الضيف لملف تعريف الارتباط المهيّأ، أو `"0x0"` إن لم تكن هناك حاجة إليه. حقول الطلب هي `kind` و`device` و`device_id` و`pnp` و`file`, `requestor_process_id` و`byte_offset` و`code` و`irp` و`completed` و`cancel_requested_at_100ns` و`dispatch_status` و`io_status` و`information` و`information_hex` و`output_hex`. يظل الحقل العددي `information` عدد JSON صحيحًا عشريًا دقيقًا؛ وتحفظ `information_hex` البتات نفسها أيضًا للعملاء الذين يقرؤون أعداد JSON بدقة لا تتجاوز 53 بت.

تستخدم ملاحظات عناصر العمل المرحلة `callback:N`. يحتفظ الطلب المعلّق بالقيمة `STATUS_PENDING` في `dispatch_status`؛ وتُسجّل حالة الإكمال النهائية منفصلة في `io_status` وتحدد مساهمته في `scenario_success`.

يمرر `ExRaiseStatus` البتات الدنيا الـ32 من NTSTATUS إلى معالج استثناءات الضيف؛ ويرفع `ExRaiseAccessViolation` و`ExRaiseDatatypeMisalignment` الاستثناءين `STATUS_ACCESS_VIOLATION` و`STATUS_DATATYPE_MISALIGNMENT`. يتبع الملف صفحات DDI الفردية لدى Microsoft: يسمح ExRaiseStatus بالمستوى `APC_LEVEL`، بينما تتطلب الدالتان بلا معاملات المستوى `PASSIVE_LEVEL`. تسمح بعض تعليقات SAL في WDK بمستوى APC_LEVEL لهاتين الدالتين؛ ويحتفظ هذا الملف بالقيد الموثق الأشد. يبقي الاستدعاء الذي يرفع استثناءً `result: null` ويسجل الرمز في `detail`؛ ولا يعرض عودة ناجحة مصطنعة من API.

يستخدم تسليم الاستثناءات جداول unwind المفككة لصورة x64 بالإصدار الأول ونطاقات `EXCEPTION_EXECUTE_HANDLER` الثابتة الخاصة بـ`__C_specific_handler`. ينفذ جسم معالج الضيف الفعلي، ويدعم فك إطارات الدوال المساعدة العادية، ويستعيد السجلات العامة غير المتطايرة المحفوظة، ويحافظ على حدود مكدس التنفيذ الحالي. يقرأ `GetExceptionCode()` الرمز المرفوع. يستطيع المعالج رفع استثناء آخر إلى نطاق محيط مدعوم. تفشل صراحةً دوال المرشحات و`__finally` وشخصيات GS/C++ والبيانات الوصفية المتسلسلة أو الناقصة وفك المقدمات واستعادة XMM عند مصادفتها. يتوقف استثناء API غير المعالج بالحالة `model_error`؛ وتظل أعطال CPU المتعلقة بالذاكرة أو المقاطعات أو التعليمات غير الصالحة نهائية.

يستخدم المثال الأصلي `driver_wdm_seh.c` رؤوس WDK أصلية والخيار `/GS-`. اضبط `NEVERD_WDM_SEH_FIXTURE` و`NEVERD_WDM_SEH_CFG_FIXTURE` للصورتين العادية وذات CFG النشط. يعيد المثال [driver-seh-scenario.json](../examples/driver-seh-scenario.json) تموضع الصورة، ويلتقط استثناء API داخل DriverEntry، ثم يفرغ برنامج التشغيل. يدعم مسار WDM المنفصل METHOD_NEITHER فحص ذاكرة المستخدم وقفل MDL ومعالجة أعطال الذاكرة ضمن السياق.

يحفظ الكائن `fault`، الذي يقبل null، أول عطل في الواجهة الخلفية. تميّز حقوله `kind` و`pc` والحقول القابلة للقيمة null، وهي `address` و`size` و`access` و`interrupt`، بين الذاكرة غير المعيّنة أو المحمية والنطاقات غير الصالحة والتعليمات غير الصالحة واستثناءات المعالج. تُستخدم سلاسل سداسية عشرية للعناوين وأعداد صحيحة للأحجام ومتجهات المقاطعة. لا يمكن لقراءات المشاهدة استبدال العطل الأصلي. لا يمكن للواجهة الخلفية المتعطلة استئناف التنفيذ، ولا يعني هذا السجل معالجة SEH داخل الضيف.

يعدّ `instructions` محاولات تنفيذ تعليمات الضيف التي سُمِح بها. لا تُحتسب التعليمة المرفوضة من سياسة التنفيذ؛ أما التعليمة المسموح بها التي تتعطل داخل المعالج فتُحتسب. لا تزيد عمليات إرسال API الاصطناعية أو علامة العودة هذا العداد.

يحمل كل عنصر `writes` القيمة `semantics: "attempted_guest_write"`: فهو يسجّل محاولة كتابة من المعالج خارج المكدس، بما فيها محاولة قد تتعطل لاحقًا أو تتوقف بسبب الميزانية. ولا يضمن اكتمال الكتابة، ولا يشمل الكتابات التي تنفذها نماذج API. تصف لقطات الأجهزة وكائن برنامج التشغيل الحالة المشاهدة عند توقف التنفيذ.

ضمّن `neverd/sdk/NeverDCAPIEmulation.h`، أو الترويسة الجامعة لـC API، وأنشئ جلسة ثم استدعِ `neverd_emulate_driver_json(session, path, options)`. يدخل المسار الصريح غير الفارغ مباشرةً إلى الفحص الصارم السابق للتنفيذ، دون التحميل أولًا عبر واجهة التحليل العامة. تستخدم CLI هذا المسار. يؤدي تمرير `NULL` للخيارات إلى اختيار القيم الافتراضية. تتطلب خيارات `neverd_driver_options_v1` الصريحة قيمة `struct_size` الدقيقة وميزانيات موجبة للتعليمات والذاكرة والأحداث والوقت. حرّر النتيجة باستخدام `neverd_free_string`.

أما تمرير `NULL` للمسار فيتطلب جلسة محمّلة، ويعيد تحليل ملفها بصورة مستقلة عن تحليل IR والتحميل المقيد بدوال محددة. يحافظ المساران على صورة الجلسة. أبقِ ملف الإدخال متاحًا ومن دون تغيير طوال مدة الاستدعاء. تعيد إخفاقات الطلب/الإعداد `NULL` وتضبط `neverd_last_error`؛ أما توقف التنفيذ فيعيد JSON. تظل الواجهة متاحة في البنى التي عُطّلت فيها الميزة، وتوضح طريقة تفعيلها.

تستخدم `neverd_emulate_driver_scenario_json(session, path, scenario_json, options)` خيارات v1 وقواعد الملكية نفسها، مع إضافة إدخال سيناريو صارم. تُطلب سلسلة JSON غير NULL ومنتهية بـNUL. يبقى ABI الأصلي لـ`neverd_emulate_driver_json` دون تغيير، ومقتصرًا على التهيئة. يوفّر محلّل C++ المسمى `driverOptionsFromScenarioJSON` التحقق نفسه من السيناريو لمستدعي `emulateDriver`.

نقطة الدخول الداخلية في C++ هي `neverd::emulation::emulateDriver` في `include/neverd/emulation/DriverSession.h`. تحليل الصيغ مسؤولية المحمّل الموجود؛ وسلوك كائنات/واجهات Windows مسؤولية `lib/emulation/windows`؛ وحالة المعالج وتنفيذه مسؤولية مهايئ Unicorn. يستخدم المهايئ والنموذج واجهة ذاكرة الضيف نفسها. لا ينتمي سلوك Windows API إلى تفريع Unicorn.

في مسار WDM `METHOD_NEITHER`، يشير `Type3InputBuffer` و`IRP.UserBuffer` إلى تخصيصين منفصلين للمستخدم. يفحص `ProbeForRead` النطاق والمحاذاة دون لمس الصفحات، بينما يلمس `ProbeForWrite` كل صفحة. يكشف `ExGetPreviousMode` نمط الطلب. يثبّت `MmProbeAndLockPages` صفحات تخصيص مستخدم واحد، ويتيح `MmGetSystemAddressForMdlSafe` تعيينًا مشتركًا، ثم يزيل `MmUnlockPages` القفل والتعيين. لا تزال سياقات العمليات العامة غير ممثلة.

يمكن لطلب WDM `METHOD_NEITHER` IOCTL ذي المخزن غير الفارغ تحديد `user_input_access` و`user_output_access` على نحو مستقل بالقيم `read_write` (افتراضي) أو `read_only` أو `no_access`. يُرفض هذان الحقلان للطرق المخزنة أو المباشرة والمخازن الفارغة؛ لا تعني `no_access` عنوانًا فارغًا بل صفحات يتعذر الوصول إليها.
يسجل `configuration.user_page_access` في التقرير إعدادات الوصول المحددة صراحة فقط، مع `source_request_index` يبدأ من الصفر؛ ويكون الاتجاه غير المحدد `read_write`.

## طلبات WDM المتزامنة المحدودة

يمكن لطلب WDM من نوع READ/WRITE/IOCTL أو لطلب في طابور KMDF افتراضي متوازٍ غير محدود تعيين `defer_callback_drain: true`. لا يُرسل الطلب التالي قبل تنفيذ الاستدعاءات الراجعة إلا إذا أعادت دالة الإرسال `STATUS_PENDING` وظل IRP معلّقًا. بعد الطلب التالي الذي لا يحدد هذا الحقل، تُنفَّذ الاستدعاءات الراجعة وتُستكمل المجموعة؛ وإذا حدده آخر طلب، يحدث ذلك في نهاية السيناريو. يمكن للطلبات المتداخلة استخدام كائنات ملفات مختلفة أو كائن ملف واحد فُتح صراحةً بنمط غير متزامن. لا يُدعم التداخل على ملف متزامن، ولا الاستباق العشوائي أو وصول الطلبات الخارجية.

## كائن الملف غير المتزامن

يمكن لطلب CREATE وحده تعيين القيمة المنطقية `asynchronous_file: true`؛ ويحافظ إغفالها أو ضبطها على false على الفتح المتزامن. يزيل الفتح غير المتزامن `FO_SYNCHRONOUS_IO` من `FILE_OBJECT` الخاص بالضيف، ولا يضع `IRP_SYNCHRONOUS_API` على طلبات IRP اللاحقة للملف. لا تتداخل طلبات READ/WRITE/IOCTL على الملف غير المتزامن نفسه إلا عند تأجيل معالجة الاستدعاءات الراجعة صراحةً. تنتظر CLEANUP/CLOSE اكتمال جميع عمليات النقل السابقة وإنهاءها. لا يُحتفظ بموضع ملف ضمني؛ وتظل `byte_offset` حقيقة مستقلة لكل طلب وقيمتها الافتراضية صفر. ترفض أنواع الطلبات غير CREATE هذا الحقل حتى عندما يكون false.
