# محركات إثبات bitvector

يستخدم NeverD محلل bitvector المضمّن افتراضياً؛ واشتقاق MBA الدقيق مستقل عن المحللات العامة. لا يقبل توليف التعابير مرشحاً إلا بعد إثبات التكافؤ. المثال المضاد أو الاستعلام غير الحاسم يبقي التعبير الأصلي.

تزيل دارة الضرب المدمجة البتات الدنيا المعروفة بأنها صفر من العاملين، ثم تبني حاصل الضرب المتبقي وتستعيد كلمة الخرج كاملة. ويشفّر محوّل Z3 الاختياري أيضًا حاصل الضرب ذي المعامل الثابت الزوجي بالعرض الدقيق الذي يؤثر في النتيجة. تحتفظ الطريقتان باستعلامات المساواة بكامل العرض، ونماذج المدخلات المستقلة، وحدود الموارد الحالية. يشترك تحسين المصدر في CLI وGUI في الدارة المدمجة دون مفتاح إضافي.

## دوائر المقارنة المدمجة

تقارن المقارنات الأعرض من ثمانية بتات النصفين العلويين أولاً، وتستخدم النصفين السفليين عند تساوي العلويين. تستخدم الأجزاء الصغيرة بتات الحمل في الطرح. يستطيع المُرمّز المشترك إعادة استخدام بوابات الجزء العلوي عندما يغيّر تحديث جزئي للسجل البتات الدنيا فقط. تظل المقارنات ذات الإشارة تعكس بتي الإشارة. لا تتغير دلالات التعبيرات ولا حدود الموارد الحالية؛ ويظل نفاد الميزانية يعيد `Unknown`.

يقارن `BitBlaster.WidePredicatesAgreeWithTheEvaluator` شروط المقارنة ذات الإشارة وبدونها مع مقيّم التعبيرات عند عروض مختارة من 8 إلى 256 بتاً، بما فيها العروض الفردية والقيم المجاورة للحدود والبتات المؤثرة فوق 64 بتاً. كما يستبعد قيم المخرجات الخاطئة. تتحقق اختبارات العدادات الجزئية من الاستعلامات الكاملة ونماذج الأمثلة المضادة ونفاد ميزانية البوابات. تثبت اختبارات الانحدار الأصلية التي تحتفظ بنتيجة المقارنة ترتيبي المقارنة والتحديث مع مراقبة جميع السجلات والأعلام، وترفض جسم الحلقة الأصلي إذا عُدّل.

## نسخ الترميز قبل البحث

تنسخ `BitVectorSolver::cloneEncoding()` ترميزًا كاملًا قبل أي محاولة بحث SAT. وتعيد null بعد البحث أو فشل الترميز. تملك كل نسخة بنودها القابلة للتعديل ونشر القيم عند الجذر والبوابات وتعيينات البتات بشكل مستقل، مع الحفاظ على ترتيب المتغيرات وحساب البوابات وإعدادات المحلّل. يجب أن يبقى السياق موجودًا طوال عمر المحلّلين، بينما يمكن تعديل المحلّل الأصلي أو حذفه بصورة مستقلة.

يحتفظ محرك SAT بأربعة عناصر مراقبة داخل كل قائمة لمتغيّر منطقي موجب أو منفي، وتنمو القوائم الأطول ديناميكيًا. يقلل ذلك التخصيصات المنفصلة للقوائم القصيرة أثناء الإنشاء والنسخ قبل البحث والإتلاف. لا يتغير ترتيب الانتشار أو محتوى العبارات أو الملكية المستقلة أو حدود العمل.

## براهين مكتملة ضمن سياق واحد

يربط مدقق الاستقلال الأصلي ذاكرة تخزين المجالات المحدودة بالسياق الرمزي الفعلي الذي تضاف إليه العقد فقط. تحتفظ المفاتيح الموجزة بالشرط الدقيق والإسقاطات المرتبة وحد القيم. لا يعاد استخدام إلا المجالات الرقمية المكتملة أو عدم التفرد المثبت؛ وكل إخفاق في العثور على نتيجة يتطلب التعداد الكامل وبرهان الاستبعاد النهائي. يجب أن يبقى السياق ومعنى العقد الموجودة ثابتين طوال عمر الذاكرة. لا تنتقل الرموز المعدة بين المالكين ولا يعاد استخدامها مع مالك بديل في العنوان نفسه. يبقى حد التخزين الحالي بالكلمات كما هو. يحتفظ المستخدمون الآخرون بالمفاتيح البنيوية وإعادة الاستخدام مع تغيير أسماء المتغيرات.

## بناء Z3 الاختياري

عند التفعيل، ينزّل CMake عبر `FetchContent` مراجعة Z3 المثبتة 4.13.3 ويبني مكتبة static مع NeverD، ولا يلزم تثبيت Z3 على النظام:

```sh
cmake -S . -B build-release -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON \
  -DNEVERD_ENABLE_Z3=ON -DNEVERD_BUILD_SOLVER_BENCH=ON
python scripts/build.py build-release --parallel 4 --target neverd \
  NeverDSolverTests NeverDSymbolicTests neverd-solver-bench
```

الموفر الافتراضي `NEVERD_Z3_PROVIDER=FETCH`. ينزّل التهيئة الأولى المصدر وتعيد البنايات اللاحقة استخدامه في `_deps`. لا تُبنى أداة Z3 أو اختباراتها وأمثلتها ووثائقها وروابط لغاتها؛ وتستخدم مولداته المصدرية Python الموجود لدى NeverD. لتثبيت مكتبة اختر `-DNEVERD_Z3_PROVIDER=SYSTEM` ويمكن تحديد `-DZ3_ROOT=/path/to/prefix`؛ يفشل هذا الوضع عند غياب ملفات التطوير ولا يبدّل الموفر بصمت. للبناء دون اتصال يمكن تمرير مصدر محلي عبر `-DFETCHCONTENT_SOURCE_DIR_NEVERD_Z3=/path/to/z3`.

عند `NEVERD_ENABLE_Z3=OFF` (الافتراضي)، لا ينزّل NeverD Z3 ولا يبحث عنه ولا يربطه. طلب backend غير متاح وقت التشغيل يفشل بلا fallback.

## توليف التعابير المشروط بالإثبات

```sh
build-release/bin/neverd simplify --synthesize --solver=z3 \
  --solver-timeout-ms=1000 --json '(x >> 4) + ((x >> 2) >> 2)'
```

`--solver=builtin` هو الافتراضي. اختيار المحلل يتطلب `--synthesize`؛ مبسّط MBA العادي لا يستدعي Z3. يطبق timeout على كل فحص دون ترجمة التعبير، والإلغاء تعاوني لا يمثل مهلة حائطية صارمة. الصفر يستخدم 1000 ms افتراضياً و`--exhaustive` يزيل الحد. حدود التعارض والنشر وزيارات watch تخص backend المضمّن وترفض مع Z3. فحوص Z3 تزيد عداد استعلامات الإثبات؛ وتظل عدادات عمل SAT المضمّن صفراً.

تضيف C API الحقلين `solver_backend` و`solver_timeout_ms` إلى `neverd_synthesize_options`. تحافظ القراءات المحدودة بالحجم على backend المضمّن للمتصلين القدامى. تعرض `neverd_solver_backend_available()` قدرة البناء، وتوفر Python الاختيار نفسه عبر `synthesize_expression(..., solver='z3', solver_timeout_ms=1000)`. ينطبق الاختيار حالياً على توليف التعابير فقط؛ وتبقى سياسات التنفيذ المختلط وتحليل السلامة وتحسين IR كما هي. يمكن للمستخدم الداخلي تمرير متحقق Z3 عبر callback الإثبات للمبسّط الدلالي.

```python
from neverd_plugin import synthesize_expression

result = synthesize_expression(
    '(x >> 4) + ((x >> 2) >> 2)', solver='z3', solver_timeout_ms=1000
)
```

## فحوص مستقلة وتصدير الاستعلامات

عند تفعيل Z3، يحتوي `NeverDSolverTests` تقييماً مستقلاً للتعابير ومقارنة بين المحللين؛ تُبنى التعابير المرجعية مباشرة حتى لا يبسّط خطأ في منشئات NeverD طرفي الاختبار معاً. عند التعطيل تُتخطى حالات oracle صراحةً مع بقاء فحص عقد backend غير المتاح.

تقارن اختبارات حاصل الضرب المضروب بمعامل الدارة المدمجة مع ضرب مطوّل مستقل وحساب صحيح حتى 257 بت. تثبت اختبارات Z3 التطابق مع ترميز مستقل بكامل العرض، وتتحقق من بتات المدخلات العليا ومن أعلى بت للخرج بعد تغييره عمدًا إلى قيمة خاطئة.

```sh
build-release/bin/NeverDSolverTests --gtest_brief=1
build-release/bin/neverd-solver-bench \
  tools/neverd-bench/solver-corpus.txt --width=32 --repeat=5 \
  --backend=both --timeout-ms=1000 --max-conflicts=10000 \
  --dump-dir=/tmp/neverd-queries > /tmp/neverd-solver-results.json
```

كل سطر غير تعليق في corpus هو `original ; candidate`؛ وإذا غاب الفاصل يستخدم المرشح نتيجة مبسّط MBA. يسجل البرنامج الأحكام وإعادة تشغيل النموذج والتوقيت، شاملاً إنشاء الجلسة والترجمة والحل ومستثنياً التحليل والتبسيط والتصدير والتنظيف. لكل تكرار محلل جديد. يجب أن يعيد SAT model إنتاج الفرق في evaluator؛ الأحكام الحاسمة المتعارضة والاستعلامات أو النماذج غير الصالحة تفشل، أما `unknown` فيسجل ولا يعد إثبات تكافؤ.

يتضمن SMT-LIB المصدّر DAG المكافئ بعد الترميز والتأكيدات الدائمة وافتراضات الاستعلام الأخير، ويمكن تشغيله بـ`z3 query-N.smt2`. سجّل حدود الموارد وإصدار المحلل؛ وحدات ميزانية backendين مختلفة، لذا المقارنة ضمن أحمال محدودة وليست عملاً متطابقاً. تستخدم براهين bitvector دلالات اللغة الكلية ذات العرض الثابت؛ تظل استثناءات الآلة وآثار الذاكرة وLLVM poison مسؤولية حدود الرفع والترجمة ولا يثبتها برهان التعبير.

تزيل نسخة الترميز التي لم يبدأ البحث فيها المتغيرات المسندة عند الجذر من طابور قراراتها، وتعيد بناء الترتيب الصارم للكومة بحسب النشاط ثم الفهرس. تبقى الإسنادات والعبارات كما هي، وتظل حقائق الجذر صحيحة خلال كل تراجع. لا تتغير ملكية المصدر أو القرارات الفعلية أو النماذج الكاملة أو أي من حدود البحث.

يمثل DAG المصدّر بصيغة SMT-LIB ترميزًا مكافئًا دلاليًا، وقد يتضمن خارج القسمة الدقيق الموضح أعلاه؛ وقد تختلف بنيته عن DAG الأصلي.
