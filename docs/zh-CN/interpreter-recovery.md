# 解释器源码恢复

实验性的解释器特化阶段会从已链接的 x64 函数中消除能够静态解析的派发，同时保留运行时输入、内存效果、分支和循环。它依据指令语义工作，不依赖 handler 特征或某一种保护器的操作码表。

```sh
neverd decompile program --func vm_entry --devirtualize \
  --recovery-report recovery.json -o recovered.c
neverd decompile program --func vm_entry --devirtualize \
  --llvm -o recovered-llvm.c
```

`--vm-control` 选择用于区分解释器上下文的完整通用寄存器。该选项可重复使用，但不会提供任何具体值。例如，可以选择由入口代码初始化的字节码游标。用作计数器的运行时输入必须保持动态。如果不同游标值在汇合时缺少必要的上下文区分，恢复可能停止；引擎不得通过猜测派发目标来弥补。若游标被溢出到栈中，`--vm-control-stack=-16:8` 可选择入口 RSP 减去 16 处的八个字节。此偏移相对于函数入口，而不是调整后的当前栈指针。

C API 为 `neverd/sdk/NeverDCAPIDevirtualize.h` 中的 `neverd_devirtualize_source_v1()`。它使用独立事务，不修改会话的普通反编译缓存。失败时不返回源码，但仍可返回 JSON 诊断。两个返回字符串均使用 `neverd_free_string()` 释放。

## 自动发现控制状态

CLI 和各版本源码恢复 C API 默认启用自动发现。与二进制提供方无关的 C++ 接口默认 `SpecializationOptions::DiscoverControlState = false`，调用方可显式设为 `true`。手工 `--vm-control` 和 `--vm-control-stack` 提示仍是可选的上下文键；普通自动发现的字段只保留有界的联合有限取值关系，不增加上下文键，也不把运行时输入绑定为采样值。除非下述选择性内存细化需要其已证明常量，普通计数器仍保持动态。

发现过程沿未解析控制流与地址的依赖，追踪结构化的节点入口寄存器输入和内存输入首次产生时的来源，包括窄字节范围。只有该来源指明节点入口时尚未改写的内存，并对应精确的入口栈帧相对范围，才会提名栈帧字段。后来读取到相同值或经存储转发的值，不会产生额外的输入依赖；内存事实失效后新产生的未知字节也不会被视为入口栈槽。历史读取记录仍保留供其他分析使用。发现缺失依赖后，会从函数入口重新分析。每个保留的关系仍须对其约束的位获得完整的有限取值证明，可能形成别名的写入仍使内存事实失效。自动发现不会把任意外部内存或无界的相关值变成有限域。

生产者需求跨节点边界保留位掩码，不会将其扩大到整个字节；对算术运算仍保守纳入可能向所需位进位或借位的低位前缀。

若已跟踪的内存依赖仍反复阻止精确地址证明，后续细化可以将其已证明的传入常量提升为上下文键。目前不会把多值元组拆成新边，也不会为选择上下文增加客户内存读取：有限取值证明本身不能证明新增读取安全。因此，动态或无界的内存相关状态仍可能在配置的限制内导致恢复停止。

反向生产者需求由原生节点入口、指令模式、字段种类及字节范围标识。只有后继节点需要该字段的边才继续展开生产者依赖，包括取值有限但精度仍不足的情况。这可能触发有预算限制的入口重启，而不会把复用的物理寄存器视为始终承担同一角色。依赖发现有界且不完备，不能保证所有解释器都可在没有手动提示时恢复。

普通自动字段的投影也按目标节点的需求限定范围。只有目标节点需要某个非常量字段时，边的联合有限取值关系才包含该字段。手工字段和自动提升为上下文键的字段仍参与全局投影。已知常量字节、相对于入口栈帧的精确指针及来源事实不受需求筛选影响，仍予保留。这样可以避免不同处理阶段的无关字段使关系中的取值组合相乘。配置的预算，以及控制目标、内存地址和返回状态所需的证明要求均不改变。

对于普通自动字段，每个元组列只约束所需的位，并携带对应的掩码。汇合时只保留所有传入路径都约束的位。同一字节内的其他位仍保留运行时值：字段的存储范围并不证明整个范围具有完整的有限域。只有全部八个位均已证明恒定，字节才能成为常量。

手工字段和提升为上下文键的字段仍会在全局先尝试全宽关系。若该证明没有结论，可以改为保留所需位的关系；这不会向上下文键提供未经证明的字节，也不会绕过已耗尽的全局预算。

从全新图重启时，完全包含于其他字段内的普通自动存储范围可以共用这些较宽字段。原始阶段位置及位需求保持不变。手工字段、上下文字段，以及由未解析内存地址直接提名的字段保留精确范围。`MaxControlFields` 限制这种规范化后实际保留的字段数。`DiscoveredControlFields` 仍为累计值，可以超过活跃字段数；字段上限和全局工作预算均未提高。

普通自动字段获得完整的有限域证明后，不会立即将其所有生产者都加入控制字段。发现过程会记录这些候选依赖，只有恢复仍受阻且即时细化没有产生候选项时才启用它们。提升为上下文键的字段仍会立即展开其生产者。发现访问、重启和证明工作继续使用原有的累计预算。

即使整个字的值仍在变化，完整有限域也可以证明其中个别字节恒定。例如，取值域 `{0, 0x100}` 的低字节恒为零。只有在每个已枚举元组中都相同的字节才会按目标字节序保留为常量，其余字节仍保持动态。不完整枚举、求解器返回未知或证明预算耗尽都不会提供此类事实。

有限域证明可以在一次恢复运行内复用，包括细化重启。有界缓存比较完整的有序表达式 DAG，允许自由变量一致重命名；变量共享关系、位宽、常量位、操作符参数和投影上限仍属于键。只缓存完整的取值域，以及取值域超过上限的证明。未知或部分结果不缓存；未命中或容量不足时采用普通证明路径。所有全局预算继续生效，`solverQueries` 统计实际求解器调用。

在同一谓词下，若已证明可达性，一个变化列的完整取值域与其他各列已证明的唯一值便可确定精确联合关系。多个变化列仍须联合证明。只有证明掩码列的输入位独立于谓词及其他所有列，才可以省略覆盖自身全部位取值域的该列。共享输入、未知结果和不完整枚举都不能作为假定笛卡尔积的依据。

默认 `MaxControlFields = 16` 同时约束手工和自动字段；`MaxControlRefinements = 16`，`MaxDiscoveryVisits = 65536`。各次重启共享全局节点（包括合成节点）、操作、求值、求解查询和发现访问预算。报告中的 `contexts` 统计原生上下文；它与 `evaluatedOperations`、`nodeEvaluations`、`solverQueries` 都跨尝试累计。每个地址的上下文数、活动原生返回槽、控制字段数及元组数仍是单次尝试的结构上限。求解查询默认上限仍为 4096。预算耗尽不发布部分结果；`residualBlocks` 只描述最终残余图。

CLI 选项 `--vm-max-refinements=N` 要求正整数，默认值为 16。C 调用方可通过 `neverd_devirtualize_source_v2()` 或 `neverd_devirtualize_machine_source_v2()` 配置相同上限：将 `neverd_devirtualize_options_v2` 清零初始化，设置 `base.struct_size = sizeof(neverd_devirtualize_options_v2)`，再设置 `max_control_refinements`（零表示保留默认值 16）。内嵌的 `base` 保存 v1 选项，两个 reserved 成员都必须为零。既有 v1 布局和入口保持不变，并忽略扩展尾部。其他工作和证明预算仍然生效。

JSON 报告新增 `discoverControlState`、`maxControlRefinements`、`maxDiscoveryVisits`、`discoveredControlFields`、`discoveredContextFields`、`controlRefinements` 和 `discoveryVisits`，分别记录启用行为、上限和分析工作量。发现字段本身不等于恢复成功。

## 执行契约

二进制适配器目前接受位于其映射地址的已链接 x64 ELF 和 PE 映像。映射、字节和权限必须保持固定，且不得并发修改。严格的按需提升会沿可达机器码进行；遇到不支持的指令、调用、不透明操作、带内存序要求的访问、未解析控制流或语言级异常处理时，恢复会停止。

PE 恢复要求完整的映像元数据，包括全映像重定位和异常记录。CLI 会先加载这些元数据，再应用 `--func`；C API 调用方不得事先用 `neverd_session_restrict_function()` 限制会话。二进制适配器拒绝按受限函数集合加载的映像，因为省略的元数据不能证明不存在修正项或异常边。

只有完整的、由文件提供内容的只读范围，且不存在重叠映射或加载器修正，才能提供映像读取常量。可写表、未解析的重定位和运行时采样快照都不能作为不可变读取的证据。COPY 重定位和结构不完整的异常目录会被拒绝。若 PE 异常目录及函数范围完整，其他函数中未能解析的处理器不会阻止当前入口分析；恢复一旦到达该处理器覆盖的代码，仍会拒绝。

源码恢复域要求普通 ABI 返回：每次外部来源存储的目标范围都必须与入口返回地址槽不相交。这是调用方／环境必须满足的显式前提，也包括由外部整数计算出的地址；缺少栈帧来源信息并不能证明数值地址不相交。由栈帧派生的存储地址必须证明与该槽不相交，返回时还必须恢复原始栈指针。来源信息会跨越溢出存储和控制流汇合保留；丢失仿射表达式不会使地址变成外部指针。目前拒绝栈切换、被调用方额外弹栈返回和基于 RET 的派发。二进制适配器强制使用 x64 小端语义。

此流程生成供分析使用的源码和 IR，不证明重定位、栈展开、异步异常或二进制替换的安全性。patch 模式拒绝该选项，也不宣称支持所有解释器或保护配置。

精确形状的 x64 `PUSHFQ`／`POPFQ` 会保留在残余程序中。分析将每次机器标志位快照视为未知运行时值；提升器另行合并已建模的算术标志位。恢复标志位仍是运行时效果。由未知标志位派生的地址不能借用外部指针与返回地址槽不相交的契约；若其派发目标无界，恢复仍会失败。

在保存完整标志位映像之前，每个已建模的算术标志位和方向标志位都必须已在恢复的函数内部得到定义。直接读取标志位也要求它在所有可达的前驱路径上已定义，即使符号化简能抵消其值；否则恢复会拒绝，而不会输出带有“未知寄存器”陷阱的 C 源码。

LowIR 临时值只在单条已提升的原生指令内有效。读取的每个字节都必须在该指令中先被定义；沿用上一条指令的偏移，或用代数化简抵消未定义值，都不能作为源码正确性的证据。入口常量只能绑定物理寄存器。

## 当前限制

只有在配置的限制内能够证明所需的有限取值域及其关联时，才能处理依赖输入的字节码地址和解码器状态关系。这不代表支持任意间接解码方案。证明所有派发目标后可以恢复动态分支和循环；普通分支的测试覆盖并不能证明支持所有此类方案。未解析控制流和必要证明预算耗尽都表示失败，不发布恢复源码或部分替代代码。原生辅助函数调用、异常／重入边界、可变代码及其他架构仍不属于此适配器的执行契约。

## 共享实现

`SpecializationProvider` 提供完整提升后的指令和不可变读取证据。`NeverDInterpreterSpecialization` 复用现有 `SymExec` 语义，对整数及控制操作进行部分求值。二进制适配器负责映射和指令解码，不实现第二套指令求值器。

对于有限的符号读取地址，内置位向量求解器在当前约束下枚举候选地址。只有最后的 UNSAT 结果证明不存在其他地址，且每个地址都具备完整的不可变、不会触发内存故障的读取证书，才接受该集合。这类已证明的 LOAD 可以在 LowIR 中替换为地址快照和精确的 SELECT 链；未经证明的普通读取仍保持动态。单次采样地址绝不能替代完整集合。选定控制寄存器和入口栈帧槽之间的有界联合元组可以跨节点保留，从而维持游标与解码 key 等关系。汇合与拓宽仍采用保守规则。部分 SAT 样本或未知求解结果，都不能证明地址或目标集合完整。此机制不依赖可选的 Z3 后端。

节点由原生指令游标、指令模式，以及选定控制寄存器和入口栈帧槽中的常量共同标识。其余字节级事实通过交集汇合。传入事实变弱时，会重新求值该节点。因此，程序本身的循环仍保持为循环，不会逐次展开每次观察到的迭代。间接目标的所有可达值必须属于有界且已穷尽证明的集合；解析出的目标会变成残余代码中的显式比较和 CFG 边。

动态操作和普通 load/store 保留在 LowIR 中。标量常量、相对于入口栈帧的仿射指针，以及已证明为常量的栈帧字节可以跨节点传递；其他表达式会被舍弃，而不是无限展开。栈帧内存沿用符号状态已有的保守别名失效规则。通过未知且可能形成别名的指针写入时，会使冲突事实失效。这既不假设栈槽私有，也不会根据未经证明的无别名契约将其消除。

唯一的合成指令标签用于区分克隆的上下文。原始指令边界保留在独立的来源映射中；原始重定位、异常和跳转表证书不会复制到新指令实例上。恢复后的 LowIR 在 HighC/LLVM 路径分流前进入普通 LowIR-to-MedIR 转换，共享寄存器、栈、CFG、SSA 和 ABI 处理。HighC 路径的恢复同样要求 MedIR 验证通过。

节点数、每个地址的上下文数、操作数、节点求值次数和有限目标数的预算共同约束分析。预算耗尽或语义不受支持时，不发布残余函数。控制流图完整与源码成功生成是不同条件；公开 API 会检查两者并分别报告。

有限读取地址集合、联合控制元组和控制字段数量也有显式上限。全局求解查询次数，以及每次查询的门、冲突、传播和监视文字访问次数限制，约束证明工作量；符号节点上限约束表达式增长。JSON 报告包含这些预算，以及 `solverQueries` 和 `relationalWidenings` 计数。

## 证据与测试

可选的本地 JSON 报告包含输入摘要、选定的控制项、预算、状态、工作量计数、残余块数、原始指令位置，以及恢复时使用的不可变字节。报告包含输入派生信息，只会写入指定的本地路径。

公开测试使用原创的寄存器线程化派发和栈派发机器，各自包含算术、分支／汇合与运行时循环程序。独立的无符号运算参考实现检查返回值、内存写入、进位／借位结果和输出哨兵。恢复得到的 HighC 和 LLVMC 在 O0/O2 下开启未定义行为陷阱编译，再与该参考实现对照执行。负例覆盖未解析派发、可写派发表、不兼容字节序、异常元数据和预算限制。

新增的原创有限地址 fixture 使用由输入选择的只读记录、相关的游标／key 控制字段，以及在不同虚拟位置复用的同一 handler。它们覆盖分支／汇合，以及记录选择随程序运行状态变化的循环。独立的原生参考实现使用 SysV 和 Win64 两种调用约定；恢复后的两条 C 路径均在 O0/O2 下结合未定义行为陷阱和输出哨兵检查。读取证书不完整或证明预算不足时，不得发布部分结果。

专项测试目标见 [testing.md](testing.md)。

## 显式机器状态恢复

使用 `--devirtualize --vm-machine-state` 或 `neverd_devirtualize_machine_source_v1()` 可选择独立的机器状态源码 ABI。参数指向 17 个对齐的 `uint64_t`：RAX、RCX、RDX、RBX、RSP、RBP、RSI、RDI、R8 至 R15，最后是 RFLAGS。返回 64 位无符号状态；只有零表示成功。非零状态表示旗标配置不符合约束，不回滚内存写入。输出状态位于最终 RET 弹出返回地址之前。状态缓冲区不得与客户内存重叠，地址沿用原映射，宿主须为 64 位小端。

此模式明确限定 CPL3/IOPL0、影子栈关闭、无异步事件且正常不发生故障的执行。入口旗标须为规范值，TF/RF/VM/AC/VIF/VIP 清零；POPFQ 输入的 TF/AC 也须清零，源码会检查。PUSHFQ/POPFQ 使用显式状态；关闭影子栈时 RDSSP 保持目标寄存器，仍拒绝实际到达的 INCSSP。内部直接近调用保留真实压栈；内部近返回必须证明唯一目标。完整的栈指针溢出保存可以传播，部分写入或可能别名写入会使事实失效。此模式可经过带异常元数据的代码，但不证明异常分派或展开等价。报告记录 `sourceABI` 和 `executionProfile`。前文默认 ABI 的严格拒绝规则保持不变。

默认普通源码 ABI 会重建本次调用私有的栈帧：所有外部来源的 LOAD/STORE 范围（包括计算得到的地址）必须与原生私有帧及其重建后的源码存储分离，这是明确的环境前提。共享证明拒绝帧地址逃逸、依赖帧地址的标量结果或分支，以及读取尚未完整初始化的私有字节。显式机器状态 ABI 保留原客户地址，不采用此私有帧前提。

若未定义旗标会影响控制流、地址或其他已定义输出，还需要独立证明这些观察不受它影响。当前恢复报告不提供该证明，也不认证这种依赖处理器的行为。
