# iOS 네이티브 코드와 소스 복원

[← 문서 색인](README.md) · [모바일 개요](../mobile.md)

`neverd mobile`은 IPA, `.app`, Mach-O를 받아 네이티브 C, 런타임 메타데이터와 지원되는 네이티브 본문에서 실험적으로 복원한 Objective-C `.m`, Swift `.swift`를 출력합니다. 게시된 결과에도 복원하지 못한 메서드가 포함될 수 있으므로 사용 전에 범위 보고서를 확인하세요. 모바일 컨테이너는 CLI 기능이며 네이티브 C SDK는 선택한 Mach-O를 별도로 로드합니다.

컴파일 과정에서 주석, 서식, 식별자와 소스 언어 구조가 사라집니다. 이 작업은 소스 표현을 재구성하며 원문을 되찾거나 임의 애플리케이션의 동작 동등성을 인증하지 않습니다. 분석 대상 애플리케이션을 실행하지도 않습니다.

## 시작과 의존성

```sh
cmake --build build --target neverd
neverd mobile App.ipa -o recovered-ios
neverd mobile App.app -o recovered-arm64 --arch=arm64
neverd mobile executable -o metadata --metadata-only
neverd mobile App.app -o recovered-framework --artifact Frameworks/Example.framework/Example
```

C++20을 지원하는 도구 체인으로 `neverd` 대상을 빌드합니다. 모바일 작업 흐름은 네이티브 CLI 안에서 실행되며 Python 인터프리터가 필요하지 않습니다. Swift 서명 디맹글링은 NeverD LLVM fork의 `LLVMSwiftDemangle`이 제공합니다. fork의 소스 빌드와 호환되는 배포 LLVM 패키지 모두 이 구성 요소를 포함하므로 NeverD는 Swift 소스를 별도 의존성으로 가져오지 않습니다. NeverD를 빌드하거나 실행하는 데 Swift 컴파일러나 도구 체인을 설치할 필요는 없습니다. LLVM, Capstone 등의 네이티브 라이브러리 의존성은 유지되며, 배포 시 빌드에 필요한 라이브러리와 라이선스 고지를 포함해야 합니다. macOS에서 생성된 Apple 언어 소스를 독립적으로 컴파일하거나 Swift 동작 회귀 테스트를 실행할 때는 용도에 맞게 Apple Clang, SDK, `swiftc`가 필요합니다.

Swift 서명 복원은 C++ 프로세스 안에서 `LLVMSwiftDemangle`의 구조화된 노드를 직접 사용합니다. 외부 디맹글링 실행 파일을 찾거나 시작하지 않으며 도구 체인 탐색 명령도 실행하지 않습니다. 기존 실행 파일 경로 옵션은 제거되었고 기존 디맹글러 환경 변수도 읽지 않습니다. `--metadata-only`는 네이티브 소스 내보내기나 서명 디맹글링을 실행하지 않습니다.

`metadata/swift-signatures.json`의 서명 목록은 내장 구성 요소를 다음과 같이 기록합니다.

```json
{
  "demangler": {
    "name": "llvm-swift-demangle",
    "execution": "builtin",
    "version": "6.3.3"
  }
}
```

```sh
neverd mobile App.ipa -o recovered-swift --timeout=600 --json
```

## 입력과 선택

IPA에는 최상위 `Payload/*.app`이 정확히 하나 있어야 합니다. IPA와 `.app`의 주 실행 파일은 `Info.plist`의 `CFBundleExecutable`로 결정합니다. 두 형식 모두 `--artifact`는 해당 앱 번들 기준 상대 경로이며 내장 실행 파일 하나만 선택합니다. 모든 프레임워크나 확장을 재귀 분석하는 옵션은 아닙니다. 원시 Mach-O 입력은 `--artifact`를 허용하지 않습니다.

Fat 바이너리에서 `--arch=auto`는 arm64, arm, x86_64, i386 순으로 우선합니다. 없거나 지원하지 않는 슬라이스는 명시적으로 실패합니다. 현재 소스 언어 출력은 arm64/x86_64를 대상으로 하므로 다른 계열 선택이 Objective-C/Swift 지원을 뜻하지 않습니다. 선택한 슬라이스가 `cryptid != 0`이면 거부합니다. 이미 복호화되어 읽을 수 있는 입력을 제공하세요. 아카이브와 디렉터리 입력은 위험한 경로, 심볼릭 링크, 특수 파일, 충돌 항목을 거부합니다.

## 옵션과 자원 제한

| 옵션 | 기본값 | 의미 |
|------|--------|------|
| `-o DIRECTORY` | 필수 | 입력 디렉터리 바깥의 새 출력 디렉터리. 기존 출력은 보존 |
| `--platform=auto\|ios` | `auto` | 플랫폼 추론 또는 iOS 선택 |
| `--arch=auto\|arm64\|arm\|x86_64\|i386` | `auto` | Mach-O 슬라이스 하나 선택 |
| `--artifact PATH` | 주 실행 파일 | 앱 기준 실행 파일 상대 경로 |
| `--metadata-only` | 꺼짐 | 소스 복원이나 도구 호출 없이 메타데이터 읽기 |
| `--max-func N` | `0` | 네이티브 함수 제한. 0은 발견한 모든 함수이며 메타데이터 모드에서는 무시 |
| `--timeout N` | `300` | 전체 분석의 양수 시간 예산(초). 자식 프로세스는 남은 예산 사용 |
| `--max-files N` | `20000` | 양의 항목 예산. Swift 심볼 목록도 제한 대상 |
| `--max-bytes N` | `2147483648` | 입력, 압축 해제 데이터, 최종 출력의 양의 바이트 예산 |
| `--json` | 꺼짐 | 버전이 있는 보고서를 JSON으로 출력 |

작업 영역을 감시하며 임시 입력과 중간 출력에 설정한 항목/바이트 예산의 최대 3배를 허용합니다. 로그는 프로세스마다 16 MiB, Swift 서명 JSON은 추가로 32 MiB까지입니다. 이는 자원 제어이며 프로세스 격리가 아닙니다. 시간 제한을 늘려도 다른 제한은 유지됩니다. `--max-func`로 제외되었어도 메타데이터 목록에 있는 메서드는 미복원 항목으로 남습니다.

## Objective-C 소스와 런타임 구조

두 소스 보고 모드 모두 `source_projection_graph`를 포함합니다. 노드는 최종 타입 지정 네이티브 본문, 로컬 진단, 병합된 native/Block `dependencies`, 실제 `closure_closed` 결과를 보여 줍니다. 로컬 검사와 전파된 의존성 실패는 서로 다른 이유를 가지며, 타입 지정 본문이 없으면 진단도 불완전합니다. 미바인딩 호출을 해결하면 새 의존성이 나타날 수 있습니다. 닫힌 노드는 의존성 단계만 통과한 것이며 `recovered`가 되려면 생성과 소스 텍스트 검사도 통과해야 합니다. `native_dependency_graph`는 별도의 LowIR 호출 목록입니다.

반복적인 범위 분석에는 다음 명령이 `--format=objc-methods`와 같은 분석 및 게시 검사를 실행하면서 `native_source`와 각 메서드의 `source`를 생략합니다. JSON은 `sources_omitted=true`를 추가하며 메서드 식별자, 상태, 진단, 시그니처, 공유 도우미 참조와 의존성 증거의 의미를 그대로 유지합니다. 렌더링 검사도 계속 실행되고, 전체 모드는 컴파일 가능한 소스를 만듭니다. 대응 C 진입점은 `neverd_objc_methods_summary_json(session, max_functions)`이며 결과는 `neverd_free_string`으로 해제합니다.

```sh
neverd export WMF --format=objc-methods-summary -o summary.json
```

네이티브 로더는 런타임 메서드 기록, 실행 가능한 IMP 주소, 지원되는 타입 인코딩을 명시적인 소스 ABI 위치에 연결합니다. 고정 스칼라/포인터 바인딩은 숨겨진 `self`/`_cmd`, 사용하지 않는 인자, 독립적인 정수/부동소수점 레지스터 뱅크와 지원되는 스택 위치를 유지합니다. float/double 비트 재해석과 수치 변환은 구분합니다. 타입 힌트는 소스 출력 입력일 뿐 인증된 ABI 증거나 실행 코드 패치 권한이 아닙니다.

`sources/objc.m`은 실제 복원한 문장을 `@implementation` 본문에 넣고 필요한 C 도우미와 타입이 연결된 호출을 보존합니다. 호출 대상에는 지원되는 소스 바인딩이 필요하며 알 수 없는 대상과 불완전한 의존성 그룹은 미복원입니다. 정의 누락, 실행 불가능한 주소, 충돌 인코딩, 미지원 ABI, 불완전한 디코딩, 거부된 IR은 선언이 있다는 이유만으로 복원 완료가 되지 않습니다.

네이티브 보조 함수의 전체 입력 값이 COPY/PHI를 통해 기존 소스 바인딩의 포인터 인수로 전달되고 충돌하는 스칼라 용도가 없으면 소스 투영에 사용할 포인터 형식을 추론할 수 있습니다. 물리적 ABI 위치와 일반 IR 형식은 유지되며, 함수 본문과 전체 네이티브 종속성 그룹은 여전히 검증을 통과해야 합니다.

네이티브 스칼라 헬퍼의 관찰된 입력 인수가 정확한 ABI 반환 레지스터에 있고 전체 결과 폭을 덮으면 해당 인수를 그대로 반환하는 경로를 증명할 수 있습니다. 제한된 분석은 모든 반환 경로, 최초 진입 및 루프 역방향 간선을 함께 검사하며 호출과 부분 쓰기는 값을 무효화합니다. 선언되지 않은 진입 값, 사용하지 않는 인수 자리, SSA 초기 표식과 PHI는 입력을 증명하지 못합니다. 이 추론은 소스 투영에만 쓰이며 물리적 위치를 보존하고 함수 본문과 의존성의 완전한 검증을 계속 요구합니다.

로컬 네이티브 보조 함수는 진입 값 관찰 분석과 완전한 LowIR 읽기 증거가 일치하면 결과 버퍼 포인터를 포함한 보조 레지스터의 전체 너비 정수 입력을 명시적 인수로 복원할 수 있습니다. 호출자 저장 레지스터는 이후 임시 값으로 덮어쓸 수 있지만, 보존 컨텍스트에는 프레임 외 보존 레지스터에 쓰지 않는 조건이 계속 적용됩니다. 호출의 암시적 정의는 SSA 버전 0이어도 진입 입력이 아니며, 명시적으로 보존된 바이트만 호출을 넘어 추적합니다. 재생성된 호출자와 함수 정의는 같은 물리적 입력 위치를 사용합니다. 외부 C/Swift 원형을 추정하지 않으며 완전한 본문과 의존성 검증이 필요합니다.

고정 C 콜백 타입은 소스 선언과 캐스트에서 매개변수 및 반환 시그니처를 보존합니다. 정확한 `swift_once` 가져오기는 초기화 플래그, `void (*)(void *)` 콜백, 컨텍스트를 바인딩하며 반환값은 없습니다. 런타임 호출은 유지하지만 콜백 본문 복원이나 공유 초기화 저장소의 소유권을 증명하지는 않습니다. 종속성이 불완전한 메서드는 미복원 상태로 남습니다.

알려진 Objective-C 런타임 가져오기 호출은 retain/release, 자동 해제, 강한 참조와 약한 참조 저장, 객체 할당, 고정 시그니처 속성 설정 함수의 인수와 반환값을 명시적으로 연결합니다. ARM64의 레지스터 전용 retain/release는 지정된 레지스터를 읽으며, 가져오기 대상과 ABI가 일치해야 합니다. 연관 객체의 조회·설정·제거는 객체, 키, 값, 포인터 너비의 정책 인수를 보존하고 생성된 C는 공개 런타임 헤더를 사용합니다. macOS 재컴파일 테스트는 객체 수명, 약한 참조 초기화, 복사 및 제거 동작을 원본 메서드와 비교합니다.

libobjc의 최적화된 클래스 및 선택자 질의는 nil 처리와 사용자 정의 재정의를 포함한 실제 런타임 호출을 보존합니다. 반환 바이트에는 호출자의 원래 변환이 적용되며 추측한 클래스 계층 검사로 대체하지 않습니다.

Objective-C 내보내기는 일반 C ABI를 사용하는 정해진 Swift 런타임 가져오기도 지원합니다. 참조 횟수, 네이티브 및 알 수 없는 객체의 약한 참조, 객체 메타데이터, 접근 검사 시작과 종료가 대상입니다. 생성된 C는 호출을 보존하며 링크 시 Swift 런타임이 필요합니다. 전용 레지스터 진입점, 알 수 없는 Swift 호출 규약, 임의의 Swift 심볼은 지원하지 않으며 가져오기 식별 정보와 스칼라 전달 위치가 정확히 일치해야 합니다.

arm64 및 x86_64에서 정확한 Darwin String → NSString 가져오기 `_$sSS10FoundationE19_bridgeToObjectiveCSo8NSStringCyF`와 선택적 NSString → String 가져오기 `_$sSS10FoundationE36_unconditionallyBridgeFromObjectiveCySSSo8NSStringCSgFZ`를 각각 바인딩합니다. 소유권과 Clang `swiftcall`을 보존하며, 링크에는 Swift Foundation과 Swift Core가 필요합니다. 역방향 브리지는 반환된 String의 두 워드를 부호 없는 128비트 정수로 전달하고 SSA 구성 전에 명시적인 반환 레지스터로 분리합니다. 이는 비트 전달 형식이며 복원된 String 레이아웃이나 일반 집계 ABI가 아닙니다. 알 수 없는 시그니처와 불완전한 초기화 종속성은 계속 지원하지 않습니다.

검증된 연관 객체 API의 키 인수에서는 읽기 전용 Mach-O C 문자열 영역의 확정된 주소를 공유 키로 재구성할 수 있습니다. 같은 원본 주소는 같은 키를 사용하고 서로 다른 내부 오프셋은 구별됩니다. mobile 내보내기는 보조 함수를 자동으로 병합합니다. C API는 `shared_identity_functions`에 이름을 나열하며, 메서드 소스 단위를 링크할 때 각 보조 함수의 정의는 하나만 포함해야 합니다. 이 키는 재구성된 코드에 속하며 이미 로드된 원본 이미지의 저장 공간을 참조하지 않습니다. 다른 용도의 미연결 이미지 주소는 여전히 복원을 제한합니다.

검증된 `os_unfair_lock_lock`, `os_unfair_lock_unlock`, `os_unfair_lock_trylock`, `os_unfair_lock_assert_owner`, `os_unfair_lock_assert_not_owner` 가져오기는 `<os/lock.h>`를 통해 실제 Darwin 구현을 호출하여 잠금 주소, 소유권 검사와 불리언 반환값을 보존합니다. 알 수 없는 변형은 지원하지 않습니다. 정수 호출 결과는 선언된 ABI 비트만 보존합니다. Darwin arm64는 부호 여부에 따라 8/16비트 결과를 32비트로 확장하며 나머지 레지스터 비트는 미확정 상태로 유지합니다. 메서드의 선언된 반환 폭을 분기 병합 전에 SSA에 반영하여 사용하지 않는 상위 비트가 유효한 하위 바이트를 가리지 않도록 합니다.

클래스 가져오기, 레이아웃, 문자 저장소와 fixup이 완전하면 검증된 Darwin `__cfstring` 레코드를 상수 객체로 재구성할 수 있습니다. 내장 NUL을 포함한 ASCII 바이트와 UTF-16 코드 단위를 보존합니다. 원본 주소가 같으면 하나의 재구성 객체를 공유하고, 다른 레코드는 구분합니다. 도우미는 `shared_identity_functions`에 포함되며 링크 시 Foundation이 필요합니다. 상수 객체 레코드에 대한 검증되지 않은 원시 메모리 접근은 허용하지 않습니다.

경계가 확정되고 포인터 재배치를 포함하지 않는 `__DATA,__llvm_prf_cnts` 숫자 카운터는 메서드 간 공유 저장 공간으로 재구성할 수 있습니다. 초기 바이트, 겹치는 1–16바이트 읽기와 쓰기, 갱신을 유지합니다. mobile 내보내기는 보조 함수를 병합하며, C API 사용자는 각 `shared_storage_functions` 정의를 한 번만 링크해야 합니다. 이 저장 공간은 원본 이미지 및 프로파일링 런타임과 독립적입니다. 외부로 전달되는 주소, 순서가 지정된 접근, 불완전한 매핑 및 포인터 재배치는 지원하지 않습니다. 계측된 block 콜백은 비공개 주소가 외부로 유출되지 않는 조건에서 이 이미지 저장소를 갱신할 수 있습니다. 일반 카운터 쓰기는 비공개 스택 프레임 쓰기와 구분됩니다.

클래스 메타데이터는 상위 클래스, 인스턴스 시작/크기, 오프셋·폭·정렬을 검증한 스칼라/포인터 ivar를 유지하며 필요한 패딩을 선언에 삽입합니다. 필요한 인스턴스 배치를 알 수 없는 메서드는 미복원입니다. 카테고리는 클래스/카테고리/주소 식별자와 구현을 분리하며 클래스·카테고리 목록에서 완전히 같은 중복 기록은 한 번만 셉니다. 지원되는 외부 카테고리는 기존 Foundation 클래스 선언을 이용합니다. 알려지지 않은 외부 헤더는 누락 의존성으로 보고하며 대체 클래스 배치를 만들어 내지 않습니다.

복원 판정에는 완전한 클래스 선언과 로컬 조상 클래스 정의, 생성된 소스의 모든 사용 경로에서 값이 먼저 정의되는지와 도달 가능한 종료 지점에 필요한 반환이 있는지도 포함됩니다. 빈 로컬 상위 클래스의 빈 `@implementation`은 검증된 배치와 완전한 메서드 목록으로 자체 일반 메서드가 없음을 입증할 때만 생성하며, 증거 부족이나 알려진 Foundation 가져오기 이름과의 충돌이 있으면 해당 메서드를 사유와 함께 커버리지 분모에 유지하고 독립적으로 복원 가능한 클래스는 계속 출력하지만, 이 이름 검사는 모든 SDK 이름이나 iOS SDK 및 버전을 포괄하지는 않습니다.

지원하는 Objective-C Block 호출에는 숨겨진 Block 객체와 모든 인수 및 반환값의 전달 위치를 포함하는 완전한 고정 스칼라 호출 ABI가 필요합니다. 런타임 인코딩 `@?`를 `id`로 넓히는 것은 선언에만 적용되며 호출 원형을 제공하지 않습니다. 전역 Block 참조는 공유 객체의 동일성을 유지합니다. 지원하는 동기 스칼라 캡처는 네이티브 캡처 저장소와 호출 흐름이 입증되어야 합니다. 검증된 `objc_retainBlock` / `_Block_copy` 호출로 복사되는 강한 객체 캡처는 도달하는 모든 생성 경로가 저장소를 초기화하고 호출·복사·해제 함수 본문이 모두 복원된 경우 이스케이프할 수 있습니다. 생성된 기술자는 원래 도우미 ABI와 소유권 레이아웃을 유지합니다. 약한 참조/byref 소유권, 알 수 없는 레이아웃, 입증되지 않은 소비자는 미복원으로 남습니다. 컴파일러가 비이스케이프로 선언한 C block 인수도 정확한 가져오기 대상, 인수 위치, 전체 콜백 ABI가 일치하면 지원합니다. 이 수명 계약은 메모리가 읽기 전용임을 뜻하지 않습니다. C API 소스 단위를 함께 링크할 때 `shared_block_functions`의 각 항목은 정의 하나만 유지해야 합니다. mobile 내보내기는 일치하는 정의를 병합하고 내부 호출 함수의 차이를 포함한 충돌을 거부합니다.

프로토콜 메서드 선언은 해결된 로컬 런타임 기록에서 읽으며 상속 프로토콜과 필수/선택 인스턴스 및 클래스 메서드를 포함합니다. 일반 목록과 상대 주소 목록은 같은 디코더를 사용합니다. 일치하는 클래스와 프로토콜 선언이 모두 동의해야 selector에 고정 호출 시그니처를 부여합니다. 잘못된 기록과 상속 순환은 타입 힌트를 제공하지 않습니다. 올바른 문법의 구조체·공용체·배열 포인터는 배치를 추론하지 않고 불투명 포인터로 전달합니다. `objc_metadata.protocols`는 선언을 별도로 공개하며 복원된 구현 수나 클래스의 프로토콜 준수를 의미하지 않습니다. 나머지 시그니처가 같으면 부호 있는 정수와 부호 없는 64비트 정수 반환값은 부호 없는 비트 표현을 공유합니다. 더 좁은 정수, 부동소수점, 포인터 또는 인자 타입 충돌은 계속 거부합니다.

컴파일러가 선언한 NSString 서식 호출은 검증된 상수 서식 객체에서 승격된 스칼라 인수를 복원할 수 있습니다. 순차 및 위치 지정 인수에는 누락이나 형식 충돌이 없어야 합니다. Darwin arm64는 8바이트 스택 슬롯에서 가변 인수를 읽고, x86_64는 정수·부동소수점 레지스터와 스택을 사용합니다. 생성된 호출은 줄임표와 동적 디스패치를 유지합니다. 알 수 없는 서식, 문자 수 쓰기, long double 및 지원하지 않는 확장은 거부합니다. 같은 서식 분석은 `NSLog` 같은 선언된 C 가져오기에도 적용됩니다. 정확한 라이브러리 내보내기를 확인하며 인수 개수가 다른 호출도 올바른 가변 인수 프로토타입을 공유합니다.

비공개 스택 프레임 쓰기는 함수 어디에서든 읽는 모든 바이트를 보존합니다. 프레임 경계, 진입부의 불변 별칭과 주소 비탈출이 증명되면 읽지 않는 쓰기를 제거하거나 정수 쓰기의 읽지 않는 끝부분을 줄일 수 있습니다. 따라서 사용하지 않는 스택 패딩만 미지 값인 경우에도 승격된 스칼라 인수를 복원할 수 있습니다. 미지 비트에 값을 채우지 않습니다. 순서가 지정된 접근, 미결합 호출, 모호한 주소, 부수 효과가 있는 값, 분석 예산 소진 시에는 원래 쓰기를 유지합니다.

카테고리의 동명 메서드는 런타임 재정의 순서를 알 수 없어도 검증된 ABI 선언을 유지합니다. 동적 호출은 모든 해당 선언이 일치할 때만 이 ABI를 사용하며, 모호한 구현은 소스 본문으로 선택하지 않습니다. 충돌하거나 잘못된 선언은 계속 호출 복원을 차단합니다.

등록된 변경 처리기가 반환할 수 있으므로 알려진 `objc_enumerationMutation` 호출은 객체 인수와 후속 실행 경로를 보존합니다. 정확한 Darwin `__stack_chk_guard` 가져오기는 런타임 객체의 동일성에 연결되며, 복원된 소스에서도 보호 값 읽기, 비교 및 `__stack_chk_fail` 호출의 동작을 보존합니다.

시스템 Foundation을 가져오는 링크된 64비트 Darwin 이미지에서는 컴파일러로 추출한 내장 프레임워크 선언도 조회합니다. 동일 선택자의 런타임 선언과 프레임워크 선언은 모두 호환되어야 하며, 가변 인수, 지원하지 않는 집계 형식, 플랫폼 간에 일치하지 않는 서명은 바인딩하지 않습니다. 이 목록은 호출 형식만 제공하며 수신 객체의 클래스나 함수 본문을 복원하지 않습니다. NeverD 사용 시 로컬 Apple SDK는 필요하지 않습니다. CoreData는 정확한 시스템 프레임워크 의존성으로만 활성화되는 별도 목록을 사용합니다. 선언은 공개 헤더를 소유한 프레임워크에 속하며, 간접적으로 포함된 의존성 헤더는 다른 프레임워크를 활성화하지 않습니다.

C 선언 카탈로그는 CoreGraphics와 ImageIO의 내보내기도 지원합니다. 불투명한 이미지 및 색상 포인터, 정수 개수, 부동소수점 반환값은 선언된 ABI를 유지합니다. 공개 시스템 프레임워크 경로 별칭은 내보내기 정보와 함께 생성합니다. 비공개 경로, 다른 프레임워크 버전 및 선언되지 않은 심볼에는 바인딩을 부여하지 않습니다. mobile 선언도 로더의 타입 문법을 사용하며, 올바른 집합 타입 포인터는 레이아웃을 추측하지 않고 불투명 포인터로 처리합니다。

Foundation 브리지 바인딩이 확인된 Swift의 큰 영구 문자열 리터럴은 UTF-8 바이트를 공유 정적 저장소로 복원할 수 있습니다. 길이, 플래그, 종결 바이트, UTF-8 유효성, 저장소 불변성 및 정확한 가져오기를 함께 검증합니다. 원래 태그 표현과 브리지 호출을 유지하며, 내부에 0바이트가 있는 리터럴과 다른 저장 형식은 바인딩하지 않습니다.

검증된 상수 NSString 객체는 완전한 데이터 주소 출처를 유지하는 정수 값으로 대입하거나 저장할 때도 공유 객체 정체성을 유지합니다. 스칼라 즉시값, 불완전한 주소, 수치 연산 및 객체 내부 바이트 접근에는 이 바인딩을 적용하지 않습니다.

불변이며 재배치가 없다고 증명된 이미지 바이트의 일반 스칼라 로드는 비트 패턴을 보존하는 상수로 복원할 수 있습니다. 1, 2, 4, 8바이트 정수와 4, 8바이트 부동소수점을 지원합니다. 쓰기 가능하거나 모호한 저장소, 순서가 지정된 로드 및 주소 용도는 바인딩하지 않습니다. 같은 표현식의 수치 용도에 대한 증명은 포인터 용도를 허용하지 않습니다.

고정 인자 C 호출은 컴파일러에서 추출한 선언과 SDK 내보내기 및 재내보내기 정보도 사용합니다. 실제 dyld 라이브러리, 심볼과 스칼라 ABI가 일치해야 하며 약한 가져오기, 알 수 없는 제공 라이브러리와 지원하지 않는 원형은 바인딩하지 않습니다. 생성된 C는 별도 식별자로 원래 심볼에 연결합니다. 언어 예외 분기 테이블이 없는 일반 동기화 호출은 실제 호출과 메모리 부작용을 보존합니다.

공유 소스 제어 흐름 분석이 모든 도달 경로의 부호 없는 상한을 증명하면 인덱스 스칼라 읽기에 재구성한 불변 바이트 테이블을 사용할 수 있습니다. 가드, 마스크, 네이티브 정수 폭과 래핑 의미를 유지하며, 쓰기나 지역 변수 주소의 탈출은 이전 증명을 무효화합니다. 테이블당 최대 4,096개 항목과 65,536바이트를 허용합니다. 소스를 공개할 때 현재 범위, 저장소, 재배치와 모든 헬퍼 사용을 다시 검증합니다. 전체 포인터 폭의 값이 이미지 섹션을 가리키면 포인터 여부가 모호하므로 제외합니다. 더 좁은 스칼라 조각이나 세그먼트 패딩만으로는 포인터 정체성을 증명하지 못합니다. 복사한 바이트는 스칼라 읽기에만 쓰이며 테이블 주소는 탈출할 수 없습니다. 실행 회귀 테스트는 정수 비트, 음의 0을 포함한 부동소수점 비트와 범위 밖 동작을 원래 메서드와 비교합니다.

외부 데이터 바인딩에는 플랫폼 공통 비 TLS SDK 선언과 정확한 라이브러리 내보내기 근거가 필요합니다. 생성된 C는 실제 심볼 저장소를 참조하고 전역 포인터와 대상 객체의 구별을 포함한 후속 메모리 접근을 보존합니다. 약한 가져오기, 식별 충돌 및 지원하지 않는 저장소는 바인딩하지 않습니다. 데이터 선언은 block 구성이나 소유권을 입증하지 않습니다. 카탈로그에는 CoreData, CoreGraphics, ImageIO, CoreSpotlight 데이터가 포함됩니다. 내장 리터럴 저장소는 모든 대상에서 빈 컬렉션과 불리언 객체를 컴파일해 얻으며, 외부 비 TLS 데이터의 직접 주소만 동일한 내보내기 검사를 거쳐 허용합니다. 카탈로그 생성에는 libclang 외에 `--clang`으로 지정한 Clang 컴파일러가 필요합니다.

런타임 정보 복원은 제한적입니다. 완전한 프로퍼티·프로토콜, 원래 소유권 주석, 임의 집합형, 가변 인자 꼬리, 예외 의존 본문, 모델에 없는 Block/캡처 배치를 보장하지 않습니다. 런타임 인코딩은 고정 인자만 설명하며 원 선언에 생략 부호가 없었다고 증명할 수 없습니다. 체인 포인터는 로더가 해당 슬롯을 해결한 경우에만 사용하며 나머지 형식에는 진단을 남깁니다.

## Swift 소스와 저장 배치

구조화된 demangler 출력은 호출 가능한 서명과 호출 불가능한 메타데이터를 분리합니다. 지원되는 서명은 본문 출력 전에 선택한 바이너리의 심볼, 진입점, 명시적인 기계 ABI와 연결합니다. Swift 수신자는 Swift ABI를 따르며 Objective-C 숨김 인자로 대체하지 않습니다. 사용자가 제공한 서명 파일도 검증해야 하는 힌트입니다.

실험적 출력기는 지원되는 자유 함수, 클래스 메서드, 지정 초기화 메서드, 고정 배치 struct 메서드를 구성하며 지원되는 mutating 수신자 형태를 포함합니다. 클래스/struct 선언과 저장 필드는 복원된 배치 메타데이터가 필요합니다. 필요한 선언과 본문이 지원되는 완전한 의존성 그룹일 때만 네이티브 호출을 출력합니다. 소스 단위는 선언과 메서드를 함께 포함하며 원래 바이너리를 호출하는 브리지를 만들지 않습니다.

지원하는 Swift getter/setter 본문은 네이티브 구현에서 복원하여 프로퍼티로 조립합니다. 비공개 backing storage는 확인된 필드 레이아웃을 유지하며 초기화 함수와 다른 메서드도 같은 저장소 이름을 사용합니다. 프로퍼티 선언이나 필드 기록만으로 접근자 본문이 복원되었다고 판단하지 않습니다.

지원하는 할당 초기화 함수, 단순 소멸자/해제 함수, 타입 메타데이터 접근자와 `_modify`/resume 진입점은 출력된 타입 단위로 투영할 수 있습니다. 각 항목에는 전체 네이티브 흐름과 효과에 대한 제한된 증명, 실제 복원된 컨텍스트/초기화 함수/프로퍼티 의존성, 관련 본문의 예외 처리 및 IR 검사가 필요합니다. 할당 함수의 쓰기는 실제 초기화 함수와 일치해야 하고 `_modify`는 정확한 가변 필드와 재개 진입점을 연결해야 합니다. 런타임 메타데이터 호출은 복원된 타입 안에서 모델링된 의미를 유지합니다. 이 항목들은 컴파일러 소스 투영으로 명시되며, 각각 복원된 일반 메서드 본문이나 원래 소스 텍스트를 뜻하지 않습니다.

제네릭 또는 resilient 배치, async/throwing 함수, 알 수 없는 호출 규약, 미지원 accessor/allocator/thunk, 불완전한 초기화와 연결되지 않은 네이티브/런타임 의존성은 개별 `unrecovered`로 남습니다. 맹글링된 심볼이나 명목 타입 이름만으로 메서드 복원이 되지는 않습니다. 제거된 심볼과 미분류 demangler 노드는 범위를 불완전하거나 알 수 없게 만듭니다.

## 출력과 범위

```text
recovered-ios/
  artifacts/selected.macho
  sources/native.c
  sources/objc.m
  sources/swift.swift
  metadata/objc.h
  metadata/objc.json
  metadata/objc-methods.json
  metadata/swift.json
  metadata/swift-signatures.json
  metadata/swift-methods.json
  logs/
  report.json
```

소스 언어 파일은 코드를 출력할 수 있을 때만 존재합니다. `objc.json`은 클래스, 카테고리, ivar, 원시 메서드 인코딩을 저장하고 `objc.h`는 지원되는 선언을 담습니다. `swift.json`은 명목 타입과 맹글링된 심볼을 포함합니다. 서명/메서드 JSON은 분류, 생략, 이유, 개수를 유지합니다. 로그에는 네이티브 진단과 실제 실행한 네이티브 Swift 내보내기의 진단이 포함됩니다. 외부 Swift 도구 체인 탐색이나 디맹글링 로그는 생성하지 않습니다. `report.json`의 경로는 해당 디렉터리 기준입니다. 선택한 바이너리는 분석 산출물이며 생성 소스에 복원 브리지로 링크하지 않습니다.

임시 패키지 복사본과 중간 JSON을 삭제합니다. 일반 실행에서 네이티브 본문이 없으면 메타데이터가 있어도 실패합니다. 메타데이터 모드는 선택 파일, `objc.h`, `objc.json`, `swift.json`, `report.json`만 만들며 소스와 서명/메서드 범위 파일은 없습니다. `native_function_count`, `objc_method_recovery`, `swift_method_recovery`는 `null`. 모든 모드는 네이티브 로더가 해석한 Objective-C 메타데이터를 사용합니다. Swift 메타데이터는 범위를 확인한 네이티브 이미지 읽기를 사용하며 지원하지 않는 fixup, 재배치 가능 레이아웃 또는 참조는 부분 분석 진단을 유지합니다.

다음 축약 예시는 의도적으로 부분 복원을 보여 줍니다.

```json
{
  "schema_version": 1,
  "status": "success",
  "platform": "ios",
  "architecture": "arm64",
  "objc_method_recovery": {
    "status": "partial",
    "method_count": 3,
    "recovered_method_count": 2,
    "unrecovered_method_count": 1
  },
  "swift_method_recovery": {
    "status": "partial",
    "coverage_status": "partial",
    "method_count": 4,
    "recovered_method_count": 2,
    "source_body_method_count": 1,
    "compiler_projection_method_count": 1,
    "unrecovered_method_count": 2,
    "metadata_symbol_count": 5,
    "unclassified_symbol_count": 1
  }
}
```

바깥쪽 `status: "success"`는 검증한 출력을 게시했다는 뜻입니다. `recovered`, `partial`, `unrecovered`, `no-methods`는 발견한 목록에 대한 상태이며 의미 동등성이나 원 프로그램 완전성이 아닙니다. 각 미복원 메서드에는 이유가 있습니다. Objective-C의 `recovered`는 완전한 런타임 메타데이터도 요구합니다. 빈 목록이 메서드가 없었다는 증거는 아닙니다.

미복원 Objective-C 메서드 행에는 단 하나의 백엔드 결과가 런타임 식별 정보와 정확히 일치할 때 `native_backend: {status, reason, diagnostics}`가 포함될 수 있습니다. 크기가 제한된 이 선택적 요약은 선언 또는 레이아웃 검사가 실패해도 중간 결과를 보존합니다. 행의 기본 상태, 이유 및 복원 개수가 최종 기준이며, 요약이 없으면 해당 증거를 사용할 수 없었다는 뜻입니다.

Swift `coverage_status`는 분류된 호출 가능 항목만 셉니다. 전체 Swift `status`는 알 수 없는 심볼도 고려하여 `unclassified`, `unsupported-architecture`, `no-symbols`일 수 있습니다. 호출 불가능 메타데이터는 `non_method_symbols`에 `not-callable`, 알 수 없는 심볼은 `unclassified`로 저장합니다. `types`, `type_metadata_count`, `source_type_count`는 타입 메타데이터와 출력 타입 단위를 별도로 세며 메서드 수를 부풀리는 데 사용하면 안 됩니다.

복원된 Swift 행의 `source_representation`은 `native-method-body` 또는 `compiler-generated-from-type`입니다. 컴파일러 투영에는 `compiler_projection_kind`와 `compiler_projection_evidence`도 보존합니다. `source_body_method_count`는 복원된 네이티브 메서드 본문 수, `compiler_projection_method_count`는 증명된 컴파일러 투영 수이며 합계는 `recovered_method_count`와 같습니다. 컴파일러 진입점도 `method_count` 분모에 남고 정확한 식별 정보가 대응하는 하나의 `type` 소스 단위에 포함되어야 합니다. 타입 메타데이터나 의존성 이름만으로 복원 수를 늘리지 않습니다. 네이티브 일괄 JSON의 컴파일러 행과 타입 단위에는 `source`가 있지만, mobile의 `source_units`는 `source` 없이 설명만 보존하며 전체 소스는 `sources/swift.swift`에 저장됩니다.

Swift 배치 `source_units`는 `{kind, module, name, source, method_entries, method_identities}`를 기록합니다. kind는 `function` 또는 `type`, identity는 `{entry, mangled_symbol}`입니다. 다른 심볼은 같은 진입점을 공유하면서 별도의 ABI 출력을 유지할 수 있습니다. 각 복원 identity는 정확히 한 번 포함되고 미복원 identity는 포함되지 않아야 합니다. `method_entries`는 `method_identities`의 진입점을 순서대로 투영한 목록과 일치하며 중복 주소를 허용합니다. 완전히 같은 중복 identity를 조용히 합치면 안 됩니다. 배치 `source`는 각 단위 소스와 줄바꿈을 순서대로 연결한 값입니다. Mobile은 전체 소스를 `sources/swift.swift`에, 단위 설명을 범위 JSON에 보관합니다. 개별 메서드 `source`는 검사 용도이며 단순 연결로 클래스 선언을 올바르게 복원할 수 없습니다.

## 직접 네이티브 내보내기와 SDK

```sh
neverd export recovered-ios/artifacts/selected.macho \
  --format=objc-methods --max-func=20 -o objc-batch.json
neverd export recovered-ios/artifacts/selected.macho \
  --format=swift-methods \
  --source-signatures=recovered-ios/metadata/swift-signatures.json -o swift-batch.json
```

Swift 내보내기는 일반 mobile 실행에서 내장 서명 파서가 생성한 구조화된 서명 목록을 받습니다. Objective-C 배치 JSON에는 `native_source`, `native_function_count`, `objc_metadata`와 메서드별 C 소스, 함수 이름, 반환 타입, 인자가 들어 있습니다. Mobile은 `.m` 생성 전에 선언·본문·배치를 추가 검증하므로 최종 범위가 C 배치보다 작을 수 있습니다. 네이티브 내보내기가 성공해도 복원 메서드가 하나도 없을 수 있습니다.

각 메서드의 `projection_diagnostics`는 독립적으로 검사 가능한 문제를 `items`의 `code`, `reason` 및 사용 가능한 문장·호출·값·의존성 증거로 기록합니다. `checks_complete: false`는 전제 부족이나 자원 제한을 뜻하며 빈 부분 보고서는 복원 성공의 증거가 아닙니다. 판정과 같은 검사를 사용하며 기존 `status`, `reason`, `unbound_call` 계약을 유지합니다.

배치 `native_dependency_graph`는 지원되는 서명의 메서드에서 최종 LowIR의 이미지 코드 직접 호출을 따라가며 호출자·블록·명령 주소, 공유 대상과 순환을 보존합니다. 간접 대상은 null입니다. 필요한 LowIR 함수가 없거나 기록 한도에 도달하면 `inventory_complete`는 false이고, `targets_complete`는 모든 기록의 직접 대상도 요구합니다. 미지원 메서드 루트와 미해결 간접 대상은 제외하며 완전한 네이티브 실행 범위나 의존 소스 복원을 증명하지 않습니다.

검증된 로컬 프로토콜 참조는 `objc_getProtocol`로 등록된 프로토콜의 동일성을 유지합니다. 배치 의존성 목록 `runtime_protocols`에는 호출된 네이티브 함수의 요구 사항도 포함됩니다. 이름 충돌, 불완전한 선언, 가져온 슬롯, 미해결 재배치는 바인딩하지 않습니다. 독립 내보내기는 null 프로토콜을 받을 수 있는 본문을 생성하는 대신 등록 누락을 보고합니다.

Swift 런타임 ABI 목록은 고정된 상위 선언에서 생성하며 C 또는 Swift 호출 규약을 유지합니다. 알려진 포인터와 포인터 폭의 부호 없는 타입으로 고정 스칼라 시그니처를 구성합니다. Swift 호출에는 정확한 강한 libswiftCore 가져오기가 필요하며 지원하는 두 버전별 메타데이터 가용성도 약한 가져오기를 허용하지 않습니다. 특수 매개변수 레지스터, 알 수 없는 표현, 미지원 가용성, 충돌 선언은 제외합니다. swift_willThrow는 선언 DSL에 없는 swiftself/swifterror 속성을 컴파일러가 추가하므로 제외합니다. 호출 효과와 기존 콜백·바이트 계약은 유지합니다. `scripts/generate_swift_runtime_declarations.py --input RuntimeFunctions.def --source-sha256 <pinned-hash>`로 생성하고 `--check`로 검증합니다. 리비전, 해시, 제삼자 고지를 함께 기록합니다.

고정 Swift 런타임 선언은 두 포인터 또는 선언된 메타데이터 포인터와 상태 워드로 구성된 두 워드 결과도 유지합니다. 공유 ABI 계층이 두 결과 레지스터를 배정하고 소스 검증이 순서, 타입, 정확한 가져오기를 다시 확인합니다. Box 할당과 메타데이터 조회는 실제 런타임 호출을 실행하며 집계 매개변수, 알 수 없는 레이아웃, 숨겨진 컨텍스트는 지원하지 않습니다.

이와 별도로, 컴파일러에서 정확히 관찰한 URLRequest, Notification, URL, Data, Date, IndexPath의 Foundation 값 브리지는 `swiftcall`과 공급자 식별 정보를 유지합니다. 간접 결과와 context/self는 전용 레지스터의 `swift_indirect_result` 및 `swift_context`(arm64의 x8/x20, x86_64의 RAX/R13)를 사용하며 일반 정수 인자 레지스터 뱅크를 소비하지 않습니다. Data는 명시적인 두 워드 전달을 유지합니다. 이는 호출 전달 위치 선언이며 복구된 값 레이아웃이나 일반 Swift ABI가 아닙니다.

네이티브 스칼라 반환 추론은 검증된 결과 ABI를 가진 호출 직후의 완전한 두 워드 추출을 인식합니다. 임시 값 식별자, 멤버 오프셋, 폭, 물리 레지스터가 모두 일치해야 합니다. 보조 함수가 첫 멤버를 직접 반환할 수 있으며 일반 레지스터 뷰 규칙, 호출에 따른 덮어쓰기, 모든 반환 경로의 결과 정의 요구 사항은 유지됩니다.

고정 C 런타임 카탈로그는 32비트 정수 전달값과 명시적으로 0 확장되는 불리언 결과도 보존합니다. 불리언 결과는 완전한 부호 없는 바이트를 사용하며, 이를 불리언 인수의 확장 규칙으로 해석하지 않습니다. 더 좁은 미확인 표현과 Swift 호출 규약의 32비트 선언은 계속 제외합니다. 런타임 테스트는 형 변환 성공 및 실패, 정확한 횟수의 참조 유지, 객체 소멸을 검증하며 호출과 소유권 효과를 보존합니다.

저장 필드 메타데이터는 확인된 바이트 배치와 알 수 없는 언어 타입을 구분합니다. 안정 ABI의 Swift 클래스는 arm64에서도 포인터 너비의 필드 오프셋 변수를 사용하며, 공개되지 않은 필드의 Objective-C 타입 인코딩은 비어 있을 수 있습니다. NeverD는 타입 부재를 유지하면서 오프셋, 크기, 정렬 및 겹침을 검증합니다. 복구된 C 함수 본문은 런타임 ivar 조회로 오프셋을 얻습니다. 알 수 없는 타입을 만들어야 하는 클래스 선언은 계속 출력하지 않습니다.

안정 ABI의 Swift 필드는 오프셋 슬롯이 런타임에 초기화되는 제로 채움 저장소에 있어도 메타데이터의 식별 정보를 유지할 수 있습니다. 클래스는 `ivar_status: "runtime"`으로 표시되며 알 수 없는 오프셋은 JSON `null`, 크기 0은 런타임에 결정되는 필드 너비를 뜻합니다. 메서드 본문은 기존 런타임 클래스에서 오프셋을 조회하고 선언된 객체 타입은 정확한 오프셋 슬롯으로 추적할 수 있습니다. 리터럴 오프셋에는 확인된 배치가 필요합니다. Swift 클래스 배치를 재구성하는 기능은 아니며 독립 클래스 내보내기는 알 수 없는 배치와 필드 타입을 계속 거부합니다.

직접 바인딩된 네이티브 호출에서는 호출 대상이 관찰 가능한 효과 전에 진입 지점에서 포인터를 정확히 한 번 읽고, 쓰기·보관·비교 등 다른 용도로 사용하지 않음을 증명한 경우에만 ivar 오프셋 주소를 로컬 스칼라 주소로 바꿉니다. 로컬 값은 기존 런타임 ivar 조회로 얻으며 네이티브 ABI와 호출 대상 본문은 유지합니다. 이 유한한 증명은 직선 제어 흐름만 허용하고 불확실한 사용이나 분석 한도 초과를 거부합니다. C API는 `.cxx_destruct`를 복원하지만 독립 Objective-C 메서드 문법은 아직 이 셀렉터를 출력할 수 없습니다.

불변 바이트 버퍼는 검증된 가져오기 호출 계약이 음수가 아닌 읽기 길이를 제한하고 쓰기, 포인터 보관, 주소 동일성 비교를 배제할 때만 재구성합니다. 원래 바이트와 길이는 보존하며 다른 포인터 사용은 미해결 상태로 유지합니다. Swift 표준 라이브러리의 정확한 어설션 실패는 컴파일러에서 유도한 스칼라 및 스택 전달 위치, `swiftcall`, `noreturn` 효과와 링커 표기를 보존합니다. C 진단 shim은 선언된 C ABI와 별도의 후속 트랩을 유지합니다. 정적 문자열과 불멸 String 리터럴 저장소는 포인터를 보관하지 않는 인증된 종단 소비자에 대해서만 복사합니다. 동적이거나 소유권이 있는 String 값은 리터럴로 취급하지 않습니다.

Mach-O를 이미 로드한 세션에서 `neverd_objc_methods_json(session, max_functions)`, `neverd_swift_methods_json(session, signatures_json, max_functions)`가 보고서를 반환합니다. 0은 발견한 모든 함수입니다. 성공 문자열은 `neverd_free_string`으로 해제합니다. `NULL`은 실패이며 세션 오류에 이유가 있습니다. 이 API는 IPA/`.app` 컨테이너를 로드하지 않습니다.

Objective-C 네이티브 의존성 추론은 소스 호출을 결합한 뒤 `NativeAnalysis`의 64비트 정수 레지스터 인수를 32비트로 좁힐 수 있습니다. 모든 HighIR 사용을 빠짐없이 검사하여 각 출현이 오프셋 0 바이트 추출 또는 정확히 결합된 호출의 정수 인수로서 하위 4바이트만 정확히 관찰함을 증명해야 합니다. 증명은 인수별로 독립적이며, 전체 너비·0이 아닌 오프셋·잘못된 사용 또는 분석 예산 소진이 있으면 원래 너비를 유지합니다. 정제된 보조 함수는 다시 리프팅되어 일반 함수 본문 및 의존성 폐쇄 검사를 통과해야 하며, 재작성 ABI는 변경되지 않습니다.

Objective-C 진입 thunk로 노출되는 Swift 지연 초기화 정적 객체 getter는 `vgZTo` 심볼, 런타임 메서드 시그니처, 조건자 검사, `swift_once` 호출, 저장소 로드, `objc_retainAutoreleaseReturnValue` 결과가 정확한 컴파일러 패턴을 이룰 때만 투영할 수 있습니다. 조건자 `_Wz`, 초기화 함수 `_WZ`, 저장소 `vpZ` 심볼이 서로 일치해야 하며, 원시 세 번째 레지스터는 once 컨텍스트로만 나타나야 합니다. 초기화 함수는 이 컨텍스트를 무시하고 일반 직접 호출자가 없어야 합니다. 투영은 조건자와 객체 저장소를 다시 만들고, 무관한 컨텍스트로 null을 전달하며, 초기화 함수를 검증된 종속성으로 유지합니다. 형태, 심볼, 매개변수 사용 또는 콜백이 달라지면 복구하지 않습니다.

인증된 `cfcTo` 심볼과 런타임 `init` 시그니처를 가진 Swift Objective-C 생성자 thunk에서도 선언되지 않은 세 번째 인수 레지스터가 정확히 검증된 단일 `swift_once` 호출의 컨텍스트로만 사용되면 해당 인수를 제거할 수 있습니다. 조건자 `_Wz`와 초기화 함수 `_WZ`가 일치해야 하며, 콜백은 컨텍스트를 무시하고 일반 직접 호출자가 없어야 합니다. 투영은 null을 전달하고 조건자의 8바이트 저장소 범위만 추론하며, 나머지 제어 흐름, 메모리 및 호출 효과를 모두 보존합니다. 일반 소스 본문 및 종속성 폐쇄 검사는 계속 적용됩니다.

## 검증과 문제 해결

macOS에서 `BUILD_TESTING`을 활성화한 빌드는 `check-neverd-mobile-ios`를 제공하며, CTest로 세 네이티브 복원 테스트 모음을 실행합니다.

Python은 아래 개발 테스트 스크립트에만 사용합니다. 내장 모바일 복구는 네이티브 C++20 CLI에서 실행됩니다.

```sh
cmake --build build --target check-neverd-mobile-ios
ctest --test-dir build -L NeverDMobileTests --output-on-failure
python3 scripts/test_mobile_ios_backend.py --neverd build/bin/neverd
python3 scripts/test_mobile_ios_calls_backend.py --neverd build/bin/neverd
python3 scripts/test_mobile_swift_backend.py --neverd build/bin/neverd
```

macOS의 Objective-C 검증 스크립트는 원본 샘플을 컴파일하고 `.m`을 복원한 뒤 생성 소스만 독립 호출 하네스와 링크합니다. 스칼라 스크립트는 정수 경계, 분기, 루프, 포인터 읽기/쓰기, 숨겨진 인수, float/double 비트 동일성, 혼합 인수와 스택 인수를 검사합니다. 호출 스크립트는 메시지 디스패치, 상속, Category, 인스턴스 변수 저장소, 네이티브 도우미와 Block 호출/캡처/공유 동일성도 검사합니다. 호출 샘플은 arm64/x86_64 × classic/default 조합마다 21/21 메서드 복구와 134/134 독립 예상 결과 일치를 요구합니다. 현재 네이티브 CLI 빌드로 검증하세요.

엄격한 Swift 스크립트는 사용자 선언 22개, getter/setter 진입점 3개, 컴파일러가 생성한 호출 가능 진입점 9개를 검사하며 어떤 항목도 목록에서 빠질 수 없습니다. 변형마다 원본 프로그램의 독립 예상 결과 858개를 확인합니다. 생성된 `.swift`와 하네스를 독립적으로 컴파일하며 원본 dylib, 모듈, 브리지 또는 수동 대체 선언을 사용하지 않습니다. 스칼라/네이티브 호출, 클래스 초기화와 저장소, 구조체 값 전달/mutating 메서드, 부동소수점과 스택 인수, 포인터 및 루프를 포함합니다. 네이티브 C++20 CLI 인수 조건은 arm64/x86_64 × classic/default 네 조합을 건너뛰지 않고 통과하는 것입니다. 조합마다 네이티브 본문 25개와 컴파일러 투영 9개를 복원하고 호출 가능한 식별 정보 34개를 보존해야 하며, 원본과 독립적으로 컴파일한 생성 Swift가 각각 858/858 예상 결과 검사에 통과해야 합니다. 이 결과는 해당 샘플에 한정되며 임의 애플리케이션이나 원래 소스 텍스트의 복원을 보장하지 않습니다. 스크립트는 커버리지 누락, 소스 컴파일 실패와 동작 불일치를 거부합니다.

이 네 조합의 컴파일 대상은 macOS입니다. 추가된 컴파일러 진입점 두 개는 빈 값 초기화 함수와 해당 메타데이터 접근자입니다. 네이티브 증명으로 각각 검증하며 하나의 `struct Empty {}` 소스 단위에 두 식별 정보를 보존합니다. 이 코퍼스의 통과가 실제 iOS 애플리케이션의 검증 완료를 뜻하지는 않습니다.

세 스크립트 모두 `--arch all|arm64|x86_64`, `--fixups both|classic|default`, `--timeout N`, `--work-dir NEW_DIRECTORY`를 지원합니다. `--setup-only`는 원본만 검증하며 복원은 테스트하지 않습니다. 스칼라 검증을 포함해 요청한 모든 아키텍처와 fixup 조합을 완료해야 합니다. 조합이 누락되거나 호스트가 요청한 아키텍처를 실행할 수 없으면 실패하며, 건너뛰기는 허용하지 않습니다. 보존된 실패 산출물로 소스 커버리지 누락, 컴파일 오류와 동작 차이를 구분하고 검증된 지원을 주장하기 전에 현재 테스트 출력을 확인하십시오.

[Mobile Real Applications 워크플로](../../.github/workflows/mobile-real-apps.yml)는 [코퍼스 매니페스트](../../scripts/mobile_real_apps.json)에 버전을 고정한 공개 앱을 사용합니다. 통과하려면 전체 iOS 번들의 모든 Mach-O와 APK의 모든 DEX에 대한 독립 목록, 원본과 생성 소스의 독립 재빌드, 동작 비교가 필요합니다. 단계 누락, 목록 범위 미확인, 필수 사례 누락은 모두 실패입니다. 실제 앱의 recompile 및 behavior 단계가 아직 미완성이므로 Experimental 표시를 유지합니다. 테스트 하네스의 오판 방지 테스트 통과는 실제 앱 검증 통과를 의미하지 않습니다.

게시는 트랜잭션 방식입니다. 새 디렉터리를 선택하고 종료 상태부터 확인하며 리디렉션 JSON은 그 밖에 저장하세요. 실패 시 임시 출력을 삭제하고 기존 결과를 보존합니다. 백엔드가 0이 아닌 값으로 종료하면 길이가 제한된 로그 끝부분이 오류에 포함됩니다. 백엔드 시간 초과도 이미 캡처한 로그 텍스트를 사용할 수 있으면 원래 시간 초과 메시지를 유지하면서 길이가 제한된 끝부분을 덧붙입니다. 예산 초과의 메시지는 그대로 유지됩니다. 네이티브 CLI는 성공 시 0, 복구 실패 시 0이 아닌 값을 반환합니다. `--json`은 처리된 실패에 `schema_version`, `status: "error"`, `error`를 포함합니다. 인수 분석, 네이티브 실행 파일이나 라이브러리 시작 실패, 중단은 stderr로만 보고될 수 있습니다. 호출자는 먼저 종료 상태를 확인해야 합니다.

암호화된 슬라이스에는 읽을 수 있는 입력을 제공하고, 필요한 아키텍처가 없으면 사용 가능한 슬라이스를 확인하세요. 생략된 메서드의 정확한 이유와 메타데이터 진단을 확인합니다. `--max-func`를 늘리는 것은 개수 제한으로 제외된 함수에만 유효합니다. 배치·서명·외부 헤더·예외·ABI 지원 누락은 구현이나 추가 유효 메타데이터가 필요하며 완전 복원이라는 주장으로 해결되지 않습니다. 배포할 때 적용되는 의존성 라이선스 고지를 보존하세요.

네이티브 스칼라 보조 함수 추론은 float/double 레지스터 인수와 반환값도 지원합니다. 공유 MedIR 진입 바이트 분석은 넓은 벡터 입력에서 하나의 하위 스칼라 레인만 관측됨을 증명해야 합니다. 모든 정의의 하위 폭이 같고, 버리는 상위 식에 부작용이 없으며, 모든 사용이 해당 하위 부분만 읽을 때 소스 지역 CONCAT 값을 좁힐 수 있습니다. 호출, 저장, 분기 위치와 NaN 이외 부동소수점 비트는 유지되며, 알 수 없는 상위 비트를 만들어 넣지 않습니다.

검증된 외부 void 꼬리 호출로 전달하는 리프 보조 함수는 완전한 스칼라 결과가 없을 때 내부 void 소스 서명을 사용할 수 있습니다. LowIR 의 모든 호출과 합성 반환이 일치해야 합니다. 리프 증명은 보존, 프레임, 스택 및 링크 레지스터 쓰기를 금지하며, 제한된 바이트 오염 고정점은 스택 유래 값을 저장하거나 호출에 전달하는 경우도 거부합니다. CFG, 본문과 의존성 검사는 유지됩니다. 결과 비트는 제공하지 않으므로 알 수 없는 결과를 읽는 호출자는 미복원 상태로 남습니다. 실행 회귀는 조건부 객체 소멸, 독립적인 호출자 반환값과 알 수 없는 결과를 읽는 호출자의 거부를 확인합니다.

제한된 LowIR 분석이 모든 종료 경로에서 보존 레지스터 바이트, 스택 포인터 및 링크 레지스터의 복원을 증명하면 void 네이티브 요약은 스택 프레임과 일반 호출도 지원합니다. 부분 쓰기, 암시적 0 확장, 겹치는 저장 및 호출로 인한 변경은 관련 증거를 무효화합니다. 프레임 유래 바이트를 포함하지 않는다고 증명된 주소를 통한 저장은 호출의 비공개 프레임과 분리되지만, 프레임에서 일부 또는 전부 유래한 별칭과 프레임 주소의 스필·외부 전달은 증명을 거부합니다. 프레임 대여의 유일한 예외는 소스에 결합된 `objc_msgSendSuper2`의 정확한 첫 번째 인수입니다. 이 런타임 계약은 동기적으로 읽으므로 할당된 프레임 안에 완전히 들어 있는 16바이트 `objc_super` 객체 전체를 가리킬 수 있습니다. 일반 메시지, 불완전한 포인터, 프레임 밖 객체와 그 밖의 모든 프레임 인수는 계속 거부합니다. HighIR 바이트 생존 분석은 스택 슬롯 값을 해당 슬롯 바이트의 제한된 읽기로 취급하지만, 그 주소를 얻거나 전달하는 것은 계속 외부 전달입니다. 잘못되었거나 겹치는 접근은 보수적으로 처리합니다. 따라서 분리된 비공개 저장은 읽히지 않은 뒤쪽 바이트만 제거할 수 있습니다. 다시 리프팅한 뒤 HighIR에 전혀 나타나지 않는 보조 레지스터 인수를 제거하고 파이프라인을 다시 실행할 수 있습니다. 비공개 저장 제거는 기존 HighIR 정리가 담당하며 표준 인수와 실제 입력 사용은 유지합니다.

arm64 UIKit 카탈로그는 `UIProgressView`의 `observedProgress` 객체 반환값과 `setProgress:animated:`도 바인딩합니다. 후자는 `float`와 불리언 인수의 별도 레지스터를 보존합니다. 두 선언 모두 컴파일러가 생성한 iPhoneOS 및 arm64 iPhoneSimulator 증거가 일치하고 정확한 시스템 UIKit 제공자를 사용해야 합니다. 다른 아키텍처는 지원하지 않습니다.
