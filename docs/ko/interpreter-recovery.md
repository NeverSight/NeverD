# 인터프리터 소스 복원

실험적 인터프리터 특수화 단계는 링크된 x64 함수에서 정적으로 해석할 수 있는 디스패치를 제거하면서 런타임 입력, 메모리 효과, 분기와 루프를 유지합니다. 핸들러 패턴이나 특정 보호기의 연산 코드 표가 아닌 명령어 의미론을 사용합니다.

```sh
neverd decompile program --func vm_entry --devirtualize \
  --recovery-report recovery.json -o recovered.c
neverd decompile program --func vm_entry --devirtualize \
  --llvm -o recovered-llvm.c
```

`--vm-control`은 인터프리터 컨텍스트를 구분할 전체 범용 레지스터를 선택합니다. 여러 번 지정할 수 있지만 구체적인 값을 제공하지는 않습니다. 예를 들어 진입 코드가 값을 설정하는 바이트코드 커서를 선택할 수 있습니다. 카운터로 쓰이는 런타임 입력은 동적인 상태로 유지해야 합니다. 서로 다른 커서 값이 합류할 때 필요한 컨텍스트 구분이 없으면 복원이 중단될 수 있습니다. 엔진은 이를 보완하려고 디스패치 대상을 추측하지 않습니다. 커서가 스택에 스필된 경우 `--vm-control-stack=-16:8`은 진입 시 RSP보다 16바이트 앞에 있는 8바이트를 선택합니다. 오프셋은 조정된 현재 스택 포인터가 아닌 함수 진입 시점을 기준으로 합니다.

C API는 `neverd/sdk/NeverDCAPIDevirtualize.h`의 `neverd_devirtualize_source_v1()`입니다. 별도 트랜잭션에서 실행되므로 세션의 일반 디컴파일 캐시를 변경하지 않습니다. 실패하면 소스를 반환하지 않으며 JSON 진단은 반환할 수 있습니다. 반환된 두 문자열은 모두 `neverd_free_string()`으로 해제합니다.

## 제어 상태 자동 탐색

CLI와 모든 버전의 소스 복원 C API는 기본적으로 자동 탐색을 활성화합니다. 특정 제공자에 종속되지 않는 C++ API에서는 `SpecializationOptions::DiscoverControlState = false`가 기본값이며 호출자가 `true`로 설정할 수 있습니다. 수동 `--vm-control` 및 `--vm-control-stack` 힌트는 선택적인 컨텍스트 키로 유지됩니다. 일반적인 자동 탐색 필드는 유한 값의 제한된 결합 관계만 보존하며, 컨텍스트 키를 추가하거나 런타임 입력을 표본 값으로 고정하지 않습니다. 아래의 선택적 메모리 정밀화에서 증명된 상수가 필요한 경우를 제외하면 일반 카운터는 동적으로 남습니다.

미해결 제어 흐름과 주소의 의존 관계에서 구조화된 노드 진입 레지스터 입력과 메모리 입력이 처음 생성된 출처를 추적하며, 좁은 바이트 범위도 처리합니다. 생성 출처가 노드 진입 이후 변경되지 않은 메모리를 가리키고 함수 진입 프레임 기준의 정확한 상대 범위를 식별할 때만 프레임 슬롯을 후보로 지정합니다. 같은 값이나 저장에서 전달된 값을 나중에 읽어도 추가 입력 의존 관계가 생기지 않으며, 메모리 정보가 무효화된 뒤 생성된 알 수 없는 바이트를 진입 슬롯으로 취급하지 않습니다. 과거 읽기 기록은 다른 분석에서 계속 사용할 수 있습니다. 누락된 의존 관계를 찾으면 함수 진입점부터 분석을 다시 수행합니다. 보존하는 각 관계에는 제약하는 비트에 대한 완전한 유한 값 증명이 여전히 필요하며, 별칭 가능성이 있는 쓰기는 메모리 사실을 무효화합니다. 임의의 외부 메모리나 무한한 상관 값이 자동으로 유한해지는 것은 아닙니다.

생산자 요구는 노드 경계를 넘어 비트 마스크를 유지하며 바이트 전체로 확대하지 않습니다. 다만 산술 연산에서는 요구된 비트에 올림이나 빌림을 전달할 수 있는 하위 비트 범위를 보수적으로 포함합니다.

이미 추적 중인 메모리 의존 관계 때문에 정확한 주소 증명이 반복해서 막히면, 추가 정밀화가 증명된 진입 상수를 컨텍스트 키로 승격할 수 있습니다.

일반 의존성 탐색이 더 진행되지 않으면 함수 진입점을 제외한 네이티브 위치와 명령 모드마다 기존 레지스터 컨텍스트 필드 하나를 분할할 수 있습니다. 진입 도메인은 완전하고 여러 값을 포함하며 선언된 모든 비트를 포괄해야 합니다. 실제 선행 간선마다 현재의 완전한 도메인을 독립적으로 증명하고 살아 있는 물리 필드를 비교해 각 경우를 다시 투영합니다. 후속 선행 간선과 확장된 노드도 다시 검사하며 지정된 진입점에서는 연결을 멈춥니다. 비교는 합성 출처를 가지며 노드, 연산, 컨텍스트, 질의, 정밀화 예산을 공유합니다. 부분 마스크, 미정의 플래그, 프레임 전용 필드는 제외합니다. 게스트 읽기나 호출자 가정을 추가하지 않습니다. 불완전한 도메인은 보수적인 간선을 유지하며 도달 가능한 모든 경우가 완료되어야 결과를 게시합니다.

이 선택적 정밀화는 진입 프레임 기준점에 정확한 변위를 더한 값으로 증명된 완전한 64비트 레지스터 값이나 저장된 포인터로도 컨텍스트를 구분할 수 있습니다. 키는 변위를 보존하며 호출의 실제 숫자 주소를 추측하지 않습니다. 부분 쓰기나 가능한 별칭은 포인터 사실을 무효화합니다. 조건 분기는 부정확한 합류로 미지원 후속 경로가 드러난 경우를 포함하여, 최종 제어 증명 전에 제한된 정밀화의 의존 후보를 제안할 수 있습니다. 후보 제안은 조건이 거짓이라는 증명이 아닙니다. 도달 가능성과 유지할 대상에는 완전한 증명이 필요하며, 미지원 연산이 계속 도달 가능하거나 필수 예산이 소진되면 게시하지 않습니다. 미지원 후속 경로에 대한 후보 탐색은 가장 가까운 조건 미확정 선행 분기를 선택하며 완전한 역방향 슬라이스는 아닙니다.

생산자에 대한 역방향 요구는 네이티브 노드 진입점, 명령 모드, 필드 종류와 바이트 범위로 식별합니다. 후속 노드가 해당 필드를 요구하는 간선만 생산자 의존 관계를 확장하며, 유한하지만 정밀도가 부족한 값의 범위도 포함합니다. 이 과정은 예산 내에서 진입점부터 다시 분석할 수 있지만, 재사용되는 물리 레지스터에 하나의 전역 역할을 부여하지는 않습니다. 의존 관계 탐색은 제한적이며 완전하지 않으므로, 모든 인터프리터를 수동 힌트 없이 복원할 수 있다고 보장하지 않습니다.

일반적인 자동 필드의 투영도 대상 노드의 요구 범위로 제한합니다. 상수가 아닌 필드는 대상 노드가 요구할 때만 간선의 결합 유한 값 관계에 포함됩니다. 수동 필드와 자동으로 컨텍스트 키로 승격된 필드는 계속 전역 투영 대상이 됩니다. 알려진 상수 바이트, 진입 프레임을 기준으로 한 정확한 포인터 및 출처 정보는 요구 여부와 관계없이 보존됩니다. 따라서 서로 다른 핸들러 단계의 무관한 필드 때문에 관계의 값 조합 수가 곱해지는 것을 막습니다. 설정된 예산과 제어 흐름 대상, 메모리 주소 및 반환 상태에 필요한 증명 조건은 바뀌지 않습니다.

일반 자동 필드에서는 각 튜플 열이 요구된 비트만 제약하고 해당 마스크를 가집니다. 합류에서는 모든 유입 경로에서 제약된 비트만 보존합니다. 같은 바이트의 다른 비트는 런타임 값으로 남습니다. 필드의 저장 범위가 그 전체 범위에 대한 완전한 유한 값 범위 증명을 뜻하지는 않습니다. 8개 비트가 모두 상수임이 증명되어야 바이트를 상수로 만들 수 있습니다.

수동 필드와 컨텍스트 키로 승격된 필드는 계속 전역적으로 전체 너비의 관계 증명을 먼저 시도합니다. 그 증명이 결론을 내리지 못하면 요구된 비트의 관계만 보존할 수 있습니다. 이 대체 경로는 증명되지 않은 바이트를 컨텍스트 키에 제공하거나 소진된 전역 예산을 우회하지 않습니다.

새 그래프로 재분석할 때 다른 필드에 완전히 포함된 일반 자동 저장 범위는 해당 넓은 필드를 함께 사용할 수 있습니다. 원래 단계의 위치와 비트 요구는 바뀌지 않습니다. 수동 필드, 컨텍스트 필드 및 미해결 메모리 주소에서 직접 후보로 지정한 필드는 정확한 범위를 유지합니다. `MaxControlFields`는 이 정규화 후 실제로 보존되는 필드 수를 제한합니다. `DiscoveredControlFields`는 누적값이므로 활성 필드 수를 초과할 수 있습니다. 필드 한도와 전역 작업 예산은 늘리지 않습니다.

완전한 유한 값 범위 증명을 얻은 일반 자동 필드는 모든 생산자를 즉시 제어 필드로 추가하지 않습니다. 탐색은 이러한 의존 관계 후보를 기록하고, 복원이 계속 막혀 있으며 즉시 수행한 정밀화에서 후보가 나오지 않을 때만 활성화합니다. 컨텍스트 키로 승격된 필드는 계속 생산자 의존 관계를 즉시 확장합니다. 탐색 방문, 재분석 및 증명 작업에는 기존 누적 예산을 그대로 적용합니다.

시도가 실패하고 일반 후보 선택을 마친 뒤, 유한한 역방향 작업 목록이 관찰된 네이티브 제어 전이를 따라 대기 중인 정확한 비트 요구를 전파합니다. 공유 스칼라 평가기를 재사용하되 현재 제어 필드가 담는 범위만 처리하므로 필드나 컨텍스트를 추가하지 않습니다. 이전 그래프는 후보의 전파 경로만 제공하며, 그 값이나 경로 실행 가능성을 새로운 사실로 가져오지 않습니다. 선행 노드 탐색, 재실행, 의존성 탐색은 누적 작업 예산을 공유합니다. 따라서 긴 연결에서도 네이티브 단계마다 전체 분석을 재시작하지 않고 요구를 전달할 수 있지만, 결과 게시에는 새 그래프에서의 완전한 고정점 증명이 필요합니다.

완전한 유한 값 범위는 워드 전체의 값이 달라져도 개별 바이트가 상수임을 증명할 수 있습니다. 예를 들어 `{0, 0x100}` 범위의 최하위 바이트는 항상 0입니다. 열거된 모든 튜플에서 동일한 바이트만 대상 바이트 순서에 따라 상수로 보존하며, 다른 바이트는 동적으로 남습니다. 불완전한 열거, 솔버의 알 수 없음 결과 또는 증명 예산 소진에서는 이러한 사실을 얻지 않습니다.

유한 값 범위 증명은 정밀화에 따른 재분석을 포함해 한 번의 복원 실행 안에서 재사용할 수 있습니다. 크기가 제한된 캐시는 자유 변수의 일관된 이름 변경을 허용하면서 완전한 순서 있는 표현식 DAG를 비교합니다. 변수 공유 관계, 너비, 상수 비트, 연산자 부가 정보 및 투영 한도는 키에 포함됩니다. 완전한 값 범위와 범위가 한도를 넘는다는 증명만 저장합니다. 알 수 없거나 부분적인 결과는 저장하지 않으며, 캐시 미적중이나 용량 부족 시 일반 증명 경로를 사용합니다. 모든 전역 예산은 계속 적용되고 `solverQueries`는 실제 솔버 호출을 셉니다.

동일한 술어에서 도달 가능성이 증명되었다면, 변하는 열 하나의 완전한 값 범위와 다른 각 열의 증명된 단일 값으로 정확한 결합 관계를 결정할 수 있습니다. 여러 열이 변하면 여전히 결합 증명이 필요합니다. 마스크 열이 가능한 비트 값 전체를 포함하더라도, 입력 비트가 술어 및 다른 모든 열과 독립적임을 증명해야만 그 열을 생략할 수 있습니다. 공유 입력, 알 수 없는 결과 또는 불완전한 열거로 데카르트 곱을 가정하지 않습니다.

기본값은 수동·자동 필드 합계에 대해 `MaxControlFields = 16`, `MaxControlRefinements = 16`, `MaxDiscoveryVisits = 65536`입니다. 재시작은 전역 노드(합성 노드 포함), 연산, 평가, 솔버 쿼리, 탐색 방문 예산을 공유합니다. `contexts`는 네이티브 컨텍스트 수이며, `evaluatedOperations`, `nodeEvaluations`, `solverQueries`와 함께 시도 전체에 걸쳐 누적됩니다. 주소별 컨텍스트 수, 활성 네이티브 반환 슬롯, 제어 필드 수, 튜플 수는 각 시도 안의 구조적 제한입니다. 기본 솔버 쿼리 제한은 여전히 4096입니다. 예산 소진 시 부분 결과를 게시하지 않으며, `residualBlocks`는 최종 잔여 그래프만 나타냅니다.

CLI 옵션 `--vm-max-refinements=N`은 양의 정수를 요구하며 기본값은 16입니다. C 호출자는 `neverd_devirtualize_source_v2()` 또는 `neverd_devirtualize_machine_source_v2()`로 같은 한도를 설정할 수 있습니다. `neverd_devirtualize_options_v2`를 0으로 초기화하고 `base.struct_size = sizeof(neverd_devirtualize_options_v2)`와 `max_control_refinements`를 설정합니다(0이면 기본값 16 유지). 내장된 `base`에는 v1 옵션이 들어가며 두 reserved 멤버는 모두 0이어야 합니다. 기존 v1 레이아웃과 진입점은 바뀌지 않고 확장된 뒷부분을 무시합니다. 다른 작업 및 증명 예산도 계속 적용됩니다.

`--vm-max-fields=N`과 `--vm-max-queries=N`은 제어 필드 및 솔버 질의 한도를 설정하며 기본값은 16과 4096으로 유지됩니다. 이 두 옵션과 `--vm-max-refinements`는 양의 32비트 십진 정수와 `--devirtualize`를 요구합니다. 0, 부호, 십육진수, 뒤따르는 문자, 오버플로는 거부합니다. 두 소스 ABI와 두 백엔드에 동일한 한도가 적용됩니다. 예산 증가는 분석 작업량만 늘리며 제어 힌트, 런타임 입력 또는 새로운 증명 보장을 제공하지 않습니다. 예산이 소진되면 C를 게시하지 않습니다.

C 호출자는 `neverd_devirtualize_source_v3()` 또는 `neverd_devirtualize_machine_source_v3()`를 사용합니다. `neverd_devirtualize_options_v3`를 0으로 초기화하고 `base.base.struct_size = sizeof(neverd_devirtualize_options_v3)`를 설정합니다. `max_control_fields`, `max_solver_queries`, 선택적으로 `base.max_control_refinements`를 설정하며 0은 기존 기본값을 선택합니다. 세 reserved 필드는 모두 0이어야 합니다. v1/v2 진입점은 reserved를 포함한 v3 꼬리를 무시하고 v3는 미래 확장 꼬리를 무시합니다. 보고서는 실제 작업량과 유효한 `maxControlFields`, `maxControlRefinements`, `maxSolverQueries`를 기록합니다.

복원은 `--vm-chain-transfers=N`(기본값 0)과 `--vm-no-control-discovery`도 제공합니다. 연결은 단일 대상이 증명된 제어 전송 사이의 기호 상관관계를 보존하며 한도에 도달하면 일반 CFG 경계로 돌아갑니다. 기계 상태 복원은 `--vm-entry-frame=begin:end`로 실행 시 검사하지 않는 비래핑 진입 RSP 오프셋 범위를 선언할 수 있습니다. 정확한 숫자 전제는 생성 C와 보고서에 남으며 메모리 접근 권한이나 동등성 증명을 제공하지 않습니다.

SSA 구성 한도를 넘는 큰 복원 함수는 `--llvm`을 통해 제한된 스칼라 가변 저장소 계약을 사용할 수 있습니다. 진입 입력, 루프에서 전달되는 값, 앞선 읽기의 의미를 보존합니다. 지원하지 않는 암시적 상태, 벡터 레지스터 매개변수, 이미지 재배치, 모호한 저장소와 잘못된 제어 흐름은 명시적으로 실패하며 HighC는 이 대체 경로를 거부합니다. 소스 출력은 기존 기계 상태 계약을 따르며 동등성 인증서를 추가하지 않습니다.

가변 부분 집합은 8/16/32/64/128비트 스칼라 저장소를 허용하며 비트 개수 입력은 최대 64비트입니다. 비표준 너비와 더 넓은 저장소에는 별도 소스 계약이 필요합니다.

검증된 가변 변수 함수 본문에서 LLVM은 명령을 끝에 추가하는 동일 기본 블록 안에서만 비공개 슬롯의 정확한 값을 전달하고 마지막 쓰기를 유지합니다. 진입 초기화와 블록·함수·모듈 경계는 분리되며 대상 프로그램의 메모리 접근은 명시적으로 남습니다. C 출력은 스칼라 식 확장과 즉시값 접기의 작업량을 제한하고 이름이 있는 중간값을 유지합니다. 접을 수 있는 상수 식에는 LLVM 대상 배치를 사용하고 지원하지 않는 식은 명시적으로 거부합니다. 지정된 가변 반환값은 0이더라도 void 반환으로 바뀌지 않습니다.

호환 v4 API는 `neverd_devirtualize_source_v4()`와 `neverd_devirtualize_machine_source_v4()`입니다. `neverd_devirtualize_options_v4`를 0으로 초기화하고 `base.base.base.struct_size`를 전체 크기로 설정합니다. CLI 연결 횟수는 음이 아닌 32비트 십진 정수이며 0은 비활성화입니다. 범위 끝점은 부호 있는 64비트 십진 정수이고 `begin < end` 및 `--vm-machine-state`가 필요하며 조정된 값이 아닌 물리적 진입 RSP를 제한합니다. C의 범위 플래그는 기계 상태 API를 요구하며 플래그가 없으면 두 끝점은 0이어야 합니다. 알 수 없는 플래그와 기존 예약 필드의 0이 아닌 값은 거부합니다. v1/v2/v3은 v4 확장 전체를 무시하고 v4는 미래 확장을 무시합니다. null 옵션은 기존 기본값을 유지합니다. 보고서는 `maxChainedTransfers`, `entryFrameBounds`, 실제 `discoverControlState`를 기록합니다. 모든 CLI 옵션은 `--devirtualize`가 필요합니다. 숫자 전제는 실행 시 검사되지 않으며 접근 가능성, 초기화, 비별칭을 보장하지 않습니다. 네이티브 증명 정책도 활성화하지 않습니다.

```c
neverd_devirtualize_options_v4 options = {0};
options.base.base.base.struct_size = sizeof(options);
options.base.base.base.use_llvm = 1;
options.max_chained_transfers = 64;
options.flags = NEVERD_DEVIRTUALIZE_V4_DISABLE_CONTROL_DISCOVERY |
                NEVERD_DEVIRTUALIZE_V4_HAS_ENTRY_FRAME_BOUNDS;
options.entry_frame_begin = -256;
options.entry_frame_end = 8;
const char *report = NULL;
const char *source = neverd_devirtualize_machine_source_v4(
    session, entry, &options, &report);
neverd_free_string(source);
neverd_free_string(report);
```

머신 상태 복원은 `--vm-entry-alignment=A:R`로 진입 RSP 합동 조건을 명시하고 실행 시 검사합니다. `A`는 양의 2의 거듭제곱이며 `R < A`여야 합니다. 다른 진입 값은 게스트 메모리 접근이나 상태 쓰기 전에 상태 2를 반환합니다. 주소 상위 비트는 자유롭고 기본값은 정렬을 가정하지 않습니다. 이 옵션은 네이티브 동등성 인증을 제공하지 않습니다.

v5 C API `neverd_devirtualize_source_v5()`와 `neverd_devirtualize_machine_source_v5()`는 v4에 `entry_frame_alignment`, `entry_frame_residue`를 추가합니다. `neverd_devirtualize_options_v5`를 0으로 초기화하고 `base.base.base.base.struct_size`를 전체 크기로 설정합니다. 정렬값 0은 비활성화를 뜻하며 나머지도 0이어야 합니다. 0이 아닌 정렬은 머신 상태 API에서만 허용됩니다. v1–v4는 새 후행 필드를, v5는 미래 후행 필드를 무시합니다. 보고서의 `entryFrameAlignment`와 생성 C는 같은 검사 조건을 기록합니다. 잘못된 정렬은 잘못된 진입 플래그보다 먼저 거부되며 모든 상태 워드를 보존합니다. 기존 숫자 프레임 범위는 여전히 실행 시 검사하지 않습니다. C++ 잔여 그래프 호출자는 RSP 영역을 직접 보장해야 합니다. 소스와 모델 래퍼는 검사 생성기를 공유하며 네이티브 증명 API는 계약에 해당 영역을 연결할 수 있을 때까지 거부합니다.

`--vm-max-symbolic-nodes=N`과 v5 `max_symbolic_nodes`는 노드별 기호 DAG 예산을 지정합니다(기본 262144). CLI는 양의 32비트 십진수를 요구하고 C의 0은 기본값을 선택합니다. 두 소스 ABI에 같은 한도가 적용되며 `maxSymbolicNodes`에 유효 예산을 기록합니다. 예산 증가는 의미적 가정이나 증명을 추가하지 않습니다.

`--vm-external-stores-disjoint-frame`은 기계 상태 복원에 명시적이며 런타임에 검사하지 않는 전제를 추가합니다. 외부 STORE의 전체 범위가 `--vm-entry-frame`과 겹치지 않아야 하며 그 범위 안의 기존 사실만 유지합니다. LOAD나 외부 포인터 간 별칭은 제한하지 않고 기본 동작은 보수적으로 유지됩니다. 네이티브 증명 API는 이 도메인을 거부합니다.

v6 API `neverd_devirtualize_source_v6()`와 `neverd_devirtualize_machine_source_v6()`는 변경 없는 v5 옵션을 포함합니다. `neverd_devirtualize_options_v6`를 0으로 초기화하고 `base.base.base.base.base.struct_size`를 전체 크기로 설정합니다. 기계 상태 소스와 v4 진입 프레임 경계를 함께 사용할 때만 `flags`에서 `NEVERD_DEVIRTUALIZE_V6_EXTERNAL_STORES_DISJOINT_ENTRY_FRAME`을 켭니다. 일반 소스는 이 플래그를 거부합니다. v1–v5는 확장을, v6는 미래의 꼬리를 무시합니다. 보고서의 `externalStoresDisjointEntryFrame`과 생성 C는 검사하지 않는 계약을 명시합니다. 프레임에서 파생되거나 출처가 불명인 쓰기에는 예외를 적용하지 않습니다. 완전한 아핀 포인터 저장 슬롯은 보호 범위에 전부 포함되어야 합니다. 기존 사실의 검사·저장·복원은 공유 연산 예산을 소비하며 소진되면 C를 내보내지 않습니다.

v7 API `neverd_devirtualize_source_v7()`와 `neverd_devirtualize_machine_source_v7()`는 변경하지 않은 v6 접두부에 `max_node_evaluations`와 `max_discovery_visits`를 추가합니다. 0은 기본값인 평가 16384회와 의존성 방문 65536회를 선택합니다. `neverd_devirtualize_options_v7` 전체를 0으로 초기화하고 `base.base.base.base.base.base.struct_size`를 전체 크기로 설정합니다. v1–v6는 이 확장을 무시하며, v7은 향후 꼬리 확장을 무시하고 상속된 검증을 유지합니다. Python은 대응하는 `abi.NeverDDevirtualizeOptionsV7` 레이아웃과 형식 지정 함수를 제공합니다. `--vm-max-evaluations=N`과 `--vm-max-discovery-visits=N`에는 `--devirtualize`와 양의 32비트 십진수가 필요하며 4294967295도 허용합니다. 보고서는 실제 `maxNodeEvaluations`와 `maxDiscoveryVisits`를 기록합니다. 이 누적 작업 한도는 의미론적 전제를 바꾸지 않으며, 예산 때문에 거부되면 C나 복원 증거를 출력하지 않습니다.

v7의 `flags`는 `NEVERD_DEVIRTUALIZE_V7_STOP_CHAIN_AT_REPEAT`(Python: `DevirtualizeFlagsV7.STOP_CHAIN_AT_REPEAT`)도 지원하며 CLI에서는 `--vm-chain-stop-at-repeat`에 해당합니다. 단일 목적지가 증명된 일반 체인이 같은 네이티브 주소와 디코드 모드의 목적지를 다시 방문하기 전에 체인을 끝내고 일반 간선 투영을 사용합니다. 루프 펼치기를 줄일 수 있지만 이후 제어 해석에 필요한 상관관계를 잃어 이전에 성공한 복원을 거부할 수 있습니다. 플래그 기본값은 0이며 체인 한도가 0이면 효과가 없습니다. 의존성 재생은 확정된 명령 출현 순서를 유지합니다. 두 소스 ABI 모두 `stopChainingAtRepeatedDestination`을 보고하며 알 수 없는 v7 플래그를 거부합니다. 이 전략은 의미론적 전제를 추가하거나 미해결 제어의 출력을 허용하지 않습니다.

`--vm-chain-visits=N`은 체인 안에서 네이티브 주소와 디코드 모드별로 음이 아닌 32비트 방문 한도를 추가합니다. 시작 위치와 연결된 전이 목적지를 세며 순차 fallthrough는 세지 않습니다. 0은 추가 한도 없음입니다. `--vm-chain-stop-at-repeat`는 여전히 더 엄격한 1회 한도를 우선 적용합니다. 전체 체인 한도가 0이면 두 설정 모두 비활성입니다. v8 C API는 `neverd_devirtualize_options_v8`을 사용합니다. 구조체를 0으로 초기화하고 `base.base.base.base.base.base.base.struct_size`를 전체 크기로, `max_chained_visits_per_destination`을 원하는 값으로 설정합니다. `reserved`는 0이어야 합니다. v1–v7은 이 확장을, v8은 미래 꼬리 필드를 무시합니다. Python은 `NeverDDevirtualizeOptionsV8`을 제공합니다. 보고서는 `maxChainedVisitsPerDestination`과 `effectiveChainedVisitsPerDestination`을 기록합니다. `--devirtualize`가 필요하며 의미 전제 추가 없이 분석 정밀도와 작업량만 바꿉니다.

유한한 다중 목적지 간접 분기도 지연 조건 의존성을 보존합니다. 합류 후 목적지 집합이 유한해도 실행 불가능한 경로가 포함될 수 있습니다. 실패 후 역방향 탐색은 새 필드·컨텍스트·생산자 요구 비트를 추가할 수 없는 조건을 지나 유용한 외부 조건을 찾습니다. 후보 선택과 활성화는 같은 규칙과 탐색 예산을 사용합니다. 후보만으로 간선을 제거하지 않으며, 결과 공개에는 전체 도달 가능 그래프의 새로운 증명이 필요합니다. 유한 분기의 의존성 탐색은 기존 정밀도 개선이 더 진행되지 않을 때 시작합니다. 활성화는 같은 누적 작업 한도 안에서 새 개선 한 번을 사용하므로 관련 없는 선택자가 기존 생산자나 네이티브 조건의 개선 예산을 먼저 소모하지 않습니다. 조건 후보가 소진되어도 지연된 생산자와 다른 정밀도 개선 절차는 계속할 수 있으며, 실패 해소에는 새로운 증명이 필요합니다.

제어 및 가드 정밀도 개선을 선택적 프레임 분할 재시도보다 우선하며 필요한 추가 분할은 유지합니다. 나머지별 고정점을 순서대로 계산하지만 모든 허용 나머지가 완료되어야 결과를 공개합니다. 명시적 정렬 영역과 분할 영역의 교집합을 사용하고 실제 나머지를 비교합니다. 컨텍스트, 연산, 노드 및 솔버 예산은 재시도 간 공유하며 한도를 유지합니다.

해결되지 않은 간접 분기 대상은 가드의 정밀도 손실 때문에 나타날 수 있습니다. 직접 대상과 지연된 생성자 정밀도 개선에서 후보가 더 이상 추가되지 않으면 실패 지점에 도달하는 가장 가까운 미결정 가드를 검사합니다. 후보 선택과 재시도는 탐색 및 정밀도 개선 예산을 공유합니다. 새로운 완전한 증명만 분기를 배제할 수 있으며, 실제로 도달 가능한 미지의 대상은 잔여 코드나 증명 자료를 공개하지 않고 계속 실패로 처리합니다.

제어 요구에는 진입 기준 포인터 관계가 필요할 수도 있습니다. 후속 노드가 요구한 완전한 64비트 레지스터에 대해서는 정렬 마스크가 없어도 해당 간선 조건 아래에서 진입 기준 주소로부터의 변위를 증명할 수 있습니다. 유일한 전체 폭 결과만 그 간선의 투영에 보존하며, 알 수 없는 결과는 사실을 추가하지 않습니다. 병합에서는 충돌하거나 한쪽에 없는 변위를 제거하고 물리적 기준 주소 값은 고정하지 않습니다.

64비트 이하의 덧셈에서는 제한된 구조적 마스크로 모든 피연산자에서 1이 될 수 있는 비트가 서로 겹치지 않음을 증명할 수 있습니다. 이 경우에만 상위 제어 구간에서 하위 비트의 올림 의존성을 제외합니다. 검사는 전체 워드의 상수와 모든 피연산자를 포함합니다. 알 수 없는 형태, 겹치는 비트 또는 더 넓은 덧셈에는 보수적인 하위 비트 접두부 규칙을 유지합니다. 마스크 검사도 의존성 탐색 작업량에 포함하며, 예산이 소진되면 후보나 루트 독립성 주장을 내보내지 않습니다. 유한 영역이나 대상 증명을 대체하지는 않습니다.

선택한 제어 워드에 유한한 선택자와 넓은 데이터 또는 주소 영역이 섞이면 복원기는 요청 마스크 안에서 32, 16, 8비트 구간을 시도할 수 있습니다. 자동 탐색은 실제 소비자의 요구를 기다리며, 탐색을 끄면 수동 힌트도 참여합니다. 이미 투영한 바이트와 진입 프레임 루트로부터의 독립성을 확인할 수 없는 후보는 건너뜁니다. 각 선택적 의존성 탐색에는 별도의 `MaxSymbolicNodes` 작업 한도를 적용하며 누적 `DiscoveryVisits`와 구분합니다. 모든 유한성 증명은 기존 질의 예산을 공유합니다. 증명한 상수 바이트를 보존하고, 그 바이트들이 선택한 마스크 전체를 포함하면 탐색을 계속합니다. 나머지 후보 중 처음으로 완전히 증명한 유한 영역을 원래 비트 위치에 유지하고, 다른 비트는 런타임 데이터로 남깁니다. 부분 증명 뒤에도 원래 생산자 요구를 즉시 처리합니다. 나중에 합류한 선행 경로는 충돌하거나 누락된 사실을 무효화합니다. 이 제한된 탐색이 유용한 모든 하위 필드를 찾는다고 보장하지는 않습니다.

JSON 보고서에는 `discoverControlState`, `maxControlRefinements`, `maxDiscoveryVisits`, `discoveredControlFields`, `discoveredContextFields`, `controlRefinements`, `discoveryVisits`가 추가되어 활성화 상태, 제한 및 분석 작업량을 기록합니다. 필드를 찾았다는 사실만으로 복원 성공이 입증되지는 않습니다.

조건에 의해 주소 의존성이 바이트 조각으로 좁아지면, 정밀화는 해당 조각을 포함하는 이미 추적 중인 완전한 8바이트 직접 주소 필드도 문맥 후보로 유지합니다. 기존의 좁은 필드와 생성자 비트 마스크는 그대로 두며, 관련 없는 넓은 필드는 승격하지 않습니다. 상수와 진입점 상대 오프셋은 여전히 증명이 필요하고 모든 문맥은 기존 한도를 공유합니다.

선택적 불변 주소 열거는 인증서가 없는 실행 가능한 주소를 만나면 중단하고 원래의 런타임 읽기를 유지합니다. 관찰한 값과 인증서는 전체 도메인이 입증된 뒤에만 사용합니다. 캐시 적중 시에도 현재 읽기 범위를 다시 확인하며, 실제로 관찰한 잘못된 인증서는 오류로 처리합니다.

현재 술어가 실제 `MaxControlTuples` 또는 `MaxImmutableReadAddresses` 한도보다 엄격히 많은 값을 허용함을 증명하면, 복원은 전체 64비트 `root + constant` 제어 값이나 불변 읽기 주소의 선택적 열거를 생략할 수 있습니다. 증명은 선언된 비순환 프레임 구간을 고려하며, 고정된 하위 32비트 나머지마다 한도보다 많은 루트가 있어야 합니다. 의존성 탐색에서는 해당 경계와 정확히 일치하는 최상위 논리곱 항만 제외합니다. 나머지 모든 항은 새 루트 변수의 상위 32비트를 제약하지 않아야 합니다. 더 강한 제약, 지원하지 않는 의존성, 작업 예산 소진 시에는 일반 풀이로 돌아갑니다.

각 증명은 경계 일치 검사와 의존성 탐색에 하나의 `MaxSymbolicNodes` 작업 예산을 공유합니다. 경로 술어가 바뀌면 새 증명이 필요합니다. 이 열거 생략은 입력을 고정하거나 도달 가능성을 증명하지 않습니다. 런타임 읽기, 좁은 생성자 마스크, 불변 읽기 인증서 및 최종 실행 가능성 검사는 계속 필요합니다.

유한 투영은 부분적으로 제약된 기호 입력 안의 독립 비트도 유지할 수 있습니다. 64비트 이하 변수에서는 공유 의존성 탐색기가 현재 술어와 모든 원래 `RelatedValues` 출력의 비트 요구를 합칩니다. 출력 비트와 정확히 대응하며 그 합집합에 없는 서로 다른 소스 비트만 값 개수의 하한에 포함합니다. 자리올림 의존성과 반복 부호 비트는 보수적으로 처리하며, 관련 출력을 불리언 논리곱으로 바꾸지 않습니다. 전혀 등장하지 않는 변수는 더 넓은 소스의 좁은 뷰를 포함해 기존 빠른 경로를 유지합니다. 모든 루트, 피연산자 스캔, 비트 탐색은 `MaxSymbolicNodes`를 공유하고 불완전한 증명은 일반 풀이로 돌아갑니다. 이 순수 표현식 모드는 기계 위치를 후보로 지정하지 않으며 상태 출처 검사를 바꾸지 않습니다.

유한 증명 캐시가 용량에 도달하면 단독으로 수용할 수 있는 적격 증명으로 가장 오래 사용하지 않은 기록을 교체합니다. 적중 시 사용 순서를 갱신하지만 중복 저장, 캐시 미스, 거부된 후보는 갱신하지 않습니다. 제거된 증명은 다시 확립해야 할 수 있습니다. 완전한 값 영역이나 값 영역 한도 초과가 증명된 결과만 보관하며, 새로운 솔버 호출은 모두 공유 질의 예산을 사용합니다.

복원은 마스크가 적용된 개별 제어 필드의 완전히 증명된 유한 값 영역도 보존합니다. 결합 관계가 `MaxControlTuples`를 초과해도 독립 영역으로 대상을 제한할 수 있지만 필드 간 상관관계를 가정하지는 않습니다. 합류에서는 공통 마스크를 적용한 값의 합집합을 구하며, 없거나 한도를 초과한 영역은 전체를 버립니다. 결합 관계가 이미 확장되었어도 영역이 바뀌면 노드를 다시 처리합니다. 불완전한 열거는 사실로 사용하지 않으며 기존 필드, 튜플, 심볼릭 노드 및 솔버 한도를 유지합니다.

생산자, 조건, 레지스터 및 프레임 정밀화에 더 이상 후보가 없어도 대상이 미해결이면, 실패한 노드의 관찰된 선행 노드를 조사하여 해당 진입점에서 확정된 요구 비트가 있는 기존 레지스터 또는 프레임 저장 범위 하나를 문맥 후보로 지정할 수 있습니다. 이 제한된 후속 단계는 수동 필드, 기존 문맥 필드와 함수 진입 입력을 제외하며 성공한 시도에는 추가 탐색을 하지 않습니다. 새 그래프는 문맥 키에 쓰는 완전한 상수나 정확한 프레임 변위를 다시 증명해야 합니다. 일부만 알려진 값과 나중에 나타나는 미지의 선행 상태는 보수적으로 유지하며 불변 읽기에는 여전히 증거가 필요합니다. 탐색 방문 수와 정밀화, 노드, 문맥 예산을 공유합니다.

`MaxChainedTransfers`는 명시적으로 켜는 C++ 한도이며 기본값은 `0`입니다. 대상 또는 불리언 결과가 하나임을 증명한 제어 전이를 연속 처리하며 전체 심볼릭 상태, 네이티브 출처와 누적 예산을 보존합니다. 결과가 여럿이면 일반 CFG 간선을 사용합니다. 역방향 탐색은 확정된 명령 출현 순서대로 재생합니다. 연결로 루프 출처가 중복되어 자동 절단점 추론이 제한될 수 있습니다.

`EntryFrameBounds`는 `FrameBaseRegister` 진입 값 기준으로 주소가 순환하지 않는 `[Begin, End)` 범위를 명시합니다. 메모리 접근이나 비별칭 사실을 부여하지 않습니다. 생략하면 루트는 모듈러 연산 영역을 유지합니다. 네이티브 증명은 호출자 프레임 경계와의 일치를 요구하고 증거에 이를 결합합니다. LLVM 증명은 해당 프레임의 기존 영역을 유지합니다. 복구 자체는 동등성 인증서가 아닙니다.

## 실행 계약

현재 바이너리 어댑터는 매핑된 주소에 있는 링크된 x64 ELF 및 PE 이미지를 받습니다. 매핑, 바이트와 권한은 고정되어야 하며 동시에 변경되어서는 안 됩니다. 도달 가능한 기계어를 엄격하게 필요할 때 리프트합니다. 지원하지 않는 명령어, 호출, 불투명 연산, 메모리 순서가 있는 접근, 미해결 제어 흐름 또는 언어 수준 예외 처리를 만나면 복원을 중단합니다.

PE 복구에는 이미지 전체의 재배치 정보와 예외 레코드를 포함한 완전한 메타데이터가 필요합니다. CLI는 이를 먼저 불러온 뒤 `--func`를 적용합니다. C API 호출자는 미리 `neverd_session_restrict_function()`으로 세션을 제한하면 안 됩니다. 생략된 메타데이터로 수정 항목이나 예외 간선의 부재를 증명할 수 없으므로, 바이너리 어댑터는 함수 집합을 제한하여 불러온 이미지를 거부합니다.

아래 PE 근거가 없을 때 이미지 읽기를 상수로 취급하려면 범위 전체가 파일에 의해 뒷받침되는 읽기 전용 영역이어야 하며, 겹치는 매핑이나 로더 수정이 없어야 합니다. 쓰기 가능한 표, 미해결 재배치, 런타임에서 채취한 스냅샷은 불변 읽기의 근거가 아닙니다. COPY 재배치와 구조가 불완전한 예외 디렉터리는 거부합니다. PE 디렉터리와 함수 범위가 완전하다면 다른 함수의 해석되지 않은 핸들러 때문에 현재 진입점의 분석을 막지는 않습니다. 복구가 그 핸들러가 적용되는 코드에 도달하면 거부합니다.

`PEFixedImageView`는 기본 이미지 베이스에서 완전한 x64 PE 이미지를 인증합니다. 원시 헤더, 유일한 매핑, 완전한 DIR64 필드와 일반 가져오기 쓰기 범위를 검사하며 IAT 바이트는 제외합니다. TLS, load-config, 지연／바인딩된 가져오기, CLR 및 알 수 없는 쓰기 메커니즘은 거부합니다. 복구와 네이티브／LLVM 증명은 같은 스냅샷에 결합됩니다. C++ 옵션 `MaxImagePreparationBytes`와 `MaxImagePreparationRecords`의 기본값은 64 MiB와 65536이며, 소진 시 `BudgetExceeded`를 보고합니다. 사용 중 이미지는 변경되면 안 됩니다. 이는 ASLR, 초기화 또는 압축 해제의 동등성을 증명하지 않습니다.

정렬 프레임 복구는 진입 루트의 하위 비트 나머지를 모두 분할하고 상위 비트는 자유롭게 유지합니다. 명시적 진입 분기를 생성하며, 일정한 변위를 증명한 뒤 원래 루트의 기호 메모리 영역을 공유합니다. 스필, 별칭 무효화, 문맥 병합은 분할 식별을 보존합니다. 후보를 작은 순서로 시도하므로 무관한 큰 마스크가 최대 분할을 강제하지 않습니다. 문맥 및 정밀화 한도가 분할과 재시도를 제한하며 노드, 연산, 평가, 솔버 질의는 누적 계산합니다. 분할 간 또는 중복 루프 출처에 대한 자동 native/LLVM 증명 집계는 아직 지원하지 않습니다. 기존 검사기는 실제 경로 조건이 보장하는 변위를 증명할 수 있습니다. 명시적 물리 스택 의미론에서는 정규 인코딩의 내부 `RET imm16`이 기존 반환 슬롯을 읽고 RSP에 8바이트와 부호 없는 정리량을 더합니다. 외부 반환은 정리량이 0이어야 하며 이 투영은 접두사가 있는 반환 인코딩을 거부합니다.

반복 전송은 횟수와 방향이 완전히 증명되면 64비트 주소와 1/2/4/8바이트 요소를 지원합니다. 명시적 기계 상태에서 횟수 0은 메모리에 접근하지 않으며 방향 증명도 필요 없습니다. 일반 ABI는 바인딩되지 않은 플래그를 계속 거부합니다. 각 스칼라 접근에는 기존 별칭 및 반환 슬롯 검사가 적용됩니다. 완전히 복사된 프레임 포인터는 간선 투영 전에 실제 메모리로 다시 증명합니다. 알 수 없는 횟수, 예산 소진, 세그먼트 접근 및 더 좁은 주소 크기는 거부합니다. 이 원본 REP 명령의 네이티브 미정의 효과 인증은 아직 지원하지 않습니다.

소스 복원 대상은 일반적인 ABI 반환을 따라야 합니다. 외부에서 유래한 모든 저장 대상 범위는 진입 시 반환 주소 슬롯과 겹치지 않아야 합니다. 이는 호출자와 환경이 충족해야 하는 명시적 전제이며 외부 정수로 계산한 주소에도 적용됩니다. 프레임 출처 정보가 없다는 사실만으로 숫자 주소가 겹치지 않음을 증명할 수는 없습니다. 프레임에서 파생된 저장 주소는 해당 슬롯과 겹치지 않음을 증명해야 하며 반환 시 원래 스택 포인터를 복구해야 합니다. 출처 정보는 스필과 합류를 거쳐 유지됩니다. 아핀 식을 잃었다고 해서 외부 포인터로 재분류하지 않습니다. 현재 스택 피벗, 피호출자가 스택을 추가로 정리하는 반환, RET 기반 디스패치는 거부합니다. 바이너리 어댑터는 x64 리틀 엔디언 의미론을 적용합니다.

이 과정은 분석용 소스와 IR을 생성합니다. 재배치, 스택 풀기, 비동기 예외 또는 바이너리 교체의 안전성을 입증하지 않습니다. patch 모드는 이 옵션을 거부합니다. 모든 인터프리터나 보호 설정을 지원한다는 의미도 아닙니다.

형식이 정확히 일치하는 x64 `PUSHFQ`/`POPFQ`는 잔여 프로그램에 유지됩니다. 분석은 기계 플래그의 각 스냅샷을 알 수 없는 런타임 값으로 취급하고, 리프터는 별도로 모델링한 산술 플래그를 결합합니다. 플래그 복원도 런타임 효과로 남습니다. 알 수 없는 플래그에서 유래한 주소에는 외부 포인터의 반환 주소 슬롯 비중첩 계약을 적용할 수 없으며, 파생된 디스패치 대상의 범위가 증명되지 않으면 복구가 실패합니다.

전체 플래그 이미지를 저장하기 전에 모델링한 모든 산술 플래그와 방향 플래그가 복구 대상 함수 안에서 정의되어 있어야 합니다. 플래그를 직접 읽을 때도 기호식 단순화로 값이 상쇄되더라도 도달 가능한 모든 선행 경로에서 정의되어야 합니다. 그렇지 않으면 알 수 없는 레지스터 트랩이 포함된 C 소스를 출력하지 않고 복구를 거부합니다.

LowIR 임시 값은 리프트한 네이티브 명령 하나 안에서만 유효합니다. 읽는 모든 바이트는 같은 명령 안에서 먼저 정의되어야 하며, 이전 명령에서 쓴 오프셋을 재사용하거나 미정의 값이 대수적으로 상쇄되는 것은 소스의 정당성을 입증하지 못합니다. 진입 상수는 물리 레지스터에만 바인딩할 수 있습니다.

## 명시적 머신 상태 복원

```sh
neverd decompile program --func entry --devirtualize --vm-machine-state \
  --recovery-report machine-report.json -o machine.c
```

`--devirtualize --vm-machine-state` 또는 `neverd_devirtualize_machine_source_v1()`은 별도 소스 ABI를 선택합니다. 인수는 정렬된 `uint64_t` 17개(RAX, RCX, RDX, RBX, RSP, RBP, RSI, RDI, R8~R15, RFLAGS)의 포인터입니다. 64비트 부호 없는 반환값이 0일 때만 성공이며, 0이 아니면 메모리 쓰기를 되돌리지 않습니다. 출력 상태는 마지막 RET의 주소 팝 직전입니다. 상태 영역은 게스트 메모리와 겹치면 안 되며 원래 매핑과 64비트 리틀 엔디언 호스트를 사용합니다.

원래 게스트 코드와 데이터 주소는 출력 레지스터에서 관찰되는 주소를 포함하여 정확한 숫자 값을 유지해야 합니다. 소스 생성 과정에서 이를 생성된 프로그램의 전역 객체 주소로 바꾸어서는 안 됩니다. 호출자가 필요한 원래 게스트 매핑을 제공하며, C 생성은 게스트 주소 공간을 재배치하지 않습니다. 증명과 복원 보고서는 계속 원래 입력 이미지를 참조합니다.

실행 조건은 CPL3/IOPL0, 섀도 스택 비활성, 비동기 이벤트 없음, 정상 무결함 실행입니다. 진입 플래그는 정규 값이고 TF/RF/VM/AC/VIF/VIP가 0이어야 하며 POPFQ의 TF/AC도 0이어야 합니다. 생성 소스가 이를 검사합니다. PUSHFQ/POPFQ는 명시 상태를 사용하고 RDSSP는 대상 레지스터를 유지하며 도달한 INCSSP는 거부합니다.  완전한 프레임 포인터 저장은 전파하지만 부분 쓰기나 별칭 가능성은 사실을 무효화합니다. 예외 메타데이터가 있어도 정상 경로만 다루며 예외 전달이나 언와인드 등가는 보장하지 않습니다. 보고서의 `sourceABI`와 `executionProfile`에 조건이 기록되며 기본 ABI 규칙은 그대로입니다.

이 머신 상태 ABI는 직접 near CALL과 유한 대상 집합을 완전히 증명한 레지스터 간접 near CALL을 지원합니다. 레지스터 간접 호출은 RSP를 변경하기 전에 원래 대상 레지스터를 캡처하고 실제 다음 명령 주소를 정확히 한 번 저장합니다.  내부 near RET는 완전히 증명된 유한 대상 집합에서 선택할 수 있습니다. 잔여 코드는 게스트 스택을 한 번 읽고 그 값을 캡처한 뒤 스택 포인터를 증가시키며, 캡처한 값으로 분기합니다. 보존된 진입 반환 슬롯에 도달하면 내부 프레임을 버린 뒤에도 바깥 호출로의 종료입니다. 알 수 없는 대상, 누락되거나 실행 불가능한 대상을 포함한 집합, 추가 스택 정리를 하는 외부 반환 및 임의 스택 전환은 거부합니다.

메모리 간접 near CALL도 명시적 머신 상태 ABI, 섀도 스택 비활성, 정상 무결함 실행 조건에서만 지원합니다. 메모리 피연산자는 세그먼트 재정의가 없는 정규 `r/m64` 인코딩이어야 하며 주소 크기 재정의(`addr32`)와 REX는 선택적으로 허용합니다. 공유 x64 유효 주소 및 LOAD 의미론이 먼저 대상을 읽은 뒤 RSP를 변경하고 실제 다음 명령 주소를 푸시합니다. 푸시가 대상 슬롯을 덮어써도 이 순서를 지키며 슬롯 주소를 읽어 온 호출 대상과 혼동하지 않습니다. 읽기 전용 포인터 슬롯이나 유한 테이블에는 불변 읽기 증거가 필요하고, 초기화가 증명된 게스트 스택 값도 완전한 유한 대상 증명이 필요합니다. 쓰기 가능한 슬롯의 초기 이미지 바이트나 실행 시점 스냅샷은 불변성의 증거가 아닙니다. 증명되지 않은 외부 읽기, 무효화된 스택 사실, 잘못된 대상, FS/GS 등의 세그먼트 재정의, far CALL 및 추가되거나 비정규적인 접두사는 거부합니다. 기본 소스 ABI는 여전히 네이티브 호출을 거부합니다.

기본 일반 소스 ABI는 호출 전용 프레임을 재구성합니다. 외부에서 유래한 모든 LOAD/STORE 범위(계산된 주소 포함)는 원래의 전용 프레임 및 재구성된 소스 저장 공간과 겹치지 않아야 한다는 명시적 전제가 있습니다. 공유 증명은 프레임 주소의 외부 유출, 그 주소에 의존하는 결과나 분기, 초기화되지 않은 바이트 읽기를 거부합니다. 명시적 머신 상태 ABI는 원래 게스트 주소를 유지하며 이 전제를 사용하지 않습니다.

정의되지 않은 플래그가 제어 흐름, 주소 또는 정의된 출력에 영향을 줄 수 있다면 별도의 비간섭 증명이 필요합니다. 현재 복구 보고서는 이 증명을 제공하지 않으며 이러한 프로세서 의존 동작을 보증하지 않습니다.

`modelInterpreterMachineStateX64`는 소스 래퍼와 같은 생성기로 `InterpreterMachineStateModel`을 반환합니다. 레지스터 바이트 `[0, 136)`은 원시 17워드 상태 객체를 나타내고, `RETURN`은 게스트 RAX와 별도로 상태를 반환합니다. 게스트 메모리 접근은 메모리 접근으로 유지됩니다. 잘못된 진입 플래그와 거부된 동적 플래그 쓰기는 실패 상태를 계속 유지합니다. 상태 저장소는 접근 가능하고 정렬되어야 하며 게스트 접근과 겹치지 않아야 합니다. `MaxOperations`는 입력 메타데이터와 생성 연산을 제한합니다. 결정적 LowIR 기록은 원래 아키텍처의 미정의 출력 증거가 아닙니다. 호출자는 관찰 항목, 진입 및 프레임 계약과 새로운 `checkLowIRLoopRefinement` 또는 유한 경로 정제 증명을 제공해야 합니다. 모델과 기록 생성은 컴파일된 C를 인증하지 않습니다.

`modelLLVMInterpreterMachineStateX64`는 상태 포인터 하나를 받고 i64 상태 코드를 반환하는 검증된 스칼라 LLVM 함수를 모델링합니다. `llvmInterpreterMachineStateContract`는 17개 워드를 모두 관찰하고 별도 `LLVMInterpreterDefinednessOffset` 바이트가 초기값 0을 유지하도록 요구합니다. 진입 도메인과 게스트 프레임을 추가해도 이 의무를 유지해야 합니다. PHI 복사는 병렬이며 정수 오버플로, 정확한 시프트, 범위 속성 등은 증명할 조건으로 변환됩니다. 죽은 코드나 select가 [LLVM 의미론](https://llvm.org/docs/UndefinedBehavior.html)에 따라 poison을 가릴 수 있어도 실행된 지원 연산은 모두 poison이 없어야 합니다. `MaxInputItems`, `MaxBlocks`, `MaxOperations`, `MaxWork`가 구성을 제한합니다. 미지원 타입, 포인터 유출, 메모리 모드, 호출, 속성, 메타데이터는 명시적으로 거부합니다. i8/i16/i32/i64의 가변 `shl`, `lshr`, `ashr`는 ISA 시프트 마스크를 적용하지 않고 부호 없는 시프트 양이 소스 비트 폭보다 작음을 요구합니다. `nuw`, `nsw`, `exact`는 별도로 검사합니다. 나눗셈과 freeze는 지원하지 않습니다. 새 완전 유한 경로 또는 귀납 검사가 정의성, 메모리 안전성, 관찰값과 종료를 증명해야 하며 자동 루프 후보 추론은 불완전합니다. 정확한 소스, 모듈, 컴파일러 입력은 별도로 결합해야 합니다. 파서와 컴파일러는 신뢰 전제로 남으며 이 API는 C, 생성 기계어 또는 실제 CPU의 미정의 비트 선택을 인증하지 않습니다. 소스 계약은 [LLVM 언어 참조](https://llvm.org/docs/LangRef.html)를 참고하세요. 읽는 진입 바이트는 초기화되어야 하며 게스트 접근은 선언된 프레임의 유효한 저장소를 가리켜야 합니다. 평탄한 LowIR 메모리는 LLVM 객체 수명이나 포인터 출처를 증명하지 않습니다.

`initializes`는 상태 객체 안의 서로 떨어진 바이트 범위만 허용합니다. 제한된 필수 데이터 흐름 분석은 선언된 각 바이트를 읽기 전과 모든 정상 반환 전에 일반 저장 명령으로 초기화할 것을 요구합니다. 부분 저장과 고정 포인터 별칭은 같은 바이트 사실을 공유하며 게스트 저장은 초기화에 포함하지 않습니다. 진입 시 초기화된 선언 집합은 비어 있으므로 역방향 간선의 저장으로 첫 반복의 읽기를 정당화할 수 없습니다. atomic/volatile 접근과 알 수 없는 상태 별칭은 계속 거부합니다. 범위 목록 요소는 검증 전에 `MaxInputItems`에 포함하고 고정점 계산은 `MaxWork`를 공유합니다. 이 보수적 검사는 경로 상관관계에 의존하는 유효한 코드를 거부할 수 있지만 증명을 얻으려고 속성을 제거하지 않습니다.

`prepareInterpreterLLVMRefinement`는 정확한 LLVM 텍스트와 선택한 함수 이름을 저장하고 모듈을 검증한 후, 진입에서 한 번만 플래그를 정규화하는 두 상태 모델을 준비합니다. `checkBinaryLLVMRefinement`는 입력을 재구성하여 실제 네이티브 이미지와 동일한 잔여 프로그램, 그 모델과 LLVM 산출물의 관계를 순서대로 증명합니다. 유한 경로와 귀납 검사는 모든 상태 워드, 실제 상태 코드, 정의 여부, 프레임 쓰기를 관찰하고 RSP와 반환 주소 슬롯의 보존을 요구합니다. 네이티브 진입 상수를 소스 계약에 복사하지 않습니다. 소스 관계는 임의의 범용 레지스터와 정규 플래그의 더 넓은 영역을 검사하므로 네이티브 제한에서만 유효한 결과를 보수적으로 거부할 수 있습니다. 루프 계획은 신뢰하지 않는 후보입니다. 두 검사가 모두 새로 성공해야 정확한 IR 바이트, 함수 이름, 두 증명 기록, 프로필 버전과 예산을 묶는 조합 기록을 생성합니다.

`MaxIRBytes`는 복사나 파싱 전에 텍스트와 함수 이름 크기를 제한하고, `MaxMachineStateOperations`와 `MaxPreparationItems`는 모델 생성 및 준비 작업을 제한합니다. 네이티브와 LLVM 증명 예산은 독립적이며 자동으로 늘리지 않습니다. 신뢰하는 LLVM 파서와 검증기에는 여기서 엄격한 CPU, 스택, 할당 상한을 적용하지 않습니다. 공유 프레임은 원시 RSP 워드를 루트로 하며 진입 반환 주소 슬롯을 포함해야 합니다. 초기화되고 살아 있는 프레임 저장소, 접근 가능하고 정렬되며 분리된 상태 저장소, 유효한 게스트 포인터 출처가 필요합니다. 이 C++ API는 지원하는 네이티브에서 LLVM으로의 관계를 증명하며 C 컴파일, 생성된 기계 코드, 오류 동작, 실제 CPU의 미정의 비트 선택은 증명하지 않습니다.

구조화된 머신 상태 C는 일반 반환 블록 사이에서 16개 GPR 쓰기 복원을 공유할 수 있습니다. 패킹된 플래그는 각 반환 경로에서 쓰며, 정렬 거부 시에는 여전히 아무것도 쓰지 않습니다. 상태는 네이티브 RET의 팝 전에 캡처하고 잘못된 프로파일 상태는 유지합니다. LLVM 출력은 자체 최적화를 위해 인라인 반환 꼬리를 유지합니다. 기존 C++ 래퍼와 모델 오버로드는 `InlineReturns`를 유지하며, 명시적인 `InterpreterMachineStateLayout::SharedGPRExit` 레이아웃은 두 경우 모두 같은 의미 생성기를 사용합니다. 잘못된 레이아웃 값은 거부합니다. 완전한 일반 합류나 새 주소 공간을 확보하지 못하면 기존 인라인 형태를 유지합니다. 독립 모델 검사와 두 C 백엔드의 O0/O2 테스트는 경로별 플래그, 부분 레지스터 쓰기, 루프, 메모리 카나리 및 정렬 거부를 검증합니다. 소스 압축은 일반 ABI나 네이티브 동등성 인증서를 제공하지 않습니다.

`LowFunc::FunctionTemporaries`는 오프셋순으로 정렬되고 겹치지 않으며 진입 시 정의되지 않은 바이트 범위를 선언합니다. 복구기는 유한 분기가 명령 경계를 넘기 전에 임시 간접 대상을 예약된 함수 내부 슬롯에 한 번만 저장합니다. 공통 관계 검사기는 현재 경로에서 실제로 정의한 바이트만 유지하며 일반 네이티브 임시 값은 명령마다 만료됩니다. 범위 메타데이터와 스냅샷 생성은 예산에 포함되고 인증서 의미 스키마 13이 수명을 바인딩합니다. 원시 상태 모델은 바이트 의미를 보존하며 소스 생성은 슬롯 전체와 정확히 일치하는 피연산자를 요구하고 바이트 별칭을 거부합니다. 절단점 상태가 이 값을 바인딩하지 않으므로 귀납적 루프 증명과 추론은 현재 이 선언을 거부합니다. 진입 가정이나 네이티브 ABI 인증을 추가하지 않습니다.

## 현재 제한 사항

입력 의존 바이트코드 주소와 디코더 상태 관계는 필요한 유한 값 영역과 상관관계를 설정된 한도 안에서 증명할 수 있을 때만 지원합니다. 임의의 간접 디코딩 방식을 지원한다는 뜻은 아닙니다. 모든 디스패치 대상을 증명하면 동적 분기와 루프를 복원할 수 있지만 일반 분기 테스트가 모든 방식의 지원 근거는 아닙니다. 미해결 제어 흐름이나 필요한 증명 예산 소진은 실패이며 소스나 부분 교체 코드를 내보내지 않습니다. 네이티브 보조 함수 호출, 예외／재진입 경계, 변경 가능한 코드와 다른 아키텍처는 여전히 실행 계약 밖에 있습니다.

## 공유 구현

`SpecializationProvider`는 완전히 리프트된 명령어와 불변 읽기의 근거를 제공합니다. `NeverDInterpreterSpecialization`은 기존 `SymExec` 의미론으로 정수 및 제어 연산을 부분 평가합니다. 바이너리 어댑터는 매핑과 명령어 디코딩을 담당하며 별도의 명령어 평가기를 구현하지 않습니다.

유한한 기호 읽기 주소에 대해 내장 비트벡터 솔버가 현재 제약 아래에서 후보 주소를 열거합니다. 마지막 UNSAT 결과가 다른 주소가 없음을 증명하고 모든 후보에 불변이며 메모리 오류를 일으키지 않는 읽기라는 완전한 근거가 있을 때만 집합을 채택합니다. 이처럼 증명된 LOAD는 LowIR에서 주소를 한 번 저장하고 정확한 값을 고르는 SELECT 체인으로 바꿀 수 있습니다. 증명되지 않은 일반 읽기는 동적으로 유지합니다. 한 주소의 표본으로 전체 집합을 대신하지 않습니다. 선택한 제어 레지스터와 진입 프레임 슬롯의 크기가 제한된 결합 튜플을 노드 사이에 유지하여 커서와 디코딩 키의 관계를 보존할 수 있습니다. 합류와 확장은 보수적으로 수행합니다. 부분 SAT 표본이나 unknown 결과는 주소 또는 대상 집합의 완전성을 증명하지 않습니다. 이 방식은 선택적 Z3 백엔드에 의존하지 않습니다.

노드는 네이티브 명령어 커서, 명령어 모드, 선택한 제어 레지스터와 진입 프레임 슬롯의 상수로 식별됩니다. 다른 바이트 단위 사실은 교집합으로 합류합니다. 들어오는 사실이 약해지면 노드를 다시 평가합니다. 따라서 프로그램 자체의 루프를 관찰된 반복마다 펼치지 않고 루프로 유지합니다. 간접 대상의 도달 가능한 모든 값은 완전성이 증명된 유한 집합에 속해야 합니다. 해석된 대상은 잔여 코드의 명시적 비교와 CFG 간선으로 바뀝니다.

동적 연산과 일반 load/store는 LowIR에 남습니다. 스칼라 상수, 진입 프레임 기준 아핀 포인터, 상수임이 증명된 프레임 바이트는 노드 사이에 전달할 수 있습니다. 다른 식은 무한히 펼치지 않고 버립니다. 프레임 메모리는 기존 기호 상태의 보수적인 별칭 무효화 규칙을 따릅니다. 별칭일 수 있는 알 수 없는 포인터를 통한 쓰기는 충돌하는 사실을 무효화합니다. 스택 슬롯을 전용 메모리로 가정하거나 증명되지 않은 비별칭 계약으로 제거하지 않습니다.

복제된 컨텍스트는 고유하게 합성한 명령어 레이블로 구분합니다. 원래 명령어 경계는 별도의 출처 맵에 보존하며, 원래 재배치·예외·점프 테이블의 증명 정보를 새 명령어 인스턴스에 복사하지 않습니다. 복원된 LowIR은 HighC/LLVM 경로가 나뉘기 전에 일반 LowIR-to-MedIR 변환으로 들어갑니다. 따라서 레지스터, 스택, CFG, SSA 및 ABI 처리를 공유합니다. HighC 경로의 복원도 MedIR 검증에 성공해야 합니다.

노드 수, 주소별 컨텍스트 수, 연산 수, 노드 평가 횟수 및 유한 대상 수에 대한 예산이 분석량을 제한합니다. 예산을 소진하거나 지원하지 않는 의미론을 만나면 잔여 함수를 내보내지 않습니다. 제어 그래프의 완성과 소스 생성 성공은 별도의 조건입니다. 공개 API는 둘 다 검사하고 구분하여 보고합니다.

유한 읽기 주소 집합, 결합 제어 튜플 및 제어 필드 수에도 명시적 한도가 있습니다. 전체 솔버 쿼리 수와 쿼리별 게이트·충돌·전파·감시 리터럴 방문 한도가 증명 작업을 제한하며 기호 노드 한도는 식의 성장을 제한합니다. JSON 보고서에는 이 예산과 `solverQueries`, `relationalWidenings`가 포함됩니다.

`AllowOverlappingNativeInstructions`는 유한 네이티브 독립성 증명과 네이티브에서 LowIR로의 정제에 사용하는 별도 옵션이며 기본값은 꺼짐입니다. 각 진입점을 독립적으로 디코딩하고 검증하며, 겹치는 명령어 바이트는 후보의 읽기를 포함한 모든 이전 명령어 및 불변 읽기 증거와 일치해야 합니다. 후보 LowIR 주소는 레이블이며 바이트 증거가 아닙니다. `MaxNativeInstructionBytes`의 기본값은 1048576이며, 새로 가져온 각 진입점의 전체 명령어 크기를 중복 바이트까지 포함하여 비교 전에 차감합니다. 예산 소진이나 바이트 충돌은 인증서를 거부합니다. 옵션과 한도는 증명 다이제스트에 포함됩니다. 정적 LowIR, 귀납적 루프 증명과 추론은 빈 루프 계획에서도 이 옵션을 거부합니다. 정확한 LLVM API와 CLI의 기본 동작은 유지됩니다.

## 근거와 테스트

선택적 로컬 JSON 보고서는 입력 다이제스트, 선택한 제어 항목, 예산, 상태, 작업량 카운터, 잔여 블록 수, 원래 명령어 위치 및 복원에 사용한 불변 바이트를 포함합니다. 입력에서 파생된 정보가 들어 있으며 지정한 로컬 경로에만 기록합니다.

공개 테스트는 직접 작성한 레지스터 기반 스레드형 디스패치 머신과 스택 디스패치 머신을 사용합니다. 각각 산술, 분기／합류 및 런타임 루프 프로그램을 포함합니다. 독립적인 부호 없는 연산 참조 구현이 반환값, 메모리 쓰기, 올림／빌림 결과와 출력 카나리를 확인합니다. 복원된 HighC와 LLVMC는 정의되지 않은 동작 트랩을 켜고 O0/O2로 컴파일한 뒤 참조 구현과 실행 결과를 비교합니다. 부정 사례는 미해결 디스패치, 쓰기 가능한 디스패치 표, 호환되지 않는 바이트 순서, 예외 메타데이터 및 예산을 검증합니다.

추가로 직접 작성한 유한 주소 fixture는 입력으로 선택한 읽기 전용 레코드, 상관관계가 있는 커서／키 제어 필드, 서로 다른 가상 위치에서 재사용하는 같은 핸들러를 사용합니다. 분기／합류 및 실행 중 프로그램 상태에 따라 레코드를 고르는 루프를 다룹니다. 독립적인 네이티브 참조 구현은 SysV와 Win64 호출 규약을 사용합니다. 두 복원 C 경로는 O0/O2, 정의되지 않은 동작 트랩과 출력 카나리로 검사합니다. 읽기 근거 누락이나 증명 예산 부족으로 부분 결과를 내보내서는 안 됩니다.

확장 테스트 행렬은 직접 스레드 방식의 포인터 바이트코드, 중첩 가상 호출을 가진 유계 소프트웨어 CALL/RET 스택, 회전하는 opcode 복호화 상태를 가진 루프라는 세 독립 형태를 수동 제어 힌트 없이 복원하도록 요구합니다. 네이티브 SysV/Win64 실행과 복원한 HighC·LLVMC를 O0/O2에서 독립 수학 참조 구현과 비교하고 출력 카나리도 검사합니다. 알 수 없는 가상 반환 커서, 제약 없는 복호화 키 및 예산 소진 시 소스를 게시해서는 안 됩니다.

별도 머신 상태 행렬은 네이티브 실행과 두 복원 C 경로가 O0/O2에서 16개 일반 레지스터, 정의된 플래그 및 검사하는 게스트 스택의 모든 바이트에 대해 일치하도록 요구합니다. 레지스터 간접 CALL의 피호출 코드는 대상 레지스터를 읽고 덮어쓰며, 반환 스레드 분기는 알려진 대상 중에서 선택합니다. 참조 구현은 실제 다음 명령 주소 저장, 플래그 유지와 RSP 복원을 검사하고 예상 코드 주소는 심볼에서 구합니다. 알 수 없거나 잘못된 대상 집합 및 증명되지 않은 메모리 대상은 소스 없이 실패해야 합니다. 이는 독창적 fixture의 검증 요구이며 임의 가상 머신이나 보호 제품의 지원을 보장하지 않습니다. 이 독창적 fixture는 로컬 x64 Linux에서 위 검증을 통과했습니다.

공개 메모리 호출 fixture는 불변 RIP 상대 포인터 슬롯, 입력으로 선택하는 유한 읽기 전용 테이블, 초기화되고 대상이 유한한 게스트 스택 슬롯, CALL 자체의 푸시가 덮어쓰는 대상 슬롯을 다룹니다. 로컬 x64 Linux에서 네 가지 형태 각각의 1,024개 상태를 네이티브 실행, HighC, LLVMC의 O0/O2로 검증했습니다. 독립 참조 구현은 전체 17개 상태 워드와 128바이트 게스트 스택을 비교하며 피호출 코드가 관찰하는 반환 주소도 포함합니다. 증명되지 않은 외부·쓰기 가능 슬롯, 별칭 쓰기로 손상된 스택 값, 잘못된 대상 및 기본 소스 ABI 호출은 게시를 거부해야 합니다.

별도 고정 주소 실행 회귀는 원래 입력 이미지 주소에 쓰기 가능한 게스트 메모리를 제공합니다. 두 C 백엔드는 O0/O2에서 해당 매핑을 읽고 쓰며, 출력 레지스터에 원래 게스트 주소의 숫자 값을 유지하고 인접 카나리를 변경하지 않아야 합니다. 생성된 전역 객체로 대체하면 이 참조 구현을 만족하지 못합니다. 이 로컬 검증은 임의 VM 지원을 의미하지 않습니다.

집중 테스트 대상은 [testing.md](testing.md)를 참조하세요.

## 자동 루프 증명 후보

아래 접두 경로 술어 유지 요구는 `GeneralizeEntryPrefix = false`일 때 적용됩니다。

`inferLowIRLoopRefinementPlan`은 공유 기호 실행기로 예산 내 템플릿을 제안합니다. 피드백 절단점은 CFG의 모든 순환을 덮으며, 확장은 증명된 고정 비트를 유지하고 보존되지 않는 부호 없는 접두 경계를 제거합니다. 관측된 단위 증감 카운터와 추론한 단계 상수로 사전식 순위를 구성하여 증가·감소 중첩 루프를 처리합니다. `OriginalPrefix`와 `CandidatePrefix`에는 `UseEntryPrefix`가 필요합니다. 앞선 절단점 뒤의 절단점은 실제 진입점에서 별도로 제한된 재실행을 수행하여 도달 가능한 대응 접두 증거를 얻을 수 있습니다. 이 증거는 전체 진입 영역을 덮지 않습니다. 모든 실제 도달 상태가 그 술어를 함의해야 하며 진입 및 전이 경로의 완전한 검증은 여전히 필수입니다. `inferAndCheckBinaryLowIRLoopRefinement`은 완전한 복원과 유일한 네이티브 출처를 요구하고 원본/후보 전체 검사를 독립적으로 다시 수행합니다. 제안과 출처 매핑은 신뢰하지 않으며 `Refinement`만 인증서를 포함할 수 있습니다. 추론과 증명은 각각 명시적 예산을 사용합니다. 이 C++ API는 `--devirtualize`에서 자동 실행되지 않습니다. 도달 불가능한 접두, 임의 제어 정렬, 탐색 밖의 순위 유형, C 백엔드 동등성 및 실제 CPU의 미정의 비트 선택은 지원하지 않습니다.

단위 카운터 탐색은 기존 전체 워드 및 영 확장 형태를 먼저 시도한 뒤, 바깥의 모든 비트를 보존하는 바이트 정렬 부분 갱신도 인식합니다. 여러 절단점에서는 저장된 실제 도달 상태와 현재의 모든 유입 상태에서 증명한 경우에만 레인 끝값 제외 조건을 제안합니다. 확장은 실패한 조건을 제거하고 다시 추가하지 않으며, 이미 알려진 카운터 워드에서 나중에 다른 레인을 발견할 수 있습니다. 마스크는 기존 전체 워드 매개변수를 재사용하고 전체 워드 순위와 상태 관측을 유지합니다. 공유 노드·질의 예산과 독립적인 완전 정제 검사는 계속 적용됩니다.

여러 절단점에서는 관측된 카운터 튜플이 실패할 때마다 다음 튜플로 넘어가기 전에 64비트 상수 단계를 앞에 붙인 변형을 시도합니다. 두 변형은 각각 `MaxRankCandidates` 시도를 소비하며 같은 질의 예산을 공유합니다. 선행 단계는 모든 실행 가능한 전이에서 증가하지 않아야 합니다. 나머지 튜플의 엄격한 감소를 증명하지 못하는 전이는 단계 값의 엄격한 감소가 필요합니다. 음이 아닌 차이 제약은 양의 가중치 순환을 거부합니다. 따라서 순차 루프가 재초기화 후 카운터를 재사용할 수 있으면서 순환 내부의 실제 진행 의무는 유지됩니다. 기존 카운터 사이 단계와 선행 단계를 함께 사용할 수 있습니다. 완전한 튜플은 원래의 전체 전이 술어로 검사하고 최종 정제 검사기가 제안된 순위를 독립적으로 다시 검사합니다. 단일 절단점 검색에는 효과 없는 상수 접두부를 추가하지 않습니다.

단일 절단점 후보는 원래 도달 가능했던 모든 블록의 순환을 끊어야 하며, 절단점을 제거한 뒤 진입점에서 분리되는 순환도 포함합니다. 각 검사에서는 기호 실행 전에 `MaxCutpointAttempts`를 차감합니다. 모든 복귀 간선에서 단위 증감을 보이는 스칼라 카운터를 우선합니다. 이후 관찰된 단위 카운터 튜플 후보를 최대 8개까지 더 넓은 스칼라 가드·경계 가설과 하나씩 번갈아 시도합니다. 나머지 스칼라 가설을 처리한 뒤 튜플 탐색을 중복 없이 재개합니다. 이 순서는 예산 상한과 무관합니다. 튜플을 시도할 때마다 저장된 완전한 안정 템플릿과 전이를 복원하며, 튜플 영역 검사 실패는 해당 후보군만 비활성화합니다. 실패한 스칼라 가드로 그 영역을 좁힐 수 없습니다. `MaxRankCandidates`, 쿼리, 연산과 경로 예산은 계속 누적됩니다. 제안은 여전히 완전한 refinement 검사를 통과해야 합니다. 다른 분기가 값을 유지하거나 초기화하더라도 절단점으로 돌아오는 덧셈 점화식 분기는 구조적 확장을 유도할 수 있습니다. 제안된 템플릿은 여전히 모든 진입 및 전이 검사를 통과해야 합니다.

단일 절단점 검색은 일반화된 템플릿 실행이 보존 또는 메모리 계약을 위반하면 다른 허용 절단점을 시도합니다. 본문 절단점이 잃은 조건부 카운터 관계를 루프 헤더가 유지할 수 있습니다. 가설 하나의 실패가 모든 절단점을 거부하지는 않습니다. 실제 진입 경로 실패, 잘못된 입력, 미지원 실행과 예산 소진은 계속 중단 사유입니다. `MaxCutpointAttempts`와 솔버 쿼리를 포함한 모든 비용을 공유하며 새 후보도 새로운 완전한 증명을 거쳐야 합니다. 이 대안 검색은 다른 중첩 피드백 집합을 찾지 않습니다.

`GeneralizeEntryPrefix`의 기본값은 `false`이며 `UseEntryPrefix`가 필요합니다. 기본 모드는 모든 도착에서 캡처한 경로 술어를 유지합니다. 명시적 일반화 모드는 경로 밖의 접두 상태 식을 전역에서 정의되는 미검증 템플릿 함수로 취급합니다. 실행 가능한 쌍의 증거, 실제 진입 및 구간의 완전한 경로 포함, 전체 레지스터/프레임 일치, 매개변수 투영, 네이티브 실행 조건, 확장된 귀납 영역의 엄격한 순위 감소가 계속 필요합니다. 추론은 유입 상태가 증거 영역을 벗어날 때만 절단점을 확장하고 모든 일반 전이를 다시 구성하고 검사합니다. 첫 증거가 반복을 하지 않아도 다른 진입의 루프를 숨길 수 없습니다. 정책은 귀납 인증서 다이제스트에 바인딩됩니다.

중첩 추론은 관찰된 단위 변화 카운터와 제어 술어가 참조하는 변경되지 않은 접두 값 사이의 엄격하거나 비엄격한 부호 없는 경계 후보를 생성할 수 있습니다. 등식 종료도 포함합니다. 구체적인 진입/유입 상태를 먼저 확인하고 일반 유입 전이에서 성립하지 않는 관계를 단조롭게 제거합니다. 술어 순회와 솔버 작업은 기존 명시적 추론 예산을 사용하며 최종 원본/후보 검사기가 템플릿을 독립적으로 증명합니다.
