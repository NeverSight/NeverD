# 인터프리터 소스 복원

실험적 인터프리터 특수화 단계는 링크된 x64 함수에서 정적으로 해석할 수 있는 디스패치를 제거하면서 런타임 입력, 메모리 효과, 분기와 루프를 유지합니다. 핸들러 패턴이나 특정 보호기의 연산 코드 표가 아닌 명령어 의미론을 사용합니다.

```sh
neverd decompile program --func vm_entry --devirtualize \
  --recovery-report recovery.json -o recovered.c
neverd decompile program --func vm_entry --devirtualize \
  --llvm -o recovered-llvm.c
```

`--vm-control`은 인터프리터 컨텍스트를 구분할 전체 범용 레지스터를 선택합니다. 여러 번 지정할 수 있지만 구체적인 값을 제공하지는 않습니다. 예를 들어 진입 코드가 값을 설정하는 바이트코드 커서를 선택할 수 있습니다. 카운터로 쓰이는 런타임 입력은 동적인 상태로 유지해야 합니다. 서로 다른 커서 값이 합류할 때 필요한 컨텍스트 구분이 없으면 복원이 중단될 수 있습니다. 엔진은 이를 보완하려고 디스패치 대상을 추측하지 않습니다. 커서가 스택에 스필된 경우 `--vm-control-stack=-16:8`은 진입 시 RSP보다 16바이트 앞에 있는 8바이트를 선택합니다. 오프셋은 조정된 현재 스택 포인터가 아닌 함수 진입 시점을 기준으로 합니다.

C API는 `neverd/sdk/NeverDCAPIDevirtualize.h`의 `neverd_devirtualize_source_v1()`입니다. 별도 트랜잭션에서 실행되므로 세션의 일반 디컴파일 캐시를 변경하지 않습니다. 실패하면 소스를 반환하지 않으며 JSON 진단은 반환할 수 있습니다. 반환된 두 문자열은 모두 `neverd_free_string()`으로 해제합니다.

## 제어 상태 자동 탐색

CLI와 모든 버전의 소스 복원 C API는 기본적으로 자동 탐색을 활성화합니다. 특정 제공자에 종속되지 않는 C++ API에서는 `SpecializationOptions::DiscoverControlState = false`가 기본값이며 호출자가 `true`로 설정할 수 있습니다. 수동 `--vm-control` 및 `--vm-control-stack` 힌트는 선택적인 컨텍스트 키로 유지됩니다. 일반적인 자동 탐색 필드는 유한 값의 제한된 결합 관계만 보존하며, 컨텍스트 키를 추가하거나 런타임 입력을 표본 값으로 고정하지 않습니다. 아래의 선택적 메모리 정밀화에서 증명된 상수가 필요한 경우를 제외하면 일반 카운터는 동적으로 남습니다.

미해결 제어 흐름과 주소의 의존 관계에서 구조화된 노드 진입 레지스터 입력과 메모리 입력이 처음 생성된 출처를 추적하며, 좁은 바이트 범위도 처리합니다. 생성 출처가 노드 진입 이후 변경되지 않은 메모리를 가리키고 함수 진입 프레임 기준의 정확한 상대 범위를 식별할 때만 프레임 슬롯을 후보로 지정합니다. 같은 값이나 저장에서 전달된 값을 나중에 읽어도 추가 입력 의존 관계가 생기지 않으며, 메모리 정보가 무효화된 뒤 생성된 알 수 없는 바이트를 진입 슬롯으로 취급하지 않습니다. 과거 읽기 기록은 다른 분석에서 계속 사용할 수 있습니다. 누락된 의존 관계를 찾으면 함수 진입점부터 분석을 다시 수행합니다. 보존하는 각 관계에는 제약하는 비트에 대한 완전한 유한 값 증명이 여전히 필요하며, 별칭 가능성이 있는 쓰기는 메모리 사실을 무효화합니다. 임의의 외부 메모리나 무한한 상관 값이 자동으로 유한해지는 것은 아닙니다.

생산자 요구는 노드 경계를 넘어 비트 마스크를 유지하며 바이트 전체로 확대하지 않습니다. 다만 산술 연산에서는 요구된 비트에 올림이나 빌림을 전달할 수 있는 하위 비트 범위를 보수적으로 포함합니다.

이미 추적 중인 메모리 의존 관계 때문에 정확한 주소 증명이 반복해서 막히면, 추가 정밀화가 증명된 진입 상수를 컨텍스트 키로 승격할 수 있습니다. 여러 값의 튜플을 새로운 간선으로 분할하거나 컨텍스트 선택을 위해 게스트 메모리 읽기를 추가하지는 않습니다. 유한 값 증명만으로는 추가 읽기의 안전성을 입증할 수 없기 때문입니다. 따라서 동적이거나 무한한 메모리 의존 상태는 설정된 제한 내에서 복원을 멈추게 할 수 있습니다.

생산자에 대한 역방향 요구는 네이티브 노드 진입점, 명령 모드, 필드 종류와 바이트 범위로 식별합니다. 후속 노드가 해당 필드를 요구하는 간선만 생산자 의존 관계를 확장하며, 유한하지만 정밀도가 부족한 값의 범위도 포함합니다. 이 과정은 예산 내에서 진입점부터 다시 분석할 수 있지만, 재사용되는 물리 레지스터에 하나의 전역 역할을 부여하지는 않습니다. 의존 관계 탐색은 제한적이며 완전하지 않으므로, 모든 인터프리터를 수동 힌트 없이 복원할 수 있다고 보장하지 않습니다.

일반적인 자동 필드의 투영도 대상 노드의 요구 범위로 제한합니다. 상수가 아닌 필드는 대상 노드가 요구할 때만 간선의 결합 유한 값 관계에 포함됩니다. 수동 필드와 자동으로 컨텍스트 키로 승격된 필드는 계속 전역 투영 대상이 됩니다. 알려진 상수 바이트, 진입 프레임을 기준으로 한 정확한 포인터 및 출처 정보는 요구 여부와 관계없이 보존됩니다. 따라서 서로 다른 핸들러 단계의 무관한 필드 때문에 관계의 값 조합 수가 곱해지는 것을 막습니다. 설정된 예산과 제어 흐름 대상, 메모리 주소 및 반환 상태에 필요한 증명 조건은 바뀌지 않습니다.

일반 자동 필드에서는 각 튜플 열이 요구된 비트만 제약하고 해당 마스크를 가집니다. 합류에서는 모든 유입 경로에서 제약된 비트만 보존합니다. 같은 바이트의 다른 비트는 런타임 값으로 남습니다. 필드의 저장 범위가 그 전체 범위에 대한 완전한 유한 값 범위 증명을 뜻하지는 않습니다. 8개 비트가 모두 상수임이 증명되어야 바이트를 상수로 만들 수 있습니다.

수동 필드와 컨텍스트 키로 승격된 필드는 계속 전역적으로 전체 너비의 관계 증명을 먼저 시도합니다. 그 증명이 결론을 내리지 못하면 요구된 비트의 관계만 보존할 수 있습니다. 이 대체 경로는 증명되지 않은 바이트를 컨텍스트 키에 제공하거나 소진된 전역 예산을 우회하지 않습니다.

새 그래프로 재분석할 때 다른 필드에 완전히 포함된 일반 자동 저장 범위는 해당 넓은 필드를 함께 사용할 수 있습니다. 원래 단계의 위치와 비트 요구는 바뀌지 않습니다. 수동 필드, 컨텍스트 필드 및 미해결 메모리 주소에서 직접 후보로 지정한 필드는 정확한 범위를 유지합니다. `MaxControlFields`는 이 정규화 후 실제로 보존되는 필드 수를 제한합니다. `DiscoveredControlFields`는 누적값이므로 활성 필드 수를 초과할 수 있습니다. 필드 한도와 전역 작업 예산은 늘리지 않습니다.

완전한 유한 값 범위 증명을 얻은 일반 자동 필드는 모든 생산자를 즉시 제어 필드로 추가하지 않습니다. 탐색은 이러한 의존 관계 후보를 기록하고, 복원이 계속 막혀 있으며 즉시 수행한 정밀화에서 후보가 나오지 않을 때만 활성화합니다. 컨텍스트 키로 승격된 필드는 계속 생산자 의존 관계를 즉시 확장합니다. 탐색 방문, 재분석 및 증명 작업에는 기존 누적 예산을 그대로 적용합니다.

완전한 유한 값 범위는 워드 전체의 값이 달라져도 개별 바이트가 상수임을 증명할 수 있습니다. 예를 들어 `{0, 0x100}` 범위의 최하위 바이트는 항상 0입니다. 열거된 모든 튜플에서 동일한 바이트만 대상 바이트 순서에 따라 상수로 보존하며, 다른 바이트는 동적으로 남습니다. 불완전한 열거, 솔버의 알 수 없음 결과 또는 증명 예산 소진에서는 이러한 사실을 얻지 않습니다.

유한 값 범위 증명은 정밀화에 따른 재분석을 포함해 한 번의 복원 실행 안에서 재사용할 수 있습니다. 크기가 제한된 캐시는 자유 변수의 일관된 이름 변경을 허용하면서 완전한 순서 있는 표현식 DAG를 비교합니다. 변수 공유 관계, 너비, 상수 비트, 연산자 부가 정보 및 투영 한도는 키에 포함됩니다. 완전한 값 범위와 범위가 한도를 넘는다는 증명만 저장합니다. 알 수 없거나 부분적인 결과는 저장하지 않으며, 캐시 미적중이나 용량 부족 시 일반 증명 경로를 사용합니다. 모든 전역 예산은 계속 적용되고 `solverQueries`는 실제 솔버 호출을 셉니다.

동일한 술어에서 도달 가능성이 증명되었다면, 변하는 열 하나의 완전한 값 범위와 다른 각 열의 증명된 단일 값으로 정확한 결합 관계를 결정할 수 있습니다. 여러 열이 변하면 여전히 결합 증명이 필요합니다. 마스크 열이 가능한 비트 값 전체를 포함하더라도, 입력 비트가 술어 및 다른 모든 열과 독립적임을 증명해야만 그 열을 생략할 수 있습니다. 공유 입력, 알 수 없는 결과 또는 불완전한 열거로 데카르트 곱을 가정하지 않습니다.

기본값은 수동·자동 필드 합계에 대해 `MaxControlFields = 16`, `MaxControlRefinements = 16`, `MaxDiscoveryVisits = 65536`입니다. 재시작은 전역 노드(합성 노드 포함), 연산, 평가, 솔버 쿼리, 탐색 방문 예산을 공유합니다. `contexts`는 네이티브 컨텍스트 수이며, `evaluatedOperations`, `nodeEvaluations`, `solverQueries`와 함께 시도 전체에 걸쳐 누적됩니다. 주소별 컨텍스트 수, 활성 네이티브 반환 슬롯, 제어 필드 수, 튜플 수는 각 시도 안의 구조적 제한입니다. 기본 솔버 쿼리 제한은 여전히 4096입니다. 예산 소진 시 부분 결과를 게시하지 않으며, `residualBlocks`는 최종 잔여 그래프만 나타냅니다.

CLI 옵션 `--vm-max-refinements=N`은 양의 정수를 요구하며 기본값은 16입니다. C 호출자는 `neverd_devirtualize_source_v2()` 또는 `neverd_devirtualize_machine_source_v2()`로 같은 한도를 설정할 수 있습니다. `neverd_devirtualize_options_v2`를 0으로 초기화하고 `base.struct_size = sizeof(neverd_devirtualize_options_v2)`와 `max_control_refinements`를 설정합니다(0이면 기본값 16 유지). 내장된 `base`에는 v1 옵션이 들어가며 두 reserved 멤버는 모두 0이어야 합니다. 기존 v1 레이아웃과 진입점은 바뀌지 않고 확장된 뒷부분을 무시합니다. 다른 작업 및 증명 예산도 계속 적용됩니다.

JSON 보고서에는 `discoverControlState`, `maxControlRefinements`, `maxDiscoveryVisits`, `discoveredControlFields`, `discoveredContextFields`, `controlRefinements`, `discoveryVisits`가 추가되어 활성화 상태, 제한 및 분석 작업량을 기록합니다. 필드를 찾았다는 사실만으로 복원 성공이 입증되지는 않습니다.

## 실행 계약

현재 바이너리 어댑터는 매핑된 주소에 있는 링크된 x64 ELF 및 PE 이미지를 받습니다. 매핑, 바이트와 권한은 고정되어야 하며 동시에 변경되어서는 안 됩니다. 도달 가능한 기계어를 엄격하게 필요할 때 리프트합니다. 지원하지 않는 명령어, 호출, 불투명 연산, 메모리 순서가 있는 접근, 미해결 제어 흐름 또는 언어 수준 예외 처리를 만나면 복원을 중단합니다.

PE 복구에는 이미지 전체의 재배치 정보와 예외 레코드를 포함한 완전한 메타데이터가 필요합니다. CLI는 이를 먼저 불러온 뒤 `--func`를 적용합니다. C API 호출자는 미리 `neverd_session_restrict_function()`으로 세션을 제한하면 안 됩니다. 생략된 메타데이터로 수정 항목이나 예외 간선의 부재를 증명할 수 없으므로, 바이너리 어댑터는 함수 집합을 제한하여 불러온 이미지를 거부합니다.

이미지 읽기를 상수로 취급하려면 범위 전체가 파일에 의해 뒷받침되는 읽기 전용 영역이어야 하며, 겹치는 매핑이나 로더 수정이 없어야 합니다. 쓰기 가능한 표, 미해결 재배치, 런타임에서 채취한 스냅샷은 불변 읽기의 근거가 아닙니다. COPY 재배치와 구조가 불완전한 예외 디렉터리는 거부합니다. PE 디렉터리와 함수 범위가 완전하다면 다른 함수의 해석되지 않은 핸들러 때문에 현재 진입점의 분석을 막지는 않습니다. 복구가 그 핸들러가 적용되는 코드에 도달하면 거부합니다.

소스 복원 대상은 일반적인 ABI 반환을 따라야 합니다. 외부에서 유래한 모든 저장 대상 범위는 진입 시 반환 주소 슬롯과 겹치지 않아야 합니다. 이는 호출자와 환경이 충족해야 하는 명시적 전제이며 외부 정수로 계산한 주소에도 적용됩니다. 프레임 출처 정보가 없다는 사실만으로 숫자 주소가 겹치지 않음을 증명할 수는 없습니다. 프레임에서 파생된 저장 주소는 해당 슬롯과 겹치지 않음을 증명해야 하며 반환 시 원래 스택 포인터를 복구해야 합니다. 출처 정보는 스필과 합류를 거쳐 유지됩니다. 아핀 식을 잃었다고 해서 외부 포인터로 재분류하지 않습니다. 현재 스택 피벗, 피호출자가 스택을 추가로 정리하는 반환, RET 기반 디스패치는 거부합니다. 바이너리 어댑터는 x64 리틀 엔디언 의미론을 적용합니다.

이 과정은 분석용 소스와 IR을 생성합니다. 재배치, 스택 풀기, 비동기 예외 또는 바이너리 교체의 안전성을 입증하지 않습니다. patch 모드는 이 옵션을 거부합니다. 모든 인터프리터나 보호 설정을 지원한다는 의미도 아닙니다.

형식이 정확히 일치하는 x64 `PUSHFQ`/`POPFQ`는 잔여 프로그램에 유지됩니다. 분석은 기계 플래그의 각 스냅샷을 알 수 없는 런타임 값으로 취급하고, 리프터는 별도로 모델링한 산술 플래그를 결합합니다. 플래그 복원도 런타임 효과로 남습니다. 알 수 없는 플래그에서 유래한 주소에는 외부 포인터의 반환 주소 슬롯 비중첩 계약을 적용할 수 없으며, 파생된 디스패치 대상의 범위가 증명되지 않으면 복구가 실패합니다.

전체 플래그 이미지를 저장하기 전에 모델링한 모든 산술 플래그와 방향 플래그가 복구 대상 함수 안에서 정의되어 있어야 합니다. 플래그를 직접 읽을 때도 기호식 단순화로 값이 상쇄되더라도 도달 가능한 모든 선행 경로에서 정의되어야 합니다. 그렇지 않으면 알 수 없는 레지스터 트랩이 포함된 C 소스를 출력하지 않고 복구를 거부합니다.

LowIR 임시 값은 리프트한 네이티브 명령 하나 안에서만 유효합니다. 읽는 모든 바이트는 같은 명령 안에서 먼저 정의되어야 하며, 이전 명령에서 쓴 오프셋을 재사용하거나 미정의 값이 대수적으로 상쇄되는 것은 소스의 정당성을 입증하지 못합니다. 진입 상수는 물리 레지스터에만 바인딩할 수 있습니다.

## 현재 제한 사항

입력 의존 바이트코드 주소와 디코더 상태 관계는 필요한 유한 값 영역과 상관관계를 설정된 한도 안에서 증명할 수 있을 때만 지원합니다. 임의의 간접 디코딩 방식을 지원한다는 뜻은 아닙니다. 모든 디스패치 대상을 증명하면 동적 분기와 루프를 복원할 수 있지만 일반 분기 테스트가 모든 방식의 지원 근거는 아닙니다. 미해결 제어 흐름이나 필요한 증명 예산 소진은 실패이며 소스나 부분 교체 코드를 내보내지 않습니다. 네이티브 보조 함수 호출, 예외／재진입 경계, 변경 가능한 코드와 다른 아키텍처는 여전히 실행 계약 밖에 있습니다.

## 공유 구현

`SpecializationProvider`는 완전히 리프트된 명령어와 불변 읽기의 근거를 제공합니다. `NeverDInterpreterSpecialization`은 기존 `SymExec` 의미론으로 정수 및 제어 연산을 부분 평가합니다. 바이너리 어댑터는 매핑과 명령어 디코딩을 담당하며 별도의 명령어 평가기를 구현하지 않습니다.

유한한 기호 읽기 주소에 대해 내장 비트벡터 솔버가 현재 제약 아래에서 후보 주소를 열거합니다. 마지막 UNSAT 결과가 다른 주소가 없음을 증명하고 모든 후보에 불변이며 메모리 오류를 일으키지 않는 읽기라는 완전한 근거가 있을 때만 집합을 채택합니다. 이처럼 증명된 LOAD는 LowIR에서 주소를 한 번 저장하고 정확한 값을 고르는 SELECT 체인으로 바꿀 수 있습니다. 증명되지 않은 일반 읽기는 동적으로 유지합니다. 한 주소의 표본으로 전체 집합을 대신하지 않습니다. 선택한 제어 레지스터와 진입 프레임 슬롯의 크기가 제한된 결합 튜플을 노드 사이에 유지하여 커서와 디코딩 키의 관계를 보존할 수 있습니다. 합류와 확장은 보수적으로 수행합니다. 부분 SAT 표본이나 unknown 결과는 주소 또는 대상 집합의 완전성을 증명하지 않습니다. 이 방식은 선택적 Z3 백엔드에 의존하지 않습니다.

노드는 네이티브 명령어 커서, 명령어 모드, 선택한 제어 레지스터와 진입 프레임 슬롯의 상수로 식별됩니다. 다른 바이트 단위 사실은 교집합으로 합류합니다. 들어오는 사실이 약해지면 노드를 다시 평가합니다. 따라서 프로그램 자체의 루프를 관찰된 반복마다 펼치지 않고 루프로 유지합니다. 간접 대상의 도달 가능한 모든 값은 완전성이 증명된 유한 집합에 속해야 합니다. 해석된 대상은 잔여 코드의 명시적 비교와 CFG 간선으로 바뀝니다.

동적 연산과 일반 load/store는 LowIR에 남습니다. 스칼라 상수, 진입 프레임 기준 아핀 포인터, 상수임이 증명된 프레임 바이트는 노드 사이에 전달할 수 있습니다. 다른 식은 무한히 펼치지 않고 버립니다. 프레임 메모리는 기존 기호 상태의 보수적인 별칭 무효화 규칙을 따릅니다. 별칭일 수 있는 알 수 없는 포인터를 통한 쓰기는 충돌하는 사실을 무효화합니다. 스택 슬롯을 전용 메모리로 가정하거나 증명되지 않은 비별칭 계약으로 제거하지 않습니다.

복제된 컨텍스트는 고유하게 합성한 명령어 레이블로 구분합니다. 원래 명령어 경계는 별도의 출처 맵에 보존하며, 원래 재배치·예외·점프 테이블의 증명 정보를 새 명령어 인스턴스에 복사하지 않습니다. 복원된 LowIR은 HighC/LLVM 경로가 나뉘기 전에 일반 LowIR-to-MedIR 변환으로 들어갑니다. 따라서 레지스터, 스택, CFG, SSA 및 ABI 처리를 공유합니다. HighC 경로의 복원도 MedIR 검증에 성공해야 합니다.

노드 수, 주소별 컨텍스트 수, 연산 수, 노드 평가 횟수 및 유한 대상 수에 대한 예산이 분석량을 제한합니다. 예산을 소진하거나 지원하지 않는 의미론을 만나면 잔여 함수를 내보내지 않습니다. 제어 그래프의 완성과 소스 생성 성공은 별도의 조건입니다. 공개 API는 둘 다 검사하고 구분하여 보고합니다.

유한 읽기 주소 집합, 결합 제어 튜플 및 제어 필드 수에도 명시적 한도가 있습니다. 전체 솔버 쿼리 수와 쿼리별 게이트·충돌·전파·감시 리터럴 방문 한도가 증명 작업을 제한하며 기호 노드 한도는 식의 성장을 제한합니다. JSON 보고서에는 이 예산과 `solverQueries`, `relationalWidenings`가 포함됩니다.

## 근거와 테스트

선택적 로컬 JSON 보고서는 입력 다이제스트, 선택한 제어 항목, 예산, 상태, 작업량 카운터, 잔여 블록 수, 원래 명령어 위치 및 복원에 사용한 불변 바이트를 포함합니다. 입력에서 파생된 정보가 들어 있으며 지정한 로컬 경로에만 기록합니다.

공개 테스트는 직접 작성한 레지스터 기반 스레드형 디스패치 머신과 스택 디스패치 머신을 사용합니다. 각각 산술, 분기／합류 및 런타임 루프 프로그램을 포함합니다. 독립적인 부호 없는 연산 참조 구현이 반환값, 메모리 쓰기, 올림／빌림 결과와 출력 카나리를 확인합니다. 복원된 HighC와 LLVMC는 정의되지 않은 동작 트랩을 켜고 O0/O2로 컴파일한 뒤 참조 구현과 실행 결과를 비교합니다. 부정 사례는 미해결 디스패치, 쓰기 가능한 디스패치 표, 호환되지 않는 바이트 순서, 예외 메타데이터 및 예산을 검증합니다.

추가로 직접 작성한 유한 주소 fixture는 입력으로 선택한 읽기 전용 레코드, 상관관계가 있는 커서／키 제어 필드, 서로 다른 가상 위치에서 재사용하는 같은 핸들러를 사용합니다. 분기／합류 및 실행 중 프로그램 상태에 따라 레코드를 고르는 루프를 다룹니다. 독립적인 네이티브 참조 구현은 SysV와 Win64 호출 규약을 사용합니다. 두 복원 C 경로는 O0/O2, 정의되지 않은 동작 트랩과 출력 카나리로 검사합니다. 읽기 근거 누락이나 증명 예산 부족으로 부분 결과를 내보내서는 안 됩니다.

집중 테스트 대상은 [testing.md](testing.md)를 참조하세요.

## 명시적 머신 상태 복원

`--devirtualize --vm-machine-state` 또는 `neverd_devirtualize_machine_source_v1()`은 별도 소스 ABI를 선택합니다. 인수는 정렬된 `uint64_t` 17개(RAX, RCX, RDX, RBX, RSP, RBP, RSI, RDI, R8~R15, RFLAGS)의 포인터입니다. 64비트 부호 없는 반환값이 0일 때만 성공이며, 0이 아니면 메모리 쓰기를 되돌리지 않습니다. 출력 상태는 마지막 RET의 주소 팝 직전입니다. 상태 영역은 게스트 메모리와 겹치면 안 되며 원래 매핑과 64비트 리틀 엔디언 호스트를 사용합니다.

실행 조건은 CPL3/IOPL0, 섀도 스택 비활성, 비동기 이벤트 없음, 정상 무결함 실행입니다. 진입 플래그는 정규 값이고 TF/RF/VM/AC/VIF/VIP가 0이어야 하며 POPFQ의 TF/AC도 0이어야 합니다. 생성 소스가 이를 검사합니다. PUSHFQ/POPFQ는 명시 상태를 사용하고 RDSSP는 대상 레지스터를 유지하며 도달한 INCSSP는 거부합니다. 직접 near CALL은 실제 스택 쓰기를 유지하고 내부 RET는 유일한 대상을 증명해야 합니다. 완전한 프레임 포인터 저장은 전파하지만 부분 쓰기나 별칭 가능성은 사실을 무효화합니다. 예외 메타데이터가 있어도 정상 경로만 다루며 예외 전달이나 언와인드 등가는 보장하지 않습니다. 보고서의 `sourceABI`와 `executionProfile`에 조건이 기록되며 기본 ABI 규칙은 그대로입니다.

기본 일반 소스 ABI는 호출 전용 프레임을 재구성합니다. 외부에서 유래한 모든 LOAD/STORE 범위(계산된 주소 포함)는 원래의 전용 프레임 및 재구성된 소스 저장 공간과 겹치지 않아야 한다는 명시적 전제가 있습니다. 공유 증명은 프레임 주소의 외부 유출, 그 주소에 의존하는 결과나 분기, 초기화되지 않은 바이트 읽기를 거부합니다. 명시적 머신 상태 ABI는 원래 게스트 주소를 유지하며 이 전제를 사용하지 않습니다.

정의되지 않은 플래그가 제어 흐름, 주소 또는 정의된 출력에 영향을 줄 수 있다면 별도의 비간섭 증명이 필요합니다. 현재 복구 보고서는 이 증명을 제공하지 않으며 이러한 프로세서 의존 동작을 보증하지 않습니다.
