# تدقيق وصيد أمان الذاكرة

يحلّل NeverD الثنائي المحمَّل بحثًا عن عائلتين من عيوب أمان الذاكرة ويبلّغ عنها JSON منظَّمًا. المساران يعملان على IR المرفوع المستقل عن الصيغة، لذا **PE/COFF وELF وMach-O أهداف من الدرجة الأولى ومتكافئة** — لا تُخفى نتيجة خلف ماسح أو جدول استيراد لصياغة واحدة.

| المسار | الأمر | يبلّغ عن |
|--------|--------|----------|
| **التدقيق (Audit)** | `neverd audit <binary>` | عيوب عمر كائنات الكومة وقراءات المكدس المحلية غير المهيأة |
| **الصيد (Hunt)** | `neverd hunt <binary>` | فيضانات النسخ الخطرة مع أدلة رمزية وقيم إدخال مرشحة؛ تكون `replayable=true` فقط مع خطة `process-input-v1` مكتملة |

يعيد المحرّك استخدام التنفيذ الرمزي ومحلّل المتجهات البتية الداخليين في NeverD للشواهد والقابلية للوصول. لا محلّل خارجي ولا آلة افتراضية ولا حاوية.

---

## الثابت الجوهري: الفشل المغلق

عملية غير مرفوعة، أو استدعاء لم يستعد مسار ABI وسائطه، أو هدف غير مباشر غير محلول، أو ميزانية مستنفدة، كلها تعطي **UNKNOWN** وليس SAFE. الوجهة التي لا تُستعاد سعتها UNKNOWN. الرفع الصارم يبقى كما هو؛ طبقة الأمان تضيف أحكامًا محافظة فوقه فقط.

تستخدم تأثيرات الاستدعاء دلالات عالم مغلق: لا ينطبق الملخص إلا إذا كانت شروطه المسبقة وكل التأثيرات ذات الصلة معروفة. يبقى التأثير المجهول أو الملخص القابل للتطبيق جزئيًا فقط UNKNOWN؛ ولا تفترض الطبقة أن الفجوة لا تفعل شيئًا أو أن الاستدعاء نجح.

## عقد الهوية حسب الصيغة

يتطلب المساران مسار الرفع (يستعيد الوسائط لكل استدعاء). تُسمّى كل دالة مستدعاة عبر نفس عرض الهوية الذي يستخدمه بقية NeverD. ترتيب اكتشاف معلومات التنقيح لا يتغيّر.

| الصيغة | التنقيح (حسب الأولوية) | حلّ الاستيراد / thunk |
|--------|------------------------|------------------------|
| **PE/COFF** | `--pdb`، دليل التنقيح أو `.pdb` المجاور، ثم `/MAP` من MSVC | فتحات IAT وthunk من `__imp_`، الاستيرادات الترتيبية |
| **ELF** | DWARF داخل الصورة، `*.debug` المنفصل، ثم MAP لـ GNU/LLD | تُحلّ بذور PLT إلى اسم الاستيراد |
| **Mach-O** | DWARF داخل الصورة، `.dSYM` المجاور، ثم `-map` لـ ld64 | ربط dyld / فتحات الرموز غير المباشرة ومساعدو البذرة |

`--pdb` / `--map` يسمّيان ملفًا مرافقًا ذا سلطة: فشل القراءة خطأ وليس تراجعًا صامتًا. `--no-debug` يقرأ الصورة وحدها على كل الصيغ.

تُستخدم تواقيع الإجراءات في PDB للتمييز بين المخصِّصات التي تُرجع قيمة ودوال التحرير من نوع `void`. أما الاسترجاع الغني للأنواع المحلية وأنواع المكدس من PDB فما زال محدودًا؛ وحين يتعذّر تحديد حجم دقيق للكائن، يتراجع الصيد إلى نموذج الإطار أو نقطة التخصيص ويُبلّغ UNKNOWN بدل اختلاق حجم.

### أولوية `name_source`

يحمل كل اكتشاف `name_source` يصف مصدر اسم الدالة المستدعاة حسب هذه الأولوية:

1. `rename` — إعادة تسمية من المستدعي
2. `import` — إدخال IAT (PE) أو PLT (ELF) أو dyld-bind / stub (Mach-O)
3. `export` / `symbol` — تصدير أو إدخال رموز صرّحت به الصورة مسبقًا
4. `pdb` / `dwarf` / `map` — رمز تنقيح يثبت عنصرًا نائبًا أو يطابق الاسم المصرّح به
5. `sig` — مطابقة توقيع
6. `synthetic` — عنصر نائب لروتين بلا اسم

`memcpy` مرتبط ثابتًا سمّاه DWARF يبلّغ `dwarf`؛ و`memcpy` مستورد يبلّغ `import` على كل الصيغ. مطابقة التوقيع لا تحلّ محل اسم أثبته المنقّح أو جدول الاستيراد أصلًا.

## كتالوج المصارف والمصادر

الكتالوج جدول قابل للضبط وليس مجموعة مضمَّنة. يعلن كل **مصرف** صنف الضعف ودوره (copy / format / alloc / free / realloc) وفتحات الوسائط المهمة (الوجهة والمصدر والطول والسعة). ويوفّر مصرف JSON من نوع copy أو format أيضًا تأثير استدعاء قابلًا للتنفيذ. يسمّي كل **مصدر** موفّر إدخال يتأثر بالمهاجم.

تقع المدخلات المدمجة في [`SafetySinks.def`](../include/neverd/safety/SafetySinks.def) و[`SafetySources.def`](../include/neverd/safety/SafetySources.def)، وتغطي عائلة النسخ الشائعة في وقت تشغيل C (`memcpy`/`memmove`/`strcpy`/`strcat`/`strncpy`/`gets`/…)، ومتغيرات `_chk` المحصَّنة (حدّ وجهة صريح)، وعائلة التخصيص والتحرير (`malloc`/`calloc`/`realloc`/`free` وعاملا `new`/`delete`)، وواجهات كومة Win32 الاختيارية. مصادر الإدخال تشمل POSIX (`getenv` و`read` و`recv` و`fgets` و`fread` و`scanf` ووسائط البرنامج) **و** Win32 (`GetCommandLineA/W` و`ReadFile` و`GetEnvironmentVariable*`)، فلا يقتصر صيد PE على مدخلات POSIX.

تُطوى تهجئات الصيغ على إدخال واحد: تُزال الشرطات السفلية البادئة (`_malloc` و`___strcpy_chk`) وتُطابق عوامل `new`/`delete` المُشوَّهة عبر أسماء مستعارة.

عند حذف `effect` من مصرف JSON من نوع copy أو format، تُستنتج قابلية التطبيق من أعلى فتحة وسيط مشار إليها. يتطلب copy حينها عدد الوسائط الدقيق ذاك، بينما يقبل مصرف format الاستدعاءات من ذلك الحد الأدنى إلى الحد الأقصى متغيّر الوسائط. ويمكن لكائن `effect` اختياري أن يحدد صراحةً نطاق عدد وسائط مقبولًا بواسطة `min_arity` و`max_arity` (أو `"variadic"`)، بما في ذلك وسائط wrapper إضافية تتجاوز العدد الدقيق المستنتج لـ copy؛ ويجب ألا يقل `min_arity` عن أعلى فتحة دور مشار إليها زائد واحد، بينما يقيّد `formats` و`abis` قابلية التطبيق. إذا لم يتطابق عدد الوسائط أو صيغة الكائن أو ABI للاستدعاء، فلا ينطبق أي ملخص وتبقى النتيجة UNKNOWN وفق دلالات العالم المغلق.

وسّع الكتالوج أو استبدله بملف مواصفات:

```bash
neverd hunt --sinks extra_sinks.json --sources extra_sources.json app
```

```json
{ "sinks": [
    { "name": "my_copy", "kind": "copy", "dst": 0, "src": 1, "len": 2 },
    { "name": "my_format", "kind": "format", "dst": 0, "fmt": 2,
      "effect": { "min_arity": 3, "max_arity": "variadic",
                  "formats": ["elf"], "abis": ["sysv"] } }
  ],
  "sources": [
    { "name": "my_read", "out": 1, "return_tainted": true }
  ]
}
```

بالنسبة إلى مصدر مخصّص، لا يعد `out` و`return_tainted` سوى بيانات وصفية للاكتشاف. ولا يثبتان تأثيرات قابلة للتنفيذ على الذاكرة أو القيمة المعادة أو التلوث. يفتقر مخطط المصادر الحالي إلى عقود النجاح والتعديل والصيغة وABI المنمطة اللازمة لهذه الدلالات، لذا يبقى أي تحليل يعتمد على تأثير مصدر مخصّص UNKNOWN. ولا تتأثر المصادر المدمجة: تواصل واصفاتها المنمطة والمتحقق من قابليتها للتطبيق توفير تأثيرات قابلة للتنفيذ.

لا يُستنتج مصرف مخصّص غير محدود ذو وسيط وجهة فقط من إدخال مصدر يحمل الاسم نفسه. يجب على مصرف مخصّص شبيه بـ `gets` تفعيل `"unbounded": true` صراحةً؛ ولا تمنحه إضافة الاسم نفسه إلى كتالوج المصادر تأثيرًا قابلًا للتنفيذ، وتُرفض حقول المصدر/الطول المتناقضة بصورة تعامليّة.

## الصيد: أحكام فيضان النسخ

لكل مصرف نسخ يستعيد الصيد سعة الوجهة — حجم مصفوفة معلَن في التنقيح، ثم موقع تخصيص كومة بحجم معروف، ثم حدّ سليم لإطار المكدس — ويصنّف الوسيط الذي يقرّر طول الكتابة بمسير SSA خلفي (يتبع spill/reload عبر فتحات المكدس):

- **الطول الثابت** داخل سعة دقيقة هو SAFE. لا يكون الفيضان الثابت UNSAFE إلا إذا كان المصرف قابلًا للوصول على مسار مُثبت؛ وإلا يبقى UNKNOWN.
- تحمل نسخ `_chk` **المحصَّنة** حدّ وجهة وقت التشغيل. الرفض أو ثبوت ملاءمة الحدّ يعطي SAFE؛ والكتابة الممكنة خارج الكائن تعطي UNSAFE؛ والحدّ غير المستعاد أو غير الحاسم يعطي UNKNOWN.
- طول **محدود إثباتًا** (استدعاء يعيد طولًا، قناع، clamp) يُسحب قبل المحلّل مع تسجيل السبب. يكون SAFE فقط مع حجم وجهة دقيق؛ أما حدّ المنطقة الأعلى وحده فيبقى UNKNOWN.
- طول **متأثر بالمهاجم** وسعة معروفة: محلّل المتجهات البتية. إن كان طول أكبر من السعة قابلًا للإرضاء فالحكم UNSAFE. لا تصبح القيم المرشحة قابلة لإعادة التشغيل إلا إذا أمكن اشتقاق خطة `process-input-v1` مكتملة: قيم بيئة حرفية دقيقة، وبحد أقصى البايتات التي يعيدها أول استهلاك للدخل القياسي. تبقى مدخلات argv أو الملفات أو الشبكة أو المصادر المخصصة أو الملتبسة غير قابلة للإعادة مع سبب.
- أي شيء آخر — طول أو سعة مجهولان — UNKNOWN.

كل سعة مستعادة **حدّ أعلى** لحجم الكائن الحقيقي، لذا الفيضان المُثبَت ليس إيجابيًا كاذبًا أبدًا.

### الإدخال المنسّق

بالنسبة إلى `scanf` و`fscanf` وتهجئاتهما ذات الإصدارات، تربط صيغة ثابتة قابلة للقراءة كل تحويل غير مثبَّط بوسيط الخرج متغيّر الوسائط الفعلي. تلوّث مخرجات `%s` و`%[` غير المحدودة استخدامات السلاسل اللاحقة؛ وتلوّث المخرجات الرقمية والمحرفية القيم المحمّلة من الكائن المكتوب، لا قيمة مؤشر الخرج نفسها. لا ينشر `sscanf` هذه التأثيرات إلا عندما تكون سلسلة إدخاله متأثرة بالمهاجم مسبقًا. تنشر مخرجات النص المحدودة مثل `%Ns` و`%N[` التلوث مع امتداد `MaxBytes` يشمل المحرف المنهي؛ وتحسب المتغيرات عريضة المحارف ذلك الامتداد بالبايت باستخدام عرض `wchar_t` الخاص بالمنصة. تبقى التحويلات المثبَّطة والوسائط الزائدة والصيغ المعتمدة على الموضع أو غير المدعومة و`%n` في حالة UNKNOWN بدل تخمينها.

## التدقيق: أحكام عمر الكومة

لكل تخصيص يتتبع التدقيق المقبض عبر مخطط التحكم، بما في ذلك spill/reload للمكدس، ويطبّق ملخص هروب (أُعيد، أو خُزّن عبر عنوان غير مكدس، أو سُلّم لمستدعى غير شفاف):

- **تسرّب** — المقبض لم يُحرَّر ولم يُسمح له بالهروب.
- **تحرير مزدوج** — تحرير ثانٍ قابل للوصول بعد الأول على مسار.
- **استخدام بعد التحرير** — إلغاء مرجع أو استخدام غير شفاف قابل للوصول بعد تحرير.

تُتعرَّف **أغلفة** التخصيص والتحرير بملخصات هروب لكل دالة، فلا يخفي ممرّر `malloc`/`free` العيب. التحريرات على فروع متنافية لا تُبلَّغ كتحرير مزدوج.

تُصدر آلة حالات الكومة أولًا تسلسل أحداث مرشَّحًا (تخصيص، تحرير، استخدام، أو خروج بالإرجاع). وعلى تمريرة ثانية أن تعيد تشغيل ذلك التسلسل على مسار LowIR رمزي وتثبت أن مُسنَد المسار قابل للإرضاء قبل أن تصير النتيجة UNSAFE بثقة عالية. وغياب LowIR، والعمليات المعتِمة، والاستدعاءات بلا ملخص، وعدم يقين الحلّال، وحدود الاستكشاف، كلها تُنزِّل المرشَّح إلى UNKNOWN. أما فوضى الذاكرة المحافِظة الناتجة عن الأسماء المستعارة المحتملة فتُتعقَّب على حدة، فلا تُبطِل الكتاباتُ العادية في إطار المكدس دليلَ وصولٍ دقيقًا فيما عدا ذلك.

## الميزانيات والخرج والارتباطات

استكشاف الصيد والمحلّل محدودان (`--max-paths` و`--max-steps` و`--max-loop` و`--solver-conflicts`)؛ استنفاد الميزانية يعطي UNKNOWN. يطبع الأمران JSON ويحترمان `-o`. رمز الخروج هو `0` لـ SAFE و`2` لـ UNSAFE و`1` لـ UNKNOWN أو الخطأ.

التحليلان نفسهما متاحان عبر واجهة C (`neverd_session_audit_json` / `neverd_session_hunt_json` مع `neverd_safety_options` ذي إصدار) وSDK بايثون (`Session.audit()` / `Session.hunt()`).

### مخطط الاكتشاف

```json
{
  "class": "buffer_overflow",
  "function": "parse_header",
  "name": "strcpy",
  "name_source": "import",
  "call_va": "0x11a4",
  "source": "reader.c:42",
  "sink": "strcpy",
  "arg_index": 1,
  "flow": "TAINTED",
  "verdict": "UNSAFE",
  "confidence": "HIGH",
  "capacity": 16,
  "capacity_kind": "exact",
  "corroboration": "path predicate and overflow are jointly satisfiable",
  "evidence": { "concrete_input": { "copy_length": "17", "argv[1]": "16 bytes" }, "candidate_values": [{ "name": "copy_length", "value": "17" }, { "name": "argv[1]", "value": "16 bytes" }], "replayable": false, "replay": { "adapter": "process-input-v1", "reason": "argv input is not supported by process-input-v1" }, "symbolic_model": [{ "id": 0, "name": "copy_len", "width": 64, "value_hex": "0x11", "origin": "input" }] }
}
```

الحقل `replayable` مشتق وليس وعدًا مستقلًا: يكون `true` فقط عندما يحتوي `replay` على خطة إدخال مكتملة للمحوّل `process-input-v1`. تسجل الخطة بايتات البيئة الدقيقة، وأول تسلسل بايتات للدخل القياسي عند استخدامه، وربط معرّفات إسنادات المحلّل بهذه المدخلات؛ وعند غيابها يشرح `replay.reason` السبب. الحقول الجديدة إضافية؛ يبقى `schema_version` الأعلى مساويًا `1`.

## حدود الإيجابيات الكاذبة والنطاق

- السعة دقيقة أو حدّ أعلى للحجم الحقيقي، لذا UNSAFE يعكس فيضانًا حقيقيًا. عند غياب الحجم الدقيق وعدم كفاية حدّ المنطقة لإثبات السلامة تكون النتيجة UNKNOWN.
- تُسحب النسخة محدودة الطول قبل المحلّل وتُحسب في `skipped`؛ السعة الدقيقة قد تثبت SAFE، أما الحدّ الأعلى وحده فيبقى UNKNOWN.
- تبقى نسخ المحارف العريضة وعمليات الإلحاق المسجّلة في الكتالوج UNKNOWN حتى استعادة عرض العنصر والطول الحالي للوجهة. كما تبقى مخصّصات وسيط الخرج وملكية `realloc` الشرطية UNKNOWN عندما يتعذر إثبات انتقال المقبض.
- **P0** (هذا الإصدار، الصيغ الثلاث): كتالوج المصارف، مرشح الوسائط المسبق، صيد فيضان النسخ، تدقيق عمر الكومة. يشغّل كل مضيف ست fixtures لـ PE وELF وMach-O على x86-64 وAArch64.
- **P1**: تتوفر فحوص فيضان المكدس/العالمي والقراءات المحلية غير المهيأة وسلاسل التنسيق؛ وتبقى أنواع مكدس PDB الأغنى ومخصِّصات المنصة الإضافية تغطية تزايدية، ويظل غياب الملخص الدقيق UNKNOWN.
- **P2**: فحوصات وقت تشغيل يدرجها patch، قابلية وصول المهاجم بين الإجراءات.
