# Восстановление нативного кода и исходников iOS

[← Указатель документации](README.md) · [Обзор мобильного анализа](../mobile.md)

`neverd mobile` принимает IPA, `.app` и Mach-O, экспортируя нативный C, метаданные среды выполнения и экспериментальные исходники Objective-C `.m` и Swift `.swift` для поддерживаемых нативных тел. Опубликованный результат может содержать невосстановленные методы: перед использованием проверьте покрытие. Мобильные контейнеры обрабатывает CLI; нативный C SDK отдельно загружает выбранный Mach-O.

Компиляция удаляет комментарии, форматирование, идентификаторы и конструкции языка. Этот процесс реконструирует представление исходного кода, но не исходный текст и не доказательство эквивалентного поведения произвольного приложения. Анализируемое приложение не запускается.

## Начало работы и зависимости

```sh
cmake --build build --target neverd
neverd mobile App.ipa -o recovered-ios
neverd mobile App.app -o recovered-arm64 --arch=arm64
neverd mobile executable -o metadata --metadata-only
neverd mobile App.app -o recovered-framework --artifact Frameworks/Example.framework/Example
```

Соберите цель `neverd` инструментами с поддержкой C++20. Мобильный процесс работает внутри нативного CLI без интерпретатора Python. Деманглинг сигнатур Swift предоставляет `LLVMSwiftDemangle` из форка LLVM проекта NeverD. Компонент включён и в сборки форка из исходников, и в соответствующие опубликованные пакеты LLVM; NeverD не загружает исходники Swift как отдельную зависимость. Для сборки и запуска NeverD не требуется устанавливать компилятор или инструменты Swift. Зависимости от LLVM, Capstone и других нативных библиотек сохраняются: распространяйте необходимые библиотеки и лицензионные уведомления. Для независимой компиляции созданных исходников Apple и проверки поведения Swift на macOS по необходимости используются Apple Clang, SDK и `swiftc`.

Восстановление сигнатур Swift использует структурированные узлы `LLVMSwiftDemangle` непосредственно в процессе C++. Оно не ищет и не запускает внешний деманглер или команды поиска инструментов. Прежний параметр пути к исполняемому файлу удалён, прежняя переменная окружения деманглера больше не читается. `--metadata-only` не выполняет ни нативный экспорт исходников, ни деманглинг сигнатур.

Список сигнатур в `metadata/swift-signatures.json` указывает встроенный компонент следующим образом:

```json
{
  "demangler": {
    "name": "llvm-swift-demangle",
    "execution": "builtin",
    "version": "6.3.3"
  }
}
```

```sh
neverd mobile App.ipa -o recovered-swift --timeout=600 --json
```

## Входные данные и выбор

IPA должна содержать ровно один каталог верхнего уровня `Payload/*.app`. Главный исполняемый файл IPA и `.app` задаётся `CFBundleExecutable` в `Info.plist`. В обоих форматах `--artifact` задаётся относительно этого приложения и выбирает один вложенный исполняемый файл, а не рекурсивный анализ всех frameworks и расширений. Для непосредственного Mach-O параметр `--artifact` недопустим.

Для fat-бинарников `--arch=auto` предпочитает arm64, arm, x86_64, затем i386. Отсутствующий или неподдерживаемый срез явно отклоняется. Проекция в исходный язык сейчас рассчитана на arm64/x86_64; выбор другой архитектуры не означает поддержку Objective-C/Swift. Срез с `cryptid != 0` отклоняется: предоставьте уже расшифрованные читаемые данные. Архивы и каталоги не допускают опасных путей, символических ссылок, специальных файлов и конфликтующих записей.

## Параметры и ограничения ресурсов

| Параметр | По умолчанию | Значение |
|----------|--------------|----------|
| `-o DIRECTORY` | Обязателен | Новый каталог вне входного каталога; существующий результат сохраняется |
| `--platform=auto\|ios` | `auto` | Определить платформу или выбрать iOS |
| `--arch=auto\|arm64\|arm\|x86_64\|i386` | `auto` | Выбрать один срез Mach-O |
| `--artifact PATH` | Главная программа | Путь исполняемого файла относительно приложения |
| `--metadata-only` | Выключен | Только метаданные, без исходников и вызова инструментов |
| `--max-func N` | `0` | Предел нативных функций; ноль — все найденные; игнорируется в режиме метаданных |
| `--timeout N` | `300` | Положительный общий бюджет анализа в секундах; дочерние процессы используют оставшееся время |
| `--max-files N` | `20000` | Положительный лимит записей; список символов Swift также ограничен |
| `--max-bytes N` | `2147483648` | Положительный бюджет байтов входа, распаковки и итогового результата |
| `--json` | Выключен | Версионированный отчёт в JSON |

Рабочая область контролируется; копии входа и промежуточные результаты могут занимать до трёх бюджетов записей/байтов. Журналы ограничены 16 MiB на процесс, JSON сигнатур Swift дополнительно ограничен 32 MiB. Это контроль ресурсов, не изоляция процессов. Увеличение timeout не отменяет другие лимиты. Методы, исключённые по `--max-func`, остаются невосстановленными в доступном списке метаданных.

## Исходники Objective-C и структура runtime

Оба режима отчёта об исходном коде содержат `source_projection_graph`. Его узлы показывают окончательные типизированные нативные тела, локальную диагностику, объединённые native/Block `dependencies` и рабочий результат `closure_closed`. Локальные проверки и распространённые сбои зависимостей имеют разные причины; при отсутствии типизированного тела диагностика неполна. Исправление непривязанного вызова может открыть новые зависимости. Закрытый узел прошёл только этап зависимостей: до состояния `recovered` метод должен пройти генерацию и проверку исходного текста. `native_dependency_graph` остаётся отдельным списком вызовов LowIR.

Для повторного анализа покрытия следующая команда выполняет те же анализ и проверки публикации, что и `--format=objc-methods`, но не сохраняет `native_source` и поле `source` каждого метода. JSON добавляет `sources_omitted=true`, сохраняя полный смысл идентификаторов, состояний, диагностики, сигнатур, ссылок на общие помощники и свидетельств зависимостей. Проверки рендеринга продолжают выполняться; полный режим нужен для компилируемых исходников. Соответствующая функция C — `neverd_objc_methods_summary_json(session, max_functions)`; результат освобождается через `neverd_free_string`.

```sh
neverd export WMF --format=objc-methods-summary -o summary.json
```

Нативный загрузчик связывает запись метода, исполняемый адрес IMP и поддерживаемую кодировку типа с явными позициями исходного ABI. Фиксированные скалярные/указательные параметры сохраняют скрытые `self`/`_cmd`, неиспользуемые аргументы, отдельные целочисленные/вещественные регистры и поддерживаемые позиции стека. Переинтерпретация битов float/double отделена от числового преобразования. Подсказки типов служат проекции исходников, но не являются аутентифицированным свидетельством ABI или разрешением патчить код.

`sources/objc.m` помещает реально восстановленные операторы в тела `@implementation`, сохраняя необходимые C-помощники и типизированные вызовы. Цели вызовов требуют поддерживаемой связи с исходным представлением; неизвестные цели и неполные группы зависимостей остаются невосстановленными. Отсутствующие определения, неисполняемые адреса, конфликтующие типы, неподдерживаемый ABI, неполное декодирование и отклонённый IR не становятся восстановленными методами только из-за наличия декларации.

Параметры нативных вспомогательных функций могут получить указательные типы для проекции исходного кода, если полные входные значения через COPY/PHI поступают в уже связанные указательные аргументы без противоречащего скалярного использования. Физические позиции ABI и типы общего IR сохраняются; тела функций и все их группы нативных зависимостей по-прежнему требуют проверки.

Нативная скалярная вспомогательная функция может вернуть наблюдаемый входной параметр, если его точный регистр ABI покрывает всю ширину результата. Ограниченный анализ объединяет все пути возврата с начальным входом и обратными рёбрами циклов; вызовы и частичные записи отменяют значение. Необъявленные входные значения, неиспользуемые заполнители параметров, начальные маркеры SSA и PHI не доказывают наличие входа. Этот вывод используется только для проекции исходного кода, сохраняет физические позиции и по-прежнему требует полной проверки тела и зависимостей.

Локальные нативные функции могут получать полные целочисленные входы из дополнительных регистров, включая указатели на результат, если анализ наблюдаемых входов согласуется с чтениями в полном LowIR. Регистры, сохраняемые вызывающей стороной, затем могут использоваться для временных значений; для сохраняемого контекста по-прежнему запрещены записи в сохраняемые регистры вне кадра. Неявные определения вызовов, включая версию SSA 0, не являются входами; через вызов отслеживаются только явно сохраняемые байты. Восстановленные вызовы и определения используют одинаковые физические позиции входов. Внешние прототипы C/Swift не выводятся; полная проверка тел функций и зависимостей обязательна.

Фиксированные типы обратных вызовов C сохраняют сигнатуры параметров и результата в объявлениях и приведениях типов исходного кода. Точный импорт `swift_once` связывает флаг инициализации, обратный вызов `void (*)(void *)` и контекст без возвращаемого значения. Вызов среды выполнения сохраняется; это не доказывает восстановление тела обратного вызова или владение общей памятью инициализации. Неполные зависимости остаются невосстановленными.

Известные импорты среды выполнения Objective-C сохраняют явную привязку аргументов и результата: retain/release, автоматическое освобождение, сильные и слабые ссылки, выделение объектов и сеттеры с фиксированной сигнатурой. Варианты ARM64 для конкретного регистра читают именно его; идентичность импорта и ABI должны совпадать. Чтение, запись и удаление ассоциированных объектов сохраняют объект, ключ, значение и политику шириной с указатель; сгенерированный C использует публичный заголовок среды выполнения. Тесты перекомпиляции на macOS сравнивают время жизни, обнуление слабых ссылок, копирование и удаление с исходными методами.

Оптимизированные запросы классов и селекторов libobjc сохраняют реальные вызовы среды выполнения, включая обработку nil и пользовательские переопределения. Байтовый результат сохраняет исходные преобразования вызывающего кода; он не заменяется предполагаемой проверкой иерархии классов.

Привязка исходного кода строит проверенную карту идентичности прямых объектов классов только тогда, когда аргумент-указатель имеет постоянный адрес. Карта действует в пределах одной операции привязки; каждая последующая операция заново проверяет текущий образ, включая имена классов, флаги метаклассов и конфликты идентичности.

Экспорт Objective-C также связывает фиксированный набор импортов среды Swift с обычным C ABI: подсчёт ссылок, слабые ссылки на нативные объекты и объекты неизвестного типа, метаданные объектов, начало и завершение проверки доступа. Созданный C сохраняет вызовы и требует среду Swift при компоновке. Точки входа со специальными регистрами, нераспознанные соглашения вызова Swift и произвольные символы Swift не поддерживаются; идентичность импорта и скалярные позиции передачи должны точно совпадать.

Отдельные привязки поддерживают на arm64 и x86_64 точные импорты Darwin String → NSString `_$sSS10FoundationE19_bridgeToObjectiveCSo8NSStringCyF` и необязательного NSString → String `_$sSS10FoundationE36_unconditionallyBridgeFromObjectiveCySSSo8NSStringCSgFZ`. Они сохраняют семантику владения и Clang `swiftcall`; для компоновки нужны Swift Foundation и Swift Core. Обратное преобразование переносит два возвращённых слова String как беззнаковое 128-битное целое и разделяет их по явным регистрам возврата до построения SSA. Это перенос битов, а не восстановленная структура String или общая ABI агрегатов. Неизвестные сигнатуры и неполные зависимости инициализации по-прежнему не поддерживаются.

Для проверенных аргументов ключа API ассоциированных объектов точные адреса строк C в области Mach-O только для чтения восстанавливаются как общие идентификаторы. Одинаковым исходным адресам соответствует один ключ, а разные внутренние смещения остаются различными. Экспорт mobile автоматически объединяет вспомогательные функции. C API перечисляет их имена в `shared_identity_functions`; при компоновке единиц методов каждую функцию следует определять ровно один раз. Ключи принадлежат восстановленному коду и не указывают на память уже загруженного исходного образа. Другие непривязанные адреса образа остаются ограничением восстановления.

Проверенные импорты `os_unfair_lock_lock`, `os_unfair_lock_unlock`, `os_unfair_lock_trylock`, `os_unfair_lock_assert_owner`, `os_unfair_lock_assert_not_owner` вызывают настоящую реализацию Darwin через `<os/lock.h>`, сохраняя адрес блокировки, проверки владельца и логический результат. Неизвестные варианты не поддерживаются. Целочисленные результаты вызовов сохраняют только объявленные биты ABI: Darwin arm64 расширяет 8/16-битные результаты до 32 бит с учётом знака; остальные биты регистра остаются неизвестными. Объявленная ширина результата метода учитывается в SSA до слияния ветвей, чтобы неиспользуемые старшие биты не скрывали корректные младшие байты.

Проверенные записи Darwin `__cfstring` восстанавливаются как константные объекты при полном импорте класса, описании структуры, данных символов и fixup. Сохраняются байты ASCII и кодовые единицы UTF-16, включая встроенные NUL. Одинаковые исходные адреса используют один восстановленный объект; разные записи остаются отдельными. Вспомогательные функции входят в `shared_identity_functions` и требуют Foundation при компоновке. Непроверенные прямые обращения к памяти константных объектов не разрешаются.

Числовые счётчики в секции `__DATA,__llvm_prf_cnts` с подтверждёнными границами и без указателей могут использовать общее восстановленное хранилище. Сохраняются начальные байты, перекрывающиеся чтения и записи размером 1–16 байт и изменения между файлами методов. Экспорт mobile объединяет вспомогательные функции; пользователям C API нужно компоновать ровно одно определение каждой функции из `shared_storage_functions`. Хранилище независимо от исходного образа и его среды профилирования. Выходящие наружу адреса, упорядоченные обращения, неполные отображения и релокации указателей пока не поддерживаются. Инструментированные обратные вызовы block могут обновлять это хранилище образа без утечки приватных адресов; обычные записи счётчиков отличаются от записей в приватный кадр стека.

Метаданные сохраняют суперкласс, начало/размер экземпляра и скалярные/указательные ivar с проверенными смещениями, ширинами и выравниванием. Декларации при необходимости добавляют заполнение. Метод, которому нужна неизвестная раскладка экземпляра, остаётся невосстановленным. Категории сохраняют отдельные идентичности класс/категория/адрес и реализации; строго одинаковые записи в обоих списках считаются один раз. Поддерживаемые внешние категории используют существующие декларации Foundation. Неизвестные внешние заголовки сообщаются как отсутствующие зависимости, без выдуманной замены класса.

Восстановление также требует полных объявлений классов, определений локальных классов-предков и исходного кода, где значения определены до использования на каждом пути, а достижимые выходы содержат необходимый возврат; пустая `@implementation` для локального суперкласса создаётся только при проверенной раскладке и полном перечне методов, доказывающем отсутствие собственных обычных методов. При нехватке этих доказательств или конфликте имени с известным импортом Foundation затронутые методы остаются в знаменателе покрытия с указанием причин, а независимо восстанавливаемые классы продолжают выводиться; эти проверки имён не охватывают все имена SDK, все SDK iOS и их версии.

Поддерживаемые вызовы Objective-C Block требуют полной ABI с фиксированными скалярными параметрами, включая скрытый объект Block и все позиции передачи аргументов и результата. Кодировка времени выполнения `@?` расширяется до `id` только в объявлениях и не задаёт прототип вызова. Ссылки на глобальные Block сохраняют идентичность общего объекта. Для поддерживаемых синхронных скалярных захватов необходимо доказать нативное размещение захваченных значений и поток вызова. Сильные ссылки, скопированные проверенным вызовом `objc_retainBlock` / `_Block_copy`, могут покидать создающую функцию, если код инициализирует их хранилище на каждом достигающем пути и полностью восстановлены тела вызова, копирования и уничтожения. Созданный дескриптор сохраняет исходные ABI вспомогательных функций и схему владения. Слабые/byref-ссылки, неизвестные схемы и непроверенные потребители остаются невосстановленными. Также поддерживаются параметры блоков C, объявленные компилятором как не покидающие вызов, если совпадают точный импорт, позиция параметра и полная ABI обратного вызова. Этот контракт времени жизни не означает доступ к памяти только для чтения. При совместной компоновке единиц исходного кода C API каждая запись `shared_block_functions` должна иметь ровно одно определение. Экспорт mobile объединяет совпадающие определения и отклоняет конфликты, включая различия в вызываемых внутренних функциях.

Объявления методов протоколов читаются из разрешённых локальных записей runtime, включая унаследованные протоколы и обязательные/необязательные методы экземпляра и класса. Обычные и относительные списки используют один декодер. Фиксированная сигнатура селектора назначается только при согласии всех соответствующих объявлений классов и протоколов; повреждённые записи и циклы наследования не дают подсказок типов. Синтаксически корректные указатели на структуры, объединения и массивы передаются как непрозрачные указатели без предположений о раскладке. `objc_metadata.protocols` публикует объявления отдельно: они не считаются восстановленными реализациями и не доказывают соответствие классов протоколам. Если остальная сигнатура совпадает, знаковые и беззнаковые 64-битные результаты используют беззнаковое представление битов; конфликты более узких целых, чисел с плавающей точкой, указателей и аргументов по-прежнему отклоняются.

Для вызовов форматирования NSString с декларацией компилятора продвинутые скалярные аргументы восстанавливаются из проверенного постоянного объекта формата. Последовательные и позиционные аргументы должны быть полными и согласованными по типам. Darwin arm64 читает переменные аргументы из восьмибайтовых слотов стека; x86_64 использует целочисленные и вещественные регистры, затем стек. Вызовы сохраняют многоточие и динамическую диспетчеризацию. Неизвестные форматы, запись счётчика, long double и неподдерживаемые расширения отклоняются. Тот же анализ поддерживает объявленные импорты C, например `NSLog`, проверяет точную библиотеку экспорта и использует общий вариадический прототип для вызовов с разным числом аргументов.

Записи в закрытый кадр стека сохраняют каждый байт, читаемый в любой точке функции. Если доказаны границы кадра, неизменяемость входных псевдонимов и отсутствие утечки адреса, NeverD может удалить нечитаемую запись или сократить нечитаемый конец целочисленной записи. Это позволяет восстанавливать расширенные скалярные аргументы, когда неизвестно только неиспользуемое заполнение стека. Неизвестные биты не подставляются. Упорядоченные обращения, несвязанные вызовы, неоднозначные адреса, значения с побочными эффектами и исчерпание бюджета анализа сохраняют исходные записи.

Одноимённые методы категорий сохраняют проверенные объявления ABI даже при неизвестном порядке переопределения. Динамический вызов использует ABI только при согласии всех соответствующих объявлений; неоднозначные реализации по-прежнему не выбираются как тела исходных методов. Несовместимые или повреждённые объявления продолжают запрещать восстановление вызова.

Известные вызовы `objc_enumerationMutation` сохраняют аргумент объекта и дальнейший путь выполнения, поскольку установленный обработчик изменений может вернуть управление. Точные импорты Darwin `__stack_chk_guard` связывают идентичность объекта среды выполнения; чтения защитного значения, сравнения и вызовы `__stack_chk_fail` сохраняются в восстановленном коде.

Связанные 64-битные образы Darwin, импортирующие системный Foundation, также используют встроенные объявления фреймворка, извлечённые компилятором. Все объявления среды выполнения и фреймворка для одного селектора должны быть совместимы; вариативные сигнатуры, неподдерживаемые агрегаты и расхождения между платформами остаются непривязанными. Каталог задаёт только типы вызовов, но не класс получателя и не тела функций. Для использования NeverD локальный Apple SDK не требуется. CoreData имеет отдельный каталог, активируемый точной системной зависимостью. Объявления принадлежат фреймворку своего публичного заголовка; косвенно включённые заголовки зависимостей не активируют другие фреймворки.

Каталог объявлений C также охватывает экспорты CoreGraphics и ImageIO. Непрозрачные указатели изображений и цветов, целочисленные счётчики и результаты с плавающей точкой сохраняют объявленный ABI. Псевдонимы публичных системных фреймворков генерируются вместе с данными экспортов; частные пути, другие версии и необъявленные символы не получают привязку. Объявления mobile также используют грамматику типов загрузчика: корректные указатели на агрегаты остаются непрозрачными без предположений о раскладке.

Большие бессмертные строковые литералы Swift могут связывать свои байты UTF-8 с общей статической памятью при подтверждённом мосте Foundation. Совместно проверяются длина, флаги, завершение, корректность UTF-8, неизменяемость памяти и точный импорт. Исходное представление с метками и вызов моста сохраняются; встроенные нулевые байты и другие формы хранения остаются непривязанными.

Проверенные константные объекты NSString сохраняют общую идентичность и при присваивании или записи через целочисленный носитель с подтверждённым полным адресом данных. Скалярные значения, неполные адреса, числовые операции и доступ к внутренним байтам объекта не получают такую привязку.

Обычные скалярные загрузки из доказанно неизменяемых байтов образа без релокаций можно восстановить как константы с сохранением битов. Поддерживаются целые числа размером 1, 2, 4 и 8 байт и числа с плавающей точкой размером 4 и 8 байт. Изменяемая или неоднозначная память, упорядоченные загрузки и адресные применения остаются непривязанными; числовое применение выражения не разрешает использовать его как указатель.

Вызовы C с фиксированными параметрами также используют объявления, извлечённые компилятором, и сведения SDK об экспорте и реэкспорте. Должны совпадать точная библиотека dyld, символ и скалярный ABI; слабые импорты, неизвестные библиотеки и неподдерживаемые прототипы остаются непривязанными. Сгенерированный C использует отдельные идентификаторы, связанные с исходными символами. Обычные вызовы синхронизации без таблиц обработки исключений сохраняют реальные вызовы и эффекты памяти.

Индексированные скалярные чтения могут использовать неизменяемую таблицу байтов, если общий анализ потока исходного кода доказывает беззнаковую верхнюю границу на каждом входящем пути. Проверки, маски, машинная разрядность и модульное переполнение сохраняют семантику; записи и утечка адресов локальных переменных отменяют прежние факты. Таблица ограничена 4 096 элементами и 65 536 байтами. Перед публикацией повторно проверяются границы, память, релокации и каждое использование вспомогательных функций. Значения полной ширины указателя, указывающие на секцию образа, остаются неоднозначными; узкие скалярные фрагменты и заполнение сегмента сами по себе не доказывают идентичность указателя. Копии байтов разрешены лишь для скалярного чтения без утечки адреса таблицы. Исполняемые регрессии сравнивают целочисленные биты, биты чисел с плавающей точкой, включая отрицательный ноль, и поведение вне границ с исходными методами.

Каталог C включает объявления `sys/mount.h` с именами символов для каждой архитектуры: ARM64 использует `getmntinfo`, а x86-64 — `getmntinfo$INODE64`. Выходной аргумент остаётся указателем на непрозрачный указатель; режим и результат — знаковыми 32-битными целыми. Применяется точная проверка системных экспортов. Структура записей файловой системы и содержимое возвращаемого буфера не предполагаются.

Привязки внешних данных требуют общих объявлений SDK без TLS и точных сведений об экспорте библиотеки. Сгенерированный C обращается к реальной памяти символа и сохраняет последующие обращения к памяти, включая различие между глобальным указателем и объектом по нему. Слабые импорты, конфликтующие идентичности и неподдерживаемая память остаются непривязанными. Объявления данных не доказывают корректность создания блоков или владения ими. Каталог включает данные CoreData, CoreImage, CoreGraphics, ImageIO и CoreSpotlight. Хранилища встроенных литералов определяются компиляцией пустых коллекций и булевых объектов для каждой цели; допускаются только прямые адреса внешних данных без TLS с той же проверкой экспорта. Для генерации, помимо libclang, требуется компилятор Clang, указанный через `--clang`.

На ARM64 идентичность внешнего хранилища `kCIContextPriorityRequestLow` и `kCIContextUseSoftwareRenderer` подтверждается совпадающими объявлениями полных SDK iPhoneOS и arm64 iPhoneSimulator и точным импортом CoreImage. Параметры контекста сохраняют реальные загрузки указателей и значения времени выполнения; привязка не подменяет строковые ключи или поведение отрисовки.

На ARM64 `UIApplicationDidEnterBackgroundNotification` также связывается с точным внешним хранилищем UIKit. Объявления обоих SDK совпадают; исходная загрузка указателя и идентичность уведомления во время выполнения сохраняются.

Реконструкция runtime ограничена: не обещаются полные свойства и протоколы, исходные аннотации владения, произвольные агрегаты, вариадические хвосты, тела с зависимостью от исключений и немоделируемые раскладки Block/захватов. Кодировка описывает фиксированные аргументы и не доказывает отсутствие многоточия в оригинале. Цепочечные указатели используются только для слотов, разрешённых загрузчиком; остальные форматы сохраняют диагностику.

## Исходники Swift и раскладка памяти

Структурированный вывод demangler разделяет вызываемые сигнатуры и невызываемые метаданные. До проекции тела поддерживаемые сигнатуры связываются с символами, входами и явным машинным ABI выбранного бинарника. Получатели Swift следуют Swift ABI; скрытые аргументы Objective-C их не заменяют. Пользовательский файл сигнатур также остаётся подсказкой, требующей проверки.

Экспериментальный emitter создаёт поддерживаемые свободные функции, методы классов, назначенные инициализаторы и методы struct с фиксированной раскладкой, включая поддерживаемые mutating-получатели. Декларациям классов/структур и хранимым полям нужны восстановленные метаданные раскладки. Нативный вызов выводится только при полной поддерживаемой группе необходимых деклараций и тел. Единицы исходников содержат их совместно, без моста, вызывающего оригинальный бинарник.

Тела поддерживаемых Swift getter/setter восстанавливаются из нативной реализации и объединяются в свойства. Закрытое хранилище сохраняет установленное расположение полей; инициализаторы и остальные методы используют те же имена хранилища. Одно объявление свойства или запись поля не доказывает восстановление тела аксессора.

Поддерживаемые выделяющие память конструкторы, тривиальные деструкторы/освобождение памяти, аксессоры метаданных типа и точки входа `_modify`/resume могут проецироваться в выданную единицу типа. Для каждой необходимы ограниченное доказательство полного нативного потока и эффектов, реально восстановленные зависимости контекста/инициализатора/свойства, а также проверки обработки исключений и IR связанных тел. Записи выделяющего конструктора должны совпадать с реальным инициализатором; `_modify` должен связывать точное изменяемое поле и продолжение. Вызовы метаданных времени выполнения сохраняют моделируемую семантику внутри восстановленного типа. Эти входы явно обозначаются как исходные проекции компилятора, а не как отдельно восстановленные тела обычных методов или исходный текст программы.

Обобщённые или resilient-раскладки, async/throwing-функции, неизвестные соглашения вызова, неподдерживаемые accessor/allocator/thunk, неполная инициализация и несвязанные нативные/runtime-зависимости остаются индивидуально `unrecovered`. Mangled-символ или имя номинального типа не являются восстановленным методом. Удалённые символы и неклассифицированные узлы demangler делают покрытие неполным или неизвестным.

## Выходные данные и покрытие

```text
recovered-ios/
  artifacts/selected.macho
  sources/native.c
  sources/objc.m
  sources/swift.swift
  metadata/objc.h
  metadata/objc.json
  metadata/objc-methods.json
  metadata/swift.json
  metadata/swift-signatures.json
  metadata/swift-methods.json
  logs/
  report.json
```

Файлы исходного языка существуют только при возможности вывести код. `objc.json` содержит классы, категории, ivar и исходные кодировки; `objc.h` — поддерживаемые декларации. `swift.json` хранит номинальные типы и mangled-символы. JSON сигнатур/методов сохраняют классификацию, пропуски, причины и счётчики. Журналы содержат нативную диагностику и диагностику нативного Swift-экспорта, если он выполняется. Журналы поиска внешних инструментов Swift и внешнего деманглинга не создаются. Пути в `report.json` относительны его каталогу. Выбранный бинарник — артефакт анализа; генерируемый код не линкует его как мост восстановления.

Временные копии пакета и промежуточные JSON удаляются. Обычный запуск без нативных тел завершается ошибкой даже при наличии метаданных. Режим метаданных создаёт лишь выбранный файл, `objc.h`, `objc.json`, `swift.json`, `report.json`; исходников и файлов сигнатур/покрытия нет, а `native_function_count`, `objc_method_recovery`, `swift_method_recovery` равны `null`. Все режимы используют метаданные Objective-C, разрешённые нативным загрузчиком. Метаданные Swift читаются из нативного образа с проверкой границ; неподдерживаемые fixup, перемещаемые структуры или ссылки сохраняют диагностику частичного результата.

Этот сокращённый пример намеренно показывает частичное восстановление:

```json
{
  "schema_version": 1,
  "status": "success",
  "platform": "ios",
  "architecture": "arm64",
  "objc_method_recovery": {
    "status": "partial",
    "method_count": 3,
    "recovered_method_count": 2,
    "unrecovered_method_count": 1
  },
  "swift_method_recovery": {
    "status": "partial",
    "coverage_status": "partial",
    "method_count": 4,
    "recovered_method_count": 2,
    "source_body_method_count": 1,
    "compiler_projection_method_count": 1,
    "unrecovered_method_count": 2,
    "metadata_symbol_count": 5,
    "unclassified_symbol_count": 1
  }
}
```

Внешний `status: "success"` означает публикацию проверенного результата. `recovered`, `partial`, `unrecovered`, `no-methods` описывают найденный список, не семантическую эквивалентность или полноту оригинальной программы. У каждого невосстановленного метода есть причина. Objective-C `recovered` дополнительно требует полных runtime-метаданных. Пустой список не доказывает отсутствия методов.

Строка невосстановленного метода Objective-C может содержать `native_backend: {status, reason, diagnostics}`, если единственный результат backend точно соответствует её идентичности runtime. Эта необязательная сводка ограниченного размера сохраняет промежуточный результат даже при отказе проверки объявлений или расположения полей. Основные статус, причина и счётчики строки остаются определяющими; отсутствие сводки означает, что эти данные были недоступны.

Swift `coverage_status` считает только классифицированные вызываемые элементы. Общий Swift `status` учитывает неизвестные символы и может быть `unclassified`, `unsupported-architecture`, `no-symbols`. Невызываемые метаданные находятся в `non_method_symbols` с `not-callable`, неизвестные — с `unclassified`. `types`, `type_metadata_count`, `source_type_count` отдельно считают метаданные/выведенные типы и не должны увеличивать число методов.

В каждой восстановленной строке Swift поле `source_representation` равно `native-method-body` или `compiler-generated-from-type`. Для проекций компилятора также сохраняются `compiler_projection_kind` и `compiler_projection_evidence`. `source_body_method_count` считает восстановленные нативные тела методов, а `compiler_projection_method_count` — доказанные проекции компилятора. Их сумма равна `recovered_method_count`. Входы компилятора остаются в знаменателе `method_count`, а их точная идентичность входит ровно в одну соответствующую единицу исходного кода `type`. Метаданные типа или одно имя зависимости не увеличивают число восстановленных методов. Нативный пакетный JSON содержит `source` в строках компилятора и единицах типа; мобильные `source_units` сохраняют только описания без `source`, а полный исходный код находится в `sources/swift.swift`.

Swift-блок `source_units` содержит `{kind, module, name, source, method_entries, method_identities}`; kind — `function` или `type`, идентичность — `{entry, mangled_symbol}`. Разные символы могут иметь один вход с различными ABI-проекциями. Каждая восстановленная идентичность появляется ровно один раз, невосстановленные не включаются. `method_entries` точно соответствует упорядоченной проекции входов `method_identities`, включая повторные адреса. Полностью одинаковые идентичности нельзя молча объединять. `source` последовательно объединяет исходники единиц с переводом строки после каждой. Mobile хранит общий текст в `sources/swift.swift`, описания единиц — в JSON покрытия. Поле `source` отдельного метода предназначено для просмотра; простое объединение таких строк не восстанавливает декларации классов.

## Прямой нативный экспорт и SDK

```sh
neverd export recovered-ios/artifacts/selected.macho \
  --format=objc-methods --max-func=20 -o objc-batch.json
neverd export recovered-ios/artifacts/selected.macho \
  --format=swift-methods \
  --source-signatures=recovered-ios/metadata/swift-signatures.json -o swift-batch.json
```

Swift-экспорт принимает структурированный список сигнатур, созданный встроенным анализатором при обычном запуске mobile. Objective-C JSON содержит `native_source`, `native_function_count`, `objc_metadata` и C-код, имя, возвращаемый тип, параметры каждого метода. Перед `.m` Mobile дополнительно проверяет декларации, тела и раскладки, поэтому итоговое покрытие может быть уже покрытия C. Успешный нативный экспорт может не содержать восстановленных методов.

Каждый метод содержит `projection_diagnostics`: `items` записывают независимо проверяемые препятствия с `code`, `reason` и доступными свидетельствами об операторе, вызове, значении или зависимости. `checks_complete: false` означает отсутствие предпосылок или лимит ресурсов; пустой частичный отчёт не доказывает восстановление. Проверки общие с допуском и сохраняют контракт `status`, `reason` и `unbound_call`.

`native_dependency_graph` обходит окончательный LowIR от поддерживаемых сигнатур по прямым вызовам кода образа. Сохраняются адреса вызывающей функции, блока и инструкции, общие цели и циклы; косвенные цели остаются null. При отсутствии необходимой функции LowIR или достижении лимита записей `inventory_complete` равно false. `targets_complete` дополнительно требует прямых целей для всех записанных вызовов. Неподдерживаемые корни и неразрешённые косвенные цели исключены; граф не доказывает полного покрытия нативного исполнения или восстановления зависимого исходного кода.

Проверенные локальные ссылки на протоколы используют `objc_getProtocol`, сохраняя зарегистрированную идентичность. Список зависимостей `runtime_protocols` включает вызываемые нативные функции. Конфликтующие имена, неполные объявления, импортированные слоты и неразрешённые перемещения остаются без привязки. Самостоятельный экспорт сообщает об отсутствии регистрации, а не выводит тело, которое может получить нулевой протокол.

Каталог ABI среды Swift создаётся из закреплённых upstream-деклараций и сохраняет соглашение C или Swift. Известные указатели и беззнаковые типы ширины указателя образуют фиксированные скалярные сигнатуры. Вызовам Swift нужен точный сильный импорт libswiftCore; две поддерживаемые категории версионной доступности метаданных также не допускают слабые импорты. Специальные регистры параметров, неизвестные представления, неподдерживаемая доступность и конфликты исключаются. Компилятор добавляет swift_willThrow атрибуты swiftself/swifterror, отсутствующие в DSL. Эффекты и существующие контракты обратных вызовов и байтов сохраняются. Генерация: `scripts/generate_swift_runtime_declarations.py --input RuntimeFunctions.def --source-sha256 <pinned-hash>`; проверка: `--check`. Факты сопровождаются ревизией, хешем и уведомлениями третьих сторон.

Фиксированные декларации среды Swift сохраняют и результат из двух слов: два указателя либо объявленные указатель метаданных и слово состояния. Общий слой ABI назначает оба регистра результата; проверка исходного кода повторно сверяет порядок, типы и точный импорт. Выделение box и запросы метаданных выполняют реальные вызовы среды; агрегатные параметры, неизвестные раскладки и скрытые контексты не поддерживаются.

Отдельно точные, наблюдаемые компилятором мосты значений Foundation для URLRequest, Notification, URL, Data, Date и IndexPath сохраняют `swiftcall` и идентичность поставщика. Косвенный результат и context/self используют `swift_indirect_result` и `swift_context` в выделенных регистрах (x8/x20 на arm64 и RAX/R13 на x86_64), не занимая обычный банк целочисленных аргументов. Data сохраняет явную передачу двух слов. Это декларации носителей вызова, а не восстановленные раскладки значений и не общая ABI Swift.

Вывод скалярного результата нативной функции распознаёт полное извлечение двух слов сразу после вызова с проверенным ABI результата. Должны совпадать идентичность временного значения, смещения полей, размеры и физические регистры. Вспомогательная функция может напрямую вернуть первое поле; правила представлений регистров, перезаписи при вызовах и требование определённого результата на каждом пути возврата сохраняются.

Каталог фиксированных вызовов C также сохраняет 32-битные целочисленные значения и логические результаты с явно заданным расширением нулями. Логический результат занимает полный беззнаковый байт; это не определяет правила расширения логических параметров. Более узкие неизвестные представления и 32-битные объявления с соглашением Swift остаются исключёнными. Исполняемые тесты проверяют успешные и неудачные приведения типов, точное увеличение числа ссылок и уничтожение объектов; вызовы и эффекты владения сохраняются.

Метаданные полей разделяют известную байтовую раскладку и неизвестные языковые типы. Классы Swift со стабильным ABI используют переменные смещений размером с указатель даже на arm64; у неэкспортируемых полей кодировка типа Objective-C может быть пустой. NeverD сохраняет отсутствие типа и проверяет смещения, размеры, выравнивание и пересечения. Восстановленные тела C получают смещения через поиск ivar во время выполнения. Неизвестный тип по-прежнему не позволяет создать объявление класса, требующее выдуманного типа.

Идентичность ivar Swift со стабильным ABI сохраняется и для смещений, которые инициализируются во время выполнения в zero-fill-памяти. Такие классы имеют `ivar_status: "runtime"`; неизвестное смещение представлено JSON `null`, а размер поля 0 означает ширину, определяемую во время выполнения. Методы могут запрашивать смещение у существующего класса, а объявленные объектные типы отслеживаются по точным слотам. Литеральные смещения требуют известной раскладки. Раскладка класса Swift при этом не восстанавливается: автономный экспорт по-прежнему отклоняет неизвестную раскладку и типы полей.

Для прямо связанного нативного вызова адрес смещения ivar можно заменить адресом локального скаляра, только если вызываемая функция читает указатель ровно один раз при входе, до наблюдаемых эффектов, и больше не записывает, не сохраняет, не сравнивает и не использует его. Локальное значение берётся из существующего поиска ivar во время выполнения; ABI и тело функции сохраняются. Ограниченное доказательство допускает только линейный поток управления и отвергает неопределённые использования или превышение лимитов анализа. C API восстанавливает `.cxx_destruct`; синтаксис самостоятельных методов Objective-C пока не позволяет вывести этот селектор.

Неизменяемые буферы байтов восстанавливаются только тогда, когда проверенный контракт импортированного вызова ограничивает чтение неотрицательной длиной и исключает запись, сохранение указателя и сравнение идентичности адресов. Исходные байты и длина сохраняются; другие способы использования указателя остаются неразрешёнными. Точно распознанный сбой утверждения стандартной библиотеки Swift сохраняет выведенные из компилятора скалярные и стековые носители, `swiftcall`, эффект `noreturn` и написание символа компоновщика; диагностические функции C сохраняют объявленный C ABI и отдельную последующую trap-операцию. Статические строки и хранилище бессмертных литералов String копируются только для этого проверенного терминального потребителя, который не сохраняет указатель. Динамические или владеющие значения String не считаются литералами.

Для сессии с уже загруженным Mach-O функции `neverd_objc_methods_json(session, max_functions)` и `neverd_swift_methods_json(session, signatures_json, max_functions)` возвращают эти отчёты. Ноль выбирает все найденные функции. Строки освобождаются через `neverd_free_string`; `NULL` обозначает сбой с объяснением в ошибке сессии. Эти API не загружают контейнеры IPA/`.app`.

После привязки исходных вызовов вывод нативных зависимостей Objective-C может сузить 64-битный целочисленный регистровый параметр `NativeAnalysis` до 32 бит. Исчерпывающая проверка использований HighIR должна доказать, что каждое вхождение наблюдает ровно младшие четыре байта: через извлечение байтов с нулевым смещением либо как точный целочисленный аргумент привязанного вызова. Доказательство независимо для каждого параметра; полноразмерные, ненулевые по смещению, некорректные или прерванные исчерпанием бюджета использования сохраняют исходную ширину. Уточнённая вспомогательная функция повторно поднимается и должна пройти обычные проверки тела и замыкания зависимостей; ABI перезаписи не меняется.

Геттеры статических объектов Swift с отложенной инициализацией, представленные входными thunk-функциями Objective-C, проецируются только тогда, когда символ `vgZTo`, сигнатура метода времени выполнения, проверка предиката, вызов `swift_once`, загрузка хранилища и результат `objc_retainAutoreleaseReturnValue` образуют точный шаблон компилятора. Символы предиката `_Wz`, инициализатора `_WZ` и хранилища `vpZ` должны согласовываться; исходный третий регистр может использоваться только как контекст once, а инициализатор должен игнорировать этот контекст и не иметь обычных прямых вызывающих функций. Проекция воссоздаёт предикат и хранилище объекта, передаёт null как несущественный контекст и сохраняет инициализатор как проверенную зависимость. Любое расхождение формы, символов, использования параметров или callback оставляет метод невосстановленным.

Thunk-функции конструкторов Swift Objective-C с подтверждённым символом `cfcTo` и сигнатурой времени выполнения `init` также могут исключить необъявленный третий регистр аргумента, если он встречается только как контекст единственного точно проверенного вызова `swift_once`. Предикат `_Wz` и инициализатор `_WZ` должны соответствовать друг другу; обратный вызов должен игнорировать контекст и не иметь обычных прямых вызывающих функций. Проекция передаёт null, выводит только восьмибайтовый диапазон хранения предиката и сохраняет все остальные эффекты потока управления, памяти и вызовов; обычные проверки тела исходного кода и замыкания зависимостей по-прежнему применяются.

Обратные вызовы once на ARM64 могут передавать нигде больше не используемый контекст x2 единственному вложенному `swift_once`, если внешний символ `_WZ` и внутренняя пара `_Wz`/`_WZ` точно совпадают, у обоих callback нет обычных прямых вызывающих функций, а независимо типизированный конечный callback игнорирует контекст. Обнаружение и проекция используют один контракт. Проекция передаёт null и сохраняет все операторы; ABI callback с возвратом void позволяет отбросить только чистое возвращаемое значение регистра, временной переменной или константы. Чтение стека, загрузки и вызовы в выражении возврата, а также незамкнутые зависимости по-прежнему отклоняются.

## Проверка и диагностика

На macOS сборки с включённым `BUILD_TESTING` предоставляют цель `check-neverd-mobile-ios`, которая запускает все три набора нативной проверки восстановления через CTest.

Python используется только в приведённых ниже тестовых сценариях разработки; встроенное мобильное восстановление выполняется нативным CLI на C++20.

```sh
cmake --build build --target check-neverd-mobile-ios
ctest --test-dir build -L NeverDMobileTests --output-on-failure
python3 scripts/test_mobile_ios_backend.py --neverd build/bin/neverd
python3 scripts/test_mobile_ios_calls_backend.py --neverd build/bin/neverd
python3 scripts/test_mobile_swift_backend.py --neverd build/bin/neverd
```

На macOS скрипты Objective-C компилируют оригиналы, восстанавливают `.m` и связывают только сгенерированный код с независимой вызывающей программой. Скалярный скрипт проверяет границы целых чисел, ветвления, циклы, чтение/запись по указателям, скрытые аргументы, побитовую идентичность float/double, смешанные и стековые аргументы. Скрипт вызовов дополнительно проверяет диспетчеризацию сообщений, наследование, Category, память переменных экземпляра, нативные вспомогательные функции, вызовы/захваты/общую идентичность Block. Набор вызовов требует восстановления 21/21 метода и совпадения 134/134 независимых результатов в каждом варианте arm64/x86_64 × classic/default. Запускайте проверки с текущей сборкой нативного CLI.

Строгий скрипт Swift проверяет 22 пользовательских объявления, три входа getter/setter и девять вызываемых входов, созданных компилятором; ни один нельзя удалить из перечня. Каждый вариант содержит 858 независимых проверок ожидаемых результатов исходной программы. Сгенерированный `.swift` и вызывающая программа компилируются независимо, без исходной dylib, модуля, моста или написанных вручную подменяющих объявлений. Проверяются скалярные/нативные вызовы, инициализация и память классов, методы структур с передачей по значению/mutating, вещественные и стековые аргументы, указатели и циклы. Нативный CLI на C++20 должен пройти все четыре варианта arm64/x86_64 × classic/default без пропусков: восстановить по 25 нативных тел и девять проекций компилятора, сохранить все 34 вызываемые идентичности и пройти 858/858 проверок как для оригиналов, так и для независимо скомпилированного сгенерированного Swift. Эти результаты относятся только к данному набору и не гарантируют восстановление произвольных приложений или исходного текста программы. Скрипт отклоняет неполное покрытие, ошибки компиляции исходного кода и расхождения поведения.

Эти четыре варианта предназначены для macOS. Два дополнительных входа компилятора — инициализатор пустого значения и его аксессор метаданных; нативные доказательства проверяют их отдельно, а единая исходная единица `struct Empty {}` сохраняет обе идентичности. Успех этого набора не означает прохождения проверки реальным приложением iOS.

Все три скрипта поддерживают `--arch all|arm64|x86_64`, `--fixups both|classic|default`, `--timeout N` и `--work-dir NEW_DIRECTORY`. `--setup-only` проверяет оригиналы, а не восстановление. Для приёмки должны завершиться все запрошенные варианты архитектуры и fixup, в том числе в скалярном тесте. Отсутствующий вариант или невозможность выполнить запрошенную архитектуру на хосте означает провал; пропуски не допускаются. Сохранённые артефакты сбоя позволяют различать отсутствующее покрытие, ошибки компиляции и расхождения поведения. Перед заявлением о проверенной поддержке ознакомьтесь с текущими результатами тестов.

[Workflow Mobile Real Applications](../../.github/workflows/mobile-real-apps.yml) использует публичные приложения с версиями, зафиксированными в [манифесте корпуса](../../scripts/mobile_real_apps.json). Приёмка требует независимых перечней всех Mach-O в полных пакетах iOS и всех DEX в APK, независимой повторной сборки оригиналов и созданного исходного кода, а также сравнения поведения. Отсутствующие этапы, неизвестная полнота перечня или пропущенные обязательные случаи приводят к провалу. Этапы recompile и behavior для реальных приложений ещё не завершены, поэтому сохраняется пометка Experimental. Успешные проверки самого тестового стенда не означают успешную проверку реальных приложений.

Публикация транзакционна: выберите новый каталог, сначала проверьте код завершения, а перенаправленный JSON храните снаружи. Ошибка удаляет временный вывод и сохраняет существующий. При ненулевом коде выхода движка добавляется ограниченный хвост журнала. При тайм-ауте движка исходное сообщение сохраняется, а ограниченный хвост добавляется, если доступен уже захваченный текст журнала. Превышения бюджетов сохраняют свои отдельные сообщения. Нативный CLI возвращает ноль при успехе и ненулевой код при ошибке восстановления. С `--json` обработанные ошибки содержат `schema_version`, `status: "error"` и `error`. Ошибки разбора аргументов, запуска нативного файла или библиотек и прерывания могут сообщаться только через stderr. Сначала проверяйте код завершения.

Для зашифрованного среза предоставьте читаемый вход, а при отсутствии архитектуры проверьте доступные срезы. Читайте точные причины и диагностику пропущенных методов. Увеличение `--max-func` помогает только исключённым по лимиту функциям. Недостающие раскладки, сигнатуры, внешние заголовки, поддержка исключений или ABI требуют реализации либо дополнительных действительных метаданных, а не заявления о полном восстановлении. При распространении инструментов или пакетов сохраняйте применимые лицензионные уведомления.

Вывод сигнатур нативных скалярных вспомогательных функций также поддерживает регистровые параметры и результаты float/double. Общий анализ входных байтов MedIR должен доказать, что широкий векторный вход использует только младшую скалярную полосу. Локальные значения CONCAT сужаются лишь при одинаковой младшей ширине всех определений, отсутствии эффектов у удаляемых старших выражений и явном чтении младшей части во всех использованиях. Вызовы, записи, позиции ветвлений и биты чисел с плавающей точкой, кроме NaN, сохраняются; неизвестные старшие биты не подставляются.

Нативная листовая вспомогательная функция, переходящая к проверенным внешним хвостовым вызовам void, может получить внутреннюю исходную сигнатуру void при отсутствии полного скалярного результата. LowIR должен подтвердить каждый вызов и синтетический возврат. Листовое доказательство запрещает запись сохранённых регистров, указателей кадра и стека, а также регистра возврата; ограниченная неподвижная точка побайтового загрязнения отклоняет сохранение производного от стека значения или его передачу вызову. Проверки CFG, тела и зависимостей сохраняются. Биты результата не предоставляются: читающий неизвестный результат вызывающий код остаётся невосстановленным. Исполняемые тесты проверяют условное уничтожение объектов, независимые результаты и отклонение чтения неизвестных результатов.

Нативные сводки void также поддерживают стековые кадры и обычные вызовы, если ограниченный анализ LowIR доказывает восстановление сохранённых байтов регистров, указателя стека и регистра возврата на каждом выходе. Частичные записи, неявное расширение нулями, перекрывающиеся записи и вызовы аннулируют соответствующие факты. Записи по адресам, для которых доказано отсутствие производных от кадра байтов, не затрагивают частный кадр вызова; частично или полностью производные от кадра псевдонимы, сохранение или утечка адреса кадра отклоняют доказательство. Единственное исключение заимствования кадра — точный первый аргумент привязанного к исходному коду `objc_msgSendSuper2`: он может указывать на полный 16-байтный объект `objc_super`, целиком расположенный в выделенном кадре, поскольку этот контракт среды выполнения читает его синхронно. Обычные сообщения, неполные указатели, объекты за пределами кадра и любые другие аргументы кадра по-прежнему отклоняются. Побайтовый анализ живости HighIR считает значение стекового слота ограниченным чтением байтов этого слота, тогда как получение или передача его адреса остаётся утечкой; некорректные и перекрывающиеся обращения обрабатываются консервативно. Поэтому независимые частные записи могут удалять только непрочитанные конечные байты. После повторного подъёма можно удалить вспомогательные регистровые параметры, которые нигде не встречаются в HighIR, и снова запустить конвейер. Удалением частных записей по-прежнему занимается существующая очистка HighIR; обычные параметры и используемые входы сохраняются.

Каталог UIKit для arm64 также связывает объектный результат `observedProgress` и `setProgress:animated:` класса `UIProgressView`. Последний сохраняет отдельные регистры для аргументов `float` и логического типа. Обе декларации требуют совпадающих данных компилятора для iPhoneOS и arm64 iPhoneSimulator и точного системного поставщика UIKit. Другие архитектуры пока не поддерживаются.

Слово помеченного литерала может содержать полный адрес образа из неизменяемого пула строк C под точным тегом старшего бита. Привязка исходного кода переносит только доказанный адрес в существующий постоянный общий пул, сохраняя целочисленное OR, тег и внутреннее смещение. Похожие скалярные значения или частичные адреса, противоречивое происхождение, изменяемые пулы или пулы с релокациями и прямое использование как адреса памяти отклоняются; структура объекта Swift String не выводится.

`setProgress:` класса `UIProgressView` требует доказанного получателя, например типизированного результата свойства, сохранённого точным вызовом ARC с тождественным результатом. Проверенная полная цепочка суперклассов и протоколов выбирает аргумент `float`. Без уточнённого получателя вызов остаётся неоднозначным: UIKit и локальные классы также объявляют сеттеры с объектным аргументом для того же селектора.

Каталог UIKit для arm64 также содержит `setTitleColor:forState:` класса `UIButton` с объектом и беззнаковым 64-битным `UIControlState`, а также void-метод `invalidateIntrinsicContentSize` класса `UIView`. Полные AST устройства и симулятора согласуются. Подтверждённое наследование `UIImageView → UIView` позволяет существующим доказательствам receiver отличать локальные объектные setter-методы от одноимённых setter-методов с плавающей точкой в несвязанных классах. Неизвестные receiver, конфликтующие объявления подклассов, отсутствие поставщиков родительских объявлений и x86_64 остаются неподдерживаемыми.

Результат поиска в словаре с неквалифицированным типом `id` не получает класс получателя при слиянии с путём, возвращающим известный класс через `new`. Каждый входящий путь должен сохранять доказательство типа получателя; даже явно типизированный аргумент-указатель не позволяет выбрать объектный setter вместо конфликтующего объявления с плавающей точкой.

На arm64 `+[NSSet setWithObjects:]` сохраняет вариативное объявление SDK с завершением nil. Первый поддерживаемый случай требует точного импорта платформенного класса и стаба селектора, а также неизменяемых строк Objective-C, полные восьмибайтовые значения которых совпадают на всех входящих путях. Восстановление останавливается на первом доказанном nil. Если первый объект равен nil, доказательство последующих стековых аргументов не требуется; слоты после терминатора не читаются. Общая вариативная ABI Darwin сохраняет три фиксированных параметра и размещает остальные объекты и nil на стеке. Перед публикацией объявление, библиотека-поставщик, получатель, селектор и каждый аргумент повторно проверяются по текущему образу. Динамические объекты, отсутствующие или частичные записи, вышедшие за пределы анализа кадры, локальные переопределения и другие архитектуры не поддерживаются. Для стекового аргумента также требуется линейное доказательство в частном кадре на момент конкретной загрузки: последующая перезапись не меняет уже прочитанное значение; перекрывающиеся записи, неизвестные вызовы, утечки адресов или поток управления препятствуют подтверждению.

Экспорт исходного кода может проецировать сгенерированный компилятором BOOL super getter отдельно для каждого входа Objective-C, только если полные актуальные доказательства инструкций ARM64, CFG и сохранения/восстановления подтверждают вход, общее тело и accessor метаданных (`CMa`). Поиск, связывание и генерация используют единый контракт. Helper сохраняет фактический вызов CMa и замкнутые зависимости, затем читает зарегистрированную runtime ячейку SEL и вызывает `objc_msgSendSuper2` с подтверждённым типом; разные селекторы сохраняют отдельные ячейки. Загрузчик заново проверяет локальное связывание через символы Mach-O и export trie LLVM с точным сопоставлением текущих сегментов/секций. Другие вызывающие функции и глобальный native ABI общего тела не меняются; отсутствующие или устаревшие доказательства отклоняются.

Инициализатор Swift once для arm64 может копировать объект между отдельными статическими ячейками через уже типизированный native helper. Единый контракт проверяет все текущие параметры и пути, сохраняя порядок: чтение предиката, необязательный `swift_once`, чтение источника, запись назначения, `objc_retain`, возврат. Допускаются четыре ролевых параметра и один необязательный неиспользуемый вход; удаление параметров остаётся задачей native-вывода. Обнаружение и привязка повторно проверяют тот же контракт, точные символы callback и памяти, непересекающиеся восьмибайтовые области и неиспользуемый контекст callback по текущему образу. ABI, поток управления, эффекты памяти и проверки зависимостей сохраняются; алиасы, частичные или упорядоченные обращения, дополнительные использования и устаревшие доказательства отклоняются.

Полные объявления SDK iOS для устройства и симулятора также подтверждают `UIGraphicsBeginImageContextWithOptions(CGSize, BOOL, CGFloat)` как фиксированный вызов C с результатом void. На ARM64 два поля размера занимают `d0` и `d1`, логическое значение передаётся байтом в `w0`, а масштаб — через `d2`. Точный экспорт компоновщика UIKit подтверждает библиотеку-поставщика. Исходный код сохраняет реальный вызов и обновления счётчиков обёртки; неверные поставщики, неподдерживаемые архитектуры и изменённые объявления отклоняются. Нативным обёрткам по-прежнему нужны независимые доказательства состояния и возвращаемого значения.

Те же проверенные данные SDK UIKit связывают `CGSizeFromString(NSString *)` с результатом `CGSize` из двух double. Общий ABI сохраняет и `d0`, и `d1`, включая отдельные результаты, которые используются после другого вызова. Повторная проверка текущего импорта и сигнатуры отклоняет посторонних поставщиков, скалярные подстановки, изменённые параметры-указатели, а также отсутствующие или переставленные носители результата.

Проверка сохранения нативного кадра ARM64 может читать входящий аргумент стека, если текущая выведенная сигнатура входа явно описывает его выровненный восьмибайтовый скалярный слот. Загрузка LowIR должна точно соответствовать всему слоту. Эти байты остаются неизвестными входными значениями и не доказывают ни идентичность сохранённого регистра, ни адрес внутри частного кадра вызываемой функции. Записи, частичные чтения, промежутки и необъявленные слоты не получают такого разрешения. Тело исходного кода, аргументы каждого вызывающего кода и замыкание зависимостей по-прежнему требуют проверки.

Полные объявления UIKit SDK для устройства и симулятора связывают `UIAccessibilityPostNotification` с `void(uint32_t, id nullable)`: ARM64 передаёт беззнаковое значение уведомления в `w0`, а указатель на объект — в `x1`. `UIAccessibilityAnnouncementNotification` — внешнее хранилище `const uint32_t`. Точный импорт UIKit подтверждает его адрес; исходное чтение четырёх байтов и реальный вызов, включая аргумент nil, сохраняются без подстановки номера уведомления. Неверные поставщики, слабые импорты и изменения ширины, знаковости или контракта возврата отклоняются; остальные зависимости от ленивого хранилища требуют собственного доказательства.

Цепочечные перебазирования Mach-O generic64 сохраняют закодированные старшие восемь битов как для `DYLD_CHAINED_PTR_64`, так и для `DYLD_CHAINED_PTR_64_OFFSET`. Форма со смещением сначала восстанавливает полное слово, затем прибавляет предпочтительную базу образа с проверкой переполнения, согласно [исполнению dyld](https://github.com/apple-oss-distributions/dyld/blob/fd8d0c4d52320ebf64db34f3cb280310d905c5ae/common/MachOLoaded.cpp#L771-L792). Загруженные байты сохраняют полное значение времени выполнения. Проверки владельца обычных указателей кода и данных используют полный отображённый адрес; строки Swift с тегами требуют отдельного доказательства представления строки. Допустимые отображённые высокие адреса по-прежнему поддерживаются.

Отдельный интерфейс чтения неизменяемого цепочечного значения выдаёт полное разрешённое слово времени выполнения только для точного слота перебазирования Mach-O в однозначно принадлежащей, представленной в файле неизменяемой памяти. Неразрешённые, неоднозначные, импортированные и перекрывающиеся fixup отклоняются. Значение не даёт обычной идентичности указателя или права копировать перемещённые байты: потребитель исходного кода обязан отдельно доказать представление и перемещение, включая тег строки Swift.
