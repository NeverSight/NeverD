# Восстановление нативного кода и исходников iOS

[← Указатель документации](README.md) · [Обзор мобильного анализа](../mobile.md)

`neverd mobile` принимает IPA, `.app` и Mach-O, экспортируя нативный C, метаданные среды выполнения и экспериментальные исходники Objective-C `.m` и Swift `.swift` для поддерживаемых нативных тел. Опубликованный результат может содержать невосстановленные методы: перед использованием проверьте покрытие. Мобильные контейнеры обрабатывает CLI; нативный C SDK отдельно загружает выбранный Mach-O.

Компиляция удаляет комментарии, форматирование, идентификаторы и конструкции языка. Этот процесс реконструирует представление исходного кода, но не исходный текст и не доказательство эквивалентного поведения произвольного приложения. Анализируемое приложение не запускается.

## Начало работы и зависимости

```sh
cmake --build build --target neverd
python3 --version
neverd mobile App.ipa -o recovered-ios
neverd mobile App.app -o recovered-arm64 --arch=arm64
neverd mobile executable -o metadata --metadata-only
neverd mobile App.app -o recovered-framework --artifact Frameworks/Example.framework/Example
```

Соберите NeverD обычным способом и распространяйте соседний каталог `mobile/` вместе с исполняемым файлом. Нужен Python 3.10+: сначала `--python PATH`, затем `NEVERD_PYTHON`, затем `python3`/`python` из PATH. Зависимости автоматически не скачиваются. Независимая компиляция полученных исходников Apple под macOS требует Apple Clang, SDK и инструментов Swift; это отдельно от статического нативного анализа.

Для сигнатур Swift выбираются `--swift-demangle PATH`, затем `NEVERD_SWIFT_DEMANGLE`, затем `swift-demangle` из PATH. Последний автоматический вариант на macOS — ограниченный по времени `xcrun --find swift-demangle`. Отсутствующий явно заданный инструмент вызывает ошибку; неудачный автоматический поиск оставляет символы неклассифицированными со статусом `unavailable`. Без символов Swift demangler не нужен. `--metadata-only` не вызывает ни нативный backend, ни demangler.

```sh
neverd mobile App.ipa -o recovered-swift \
  --python python3 --swift-demangle /path/to/swift-demangle --timeout=600 --json
```

## Входные данные и выбор

IPA должна содержать ровно один каталог верхнего уровня `Payload/*.app`. Главный исполняемый файл IPA и `.app` задаётся `CFBundleExecutable` в `Info.plist`. В обоих форматах `--artifact` задаётся относительно этого приложения и выбирает один вложенный исполняемый файл, а не рекурсивный анализ всех frameworks и расширений. Для непосредственного Mach-O параметр `--artifact` недопустим.

Для fat-бинарников `--arch=auto` предпочитает arm64, arm, x86_64, затем i386. Отсутствующий или неподдерживаемый срез явно отклоняется. Проекция в исходный язык сейчас рассчитана на arm64/x86_64; выбор другой архитектуры не означает поддержку Objective-C/Swift. Срез с `cryptid != 0` отклоняется: предоставьте уже расшифрованные читаемые данные. Архивы и каталоги не допускают опасных путей, символических ссылок, специальных файлов и конфликтующих записей.

## Параметры и ограничения ресурсов

| Параметр | По умолчанию | Значение |
|----------|--------------|----------|
| `-o DIRECTORY` | Обязателен | Новый каталог вне входного каталога; существующий результат сохраняется |
| `--platform=auto\|ios` | `auto` | Определить платформу или выбрать iOS |
| `--arch=auto\|arm64\|arm\|x86_64\|i386` | `auto` | Выбрать один срез Mach-O |
| `--artifact PATH` | Главная программа | Путь исполняемого файла относительно приложения |
| `--metadata-only` | Выключен | Только метаданные, без исходников и вызова инструментов |
| `--max-func N` | `0` | Предел нативных функций; ноль — все найденные; игнорируется в режиме метаданных |
| `--python PATH` | Окружение/PATH | Интерпретатор Python 3.10+ вспомогательного процесса |
| `--swift-demangle PATH` | Окружение/PATH/инструменты | Demangler сигнатур Swift |
| `--timeout N` | `300` | Положительное число секунд на процесс backend |
| `--max-files N` | `20000` | Положительный лимит записей; список символов Swift также ограничен |
| `--max-bytes N` | `2147483648` | Положительный бюджет байтов входа, распаковки и итогового результата |
| `--json` | Выключен | Версионированный отчёт в JSON |

Рабочая область контролируется; копии входа и промежуточные результаты могут занимать до трёх бюджетов записей/байтов. Журналы ограничены 16 MiB на процесс, JSON сигнатур Swift дополнительно ограничен 32 MiB. Это контроль ресурсов, не изоляция процессов. Увеличение timeout не отменяет другие лимиты. Методы, исключённые по `--max-func`, остаются невосстановленными в доступном списке метаданных.

## Исходники Objective-C и структура runtime

Нативный загрузчик связывает запись метода, исполняемый адрес IMP и поддерживаемую кодировку типа с явными позициями исходного ABI. Фиксированные скалярные/указательные параметры сохраняют скрытые `self`/`_cmd`, неиспользуемые аргументы, отдельные целочисленные/вещественные регистры и поддерживаемые позиции стека. Переинтерпретация битов float/double отделена от числового преобразования. Подсказки типов служат проекции исходников, но не являются аутентифицированным свидетельством ABI или разрешением патчить код.

`sources/objc.m` помещает реально восстановленные операторы в тела `@implementation`, сохраняя необходимые C-помощники и типизированные вызовы. Цели вызовов требуют поддерживаемой связи с исходным представлением; неизвестные цели и неполные группы зависимостей остаются невосстановленными. Отсутствующие определения, неисполняемые адреса, конфликтующие типы, неподдерживаемый ABI, неполное декодирование и отклонённый IR не становятся восстановленными методами только из-за наличия декларации.

Метаданные сохраняют суперкласс, начало/размер экземпляра и скалярные/указательные ivar с проверенными смещениями, ширинами и выравниванием. Декларации при необходимости добавляют заполнение. Метод, которому нужна неизвестная раскладка экземпляра, остаётся невосстановленным. Категории сохраняют отдельные идентичности класс/категория/адрес и реализации; строго одинаковые записи в обоих списках считаются один раз. Поддерживаемые внешние категории используют существующие декларации Foundation. Неизвестные внешние заголовки сообщаются как отсутствующие зависимости, без выдуманной замены класса.

Реконструкция runtime ограничена: не обещаются полные свойства и протоколы, исходные аннотации владения, произвольные агрегаты, вариадические хвосты, тела с зависимостью от исключений и немоделируемые раскладки Block/захватов. Кодировка описывает фиксированные аргументы и не доказывает отсутствие многоточия в оригинале. Цепочечные указатели используются только для слотов, разрешённых загрузчиком; остальные форматы сохраняют диагностику.

## Исходники Swift и раскладка памяти

Структурированный вывод demangler разделяет вызываемые сигнатуры и невызываемые метаданные. До проекции тела поддерживаемые сигнатуры связываются с символами, входами и явным машинным ABI выбранного бинарника. Получатели Swift следуют Swift ABI; скрытые аргументы Objective-C их не заменяют. Пользовательский файл сигнатур также остаётся подсказкой, требующей проверки.

Экспериментальный emitter создаёт поддерживаемые свободные функции, методы классов, назначенные инициализаторы и методы struct с фиксированной раскладкой, включая поддерживаемые mutating-получатели. Декларациям классов/структур и хранимым полям нужны восстановленные метаданные раскладки. Нативный вызов выводится только при полной поддерживаемой группе необходимых деклараций и тел. Единицы исходников содержат их совместно, без моста, вызывающего оригинальный бинарник.

Обобщённые или resilient-раскладки, async/throwing-функции, неизвестные соглашения вызова, неподдерживаемые accessor/allocator/thunk, неполная инициализация и несвязанные нативные/runtime-зависимости остаются индивидуально `unrecovered`. Mangled-символ или имя номинального типа не являются восстановленным методом. Удалённые символы и неклассифицированные узлы demangler делают покрытие неполным или неизвестным.

## Выходные данные и покрытие

```text
recovered-ios/
  artifacts/selected.macho
  sources/native.c
  sources/objc.m
  sources/swift.swift
  metadata/objc.h
  metadata/objc.json
  metadata/objc-methods.json
  metadata/swift.json
  metadata/swift-signatures.json
  metadata/swift-methods.json
  logs/
  report.json
```

Файлы исходного языка существуют только при возможности вывести код. `objc.json` содержит классы, категории, ivar и исходные кодировки; `objc.h` — поддерживаемые декларации. `swift.json` хранит номинальные типы и mangled-символы. JSON сигнатур/методов сохраняют классификацию, пропуски, причины и счётчики. Журналы содержат нативную диагностику и, если использовались, поиск инструментов Swift, demangling и нативный Swift-экспорт. Пути в `report.json` относительны его каталогу. Выбранный бинарник — артефакт анализа; генерируемый код не линкует его как мост восстановления.

Временные копии пакета и промежуточные JSON удаляются. Обычный запуск без нативных тел завершается ошибкой даже при наличии метаданных. Режим метаданных создаёт лишь выбранный файл, `objc.h`, `objc.json`, `swift.json`, `report.json`; исходников и файлов сигнатур/покрытия нет, а `native_function_count`, `objc_method_recovery`, `swift_method_recovery` равны `null`. Его Python-reader Objective-C не разрешает цепочечные указатели и указатели перемещаемых объектов. Полное восстановление использует разрешённые данные нативного загрузчика. Простой Swift-reader всё ещё может отмечать неподдерживаемые ссылки как частичные.

Этот сокращённый пример намеренно показывает частичное восстановление:

```json
{
  "schema_version": 1,
  "status": "success",
  "platform": "ios",
  "architecture": "arm64",
  "objc_method_recovery": {
    "status": "partial",
    "method_count": 3,
    "recovered_method_count": 2,
    "unrecovered_method_count": 1
  },
  "swift_method_recovery": {
    "status": "partial",
    "coverage_status": "partial",
    "method_count": 4,
    "recovered_method_count": 2,
    "unrecovered_method_count": 2,
    "metadata_symbol_count": 5,
    "unclassified_symbol_count": 1
  }
}
```

Внешний `status: "success"` означает публикацию проверенного результата. `recovered`, `partial`, `unrecovered`, `no-methods` описывают найденный список, не семантическую эквивалентность или полноту оригинальной программы. У каждого невосстановленного метода есть причина. Objective-C `recovered` дополнительно требует полных runtime-метаданных. Пустой список не доказывает отсутствия методов.

Swift `coverage_status` считает только классифицированные вызываемые элементы. Общий Swift `status` учитывает неизвестные символы и может быть `unavailable`, `unclassified`, `unsupported-architecture`, `no-symbols`. Невызываемые метаданные находятся в `non_method_symbols` с `not-callable`, неизвестные — с `unclassified`. `types`, `type_metadata_count`, `source_type_count` отдельно считают метаданные/выведенные типы и не должны увеличивать число методов.

Swift-блок `source_units` содержит `{kind, module, name, source, method_entries, method_identities}`; kind — `function` или `type`, идентичность — `{entry, mangled_symbol}`. Разные символы могут иметь один вход с различными ABI-проекциями. Каждая восстановленная идентичность появляется ровно один раз, невосстановленные не включаются. `method_entries` точно соответствует упорядоченной проекции входов `method_identities`, включая повторные адреса. Полностью одинаковые идентичности нельзя молча объединять. `source` последовательно объединяет исходники единиц с переводом строки после каждой. Mobile хранит общий текст в `sources/swift.swift`, описания единиц — в JSON покрытия. Поле `source` отдельного метода предназначено для просмотра; простое объединение таких строк не восстанавливает декларации классов.

## Прямой нативный экспорт и SDK

```sh
neverd export recovered-ios/artifacts/selected.macho \
  --format=objc-methods --max-func=20 -o objc-batch.json
neverd export recovered-ios/artifacts/selected.macho \
  --format=swift-methods \
  --source-signatures=recovered-ios/metadata/swift-signatures.json -o swift-batch.json
```

Swift-экспорт принимает структурированный список сигнатур обычного mobile-запуска с demangler. Objective-C JSON содержит `native_source`, `native_function_count`, `objc_metadata` и C-код, имя, возвращаемый тип, параметры каждого метода. Перед `.m` Mobile дополнительно проверяет декларации, тела и раскладки, поэтому итоговое покрытие может быть уже покрытия C. Успешный нативный экспорт может не содержать восстановленных методов.

Для сессии с уже загруженным Mach-O функции `neverd_objc_methods_json(session, max_functions)` и `neverd_swift_methods_json(session, signatures_json, max_functions)` возвращают эти отчёты. Ноль выбирает все найденные функции. Строки освобождаются через `neverd_free_string`; `NULL` обозначает сбой с объяснением в ошибке сессии. Эти API не загружают контейнеры IPA/`.app`.

## Проверка и диагностика

```sh
NEVERD_BUILD_DIR=build python3 -m unittest discover -s scripts/tests -p 'test_mobile_*.py' -v
python3 scripts/test_mobile_ios_backend.py --neverd build/bin/neverd
python3 scripts/test_mobile_swift_backend.py --neverd build/bin/neverd
```

На macOS собственный Objective-C-runner компилирует исходные примеры, восстанавливает `.m` и линкует только сгенерированный код с независимым вызывающим стендом. Проверяются границы целых, ветвления, циклы, указатели, скрытые параметры, битовая идентичность float/double, смешанные и стековые аргументы. Swift-runner независимо компилирует `.swift` со стендом без исходной dylib, модуля, моста или ручных замен деклараций. Проверяются скаляры/нативные вызовы, инициализация/память классов, методы struct по значению/mutating, вещественные значения, стек, указатели и циклы. Строгие проверки могут обнаружить неподдерживаемые случаи; само наличие скрипта не означает прохождение всех случаев каждой сборкой.

Оба скрипта принимают `--arch all|arm64|x86_64`, `--fixups both|classic|default`, `--timeout N`, `--work-dir NEW_DIRECTORY`. `--setup-only` проверяет оригиналы, не восстановление. Невыполнимые на хосте архитектуры явно пропускаются там, где это разрешено; пропуск не является успехом. Сохранённые артефакты различают отсутствие покрытия, ошибки компиляции и поведенческие различия. Проверяйте текущие результаты, прежде чем заявлять подтверждённую поддержку.

Публикация транзакционна: выберите новый каталог, сначала проверьте код завершения, а перенаправленный JSON храните снаружи. Ошибка удаляет временный вывод и сохраняет существующий. Ненулевой код backend включает ограниченный конец журнала; timeout и бюджет имеют отдельные сообщения. С `--json` обработанные ошибки helper дают `status: "error"`; разбор аргументов, отсутствие helper/интерпретатора, Python ниже 3.10 и прерывание могут раньше завершиться сообщением stderr.

Для зашифрованного среза предоставьте читаемый вход, для отсутствующей архитектуры проверьте доступные срезы, для Swift выберите реальный demangler. Читайте точные причины и диагностику пропущенных методов. Увеличение `--max-func` помогает только исключённым по лимиту функциям. Недостающие раскладки, сигнатуры, внешние заголовки, поддержка исключений или ABI требуют реализации либо дополнительных действительных метаданных, а не заявления о полном восстановлении. При распространении инструментов или пакетов сохраняйте применимые лицензионные уведомления.
