# Восстановление исходного кода интерпретатора

Экспериментальный этап специализации интерпретатора удаляет статически разрешённую диспетчеризацию из слинкованной функции x64, сохраняя входные данные времени выполнения, эффекты памяти, ветвления и циклы. Он опирается на семантику инструкций, а не на сигнатуры обработчиков или таблицу опкодов конкретного средства защиты.

```sh
neverd decompile program --func vm_entry --devirtualize \
  --recovery-report recovery.json -o recovered.c
neverd decompile program --func vm_entry --devirtualize \
  --llvm -o recovered-llvm.c
```

`--vm-control` выбирает полные регистры общего назначения, по которым различаются контексты интерпретатора. Параметр можно повторять; конкретных значений он не задаёт. Например, можно выбрать указатель байткода, значение которого устанавливается входным кодом. Входное значение времени выполнения, используемое как счётчик, должно оставаться динамическим. Если в точке слияния разных значений указателя недостаточно разделения контекстов, восстановление может остановиться. Движок не должен компенсировать это угадыванием цели диспетчеризации. Если указатель сохранён в стеке, `--vm-control-stack=-16:8` выбирает восемь байтов по смещению −16 от RSP на входе. Смещение отсчитывается от входа в функцию, а не от текущего указателя стека после его изменения.

C API — `neverd_devirtualize_source_v1()` из `neverd/sdk/NeverDCAPIDevirtualize.h`. Он выполняется в отдельной транзакции и не меняет обычный кэш декомпиляции сеанса. При неудаче исходный код не возвращается, но может возвращаться диагностический JSON. Обе возвращённые строки освобождаются через `neverd_free_string()`.

## Автоматическое обнаружение состояния управления

CLI и все версии C API восстановления исходного кода включают автоматическое обнаружение по умолчанию. В независимом от поставщика инструкций C++ API сохраняется `SpecializationOptions::DiscoverControlState = false`; вызывающая сторона может задать `true`. Ручные подсказки `--vm-control` и `--vm-control-stack` остаются необязательными ключами контекста. Обычные автоматически найденные поля сохраняют ограниченные совместные отношения конечных значений, не создавая ключи контекста и не фиксируя входы на значениях из выборки. Счётчики остаются динамическими, если описанному ниже избирательному уточнению памяти не потребуются их доказанные константы.

Обнаружение следует неразрешённым зависимостям управления и адресов до структурированных регистровых входов узла и сведений о первоначальном создании входов памяти, включая узкие диапазоны байтов. Слот кадра предлагается только тогда, когда эти сведения указывают на неизменённую со входа в узел память в точном диапазоне относительно кадра на входе в функцию. Последующие чтения равных значений или значений, переданных из записи, не создают дополнительных входных зависимостей; неизвестные байты, созданные после сброса фактов о памяти, не считаются входными слотами. История чтений остаётся доступной другим анализам. Новые зависимости запускают анализ заново от входа в функцию. Для каждого сохраняемого отношения по-прежнему требуется полное доказательство конечного диапазона ограничиваемых им битов; записи с возможным наложением адресов отменяют соответствующие факты о памяти. Произвольная внешняя память и неограниченные отношения значений не становятся конечными.

Запросы к производителям сохраняют битовые маски на границах узлов, не расширяя их до целых байтов; для арифметики по-прежнему консервативно включается префикс младших битов, способных передать перенос или заимствование в требуемый бит.

Если уже отслеживаемые зависимости памяти повторно мешают доказать точный адрес, уточнение может дополнительно использовать их доказанные входящие константы как ключи контекста.

Когда обычный поиск зависимостей останавливается, восстановление может разделить одно существующее регистровое поле контекста для каждой нативной позиции и режима, кроме входа функции. Входящий домен должен быть полным, многозначным и охватывать все объявленные биты поля. Каждый реальный предшественник независимо доказывает свой текущий полный домен, сравнивает живое физическое поле и заново проецирует каждый случай. Поздние предшественники и расширенные узлы проверяются повторно; цепочка останавливается на предложенном входе. Сравнения имеют синтетическое происхождение и общие бюджеты узлов, операций, контекстов, запросов и уточнений. Частичные маски, неопределённые флаги и поля только в кадре исключены. Новых чтений гостевой памяти и предположений о вызывающем коде нет. Неполные домены сохраняют консервативное ребро; выдача требует завершения всех достижимых случаев.

Такое выборочное уточнение также может различать контексты по полным 64-битным значениям регистров или сохранённым в стеке указателям, если доказано их равенство базе входного кадра плюс точное смещение. Ключ хранит смещение, не угадывая числовой адрес конкретного вызова. Частичные или потенциально алиасные записи уничтожают факт об указателе. Условия переходов могут предлагать зависимости для ограниченного уточнения до окончательного доказательства управления, в том числе когда неточное слияние открывает неподдерживаемого преемника. Предложение не доказывает ложность условия. Достижимость и сохраняемые цели всё ещё требуют полного доказательства; оставшаяся достижимой неподдерживаемая операция или исчерпанный необходимый бюджет запрещают выдачу исходника. Для неподдерживаемого преемника поиск выбирает ближайшие предшествующие условия с неустановленным исходом; это не полный обратный срез зависимостей.

Обратные запросы к источникам значений определяются входом нативного узла, режимом инструкций, видом поля и диапазоном байтов. Только ребро, чей преемник запрашивает это поле, раскрывает зависимости его значения, в том числе при конечном, но недостаточно точном диапазоне. Это может вызвать ограниченные бюджетом перезапуски анализа от входа, не назначая повторно используемому физическому регистру единственную глобальную роль. Поиск зависимостей ограничен и неполон; восстановление без ручных подсказок не гарантируется для любого интерпретатора.

Проекция обычных автоматических полей также ограничивается запросами узла назначения. Неконстантное поле включается в совместное отношение конечных значений на ребре только тогда, когда его запрашивает узел назначения. Ручные поля и поля, автоматически повышенные до ключей контекста, по-прежнему проецируются глобально. Известные константные байты, точные указатели относительно кадра на входе и сведения о происхождении сохраняются независимо от запросов. Это не позволяет несвязанным полям разных стадий обработчиков перемножать число комбинаций значений в отношении. Заданные бюджеты и требования к доказательствам целей переходов, адресов памяти и состояния при возврате не меняются.

Для обычных автоматических полей каждый столбец кортежа ограничивает только запрошенные биты и содержит соответствующую маску. При слиянии сохраняются лишь биты, ограниченные на всех входящих путях. Остальные биты того же байта остаются значениями времени выполнения: диапазон хранения поля не удостоверяет полный конечный диапазон значений для всей этой области. Байт становится константой только после доказательства постоянства всех восьми битов.

Ручные поля и поля, повышенные до ключей контекста, по-прежнему сначала пытаются глобально доказать отношения по всей ширине. Если доказательство не даёт результата, можно сохранить отношение только для запрошенных битов; это не предоставляет недоказанные байты ключу контекста и не обходит исчерпанный глобальный бюджет.

При перезапуске с новым графом обычные автоматические диапазоны хранения, полностью содержащиеся в других полях, могут использовать эти более широкие поля. Исходные позиции фаз и запросы битов остаются неизменными. Ручные поля, поля контекста и поля, предложенные непосредственно неразрешённым адресом памяти, сохраняют точные диапазоны. `MaxControlFields` ограничивает число полей, фактически сохранённых после этой нормализации. `DiscoveredControlFields` остаётся накопительным и может превышать число активных полей; лимит полей и глобальные бюджеты работы не увеличиваются.

Обычное автоматическое поле с полностью доказанным конечным диапазоном не добавляет сразу всех производителей своего значения как управляющие поля. Поиск сохраняет эти зависимости-кандидаты и активирует их лишь тогда, когда восстановление всё ещё заблокировано, а непосредственное уточнение не даёт кандидатов. Поля, повышенные до ключей контекста, по-прежнему раскрывают зависимости производителей немедленно. Посещения при поиске, перезапуски и доказательства сохраняют прежние накопительные бюджеты.

После неудачной попытки и обычного выбора кандидатов ограниченная обратная рабочая очередь распространяет ожидающие точные запросы битов через наблюдавшиеся нативные переходы. Она использует общий скалярный вычислитель только для диапазонов, покрытых текущими полями управления, не добавляя полей или контекстов. Старый граф задаёт лишь маршруты кандидатов; его значения и выполнимость путей не становятся новыми фактами. Обход предшественников, повторное вычисление и поиск зависимостей используют общие накопительные бюджеты. Это позволяет передавать запросы по длинным цепочкам без полного перезапуска для каждой нативной фазы; публикация по-прежнему требует полного доказательства неподвижной точки на новом графе.

Полный конечный диапазон также позволяет доказать постоянство отдельных байтов, даже если слово целиком меняется. Например, в диапазоне `{0, 0x100}` младший байт постоянен. Как константы сохраняются только байты, одинаковые во всех перечисленных кортежах, с учётом порядка байтов целевой архитектуры; остальные остаются динамическими. Частичное перечисление, неизвестный результат решателя или исчерпание бюджета доказательства не дают таких фактов.

Доказательства конечных диапазонов можно повторно использовать в пределах одного запуска восстановления, включая перезапуски уточнения. Ограниченный кэш сравнивает полный упорядоченный DAG выражений с точностью до согласованного переименования свободных переменных; общие переменные, разрядности, биты констант, параметры операторов и предел проекции остаются частью ключа. Сохраняются только полные диапазоны и доказательства превышения предела. Неизвестные и частичные результаты не сохраняются; при отсутствии записи или нехватке места используется обычное доказательство. Все глобальные бюджеты продолжают действовать, а `solverQueries` считает фактические вызовы решателя.

При одном и том же предикате полный диапазон единственного изменяющегося столбца и доказанные единственные значения остальных определяют точное совместное отношение, если достижимость установлена. Несколько изменяющихся столбцов по-прежнему требуют совместного доказательства. Столбец с маской, покрывающий весь свой битовый диапазон, можно опустить лишь после доказательства независимости его входных битов от предиката и всех остальных столбцов. Общие входы, неизвестные результаты и частичное перечисление не позволяют предполагать декартово произведение.

По умолчанию `MaxControlFields = 16` ограничивает сумму ручных и автоматических полей, `MaxControlRefinements = 16`, `MaxDiscoveryVisits = 65536`. Перезапуски разделяют глобальные бюджеты узлов (включая синтетические), операций, вычислений, запросов решателю и посещений при обнаружении. `contexts` считает нативные контексты и, как `evaluatedOperations`, `nodeEvaluations` и `solverQueries`, суммируется по всем попыткам. Контексты на адрес, активные нативные слоты возврата, поля и кортежи остаются структурными ограничениями отдельной попытки. Лимит запросов остаётся равным 4096. При исчерпании частичный результат не публикуется; `residualBlocks` описывает только итоговый остаточный граф.

Параметр CLI `--vm-max-refinements=N` требует положительного целого числа и по умолчанию равен 16. В C тот же предел задаётся через `neverd_devirtualize_source_v2()` или `neverd_devirtualize_machine_source_v2()`: обнулить `neverd_devirtualize_options_v2`, задать `base.struct_size = sizeof(neverd_devirtualize_options_v2)`, затем `max_control_refinements` (ноль сохраняет значение по умолчанию 16). Встроенный `base` содержит параметры v1; оба поля reserved должны оставаться нулевыми. Существующие структуры и точки входа v1 не меняются и игнорируют добавленные хвостовые расширения. Остальные бюджеты работы и доказательств продолжают действовать.

`--vm-max-fields=N` и `--vm-max-queries=N` задают пределы полей управления и запросов решателю; значения по умолчанию остаются 16 и 4096. Эти параметры и `--vm-max-refinements` требуют положительных 32-битных десятичных целых и `--devirtualize`; ноль, знаки, шестнадцатеричная запись, лишний текст и переполнение отклоняются. Обе ABI исходного кода и оба бэкенда используют одинаковые пределы. Увеличение бюджета разрешает больше анализа, но не задаёт подсказки управления, входные данные или новые гарантии доказательства. При исчерпании C не публикуется.

В C используются `neverd_devirtualize_source_v3()` или `neverd_devirtualize_machine_source_v3()`. Обнулите `neverd_devirtualize_options_v3` и задайте `base.base.struct_size = sizeof(neverd_devirtualize_options_v3)`. Установите `max_control_fields`, `max_solver_queries` и при необходимости `base.max_control_refinements`; ноль выбирает прежнее значение по умолчанию. Все три поля reserved должны быть нулевыми. v1/v2 игнорируют хвост v3, включая reserved; v3 игнорирует будущие хвосты. Отчёт фиксирует фактическую работу и действующие `maxControlFields`, `maxControlRefinements`, `maxSolverQueries`.

Восстановление также поддерживает `--vm-chain-transfers=N` (по умолчанию 0) и `--vm-no-control-discovery`. Цепочки сохраняют символические связи между переходами с доказанной единственной целью; при достижении лимита возвращаются обычные границы CFG. В режиме машинного состояния `--vm-entry-frame=begin:end` объявляет не проверяемый при исполнении диапазон смещений от входного RSP без циклического переполнения. Точная числовая предпосылка сохраняется в C и отчёте, не разрешая доступ к памяти и не доказывая эквивалентность.

Крупные восстановленные функции, превышающие лимит построения SSA, могут использовать `--llvm` с ограниченным контрактом изменяемого скалярного хранилища. Входы, переносимые между итерациями значения и результаты прежних чтений сохраняют смысл. Неподдерживаемое неявное состояние, параметры в векторных регистрах, релокации образа, неоднозначное хранилище и некорректный поток управления вызывают явную ошибку; HighC отклоняет этот запасной путь. Вывод следует прежнему контракту машинного состояния и не добавляет сертификат эквивалентности.

Изменяемое подмножество допускает скалярное хранилище на 8/16/32/64/128 бит; входы подсчёта битов ограничены 64 битами. Нестандартные и большие разрядности требуют отдельного контракта исходного кода.

Для проверенных тел функций с изменяемыми переменными LLVM передаёт точные значения частных ячеек только внутри блока с добавлением инструкций в конец и сохраняет последние записи. Инициализация входа и границы блоков, функций и модулей остаются раздельными. Обращения программы к памяти сохраняются явно. Вывод C ограничивает раскрытие скалярных выражений и работу по свёртке констант, сохраняя именованные промежуточные значения. Сворачиваемые константные выражения используют целевую компоновку LLVM; неподдерживаемые выражения приводят к явной ошибке. Назначенные изменяемые возвращаемые значения, включая ноль, не превращаются в возврат void.

Совместимые API v4: `neverd_devirtualize_source_v4()` и `neverd_devirtualize_machine_source_v4()`. Обнулите `neverd_devirtualize_options_v4` и задайте полный размер в `base.base.base.struct_size`. Счётчик CLI принимает неотрицательное 32-битное десятичное число; ноль отключает цепочки. Границы — знаковые 64-битные десятичные числа с `begin < end`, требуют `--vm-machine-state` и ограничивают физический входной RSP, а не изменённое значение. В C флаг границ требует API машинного состояния; без флага обе границы должны быть нулевыми. Неизвестные флаги и ненулевые старые резервные поля отклоняются. v1/v2/v3 игнорируют весь хвост v4; v4 игнорирует будущие хвосты. Нулевой указатель опций сохраняет прежние настройки. Отчёт добавляет `maxChainedTransfers`, `entryFrameBounds` и фактический `discoverControlState`. Все CLI-опции требуют `--devirtualize`. Предпосылка не проверяется при исполнении и не гарантирует доступность, инициализацию или отсутствие алиасов. Она не включает политику нативных доказательств.

```c
neverd_devirtualize_options_v4 options = {0};
options.base.base.base.struct_size = sizeof(options);
options.base.base.base.use_llvm = 1;
options.max_chained_transfers = 64;
options.flags = NEVERD_DEVIRTUALIZE_V4_DISABLE_CONTROL_DISCOVERY |
                NEVERD_DEVIRTUALIZE_V4_HAS_ENTRY_FRAME_BOUNDS;
options.entry_frame_begin = -256;
options.entry_frame_end = 8;
const char *report = NULL;
const char *source = neverd_devirtualize_machine_source_v4(
    session, entry, &options, &report);
neverd_free_string(source);
neverd_free_string(report);
```

Восстановление с машинным состоянием принимает `--vm-entry-alignment=A:R` как явно заданную и проверяемую область начального RSP. `A` должно быть положительной степенью двойки, а `R < A`. Другие значения возвращают статус 2 до доступа к гостевой памяти или записи состояния. Старшие биты адреса свободны; по умолчанию выравнивание не предполагается. Эта опция не удостоверяет нативную эквивалентность.

C API v5 `neverd_devirtualize_source_v5()` и `neverd_devirtualize_machine_source_v5()` добавляют к v4 поля `entry_frame_alignment` и `entry_frame_residue`. Обнулите `neverd_devirtualize_options_v5` и задайте полный размер в `base.base.base.base.struct_size`. Нулевое выравнивание отключает опцию и требует нулевого остатка; ненулевое доступно только API машинного состояния. v1–v4 игнорируют новое расширение, v5 — будущие. `entryFrameAlignment` и сгенерированный C фиксируют одно проверяемое условие. Отказ по выравниванию предшествует отказу по входным флагам и сохраняет все слова состояния. Числовые границы кадра остаются непроверяемыми. Пользователи остаточного графа C++ обязаны сами обеспечить область RSP. Исходный код и модель используют общий генератор проверки; API нативного доказательства отвергают эту область, пока контракт не сможет её связать.

`--vm-max-symbolic-nodes=N` и v5 `max_symbolic_nodes` задают бюджет символического DAG на узел (по умолчанию 262144). CLI требует положительное 32-битное десятичное число; ноль в C выбирает значение по умолчанию. Обе исходные ABI используют один предел, записанный в `maxSymbolicNodes`. Увеличение бюджета не добавляет семантических предположений или доказательств.

`--vm-external-stores-disjoint-frame` добавляет явную предпосылку без проверки при исполнении: полный диапазон каждой внешней STORE не пересекает `--vm-entry-frame`. Сохраняются только уже известные факты внутри диапазона. LOAD и алиасы между внешними указателями не ограничиваются; поведение по умолчанию остаётся консервативным. API нативного доказательства отвергают этот домен.

API v6 `neverd_devirtualize_source_v6()` и `neverd_devirtualize_machine_source_v6()` включают неизменённые параметры v5. Обнулите `neverd_devirtualize_options_v6`, задайте полный размер в `base.base.base.base.base.struct_size` и включайте `NEVERD_DEVIRTUALIZE_V6_EXTERNAL_STORES_DISJOINT_ENTRY_FRAME` в `flags` только для исходника с состоянием машины и границами кадра v4. Обычный исходник отвергает флаг. v1–v5 игнорируют расширение, v6 — будущие хвосты. Отчёт `externalStoresDisjointEntryFrame` и созданный C явно указывают непроверяемый контракт. Записи, производные от кадра или неизвестного происхождения, не получают исключений. Сохранённый аффинный указатель должен целиком помещаться в диапазон. Просмотр, сохранение и восстановление фактов расходуют общий бюджет операций; при исчерпании C не публикуется.

API v7 `neverd_devirtualize_source_v7()` и `neverd_devirtualize_machine_source_v7()` добавляют `max_node_evaluations` и `max_discovery_visits` к неизменному префиксу v6. Ноль выбирает 16384 вычисления и 65536 посещений зависимостей. Обнулите всю структуру `neverd_devirtualize_options_v7` и задайте полный размер в `base.base.base.base.base.base.struct_size`. v1–v6 игнорируют расширение; v7 игнорирует будущие хвосты и сохраняет унаследованные проверки. Python предоставляет соответствующую структуру `abi.NeverDDevirtualizeOptionsV7` и типизированные функции. Параметры `--vm-max-evaluations=N` и `--vm-max-discovery-visits=N` требуют `--devirtualize` и положительных десятичных 32-битных значений, включая 4294967295. Отчёты сохраняют действующие `maxNodeEvaluations` и `maxDiscoveryVisits`. Эти накопительные ограничения работы не меняют семантических предпосылок; при отказе по бюджету не публикуются ни C, ни свидетельства восстановления.

Поле v7 `flags` также принимает `NEVERD_DEVIRTUALIZE_V7_STOP_CHAIN_AT_REPEAT` (Python: `DevirtualizeFlagsV7.STOP_CHAIN_AT_REPEAT`), доступный через `--vm-chain-stop-at-repeat`. Обычная цепочка доказанных однозначных переходов завершается перед повторным посещением нативной цели с той же парой адреса и режима декодирования, используя обычную проекцию ребра. Это уменьшает развёртывание циклов, но может потерять корреляции, нужные для разрешения последующего управления, и привести к отказу ранее успешного восстановления. По умолчанию флаги нулевые; при нулевом пределе цепочки опция не действует. Повторный анализ зависимостей сохраняет подтверждённую последовательность вхождений. Обе исходные ABI сообщают `stopChainingAtRepeatedDestination`; неизвестные флаги v7 отклоняются. Стратегия не добавляет семантических предпосылок и не разрешает публикацию неразрешённого управления.

`--vm-chain-visits=N` задаёт дополнительный неотрицательный 32-битный предел посещений каждой пары адреса и режима декодирования внутри цепочки. Считаются начальная позиция и цели сцепленных переходов, но не последовательное выполнение. Ноль не добавляет предела; `--vm-chain-stop-at-repeat` по-прежнему имеет приоритет с одним посещением. Нулевой общий предел цепочки отключает оба ограничения. C API v8 используют `neverd_devirtualize_options_v8`: обнулите структуру, задайте полный размер в `base.base.base.base.base.base.base.struct_size` и заполните `max_chained_visits_per_destination`. `reserved` должен быть нулём. v1–v7 игнорируют это расширение, v8 — будущие хвосты. Python предоставляет `NeverDDevirtualizeOptionsV8`. Отчёты содержат `maxChainedVisitsPerDestination` и `effectiveChainedVisitsPerDestination`. Требуется `--devirtualize`; меняются точность и объём работы, но не семантические предпосылки.

Косвенная диспетчеризация с несколькими конечными целями также сохраняет отложенные зависимости условий: после слияния конечное множество может включать невыполнимые ветви. Обратный поиск после ошибки проходит через условия, не дающие новых полей, контекстов или битов производителя, и ищет полезные внешние условия. Отбор и активация используют единое правило и бюджет поиска. Кандидаты не удаляют рёбра; публикация требует нового доказательства всего достижимого графа. Обход зависимостей конечной диспетчеризации начинается лишь после остановки существующих уточнений. Его включение расходует одно новое уточнение в рамках общих накопительных лимитов, поэтому посторонний селектор не опережает уже намеченное уточнение производителя или машинного условия. Исчерпание кандидатов условий не исключает отложенных производителей и другие уточнения; устранить ошибку может только новое доказательство.

Уточнение управления и условий предшествует повторным попыткам необязательного разбиения кадра; необходимые более мелкие разбиения сохраняются. Неподвижная точка каждого остатка вычисляется перед следующим, но публикация требует завершения всех допустимых остатков. Явное выравнивание пересекается с областью разбиения, диспетчер сравнивает фактические остатки. Бюджеты контекстов, операций, узлов и решателя ограничены и разделяются между попытками.

Неразрешённая косвенная цель может возникнуть из-за потери точности условия. Когда уточнение самой цели и отложенных производителей перестаёт добавлять кандидатов, восстановление проверяет ближайшие неопределённые условия на путях к сбою. Выбор и повторные попытки используют общие бюджеты обнаружения и уточнения. Исключить ветвь может только новое полное доказательство; действительно достижимые неизвестные цели по-прежнему приводят к отказу без публикации остаточного кода и свидетельств.

Потребность управления может также требовать отношения указателя к корню входного кадра. Для полного 64-битного регистра, востребованного преемником, восстановление может доказать смещение от этого корня при условии данного ребра даже без маски выравнивания. В проекцию ребра попадает только единственный результат для всей разрядности; неизвестный результат не добавляет фактов. При слиянии конфликтующие или отсутствующие смещения удаляются, а физический адрес корня остаётся свободным.

Для сумм шириной до 64 бит ограниченный анализ структурных масок может доказать, что биты, способные принимать единицу, попарно не пересекаются у всех слагаемых. Только тогда верхний управляющий срез может исключить зависимости от переноса из младших битов. Проверка включает константы и все слагаемые по всей ширине слова. Неизвестные формы, пересекающиеся биты и более широкие суммы сохраняют консервативное правило младшего префикса. Проверка масок расходует бюджет обнаружения; при его исчерпании не публикуются ни кандидаты, ни утверждения о независимости от корня. Это не заменяет доказательств конечности области значений или целей перехода.

Если выбранное управляющее слово совмещает конечный селектор с большим множеством данных или адресов, восстановление может проверять окна по 32, 16 и 8 бит внутри запрошенной маски. Автоматическое обнаружение ждёт активного запроса потребителя; при его отключении участвуют и ручные подсказки. Поиск пропускает уже спроецированные байты и кандидатов, для которых не установлена независимость от корня входного кадра. Каждый необязательный обход зависимостей имеет отдельный предел работы `MaxSymbolicNodes`, отличный от накопительного `DiscoveryVisits`; все доказательства конечности используют общий бюджет запросов. Доказанные постоянные байты сохраняются; поиск продолжается, если они покрывают всю выбранную маску. Первый оставшийся исчерпывающе доказанный конечный домен сохраняется в исходных позициях битов; остальные биты остаются данными времени выполнения. После частичного доказательства исходные запросы к производителям продолжают обрабатываться немедленно. Поздние предшественники аннулируют несовместимые или отсутствующие факты. Этот ограниченный поиск не гарантирует обнаружения всех полезных подполей.

В JSON-отчёт добавлены `discoverControlState`, `maxControlRefinements`, `maxDiscoveryVisits`, `discoveredControlFields`, `discoveredContextFields`, `controlRefinements` и `discoveryVisits`: они описывают включённое поведение, ограничения и объём анализа. Само обнаружение полей не доказывает успешность восстановления.

Если условие сужает зависимость адреса до части байтов, уточнение также сохраняет в качестве кандидатов контекста уже отслеживаемые полные восьмибайтовые поля прямого адреса, содержащие эту часть. Исходное узкое поле и битовая маска его производителя не меняются; несвязанные широкие поля не повышаются до контекстных. Константы и смещения относительно входа по-прежнему требуют доказательства, а все контексты используют общие действующие лимиты.

Необязательный перебор неизменяемых адресов останавливается, когда у достижимого адреса нет сертификата. Исходное чтение сохраняется. Наблюдаемые значения и сертификаты используются лишь после доказательства полного множества; попадание в кэш не отменяет повторную проверку текущего размера чтения, а фактически полученный некорректный сертификат остаётся ошибкой.

Восстановление может пропустить необязательный перебор полного 64-битного управляющего значения `root + constant` или адреса неизменяемого чтения, если доказано, что текущий предикат допускает строго больше значений, чем фактический предел `MaxControlTuples` или `MaxImmutableReadAddresses`. Доказательство учитывает объявленный интервал кадра без перехода через границу адресного пространства: каждому фиксированному остатку младших 32 бит должно соответствовать больше корней, чем этот предел. Из обхода зависимостей исключаются только конъюнкты верхнего уровня, точно совпадающие с этими границами; остальные должны оставлять старшие 32 бита свежего корня свободными. Более строгие ограничения, неподдерживаемые зависимости и исчерпание бюджета возвращают обычное решение.

Каждое доказательство использует общий бюджет работы `MaxSymbolicNodes` для сопоставления границ и обходов зависимостей. Изменение предиката пути требует нового доказательства. Пропуск не фиксирует входы и не доказывает достижимость; сохраняются чтения во время выполнения, узкие маски производителей, сертификаты неизменяемого чтения и заключительные проверки выполнимости.

Конечная проекция также может сохранять независимые биты частично ограниченного символьного входа. Для переменных шириной до 64 бит общий обход зависимостей объединяет требования текущего предиката и каждого исходного выхода `RelatedValues`. В нижнюю границу мощности входят только различные исходные биты, сохраняемые точным отображением в выходные биты и отсутствующие в этом объединении. Зависимости переноса и повторяющиеся знаковые биты учитываются консервативно; связанные выходы никогда не заменяются булевой конъюнкцией. Полностью отсутствующие переменные сохраняют прежний быстрый путь, включая узкие представления более широких источников. Все корни, проходы по операндам и обходы битов разделяют `MaxSymbolicNodes`; неполные доказательства возвращаются к обычному решению. Этот режим чистых выражений не предлагает машинные позиции и не меняет проверки происхождения состояния.

При заполнении кэш конечных доказательств заменяет записи, к которым дольше всего не обращались, допустимыми доказательствами, каждое из которых отдельно помещается в кэш. Попадание обновляет порядок использования; повторная запись, промах и отклонённый кандидат его не меняют. Вытесненное доказательство может потребовать повторного построения. Сохраняются только полные области значений или доказанное превышение их лимита; каждый новый вызов решателя по-прежнему расходует общий бюджет запросов.

Восстановление также сохраняет полностью доказанные конечные множества значений отдельных управляющих полей с масками. Если совместное отношение превышает `MaxControlTuples`, независимые множества всё ещё ограничивают цель, не утверждая корреляций между полями. При слиянии значения проецируются общей маской и объединяются; отсутствующее или слишком большое множество отбрасывается целиком. Изменение множества повторно ставит узел на обработку, даже если совместное отношение уже расширено. Частичный перебор не даёт фактов; сохраняются прежние ограничения числа полей, кортежей, символьных узлов и работы решателя.

Если цель остаётся неразрешённой после исчерпания уточнений производителей, условий, регистров и кадра, восстановление может проверить наблюдавшихся предшественников сбойного узла и выбрать один уже отслеживаемый регистр или диапазон кадра с зафиксированными требуемыми битами на этом входе. Ограниченный резервный шаг пропускает ручные поля, существующие поля контекста и входы функции; успешные попытки не выполняют дополнительный обход. Новый граф обязан заново доказать каждую полную константу или точное смещение кадра для ключа контекста. Частичные значения и поздние неизвестные предшественники сохраняют консервативную трактовку; неизменяемые чтения по-прежнему требуют свидетельств. Бюджеты посещений, уточнений, узлов и контекстов остаются общими.

`MaxChainedTransfers` — включаемый явно лимит C++ (по умолчанию `0`) для последовательных переходов с доказанным единственным адресом или булевым исходом. Сохраняются полное символьное состояние, нативное происхождение и общие бюджеты; несколько исходов используют обычные рёбра CFG. Обратный поиск воспроизводит подтверждённые вхождения инструкций. Объединение может дублировать происхождение циклов и ограничивать автоматический вывод точек разреза.

`EntryFrameBounds` явно задаёт диапазон `[Begin, End)` без переполнения относительно входного значения `FrameBaseRegister`. Он не даёт прав доступа к памяти и не устанавливает отсутствие алиасов. Без него корни остаются в модульной области. Нативное доказательство требует совпадения границ с контрактом вызывающей стороны и связывает их с подтверждением; доказательство LLVM сохраняет существующую область кадра. Одно восстановление не является сертификатом эквивалентности.

## Контракт выполнения

Сейчас бинарный адаптер принимает слинкованные образы x64 ELF и PE по их отображённым адресам. Отображения, байты и права доступа должны оставаться неизменными; параллельные изменения исключены. Строгий подъём по требованию следует по достижимому машинному коду. Неподдерживаемые инструкции, вызовы, непрозрачные операции, обращения с требованиями к порядку памяти, неразрешённый поток управления и обработка исключений языка останавливают восстановление.

Восстановление PE требует полных метаданных образа, включая все релокации и записи об исключениях. CLI загружает их до применения `--func`; пользователи C API не должны заранее ограничивать сеанс через `neverd_session_restrict_function()`. Бинарный адаптер отклоняет образы, загруженные с ограниченным набором функций: пропущенные метаданные не доказывают отсутствие исправлений загрузчика или рёбер исключений.

Без описанных ниже свидетельств PE для получения константы при чтении образа нужен полный диапазон только для чтения, содержимое которого обеспечено файлом, без перекрывающихся отображений и исправлений загрузчика. Изменяемые таблицы, неразрешённые релокации и снимок, полученный во время выполнения, не доказывают неизменность чтения. Релокации COPY и структурно неполные каталоги исключений отвергаются. Если каталог PE и диапазоны функций полны, нераспознанный обработчик в другой функции не препятствует анализу выбранного входа; при достижении кода, охваченного этим обработчиком, восстановление прекращается.

`PEFixedImageView` проверяет полные образы x64 PE по предпочтительному базовому адресу: исходные заголовки, однозначные отображения, полные поля DIR64 и записи обычного импорта; байты IAT исключены. TLS, load-config, отложенный/связанный импорт, CLR и неизвестные механизмы записи отвергаются. Восстановление и доказательства для машинного кода/LLVM связаны с одним снимком. Параметры C++ `MaxImagePreparationBytes` и `MaxImagePreparationRecords` по умолчанию равны 64 MiB и 65536; исчерпание даёт `BudgetExceeded`. Образ должен оставаться неизменным. Эквивалентность ASLR, инициализации и распаковки не доказывается.

Восстановление выровненного кадра охватывает все остатки младших битов входного корня, оставляя старшие биты свободными. Оно создаёт явную входную диспетчеризацию и доказывает каждое постоянное смещение перед использованием общей символической памяти исходного корня. Сохранённые значения, сброс фактов при алиасинге и слияния сохраняют идентичность разбиения. Кандидаты проверяются по возрастанию; посторонняя большая маска не навязывает максимальное разбиение. Лимиты контекстов и уточнений ограничивают разбиения и повторы; узлы, операции, вычисления и запросы суммируются. Автоматическая агрегация доказательств native/LLVM между разбиениями и дублированными исходными точками циклов пока не реализована. Текущие проверяющие средства могут доказывать смещения, следующие из фактических предикатов пути. При явной семантике физического стека канонический внутренний `RET imm16` читает прежний слот возврата и увеличивает RSP на восемь байт плюс беззнаковую величину очистки; внешний возврат по-прежнему требует нулевой очистки. Эта проекция отклоняет кодировки возврата с префиксами.

Повторные пересылки поддерживают 64-битные адреса и элементы по 1/2/4/8 байт после полного доказательства счётчика и направления. При явном машинном состоянии нулевой счётчик не обращается к памяти и не требует доказательства направления; обычный ABI по-прежнему отклоняет несвязанные флаги. Каждый скалярный доступ сохраняет проверки алиасов и слота возврата. Полностью скопированные указатели кадра повторно доказываются по фактической памяти до проекции рёбер. Неизвестные счётчики, исчерпанные бюджеты, сегментные обращения и меньшая разрядность адреса отклоняются. Нативная сертификация неопределённых эффектов этих исходных REP-инструкций пока не поддерживается.

Область восстановления предполагает обычный возврат по ABI: целевой диапазон каждой записи через адрес внешнего происхождения не должен пересекаться со слотом адреса возврата на входе. Это явное предусловие для вызывающей стороны и окружения, в том числе для адресов, вычисленных из внешних целых значений. Отсутствие сведений о происхождении из кадра не доказывает, что числовые адреса не пересекаются. Для адресов записи, производных от кадра, непересечение должно быть доказано; при возврате требуется восстановить исходный указатель стека. Сведения о происхождении сохраняются при выгрузке значений в стек и слиянии потоков. Потеря аффинного выражения не превращает адрес во внешний указатель. Переключение стека, возврат с дополнительной очисткой стека вызываемой функцией и диспетчеризация через RET пока отвергаются. Адаптер применяет семантику x64 с порядком байтов little-endian.

Результат — исходный код и IR для анализа. Он не доказывает безопасность релокации, раскрутки стека, асинхронных исключений или замены бинарного кода. Режим patch отвергает этот параметр. Поддержка любого интерпретатора или любой конфигурации защиты не заявляется.

Точные формы x64 `PUSHFQ`/`POPFQ` сохраняются в остаточной программе. Анализ рассматривает каждый снимок машинных флагов как неизвестное значение времени выполнения; лифтер отдельно объединяет смоделированные арифметические флаги. Восстановление флагов также остаётся эффектом времени выполнения. Адрес, полученный из неизвестных флагов, не может использовать контракт отсутствия пересечения внешнего указателя со слотом адреса возврата; диспетчеризация с недоказанным конечным набором целей по-прежнему отклоняется.

Перед сохранением полного образа флагов каждый смоделированный арифметический флаг и флаг направления должен быть определён внутри восстанавливаемой функции. Прямое чтение флага также требует определения на каждом достижимом предшествующем пути, даже если символьное упрощение устраняет его значение. Иначе восстановление отклоняется, а не выдаёт C с ловушкой «неизвестный регистр».

Временные значения LowIR действуют только внутри одной поднятой машинной инструкции. Каждый читаемый байт должен быть определён ранее в этой же инструкции; повторно использованное смещение из предыдущей инструкции или алгебраическое сокращение неопределённого значения не доказывают корректность исходного кода. Входные константы могут связывать только физические регистры.

## Восстановление с явным состоянием машины

```sh
neverd decompile program --func entry --devirtualize --vm-machine-state \
  --recovery-report machine-report.json -o machine.c
```

`--devirtualize --vm-machine-state` или `neverd_devirtualize_machine_source_v1()` выбирает отдельный исходный ABI: указатель на 17 выровненных слов `uint64_t` (RAX, RCX, RDX, RBX, RSP, RBP, RSI, RDI, R8–R15, RFLAGS). Только нулевой беззнаковый 64-битный статус означает успех. Ненулевой статус не отменяет записи в память. Состояние фиксируется до извлечения адреса последним RET. Его буфер не должен пересекаться с гостевой памятью; нужны исходные отображения и 64-битный little-endian хост.

Исходные адреса гостевого кода и данных сохраняют точные числовые значения, включая адреса, наблюдаемые в выходных регистрах. Генерация исходника не должна заменять их адресами глобальных объектов созданной программы. Вызывающая сторона предоставляет необходимые исходные отображения гостевой памяти; генерация C не перемещает гостевое адресное пространство. Доказательства и отчёты восстановления по-прежнему относятся к исходному входному образу.

Профиль требует CPL3/IOPL0, отключённого теневого стека, отсутствия асинхронных событий и обычного выполнения без исключений доступа. Начальные флаги должны быть каноническими с нулевыми TF/RF/VM/AC/VIF/VIP; POPFQ должен оставлять TF/AC нулевыми, что проверяет исходный код. PUSHFQ/POPFQ используют явное состояние; RDSSP сохраняет регистр, достигнутый INCSSP отклоняется. Полные сохранения указателей кадра распространяются, частичные записи или возможные алиасы уничтожают факты. Метаданные исключений допускаются только для обычного пути, без доказательства диспетчеризации или раскрутки стека. Отчёт содержит `sourceABI` и `executionProfile`; ограничения ABI по умолчанию сохраняются.

Этот ABI состояния машины поддерживает прямые near CALL и косвенные near CALL через регистр с исчерпывающе доказанным конечным набором целей. Косвенный вызов через регистр фиксирует исходный регистр цели до изменения RSP и ровно один раз сохраняет фактический адрес следующей инструкции. Внутренний near RET может выбирать из полностью доказанного конечного набора целей. Остаточный код сохраняет одно чтение гостевого стека, фиксирует значение до увеличения указателя и выполняет переход по нему. Достижение сохранённой входной ячейки возврата остаётся внешним выходом, даже после удаления внутренних кадров. Неизвестные цели, наборы с отсутствующими или неисполняемыми целями, внешние возвраты с дополнительной очисткой и произвольные переключения стека отклоняются.

Косвенные near CALL через память также поддерживаются только в этом ABI явного состояния, с отключённым теневым стеком и обычным выполнением без ошибок доступа. Операнд памяти должен иметь каноническую кодировку `r/m64` без переопределения сегмента; допустимы необязательные префиксы размера адреса (`addr32`) и REX. Общая семантика эффективного адреса и LOAD x64 читает цель до изменения RSP и помещения фактического адреса следующей инструкции в стек. Это верно и когда push перезаписывает ячейку цели; адрес ячейки никогда не подменяет загруженный адрес вызова. Для неизменяемых ячеек указателей и конечных таблиц нужны свидетельства неизменяемого чтения; для доказанно инициализированных значений гостевого стека всё ещё требуется полное доказательство конечного набора целей. Начальные байты образа или снимок изменяемой ячейки не доказывают неизменность. Недоказанные внешние чтения, утраченные факты о стеке, недопустимые цели, FS/GS и другие сегментные префиксы, far CALL, дополнительные или неканонические префиксы отклоняются. Исходный ABI по умолчанию по-прежнему запрещает нативные вызовы.

Обычный исходный ABI создаёт приватный кадр вызова. Все внешние диапазоны LOAD/STORE, включая вычисленные адреса, должны быть отделены от нативного приватного кадра и его восстановленной памяти в исходном коде; это явная предпосылка. Общая проверка отклоняет утечки адресов кадра, зависимые от них результаты и ветвления, а также чтение неинициализированных приватных байтов. ABI состояния машины сохраняет гостевые адреса и не использует эту предпосылку приватного кадра.

Если неопределённые флаги влияют на управление, адреса или определённые выходные значения, необходимо отдельное доказательство невлияния. Текущий отчёт не предоставляет такого доказательства и не подтверждает подобное поведение, зависящее от процессора.

`modelInterpreterMachineStateX64` возвращает `InterpreterMachineStateModel`, используя тот же генератор, что и исходная обёртка. Байты регистров `[0, 136)` представляют исходные 17 слов объекта состояния; `RETURN` передаёт статус отдельно от гостевого RAX, а гостевая память остаётся памятью. Недопустимые входные флаги и отклонённые динамические записи флагов сохраняют статус ошибки. Область состояния должна быть доступной, выровненной и не пересекаться с гостевыми обращениями. `MaxOperations` ограничивает входные метаданные и созданные операции. Детерминированные записи LowIR не служат доказательством архитектурно неопределённых выходов. Вызывающая сторона задаёт наблюдения, контракты входа и кадра, затем выполняет новое доказательство через `checkLowIRLoopRefinement` или уточнение конечных путей; модель и записи не сертифицируют скомпилированный C.

`modelLLVMInterpreterMachineStateX64` моделирует проверенную скалярную функцию LLVM с одним указателем состояния и результатом статуса i64. `llvmInterpreterMachineStateContract` наблюдает все 17 слов и требует, чтобы отдельный байт `LLVMInterpreterDefinednessOffset` начинался и оставался нулевым. Сохраняйте эти обязательства при добавлении входного домена и гостевого кадра. Копии PHI параллельны; переполнения, точные сдвиги и атрибуты диапазона становятся проверяемыми условиями. Каждая выполненная поддерживаемая операция должна быть без poison, даже если мёртвый код или select могут скрыть его по [семантике LLVM](https://llvm.org/docs/UndefinedBehavior.html). `MaxInputItems`, `MaxBlocks`, `MaxOperations` и `MaxWork` ограничивают построение. Неподдерживаемые типы, утечки указателей, режимы памяти, вызовы, атрибуты и метаданные явно отклоняются; деление и freeze исключены. Переменные `shl`, `lshr` и `ashr` для i8/i16/i32/i64 требуют беззнакового счётчика меньше исходной разрядности без маски ISA; `nuw`, `nsw` и `exact` проверяются отдельно. Новая полная конечная или индуктивная проверка должна доказать определённость, безопасность памяти, наблюдения и завершение; автоматические предложения циклов остаются неполными. Точные исходники, модули и входы компилятора связываются отдельно. Парсер и компилятор остаются доверенными; API не сертифицирует C, машинный код или неопределённые решения физических CPU. См. [справочник LLVM](https://llvm.org/docs/LangRef.html). Читаемые входные байты должны быть инициализированы, а гостевые обращения указывать на живое хранилище в объявленном кадре; плоская память LowIR не доказывает время жизни объектов LLVM или происхождение указателей.

`initializes` допускается только для разделённых диапазонов байтов внутри объекта состояния. Ограниченный анализ гарантированных фактов требует инициализировать каждый заявленный байт обычной записью до любого чтения этого байта и до каждого нормального возврата. Частичные записи и фиксированные алиасы разделяют одни побайтовые факты; гостевые записи не учитываются. На входе множество инициализированных заявленных байтов пусто, поэтому запись на обратном ребре не обосновывает чтение на первой итерации. Атомарные/volatile-доступы и неизвестные алиасы состояния по-прежнему отклоняются. Элементы списков диапазонов учитываются в `MaxInputItems` до верификации, а вычисление неподвижной точки использует общий `MaxWork`. Эта консервативная проверка может отвергнуть корректный код с корреляцией путей; атрибут никогда не удаляется ради получения доказательства.

`prepareInterpreterLLVMRefinement` сохраняет точный текст LLVM и имя выбранной функции, проверяет модуль и готовит обе модели с канонизацией флагов только при входе. `checkBinaryLLVMRefinement` заново строит входные данные и доказывает соответствие реального нативного образа тому же остаточному коду, затем его модели этому артефакту LLVM. Конечные и индуктивные проверки учитывают все слова состояния, фактический статус, определённость и записи во фрейм, сохраняя RSP и слот возврата. Нативные входные константы не копируются в контракт исходного кода: его более широкая область произвольных общих регистров и канонических флагов может консервативно отвергнуть результат, верный лишь при нативных ограничениях. Планы циклов — недоверенные предложения. Только две новые успешные проверки создают составное свидетельство, связанное с точными байтами IR, именем функции, обеими проверками, версией профиля и лимитами.

`MaxIRBytes` ограничивает текст и имя до копирования и разбора; `MaxMachineStateOperations` и `MaxPreparationItems` ограничивают моделирование и подготовку. Бюджеты нативной и LLVM-проверки независимы и автоматически не увеличиваются. Для доверенного парсера/верификатора LLVM здесь нет жёстких ограничений CPU, стека или выделений памяти. Общий фрейм должен иметь корень в сыром слове RSP и включать входной слот возврата. Нужны живая и инициализированная память фрейма, доступная выровненная отдельная память состояния и корректное происхождение гостевых указателей. Этот C++ API доказывает поддерживаемое соответствие нативного кода LLVM, но не компиляцию C, сгенерированный машинный код, сбои или выбор неопределённых битов физическим CPU.

Структурированный C для машинного состояния может объединять шестнадцать записей GPR из обычных блоков возврата. Упакованные флаги записываются на каждом пути возврата; отказ проверки выравнивания по-прежнему не выполняет записей. Состояние фиксируется до извлечения адреса возврата командой RET, а статус нарушения профиля сохраняется. Вывод LLVM оставляет встроенные последовательности возврата для собственной оптимизации. Существующие перегрузки C++ для обёртки и модели сохраняют `InlineReturns`; явная компоновка `InterpreterMachineStateLayout::SharedGPRExit` использует для них один семантический генератор. Недопустимые значения компоновки отклоняются. Если невозможно построить полный обычный узел слияния или выделить новые адреса, остаётся исходная встроенная форма. Независимая модель и оба C-бэкенда при O0/O2 проверяют флаги отдельных ветвей, частичные записи регистров, циклы, сторожевые значения памяти и отказ по выравниванию. Сокращение исходного кода не добавляет сертификата обычного ABI или нативной эквивалентности.

`LowFunc::FunctionTemporaries` объявляет упорядоченные непересекающиеся диапазоны байтов без начального значения. Перед переходом конечного диспетчера через границу инструкции восстановление однократно сохраняет временную косвенную цель в зарезервированном локальном слоте функции. Общий проверяющий сохраняет только байты, действительно определённые на текущем пути; обычные машинные временные значения действуют лишь внутри инструкции. Метаданные и сохранение учитываются в бюджетах, а семантическая схема 13 связывает время жизни с сертификатом. Модель сырого состояния сохраняет побайтовую семантику; генерация исходника требует операндов размером ровно со слот и отвергает частичные псевдонимы. Индуктивные доказательства и вывод циклов пока отвергают эти объявления, поскольку состояния точек разреза их не связывают. Новые предположения о входе и сертификат машинного ABI не добавляются.

## Текущие ограничения

Адреса байткода, зависящие от входа, и связи состояния декодера поддерживаются только тогда, когда нужные конечные области значений и корреляции доказаны в заданных пределах. Это не означает поддержку произвольных схем косвенного декодирования. Динамические ветвления и циклы можно восстановить при доказанности всех целей диспетчеризации, но обычное покрытие ветвей не подтверждает все такие схемы. Неразрешённое управление и исчерпание необходимого бюджета доказательства означают отказ без исходного кода или частичной замены. Нативные вспомогательные вызовы, границы исключений и повторного входа, изменяемый код и другие архитектуры остаются вне контракта адаптера.

## Общая реализация

`SpecializationProvider` предоставляет полностью поднятые инструкции и свидетельства неизменного чтения. `NeverDInterpreterSpecialization` использует существующую семантику `SymExec` для частичного вычисления целочисленных операций и управления. Бинарный адаптер отвечает за отображение и декодирование инструкций и не реализует второй вычислитель их семантики.

Для конечного символьного адреса чтения встроенный решатель битовых векторов перечисляет кандидатов при текущих ограничениях. Множество принимается лишь после итогового UNSAT, доказывающего отсутствие иных адресов, и при полном свидетельстве неизменного чтения без ошибки памяти для каждого кандидата. Такой подтверждённый LOAD можно заменить в LowIR фиксацией адреса и точной цепочкой SELECT; обычные неподтверждённые чтения остаются динамическими. Один выбранный адрес не заменяет всё множество. Ограниченные совместные кортежи выбранных управляющих регистров и слотов входного кадра сохраняются между узлами, удерживая связи указателя и ключа декодирования. Слияние и расширение консервативны. Частичные SAT-модели и неизвестный результат решателя не доказывают полноту множества адресов или целей. Механизм не требует необязательного Z3.

Узел определяется позицией в нативном коде, режимом инструкций и константами выбранных управляющих регистров и слотов кадра на входе. Остальные побайтовые факты объединяются пересечением. При ослаблении входящих фактов узел вычисляется повторно. Это сохраняет циклы самой программы, не разворачивая каждую наблюдаемую итерацию. Все достижимые значения косвенной цели должны принадлежать ограниченному множеству, полнота которого доказана. Разрешённые цели превращаются в явные сравнения и рёбра CFG остаточного кода.

Динамические операции и обычные load/store остаются в LowIR. Между узлами можно передавать скалярные константы, аффинные указатели относительно входного кадра и доказанно постоянные байты кадра. Прочие выражения отбрасываются, а не разворачиваются без ограничения. Для памяти кадра используются существующие консервативные правила инвалидирования при алиасинге в символьном состоянии. Запись по неизвестному указателю, который может образовывать алиас, аннулирует конфликтующие факты. Ни приватность слота стека, ни возможность удалить его на основании недоказанного отсутствия алиасинга не предполагаются.

Уникальные синтетические метки инструкций различают клонированные контексты. Исходные границы инструкций сохраняются в отдельной карте происхождения. Исходные свидетельства релокаций, исключений и таблиц переходов не копируются на новые экземпляры инструкций. Восстановленный LowIR проходит обычное преобразование LowIR-to-MedIR до разделения маршрутов HighC/LLVM, используя общую обработку регистров, стека, CFG, SSA и ABI. Восстановление через HighC также требует успешной проверки MedIR.

Анализ ограничен бюджетами числа узлов, контекстов на адрес, операций, вычислений узлов и конечных целей перехода. При исчерпании бюджета или неподдерживаемой семантике остаточная функция не выдаётся. Полнота графа управления и успешная генерация исходного кода — разные условия. Публичный API проверяет оба и сообщает о них раздельно.

Явные пределы также заданы для множества адресов чтения, совместных управляющих кортежей и числа управляющих полей. Общий бюджет запросов и ограничения каждого запроса на логические элементы, конфликты, распространения и обращения к наблюдаемым литералам ограничивают доказательство; предел символьных узлов ограничивает рост выражений. JSON содержит эти бюджеты и счётчики `solverQueries` и `relationalWidenings`.

`AllowOverlappingNativeInstructions` — отдельный параметр, отключённый по умолчанию, для конечных нативных доказательств независимости и уточнения в LowIR. Каждый вход декодируется и проверяется независимо; перекрывающиеся байты должны совпадать со всеми предыдущими свидетельствами инструкций и неизменяемых чтений, включая чтения кандидата. Адреса LowIR кандидата остаются метками, а не свидетельствами байтов. `MaxNativeInstructionBytes` по умолчанию равен 1048576 и до сравнения учитывает полный размер каждого нового входа, включая повторные байты. Исчерпание бюджета или противоречивые байты запрещают сертификат. Параметр и предел связаны с хешем доказательства. Статический LowIR, индуктивные доказательства циклов и вывод планов отклоняют параметр даже при пустом плане; точный LLVM API и CLI сохраняют прежние значения по умолчанию.

## Свидетельства и тесты

Необязательный локальный JSON-отчёт содержит дайджест входных данных, выбранные управляющие элементы, бюджеты, статус, счётчики работы, число остаточных блоков, позиции исходных инструкций и неизменные байты, использованные при восстановлении. Отчёт включает информацию, полученную из входных данных, и записывается только по указанному локальному пути.

Публичные тесты используют самостоятельно разработанные машины с регистровой шитой диспетчеризацией и стековой диспетчеризацией. Для каждой предусмотрены программы с арифметикой, ветвлением и слиянием, а также циклами времени выполнения. Независимая эталонная реализация беззнаковых вычислений проверяет возвращаемые значения, записи в память, переносы и займы, а также защитные значения вокруг выходных данных. Восстановленные HighC и LLVMC компилируются с O0/O2 и ловушками неопределённого поведения, после чего результаты выполнения сравниваются с эталоном. Отрицательные случаи проверяют неразрешённую диспетчеризацию, изменяемые таблицы, несовместимый порядок байтов, метаданные исключений и бюджеты.

Дополнительные оригинальные fixture с конечными адресами используют выбираемые по входу неизменяемые записи, связанные поля указателя и ключа, а также общий обработчик в разных виртуальных позициях. Они проверяют ветвления со слиянием и циклы, выбор записи в которых зависит от текущего состояния программы. Независимый нативный эталон использует ABI SysV и Win64. Оба восстановленных маршрута C проверяются с O0/O2, ловушками неопределённого поведения и защитными значениями вокруг выходных данных. Отсутствие свидетельств чтения или недостаточный бюджет доказательства не должны приводить к выдаче частичного результата.

Расширенная матрица требует восстановления без ручных подсказок трёх независимых форм: прямо-связанного байткода указателей, ограниченного программного стека CALL/RET с вложенными виртуальными вызовами и цикла с вращающимся состоянием декодирования opcode. Нативное выполнение SysV/Win64 и восстановленные HighC/LLVMC при O0/O2 должны совпадать с независимыми математическими эталонами, включая защитные значения выходных данных. Неизвестные курсоры виртуального возврата, неограниченные ключи декодирования и исчерпанные бюджеты не должны приводить к выдаче исходника.

Отдельная матрица состояния машины требует при O0/O2 совпадения нативного выполнения и обоих путей C по всем 16 общим регистрам, определённым флагам и каждому байту проверяемого гостевого стека. Код, вызываемый косвенным CALL через регистр, читает и перезаписывает регистр цели; диспетчеризация через возвраты выбирает известные цели. Эталон проверяет фактическую запись адреса следующей инструкции, сохранение флагов и восстановление RSP. Ожидаемые адреса кода извлекаются из символов. Неизвестные или недопустимые наборы целей и недоказанные цели в памяти должны завершаться отказом без исходника. Это требования покрытия оригинальных fixture, а не гарантия для любой виртуальной машины или защитного продукта. Эти оригинальные fixture прошли описанные проверки локально на x64 Linux.

Открытые fixture вызовов через память охватывают неизменяемые ячейки указателей относительно RIP, конечные таблицы только для чтения с выбором по входу, инициализированные ячейки гостевого стека с конечными целями и ячейки, перезаписываемые push самого CALL. Локальная проверка на x64 Linux охватывает каждую из четырёх форм с 1 024 состояниями при нативном выполнении, HighC и LLVMC с O0/O2. Независимый эталон сравнивает все 17 слов состояния и 128 байт гостевого стека, включая адрес возврата, наблюдаемый вызываемым кодом. Недоказанные внешние или изменяемые ячейки, значения стека, испорченные алиасной записью, недопустимые цели и вызовы через ABI по умолчанию должны блокировать выдачу исходника.

Отдельная регрессия выполнения с фиксированными адресами предоставляет изменяемую гостевую память по её исходному адресу во входном образе. Оба C-бэкенда при O0/O2 должны читать и записывать это отображение, сохранять числовые гостевые адреса в выходных регистрах и не менять соседние защитные значения. Сгенерированные глобальные объекты не могут подменить отображение в этом эталоне. Эти локальные проверки не доказывают поддержку произвольных VM.

Специализированные тестовые цели описаны в [testing.md](testing.md).

## Автоматическое построение кандидатов доказательства циклов

Следующее требование сохранения предиката префикса применяется при `GeneralizeEntryPrefix = false`.

`inferLowIRLoopRefinementPlan` предлагает ограниченные шаблоны через общий символьный исполнитель. Точки разреза покрывают все циклы CFG; расширение сохраняет доказанные фиксированные биты и отбрасывает несохраняемые беззнаковые границы префикса. Наблюдаемые счётчики с единичным шагом и выведенные фазы образуют лексикографические ранги для вложенных возрастающих и убывающих циклов. `OriginalPrefix` и `CandidatePrefix` требуют `UseEntryPrefix`. Для точки за предыдущими разрезами отдельный ограниченный повтор от реального входа может получить достижимую пару префиксов. Это свидетельство не покрывает входную область: каждое прибытие должно влечь его предикат, а полное покрытие входа и переходов остаётся обязательным. `inferAndCheckBinaryLowIRLoopRefinement` требует полного восстановления и однозначных нативных источников, затем независимо повторяет полную проверку оригинала и кандидата. Предложения и соответствия недоверенные; сертификат может содержаться только в `Refinement`. Вывод и доказательство сохраняют отдельные явные бюджеты. Этот C++ API не запускается автоматически с `--devirtualize`. Недостижимые префиксы, произвольное сопоставление управления, ранги вне поиска, эквивалентность C-бэкенда и выбор неопределённых битов физическим CPU не поддерживаются.

Поиск единичных счётчиков после прежних форм целого слова и нулевого расширения распознаёт также обновления выровненных по байтам частей слова с сохранением всех остальных битов. При нескольких сечениях исключение крайних значений части слова предлагается только после доказательства на сохранённых конкретных и всех текущих входящих состояниях. Расширение удаляет неудачные условия без повторного введения и может обнаружить другую часть уже известного слова. Маски используют существующий параметр целого слова; полные ранги и наблюдения состояния сохраняются. Общие бюджеты узлов/запросов и независимая полная проверка уточнения остаются обязательными.

При нескольких сечениях за каждой неудачной попыткой наблюдаемого кортежа счётчиков следует вариант с начальной постоянной 64-битной фазой, прежде чем поиск перейдёт к следующему кортежу. Оба варианта отдельно расходуют попытки `MaxRankCandidates` и делят тот же бюджет запросов. Начальная фаза не должна возрастать ни на одном выполнимом переходе; если строгое убывание остатка кортежа не доказано, переход обязан строго уменьшать фазу. Неотрицательные разностные ограничения отвергают циклы положительного веса. Это позволяет последовательным циклам повторно использовать заново инициализированный счётчик, сохраняя обязательства прогресса внутри циклов. Имеющиеся фазы между счётчиками могут сочетаться с начальной фазой. Каждый полный кортеж проверяется под исходными полными предикатами переходов, а итоговый проверяющий уточнения независимо перепроверяет предложенный ранг. Поиск с единственным сечением не добавляет такой бесполезный постоянный префикс.

Кандидат с единственным сечением должен перекрывать все циклы первоначально достижимых блоков, включая циклы, отделённые от входа удалением сечения. Каждая проверка расходует `MaxCutpointAttempts` до символьного исполнения. Приоритет сохраняют скалярные счётчики с единичным прогрессом на каждом ребре возврата. Затем до восьми предложений кортежей наблюдаемых единичных счётчиков чередуются по одному с более общими скалярными гипотезами условий и границ. После остальных скалярных гипотез поиск кортежей продолжается без повторений. Порядок не зависит от предела бюджета. Каждая попытка кортежа восстанавливает сохранённые полную стабильную модель и переходы; неудачная проверка области отключает только это семейство. Отвергнутые скалярные условия не сужают область кортежей. `MaxRankCandidates` и бюджеты запросов, операций и путей продолжают суммироваться. Предложение по-прежнему требует полной проверки refinement. Аддитивная ветвь возврата может запускать структурное расширение, даже если соседние ветви сохраняют или сбрасывают значение; предложенная модель всё равно должна пройти все проверки входов и переходов.

При поиске с одной точкой разреза пробуется другая допустимая точка, если выполнение обобщённого шаблона нарушает контракт сохранения или памяти. Разрез в теле может потерять защищённое условием отношение счётчика, которое сохраняется в заголовке. Отклонение одной гипотезы не отклоняет все точки. Ошибки реального входного префикса, некорректный ввод, неподдерживаемое выполнение и исчерпание бюджетов по-прежнему останавливают поиск. Учёт общий, включая `MaxCutpointAttempts` и запросы решателя; каждое предложение требует нового полного доказательства. Другие вложенные множества разрезов этот механизм не ищет.

`GeneralizeEntryPrefix` по умолчанию равен `false` и требует `UseEntryPrefix`. Обычный режим сохраняет предикат захваченного пути при каждом достижении. Явное обобщение рассматривает выражения префикса вне этого пути как тотальные непроверенные функции шаблона. По-прежнему нужны достижимый парный свидетель, полное покрытие входов и сегментов, равенство всех регистров и кадра, проекции параметров, нативные условия и строгое убывание ранга в расширенной области индукции. Вывод расширяет точку отсечения только при входящем состоянии вне области свидетеля, затем заново строит и проверяет все общие переходы. Первый свидетель с нулём итераций не может скрыть другой вход с циклом. Политика связана с дайджестом индуктивного сертификата.

Для вложенных циклов можно предложить строгие и нестрогие беззнаковые границы между наблюдаемыми счётчиками с единичным шагом и неизменными значениями префикса из управляющих предикатов, включая выходы по равенству. Сначала проверяются конкретные состояния; затем неверные отношения монотонно удаляются на общих входящих переходах. Обходы и запросы используют существующие явные лимиты, а итоговый проверяющий оригинала/кандидата независимо доказывает шаблоны.

При выводе вложенных циклов также предлагается равенство кэшированного операнда со счётчиком или неизменным управляющим входом, если их выражения префикса совпадают. Проверяется каждое конкретное входящее состояние; кандидаты сохраняются для кэшей, обнаруженных при последующих расширениях, а нарушенные общим входящим состоянием отношения удаляются. Каждое слово сохраняет собственный восстанавливаемый параметр; равенство остаётся проверяемым предикатом. Рекуррентные копирования могут ускорить удаление случайно фиксированных битов, но не задают предполагаемую семантику.

Вывод для вложенных циклов также ищет сохранённые сравнения равенства и неравенства в полях с не более чем 16 изменяющимися битами. Каждое отношение использует текущие значения счётчика и границы; кеш сохраняет отдельный восстанавливаемый параметр состояния. Входная проверка или свёртка начального значения в константу может скрыть сравнение до следующего расширения. Тогда допускаются новые кандидаты, но отвергнутые или удалённые не восстанавливаются. Они должны выполняться для всех сохранённых конкретных входов и текущих входящих переходов. Обходы переменных DAG кешируются для каждой точки разреза и учитываются в общем бюджете предикатов. Полное покрытие нативных путей, равенство всего состояния и строгое уменьшение ранга остаются независимыми требованиями. Поиск счётчиков продолжается после общих переходов: внешний счётчик, скрытый первым свидетельством внутреннего цикла, также получает проверенные кандидаты границ и копий операндов. Отвергнутые отношения не восстанавливаются; проверка единичных шагов учитывает бюджет символьных узлов.

Повторное исполнение входных префиксов посещает ожидающие ветви до дальнейшего разворачивания предыдущего цикла. Это позволяет найти короткий достижимый свидетель, даже если другая ветвь допускает произвольное число итераций. Вывод плана и проверка исходной/кандидатной программы используют один порядок. Вся работа по-прежнему учитывается в существующих бюджетах; свидетель префикса не заменяет полного покрытия входов, сохранения инвариантов и проверки завершения.

`pairLowIRLoopRefinementPlans` объединяет два независимо предложенных плана отношения программы к самой себе через явные элементы `LowIRLoopCutpointPair`. Каждая точка разреза должна быть сопоставлена ровно один раз. `SharedInputs` добавляет предикаты равенства между индуктивными входами одинаковой ширины, сохраняя обе привязки и проекции для проверки. Остальные временные значения независимы, префиксные входы кандидата используют `CandidatePrefix`, сохраняются оба предиката и выбирается исходный ранг. Значения `UseEntryPrefix` должны совпадать; `GeneralizeEntryPrefix` включается, если нужен хотя бы одному плану. Определения временных значений не должны перекрываться, а ширина использования должна совпадать точно. `MaxMetadata` по умолчанию равен 65536 и ограничивает построение до копирования. Результат остаётся недоверенным предложением: `checkLowIRLoopRefinement` обязан независимо проверить полноту покрытия, равенство состояний и памяти кадра, наблюдения и строгое продвижение. Помощник не выдаёт сертификат и не меняет параметры CLI по умолчанию.

`inferAndCheckLowIRLoopRefinement` ищет проверенное отношение между циклами LowIR. По порядку проверяются стандартные планы, планы всех входов ветвей и их фильтрованный вариант. Сначала сопоставляются одинаковые семейства, затем все разные пары, затем отдельные циклические сечения кандидата. Полное семейство выбирает преемников блока ветвления внутри циклической компоненты с единственным исходящим ребром. Фильтр исключает ветвь, только если все её пути сходятся в одном нетерминальном узле до достижения цели обратного ребра DFS. Учитываются все преемники, включая выходы и границы; схождение только на границе не исключает ветвь. Жадное добавление сечений по-прежнему покрывает каждый изначально достижимый цикл. Эти предложения сохраняют фазы и не требуют успешного стандартного вывода. `MaxCutSelectionWork` отдельно ограничивает анализ общих путей, включая построение и сравнение множеств; `CutSelectionWork` учитывает работу и при неудаче, расходуя также оставшийся общий `MaxSearchWork`. Стандартный и полный селекторы не меняются. Успехи и неудачи кешируются: до трёх планов на сторону, перестановки — по необходимости. Дополнительные семейства пропускают наборы сечений, уже сохранённые на той же стороне, даже если план получен семейством с большим номером. Пустые и дублирующие семейства не используют символьных запросов, но считаются попыткой. Все шесть планов делят один бюджет `MaxMetadata`; каждое построение пары ограничивается отдельно. По умолчанию `MaxRankPairingAttempts = 0` сохраняет прежний порядок предложений и учёт, предлагая равенство только для входов кадра одинаковой ширины и смещения. При включении после каждого неудачного обычного сопоставления пробуются прямые связи рангов, затем их объединение с совместимыми связями кадра. Непустые кортежи рангов должны иметь одинаковую длину; каждый компонент обязан точно обозначать единственный вход `Original` по полной идентичности `NdVar`, с различными позициями на каждой стороне и равными ненулевыми ширинами. Константы, выражения, префиксные входы и преобразования ширины не угадываются. Объединение сохраняет связи рангов и пропускает связи кадра, конфликтующие на любом конце. Наборы связей, повторяющие обычное предложение или предложение только рангов, пропускаются до повторной полной проверки. Начатые дополнительные попытки, включая непригодные и дублирующие, расходуют и `MaxRankPairingAttempts`, и общий `MaxPairingAttempts`; обходы, сравнения и хранение учитываются в `MaxSearchWork`, а оба рабочих вектора делят один лимит `MaxMetadata` на попытку. Исчерпание только дополнительного лимита не мешает последующему обычному доказательству в оставшихся общих бюджетах. Аффинные отношения и произвольные наборы обратных связей по-прежнему требуют явного сопоставления. Основной механизм сопоставления и полная проверка сохраняют исходные аудированные записи вызывающего кода, witness, входную область, наблюдения кадра и обязательства завершения. В `LowIRLoopAlignmentLimits` бюджет `MaxSolverQueries` общий для всех выводов и доказательств, включая неудачные; каждый вызов получает не больше минимума лимита этапа и общего остатка. `MaxSearchWork`, `MaxMetadata`, `MaxCandidateAttempts`, `MaxPairingAttempts` и `MaxCuts` ограничивают построение поиска и перебор. Исчерпание отдельной попытки допускает повторную; исчерпание общего бюджета останавливает поиск. `Unsupported` означает, что отношение не найдено, а не доказанную неэквивалентность. Только заново успешно проверенный `Refinement` содержит сертификат. Значения CLI по умолчанию не меняются.


Поиск согласования передаёт `MaxCuts` общему механизму вывода. После проверки входа и выбора полного множества сечений, покрывающего все циклы, слишком большое множество отклоняется до символьного обхода входа или расширения инвариантов. Этот предел на план не уменьшает `MaxCutpointAttempts` и не запрещает допустимые повторные попытки с одним сечением. Затраты выбора фильтрованных семейств сохраняются. Самостоятельный и нативный вывод сохраняют прежние пределы; каждая принимаемая связь по-прежнему требует неизменённого полного проверяющего.
