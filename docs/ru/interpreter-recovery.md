# Восстановление исходного кода интерпретатора

Экспериментальный этап специализации интерпретатора удаляет статически разрешённую диспетчеризацию из слинкованной функции x64, сохраняя входные данные времени выполнения, эффекты памяти, ветвления и циклы. Он опирается на семантику инструкций, а не на сигнатуры обработчиков или таблицу опкодов конкретного средства защиты.

```sh
neverd decompile program --func vm_entry --devirtualize \
  --recovery-report recovery.json -o recovered.c
neverd decompile program --func vm_entry --devirtualize \
  --llvm -o recovered-llvm.c
```

`--vm-control` выбирает полные регистры общего назначения, по которым различаются контексты интерпретатора. Параметр можно повторять; конкретных значений он не задаёт. Например, можно выбрать указатель байткода, значение которого устанавливается входным кодом. Входное значение времени выполнения, используемое как счётчик, должно оставаться динамическим. Если в точке слияния разных значений указателя недостаточно разделения контекстов, восстановление может остановиться. Движок не должен компенсировать это угадыванием цели диспетчеризации. Если указатель сохранён в стеке, `--vm-control-stack=-16:8` выбирает восемь байтов по смещению −16 от RSP на входе. Смещение отсчитывается от входа в функцию, а не от текущего указателя стека после его изменения.

C API — `neverd_devirtualize_source_v1()` из `neverd/sdk/NeverDCAPIDevirtualize.h`. Он выполняется в отдельной транзакции и не меняет обычный кэш декомпиляции сеанса. При неудаче исходный код не возвращается, но может возвращаться диагностический JSON. Обе возвращённые строки освобождаются через `neverd_free_string()`.

## Автоматическое обнаружение состояния управления

CLI и все версии C API восстановления исходного кода включают автоматическое обнаружение по умолчанию. В независимом от поставщика инструкций C++ API сохраняется `SpecializationOptions::DiscoverControlState = false`; вызывающая сторона может задать `true`. Ручные подсказки `--vm-control` и `--vm-control-stack` остаются необязательными ключами контекста. Обычные автоматически найденные поля сохраняют ограниченные совместные отношения конечных значений, не создавая ключи контекста и не фиксируя входы на значениях из выборки. Счётчики остаются динамическими, если описанному ниже избирательному уточнению памяти не потребуются их доказанные константы.

Обнаружение следует неразрешённым зависимостям управления и адресов до структурированных регистровых входов узла и сведений о первоначальном создании входов памяти, включая узкие диапазоны байтов. Слот кадра предлагается только тогда, когда эти сведения указывают на неизменённую со входа в узел память в точном диапазоне относительно кадра на входе в функцию. Последующие чтения равных значений или значений, переданных из записи, не создают дополнительных входных зависимостей; неизвестные байты, созданные после сброса фактов о памяти, не считаются входными слотами. История чтений остаётся доступной другим анализам. Новые зависимости запускают анализ заново от входа в функцию. Для каждого сохраняемого отношения по-прежнему требуется полное доказательство конечного диапазона ограничиваемых им битов; записи с возможным наложением адресов отменяют соответствующие факты о памяти. Произвольная внешняя память и неограниченные отношения значений не становятся конечными.

Запросы к производителям сохраняют битовые маски на границах узлов, не расширяя их до целых байтов; для арифметики по-прежнему консервативно включается префикс младших битов, способных передать перенос или заимствование в требуемый бит.

Если уже отслеживаемые зависимости памяти повторно мешают доказать точный адрес, уточнение может дополнительно использовать их доказанные входящие константы как ключи контекста. Оно не разбивает многозначные кортежи на новые рёбра и не добавляет чтения гостевой памяти для выбора контекста: конечность значений не доказывает безопасность дополнительного чтения. Поэтому динамические или неограниченные состояния, зависящие от памяти, по-прежнему могут остановить восстановление в заданных пределах.

Обратные запросы к источникам значений определяются входом нативного узла, режимом инструкций, видом поля и диапазоном байтов. Только ребро, чей преемник запрашивает это поле, раскрывает зависимости его значения, в том числе при конечном, но недостаточно точном диапазоне. Это может вызвать ограниченные бюджетом перезапуски анализа от входа, не назначая повторно используемому физическому регистру единственную глобальную роль. Поиск зависимостей ограничен и неполон; восстановление без ручных подсказок не гарантируется для любого интерпретатора.

Проекция обычных автоматических полей также ограничивается запросами узла назначения. Неконстантное поле включается в совместное отношение конечных значений на ребре только тогда, когда его запрашивает узел назначения. Ручные поля и поля, автоматически повышенные до ключей контекста, по-прежнему проецируются глобально. Известные константные байты, точные указатели относительно кадра на входе и сведения о происхождении сохраняются независимо от запросов. Это не позволяет несвязанным полям разных стадий обработчиков перемножать число комбинаций значений в отношении. Заданные бюджеты и требования к доказательствам целей переходов, адресов памяти и состояния при возврате не меняются.

Для обычных автоматических полей каждый столбец кортежа ограничивает только запрошенные биты и содержит соответствующую маску. При слиянии сохраняются лишь биты, ограниченные на всех входящих путях. Остальные биты того же байта остаются значениями времени выполнения: диапазон хранения поля не удостоверяет полный конечный диапазон значений для всей этой области. Байт становится константой только после доказательства постоянства всех восьми битов.

Ручные поля и поля, повышенные до ключей контекста, по-прежнему сначала пытаются глобально доказать отношения по всей ширине. Если доказательство не даёт результата, можно сохранить отношение только для запрошенных битов; это не предоставляет недоказанные байты ключу контекста и не обходит исчерпанный глобальный бюджет.

При перезапуске с новым графом обычные автоматические диапазоны хранения, полностью содержащиеся в других полях, могут использовать эти более широкие поля. Исходные позиции фаз и запросы битов остаются неизменными. Ручные поля, поля контекста и поля, предложенные непосредственно неразрешённым адресом памяти, сохраняют точные диапазоны. `MaxControlFields` ограничивает число полей, фактически сохранённых после этой нормализации. `DiscoveredControlFields` остаётся накопительным и может превышать число активных полей; лимит полей и глобальные бюджеты работы не увеличиваются.

Обычное автоматическое поле с полностью доказанным конечным диапазоном не добавляет сразу всех производителей своего значения как управляющие поля. Поиск сохраняет эти зависимости-кандидаты и активирует их лишь тогда, когда восстановление всё ещё заблокировано, а непосредственное уточнение не даёт кандидатов. Поля, повышенные до ключей контекста, по-прежнему раскрывают зависимости производителей немедленно. Посещения при поиске, перезапуски и доказательства сохраняют прежние накопительные бюджеты.

Полный конечный диапазон также позволяет доказать постоянство отдельных байтов, даже если слово целиком меняется. Например, в диапазоне `{0, 0x100}` младший байт постоянен. Как константы сохраняются только байты, одинаковые во всех перечисленных кортежах, с учётом порядка байтов целевой архитектуры; остальные остаются динамическими. Частичное перечисление, неизвестный результат решателя или исчерпание бюджета доказательства не дают таких фактов.

Доказательства конечных диапазонов можно повторно использовать в пределах одного запуска восстановления, включая перезапуски уточнения. Ограниченный кэш сравнивает полный упорядоченный DAG выражений с точностью до согласованного переименования свободных переменных; общие переменные, разрядности, биты констант, параметры операторов и предел проекции остаются частью ключа. Сохраняются только полные диапазоны и доказательства превышения предела. Неизвестные и частичные результаты не сохраняются; при отсутствии записи или нехватке места используется обычное доказательство. Все глобальные бюджеты продолжают действовать, а `solverQueries` считает фактические вызовы решателя.

При одном и том же предикате полный диапазон единственного изменяющегося столбца и доказанные единственные значения остальных определяют точное совместное отношение, если достижимость установлена. Несколько изменяющихся столбцов по-прежнему требуют совместного доказательства. Столбец с маской, покрывающий весь свой битовый диапазон, можно опустить лишь после доказательства независимости его входных битов от предиката и всех остальных столбцов. Общие входы, неизвестные результаты и частичное перечисление не позволяют предполагать декартово произведение.

По умолчанию `MaxControlFields = 16` ограничивает сумму ручных и автоматических полей, `MaxControlRefinements = 16`, `MaxDiscoveryVisits = 65536`. Перезапуски разделяют глобальные бюджеты узлов (включая синтетические), операций, вычислений, запросов решателю и посещений при обнаружении. `contexts` считает нативные контексты и, как `evaluatedOperations`, `nodeEvaluations` и `solverQueries`, суммируется по всем попыткам. Контексты на адрес, активные нативные слоты возврата, поля и кортежи остаются структурными ограничениями отдельной попытки. Лимит запросов остаётся равным 4096. При исчерпании частичный результат не публикуется; `residualBlocks` описывает только итоговый остаточный граф.

Параметр CLI `--vm-max-refinements=N` требует положительного целого числа и по умолчанию равен 16. В C тот же предел задаётся через `neverd_devirtualize_source_v2()` или `neverd_devirtualize_machine_source_v2()`: обнулить `neverd_devirtualize_options_v2`, задать `base.struct_size = sizeof(neverd_devirtualize_options_v2)`, затем `max_control_refinements` (ноль сохраняет значение по умолчанию 16). Встроенный `base` содержит параметры v1; оба поля reserved должны оставаться нулевыми. Существующие структуры и точки входа v1 не меняются и игнорируют добавленные хвостовые расширения. Остальные бюджеты работы и доказательств продолжают действовать.

В JSON-отчёт добавлены `discoverControlState`, `maxControlRefinements`, `maxDiscoveryVisits`, `discoveredControlFields`, `discoveredContextFields`, `controlRefinements` и `discoveryVisits`: они описывают включённое поведение, ограничения и объём анализа. Само обнаружение полей не доказывает успешность восстановления.

## Контракт выполнения

Сейчас бинарный адаптер принимает слинкованные образы x64 ELF и PE по их отображённым адресам. Отображения, байты и права доступа должны оставаться неизменными; параллельные изменения исключены. Строгий подъём по требованию следует по достижимому машинному коду. Неподдерживаемые инструкции, вызовы, непрозрачные операции, обращения с требованиями к порядку памяти, неразрешённый поток управления и обработка исключений языка останавливают восстановление.

Восстановление PE требует полных метаданных образа, включая все релокации и записи об исключениях. CLI загружает их до применения `--func`; пользователи C API не должны заранее ограничивать сеанс через `neverd_session_restrict_function()`. Бинарный адаптер отклоняет образы, загруженные с ограниченным набором функций: пропущенные метаданные не доказывают отсутствие исправлений загрузчика или рёбер исключений.

Для получения константы при чтении образа нужен полный диапазон только для чтения, содержимое которого обеспечено файлом, без перекрывающихся отображений и исправлений загрузчика. Изменяемые таблицы, неразрешённые релокации и снимок, полученный во время выполнения, не доказывают неизменность чтения. Релокации COPY и структурно неполные каталоги исключений отвергаются. Если каталог PE и диапазоны функций полны, нераспознанный обработчик в другой функции не препятствует анализу выбранного входа; при достижении кода, охваченного этим обработчиком, восстановление прекращается.

Область восстановления предполагает обычный возврат по ABI: целевой диапазон каждой записи через адрес внешнего происхождения не должен пересекаться со слотом адреса возврата на входе. Это явное предусловие для вызывающей стороны и окружения, в том числе для адресов, вычисленных из внешних целых значений. Отсутствие сведений о происхождении из кадра не доказывает, что числовые адреса не пересекаются. Для адресов записи, производных от кадра, непересечение должно быть доказано; при возврате требуется восстановить исходный указатель стека. Сведения о происхождении сохраняются при выгрузке значений в стек и слиянии потоков. Потеря аффинного выражения не превращает адрес во внешний указатель. Переключение стека, возврат с дополнительной очисткой стека вызываемой функцией и диспетчеризация через RET пока отвергаются. Адаптер применяет семантику x64 с порядком байтов little-endian.

Результат — исходный код и IR для анализа. Он не доказывает безопасность релокации, раскрутки стека, асинхронных исключений или замены бинарного кода. Режим patch отвергает этот параметр. Поддержка любого интерпретатора или любой конфигурации защиты не заявляется.

Точные формы x64 `PUSHFQ`/`POPFQ` сохраняются в остаточной программе. Анализ рассматривает каждый снимок машинных флагов как неизвестное значение времени выполнения; лифтер отдельно объединяет смоделированные арифметические флаги. Восстановление флагов также остаётся эффектом времени выполнения. Адрес, полученный из неизвестных флагов, не может использовать контракт отсутствия пересечения внешнего указателя со слотом адреса возврата; диспетчеризация с недоказанным конечным набором целей по-прежнему отклоняется.

Перед сохранением полного образа флагов каждый смоделированный арифметический флаг и флаг направления должен быть определён внутри восстанавливаемой функции. Прямое чтение флага также требует определения на каждом достижимом предшествующем пути, даже если символьное упрощение устраняет его значение. Иначе восстановление отклоняется, а не выдаёт C с ловушкой «неизвестный регистр».

Временные значения LowIR действуют только внутри одной поднятой машинной инструкции. Каждый читаемый байт должен быть определён ранее в этой же инструкции; повторно использованное смещение из предыдущей инструкции или алгебраическое сокращение неопределённого значения не доказывают корректность исходного кода. Входные константы могут связывать только физические регистры.

## Текущие ограничения

Адреса байткода, зависящие от входа, и связи состояния декодера поддерживаются только тогда, когда нужные конечные области значений и корреляции доказаны в заданных пределах. Это не означает поддержку произвольных схем косвенного декодирования. Динамические ветвления и циклы можно восстановить при доказанности всех целей диспетчеризации, но обычное покрытие ветвей не подтверждает все такие схемы. Неразрешённое управление и исчерпание необходимого бюджета доказательства означают отказ без исходного кода или частичной замены. Нативные вспомогательные вызовы, границы исключений и повторного входа, изменяемый код и другие архитектуры остаются вне контракта адаптера.

## Общая реализация

`SpecializationProvider` предоставляет полностью поднятые инструкции и свидетельства неизменного чтения. `NeverDInterpreterSpecialization` использует существующую семантику `SymExec` для частичного вычисления целочисленных операций и управления. Бинарный адаптер отвечает за отображение и декодирование инструкций и не реализует второй вычислитель их семантики.

Для конечного символьного адреса чтения встроенный решатель битовых векторов перечисляет кандидатов при текущих ограничениях. Множество принимается лишь после итогового UNSAT, доказывающего отсутствие иных адресов, и при полном свидетельстве неизменного чтения без ошибки памяти для каждого кандидата. Такой подтверждённый LOAD можно заменить в LowIR фиксацией адреса и точной цепочкой SELECT; обычные неподтверждённые чтения остаются динамическими. Один выбранный адрес не заменяет всё множество. Ограниченные совместные кортежи выбранных управляющих регистров и слотов входного кадра сохраняются между узлами, удерживая связи указателя и ключа декодирования. Слияние и расширение консервативны. Частичные SAT-модели и неизвестный результат решателя не доказывают полноту множества адресов или целей. Механизм не требует необязательного Z3.

Узел определяется позицией в нативном коде, режимом инструкций и константами выбранных управляющих регистров и слотов кадра на входе. Остальные побайтовые факты объединяются пересечением. При ослаблении входящих фактов узел вычисляется повторно. Это сохраняет циклы самой программы, не разворачивая каждую наблюдаемую итерацию. Все достижимые значения косвенной цели должны принадлежать ограниченному множеству, полнота которого доказана. Разрешённые цели превращаются в явные сравнения и рёбра CFG остаточного кода.

Динамические операции и обычные load/store остаются в LowIR. Между узлами можно передавать скалярные константы, аффинные указатели относительно входного кадра и доказанно постоянные байты кадра. Прочие выражения отбрасываются, а не разворачиваются без ограничения. Для памяти кадра используются существующие консервативные правила инвалидирования при алиасинге в символьном состоянии. Запись по неизвестному указателю, который может образовывать алиас, аннулирует конфликтующие факты. Ни приватность слота стека, ни возможность удалить его на основании недоказанного отсутствия алиасинга не предполагаются.

Уникальные синтетические метки инструкций различают клонированные контексты. Исходные границы инструкций сохраняются в отдельной карте происхождения. Исходные свидетельства релокаций, исключений и таблиц переходов не копируются на новые экземпляры инструкций. Восстановленный LowIR проходит обычное преобразование LowIR-to-MedIR до разделения маршрутов HighC/LLVM, используя общую обработку регистров, стека, CFG, SSA и ABI. Восстановление через HighC также требует успешной проверки MedIR.

Анализ ограничен бюджетами числа узлов, контекстов на адрес, операций, вычислений узлов и конечных целей перехода. При исчерпании бюджета или неподдерживаемой семантике остаточная функция не выдаётся. Полнота графа управления и успешная генерация исходного кода — разные условия. Публичный API проверяет оба и сообщает о них раздельно.

Явные пределы также заданы для множества адресов чтения, совместных управляющих кортежей и числа управляющих полей. Общий бюджет запросов и ограничения каждого запроса на логические элементы, конфликты, распространения и обращения к наблюдаемым литералам ограничивают доказательство; предел символьных узлов ограничивает рост выражений. JSON содержит эти бюджеты и счётчики `solverQueries` и `relationalWidenings`.

## Свидетельства и тесты

Необязательный локальный JSON-отчёт содержит дайджест входных данных, выбранные управляющие элементы, бюджеты, статус, счётчики работы, число остаточных блоков, позиции исходных инструкций и неизменные байты, использованные при восстановлении. Отчёт включает информацию, полученную из входных данных, и записывается только по указанному локальному пути.

Публичные тесты используют самостоятельно разработанные машины с регистровой шитой диспетчеризацией и стековой диспетчеризацией. Для каждой предусмотрены программы с арифметикой, ветвлением и слиянием, а также циклами времени выполнения. Независимая эталонная реализация беззнаковых вычислений проверяет возвращаемые значения, записи в память, переносы и займы, а также защитные значения вокруг выходных данных. Восстановленные HighC и LLVMC компилируются с O0/O2 и ловушками неопределённого поведения, после чего результаты выполнения сравниваются с эталоном. Отрицательные случаи проверяют неразрешённую диспетчеризацию, изменяемые таблицы, несовместимый порядок байтов, метаданные исключений и бюджеты.

Дополнительные оригинальные fixture с конечными адресами используют выбираемые по входу неизменяемые записи, связанные поля указателя и ключа, а также общий обработчик в разных виртуальных позициях. Они проверяют ветвления со слиянием и циклы, выбор записи в которых зависит от текущего состояния программы. Независимый нативный эталон использует ABI SysV и Win64. Оба восстановленных маршрута C проверяются с O0/O2, ловушками неопределённого поведения и защитными значениями вокруг выходных данных. Отсутствие свидетельств чтения или недостаточный бюджет доказательства не должны приводить к выдаче частичного результата.

Специализированные тестовые цели описаны в [testing.md](testing.md).

## Восстановление с явным состоянием машины

`--devirtualize --vm-machine-state` или `neverd_devirtualize_machine_source_v1()` выбирает отдельный исходный ABI: указатель на 17 выровненных слов `uint64_t` (RAX, RCX, RDX, RBX, RSP, RBP, RSI, RDI, R8–R15, RFLAGS). Только нулевой беззнаковый 64-битный статус означает успех. Ненулевой статус не отменяет записи в память. Состояние фиксируется до извлечения адреса последним RET. Его буфер не должен пересекаться с гостевой памятью; нужны исходные отображения и 64-битный little-endian хост.

Профиль требует CPL3/IOPL0, отключённого теневого стека, отсутствия асинхронных событий и обычного выполнения без исключений доступа. Начальные флаги должны быть каноническими с нулевыми TF/RF/VM/AC/VIF/VIP; POPFQ должен оставлять TF/AC нулевыми, что проверяет исходный код. PUSHFQ/POPFQ используют явное состояние; RDSSP сохраняет регистр, достигнутый INCSSP отклоняется. Прямые near CALL сохраняют реальную запись адреса возврата; внутренний RET требует доказанной единственной цели. Полные сохранения указателей кадра распространяются, частичные записи или возможные алиасы уничтожают факты. Метаданные исключений допускаются только для обычного пути, без доказательства диспетчеризации или раскрутки стека. Отчёт содержит `sourceABI` и `executionProfile`; ограничения ABI по умолчанию сохраняются.

Обычный исходный ABI создаёт приватный кадр вызова. Все внешние диапазоны LOAD/STORE, включая вычисленные адреса, должны быть отделены от нативного приватного кадра и его восстановленной памяти в исходном коде; это явная предпосылка. Общая проверка отклоняет утечки адресов кадра, зависимые от них результаты и ветвления, а также чтение неинициализированных приватных байтов. ABI состояния машины сохраняет гостевые адреса и не использует эту предпосылку приватного кадра.

Если неопределённые флаги влияют на управление, адреса или определённые выходные значения, необходимо отдельное доказательство невлияния. Текущий отчёт не предоставляет такого доказательства и не подтверждает подобное поведение, зависящее от процессора.
