# x86 instruction support audit

This audit starts from `f17f944a7` (the merge of virtualization support in
`367df5693`) and the pinned Capstone revision
`1d29fa3c00c916e62e23c3da7bc0cc35d2cf4c44`. It covers NeverD's 32-bit x86 and
64-bit x86 targets, not a 16-bit real-mode target.

The `dev` integration also adopts the decoder update in `cb6678521`, using
Capstone `b9048c860493ce8511f4d535526495ff273c7641`. The original audit baseline
above and the integration verification below are recorded separately.
The floating-point follow-up also integrates `39d727a54`, with Capstone
`ed51c6cbeb198c2a2d72412c8571f160ec37c30a`. The integration includes
the Windows type/ABI update merged in `5a3354cad`.
Before publication, `c17776c92` also advances the decoder to
`9d458aa76ce3b294d6ffea9f16a5b5d0cd2a6eae`.

## Support is a pipeline property

Decoder recognition, strict LowIR lifting, executable LLVM/C output and
software emulation are separate capabilities. A switch label does not prove
any of them. Valid instruction forms can also differ in operand width,
encoding, mask, rounding, segment or addressing mode.

The audit baseline has 1,652 instruction IDs; the MSRLIST decoder follow-up
appended two; the bounded-system follow-up adds eight more, bringing the
current census to 1,662. Twenty IDs without literal
mentions in the lifter are generated by the floating-point family macros in
`X86FPArithState.h` and `X86FPPackedConvertState.h`; they are not missing
implementations. The previous source-text coverage script cannot establish
complete instruction support or semantic test coverage.

`X86SystemState.def` and `X86SystemState.h` own the system-instruction inventory
and operand/completion shapes. LowIR, Low-to-Med conversion, Med verification,
LLVM and both C routes consume that contract. `X86SystemStateAsm.h` owns the
assembly constraints shared by the emitters. No new intrinsic renumbers an
existing intrinsic.

The bounded system instructions emit real native instructions with their
memory and flag constraints. They require the architectural CPU features,
privilege and machine state at execution time. The scalar emulator explicitly
refuses these environment-dependent effects before mutating state. This change
does not introduce a virtual CPU or synthesize successful hardware responses.

The system-memory follow-up also brings the existing CET writes and enqueue
intrinsics under this contract without changing their serialized IDs.
WRSSD/WRUSSD retain their 32-bit-target forms; the qword forms require x64.
ENQCMD/ENQCMDS retain an implicit ES destination, independent of the source
segment. The i386 forms use the segmented block contract described below.
Their native implementations own all permission checks and memory accesses; no compiler
preload or ordinary store is substituted. The existing scalar enqueue executor
continues to require explicit CPL/PASID state and returns retry for ordinary
memory. It does not acquire a real device portal from this change.
Windows HighC keeps MSVC intrinsics for unsegmented CET writes, including the
required header, after the common operand validation. Other source spellings
use the owned assembly contract.

LLVM-to-C now lowers masked memory operations to guarded lane accesses in its
private module clone before scalarization. Inactive lanes neither access memory
nor consume poison values. Constant expressions left by vector packing are
simplified before printing, including with pipeline optimization disabled, so
unneeded i128 expressions do not break i386 C compilation. LLVM-to-C also
supplies signed/unsigned `_BitInt(128)` aliases on i386 compilers without native
128-bit aliases, retaining 65..128-bit value operations and packed FP/MXCSR
results. General wide-integer runtime and ABI support remains unqualified.

The VEX/EVEX failures were latent mode-selection defects. The canonical prefix
structures now own register and address extension selection; all 133 callers
of the former mode-independent EVEX register helpers use that authority.
Tests retain the 32-bit BOUND/LES disambiguation and reserved-field checks.

`X86FPEncoding` now owns the floating-point prefix decision too. REX2 R4/B4
extend GPRs but are ignored for XMM operands; address registers use all applicable
extension bits. Used VEX vvvv selects the low eight registers in 32-bit mode,
while an unused vvvv field must still be all ones. Arithmetic, COMI, mask
comparison, scalar/packed conversion, approximation and ROUND retain their
family-specific rules. REX2 cannot encode ROUND's map 3.

## Known remaining gaps

| Instructions or family | Missing contract |
| --- | --- |
| LDS, LES, LSS, LFS, LGS | Coupled GPR/segment-selector completion, hidden descriptor state and fault ordering. The former ordinary load/COPY approximation is now explicitly refused in both strict and permissive lifting. |
| 3DNow! arithmetic, comparison, conversion and rearrangement operations | Packed-lane results, instruction-specific floating-point rules and MMX/x87 state. The 24 former COPY/scalar-FLOAT approximations now fail explicitly; decoder recognition remains available. |
| VMRUN | Complete guest/host transition, including guest-modified unsaved GPRs and floating/vector state, plus the VM-exit continuation. |
| SKINIT | Machine reinitialization and nonlocal control transfer. |
| GETSEC transferring or unproved leaves | Measured-environment entry/exit and a complete-machine-state continuation. Leaves 0 and 6..8 now use the bounded contract below when natural-width AX is proven constant. |
| ENCLU entry/exit/resume or unproved leaves | Enclave entry/exit/resume and asynchronous exit state. Leaves 0, 1 and 5..11 now use the bounded contract below when natural-width AX is proven constant. |
| ERETS, ERETU, UIRET | Return-frame and nonlocal control-transfer ownership. FRED returns explicitly fail decoding instead of aliasing CLAC; UIRET is not decoded. |
| RETF/RETFQ, IRET/IRETD/IRETQ | Complete frame, privilege, segment and flag restoration. The old ordinary ABI-return approximation has been removed; strict lifting now refuses these forms. |
| SYSENTER, SYSEXIT/SYSEXITQ, SYSRET/SYSRETQ, RSM | Complete register, privilege, segment and SMM continuation state. The integrated nonlocal-control boundary rejects these forms before an ordinary call/return or bare assembly can lose that state. |
| BNDMK, BNDMOV, BNDCL, BNDCU, BNDCN, BNDLDX, BNDSTX | MPX bounds-register bank, bounds-table translation, enable state and #BR/partial-fault behavior. The old COPY/NOP approximations are removed. |
| XACQUIRE/XRELEASE | HLE prefix ownership belongs to the associated memory operation. Prefixed LOCK operations, implicit-lock XCHG and XRELEASE MOV stores are explicitly refused before ordinary memory lowering; native transactional completion remains missing. |
| XBEGIN and full RTM regions | Original abort target, register/memory checkpoint, nesting and rollback continuation. A C `_xbegin()` status result cannot substitute for the decoded instruction. Strict/permissive lifting and legacy IR admission explicitly refuse that incomplete representation. |
| Remaining compact-memory address forms | Native LLVM and both C routes now support DS/FS/GS compact memory. A 64-bit RSP/RBP-based address without FS/GS still lacks its #SS fault provenance. In i386, SS-default stack bases and explicit CS/ES/SS segments remain refused; an explicit DS override is supported. Physical AVX-512 fault execution remains unqualified. |
| Remaining four-source address forms and hardware qualification | Native lowering now uses explicit SSA sources. The same stack/segment fault-provenance boundary as compact memory remains; physical AVX512_4FMAPS/AVX512_4VNNIW execution and exception behavior require separate qualification. Legacy implicit-bank IDs remain guarded at native output. |
| Remaining RAO-INT/CMPccXADD fault provenance | Legacy and EVEX AADD/AAND/AOR/AXOR, and VEX/EVEX CMPccXADD, now have distinct native encoding contracts. Legacy RAO includes i386. Default-stack memory and i386 non-DS segments still require preserved segment-fault provenance; see the native atomic sections below. Physical atomicity and CPU faults remain unqualified. |
| VMCALL/VMMCALL | Existing narrow argument/result spellings do not provide a complete hypercall register/state ABI. They must not be treated as full machine-state support. |

This list includes backend guards as well as strict-lifter refusals. A decoded
instruction and passing LowIR/concrete tests do not establish native LLVM or C
support. The additional vector/atomic rows were found by inspecting explicit
refusals in `lib/backend/llvm/emit/MedLLVMIntrinsic.cpp`; they were absent from
the earlier strict-lifter census.

The direct-store execution checks cover ordinary memory. Native instructions
retain WC protocol, concurrent write completion and device transactions, but
these tests do not independently measure those properties. The concrete
emulator models only the single-threaded ordinary-memory projection.

VMRUN and SKINIT still fail strict lifting explicitly. ENCLU and GETSEC decode
to pending state, which cannot enter MedIR or either emitter until the CFG
proves a supported leaf. Dynamic, transferring and unknown leaves remain
explicitly unsupported. Legacy
AMX value-form intrinsics retain their LLVM guard: an arbitrary 64-byte config
and 1024-byte tile SSA value cannot be treated as the ambient CPU bank. Decoded
AMX instructions now use the separate architectural-bank contract below. An
opaque helper declaration, assembly that loses state, or a NOP does not close
a missing semantic contract.

The HLE admission check reads raw prefix bytes: Capstone can report LOCK in
its normalized prefix slot without retaining F2/F3 there. An earlier lift of
`XACQUIRE LOCK XADD` silently emitted a plain LLVM `atomicrmw`. Both strict
and permissive lifting now reject the affected memory operations without
appending effects. The regression covers both prefix orders, all eighteen
LOCK instruction families, implicit-lock byte/dword XCHG and four XRELEASE
MOV store encodings on x86/x64 through all three decode routes. Unrelated
mandatory/repeat prefixes retain their existing behavior. This is explicit
unsupported-state admission, not completed HLE execution support. The native
contract must retain transactional checkpoint/abort/restart state and ordinary
memory ordering across the critical section, as specified by the
[Intel XACQUIRE/XRELEASE reference](https://cdrdv2-public.intel.com/782156/325383-sdm-vol-2abcd.pdf).
Whole-module lift/patch reports the rejected entry and instruction address when
no attempted body survives. An empty LLVM module is no longer reported as a
successful lift of an unsupported HLE-only input; read-only analysis retains
the rejection audit.

XTEST keeps its native transaction-state query and defines all six arithmetic
flags: ZF reflects the query and CF/PF/AF/SF/OF are cleared. The concrete suite
checks both completions against all 64 incoming arithmetic-flag states on
x86/x64, without fabricating an unknown transaction state. Native LLVM, HighC
and LLVM-to-C compile across ELF/COFF/Mach-O at O0/O2; the x64 C routes also
compile with NeverC's standard transaction headers. LLVM IR carries `+rtm`
and both C routes use `_xtest`. This qualification does not execute physical
RTM regions. XBEGIN remains refused because its original abort target and
complete checkpoint are absent; the previous status-only lowering could
lose both the abort branch and the successful path's EAX value. These
instruction contracts follow the
[Intel XBEGIN/XTEST reference](https://cdrdv2-public.intel.com/874247/334569-090-sdm-vol-2d.pdf).

XABORT now retains its exact constant byte through the shared system-state
contract, using native `llvm.x86.xabort` on both the pinned SDK and current
fork. Missing, variable, mistyped or contradictory operands fail before
effects. LLVM-to-C also rejects narrowed memory effects and speculative or
nonreturning annotations; its legacy assembly input retains the required
`rtm` function attribute. Store/abort/reload fixtures preserve ordinary memory
order. The decoder qualification covers all 256 bytes in 14,592 combinations;
48 source fixtures cover x86/x64, ELF/COFF/Mach-O and both pipeline settings,
including 24 x64 fixtures compiled with NeverC. Native and C outputs are
compiled at O0/O2. NeverC's bare Microsoft `_xabort` also now rejects a
nonconstant argument before publishing an object. The independent compiler
oracle checks all 256 codes over 40 profiles (10,240 functions), including
NeverC, the full LLVM backend and the NeverC-to-LLVM bridge. This is byte,
operand and ordering qualification, not physical transactional rollback.

An additional audit reproduced two previously hidden false positives:
`48 0f b4 07` (LFS) became an ordinary eight-byte load, and `0f 0f c1 94`
(PFMIN) became a COPY of MM1 to MM0. The former loses the segment selector and
descriptor transition; the latter loses both minimum comparisons. The
related far-pointer loads and all 24 affected 3DNow! operations now refuse
before appending LowIR effects. `NeverDX86LegacyAdmissionTests` covers 76
far-pointer forms and 384 3DNow! forms, each through three decoder routes in
strict and permissive mode (2,760 admission checks), plus ordinary-load/MMX
positive controls. These are explicit remaining implementation gaps. 3DNow!
completion must follow the packed-operation and state rules in
[AMD APM volume 5](https://www.amd.com/content/dam/amd/en/documents/processor-tech-docs/programmer-references/26569.pdf),
including its defined and undefined input domains.

The same audit found a TBM counterexample:
`mov rdi, -1; clc; blcfill rax, rdi; setc al; movzx eax, al; ret` previously
exported a constant zero. BLCFILL's carry comes from incrementing its source
and must be one for that input, as specified in
[AMD APM volume 3](https://docs.amd.com/api/khub/documents/j44LvPXzuuXgM0WyHKQfeQ/content).
`X86LiftTBM` now owns the nine operations' byte/detail admission, values and
flags. It computes CF before an aliased destination write, derives ZF/SF from
the result, clears OF and preserves DF. AF/PF remain explicitly undefined;
the concrete representative does not establish architectural zero. Memory
loads precede all architectural writes. Malformed forms fail before effects,
including permissive lifting. The shared XOP prefix parser retains ignored
32-bit W/vvvv/B fields without selecting long-mode registers.

`NeverDX86TBMTests` covers 25,920 value/flag cases, 432 ignored-field cases,
1,296 memory-encoding cases and 1,782 malformed-instruction refusals, plus
faulting-read checks. Its reference scans for the first set/clear bit rather
than repeating the lifter's adjacent-value formulas. The prefix, APX BMI and
undefined-effect suites cover the shared boundary.
`NeverDX86TBMPipeline` exercises both pipeline optimization settings, O0/O2
compilation and LLVM/HighC/LLVM-to-C for 32/64-bit operands: 216 profiles and
31,104 executed value/flag cases. It disables TBM and inspects the assembly
before linking, so it never executes the original TBM instruction on the host.
The old CLI fails this regression at BLCFILL(0), where ZF was lost.

NeverC now installs the native `tbmintrin.h` interfaces through `x86intrin.h`:
20 value interfaces across ten operations and two widths, including BEXTR's
constant control. Function-level `target("tbm")` works without a translation-
unit feature flag. The LLVM fork already selects all these instructions from
its standard intrinsics/arithmetic patterns; no new LLVM intrinsic ID or
inline assembly is needed. ELF/COFF/Mach-O O0/O2 compilation, native O2
selection, the NeverC-to-LLVM bridge and nonconstant BEXTR refusals are covered.
These C interfaces return values; they do not expose the architectural flags.
Physical TBM hardware execution and CPU exception delivery remain unqualified.

The broader integration run retains a separate source-frame proof gap:
`NativePointerRelocationBoundary.MinGWProgramWholeModuleLLVMCCompiles` rejects
`_pei386_runtime_relocator` because a dynamic-stack CALL may overwrite an
observed physical return-address slot. The safe-output guard remains enabled;
whole-program source qualification for this fixture is still incomplete.

MPX memory forms retain their decoded identity in both full and lightweight
decoding. The decoder no longer assumes MPX is disabled for BNDLDX/BNDSTX.
Only the unprefixed register forms of `0F 1A/1B` remain architectural NOPs, as
specified by the SDM's BNDLDX/BNDSTX descriptions. Strict lifting rejects the
seven unmodeled MPX operations without appending partial effects. Existing
serialized MPX, standalone HLE and generic SHA placeholder IDs remain readable,
but both LLVM and HighC output fail explicitly instead of silently dropping
them. Specific SHA and bounded RTM instruction contracts are separate.
Qualification covers 192 strict MPX form/register/mode/decode-route cases,
60 legacy emitter refusals, the pinned decoder corpus, and all 86 instruction
boundary tests. The related source and system-sideeffect suites pass too.

The LLVM fork now provides 26 native MPX APIs, and NeverC exposes 14 portable
builtins for the same architectural bounds bank. `llvm.x86.bnd.branch` retains
an original near transfer's conditional BNDINIT effect independently of CFG
folding; compiler-created transfers preserve the bank. Its initializing form
uses unprefixed E9 with forced disp32, including assembly roundtrips. These
compiler surfaces do not yet supply NeverD's shared MPX state and original
branch/fault-order contract, so the strict lifting boundary above remains.
The compiler qualification is recorded in LLVM's `X86MPXIntrinsics.rst` and
NeverC's `development.md`. QEMU 10.2.2's explicit limitation mode skips 180/520
instruction cases and one of six branch-state cases; skipped behavior and
physical MPX hardware execution are not qualified as passing.

Completion therefore still requires extending the shared machine-state/runtime
contract for transitions, completing the ENCLU leaf/state contracts, and
testing the remaining instruction forms. The bounded system contract added
here is deliberately not a replacement for a complete machine-state boundary.
This audit does **not** certify every encoding of the other decoder IDs.
The newer MSRLIST extension is enumerated in Intel's
[June 2026 ISA reference](https://cdrdv2.intel.com/v1/dl/getContent/671368);
[SDM 093 Volume 2B](https://cdrdv2.intel.com/v1/dl/getContent/671241)
defines RDMSRLIST's memory tables, RCX mask and partial-completion behavior.
Both list instructions now have public IDs and a bounded native contract
described below. Extending this census still does not establish complete
architectural coverage.

## Work needed for complete coverage

The requested completion also includes native LLVM intrinsic support and
NeverC's builtin frontend. Architectural native assembly is a validated
intermediate implementation, not completion of that requirement. Audit
`NeverSight/llvm-project` and NeverC's embedded LLVM separately: reusable
intrinsics must preserve every result, memory effect, encoding requirement and
control continuation. Add missing IR definitions and instruction selection to
the LLVM fork, synchronize NeverC's definitions/generated tables and builtins,
and replace NeverD's assembly paths where the equivalent intrinsic is ready.
After the complete instruction work is validated, publish a new immutable LLVM
release, pin the exact commit plus every platform artifact digest, and update
NeverD's LLVM submodule and consumers together. Do not publish a release for an
incomplete intermediate batch.

1. Extend the shared instruction encoding audit beyond the current MC corpus,
   with separate expectations for decoding, strict lifting and each emitter.
   Include positive and negative forms for widths, register banks, masks,
   address sizes, segments and privilege-sensitive operations.
2. Extend instruction coverage without weakening the bounded ENCLU/GETSEC
   proof or inventing successful hardware execution. The native state
   integration below is implemented; selectors with unknown natural-register
   high bits and transferring leaves still require additional contracts.
3. Introduce a versioned complete-machine-state boundary and explicit
   continuations for VMRUN, SKINIT and the transferring GETSEC/ENCLU leaves.
   It must carry the affected integer, flag, segment, x87/SIMD and control
   state, distinguish native return, VM exit and nonlocal transfer, and reject
   states the selected runtime cannot transport. A compiler calling convention
   alone does not preserve the unsaved guest registers exposed by VMRUN.
4. Qualify native AMX successful execution and fault restart on suitable
   hardware using the checked-in signal-context oracle. The shared bank
   contract and concrete partial-progress tests are implemented. A concrete
   i386 segmented executor still requires a supplied descriptor environment;
   native block transactions now retain that state.
5. Validate transition and privilege behavior in an authenticated execution
   environment. Compile-only checks establish operand transport and generated
   code validity; they do not establish VM-exit, enclave or fault semantics.

## Bounded user interrupts, descriptor loading and TLB control

## SGX supervisor and VMM completion

The qualified fork now lowers this shared contract through native
`llvm.x86.encls{,32}` and `llvm.x86.enclv{,32}`. The full-register intrinsic
status byte is projected into NeverD's CF/ZF transport without changing the
lifter's leaf-specific preservation rules. HighC and LLVM-to-C use NeverC's
matching builtins on x64; old SDKs and other C compilers retain the validated
assembly path. Native declarations with altered types, code mode, memory
effects or completion behavior are rejected. Function feature requirements
are merged with AMX so mixed functions retain both sets of instructions.

Both SDK profiles pass 192 generated-C native IR compilations and 192 object
compilations for this integration, including mixed SGX/AMX functions, both C
routes, dead results, three object formats and O0/O2. Controlled sigreturn
completions compare generated NeverC code against original bytes for full-width
registers, native CF/ZF and leaf-preserved flags; separate runs retain the
Clang assembly fallback and linked LLVM object checks. These are compiler
transport and CPL3-fault checks, not successful privileged enclave execution.

`X86Sgx.h` owns ENCLS/ENCLV's four natural-width GPR inputs, primary rAX
result and two auxiliary outputs (rBX and a two-byte CF/ZF snapshot).
`X86SgxLeaves.h` defines which implicit registers each leaf consumes. Unused
inputs are conditionally zeroed before the native boundary, and only EDBGRD
publishes rBX completion. EUPDATESVN therefore remains a zero-argument
operation without invented register reads or traps. Call-graph summaries and
MedIR both prune constant selections, retaining the selected value's address
provenance. All
three emitters share `X86SgxAsm.h`. The instruction keeps implicit DS accesses,
privilege checks, enclave state and memory fault ordering; no compiler preload
or ordinary memory store substitutes for an SGX access. Segment, address-size
and long-mode REX overrides are ignored. LOCK, 66H and REP forms fail strict
lifting. Runtime rAX retains its full input, while leaf selection uses EAX.

ENCLS leaves ECREATE, EADD, EEXTEND, EPA and EAUG preserve the incoming
arithmetic flags. Other documented supervisor/VMM leaves return native CF/ZF
and clear PF/AF/SF/OF; DF remains unchanged. This includes current EUPDATESVN
and the historical conflict/virtualization leaves. Native rBX completion
retains EDBGRD's data, without fabricating outputs for rCX or rDX. The assembly
saves rAX before SETC/SETZ write AL/AH, using neither stack scratch nor LAHF.
The primary result participates in the shared return contract, and unused
results cannot remove the ordered instruction. The scalar emulator refuses
SGX without an architectural environment.

The references are Intel's [SDM 093 Volume 3D](https://cdrdv2.intel.com/v1/dl/getContent/671269)
and the [earlier Volume 3D containing ENCLV](https://cdrdv2-public.intel.com/774498/332831-sdm-vol-3d.pdf).
These normal-completion contracts do not implement ENCLU transitions or an
AEX/VM-exit handler. Native execution still needs the CPU and OS SGX state.

LLVM at O0/O2 and generate native objects for x86/x64 ELF, COFF and Mach-O.
Linux x64 tests compare the real fault signal/code with original bytes, then
use controlled sigreturn to validate register/flag transport across the three
routes and native objects. That second oracle does not certify successful

## i386 segmented block transactions

`ENQCMD`, `ENQCMDS` and `MOVDIR64B` now retain protected/compatibility-mode
segment semantics through `X86SegmentedBlockMemory`. Its constant selector
identifies the instruction, source segment and 16/32-bit address size; the two
32-bit values are segment offsets, never linear image pointers. Source
DS/ES/SS/CS/FS/GS selection is explicit, including default SS for BP/EBP/ESP
addressing. Destination ES cannot be overridden. The native instruction owns
segment descriptors, limits, access rights, source reads, alignment, feature
and privilege checks and the ordered transaction. No compiler preload or
ordinary store substitutes for it. Enqueue returns native ZF and clears the
other arithmetic flags; MOVDIR64B preserves flags.

The shared system shape and assembly plan drive LowIR validation, MedIR,
LLVM, HighC and LLVMC. Native assembly uses the original address width and
fixed SI/DI operands; source segment prefixes are independent of register
allocation. Both native arguments remain integers, so an offset matching an
image VA cannot acquire an unrelated symbol identity. The scalar emulator
refuses these operations before effects because it has no descriptor context.
This is native CPU execution support, not a new software segmentation model.

`X86SegmentedBlock.*` tests decode/detail agreement, segment selection, address
wrapping, output shapes and missing-environment refusal.
`X86SegmentedBlockSource.*` compiles all six source segments and both address
sizes for i386 ELF, COFF and Mach-O through both C routes and LLVM at O0/O2.
Linux i386 executables compare the original bytes and generated objects with
nonflat ES/FS descriptors, ES source/destination overlap, read-only ES, segment
limits and unaligned destinations. MOVDIR64B success has a separate byte and
flag oracle. Enqueue checks cover native faults, not successful CPL0 execution
or device acceptance. Windows C compilation uses Clang GNU inline assembly.
The references are Intel's [SDM Volume 2A](https://cdrdv2.intel.com/v1/dl/getContent/671199)
and [SDM Volume 2B](https://cdrdv2.intel.com/v1/dl/getContent/671241).

## Architectural AMX bank and native output

`X86AmxState.h` owns the version-1 descriptor for 28 operation kinds. The new
append-only `X86AMXState` intrinsic carries a base address, a constant descriptor,
and a stride or row selector where required. The descriptor distinguishes tile
register indices, four load hints, address-size wrapping, APX-promoted memory,
register/immediate row selection, extended row GPRs and the default SS segment.
FS/GS use the existing address-space authority. All validation layers consume
this shape; malformed versions, modes, widths and effects fail explicitly.

The operation owns the complete architectural TILECFG/TILEDATA bank. Native
LLVM and both C routes emit the real instruction with volatile ordering,
compiler memory effects and all eight TMM clobbers. Hardware retains the bank,
including partial completion and `start_row` when a tile transfer faults. There
is no tile-valued function ABI, synthetic configuration load, speculative row
preload, or implicit software runtime helper. Only the 64-byte result of a row
instruction enters ordinary SSA; an explicit ZMM result and private row storage
transport those bytes. LLVM allocates this storage once in the entry block.

`TILERELEASE` is now a native side effect instead of a series of zero copies.
`TILELOADD`, `TILELOADDT1`, `TILELOADDRS` and `TILELOADDRST1` retain their separate
instructions. APX memory uses EVEX even for low GPRs; extended row selectors
retain an extended GPR. Native memory retains the source segment, address width,
byte stride and instruction-owned feature, permission and fault checks.
Successful execution still requires the relevant CPU features and OS state
permission. Generated source selects NeverC's native builtins where available;
other compilers use GNU-compatible assembly, including Clang for Windows.
This does not add an MSVC C spelling for AMX.

The concrete evaluator owns the same physical bank in its register state and
reuses the existing tile/configuration arithmetic and memory evaluators. It
preserves partial tile data and `start_row` on failed memory accesses, clears
progress only on completion, and refuses missing configuration/tile state.
This is the ordinary-memory projection, not emulation of CPU enablement, XFD,
TSX or hardware cache protocols. Legacy value-form AMX intrinsics remain valid
for their existing concrete use but cannot bypass their LLVM transport guard.

The historical `TMMULTF32PS` opcode remains supported for decoded older input.
Intel withdrew AMX-TF32 in ISE revision 062, and
[LLVM removed its mnemonic in July 2026](https://lists.llvm.org/pipermail/llvm-commits/Week-of-Mon-20260706/1969009.html).
Native output therefore preserves the exact five opcode bytes and tile indices,
including the processor's actual unsupported-feature fault, rather than using
another matrix instruction. Its concrete arithmetic follows the historical
[ISE revision 059](https://cdrdv2-public.intel.com/865891/319433-059-architecture-instruction-set-extensions-programming-reference_2025-0930.pdf).
It is not counted as a currently advertised CPU extension.

The six row operations follow
[ISE revision 062](https://cdrdv2.intel.com/v1/dl/getContent/671368): both immediate
and register selectors use only bits 3:0. A row beyond the configured extent
produces 64 zero bytes and clears `start_row`; ignored selector high bits do not
raise a synthetic fault. The earlier row-chunk interpretation is removed from
the shared concrete evaluator. Out-of-range rows do not require known tile
contents, while rows that are actually read still do. Invalid configuration
and column shapes continue to fail before output publication.

Qualification uses 63 independently assembled/reference encodings, all three
native object formats and both pipeline optimization settings. HighC,
LLVM-to-C and LLVM IR compile at O0/O2, and the repository backend emits native
objects. Fixed-bank operations are checked against exact object bytes. Isolated
Linux subprocesses compare native completion or signal/code with original bytes
for every fixture. The complete configuration/load/store/release sequence and
its signal-context restart oracle compile and link on the baseline host.
The AMX hardware test checks normal row data, saved first-row bytes and
`start_row=1` at a second-row protection fault, then resumes the same instruction.
It is explicitly skipped when AMX-TILE is unavailable; this host cannot qualify
native successful tile computation or fault restart. Concrete tests cover
integer/floating arithmetic, row conversion, shape checks and partial progress.

`__NEVERC_X86_REP_STATE__=1` capability macro. The macro selects an API; it does

The new interfaces take the complete natural-width registers, explicit DF,
comparison input flags where applicable, and constant element/address/segment
controls. MOVS returns SI/DI/CX, STOS returns DI/CX, LODS returns SI/CX/AX,

Qualified fork interfaces replace owned assembly automatically. Older SDKs use

controls and exact owned assembly before admitting either form. REP feature

## LLVM assembly arithmetic-flag effects

A native VERR counterexample exposed an independent lowering gap: LLVM's x86
assembly constraint parser ignores `~{cc}`, so a comparison used before and
after VERR could reuse VERR's ZF. Four equal-input cases returned -1 instead

## NeverD bounded SGX/SMX state integration

NeverD now admits ENCLU leaves 0, 1 and 5..11, and GETSEC leaves 0 and 6..8,
when the final CFG proves the complete natural-width AX value. The shared
contract owns input dependencies, register writes, arithmetic flags and
mode/shape validation. ENCLU's preserved registers and flags keep their
original SSA values. GETSEC PARAMETERS retains the old BX/CX values needed
by its conditional writes. EVERIFYREPORT2 captures actual native flags with
the previous flags as input because SDM 093's pseudocode and Flags Affected
paragraph disagree. A dead flag result does not create an otherwise unused
entry flag dependency; this rule belongs to MedIR liveness.

The decoder retains explicit pending state, including all potentially changed
registers. A bounded byte-fact analysis meets every predecessor, resets
instruction-local temporaries and refuses address-derived selectors. Calls,
independent entries and exception entries supply unknown incoming state.
Partial register writes retain their unaffected bytes. Rebuilding the CFG
starts from the pending decoder records, so another discovered edge can revoke
a proof. Only the final graph publishes unresolved leaves as unsupported;
no-return screening also refuses to guess their control effects. Budget
exhaustion leaves the operation pending. Knowing EAX alone is insufficient in
x64 when the upper AX bytes remain unknown: the published native API requires
the whole AX operand to be constant.

LLVM output selects the real `llvm.x86.{enclu,getsec}.bounded.state{,32}`
interface when available. An older SDK uses a strictly identified, indivisible
assembly window with explicit EFLAGS and memory effects. HighC and LLVM-to-C
share one renderer and validate complete types, selectors, effects and
auxiliary results. NeverC's capability macro selects its native builtin;
other C compilers use the owned assembly. SGX and SAHF requirements compose
with the existing AMX/SGX/REP function attributes.

per configuration, plus 182 exported IR modules per configuration including

## Unsigned immediate port transport

The LLVM-to-C scalar-system recognizer now renders a validated 8-bit port
immediate from its unsigned LLVM constant. Previously, the signed spelling
of byte 0x80 could widen directly to the 16-bit value 0xff80. DX operands
retain all 16 bits. The correction applies to both native-builtin and MSVC
selection and the shared assembly fallback expression.

`NeverDX86PortSourceTests` covers all 256 immediate ports and eight DX boundary
values across the six byte/word/dword IN/OUT forms. Two SDK configurations
each pass 20 compiled observer programs at O0/O2 with Clang, GCC and NeverC,
for 63,360 controlled operand comparisons. The four exported observer sources
are identical between SDKs. Restoring the signed-widening expression makes
all four observers fail. These are C operand-transport checks; they do not
execute privileged port I/O.

## Native APX atomic output

EVEX AADD/AAND/AOR/AXOR and all sixteen CMPccXADD conditions now retain their
native 32/64-bit transactions through MedIR, LLVM, HighC and LLVM-to-C.
The fork adds ten `llvm.x86.<operation><width>.address` interfaces; NeverC
provides matching `__builtin_ia32_<operation><width>_address` builtins and
`__NEVERC_X86_APX_ATOMIC__=1`. These are native IR operations. The existing
SDK uses validated owned assembly, and ordinary Clang/GCC C output uses the
same native instructions through the compiler fallback.

The interfaces preserve explicit address width, all seven segment-prefix
choices, EVEX encoding, unknown memory/synchronization effects, dead results
and repeated transactions. CMPccXADD retains false-condition write-back and
EFLAGS definitions; RAO-INT preserves flags. Normalized NeverD addresses have
already wrapped before native FS/GS base addition. The C renderer therefore
does not require Clang address-space pointers for these instruction-owned
accesses. LLVM fixed-register constraints use `{bx}`; GNU C uses `b`, and
RAO mnemonics infer width from their register for GNU assembler compatibility.

LLVM, NeverC and NeverC-IR-to-full-LLVM each pass 120,960 controlled completions
across 10,080 compiled functions, O0/O2 and ELF/COFF/Mach-O. Each profile also
passes twelve ATT/Intel assembly round trips. Function identities, instruction
bytes and offsets within each function are compared; alignment padding and
independent function order do not define instruction semantics. The LLVM
neighbor matrix passes 22 tests, and NeverC's 76 focused frontend tests pass.

The initial pinned and native SDK matrices register 740 tests: 734 pass and six
skip unavailable SDK/platform interfaces. Each SDK passes 159,840 controlled
wrapper completions across 37 programs. Both additionally qualify 504
production pipeline objects, checking offsets, operands, return flags and
nonvolatile registers against the original CMP/atomic/LAHF/SETO sequence.
The 1,008 recovered pipeline C files are identical between SDKs; their 4,032
Clang/NeverC compilations at O0/O2 supply 28,224 controlled completions, reused
only after byte-for-byte source comparison. Production pipeline objects add
3,528 completions per SDK. A separate Codegen regression prevents recoverable
LLVM errors from publishing parseable but incomplete objects.

The subsequent `dev` integration at `101544392` registers 752 tests across
the two SDKs: 746 pass and six skip unavailable SDK/platform interfaces. The
feature-composition regression now covers all sixteen combinations of SGX,
AMX, REP and APX atomics with SHA present, using native interfaces or the shared
owned-assembly templates according to SDK availability. Both SDKs again pass
37 wrapper programs and 504 production pipeline objects. All 1,008 pipeline
C sources match between SDKs; 396 changed since the initial qualification
and were recompiled 1,584 times, while the other 612 reuse the prior evidence

The following system-contract integration exposes an older-SDK XEND source

O0/O2 and with APX register allocation enabled; NeverC's x86 backend test
checks the same 48 signatures, alongside 76 passing frontend tests. This
does not change the production SDK pin or qualify physical atomicity.

The remaining row above is deliberately narrower than full RAO/CMPccXADD
support. Legacy RAO and VEX CMPccXADD are covered below. Unoverridden
RSP/RBP bases with 64-bit addressing need explicit stack-fault provenance;
ignored CS/DS/ES/SS prefixes cannot restore it after normalization. See
[Intel's canonical-address rule, section 3.3.7.1](https://www.intel.com/content/dam/support/us/en/documents/processors/pentium4/sb/25366521.pdf)
and [APX revision 9 exception tables](https://kib.kiev.ua/x86docs/Intel/APX/355828-009.pdf).
The concrete executor still restricts atomic accesses to aligned ordinary
memory. Controlled completions do not prove physical atomicity, coherence or
hardware fault behavior. LLVM release and production pinning remain deferred
while the remaining instruction contracts are unfinished.

## Legacy RAO and VEX CMPccXADD

Legacy AADD/AAND/AOR/AXOR and all sixteen VEX CMPccXADD conditions retain
separate LowIR identities from their APX forms. Capstone validates raw
prefixes, code mode, addressing, operand widths/access and implicit flags.
The lifter independently checks those details against the instruction bytes
before admitting a transaction. Both encoding families share the operand
shape and arithmetic contract; decoding, LLVM and the C renderers preserve
which encoding was requested.

The LLVM fork adds ten `llvm.x86.<operation><width>.legacy.address` interfaces
for x86-64 and four `llvm.x86.<rao-operation>32.legacy.address32` interfaces
for i386. The former support 32/64-bit operands and addresses; the latter
support 32-bit operands with 16/32-bit effective addressing. Address controls
wrap offsets before native segment-base addition. Native data operands use
register classes excluding APX-only registers. NeverC exposes the ten x86-64
`__builtin_ia32_<operation><width>_legacy_address` builtins and
`__NEVERC_X86_LEGACY_ATOMIC__=1`; its C frontend remains x86-64-only.

The pinned SDK uses validated owned assembly with encoding controls and
legacy register constraints. The native SDK calls the new LLVM intrinsics.
The C renderer shares these controls across HighC and LLVM-to-C. i386 C
output uses Clang's assembly fallback. The concrete executor now also
rejects unknown address, source or comparator bytes before an atomic access;
an uninitialized input cannot become an accidental transaction with zero.

Direct native APIs expose all segment controls. Normalized lifter addresses
currently admit DS-default/DS override and FS/GS forms on i386; implicit
SS stack bases and explicit CS/ES/SS forms are refused. x86-64 default-stack
RSP/RBP accesses with 64-bit addressing remain refused without FS/GS.
These guards preserve the outstanding segment-fault distinction rather than
emitting an instruction with a different fault class. Hardware atomicity,
write-back memory-type behavior and fault ordering remain unqualified.

The standalone LLVM, NeverC and NeverC-IR-to-LLVM matrices each pass 10,080
functions, 120,960 controlled completions and twelve ATT/Intel assembly round
trips. Capstone's 80 focused x86 tests, NeverC's 85 x86 tests and six atomic
generator tests pass. LLVM's four new legacy tests and nineteen neighboring
codegen/assembler tests pass, including APX-only inputs copied into encodable
registers and invalid i386 mode/address controls.

For each pinned/native SDK, NeverD exports 360 x86-64 wrappers and 504 decoded
pipeline cases, including original flags, addressing and returned values.
The wrapper qualification passes 37 compiled programs and 159,840 controlled
completions per SDK. The pipeline matrix covers 504 production objects and
4,032 HighC/LLVMC compilations with Clang and NeverC at O0/O2. Native pipeline
C and case metadata match the qualified pinned exports byte-for-byte; only
that exact source work is reused, with all native production objects checked.

i386 adds 112 wrappers per format, 21 compiled programs and 35,280 controlled
completions per SDK. Its 144 decoded pipeline cases pass all 720 production/C
objects, including 576 Clang compilations per SDK. The test loader validates
ELF/COFF code relocations and Mach-O local section-difference pairs rather
than executing unresolved object bytes. These results qualify operand
transport, effects, flags and ABI preservation, not physical atomicity.

## Native compact-memory qualification

The twelve compress-store/expand-load families retain their original opcode
kind and 128/256/512-bit width. `X86CompressExpand.h` owns the stable LowIR
control: element bytes, the floating-point kind bit and load zeroing. LowIR
and MedIR adapters live in their own `X86/` directories; native LLVM transport
and C projection likewise stay in the owning component's `X86/` directory.
Both decoders, Low-to-Med conversion, verification, execution and emitters
consume that contract. Invalid controls, insufficient mask widths, mismatched
results and non-x86 inputs fail explicitly.

The LLVM fork supplies six fixed-signature native interfaces with raw i32
vector carriers. NeverC exposes 36 corresponding builtins and the
`__NEVERC_X86_COMPRESS_EXPAND__` capability. Expand-load pointers are const;
stores take writable pointers. Native calls retain conservative memory effects
and lower to volatile, byte-aligned machine memory operands of unknown size.
Zero masks and dead load results retain the instruction. The pinned older SDK
uses a checked owned-assembly interface; C output selects NeverC's native
builtins when available and supports Clang's ATT/Intel assembly alternatives
otherwise. C target attributes use the frontend spelling `avx512f`, without
passing LLVM's backend-only `evex512` spelling to ordinary Clang.

FS/GS arguments carry segment-relative offsets, not pre-added linear
addresses. LLVM's address-space pointer is converted through its integer
offset before entering the native interface; the instruction owns segment
base addition. An RBX/EBX carrier retains default DS addressing. The remaining
stack/segment provenance limitations are listed above. The full LLVM and
NeverD matrices include i386; NeverC's builtin frontend remains x86-64 only.

Concrete execution refuses unknown active masks, addresses and source/prior
values. A zero mask suppresses address and segment-base resolution; all-active
or zeroing loads need no old destination. Native reconstruction of functions
containing these operations preserves entry-value evidence through emission
and rejects remaining unknown values instead of inventing a zero mask.
Analysis output retains the existing unknown-value markers. This does not
introduce an implicit entry-register ABI or a runtime unknown-value helper.

`NeverDX86EVEXCompressExpandMemoryTests` covers masked contiguous access,
zero suppression, merge/zero lanes, upper-lane clearing, malformed controls,
unknown inputs, both decoder routes and both x86 modes. Its existing
partial-store fault model is a software projection; hardware partial-fault
completion has not been independently qualified.
`NeverDX86CompressExpandSourceTests` checks shared contracts, altered native
and assembly effects, unknown-entry rejection, 162 wrapper variants and 162
pipeline variants with explicit address/mask/vector input setup and observable
load results. Their `KMOVW` setup also checks that a narrowing machine `COPY`
survives Med-to-High expression substitution. The shared conversion retains
that byte slice; an executable regression covers i386, x86-64 and AArch64.
A naked instruction with unrecovered entry RAX/K2 is not an executable C fixture.

Run the source test with `NEVERD_COMPACT_EXPORT_DIR` set, then use
`scripts/verify_x86_compact_memory.py --exports DIR --keep AUDIT_DIR
--llc LLVM/bin/llc --neverc NEVERC/bin/neverc --pipeline`. The script audits
EVEX bytes independently of the lifter and checks width, kind, masks,
zeroing, prefixes, DS-default addressing and instruction counts. It covers
ELF/COFF/Mach-O at O0/O2, both C routes and both assembly dialects. Its C
recorders execute the emitted operand/return transport and compare compacted
bytes, inactive lanes, high ignored mask bits and repeated zero-mask effects
without requiring AVX-512 hardware. Additional full-pipeline recorders run both
C routes through Clang and NeverC at O0/O2, including dirty mask bits above
`KMOVW`'s 16-bit input and each expand result's final memory store.
Those recorders do not certify physical
AVX-512 execution, exception ordering, concurrency or device memory.
The architectural reference is Intel's
[December 2024 instruction-set manual, Volume 2](https://cdrdv2-public.intel.com/843829/325383-sdm-vol-2abcd-dec-24.pdf).

## Native four-source qualification

`X86FourSourceMemory` appends one stable intrinsic identity without renumbering
older IDs. Its operands are a segment-relative address, accumulator, packed
four-source value, lane mask and constant kind/zeroing control. SS forms pack
only the low dword of each XMM source; packed forms retain all four ZMM values.
The lifter snapshots those reads before any aliasing destination write.
LowIR, MedIR, concrete execution and both source routes share shape and operand
observation rules in `ir/intrinsics/X86/X86FourSource.h`. Unknown active operands
remain unsupported; a zero mask does not observe the address or source group.
Scalar upper 96 bits always come from the old destination.

LLVM `588b19e45293` introduces six native interfaces. Every source is an LLVM
operand, with XMM4..7 or ZMM4..7 materialized as a complete aligned physical
group. The three unencoded members remain explicit machine-register uses.
Native instructions own the four sequential rounding/saturation steps, MXCSR,
full m128 access and hardware faults. The older SDK uses an exact checked
assembly contract with the same complete register group. NeverC exposes six
corresponding builtins in `336a54b88` and `__NEVERC_X86_FOUR_SOURCE__`; C output selects them
when available and otherwise uses the owned ATT/Intel assembly form.

The native pointer carrier is RBX/EBX, so the remaining default-stack and i386
segment limitations match compact memory. LLVM and NeverD cover i386 and x64;
NeverC's frontend remains x64-only. Compiler `avx512f` enables the carriers,
but execution additionally requires AVX512_4FMAPS or AVX512_4VNNIW and the
appropriate enabled extended state. Ordinary AVX512F hardware is insufficient.

The numerical executors retain independent four-iteration FP and integer tests,
including source/destination aliasing, mask suppression, saturation and memory
completion. `NeverDX86FourSourceSourceTests` checks malformed effects and source
groups, unknown operands, 36 wrapper variants and 36 raw pipeline variants.
Set `NEVERD_FOUR_SOURCE_EXPORT_DIR` and run
`scripts/verify_x86_four_source.py --exports DIR --keep AUDIT_DIR
--llc LLVM/bin/llc --neverc NEVERC/bin/neverc` for O0/O2 ELF/COFF/Mach-O objects,
both C routes, assembly dialects and executable independent operand recorders.
The recorder compares each distinct source, accumulator, mask, segment and
returned value without executing these uncommon instructions.

`scripts/verify_x86_four_source_registers.py` additionally interprets the moves,
spills, mask setup and returns of x64 ELF compiler probes. It checks all four
native register inputs and uses independent result tokens to check return
transport and preserved registers. NeverC probes can select the ordinary C
stack ABI for wide vectors with `--stack-wide-args`; LLVM probes use vector
register arguments. Unrecognized instructions fail. These bounded transport
checks do not simulate native arithmetic or qualify Xeon Phi hardware faults.

The pinned and native SDKs each pass 414 object checks covering 6,804 native
encodings and sixteen executable C operand recorders, eight under Clang UBSan.
Together, these qualify 828 objects, 13,608 instruction encodings and 32
recorders. NeverC passes all 83 focused x86 tests; both its default stack ABI
