# iOS のネイティブコードとソースの復元

[← ドキュメント索引](README.md) · [モバイル概要](../mobile.md)

`neverd mobile` は IPA、`.app`、Mach-O を受け付け、ネイティブ C、ランタイムメタデータ、および対応するネイティブ本体から実験的に復元した Objective-C `.m` と Swift `.swift` を出力します。公開済みの結果にも未復元メソッドが含まれるため、使用前にカバレッジを確認してください。モバイルコンテナは CLI の機能であり、ネイティブ C SDK は選択済み Mach-O を別途読み込みます。

コンパイルによりコメント、書式、識別子、言語構造は失われます。この処理はソース表現を再構成するもので、元のテキストの復元や任意のアプリの動作同等性を保証しません。解析対象アプリを起動することもありません。

## 開始手順と依存関係

```sh
cmake --build build --target neverd
neverd mobile App.ipa -o recovered-ios
neverd mobile App.app -o recovered-arm64 --arch=arm64
neverd mobile executable -o metadata --metadata-only
neverd mobile App.app -o recovered-framework --artifact Frameworks/Example.framework/Example
```

C++20 対応のツールチェーンで `neverd` ターゲットをビルドします。モバイル処理はネイティブ CLI 内で動作し、Python インタープリターを必要としません。Swift 署名のデマングルには NeverD LLVM fork の `LLVMSwiftDemangle` を使います。このコンポーネントは fork のソースビルドと対応する配布 LLVM パッケージの両方に含まれ、NeverD が Swift ソースを別途取得することはありません。NeverD のビルドと実行に Swift コンパイラーやツールチェーンのインストールは不要です。LLVM、Capstone などのネイティブライブラリへの依存は引き続き存在するため、必要なライブラリとライセンス通知を配布してください。macOS で生成した Apple 言語のソースを独立してコンパイルし、Swift の動作回帰テストを実行する場合には、用途に応じて Apple Clang、SDK、`swiftc` が必要です。

Swift 署名の復元は、C++ プロセス内で `LLVMSwiftDemangle` の構造化ノードを直接利用します。外部のデマングル実行ファイルの検索・起動や、ツールチェーン探索コマンドの実行は行いません。従来の実行ファイルパス指定オプションは削除され、従来のデマングラー環境変数も読み取りません。`--metadata-only` はネイティブのソースエクスポーターも署名のデマングルも実行しません。

`metadata/swift-signatures.json` の署名一覧には、内蔵コンポーネントが次のように記録されます。

```json
{
  "demangler": {
    "name": "llvm-swift-demangle",
    "execution": "builtin",
    "version": "6.3.3"
  }
}
```

```sh
neverd mobile App.ipa -o recovered-swift --timeout=600 --json
```

## 入力と選択

IPA には最上位の `Payload/*.app` がちょうど一つ必要です。IPA と `.app` のメイン実行ファイルは `Info.plist` の `CFBundleExecutable` で決まります。どちらも `--artifact` はアプリバンドルからの相対パスで、一つの埋め込み実行ファイルのみを選びます。すべての Framework や Extension を再帰解析する指定ではありません。生の Mach-O 入力には `--artifact` を使えません。

Fat バイナリの `--arch=auto` は arm64、arm、x86_64、i386 の順に優先します。不在または未対応のスライスは明示的に失敗します。現在のソース言語への出力は arm64/x86_64 が対象で、他のアーキテクチャ選択は Objective-C/Swift 対応を意味しません。選択したスライスが `cryptid != 0` なら拒否します。復号済みで読み取り可能な入力を用意してください。アーカイブとディレクトリでは危険なパス、シンボリックリンク、特殊ファイル、衝突する項目を拒否します。

## オプションとリソース制限

| オプション | 既定値 | 意味 |
|------------|--------|------|
| `-o DIRECTORY` | 必須 | 入力ディレクトリの外にある新規出力先。既存出力は保持 |
| `--platform=auto\|ios` | `auto` | プラットフォームを推定、または iOS を選択 |
| `--arch=auto\|arm64\|arm\|x86_64\|i386` | `auto` | Mach-O スライスを一つ選択 |
| `--artifact PATH` | メイン実行ファイル | アプリ基準の実行ファイル相対パス |
| `--metadata-only` | 無効 | ソース復元やツール呼び出しをせずメタデータを読む |
| `--max-func N` | `0` | ネイティブ関数上限。ゼロは検出した全関数。メタデータモードでは無視 |
| `--timeout N` | `300` | 解析全体の正の時間上限（秒）。子プロセスには残りの時間を割り当てる |
| `--max-files N` | `20000` | 正の項目数予算。Swift シンボル一覧も制限対象 |
| `--max-bytes N` | `2147483648` | 入力、展開データ、最終出力の正のバイト予算 |
| `--json` | 無効 | バージョン付きレポートを JSON で出力 |

作業領域は監視され、一時入力と中間出力のために設定した項目数/バイト予算の最大三倍を許容します。ログはプロセスごとに 16 MiB、Swift 署名 JSON はさらに 32 MiB に制限されます。これはリソース制御でありプロセス隔離ではありません。タイムアウトを増やしても他の制限は無効になりません。`--max-func` で除外されてもメタデータ一覧にあるメソッドは未復元として残ります。

## Objective-C ソースとランタイム構造

どちらのソースレポートモードも `source_projection_graph` を含みます。各ノードは最終的な型付きネイティブ本体、ローカル診断、統合された native/Block の `dependencies`、実運用の `closure_closed` 結果を示します。ローカル検査と伝播した依存失敗は別の理由を持ち、型付き本体がなければ診断も未完了です。未束縛呼び出しを解決すると新たな依存が現れる場合があります。閉じたノードは依存段階を通過しただけで、`recovered` になるには生成とソーステキスト検査も必要です。`native_dependency_graph` は別の LowIR 呼び出し一覧です。

繰り返しカバレッジを調べる場合、次のコマンドは `--format=objc-methods` と同じ解析・公開検査を実行しつつ、`native_source` と各メソッドの `source` を省略します。JSON は `sources_omitted=true` を追加し、メソッドの識別子、状態、診断、シグネチャ、共有ヘルパー参照、依存証拠の意味を保持します。レンダリング検査は実行され、完全モードはコンパイル可能なソースを出力します。対応する C API は `neverd_objc_methods_summary_json(session, max_functions)` で、結果は `neverd_free_string` で解放します。

```sh
neverd export WMF --format=objc-methods-summary -o summary.json
```

ネイティブローダーはメソッド記録、実行可能な IMP アドレス、対応する型エンコーディングを明示的なソース ABI 位置に結び付けます。固定のスカラー/ポインター引数は隠れた `self`/`_cmd`、未使用引数、独立した整数/浮動小数点レジスタ群、対応するスタック位置を保持します。float/double のビット再解釈と数値変換は区別します。型ヒントはソース出力の入力であり、認証済み ABI 証拠や実行コードのパッチ許可ではありません。

`sources/objc.m` は実際に復元した文を `@implementation` 本体に置き、必要な C ヘルパーと型付き呼び出しを保持します。呼び出し先には対応するソース結合が必要で、未知の相手や不完全な依存グループは未復元です。定義欠落、不正な実行アドレス、競合する型、未対応 ABI、不完全なデコード、IR 検証拒否は、宣言があるだけで復元済みにはなりません。

ネイティブ補助関数の完全な入力値が COPY/PHI を通じて既存のソース結合のポインター引数に渡され、競合するスカラー用途がない場合、ソース投影用のポインター型を推論できます。物理 ABI 位置と汎用 IR 型は維持され、関数本体とネイティブ依存関係全体の検証も必要です。

ネイティブのスカラーヘルパーでは、観測された入力引数が正確な ABI 戻り値レジスターにあり、結果の全幅を覆う場合、その引数をそのまま返す経路を証明できます。有界解析は全戻り経路、初期入口、ループ後退辺を統合し、呼び出しや部分書き込みで値を無効にします。未宣言の入口値、未使用の引数枠、SSA 初期マーカー、PHI は入力の証明になりません。これはソース投影だけの推論であり、物理位置を維持し、関数本体と依存関係の完全な検証を引き続き要求します。

ローカルのネイティブ補助関数は、入口の可観測性解析と完全な LowIR の読み取り証拠が一致する場合、結果バッファのポインタを含む補助レジスタの全幅整数入力を明示的な引数にできます。呼び出し側保存レジスタは後で一時値に使用できますが、保存対象のコンテキストではフレーム以外の保存レジスタへの書き込みを引き続き禁止します。呼び出しによる暗黙の定義は SSA バージョン 0 でも入口入力ではなく、明示的に保存されたバイトだけを呼び出し越しに追跡します。再生成した呼び出し側と関数定義は同じ物理入力位置を使用します。外部 C/Swift プロトタイプは推定せず、関数本体と依存関係の完全な検証も必要です。

固定 C コールバック型は、ソースの宣言とキャストで引数と戻り値のシグネチャを保持します。正確な `swift_once` インポートは、初期化フラグ、`void (*)(void *)` コールバック、コンテキストを結び付け、戻り値はありません。ランタイム呼び出しは保持されますが、コールバック本体の復元や共有初期化ストレージの所有権は証明されません。依存関係が不完全なメソッドは未復元のままです。

既知の Objective-C ランタイムのインポート呼び出しには、retain/release、自動解放、強参照・弱参照の保存、オブジェクト割り当て、固定シグネチャのプロパティ設定について、明示的な引数と戻り値の対応があります。ARM64 のレジスタ専用 retain/release は指定レジスタを読み取ります。インポートの識別と ABI の一致が必要です。関連オブジェクトの取得・設定・削除では、オブジェクト、キー、値、ポインタ幅のポリシー引数を保持し、生成 C は公開ランタイムヘッダーを使います。macOS の再コンパイル試験で寿命、弱参照のゼロ化、コピー、削除を元のメソッドと比較します。

libobjc の最適化されたクラス照会とセレクタ照会は、nil 処理と独自のオーバーライドを含む実際のランタイム呼び出しを保持します。結果のバイト値には呼び出し元のネイティブ変換が適用され、推測した継承関係の検査には置き換えません。

ソースの束縛では、ポインタ引数が定数アドレスを持つ場合に限り、検証済みの直接クラスオブジェクト識別マップを構築します。マップはその束縛処理内に限定され、後続の処理ではクラス名、メタクラスのフラグ、識別の競合を含め、現在のイメージを再検証します。

Objective-C 出力は、通常の C ABI を持つ限定された Swift ランタイムのインポートも扱います。対象は参照カウント、ネイティブおよび型不明オブジェクトの弱参照、オブジェクトのメタデータ、アクセス検査の開始と終了です。生成 C は呼び出しを保持し、リンクには Swift ランタイムが必要です。専用レジスタの入口、未知の Swift 呼び出し規約、任意の Swift シンボルは対象外で、インポートの識別情報とスカラーの格納位置が正確に一致する必要があります。

arm64 と x86_64 では、Darwin の正確な String → NSString インポート `_$sSS10FoundationE19_bridgeToObjectiveCSo8NSStringCyF` と、オプショナル NSString → String インポート `_$sSS10FoundationE36_unconditionallyBridgeFromObjectiveCySSSo8NSStringCSgFZ` を個別にバインドします。所有権と Clang `swiftcall` を保持し、リンクには Swift Foundation と Swift Core が必要です。逆変換は返された String の 2 ワードを符号なし 128 ビット整数で運び、SSA の構築前に明示的な戻り値レジスタへ分割します。これはビットの搬送形式であり、復元された String レイアウトや汎用の集約 ABI ではありません。未知のシグネチャと不完全な初期化依存関係は引き続き未対応です。

確認済みの関連オブジェクト API のキー引数では、読み取り専用 Mach-O C 文字列領域内の確定したアドレスを共有キーとして再構築できます。同じ元アドレスは同じキーを使い、異なる内部オフセットは別のキーを保ちます。mobile 出力は補助関数を自動的に統合します。C API は `shared_identity_functions` に名前を列挙するため、メソッドの翻訳単位をリンクする際は各補助関数の定義を一つにしてください。キーは再構築したコードに属し、ロード済みの元イメージは参照しません。それ以外の未解決イメージアドレスは復元上の制限として残ります。

検証済みの `os_unfair_lock_lock`, `os_unfair_lock_unlock`, `os_unfair_lock_trylock`, `os_unfair_lock_assert_owner`, `os_unfair_lock_assert_not_owner` インポートは `<os/lock.h>` を通して実際の Darwin 実装を呼び出し、ロックのアドレス、所有権検査、真偽値の戻り値を保持します。未知の派生 API は未対応です。整数の呼び出し結果は宣言された ABI のビットだけを保持します。Darwin arm64 は符号の有無に従って 8/16 ビットの結果を 32 ビットに拡張し、残りのレジスタビットは不明のままです。メソッドの戻り値幅は分岐の合流前に SSA に反映され、未使用の上位ビットが有効な下位バイトを妨げないようにします。

クラスのインポート、レイアウト、文字ストレージ、fixup が完全な場合、検証済みの Darwin `__cfstring` レコードを定数オブジェクトとして再構築できます。埋め込み NUL を含む ASCII バイトと UTF-16 コード単位を保持します。同じ元アドレスは再構築後も同じオブジェクトを共有し、異なるレコードは別のままです。ヘルパーは `shared_identity_functions` に含まれ、リンクには Foundation が必要です。定数オブジェクトへの未検証の生メモリアクセスは許可しません。

境界が確定し、ポインター再配置を含まない `__DATA,__llvm_prf_cnts` の数値カウンターは、メソッド間で共有するストレージとして再構築できます。初期バイト、重なり合う 1–16 バイトの読み書き、更新を保持します。mobile 出力は補助関数を統合し、C API の利用者は各 `shared_storage_functions` の定義を一度だけリンクします。このストレージは元イメージとプロファイル実行環境から独立しています。外部へ渡すアドレス、順序付きアクセス、不完全なマッピング、ポインター再配置は未対応です。 計測された block コールバックは、プライベートなアドレスを外部へ流出させずに、このイメージ内ストレージを更新できます。通常のカウンター書き込みはプライベートなスタックフレームへの書き込みとは区別されます。

クラスメタデータは親クラス、インスタンス開始位置/サイズ、オフセット・幅・アラインメントを検証したスカラー/ポインター ivar を保持します。宣言には必要なパディングを挿入します。必要なインスタンス配置が不明なメソッドは未復元です。Category はクラス/カテゴリ/アドレスの識別情報と実装を分離し、クラスとカテゴリ一覧に重複する完全に同じ記録は一度だけ数えます。対応する外部カテゴリは既存の Foundation クラス宣言を使用します。未知の外部ヘッダーは不足依存として報告し、代替クラス配置を捏造しません。

復元済みと判定するには、完全なクラス宣言とローカルの祖先クラスの定義に加え、生成ソースのすべての使用経路で値が使用前に定義され、到達可能な出口に必要な戻り処理があることも求められます。空のローカル親クラスの `@implementation` は、検証済みの配置と完全なメソッド一覧から自身の通常メソッドがないと証明できる場合にのみ生成し、証拠不足や既知の Foundation インポート名との衝突がある場合は、該当メソッドを理由付きでカバレッジの分母に残しつつ独立して復元可能なクラスを出力しますが、この名前検査はすべての SDK 名、iOS SDK、バージョンを網羅するものではありません。

対応する Objective-C Block 呼び出しには、暗黙の Block オブジェクトと全引数・戻り値の格納位置を含む、完全な固定スカラー呼び出し ABI が必要です。実行時エンコーディング `@?` を `id` に広げるのは宣言だけであり、呼び出しプロトタイプは確定しません。グローバル Block の参照は共有オブジェクトの同一性を維持します。対応する同期スカラーキャプチャでは、実際の格納位置と呼び出しフローを証明します。検証済みの `objc_retainBlock` / `_Block_copy` 呼び出しでコピーされる強参照キャプチャは、到達するすべての構築経路で格納領域が初期化され、呼び出し・コピー・破棄の関数本体が完全に復元された場合にエスケープできます。生成した記述子は元のヘルパー ABI と所有権レイアウトを維持します。弱参照/byref の所有権、未知のレイアウト、未検証の利用先は未復元のままです。 コンパイラーが非エスケープと宣言した C の block 引数も、正確なインポート、引数位置、完全なコールバック ABI が一致すれば対応します。この寿命の契約はメモリーが読み取り専用であることを意味しません。 C API のソース単位をまとめてリンクする場合、`shared_block_functions` の各項目の定義は一つだけにします。mobile エクスポートは一致する定義を統合し、内部で呼び出される関数の差異も含めて競合を拒否します。

プロトコルのメソッド宣言は、解決済みのローカルランタイム記録から読み取り、継承プロトコルと必須・任意のインスタンス／クラスメソッドを扱います。通常形式と相対アドレス形式のリストは同じデコーダーを使います。一致するクラスとプロトコルの宣言がすべて整合する場合だけ、selector に固定の呼び出しシグネチャを与えます。不正な記録や継承サイクルは型ヒントを提供しません。正しい構文の構造体・共用体・配列へのポインターは不透明なポインターとして渡し、配置を推測しません。`objc_metadata.protocols` は宣言を別途公開し、復元済み実装数やクラスの準拠関係には含めません。 他のシグネチャが同一なら、符号付き・符号なし 64 ビット整数の戻り値は符号なしビット表現を共有できます。より狭い整数、浮動小数点、ポインター、引数型の競合は引き続き拒否します。

コンパイラが宣言した NSString の書式呼び出しでは、検証済みの定数書式オブジェクトから昇格後のスカラー引数を復元できます。順序指定と位置指定は、欠落や型の矛盾がない場合に限ります。Darwin arm64 は可変引数を 8 バイトのスタックスロットから読み、x86_64 は整数・浮動小数点レジスタとスタックを使います。生成呼び出しは省略記号と動的ディスパッチを保持します。未知の書式、文字数の書き込み、long double、未対応の拡張は拒否します。 同じ書式解析は `NSLog` などの宣言済み C インポートにも適用されます。正確なライブラリエクスポートを検証し、引数の数が異なる呼び出しでも正しい可変引数プロトタイプを共有します。

プライベートなスタックフレームへの書き込みでは、関数内のどこかで読み取られる全バイトを保持します。フレーム境界、入口の不変なエイリアス、アドレスが外部へ渡されないことを証明できた場合に限り、未読の書き込みを削除し、または整数書き込みの未読の末尾を短縮します。これにより、未使用のスタック詰め物だけが未知でも、昇格後のスカラー引数を復元できます。未知のビットは補完しません。順序付きアクセス、未解決の呼び出し、曖昧なアドレス、副作用のある値、解析予算の枯渇では元の書き込みを保持します。

カテゴリ内の同名メソッドは、実行時の上書き順序が不明でも検証済み ABI 宣言を保持します。動的呼び出しに使えるのは一致する全宣言が同意する場合だけで、曖昧な実装はソース本体として選択しません。矛盾や不正な宣言は引き続き呼び出しの復元を拒否します。

既知の `objc_enumerationMutation` 呼び出しでは、登録された変更ハンドラが復帰する可能性があるため、オブジェクト引数と後続の実行経路を保持します。正確な Darwin `__stack_chk_guard` インポートはランタイムオブジェクトの同一性に結び付けられ、復元したソースにもガード値の読み取り、比較、`__stack_chk_fail` 呼び出しの動作が残ります。

システムの Foundation をインポートするリンク済み 64 ビット Darwin イメージでは、コンパイラから抽出した組み込みのフレームワーク宣言も参照します。同じセレクタのランタイム宣言とフレームワーク宣言はすべて互換である必要があり、可変引数、未対応の集約型、プラットフォーム間で不一致のシグネチャは未解決のままです。このカタログは呼び出し型だけを提供し、レシーバのクラスや関数本体は復元しません。NeverD の使用にローカルの Apple SDK は不要です。 CoreData には、正確なシステムフレームワーク依存関係でのみ有効になる独立したカタログがあります。宣言は公開ヘッダーの所有フレームワークに属し、間接的に含まれる依存ヘッダーは別のフレームワークを有効にしません。

C 宣言カタログは CoreGraphics と ImageIO のエクスポートにも対応します。不透明な画像・色ポインター、整数の個数、浮動小数点の戻り値は宣言された ABI を保持します。公開システムフレームワークのパス別名はエクスポート情報とともに生成されます。非公開パス、異なるバージョン、未宣言のシンボルにはバインドしません。 mobile 宣言もローダーの型文法を使用し、正しい構文の集約型へのポインターをレイアウトを推測せず不透明なポインターとして扱います。

Foundation ブリッジが確立された Swift の大きな永久文字列リテラルは、UTF-8 バイトを共有の静的領域に復元できます。長さ、フラグ、終端、UTF-8 の妥当性、不変性、正確なインポートをまとめて検証します。元のタグ付き表現とブリッジ呼び出しを保ち、埋め込みゼロを含むリテラルや他の格納形式は未解決のままです。

検証済みの定数 NSString オブジェクトは、完全なデータアドレスの由来を保持する整数値として代入・格納される場合も共有の同一性を維持します。スカラー即値、不完全なアドレス、数値演算、オブジェクト内部のバイトへのアクセスには、このバインディングを適用しません。

不変かつ再配置のないイメージ内バイトからの通常のスカラー読み込みは、ビット列を保持する定数に復元できます。1、2、4、8 バイト整数と 4、8 バイト浮動小数点数に対応します。書き込み可能または曖昧な領域、順序付き読み込み、アドレス用途は未解決のままです。同じ式の数値用途の証明をポインター用途に流用しません。

固定引数の C 呼び出しは、コンパイラから抽出した宣言と SDK のエクスポート・再エクスポート情報も使用します。実際の dyld ライブラリ、シンボル、スカラー ABI の一致が必要で、弱いインポート、不明な提供元、未対応のプロトタイプは未束縛のままです。生成 C は別の識別子で元のシンボルにリンクします。言語の例外分岐テーブルを持たない通常の同期呼び出しは、実際の呼び出しとメモリへの作用を保持します。

共有のソース制御フロー解析がすべての到達経路で符号なし上限を証明できる場合、添字付きスカラー読み込みに再構築した不変バイト表を使用できます。ガード、マスク、ネイティブ整数幅、ラップアラウンドの意味を保持し、書き込みやローカル変数のアドレスの逸出は以前の証明を無効にします。各表の上限は 4,096 要素、65,536 バイトです。ソース公開時に現在の範囲、記憶領域、再配置、ヘルパーの全用途を再検証します。ポインター幅の値がイメージのセクションを指す場合は曖昧なままです。狭いスカラー断片やセグメントのパディングだけではポインターの同一性を証明できません。コピーしたバイトはスカラー読み込み専用で、表アドレスは逸出できません。実行テストで整数ビット、負のゼロを含む浮動小数点ビット、範囲外の動作を元のメソッドと比較します。

C カタログは `sys/mount.h` の宣言とアーキテクチャ固有のリンク名を含みます。ARM64 は `getmntinfo`、x86-64 は `getmntinfo$INODE64` を使用します。出力引数は不透明なポインタへのポインタ、モードと戻り値は符号付き 32 ビット整数のままで、正確なシステムエクスポートを検証します。ファイルシステムのレコード配置や返却バッファの内容は推測しません。

外部データの束縛には、各プラットフォームで共通の非 TLS SDK 宣言と、正確なライブラリエクスポートの証拠が必要です。生成 C は実際のシンボルの記憶域を参照し、グローバルポインタと参照先の区別を含め、後続のメモリアクセスを保持します。弱いインポート、識別の競合、未対応の記憶域は未束縛のままです。データ宣言だけでは block の構築や所有権を証明できません。 カタログには CoreData、CoreImage、CoreGraphics、ImageIO、CoreSpotlight のデータを含みます。組み込みリテラルの記憶域は、各ターゲットで空コレクションと真偽値オブジェクトをコンパイルして取得します。外部の非 TLS データへの直接アドレスだけを認め、同じエクスポート検証を適用します。カタログ生成には libclang に加えて `--clang` で指定する Clang コンパイラが必要です。

ARM64 では、外部の `kCIContextPriorityRequestLow` と `kCIContextUseSoftwareRenderer` のストレージ識別を、完全な iPhoneOS と arm64 iPhoneSimulator SDK の一致する宣言、および正確な CoreImage インポートで検証します。コンテキストのオプションは実際のポインタ読み込みとランタイム値を保持し、束縛によって文字列キーや描画動作を置き換えることはありません。

ARM64 の `UIApplicationDidEnterBackgroundNotification` も正確な UIKit 外部ストレージに束縛します。両 SDK の宣言は一致しており、元のポインタ読み込みとランタイムの通知識別を保持します。

ランタイム情報の復元は限定的です。完全なプロパティ・プロトコル、元の所有権注釈、任意の集約型、可変引数末尾、例外に依存する本体、モデル外の Block/キャプチャ配置は保証しません。ランタイム型記述は固定引数のみを示し、元の宣言に省略記号がなかったとは証明できません。Chained Pointer はローダーが対象スロットを解決した場合のみ利用し、未解決形式は診断を残します。

## Swift ソースと記憶配置

構造化 demangler 出力は呼び出せる署名と呼び出せないメタデータを分離します。対応する署名は本体復元前に選択バイナリのシンボル、入口、明示的な機械 ABI と照合されます。Swift レシーバーは Swift ABI に従い、Objective-C の隠れた引数で代用しません。利用者が渡す署名ファイルも検証が必要なヒントです。

実験的エミッターは対応する自由関数、クラスメソッド、指定イニシャライザー、固定配置 struct のメソッドを構築し、一部の mutating レシーバーにも対応します。クラス/struct 宣言と格納フィールドには復元した配置メタデータが必要です。必要な宣言と本体が完全な対応済み依存グループを構成する場合にのみネイティブ呼び出しを出力します。ソース単位には宣言とメソッドをまとめ、元のバイナリを呼ぶブリッジは生成しません。

対応する Swift getter/setter の本体はネイティブ実装から復元し、プロパティに組み込みます。非公開の backing storage は確認済みのフィールド配置を保ち、初期化子や他のメソッドも同じ格納名を使います。プロパティ宣言やフィールド記録だけでは、アクセサー本体の復元を証明できません。

対応する割り当て初期化子、単純なデストラクター/解放処理、型メタデータアクセサー、`_modify`/resume エントリーは、出力済みの型単位に投影できます。各項目には、ネイティブの全フローと効果の有界な証明、実際に復元されたコンテキスト・初期化子・プロパティの依存関係、および関連本体の例外処理と IR の監査が必要です。割り当て側の書き込みは実際の初期化子と一致し、`_modify` は正確な可変フィールドと継続エントリーに結び付かなければなりません。実行時メタデータ呼び出しのモデル上の意味は復元された型内で維持します。これらはコンパイラーのソース投影として明示され、個別に復元した通常のメソッド本体や元のソース文字列を意味しません。

ジェネリック/resilient 配置、async/throwing 関数、不明な呼び出し規約、未対応 accessor/allocator/thunk、不完全な初期化、結合できないネイティブ/ランタイム依存は個別に `unrecovered` です。mangled シンボルや型名だけではメソッド復元ではありません。削除されたシンボルや未分類 demangler ノードはカバレッジを不完全または不明にします。

## 出力とカバレッジ

```text
recovered-ios/
  artifacts/selected.macho
  sources/native.c
  sources/objc.m
  sources/swift.swift
  metadata/objc.h
  metadata/objc.json
  metadata/objc-methods.json
  metadata/swift.json
  metadata/swift-signatures.json
  metadata/swift-methods.json
  logs/
  report.json
```

ソース言語のファイルはコードを出力できる場合だけ存在します。`objc.json` はクラス、カテゴリ、ivar、生のメソッド型記述を、`objc.h` は対応する宣言を保存します。`swift.json` は名義型メタデータと mangled シンボルです。署名/メソッド JSON は分類、省略、理由、件数を保持します。ログにはネイティブ診断と、実行された場合のネイティブ Swift エクスポート診断が含まれます。外部 Swift ツールチェーンの探索やデマングルのログは生成されません。`report.json` の出力パスは同じディレクトリ基準です。選択バイナリは解析成果物であり、生成コードの復元ブリッジとしてリンクしません。

パッケージの一時コピーと中間 JSON は削除します。通常実行でネイティブ本体がなければ、メタデータがあっても失敗します。メタデータモードは選択ファイル、`objc.h`、`objc.json`、`swift.json`、`report.json` のみを生成し、ソースや署名/メソッドカバレッジはありません。`native_function_count`、`objc_method_recovery`、`swift_method_recovery` は `null`。すべてのモードで、ネイティブローダーが解決した Objective-C メタデータを使用します。Swift メタデータは範囲を検証したネイティブイメージ読み取りを使用し、未対応の fixup、再配置可能レイアウト、参照には部分的な解析の診断が残ります。

以下は部分復元を示す短縮した例です。

```json
{
  "schema_version": 1,
  "status": "success",
  "platform": "ios",
  "architecture": "arm64",
  "objc_method_recovery": {
    "status": "partial",
    "method_count": 3,
    "recovered_method_count": 2,
    "unrecovered_method_count": 1
  },
  "swift_method_recovery": {
    "status": "partial",
    "coverage_status": "partial",
    "method_count": 4,
    "recovered_method_count": 2,
    "source_body_method_count": 1,
    "compiler_projection_method_count": 1,
    "unrecovered_method_count": 2,
    "metadata_symbol_count": 5,
    "unclassified_symbol_count": 1
  }
}
```

外側の `status: "success"` は検証済み出力の公開を意味します。`recovered`、`partial`、`unrecovered`、`no-methods` は検出一覧に対する状態であり、意味的同等性や元プログラムの完全性ではありません。未復元メソッドには理由があります。Objective-C の `recovered` はランタイムメタデータの完全性も必要です。空一覧はメソッドが存在しなかった証拠にはなりません。

未復元の Objective-C メソッド行には、単一のバックエンド結果がランタイムの識別情報と完全に一致する場合、`native_backend: {status, reason, diagnostics}` が含まれることがあります。この任意のサイズ制限付き要約は、宣言や配置の検証が失敗した場合にも中間結果を保持します。行の主ステータス、理由、復元件数が最終的な判断基準であり、要約がない場合はこの証拠を利用できなかったことを意味します。

Swift の `coverage_status` は分類済みの呼び出し可能項目のみを数えます。全体の Swift `status` は未知シンボルも考慮し、`unclassified`、`unsupported-architecture`、`no-symbols` になる場合があります。呼び出せないメタデータは `non_method_symbols` に `not-callable`、未知項目は `unclassified` として保存します。`types`、`type_metadata_count`、`source_type_count` は型情報と出力型単位を別に数え、メソッド数を増やす用途には使いません。

復元済み Swift 行の `source_representation` は `native-method-body` または `compiler-generated-from-type` です。コンパイラー投影には `compiler_projection_kind` と `compiler_projection_evidence` も残します。`source_body_method_count` は復元したネイティブメソッド本体、`compiler_projection_method_count` は証明済みのコンパイラー投影を数え、合計は `recovered_method_count` と一致します。コンパイラーのエントリーも `method_count` の分母に残り、正確な識別情報を対応する一つの `type` ソース単位に記録します。型メタデータや依存先の名前だけで復元数を増やすことはありません。ネイティブの一括 JSON ではコンパイラーの行と型単位に `source` を含みますが、mobile の `source_units` は説明のみを保持して `source` を含まず、完全なソースは `sources/swift.swift` に保存されます。

Swift バッチの `source_units` は `{kind, module, name, source, method_entries, method_identities}` を持ち、kind は `function` または `type`、各 identity は `{entry, mangled_symbol}` です。異なるシンボルは同じ入口を共有しつつ個別の ABI 出力を保持できます。各復元済み identity は一度だけ現れ、未復元 identity は含めません。`method_entries` は `method_identities` の入口を順に並べたものと一致し、アドレス重複を許します。同一 identity の重複を黙って統合してはいけません。バッチ `source` は各単位のソースと改行を順に結合したものです。Mobile は全体を `sources/swift.swift` に、単位の説明をカバレッジ JSON に保存します。個別メソッドの `source` は閲覧用で、単純連結ではクラス宣言を正しく構成できません。

## ネイティブ直接エクスポートと SDK

```sh
neverd export recovered-ios/artifacts/selected.macho \
  --format=objc-methods --max-func=20 -o objc-batch.json
neverd export recovered-ios/artifacts/selected.macho \
  --format=swift-methods \
  --source-signatures=recovered-ios/metadata/swift-signatures.json -o swift-batch.json
```

Swift エクスポートは、通常の mobile 実行で内蔵の署名パーサーが生成した構造化署名一覧を受け取ります。Objective-C バッチ JSON は `native_source`、`native_function_count`、`objc_metadata` と、各メソッドの C ソース、関数名、戻り型、引数を含みます。Mobile は `.m` の前に宣言、本体、配置を追加検証するため、最終カバレッジは C バッチより狭くなる場合があります。ネイティブエクスポート成功時も復元メソッドがゼロの場合があります。

各メソッドの `projection_diagnostics` は、独立して検査できる問題を `items` の `code`、`reason` と利用可能な文・呼び出し・値・依存関係の証拠で記録します。`checks_complete: false` は前提不足または資源上限を示し、空の部分報告は復元成功を意味しません。判定と同じ検査を使い、既存の `status`、`reason`、`unbound_call` を維持します。

バッチの `native_dependency_graph` は、対応する署名のメソッドから最終 LowIR の直接呼び出しを追跡し、呼び出し元・ブロック・命令アドレス、共有先、循環を保持します。間接ターゲットは null です。必要な LowIR 関数の欠落または記録上限で `inventory_complete` が false となり、`targets_complete` はさらに全記録の直接ターゲットを要求します。未対応のメソッド起点と未解決の間接ターゲットは範囲外で、完全なネイティブ実行カバレッジや依存ソースの復元は証明しません。

検証済みのローカルプロトコル参照は `objc_getProtocol` で登録済みの同一性を維持します。バッチの依存一覧 `runtime_protocols` はネイティブ呼び出し先の要件も含みます。名前の競合、不完全な宣言、インポートスロット、未解決の再配置はバインドしません。独立エクスポートは、null のプロトコルを受け取る本体を生成せず、プロトコル登録の不足を報告します。

Swift ランタイム ABI カタログは固定リビジョンの上流宣言から生成し、C または Swift の呼び出し規約を保持します。既知のポインタとポインタ幅の符号なし型による固定スカラー署名を扱います。Swift 呼び出しには正確な非弱 libswiftCore インポートが必要で、対応する二種類のバージョン付きメタデータ可用性も弱インポートを許可しません。特殊引数レジスタ、不明な表現、未対応の可用性、競合宣言は除外します。swift_willThrow は宣言 DSL にない swiftself/swifterror 属性をコンパイラが追加するため対象外です。副作用と既存のコールバック・バイト契約を保持します。`scripts/generate_swift_runtime_declarations.py --input RuntimeFunctions.def --source-sha256 <pinned-hash>` で再生成し、`--check` で検証します。リビジョン、ハッシュ、第三者通知を付記します。

固定 Swift ランタイム宣言は、二つのポインタ、または宣言されたメタデータポインタと状態ワードからなる二ワードの結果も保持します。共有 ABI 層が両方の結果レジスタを割り当て、ソース検証が順序、型、正確なインポートを再確認します。Box 割り当てとメタデータ照会は実際のランタイム呼び出しを実行し、集約引数、不明なレイアウト、隠れたコンテキストは未対応です。

これとは別に、コンパイラで正確に観測した URLRequest、Notification、URL、Data、Date、IndexPath の Foundation 値ブリッジは、`swiftcall` と提供元の同一性を保持します。間接結果と context/self は専用レジスタの `swift_indirect_result` と `swift_context`（arm64 の x8/x20、x86_64 の RAX/R13）を使い、通常の整数引数レジスタ群を消費しません。Data は明示的な二ワード転送を保持します。これは呼び出しキャリアの宣言であり、復元した値レイアウトや一般的な Swift ABI ではありません。

ネイティブのスカラー結果推論は、検証済みの結果 ABI を持つ呼び出し直後の完全な二ワード抽出を認識します。一時値の同一性、メンバーのオフセット、幅、物理レジスタがすべて一致する必要があります。補助関数は最初のメンバーを直接返せますが、通常のレジスタビュー規則、呼び出しによる上書き、全リターン経路で結果が定義される要件は維持します。

固定 C ランタイムのカタログは、32 ビット整数の受け渡しと、明示的にゼロ拡張される真偽値の戻り値にも対応します。真偽値は完全な符号なし 1 バイトとして扱い、真偽値の引数の拡張規則は推測しません。さらに狭い未確定の表現や Swift 呼出規約の 32 ビット宣言は対象外です。実行テストでは型変換の成功・失敗、指定回数の参照保持、オブジェクト破棄を検証し、呼び出しと所有権への効果を維持します。

格納フィールドのメタデータでは、既知のバイト配置と不明な言語型を区別します。安定 ABI の Swift クラスは arm64 でもポインター幅のフィールドオフセット変数を使用し、非公開フィールドの Objective-C 型エンコーディングは空の場合があります。NeverD は型の欠落を保持し、オフセット、サイズ、アラインメント、重複を検証します。復元した C 関数本体は実行時の ivar 検索でオフセットを取得します。不明な型を作り出す必要があるクラス宣言は引き続き出力できません。

安定 ABI の Swift フィールドは、オフセットが実行時に初期化されるゼロ埋め領域にあっても、メタデータ上の識別情報を保持できます。クラスは `ivar_status: "runtime"` となり、未知のオフセットは JSON の `null`、サイズ 0 は実行時に決まるフィールド幅を示します。メソッド本体は既存のランタイムクラスからオフセットを取得し、宣言されたオブジェクト型は正確なオフセットスロットから追跡できます。定数オフセットには既知の配置が必要です。Swift クラス配置を再構築する機能ではなく、独立したクラスの出力では未知の配置やフィールド型を引き続き拒否します。

直接バインドされたネイティブ呼び出しでは、呼び出し先が観測可能な副作用より前の入口でポインタを一度だけ読み取り、書き込み、保持、比較などに使わないと証明できる場合に限り、ivar オフセットのアドレスをローカルスカラーのアドレスに置き換えます。値は既存の実行時 ivar 検索から取得し、ネイティブ ABI と呼び出し先の本体は維持します。この有界な証明は直線的な制御フローのみを受け付け、不明な用途や解析上限の超過を拒否します。C API は `.cxx_destruct` を復元できますが、独立した Objective-C メソッド構文ではこのセレクタをまだ出力できません。

不変バイトバッファーは、検証済みのインポート呼び出し契約が非負の読み取り長を制限し、書き込み、ポインターの保持、アドレス同一性の比較を除外する場合にのみ再構築されます。元のバイトと長さを保持し、その他のポインター用途は未解決のままです。Swift 標準ライブラリの正確なアサーション失敗は、コンパイラから導出したスカラーおよびスタックキャリア、`swiftcall`、`noreturn` 効果、リンカー表記を保持します。C の診断 shim は宣言済みの C ABI と独立した後続トラップを保ちます。静的文字列と不滅な String リテラルの格納領域は、ポインターを保持しない認証済みの終端コンシューマーに対してだけコピーします。動的または所有権を持つ String 値をリテラルとして扱いません。

Mach-O 読み込み済みセッションでは `neverd_objc_methods_json(session, max_functions)` と `neverd_swift_methods_json(session, signatures_json, max_functions)` が対応するレポートを返します。ゼロは検出した全関数です。返された文字列は `neverd_free_string` で解放してください。`NULL` は失敗で、理由はセッションエラーにあります。これらの API は IPA/`.app` コンテナを読み込みません。

Objective-C のネイティブ依存関係推論は、ソース呼び出しを結び付けた後、`NativeAnalysis` の 64 ビット整数レジスタ引数を 32 ビットへ狭められます。網羅的な HighIR 使用証明により、すべての出現がオフセット 0 のバイト抽出または正確に結び付けられた呼び出しの整数引数として、下位 4 バイトだけを正確に観測することを示す必要があります。証明は引数ごとに独立しており、全幅、0 以外のオフセット、不正な使用、または解析予算の枯渇では元の幅を維持します。精緻化した補助関数は再リフトされ、通常の本体検査と依存関係閉包検査に合格する必要があります。書き換え ABI は変わりません。

Objective-C エントリー thunk として公開される Swift の遅延初期化 static オブジェクト getter は、`vgZTo` シンボル、ランタイムメソッド署名、述語テスト、`swift_once` 呼び出し、ストレージのロード、`objc_retainAutoreleaseReturnValue` の結果がコンパイラーの厳密なパターンを構成する場合にのみ投影できます。述語 `_Wz`、初期化子 `_WZ`、ストレージ `vpZ` の各シンボルが一致し、未加工の第 3 レジスターは once コンテキストとしてだけ現れ、初期化子はそのコンテキストを無視し、通常の直接呼び出し元を持たない必要があります。投影は述語とオブジェクトストレージを再構築し、無関係なコンテキストとして null を渡し、初期化子を検証済みの依存関係として保持します。形状、シンボル、引数の使用、コールバックのいずれかが異なる場合は復元しません。

認証済みの `cfcTo` シンボルとランタイムの `init` シグネチャを持つ Swift Objective-C コンストラクター thunk でも、宣言されていない第 3 引数レジスターの唯一の使用箇所が、厳密に検証された単一の `swift_once` 呼び出しのコンテキストである場合、その引数を除去できます。述語 `_Wz` と初期化子 `_WZ` が一致し、コールバックはコンテキストを無視し、通常の直接呼び出し元を持たない必要があります。投影は null を渡し、述語の 8 バイトのストレージ範囲のみを推論して、その他の制御フロー、メモリー、呼び出しの効果をすべて保持します。通常のソース本体と依存関係の閉包の検証も引き続き適用されます。

ARM64 の once コールバックは、外側の `_WZ` シンボルと内側の `_Wz`/`_WZ` の組が厳密に一致し、両コールバックに通常の直接呼び出し元がなく、独立して型が検証された末端コールバックがコンテキストを無視する場合、他では使われない x2 を単一の入れ子の `swift_once` に転送できます。検出と投影は同じ契約を使います。投影は null を渡して全ステートメントを保持し、void コールバック ABI により副作用のないレジスター、テンポラリ、定数の戻り値だけを除去できます。戻り値内のスタック読み取り、ロード、呼び出し、および未解決の依存関係は引き続き拒否されます。

## 検証とトラブルシューティング

macOS で `BUILD_TESTING` を有効にしたビルドには `check-neverd-mobile-ios` があり、CTest で三つのネイティブ復元テストスイートを実行します。

Python は以下の開発用テストスクリプトでのみ使用します。内蔵のモバイル復元はネイティブ C++20 CLI で実行されます。

```sh
cmake --build build --target check-neverd-mobile-ios
ctest --test-dir build -L NeverDMobileTests --output-on-failure
python3 scripts/test_mobile_ios_backend.py --neverd build/bin/neverd
python3 scripts/test_mobile_ios_calls_backend.py --neverd build/bin/neverd
python3 scripts/test_mobile_swift_backend.py --neverd build/bin/neverd
```

macOS の Objective-C 検証スクリプトは元のサンプルをコンパイルし、`.m` を復元した後、生成ソースだけを独立した呼び出しハーネスとリンクします。スカラー用スクリプトは整数境界、分岐、ループ、ポインター読み書き、暗黙引数、float/double のビット同一性、混合引数、スタック引数を扱います。呼び出し用スクリプトはメッセージ配送、継承、Category、インスタンス変数、ネイティブヘルパー、Block 呼び出し・キャプチャ・共有同一性も扱います。呼び出しサンプルは、arm64/x86_64 × classic/default の各構成で 21/21 件のメソッド復元と 134/134 件の独立した期待結果への一致を要求します。現在のネイティブ CLI ビルドで検証してください。

厳格な Swift スクリプトは、ユーザー宣言 22 件、getter/setter エントリー 3 件、コンパイラー生成の呼び出し可能エントリー 9 件を確認し、一覧からの欠落を許しません。各バリアントで元のプログラムに対して 858 件の独立した期待結果を確認します。生成した `.swift` とハーネスを独立にコンパイルし、元の dylib、モジュール、ブリッジ、手書きの代替宣言は使用しません。スカラー/ネイティブ呼び出し、クラス初期化と格納、構造体の値渡し/mutating メソッド、浮動小数点とスタック引数、ポインター、ループを扱います。ネイティブ C++20 CLI の受け入れ条件は、arm64/x86_64 × classic/default の四構成ですべてスキップなしに成功することです。各構成でネイティブ本体 25 件とコンパイラー投影 9 件を復元し、呼び出し可能な識別情報 34 件を保持し、元のプログラムと独立にコンパイルした生成 Swift がそれぞれ 858/858 件の期待結果に一致する必要があります。この結果は当該サンプルに限られ、任意のアプリケーションや元のソース文字列の復元を保証しません。スクリプトはカバレッジ欠落、ソースのコンパイル失敗、動作の不一致を拒否します。

この四構成のコンパイル対象は macOS です。追加の二つのコンパイラーエントリーは空の値型の初期化子とそのメタデータアクセサーであり、それぞれのネイティブ証明を検証し、一つの `struct Empty {}` ソース単位で両方の識別情報を保持します。このコーパスの成功は、実際の iOS アプリケーションの検証完了を意味しません。

三つのスクリプトは `--arch all|arm64|x86_64`、`--fixups both|classic|default`、`--timeout N`、`--work-dir NEW_DIRECTORY` に対応します。`--setup-only` は元のサンプルだけを検証し、復元はテストしません。スカラー検証を含め、指定したすべてのアーキテクチャと fixup の組み合わせを完了する必要があります。組み合わせが欠ける場合や、ホストで指定アーキテクチャを実行できない場合は失敗となり、スキップは認められません。保存された失敗成果物でソースの欠落、コンパイルエラー、動作の差を区別し、検証済みと主張する前に現在のテスト結果を確認してください。

[Mobile Real Applications ワークフロー](../../.github/workflows/mobile-real-apps.yml) は、[コーパスマニフェスト](../../scripts/mobile_real_apps.json)でバージョンを固定した公開アプリを使用します。合格には、iOS バンドル内の全 Mach-O と APK 内の全 DEX の独立した一覧、元のアプリと生成ソースの独立した再ビルド、動作比較が必要です。未完了の段階、一覧の網羅性が不明な項目、必須ケースの欠落はいずれも不合格になります。実アプリの recompile と behavior 段階はまだ未完了のため、Experimental 表記を維持します。テスト基盤の誤判定防止テストに通っても、実アプリの検証に合格したことにはなりません。

公開はトランザクション方式です。新規ディレクトリを選び、最初に終了状態を確認し、リダイレクトする JSON はその外に置いてください。失敗時は一時出力を削除し既存結果を保持します。バックエンドの非ゼロ終了時には、長さを制限したログ末尾がエラーに付きます。バックエンドのタイムアウトでも、すでに取得したログテキストが利用可能な場合は、元のタイムアウトメッセージを保ったまま長さを制限した末尾を付加します。予算超過のメッセージは従来どおりです。ネイティブ CLI は成功時にゼロ、復元失敗時に非ゼロを返します。`--json` では処理済みの失敗に `schema_version`、`status: "error"`、`error` が含まれます。引数解析、ネイティブ実行ファイルやライブラリの起動失敗、中断は stderr のみで報告される場合があります。まず終了状態を確認してください。

暗号化スライスには読み取り可能な入力を用意し、必要なアーキテクチャが見つからない場合は利用可能なスライスを確認してください。省略メソッドの正確な理由とメタデータ診断を確認します。`--max-func` の増加が有効なのは上限で除外された関数だけです。配置、署名、外部ヘッダー、例外、ABI 対応不足には実装や追加の有効メタデータが必要で、完全復元という主張では解消しません。配布時には適用される依存ライセンス通知を保持してください。

ネイティブのスカラー補助関数では、float/double のレジスター引数と戻り値も推論できます。共有 MedIR の入口バイト解析で、広いベクトル入力が下位の単一スカラーレーンだけを観測すると証明する必要があります。ローカル CONCAT 値の縮小には、全定義で同じ下位幅、破棄する上位式に副作用がないこと、全使用がその下位部分だけを読むことが必要です。呼び出し、ストア、分岐位置、NaN 以外の浮動小数点ビット列を保持し、未知の上位ビットを補いません。

検証済みの外部 void 末尾呼び出しへ転送するリーフ補助関数は、完全なスカラー結果がない場合、内部 void ソース署名を使用できます。LowIR の全呼び出しと合成 return が一致する必要があります。リーフ証明は保存対象、フレーム、スタック、リンクの各レジスタへの書き込みを禁止し、制限付きのバイト汚染不動点はスタック由来値の保存や呼び出しへの受け渡しも拒否します。CFG、本体、依存関係の検証は継続します。結果ビットは供給されず、未知の結果を読む呼び出し元は未復元のままです。実行回帰では条件付きオブジェクト破棄、独立した呼び出し元の戻り値、未知の結果を読む呼び出し元の拒否を確認します。

void のネイティブ要約は、制限付き LowIR 解析がすべての出口で保存対象のレジスタバイト、スタックポインタ、リンクレジスタの復元を証明できる場合、スタックフレームと通常の呼び出しにも対応します。部分書き込み、暗黙のゼロ拡張、重複ストア、呼び出しによる破壊は対応する事実を無効にします。フレーム由来のバイトを含まないと証明されたアドレスへのストアは、その呼び出しの非公開フレームとは独立していますが、フレームから部分的または完全に導出されたエイリアス、フレームアドレスのスピルやエスケープは証明を拒否します。フレーム借用の唯一の例外は、ソースに結び付けられた `objc_msgSendSuper2` の正確な第 1 引数です。このランタイム契約は同期的に読み取るため、割り当て済みフレーム内に完全に収まる 16 バイトの完全な `objc_super` オブジェクトを指せます。通常のメッセージ、不完全なポインタ、フレーム外のオブジェクト、その他すべてのフレーム引数は引き続き拒否します。HighIR のバイト生存解析はスタックスロット値をそのスロットのバイトに限定した読み取りとして扱いますが、そのアドレスの取得や受け渡しは引き続きエスケープです。不正または重複するアクセスは保守的に扱います。これにより、独立した非公開ストアは未読の末尾バイトだけを除去できます。再リフト後、HighIR に一度も現れない補助レジスタ引数を除去してパイプラインを再実行できます。非公開ストアの除去は既存の HighIR クリーンアップが担い、通常の引数と実際の入力使用は保持します。

arm64 UIKit カタログは `UIProgressView` の `observedProgress` のオブジェクト戻り値と `setProgress:animated:` もバインドします。後者では `float` と Boolean の引数レジスタを分離して保持します。両宣言にはコンパイラが生成した iPhoneOS と arm64 iPhoneSimulator の証拠の一致、および正確なシステム UIKit 提供元が必要です。他のアーキテクチャは未対応です。

タグ付きリテラルのワードは、厳密な最上位ビットのタグと、不変なC文字列プール内の完全なイメージアドレスを保持できます。ソースバインディングは証明済みのアドレスだけを既存の永続共有プールへ再配置し、整数OR、タグ、内部オフセットを維持します。似たスカラー値や部分アドレス、矛盾する由来、書き換え可能または再配置情報を持つプール、直接のメモリアドレスとしての使用は拒否します。Swift Stringオブジェクトのレイアウトは推測しません。

`UIProgressView` の `setProgress:` には、正確な ARC 同一性呼び出しを経ても保持される型付きプロパティ結果など、証明済みのレシーバが必要です。検証済みの親クラスとプロトコルの閉包により `float` 引数を選びます。UIKit とローカルクラスには同名のオブジェクト引数 setter もあるため、レシーバ未限定の呼び出しは曖昧なままです。

arm64 UIKit カタログには、オブジェクト引数と符号なし 64 ビットの `UIControlState` を取る `UIButton` の `setTitleColor:forState:` と、`UIView` の void メソッド `invalidateIntrinsicContentSize` も記録されています。デバイスとシミュレーターの完全な AST の証拠は一致しています。確認済みの `UIImageView → UIView` 継承関係により、既存の receiver 証明は、ローカルのオブジェクト setter と無関係なクラスの同名浮動小数点 setter を区別できます。不明な receiver、サブクラス宣言の競合、親の提供元の欠落、x86_64 は引き続き未対応です。

辞書検索が修飾なしの `id` を返す場合、`new` から既知のクラスを返す経路と合流しても、そのレシーバークラスを引き継ぐことはありません。すべての流入経路でレシーバーの根拠を保持する必要があり、明示的に型付けされたポインター引数だけでは、競合する浮動小数点の宣言を除外してオブジェクト値の setter を選択できません。

Arm64 の `+[NSSet setWithObjects:]` は SDK の nil 終端可変引数宣言を保持します。最初の対応範囲は、正確なプラットフォームクラスのインポートと selector スタブ、および全流入経路で完全な 8 バイト値が一致する不変 Objective-C 文字列引数です。復元は最初の確定 nil で停止します。最初のオブジェクトが nil ならスタック末尾引数の証明は不要で、終端以降のスロットを読みません。共有 Darwin 可変引数 ABI は固定引数を 3 個保持し、残りのオブジェクトと nil をスタックに配置します。公開時に現在のイメージに対して宣言、提供ライブラリ、レシーバー、selector、各引数を再検証します。動的オブジェクト、不完全または欠落した末尾ストア、エスケープしたフレーム、ローカルオーバーライド、他のアーキテクチャは未対応です。 スタック引数は、直線的なプライベートフレーム内の各ロード時点でも証明します。後の上書きは読み取り済みの値を変更できず、重複書き込み、不明な呼び出し、エスケープ、制御フローがある場合は認証しません。

コンパイラ生成の BOOL super getter は、現在の完全な ARM64 命令、CFG、保存・復元の証明が Objective-C の入口、共有本体、metadata accessor（`CMa`）を認証した場合に限り、入口ごとにソースへ投影できます。検出、バインド、出力は同じ契約を使います。helper は実際の CMa 呼び出しと閉じた依存関係を保持し、その後にランタイム登録済み SEL セルを読み、認証済みの型で `objc_msgSendSuper2` を呼びます。異なる selector は別のセルを保持します。loader は LLVM の Mach-O シンボルと export trie、および現在の segment/section マッピングの厳密な一致からローカルなリンク属性を再検証します。他の呼び出し元や共有関数のグローバルな native ABI は変更せず、証拠の欠落や陳腐化は拒否します。

arm64 の Swift once 初期化子は、型が確定した native helper を通じて、独立した静的スロット間でオブジェクトをコピーできます。単一の用途契約が現在の全引数と全経路を検証し、predicate の読み取り、任意の `swift_once`、コピー元の読み取り、コピー先への書き込み、`objc_retain`、return の順序を保ちます。対象は四つの役割を持つ引数と、必要なら未使用の入力一つです。引数の削除は native 推論だけが担当します。検出と束縛は、現在の image に対して同じ契約、正確なコールバックとストレージのシンボル、重ならない8バイトの範囲、コールバックが context を使わないことを再検証します。ABI、制御フロー、メモリ効果、依存関係の検査は維持され、別名、部分アクセス、順序付きアクセス、追加用途、古い証拠は拒否されます。

完全な iOS 実機用およびシミュレータ用 SDK 宣言は、`UIGraphicsBeginImageContextWithOptions(CGSize, BOOL, CGFloat)` が void を返す固定 C 呼び出しであることも示します。ARM64 ではサイズの2フィールドを `d0` と `d1`、真偽値を `w0` 内の1バイト、倍率を `d2` で渡します。正確な UIKit リンカーエクスポートで提供元を認証します。ソースは実際の呼び出しとラッパーのカウンター更新を保持し、異なる提供元、未対応のアーキテクチャ、変更された宣言を拒否します。 ネイティブラッパーには状態と戻り値の独立した証明が引き続き必要です。

同じ検証済み UIKit SDK の証拠により、`CGSizeFromString(NSString *)` と double 二つからなる `CGSize` 戻り値を結び付けます。共有 ABI は `d0` と `d1` の両方を保持し、別の呼び出しをまたいで使われる個別の戻り値も維持します。現在のインポートとシグネチャの再検証では、異なる提供元、スカラーへの置換、変更されたポインタ引数、欠落または交換された戻り値キャリアを拒否します。

ARM64 のネイティブフレーム保存解析は、現在推論された入口シグネチャが明示する、8 バイト境界に整列した完全なスカラー入力スタックスロットを読み取れます。LowIR の読み取りはスロット全体と正確に一致する必要があります。この値は未知の入力であり、保存レジスタの同一性や呼び出し先の私有フレーム内のアドレスの根拠にはなりません。書き込み、部分読み取り、隙間、未宣言のスロットにはこの許可を与えません。ソース本体、各呼び出し元の引数値、依存関係の閉包は引き続き検証が必要です。

デバイスとシミュレータの完全な UIKit SDK 宣言は、`UIAccessibilityPostNotification` を `void(uint32_t, id nullable)` として結び付けます。ARM64 では符号なし通知値を `w0`、オブジェクトポインタを `x1` で渡します。`UIAccessibilityAnnouncementNotification` は外部の `const uint32_t` ストレージです。正確な UIKit インポートによってそのアドレスを確認し、元の4バイト読み取りと nil 引数を含む実際の呼び出しを保持します。通知番号は置換しません。異なる提供元、弱いインポート、幅・符号・戻り値契約の変更は拒否し、その他の遅延ストレージ依存関係には独立した証明を要求します。

Mach-O generic64 のチェーン形式リベースは、`DYLD_CHAINED_PTR_64` と `DYLD_CHAINED_PTR_64_OFFSET` の両方で符号化された上位 8 ビットを保持します。オフセット形式では、完全なワードを復元してからオーバーフローを検査しつつ優先映像ベースを加算し、[dyld の実行](https://github.com/apple-oss-distributions/dyld/blob/fd8d0c4d52320ebf64db34f3cb280310d905c5ae/common/MachOLoaded.cpp#L771-L792)に合わせます。読み込まれたバイトは完全な実行時の値を保持します。通常のコード・データポインタの所有範囲は完全なマップ済みアドレスで検査し、タグ付き Swift 文字列には専用の文字列表現の証明が必要です。正当にマップされた高位アドレスも引き続き対応します。

独立した不変チェーン値リーダーは、一意に所有されたファイル由来の不変領域内にある正確な Mach-O リベーススロットについてのみ、解決済みの完全な実行時ワードを返します。未解決・曖昧・インポート・重複した fixup は拒否します。この値は通常のポインタ識別や再配置済みバイトのコピーを許可しません。ソース側の利用者は、Swift 文字列のタグを含め、表現と再配置を別途証明する必要があります。

不変 Swift 文字列の once コールバックは、6 命令の呼び出し元、12 命令の共有本体、3 命令のアドレス取得関数を完全に検証して一つの経路を証明できる場合に投影できます。8 バイトの書き込み 2 回の順序と実際の `swift_bridgeObjectRetain` 呼び出しを保持します。タグ付き文字列を検証し、リテラルセクション全体の共有ストレージでアドレスを再構築するとともに、書き込み先シンボルの共有ストレージも保持します。現在のイメージバイト、完全なパイプライン監査、フレーム保存、強いランタイムインポート、最終ソース本体を再検証し、共有本体やアドレス取得関数に汎用 ABI を付与しません。

ARM64 Objective-C のソース復元は、呼び出し元で証明した一か所の Swift 文字列比較と、その生の 1 ビット結果を扱えます。ゼロ拡張の前に現在の入口 ABI、強いインポート、正確な呼び出し位置と全利用箇所を検証します。生成 C はランタイムを `swiftcall` の `_Bool` として宣言し、結果を明示的に `uint8_t` に変換します。元のマスクと周辺の呼び出しは保持します。公開時に LowIR とパイプライン監査を再確認し、重複評価や別関数の証拠を拒否します。通常のバイト戻り値、ネイティブ呼び出しの推測、patch と lift モードには適用しません。

手動の Swift String ABI 証拠収集ワークフローは、`String.hasPrefix` 用の固定 `prefix` プローブにも対応します。両 ARM64 iOS SDK の独立した Swift/C コンパイラ出力を保存し、正確な `swiftcc i1(i64, ptr, i64, ptr)` 呼び出しを要求します。マニフェストにはプローブ、シンボル、コンパイラの識別情報、ソースのハッシュを記録します。証拠の収集だけではソースバインディングは追加されません。
