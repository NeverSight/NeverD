# インタープリターのソース復元

実験的なインタープリター特化処理は、リンク済みの x64 関数から静的に解決できるディスパッチを除去し、実行時入力、メモリへの作用、分岐、ループを残します。ハンドラーの特徴や特定の保護ツールのオペコード表ではなく、命令の意味論に基づいて動作します。

```sh
neverd decompile program --func vm_entry --devirtualize \
  --recovery-report recovery.json -o recovered.c
neverd decompile program --func vm_entry --devirtualize \
  --llvm -o recovered-llvm.c
```

`--vm-control` は、インタープリターのコンテキストを区別する汎用レジスタ全体を選択します。複数回指定できますが、具体値を与えるものではありません。たとえば、入口のコードが値を設定するバイトコードカーソルを指定します。カウンターに使う実行時入力は動的なまま扱う必要があります。異なるカーソル値が合流するとき、コンテキストの分離が不足していれば復元が停止することがあります。これを補うためにディスパッチ先を推測することはありません。カーソルがスタックへ退避される場合、`--vm-control-stack=-16:8` で入口 RSP から 16 バイト手前の 8 バイトを選択できます。このオフセットの基準は関数入口であり、調整後の現在のスタックポインターではありません。

C API は `neverd/sdk/NeverDCAPIDevirtualize.h` の `neverd_devirtualize_source_v1()` です。独立したトランザクションで実行し、セッションの通常の逆コンパイルキャッシュを変更しません。失敗時はソースを返しませんが、JSON 診断を返すことはできます。返された両方の文字列は `neverd_free_string()` で解放します。

## 制御状態の自動検出

CLI とすべてのバージョンのソース復元 C API は、自動検出を既定で有効にします。プロバイダーに依存しない C++ API では `SpecializationOptions::DiscoverControlState = false` が既定であり、利用側が `true` を指定します。手動の `--vm-control` と `--vm-control-stack` は引き続き任意のコンテキストキーです。通常の自動検出フィールドは、有界な有限値の同時関係だけを保持し、コンテキストキーの追加や実行時入力の標本値への固定は行いません。以下の選択的なメモリー精密化で証明済み定数が必要になる場合を除き、通常のカウンターは動的なままです。

未解決の制御・アドレス依存から、構造化されたノード入口のレジスター入力と、メモリー入力が最初に生成されたときの由来を追跡します。狭いバイト範囲も対象です。フレームスロットを候補にするのは、その由来がノード入口から未変更のメモリーを示し、関数入口のフレームに対する正確な相対範囲を特定する場合だけです。同じ値やストアから転送された値を後から読み取っても、新しい入力依存は生じません。メモリーの情報を無効化した後に生成された未知バイトも入口のスロットとは扱いません。過去の読み取り記録は、他の解析で引き続き利用できます。欠けた依存を検出すると関数入口から解析を再開します。保持する各関係には、その関係が制約するビットについて完全な有限値証明が必要であり、別名の可能性がある書き込みは引き続きメモリーの事実を無効化します。任意の外部メモリーや無界な相関値を有限化するものではありません。

生産側への要求は、ノード境界を越えてビットマスクを保持し、バイト全体へ切り上げません。ただし算術演算では、要求されたビットに桁上がりや桁借りを伝える可能性がある下位ビット列を保守的に含めます。

追跡済みのメモリー依存により正確なアドレスの証明が繰り返し妨げられる場合、追加の精密化で証明済みの流入定数をコンテキストキーに昇格できます。

通常の依存探索が停滞した場合、関数入口以外のネイティブ位置と命令モードごとに、既存のレジスターコンテキストフィールドを一つ分割できます。流入ドメインは完全で複数の値を持ち、宣言された全ビットを覆う必要があります。実際の各先行辺が現在の完全なドメインを独立に証明し、生きた物理フィールドを比較して各ケースを再投影します。後続の先行辺や拡大されたノードも再検査し、連鎖は候補入口で停止します。比較は合成の来歴を持ち、ノード、操作、コンテキスト、クエリ、精密化の予算を共有します。部分マスク、未定義フラグ、フレームのみのフィールドは対象外です。ゲスト読み取りや呼び出し側の仮定は追加しません。不完全なドメインでは保守的な辺を保持し、到達可能な全ケースの完了を公開条件とします。

この選択的な精密化では、入口フレームの基点に正確な変位を加えた値と証明された、完全な 64 ビットレジスター値や退避済みポインターもコンテキストを区別できます。キーは変位を保持し、呼び出し時の数値アドレスを推測しません。部分書き込みや別名の可能性はポインターの事実を無効にします。条件分岐は、精度不足の合流によって未対応の後続処理が現れた場合を含め、最終制御証明の前に有界な精密化の依存候補を提案できます。候補は条件が偽である証明ではありません。到達可能性と保持する宛先は完全な証明を要し、未対応処理が到達可能なまま、または必要な予算が尽きた場合は公開しません。未対応の後続処理に対する候補探索は、直近の条件未確定な先行分岐を選びます。完全な後方スライスではありません。

生産側への逆向き要求は、ネイティブノードの入口、命令モード、フィールドの種類とバイト範囲で識別します。後続ノードがそのフィールドを必要とするエッジだけが生産側の依存を展開し、有限でも精度が不足する値域も対象にします。これにより予算内で入口から再解析することがありますが、再利用される物理レジスターに全体で一つの役割を割り当てることはありません。依存検出は有界で不完全であり、すべてのインタープリターを手動ヒントなしで復元できる保証はありません。

通常の自動検出フィールドの射影も、遷移先ノードの要求に限定します。定数でないフィールドをエッジの有限値の同時関係に含めるのは、遷移先がそのフィールドを要求する場合だけです。手動フィールドと、自動的にコンテキストキーへ昇格したフィールドは、引き続き全体で射影の対象になります。既知の定数バイト、関数入口のフレームに相対的な正確なポインター、および由来の情報は、要求の有無にかかわらず保持します。これにより、異なるハンドラー段階の無関係なフィールドが値の組み合わせを乗算的に増やすことを防ぎます。設定された予算と、制御の遷移先、メモリーアドレス、戻り時の状態に必要な証明条件は変わりません。

通常の自動フィールドでは、各組の列は要求されたビットだけを制約し、対応するマスクを持ちます。合流では、すべての流入経路で制約されているビットだけを保持します。同じバイト内の他のビットは実行時の値のままです。フィールドの格納範囲は、その範囲全体について完全な有限値域が証明されたことを意味しません。バイトを定数にできるのは、8 ビットすべてが定数であると証明された場合だけです。

手動フィールドとコンテキストキーへ昇格したフィールドは、引き続き全体で全幅の関係の証明を先に試みます。その証明で結論が得られない場合は、要求されたビットの関係だけを保持できます。未証明のバイトをコンテキストキーへ渡したり、使い切った全体予算を回避したりはしません。

新しいグラフで解析を再開するとき、他のフィールドに完全に含まれる通常の自動格納範囲は、その広いフィールドを共有できます。元の段階の位置とビット要求は変わりません。手動フィールド、コンテキストフィールド、未解決のメモリーアドレスから直接候補になったフィールドは、正確な範囲を保持します。`MaxControlFields` は、この正規化後に実際に保持するフィールド数を制限します。`DiscoveredControlFields` は累積値のままで、有効なフィールド数を超えることがあります。フィールド数の上限と全体の処理予算は引き上げません。

完全な有限値域の証明が得られた通常の自動フィールドについては、すべての生産側入力を直ちに制御フィールドへ追加しません。検出処理はこれらの依存候補を記録し、復元がなお阻まれ、直近の精密化で候補が得られない場合にのみ有効化します。コンテキストキーへ昇格したフィールドは、引き続き生産側の依存を直ちに展開します。検出の訪問数、再解析、証明処理には従来の累積予算を適用します。

試行が失敗して通常の候補選択を終えた後、有界の逆向きワークリストが、観測済みのネイティブ制御遷移を通じて未処理の正確なビット要求を伝播します。共通のスカラー評価器を再利用し、現在の制御フィールドが保持する範囲だけを扱うため、フィールドやコンテキストは追加しません。古いグラフは候補の伝播経路にのみ使用し、その値や経路の実行可能性を新たな事実として取り込みません。先行ノードの走査、再実行、依存関係の検出は累積作業予算を共有します。これにより、長い連鎖でもネイティブ段階ごとの完全な再解析を避けて要求を伝播できますが、公開には新しいグラフでの完全な固定点証明が必要です。

完全な有限値域からは、ワード全体の値が変化していても、個々のバイトが定数であることを証明できます。例えば、値域 `{0, 0x100}` の最下位バイトは常にゼロです。列挙されたすべての組で等しいバイトだけを、対象のバイト順に従って定数として保持し、他のバイトは動的なまま残します。不完全な列挙、ソルバーの不明という結果、証明予算の枯渇から、このような事実を得ることはありません。

有限値域の証明は、精密化による再解析を含む 1 回の復元処理内で再利用できます。有界キャッシュは、自由変数の一貫した名前変更を許しつつ、完全な順序付き式 DAG を比較します。変数の共有関係、幅、定数のビット、演算子の付加情報、射影上限はキーに残ります。完全な値域と、値域が上限を超える証明だけを保存します。不明または部分的な結果は保存せず、未ヒットや容量不足では通常の証明経路を使います。全体予算はすべて引き続き適用し、`solverQueries` は実際のソルバー呼び出しを数えます。

同じ述語の下で到達可能性が証明されていれば、値が変化する 1 列の完全な値域と、他の各列について証明された唯一の値から、正確な同時関係を決定できます。複数の列が変化する場合は、引き続き同時の証明が必要です。マスクされた列がその全ビット値域を覆う場合でも、入力ビットが述語および他の全列から独立していると証明した場合だけ省略できます。共有入力、不明な結果、不完全な列挙から直積を仮定することはありません。

既定値は手動・自動フィールド合計で `MaxControlFields = 16`、`MaxControlRefinements = 16`、`MaxDiscoveryVisits = 65536` です。再解析は全体のノード数（合成ノードを含む）、操作数、評価数、求解回数、検出訪問数の予算を共有します。`contexts` はネイティブコンテキスト数であり、`evaluatedOperations`、`nodeEvaluations`、`solverQueries` と同様に試行間で累計します。アドレスごとのコンテキスト数、使用中のネイティブ復帰スロット数、フィールド数、組の数は各試行内の構造上限です。求解回数の既定上限は 4096 のままです。予算切れで部分結果を公開せず、`residualBlocks` は最終残余グラフだけを表します。

CLI オプション `--vm-max-refinements=N` は正の整数を要求し、既定値は 16 です。C の呼び出し側は `neverd_devirtualize_source_v2()` または `neverd_devirtualize_machine_source_v2()` で同じ上限を設定できます。`neverd_devirtualize_options_v2` をゼロ初期化し、`base.struct_size = sizeof(neverd_devirtualize_options_v2)` と `max_control_refinements` を設定します（ゼロなら既定値 16）。埋め込まれた `base` に v1 のオプションを保持し、2 つの reserved メンバーはゼロのままにします。既存の v1 レイアウトと入口は変わらず、拡張末尾を無視します。他の処理予算と証明予算も引き続き適用されます。

`--vm-max-fields=N` と `--vm-max-queries=N` は制御フィールド数とソルバー問い合わせ数の上限を設定し、既定値は 16 と 4096 のままです。これらと `--vm-max-refinements` は正の 32 ビット十進整数と `--devirtualize` を必要とし、ゼロ、符号、十六進数、末尾文字、桁あふれを拒否します。両方のソース ABI とバックエンドに同じ上限が適用されます。予算の増加は解析量を増やすだけで、制御ヒント、実行時入力、新たな証明保証を与えません。予算超過時は C を公開しません。

C では `neverd_devirtualize_source_v3()` または `neverd_devirtualize_machine_source_v3()` を使用します。`neverd_devirtualize_options_v3` をゼロ初期化し、`base.base.struct_size = sizeof(neverd_devirtualize_options_v3)` を設定します。`max_control_fields`、`max_solver_queries`、必要なら `base.max_control_refinements` を指定し、ゼロは従来の既定値を選択します。3 個の reserved フィールドはすべてゼロにします。v1/v2 は reserved を含む v3 末尾を無視し、v3 は将来の拡張末尾を無視します。レポートは実際の処理量と有効な `maxControlFields`、`maxControlRefinements`、`maxSolverQueries` を記録します。

復元では `--vm-chain-transfers=N`（既定値 0）と `--vm-no-control-discovery` も指定できます。連鎖は単一ターゲットが証明された制御転送間で記号的な相関を保持し、上限で通常の CFG 境界に戻ります。マシン状態復元では `--vm-entry-frame=begin:end` で、実行時には検査しない非ラップの入口 RSP オフセット範囲を宣言できます。正確な数値前提は生成 C とレポートに残り、メモリアクセスや等価性の証明を与えません。

SSA 構築の上限を超える大規模な復元関数は、`--llvm` で有界なスカラー可変ストレージ契約を使用できます。入口の入力、ループで引き継ぐ値、過去の読み取りの意味を保持します。未対応の暗黙状態、ベクトルレジスター引数、イメージ再配置、曖昧なストレージ、不正な制御フローは明示的に失敗し、HighC はこの代替経路を拒否します。ソース出力は既存のマシン状態契約に従い、等価性証明書は追加しません。

可変ストレージの部分集合は 8/16/32/64/128 ビットのスカラーに対応し、ビットカウントの入力は最大 64 ビットです。非標準幅やそれ以上の幅には別のソース契約が必要です。

検証済みの可変変数を持つ関数本体では、LLVM は命令を末尾に追加する同一基本ブロック内で私有スロットの正確な値を転送し、最後の書き込みを残します。入口の初期化とブロック・関数・モジュールの境界は分離され、対象プログラムのメモリアクセスは明示的に保持されます。C 出力はスカラー式の展開と即値の畳み込みの処理量を制限し、名前付きの中間値を残します。畳み込み可能な定数式には LLVM のターゲットレイアウトを使い、未対応の式は明示的に拒否します。指定された可変戻り値は、ゼロでも void に変更しません。

互換 v4 API は `neverd_devirtualize_source_v4()` と `neverd_devirtualize_machine_source_v4()` です。`neverd_devirtualize_options_v4` をゼロ初期化し、`base.base.base.struct_size` に構造体全体のサイズを設定します。CLI の連鎖数は非負の 32 ビット十進整数で、ゼロは無効化を意味します。範囲端点は符号付き 64 ビット十進整数で、`begin < end` と `--vm-machine-state` が必要です。制約は調整後ではなく物理的な入口 RSP に適用します。C で範囲フラグを使うにはマシン状態 API が必要で、フラグがなければ両端点はゼロです。不明なフラグと旧予約フィールドの非ゼロ値は拒否します。v1/v2/v3 は v4 拡張全体を無視し、v4 は将来の拡張を無視します。null オプションは従来の既定値を維持します。レポートは `maxChainedTransfers`、`entryFrameBounds` と実際の `discoverControlState` を記録します。全 CLI オプションには `--devirtualize` が必要です。数値前提は実行時検査ではなく、アクセス可能性、初期化、非エイリアスを保証しません。ネイティブ証明ポリシーも有効にしません。

```c
neverd_devirtualize_options_v4 options = {0};
options.base.base.base.struct_size = sizeof(options);
options.base.base.base.use_llvm = 1;
options.max_chained_transfers = 64;
options.flags = NEVERD_DEVIRTUALIZE_V4_DISABLE_CONTROL_DISCOVERY |
                NEVERD_DEVIRTUALIZE_V4_HAS_ENTRY_FRAME_BOUNDS;
options.entry_frame_begin = -256;
options.entry_frame_end = 8;
const char *report = NULL;
const char *source = neverd_devirtualize_machine_source_v4(
    session, entry, &options, &report);
neverd_free_string(source);
neverd_free_string(report);
```

マシン状態の復元では `--vm-entry-alignment=A:R` により入口 RSP の合同条件を明示し、実行時に検査できます。`A` は正の 2 の累乗、`R < A` が必要です。他の入口はゲストメモリアクセスや状態書き込みの前にステータス 2 を返します。アドレス上位ビットは自由で、既定では整列を仮定しません。これはネイティブ等価性の認証ではありません。

v5 C API の `neverd_devirtualize_source_v5()` と `neverd_devirtualize_machine_source_v5()` は v4 に `entry_frame_alignment` と `entry_frame_residue` を追加します。`neverd_devirtualize_options_v5` をゼロ初期化し、`base.base.base.base.struct_size` に構造体全体のサイズを設定します。整列値 0 は無効化を意味し、剰余も 0 が必要です。非ゼロの整列指定はマシン状態 API のみが受け付けます。v1–v4 は新しい末尾を、v5 は将来の末尾を無視します。レポートの `entryFrameAlignment` と生成 C は同じ検査条件を記録します。整列違反の拒否は入口フラグ違反より先で、状態は変更されません。既存の数値フレーム範囲は引き続き未検査です。C++ の残余グラフ利用者は RSP 条件を自ら保証する必要があります。ソースとモデルは同じガード生成器を使い、ネイティブ証明 API は契約にこの領域を結び付けられるまで指定を拒否します。

`--vm-max-symbolic-nodes=N` と v5 の `max_symbolic_nodes` はノード単位のシンボリック DAG 予算を指定します（既定 262144）。CLI は正の 32 ビット十進整数を要求し、C のゼロは既定値を選びます。両ソース ABI に同じ制限が適用され、`maxSymbolicNodes` に実効値を記録します。増額は意味論上の仮定や証明を追加しません。

`--vm-external-stores-disjoint-frame` は機械状態の復元に、実行時に検査しない明示的前提を追加します。外部 STORE の全範囲は `--vm-entry-frame` と重なってはなりません。その範囲内の既存の事実だけを保持します。LOAD や外部ポインタ間の別名関係には制約を加えず、既定の処理は保守的です。ネイティブ証明 API はこのドメインを拒否します。

v6 API `neverd_devirtualize_source_v6()` と `neverd_devirtualize_machine_source_v6()` は変更のない v5 オプションを内包します。`neverd_devirtualize_options_v6` をゼロ初期化し、`base.base.base.base.base.struct_size` に全体サイズを設定します。機械状態ソースと v4 の入口フレーム境界を使用する場合に限り、`flags` の `NEVERD_DEVIRTUALIZE_V6_EXTERNAL_STORES_DISJOINT_ENTRY_FRAME` を有効にします。通常ソースはこのフラグを拒否します。v1–v5 は拡張を、v6 は将来の末尾を無視します。レポートの `externalStoresDisjointEntryFrame` と生成 C は未検査の契約を明示します。フレーム由来または出所不明の書き込みは対象外です。完全なアフィンポインタの保存領域は全体が保護範囲に収まる必要があります。既存の事実の走査・保存・復元は共有操作予算を消費し、枯渇時は C を公開しません。

v7 API の `neverd_devirtualize_source_v7()` と `neverd_devirtualize_machine_source_v7()` は、変更のない v6 接頭部に `max_node_evaluations` と `max_discovery_visits` を追加します。ゼロは既定の 16384 回の評価と 65536 回の依存走査を選びます。`neverd_devirtualize_options_v7` 全体をゼロ初期化し、`base.base.base.base.base.base.struct_size` に完全なサイズを設定します。v1–v6 はこの拡張を無視し、v7 は将来の末尾拡張を無視して既存の検証を維持します。Python は対応する `abi.NeverDDevirtualizeOptionsV7` の配置と型付き関数を公開します。`--vm-max-evaluations=N` と `--vm-max-discovery-visits=N` は `--devirtualize` と正の 32 ビット十進数を要求し、4294967295 も受理します。レポートには有効な `maxNodeEvaluations` と `maxDiscoveryVisits` を記録します。これらの累積作業上限は意味論上の前提を変えず、予算による拒否時は C も復元証拠も出力しません。

v7 の `flags` は `NEVERD_DEVIRTUALIZE_V7_STOP_CHAIN_AT_REPEAT`（Python: `DevirtualizeFlagsV7.STOP_CHAIN_AT_REPEAT`）も受け付け、CLI では `--vm-chain-stop-at-repeat` に対応します。単一の転送先が証明された通常のチェーンで、同じネイティブアドレスとデコードモードの転送先を再訪する直前にチェーンを終了し、通常の辺射影に戻します。ループ展開を減らせますが、後続の制御解決に必要な相関を失い、従来成功した復元を拒否する場合があります。フラグの既定値はゼロで、チェーン上限がゼロなら効果はありません。依存関係の再実行は確定済みの命令出現順を維持します。両方のソース ABI は `stopChainingAtRepeatedDestination` を報告し、未知の v7 フラグを拒否します。この戦略は意味的な前提を追加せず、未解決の制御を含む出力を許可しません。

`--vm-chain-visits=N` はチェーン内のネイティブアドレスとデコードモードごとに、非負の32ビット訪問上限を追加します。開始位置と連鎖する転送先を数え、順次フォールスルーは数えません。0は追加上限なしです。`--vm-chain-stop-at-repeat` は引き続き、より厳しい1回の上限を優先します。総チェーン上限が0なら両方とも無効です。v8 C API は `neverd_devirtualize_options_v8` を使用し、ゼロ初期化後に `base.base.base.base.base.base.base.struct_size` を全体サイズに、`max_chained_visits_per_destination` を指定値に設定します。`reserved` は0が必須です。v1–v7はこの拡張を無視し、v8は将来の末尾を無視します。Pythonは `NeverDDevirtualizeOptionsV8` を公開します。レポートには `maxChainedVisitsPerDestination` と `effectiveChainedVisitsPerDestination` を記録します。`--devirtualize` が必要であり、解析精度と作業量だけを変え、意味的な前提は追加しません。

有限の複数ターゲットを持つ間接ディスパッチも、遅延ガード依存関係を保持します。合流後の集合が有限でも、実行不可能な分岐が含まれる場合があります。失敗後の逆探索は、新しいフィールド・コンテキスト・生成元要求ビットを追加できないガードを通過し、有用な外側のガードを探します。候補選択と有効化は同じ規則と探索予算を使います。候補自体は辺を除去せず、公開には到達可能グラフ全体の再証明が必要です。 有限ディスパッチの依存関係の走査は、既存の精度改善が停滞してから開始します。有効化は同じ累積作業上限内で新たな改善を1回消費し、無関係なセレクターが既存の生成元やネイティブガードの改善予算を先に使わないようにします。 ガード候補を使い切っても、遅延した生成元や他の精度改善は継続できます。失敗の解消には新たな証明が必要です。

制御状態とガードの精度改善を、任意のフレーム分割の再試行より優先します。必要な細分化は引き続き利用できます。各剰余の不動点を順番に計算しますが、結果公開には許可された全剰余の完了が必要です。入口整列条件と分割領域の共通部分を使い、分岐は実際の剰余を比較します。コンテキスト、操作、ノード、ソルバーの予算は再試行を通じて共有されます。

未解決の間接分岐先は、ガードの精度低下によって生じることがあります。分岐先と遅延した生成元の精度改善で候補が増えなくなった後、失敗箇所に到達する最も近い未確定ガードを調べます。候補選択と再試行は探索と精度改善の予算を共有します。分岐を除外できるのは新たな完全証明だけです。実際に到達可能な未知の分岐先は引き続き失敗となり、残余コードや証明の証拠を公開しません。

制御の要求が入口を基準とするポインター関係を必要とする場合もあります。後続ノードが要求した完全な64ビットレジスターについては、整列マスクがなくても、その辺の条件の下で入口の基準アドレスからの変位を証明できます。一意な全幅の結果だけをその辺の射影に保持し、不明な結果から事実を追加しません。合流では矛盾する変位や一方に存在しない変位を削除し、物理的な基準アドレスの値は固定しません。

64 ビット以下の加算では、有界な構造マスクによって、各加数で 1 になり得るビットが互いに重ならないことを証明できます。その場合に限り、上位の制御スライスから下位の桁上がり依存を除外できます。検査はワード全体の定数と全加数を含みます。不明な形状、重なるビット、より広い加算では、下位ビットのプレフィックスを保守的に保持します。マスク検査も依存探索の作業量に計上し、予算を使い切った場合は候補もルートからの独立性も公表しません。有限領域や制御先の証明を置き換えるものではありません。

選択した制御ワードに有限のセレクターと広いデータ領域またはアドレス領域が混在する場合、復元処理は要求マスク内で 32、16、8 ビットの窓を試せます。自動検出では実際の利用側の要求を待ち、検出を無効にした場合は手動ヒントも対象になります。投影済みのバイトと、入口フレームルートからの独立性を確認できない候補は除外します。任意の依存走査ごとに `MaxSymbolicNodes` の処理上限を設け、累積の `DiscoveryVisits` とは分けます。有限性の証明はすべて既存の問い合わせ予算を共有します。証明した定数バイトを保持し、それらが選択マスク全体を覆う場合は探索を続けます。残る候補のうち最初に完全な有限域を証明できたものを元のビット位置で保持し、他のビットは実行時データのままです。部分的な証明の後も、元の生成側要求は即時処理の対象です。後から合流する経路は、矛盾する事実や欠けた事実を無効化します。この有界探索は有用な部分フィールドをすべて発見する保証ではありません。

JSON レポートには `discoverControlState`、`maxControlRefinements`、`maxDiscoveryVisits`、`discoveredControlFields`、`discoveredContextFields`、`controlRefinements`、`discoveryVisits` が追加され、有効な動作、上限、解析作業量を記録します。フィールドの検出だけでは復元成功を証明しません。

条件によってアドレス依存がバイト部分に狭まる場合、細分化は、その部分を包含する追跡済みの完全な8バイトの直接アドレスフィールドもコンテキスト候補に保持します。元の狭いフィールドと生成元ビットマスクは変更せず、無関係な広いフィールドは昇格しません。定数と入口相対オフセットには引き続き証明が必要で、全コンテキストは既存の上限を共有します。

任意の不変アドレス列挙は、証明書のない実行可能アドレスが見つかると停止し、元の実行時読み取りを保持します。観測した値と証明書は、完全な領域が証明された後にのみ使用します。キャッシュ命中時も現在の読み取り範囲を再検証し、実際に観測した不正な証明書はエラーになります。

現在の述語が、実際の `MaxControlTuples` または `MaxImmutableReadAddresses` の上限を厳密に超える値を許すと証明できる場合、復元は完全な 64 ビットの `root + constant` 制御値または不変読み取りアドレスの任意列挙を省略できます。証明は宣言された非ラップのフレーム区間を考慮し、下位 32 ビットを固定した各剰余に対して上限を超える数の根が必要です。依存関係の走査で除外するのは、その境界と完全一致する最上位の論理積項だけです。残りの全項は新しい根変数の上位 32 ビットを制約してはなりません。より強い制約、未対応の依存関係、作業予算の枯渇では通常の求解に戻ります。

各証明は境界照合と依存関係走査で一つの `MaxSymbolicNodes` 作業予算を共有します。経路述語が変われば再証明が必要です。この列挙の省略は入力を固定せず、到達可能性も証明しません。実行時読み取り、狭い生成元マスク、不変読み取りの証明書、最終的な実行可能性検査は引き続き必要です。

有限射影は、部分的に制約されたシンボリック入力内の独立ビットも保持できます。64 ビット以下の変数では、共通の依存関係走査が現在の述語と元の各 `RelatedValues` 出力のビット要求を合併します。出力への厳密なビット対応で保持され、この合併に含まれない異なるソースビットだけを値の個数の下界に数えます。桁上がり依存と反復する符号ビットは保守的に扱い、関連出力を論理積に置き換えることはありません。全く現れない変数は、より広いソースの狭いビューも含め既存の高速経路を維持します。すべての根、オペランド走査、ビット走査は `MaxSymbolicNodes` を共有し、不完全な証明では通常の求解に戻ります。この純粋な式モードは機械位置を候補化せず、状態の由来検査を変更しません。

有限証明キャッシュが容量に達すると、単独で収まる有効な証明で最も長く使われていない記録を置き換えます。ヒット時は使用順を更新しますが、重複した保存、ミス、拒否された候補では更新しません。追い出された証明は再度確立する必要が生じます。保持するのは完全な値域または値域上限の超過を証明した結果だけで、新たなソルバー呼び出しはすべて共有クエリ予算を消費します。

復元では、マスク付き制御フィールドごとに完全に証明された有限値域も保持します。結合関係が `MaxControlTuples` を超えても、独立した値域でターゲットを制約できますが、フィールド間の相関は仮定しません。合流では共通マスクを適用した値の和集合を取り、欠落または上限超過の値域は全体を破棄します。結合関係が既に拡大されていても、値域が変わればノードを再処理します。部分列挙は事実として使わず、既存のフィールド数、タプル数、シンボリックノード数、ソルバーの上限を維持します。

生成元、条件、レジスタ、フレームの精密化に候補がなくてもターゲットが未解決の場合、失敗ノードの観測済み先行ノードを調べ、その入口で確定済みの要求ビットを持つ追跡済みレジスタまたはフレーム領域を一つだけコンテキスト候補にできます。この有界フォールバックは手動指定、既存コンテキスト、関数入口の入力を除外し、成功する試行には追加走査を行いません。新しいグラフで、キーに使う完全な定数または正確なフレーム変位を再証明します。部分的な値と後から現れる未知の先行状態は保守的に扱い、不変読み取りの証明も引き続き必要です。探索訪問数、精密化、ノード、コンテキストの予算は共有されます。

`MaxChainedTransfers` は明示的に有効化する C++ の上限（既定値 `0`）です。ターゲットまたは真偽値が一意と証明された制御移送を連続して処理し、完全なシンボリック状態、ネイティブ由来情報、累積予算を保持します。複数の結果がある場合は通常の CFG エッジを使います。逆方向の探索は確定済み命令の出現順に再生します。連結によってループの由来が重複し、自動カットポイント推論が制限されることがあります。

`EntryFrameBounds` は `FrameBaseRegister` の入口値を基準に、回り込みのない `[Begin, End)` を明示します。メモリアクセスや非エイリアスの事実は与えません。省略時の根は剰余算術の領域に残ります。ネイティブ証明は呼び出し側のフレーム境界との一致を要求し、証拠に結び付けます。LLVM 証明は同じフレームの既存領域を保持します。復元だけでは等価性証明になりません。

## 実行契約

現在のバイナリアダプターは、マッピングされたアドレスにあるリンク済み x64 ELF / PE イメージを受け付けます。マッピング、バイト列、アクセス権は固定され、並行して変更されないことが必要です。到達可能な機械語を厳密にオンデマンドでリフトします。未対応の命令、呼び出し、不透明な操作、メモリ順序を伴うアクセス、未解決の制御フロー、言語レベルの例外処理に遭遇すると復元を停止します。

PE の復元には、イメージ全体の再配置情報と例外レコードを含む完全なメタデータが必要です。CLI はこれらを読み込んでから `--func` を適用します。C API の呼び出し側は、先に `neverd_session_restrict_function()` でセッションを制限してはいけません。省略したメタデータから修正箇所や例外エッジの不在は証明できないため、バイナリアダプターは関数集合を限定してロードしたイメージを拒否します。

以下の PE 証拠がない場合、イメージの読み取りを定数とするには、その範囲全体がファイルに裏付けられた読み取り専用領域であり、マッピングの重複やローダーによる修正がないことを確認できなければなりません。書き込み可能な表、未解決の再配置、実行時に採取したスナップショットは、不変の読み取りを示す証拠にはなりません。COPY 再配置と構造が不完全な例外ディレクトリは拒否します。PE のディレクトリと関数範囲が完全なら、別の関数にある未解読のハンドラーは現在の入口の解析を妨げません。ただし、そのハンドラーが覆うコードに到達すると回復を拒否します。

`PEFixedImageView` は優先ベースアドレスで完全な x64 PE イメージを認証します。生のヘッダー、一意なマッピング、完全な DIR64 フィールド、通常のインポート書き込み範囲を検証し、IAT バイトは除外します。TLS、load-config、遅延／バインド済みインポート、CLR、未知の書き込み機構は拒否します。回復とネイティブ／LLVM 証明は同じスナップショットに結び付きます。C++ の `MaxImagePreparationBytes` と `MaxImagePreparationRecords` の既定値は 64 MiB と 65536 で、超過時は `BudgetExceeded` を返します。使用中のイメージは変更できません。ASLR、初期化、アンパックの等価性は証明しません。

整列フレームの回復では入口ルートの下位ビットの全剰余を分割し、上位ビットは自由のまま保ちます。明示的な入口分岐を生成し、一定変位を証明してから元のルートのシンボリックメモリ領域を共有します。スピル、エイリアスによる無効化、コンテキスト結合は分割の識別を保持します。候補は小さい順に試すため、無関係な大きなマスクが最大分割を強制しません。コンテキスト数と精密化回数が分割と再試行を制限し、ノード、操作、評価、ソルバー照会は累積計上します。分割間や重複するループ起点を扱う自動 native/LLVM 証明集約は未実装です。既存の検査器は実際の経路述語から導かれる変位を証明できます。明示的な物理スタック意味論では、正規エンコードの内部 `RET imm16` は旧戻り先スロットを読み、RSP に八バイトと符号なし解放量を加えます。外側の戻りは解放量ゼロに限り、接頭辞付きの戻り命令はこの投影で拒否します。

反復転送は、回数と方向を完全に証明した場合に、64 ビットアドレスと 1/2/4/8 バイト要素を扱います。明示的なマシン状態では回数ゼロはメモリにアクセスせず、方向の証明も不要です。通常 ABI は未束縛フラグを引き続き拒否します。各スカラーアクセスには通常のエイリアス検査と戻りスロット検査が適用されます。完全にコピーされたフレームポインターは、辺の射影前に実際のメモリから再証明します。不明な回数、予算超過、セグメント付きアクセス、狭いアドレス幅は拒否します。これらの元 REP 命令のネイティブ未定義効果認証は未対応です。

ソース復元の対象には通常の ABI による復帰が必要です。外部由来のアドレスを使うすべてのストアについて、書き込み先の範囲が入口の戻りアドレススロットと重ならないことを要求します。これは呼び出し元／実行環境が満たすべき明示的な前提であり、外部の整数から計算したアドレスも含みます。フレーム由来の情報がないだけでは、数値アドレスが重ならないことを証明できません。フレームから派生したストア先は、このスロットと重ならないことを証明する必要があります。また、復帰時には元のスタックポインターに戻っていなければなりません。由来の情報は退避・再読み込みや合流を越えて保持され、アフィン式が失われても外部ポインターとして扱い直すことはありません。スタックの切り替え、呼び出し先が余分にスタックを解放する復帰、RET によるディスパッチは現在拒否します。バイナリアダプターは x64 のリトルエンディアン意味論を適用します。

この処理が生成するのは解析用のソースと IR です。再配置、アンワインド、非同期例外、バイナリ置換の安全性を保証するものではありません。patch モードではこのオプションを拒否します。すべてのインタープリターや保護設定への対応を意味するものでもありません。

形状が厳密に一致する x64 の `PUSHFQ`／`POPFQ` は残余プログラムに保持します。解析では機械フラグの各スナップショットを未知の実行時値とし、リフターが別途モデル化した算術フラグを合成します。フラグの復元も実行時の作用として残ります。未知のフラグに由来するアドレスに外部ポインターの戻りアドレス領域非重複契約は適用できず、派生するディスパッチ先が有界と証明できなければ復元は失敗します。

フラグ全体を保存する前に、モデル化された算術フラグと方向フラグのすべてが復元対象の関数内で定義されている必要があります。フラグを直接読み取る場合も、記号的な簡約で値が相殺されても、到達可能なすべての先行経路で定義されていなければなりません。そうでなければ、未知レジスターのトラップを含む C ソースを出力せずに復元を拒否します。

LowIR の一時値は、リフトした各ネイティブ命令内だけで有効です。読み取る各バイトは同じ命令内で先に定義されている必要があり、前の命令で使ったオフセットや、未定義値が代数的に相殺されることはソースの正しさの証拠になりません。入口定数で束縛できるのは物理レジスターだけです。

## 明示的なマシン状態の復元

```sh
neverd decompile program --func entry --devirtualize --vm-machine-state \
  --recovery-report machine-report.json -o machine.c
```

`--devirtualize --vm-machine-state` または `neverd_devirtualize_machine_source_v1()` は専用のソース ABI を選択します。引数は整列した 17 個の `uint64_t`（RAX、RCX、RDX、RBX、RSP、RBP、RSI、RDI、R8〜R15、RFLAGS）へのポインターです。64 ビット符号なし戻り値がゼロの場合のみ成功です。非ゼロではメモリ書き込みを取り消しません。状態は最後の RET が戻り先を取り出す直前です。状態領域はゲストメモリと重複できず、元のマッピングと 64 ビットリトルエンディアンホストが必要です。

元のゲストコードとデータのアドレスは、出力レジスターで観測されるものも含め、正確な数値を保持します。ソース生成によって生成プログラムのグローバルオブジェクトのアドレスへ置き換えてはなりません。必要な元のゲストマッピングは呼び出し側が用意し、C の生成はゲストアドレス空間の再配置を行いません。証明と復元レポートは引き続き元の入力イメージを参照します。

条件は CPL3/IOPL0、シャドウスタック無効、非同期イベントなし、通常の非フォールト実行です。入口フラグは正規値で TF/RF/VM/AC/VIF/VIP がゼロ、POPFQ では TF/AC がゼロであることを生成ソースが確認します。PUSHFQ/POPFQ は明示状態を使用し、RDSSP は宛先を保持します。到達した INCSSP は拒否します。完全なフレームポインター保存は伝播でき、部分書き込みや別名の可能性で無効になります。例外メタデータを持つコードも通常経路のみ対象で、例外配送・アンワインド等価性は保証しません。報告の `sourceABI` と `executionProfile` に条件を記録し、既定 ABI の厳格な規則は維持します。

この機械状態 ABI は直接 near CALL と、有限の宛先集合を網羅的に証明できるレジスター間接 near CALL を扱います。レジスター間接呼び出しは RSP の変更前に元の宛先レジスターを取り込み、実際の次命令アドレスを一度だけ書き込みます。内部 near RET は完全に証明された有限宛先集合から選択できます。残余コードはゲストスタックを一度読み、その値を保持してからスタックポインターを増加させ、保持値で分岐します。保存された入口の戻りスロットに到達すれば、内部フレームを破棄した後でも外側への終了です。未知の宛先、欠落または実行不能な宛先を含む集合、引数を追加でポップする外側への戻り、任意のスタック切り替えは拒否します。

メモリー間接 near CALL も、この明示的機械状態 ABI、シャドウスタック無効、通常の非フォールト実行という条件でのみ対応します。メモリーオペランドはセグメントオーバーライドのない正規の `r/m64` 符号化に限定し、アドレスサイズオーバーライド（`addr32`）と REX は任意です。共通の x64 実効アドレスと LOAD の意味論で宛先を読み、その後に RSP を変更して実際の次命令アドレスをプッシュします。プッシュが宛先スロットを上書きする場合も同じ順序であり、スロットのアドレスを読み込んだ呼び出し先と取り違えません。読み取り専用のポインタースロットや有限テーブルには不変読み取りの証拠が必要で、初期化が証明されたゲストスタック値にも完全な有限宛先の証明が必要です。書き込み可能スロットの初期イメージや実行時スナップショットは不変性の証拠ではありません。未証明の外部読み取り、失効したスタックの事実、不正な宛先、FS/GS などのセグメント指定、far CALL、余分または非正規のプレフィックスは拒否します。既定のソース ABI は引き続きネイティブ呼び出しを拒否します。

既定の通常ソース ABI は呼び出し専用のフレームを再構築します。外部由来のすべての LOAD/STORE 範囲（計算したアドレスを含む）は元の専用フレームおよび再構築後のソース側ストレージと重複しないことが明示的な前提です。共有証明はフレームアドレスの流出、アドレスに依存する結果や分岐、未初期化バイトの読み取りを拒否します。明示的マシン状態 ABI は元のゲストアドレスを保持し、この専用フレームの前提を使用しません。

未定義フラグが制御フロー、アドレス、または定義済みの出力に影響する場合、それらへの非干渉を別途証明する必要があります。現在の復元レポートはこの証明を提供せず、プロセッサ依存の動作を保証しません。

`modelInterpreterMachineStateX64` はソースラッパーと同じ生成器から `InterpreterMachineStateModel` を返します。レジスタバイト `[0, 136)` は生の 17 ワードの状態オブジェクトを表し、`RETURN` はゲスト RAX と別にステータスを返します。ゲストメモリアクセスはメモリアクセスのままです。不正な入口フラグと拒否された動的フラグ書込みは失敗状態を保持します。状態領域にはアクセス可能性、アラインメント、ゲストアクセスとの非重複が必要です。`MaxOperations` は入力メタデータと生成操作を制限します。決定的 LowIR 記録は元のアーキテクチャの未定義出力の証拠ではありません。呼出側は観測、入口・フレーム契約と新しい `checkLowIRLoopRefinement` または有限経路の精化証明を提供する必要があります。モデルや記録の生成はコンパイル済み C を証明しません。

`modelLLVMInterpreterMachineStateX64` は、状態ポインターを一つ受け取り i64 のステータスを返す検証済みスカラー LLVM 関数をモデル化します。`llvmInterpreterMachineStateContract` は全 17 ワードを観測し、独立した `LLVMInterpreterDefinednessOffset` バイトが初期値ゼロを維持することを要求します。入口領域とゲストフレームを追加しても、この義務を保持してください。PHI コピーは並列で、整数オーバーフロー、正確なシフト、値域属性などは検証対象のガードになります。デッドコードや select が [LLVM の意味論](https://llvm.org/docs/UndefinedBehavior.html)で poison を隠せる場合も、実行された対応操作はすべて非 poison である必要があります。`MaxInputItems`、`MaxBlocks`、`MaxOperations`、`MaxWork` が構築を制限します。未対応の型、ポインターの逸脱、メモリモード、呼び出し、属性、メタデータは明示的に拒否します。i8/i16/i32/i64 の可変 `shl`、`lshr`、`ashr` は、ISA のカウントマスクを適用せず、符号なしシフト量がソースのビット幅未満であることを要求します。`nuw`、`nsw`、`exact` は別途検査します。除算と freeze は未対応です。完全な有限経路または帰納的検査を改めて実行し、定義性、メモリ安全性、観測値、停止性を証明してください。自動ループ候補推論は不完全です。ソース、モジュール、コンパイラー入力は別途厳密に結び付けます。パーサーとコンパイラーは信頼前提であり、この API は C、生成機械語、実 CPU の未定義ビット選択を認証しません。契約は [LLVM 言語リファレンス](https://llvm.org/docs/LangRef.html)を参照してください。 読み取る入口バイトは初期化済みで、ゲストアクセスは宣言したフレーム内の生存ストレージを指す必要があります。平坦な LowIR メモリは LLVM オブジェクト寿命やポインター由来を証明しません。

`initializes` は状態オブジェクト内の互いに離れたバイト範囲に限り受け入れます。有界の must データフロー解析により、宣言された各バイトが読み取られる前、および各正常リターン前に、通常のストアで初期化されることを要求します。部分ストアと固定ポインターの別名は同じバイトの事実を共有し、ゲストへのストアは初期化に数えません。入口の初期化済み集合は空なので、後退辺上のストアで初回の読み取りを正当化できません。atomic／volatile アクセスと未知の状態別名は引き続き未対応です。範囲リストの要素は検証前に `MaxInputItems` に計上し、固定点計算は `MaxWork` を共有します。この保守的な検査は経路の相関に依存する有効なコードを拒否する場合がありますが、証明のために属性を削除しません。

`prepareInterpreterLLVMRefinement` は正確な LLVM テキストと選択関数名を保存し、モジュールを検証して、入口で一度だけフラグを正規化する両状態モデルを準備します。`checkBinaryLLVMRefinement` は入力を再構築し、実際のネイティブイメージと同一の残余プログラム、そのモデルと LLVM 成果物の関係を順に証明します。有限経路・帰納検証とも全状態ワード、実際のステータス、定義性、フレーム書込みを観測し、RSP と戻り先スロットの保持を要求します。ネイティブ入口定数をソース契約へコピーせず、ソース側では任意の汎用レジスタと正規フラグの広い領域を検証するため、ネイティブ制約下だけで正しい結果を保守的に拒否することがあります。ループ案は信頼されません。両方の新規検証が成功した場合だけ、正確な IR バイト、関数名、両証明結果、プロファイル版、予算を結び付けた合成証明結果を生成します。

`MaxIRBytes` はコピー・解析前にテキストと関数名を制限し、`MaxMachineStateOperations` と `MaxPreparationItems` はモデル生成と準備作業を制限します。ネイティブと LLVM の証明予算は独立し、自動増加しません。信頼される LLVM パーサー／検証器には、ここでの厳密な CPU・スタック・割当て上限はありません。共通フレームは生の RSP ワードをルートとし、入口の戻り先スロットを含む必要があります。初期化済みで生存するフレーム、アクセス可能で整列し分離された状態領域、有効なゲストポインタの由来が前提です。この C++ API は対応するネイティブから LLVM への関係を証明し、C コンパイル、生成機械語、フォールト、実 CPU の未定義ビット選択は証明しません。

構造化されたマシン状態 C は、通常の return ブロック間で 16 個の GPR 書き戻しを共有できます。パックされたフラグは各 return 経路で書き込み、アラインメント拒否時には書き込みません。状態はネイティブ RET のポップ前に取得し、不正なプロファイルの状態コードは保持されます。LLVM 出力は独自の最適化のため、インラインの return 末尾を維持します。既存の C++ ラッパーとモデルのオーバーロードは `InlineReturns` を維持し、明示的な `InterpreterMachineStateLayout::SharedGPRExit` は両方に同じ意味生成器を使用します。不正なレイアウト値は拒否します。完全な通常の合流や新しいアドレス領域を確保できなければ、従来のインライン形式を維持します。独立したモデル検査と両 C バックエンドの O0/O2 テストは、経路別フラグ、部分レジスタ書き込み、ループ、メモリカナリア、アラインメント拒否を検証します。この圧縮は通常 ABI やネイティブ等価性の証明書を追加しません。

`LowFunc::FunctionTemporaries` は、オフセット順で重複せず、入口で未定義のバイト範囲を宣言します。復元器は有限分岐が命令境界を越える前に、一時的な間接転送先を予約された関数内スロットへ一度だけ保存します。共有関係検査器が保持するのは現在の経路で実際に定義されたバイトだけで、通常のネイティブ一時値は命令ごとに失効します。範囲メタデータと保存処理は予算に算入され、証明書の意味スキーマ 13 が存続期間を束縛します。生の状態モデルはバイト意味論を保持し、ソース生成はスロット全体と一致するオペランドのみ受理してバイト別名を拒否します。切点状態はこれらを束縛しないため、帰納的ループ証明と推論は現在この宣言を拒否します。入口仮定やネイティブ ABI 証明は追加しません。

## 現在の制限

入力依存のバイトコードアドレスやデコーダー状態の関係を扱えるのは、必要な有限の値域と相関を設定された上限内で証明できる場合だけです。任意の間接デコード方式に対応するわけではありません。すべてのディスパッチ先を証明できれば動的分岐やループを復元できますが、通常の分岐テストはすべての方式への対応を示しません。制御フローが未解決の場合や必要な証明予算を使い切った場合は失敗し、復元ソースや部分的な置換コードを公開しません。ネイティブの補助関数呼び出し、例外／再入の境界、変更可能なコード、他のアーキテクチャは対象外です。

## 共通実装

`SpecializationProvider` が完全にリフトされた命令と、不変の読み取りに関する証拠を提供します。`NeverDInterpreterSpecialization` は既存の `SymExec` の意味論を用いて、整数操作と制御操作を部分評価します。バイナリアダプターはマッピングと命令デコードを担当し、別の命令評価器を実装しません。

有限のシンボリック読み取りアドレスに対して、組み込みのビットベクトルソルバーが現在の制約の下で候補を列挙します。最後の UNSAT により他のアドレスが存在しないことを証明し、全候補に不変かつメモリ障害を起こさない読み取りの完全な証拠がある場合だけ、その集合を採用します。このように証明された LOAD は、LowIR でアドレスを一度保存して正確な値を選ぶ SELECT の連鎖に置き換えられます。証明されていない通常の読み取りは動的なままです。一つの採取アドレスで集合全体を代用しません。選択した制御レジスタと入口フレームスロットの有界な組の集合をノード間で保持し、カーソルとデコードキーなどの関係を維持できます。合流と拡大は保守的に行います。部分的な SAT の標本やソルバーの unknown は、アドレスやターゲット集合の完全性の証明ではありません。この機構は任意機能の Z3 バックエンドを必要としません。

ノードはネイティブ命令カーソル、命令モード、選択した制御レジスタおよび入口フレームスロットの定数で識別されます。その他のバイト単位の事実は共通部分を取って合流します。流入する事実が弱まった場合は、そのノードを再評価します。これにより、プログラム本来のループを、観測された反復ごとに展開せず、ループとして残せます。間接ターゲットのすべての到達可能な値は、網羅性が証明された有界な集合に属していなければなりません。解決されたターゲットは、残余コード内の明示的な比較と CFG の辺に変換されます。

動的な操作と通常の load/store は LowIR に残ります。スカラー定数、入口フレームに対するアフィンなポインター、定数であると証明されたフレームのバイトはノード間を伝播できます。その他の式は無制限に展開せず、破棄します。フレームメモリには、既存のシンボリック状態の保守的なエイリアス無効化を適用します。エイリアスの可能性がある未知のポインターへの書き込みは、矛盾する事実を無効にします。スタックスロットを私有領域と仮定したり、未証明の非エイリアス契約によって消去したりはしません。

複製したコンテキストは一意の合成命令ラベルで区別します。元の命令境界は別の由来マップに保持し、元の再配置、例外、ジャンプテーブルの証明情報を新しい命令実体へコピーしません。復元した LowIR は HighC/LLVM の分岐より前で通常の LowIR-to-MedIR 変換に入り、レジスタ、スタック、CFG、SSA、ABI の処理を共有します。HighC 経路でも、復元には MedIR 検証の成功が必要です。

ノード数、アドレスごとのコンテキスト数、操作数、ノードの評価回数、有限ターゲット数の予算で解析量を制限します。予算超過や未対応の意味論がある場合、残余関数は公開しません。制御グラフが完全であることとソース生成の成功は別の条件です。公開 API は両方を検査し、区別して報告します。

有限読み取りアドレス集合、制御値の組、制御フィールド数にも明示的な上限があります。ソルバーへの問い合わせ総数と、各問い合わせのゲート、衝突、伝播、監視リテラル参照の上限で証明処理を制限します。シンボリックノード数にも上限を設けます。JSON レポートにはこれらの予算と `solverQueries`、`relationalWidenings` を含めます。

`AllowOverlappingNativeInstructions` は、有限ネイティブ独立性証明とネイティブから LowIR への精緻化に使う、既定で無効の独立したオプションです。各入口を個別にデコードして検証し、重なる命令バイトは、候補側の読み取りを含む、それまでの全命令および不変読み取りの証拠と一致する必要があります。候補 LowIR のアドレスはラベルであり、バイトの証拠ではありません。`MaxNativeInstructionBytes` の既定値は 1048576 で、新しく取得した各入口の命令全体を、重複バイトも含めて比較前に計上します。予算の枯渇やバイトの矛盾があれば証明書を拒否します。オプションと上限は証明ダイジェストに含まれます。静的 LowIR、帰納的ループ証明および推論では、空のループ計画でもこのオプションを拒否します。厳密な LLVM API と CLI の既定動作は変わりません。

## 証拠とテスト

任意のローカル JSON レポートには、入力のダイジェスト、選択した制御項目、予算、状態、処理量のカウンター、残余ブロック数、元の命令位置、復元で使用した不変のバイトが含まれます。入力由来の情報を含むため、指定されたローカルパスにだけ書き込みます。

公開テストは、独自に作成したレジスタ型のスレッデッドディスパッチとスタック型ディスパッチのマシンを使い、それぞれ算術、分岐／合流、実行時ループのプログラムを持ちます。独立した符号なし演算の参照実装で、戻り値、メモリへの書き込み、桁上がり／借り、出力のカナリアを確認します。復元した HighC と LLVMC は、未定義動作トラップを有効にして O0/O2 でコンパイルし、参照実装と実行結果を照合します。負のケースでは未解決のディスパッチ、書き込み可能なディスパッチ表、非互換のバイト順、例外メタデータ、予算を検証します。

追加の独自の有限アドレス fixture は、入力で選ぶ読み取り専用レコード、相関のあるカーソル／キー制御フィールド、異なる仮想位置で再利用する同じハンドラーを使います。分岐／合流と、実行中のプログラム状態によってレコードを選ぶループを対象にします。独立したネイティブ参照実装は SysV と Win64 の両呼び出し規約を使います。両方の復元 C 経路を O0/O2、未定義動作トラップ、出力カナリアで確認します。読み取りの証拠不足や証明予算不足で部分的な結果を公開してはいけません。

拡張テスト行列では、直接スレッド化ポインターバイトコード、有界なソフトウェア CALL/RET スタックと入れ子の仮想呼び出し、回転するオペコード復号状態を持つループという三つの独立形態を、手動制御ヒントなしで復元することを要求します。ネイティブ SysV/Win64 と復元後の HighC・LLVMC を O0/O2 で独立した数学的参照実装と照合し、出力カナリアも確認します。未知の仮想戻りカーソル、制約のない復号キー、予算切れではソースを公開しません。

別の機械状態行列では、ネイティブ実行と両方の復元 C 経路について、O0/O2 で全 16 汎用レジスター、定義済みフラグ、テスト対象ゲストスタックの全バイトの一致を要求します。レジスター間接 CALL の呼び出し先は宛先レジスターを読み取り、上書きします。戻りスレッド化分岐は既知の宛先を選択します。参照実装は次命令アドレスの実際の保存、フラグ保持、RSP 復元を検証し、期待するコードアドレスはシンボルから取得します。未知・不正な宛先集合や証明されていないメモリー上の宛先はソースなしで失敗する必要があります。これは独自 fixture の検証要件であり、任意の仮想マシンや保護製品への対応保証ではありません。これらの独自 fixture は、ローカルの x64 Linux で上記の検証を通過しています。

公開メモリー呼び出し fixture は、不変の RIP 相対ポインタースロット、入力で選ぶ有限の読み取り専用テーブル、初期化済みで宛先が有限のゲストスタックスロット、CALL 自身のプッシュで上書きされる宛先スロットを対象にします。ローカルの x64 Linux では、この四つの形態それぞれについて 1,024 状態を、ネイティブ実行、HighC、LLVMC の O0/O2 で検証しています。独立参照実装は全 17 状態ワードと 128 バイトのゲストスタックを比較し、呼び出し先が観測する戻りアドレスも含めます。未証明の外部・書き込み可能スロット、別名書き込みで壊れたスタック値、不正な宛先、既定ソース ABI 経由の呼び出しは公開を拒否します。

別の固定アドレス実行回帰では、元の入力イメージのアドレスに書き込み可能なゲストメモリーを用意します。両 C バックエンドは O0/O2 でそのマッピングを読み書きし、出力レジスターで元のゲストアドレスの数値を保持し、隣接カナリアを変更しないことが必要です。生成されたグローバルオブジェクトへの置き換えは、この参照実装を満たしません。これらのローカル検証は任意の VM への対応を意味しません。

専用のテストターゲットは [testing.md](testing.md) を参照してください。

## ループ証明候補の自動推論

以下の前置経路述語を保持する要件は `GeneralizeEntryPrefix = false` の場合に適用します。

`inferLowIRLoopRefinementPlan` は共有シンボリック実行器で予算内のテンプレートを提案します。フィードバック切断点は CFG の全閉路を覆い、拡大は証明済み固定ビットを維持し、保存されない符号なし接頭辞境界を除きます。観測した単位増減カウンタと推論した段階定数から辞書式順位を構成し、増加・減少する入れ子ループを扱います。`OriginalPrefix` と `CandidatePrefix` には `UseEntryPrefix` が必要です。先行切断点の後にある切断点は、実際の入口から別途有限再実行して到達可能な対応接頭辞を取得できます。この証拠は入口領域全体を覆いません。各到達状態がその述語を含意し、入口と遷移の完全な経路網羅が必要です。`inferAndCheckBinaryLowIRLoopRefinement` は完全な復元と一意のネイティブ由来を要求し、元プログラムと候補の完全な検査を独立に再実行します。提案と由来対応は信頼せず、証明書を持てるのは `Refinement` のみです。推論と証明は別々の明示予算を使います。この C++ API は `--devirtualize` で自動実行されません。到達不能な接頭辞、任意の制御対応、探索外の順位形式、C バックエンド等価性、実 CPU の未定義ビット選択は未対応です。

単位カウンターの検出は、既存の全語・ゼロ拡張形式を優先した後、対象外の全ビットを保持するバイト境界の部分更新も認識します。複数カットでは、レーンの端点を除外する条件を、保存済みの具体的な到達状態と現在の全流入状態で証明した場合にのみ提案します。拡大は失敗した条件を削除して再導入せず、既知のカウンター語でも後から別レーンを発見できます。マスクは既存の全語パラメーターを再利用し、全語の順位と状態観測を維持します。共有ノード・クエリ予算と独立した完全精緻化検査は引き続き必須です。

複数カットでは、観測されたカウンター組が失敗するたびに、次の組へ進む前に先頭へ64ビットの定数フェーズを追加した案を試します。両案は個別に `MaxRankCandidates` を消費し、同じクエリ予算を共有します。先頭フェーズはすべての実行可能な遷移で非増加でなければならず、残りの組の厳密な減少を証明できない遷移ではフェーズが厳密に減少する必要があります。非負の差分制約は正の重みの閉路を拒否します。これにより、循環内部の進行義務を維持しながら、順次ループの再初期化後にカウンターを再利用できます。既存のカウンター間フェーズとの組合せも可能です。完全な組は元の全遷移述語で検査し、最終の精緻化チェッカーが提案された順位を独立に再検査します。単一カットの探索には効果のない定数接頭部を追加しません。

単一カット候補は、もともと到達可能な全ブロック内の全循環を覆う必要があります。カットの削除で入口から切り離される循環も対象です。各被覆検査は記号実行前に `MaxCutpointAttempts` を消費します。すべての戻り辺で単位ステップの進行を示すスカラーカウンタを優先します。その後、観測された単位カウンタのタプル候補を最大8個まで、より広いスカラーのガード・境界仮説と1個ずつ交互に試します。残りのスカラー仮説の後、タプル探索を重複なく再開します。この順序は予算上限に依存しません。各タプル試行では保存した完全な安定テンプレートと遷移を復元し、タプル領域の検査失敗はこの候補群だけを無効にします。失敗したスカラーガードでその領域を狭めることはできません。 `MaxRankCandidates`、クエリ、操作、経路の予算は累積されます。提案には完全な refinement 検査が引き続き必要です。 他の分岐が値を保つかリセットしても、カットへ戻る加算漸化式の分岐は構造に基づく拡大を促せます。提案したテンプレートは引き続き全入口・遷移検査を通過する必要があります。

単一カット探索では、一般化テンプレートの実行が保持またはメモリ契約に違反した場合、別の許可されたカットを試します。ループ本体のカットで失われるガード付きカウンター関係を、ヘッダーでは保持できる場合があります。一つの仮説の失敗で全候補を拒否しません。実入口の接頭経路の失敗、不正入力、未対応実行、予算超過は引き続き停止します。`MaxCutpointAttempts` とソルバー問い合わせを含む全計数を共有し、新候補にも完全な証明を改めて要求します。このフォールバックは別の入れ子フィードバック集合を探索しません。

`GeneralizeEntryPrefix` の既定値は `false` で、`UseEntryPrefix` が必要です。既定モードでは、すべての到達で取得した経路述語を保持します。明示的な汎化モードは、経路外の前置状態式を全域の未検証テンプレート関数として扱います。実行可能な両側の証人、実入口と区間の完全な網羅、全レジスタ／フレームの一致、引数の射影、ネイティブ実行条件、拡大した帰納領域での厳密な順位減少が必要です。推論は流入状態が証人の領域を越える場合だけ切点を拡大し、すべての一般遷移を再構築して検査します。最初の証人がゼロ回反復でも、別の入口のループを見落とせません。方針は帰納証明書のダイジェストに結び付きます。

多重ループの推論は、観測した単位増減カウンタと制御述語が参照する不変の前置値との間で、厳密／非厳密な符号なし境界を提案できます。等値による終了も対象です。具体的な入口と流入状態で検査した後、一般流入遷移で成立しない関係を単調に除去します。述語走査とソルバ処理は既存の明示的な推論予算を使い、最終の原プログラム／候補チェッカーがテンプレートを独立に証明します。

入れ子ループの推論は、前置状態の式が一致する場合、キャッシュされたオペランドとカウンターまたは不変の制御入力の等式も提案します。すべての具体的な流入状態を検査し、後の拡大で発見されたキャッシュにも候補を用意し、一般化された流入状態が関係に違反すれば削除します。各ワードは復元可能な独自のパラメーターを保持し、等式は検査対象の述語です。コピーの漸化式は不要な固定ビットの除去を速めますが、意味を仮定しません。

入れ子ループの推論では、変化するビットが最大 16 個のフィールドについて、カウンタの等値・不等値比較を保存する関係も探索します。関係は現在のカウンタと境界値を使い、キャッシュには独立した復元可能な状態パラメータを保持します。入口ガードや定数畳み込みされた初期値により比較が後の拡幅まで現れない場合、新しい候補を追加できますが、拒否・削除された候補は再追加しません。候補は保存済みの全具体到達状態と現在の全入力遷移で成立する必要があります。変数 DAG の走査は切点ごとにキャッシュし、共通の述語予算に計上します。完全なネイティブ経路網羅、全状態の等価性、厳密なランク減少は独立に検証します。 一般遷移後もカウンタの発見を続けます。最初の内側ループの証拠では見えなかった外側カウンタにも、検証済みの境界とオペランドコピーの候補を与えます。拒否した関係は復活させず、単位増減の探索にもシンボリックノード予算を適用します。

入口プレフィックスの再実行は、先のループをさらに展開する前に待機中の分岐を訪問します。別の分岐が任意回数の反復を許していても、短い到達可能な証拠を探索できます。推論と元プログラム／候補プログラムの検査は同じ順序規則を使います。すべての処理は従来の予算に計上され、プレフィックスの証拠は完全な入口網羅、不変条件の保持、停止性の検査を代替しません。

`pairLowIRLoopRefinementPlans` は、明示的な `LowIRLoopCutpointPair` により独立に提案された二つの自己関係計画を結合します。各カット点は一度だけ対応付けます。`SharedInputs` は同じ幅の帰納入力間に等価述語を追加し、検査器が検証できるよう両側の束縛と射影を保持します。他の一時値は独立のままで、候補側の前置入力には `CandidatePrefix` を使い、両方の述語と原側のランクを保持します。`UseEntryPrefix` は両計画で一致する必要があり、どちらかが必要とすれば `GeneralizeEntryPrefix` を有効にします。一時値の定義は重複不可で、使用幅は厳密に一致させます。`MaxMetadata` の既定値は 65536 で、コピー前に構築量を制限します。結果は未検証の提案です。`checkLowIRLoopRefinement` による完全な網羅性、状態とフレームの一致、観測結果、厳密な進捗の独立検査が必要です。この補助 API は証明書を発行せず、CLI の既定値も変更しません。

`inferAndCheckLowIRLoopRefinement` は LowIR ループ間の検証済み関係を探索します。 既定、全分岐アーム、フィルター付き分岐アームの順に計画を試します。同じ候補群の対応付け、すべての異なる候補群の組合せ、候補側の個別循環カットの順です。全分岐アーム案は循環成分内で分岐ブロックの後続となり、出辺が一本のブロックを選びます。フィルターはすべての経路が DFS 後退辺の到達先より前に同じ非終端ノードで合流する場合だけ、その分岐のアームを除外します。終了や境界を含む全後続を調べ、境界だけで合流する分岐は残します。貪欲な追加カットで元々到達可能な全循環を覆います。既定推論の成功を前提にせず動作段階を保持します。`MaxCutSelectionWork` は集合構築と比較を含む共通経路解析を別途制限します。`CutSelectionWork` は失敗時も作業量を記録し、全体の残り `MaxSearchWork` からも差し引かれます。既定と全分岐の選択器は変更しません。成功・失敗をキャッシュし、各側最大三計画、順列は遅延列挙です。追加候補群は同じ側で既に保持するカット集合を省略し、既存計画の候補群番号が後でも同様です。空・重複候補群は記号クエリを使いませんが候補試行に数えます。最大六計画で一つの `MaxMetadata` 枠を共有し、各対応付け構築は別途制限します。 既定の `MaxRankPairingAttempts = 0` は従来の提案順序と計上を維持し、同一オフセット・同一幅のフレーム入力にのみ等式を提案します。有効化すると、通常の対応付けが失敗するたびに、直接のランク入力の対応付け、次にそれと両立するフレーム対応付けとの和集合を試します。両側の空でないランク組は同じ長さで、各成分は完全な `NdVar` の同一性で一意の `Original` 入力を厳密に指し、各側の位置は重複せず、幅は非ゼロかつ等しくなければなりません。定数、式、プレフィックス入力、幅変換は推測しません。和集合はランク対応付けを優先し、どちらかの端点が競合するフレーム対応付けを省きます。通常案またはランクのみの案と同じ対応集合は、完全な検査を再実行する前に省きます。不適格・重複案を含む開始済みの追加試行は、`MaxRankPairingAttempts` と全体の `MaxPairingAttempts` の両方に計上します。走査、比較、格納は `MaxSearchWork` に計上し、二つの作業用対応ベクトルは一試行の `MaxMetadata` 枠を共有します。追加試行数だけが尽きても、残りの全体予算内で通常の対応付けによる証明を続けられます。アフィン関係と任意のフィードバック集合には引き続き明示的な対応付けが必要です。正規の対応付け器と完全な検査器は、呼び出し元の元の監査記録、witness、入口領域、フレーム観測、停止性の証明義務を保持します。`LowIRLoopAlignmentLimits` の `MaxSolverQueries` は失敗も含む全推論・証明で共有され、各呼び出しには段階上限と残り総量の小さい方だけを渡します。`MaxSearchWork`、`MaxMetadata`、`MaxCandidateAttempts`、`MaxPairingAttempts`、`MaxCuts` が探索構築と列挙を制限します。単一試行の予算切れは再試行できますが、全体予算切れは停止します。`Unsupported` は関係が見つからないことを示し、非等価の証明ではありません。新たな検証に成功した `Refinement` だけが証明書を持ちます。CLI の既定動作は変わりません。


整列探索は `MaxCuts` を共通の推論処理へ渡します。入力の検証と完全なフィードバック切断点の選択後、上限を超える集合を記号的な入口探索や拡大の前に拒否します。計画単位の上限であり、`MaxCutpointAttempts` や有効な単一切断点の再試行は減らしません。フィルタ付き候補群の選択コストは計上されたままです。単独およびネイティブ推論の既存の制限は維持され、受理する関係は引き続き完全な検査器を通る必要があります。
