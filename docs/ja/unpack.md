# パックされた実行ファイルのアンパック

`neverd unpack` は、パックされた実行ファイルが自身のアドレス空間内に再構築するプログラムを復元します。入力を有界なゲストプロセスとして実行し、スタブが自ら生成したコードへ制御を渡す箇所を観測して、その時点のイメージを同じコンテナ形式の新しいファイルとして書き出します。仮想化の解除は行いません。保護ツールが仮想化した関数は仮想化されたままです。ビルドには `NEVERD_ENABLE_CPU_EMULATION=ON` が必要です。

## 対応する入力

コンテナ形式はファイルの検証と再構築の方法を、命令セットは転送の判定方法を決め、両者がゲストプロセスのプロファイルを決めます。この表にない入力は、何も実行される前に名前を挙げて拒否されます。

| コンテナ (`format`) | 命令セット | ゲストプロファイル | エントリの根拠 |
| --- | --- | --- | --- |
| PE32+ (`pe64`) | x86-64 | [`windows-pe64-v1`](process-emulation.md) | 実行時の観測 |
| PE32+ (`pe64`) | ARM64 | [`windows-pe64-v1`](process-emulation.md) | 実行時の観測 |
| PE32+ native (`.sys`) | x86-64 | [`wdm-x64-scheduled-v101`](driver-emulation.md) | `DriverEntry` |

PE32+ DLL 入力は `IMAGE_FILE_DLL` で識別します。モデル化されたゲスト EXE が `LoadLibraryA`、`FreeLibrary` を呼び出し、通常の依存関係、TLS、`DllMain` のライフサイクルを使います。DLL の既定入口はプロセスアタッチ呼び出しです。任意のエクスポートの引数は推測しません。名前、序数、別名、データ、転送エクスポートを保持し、自身のエクスポートへのポインターは自己インポートに変換しません。ヘルパーが返すアドレスにも同じ規則を適用します。内部アドレスが返された場合、その位置で以前に得たインポート修復の証拠を撤回します。

## Windows x64 ドライバー

`NEVERD_ENABLE_DRIVER_EMULATION=ON` では、native サブシステムの x64 PE（`.sys`）をドライバー環境で実行します。入口の根拠は `DriverEntry` であり、ディスパッチやアンロードのコールバックは既定の復元入口になりません。任意の `driver` オブジェクトは、サービス名、レジストリ、要求、スケジューリングを含む[ドライバーシナリオ](driver-emulation.md)を受け付けます。共通のバックエンド、実行契約、資源制限が適用され、ユーザープロセスの引数、環境、PEB 入力は拒否されます。

ドライバー UNPACK は書き込みごとのレポート保存を無効にし、メモリ検証と復元用の監視を維持します。イベント予算は API 呼び出しを数え、命令数と時間の制限も適用されます。

復元では入口引数、戻り先とシャドウ領域、非揮発レジスター、方向フラグ、浮動小数点制御、カーネルオブジェクトの所有権を確認します。残存プール、借用カーネルポインター、変更済みローダーオブジェクト、未計上のカーネル作用は `unsupported_state` となり、明示的な `snapshot_only` は診断を保持します。カーネル状態の `restore_runtime` は未実装です。カーネルのエクスポート識別情報でインポートを再構築し、元のエクスポートを検証して PE チェックサムを再計算します。固定ベースの出力は Windows カーネルへのロード、署名の有効性、未実行経路の動作を保証しません。

`backend: "unicorn"` と `execution_contract: "driver-strict"` を指定すると、x64 ドライバー復元では停止状態の命令デコードと、物理エイリアスを横断する確定済み RAM 書き込み監視を使用します。この契約は Unicorn の命令セマンティクスを使用し、`checked-x64-v1` は実行前の命令許可検査を提供します。

ローダー所有の画像ページに対する一時 MDL は、すべての別名の解除、すべてのロック解除、すべての記述子の解放が完了すると、追加の復元依存性を残しません。この契約では指定アドレスのないカーネルモードのキャッシュ付き別名を許可します。存続する MDL、他の所有権やマッピング形式、ゲストによる物理 PFN 識別値の読み取りは依存性として残り、モデル化されたコピー・移動・比較サービスによる読み取りも含みます。

`KeQueryPerformanceCounter`、`RDTSC`、`RDTSCP` によるクロック読み取りは、ドライバー復元の明示的な依存関係を保持します。取得したカウンター値と周波数を新しいカーネル環境に再対応付けする契約はありません。既定の復元は `unsupported_state` を返し、`snapshot_only` は診断を保持します。

```bash
neverd unpack packed.sys -o unpacked.sys --options='{"backend":"kvm","driver":{"service_name":"Example"}}'
```

## 使い方

```bash
neverd unpack packed.exe -o unpacked.exe
neverd unpack packed.exe -o unpacked.exe \
  --options='{"backend":"unicorn","instruction_limit":400000000,"transfer":2}'
```

コマンドは JSON レポートを 1 つ出力します。終了コード 0 は `unpacked` イメージまたは明示的に要求した `snapshot` / `restored` の書き出し、3 は `no_entry` または `unsupported_state`（出力ファイルを作成・切り詰めしない）、1 は入力・オプションの不正または準備の失敗を表します。レポートには、実際に実行された `format`、`architecture`、`profile` が記載されます。C のエントリポイントは `neverd_unpack_json`、Python では `Session.unpack` です。オプションは[プロセスオプション](process-emulation.md)に `transfer` と `snapshot_only` / `restore_runtime` を加えたものです。スタブがより多くの資源を必要とする項目では既定値が異なります。100000000 命令、600 秒、512 MiB で、`windows.defer_unmodeled` は有効です。

## 明示的な実行時状態の復元

`restore_runtime:true` は自己完結する Windows x64 初期化コードを生成し、`restored` と終了コード 0 を返します。`snapshot_only` とは排他的です。`PATH` に Clang と `lld-link` が必要で、`windows.peb_version` で対象のネイティブ環境を明示します。初期化コードは PEB を変更せずバージョンを検査し、所有権のあるヒープ領域、ポインターの符号化操作、FLS 値とコールバック、再帰クリティカルセクション、プライベート仮想メモリの予約とページ保護、`LastError` を復元します。エクスポートのゲートは観測した呼び出し形式を保持します。コード、データ、メタデータはそれぞれの権限を持つ `.nd*` セクションに入り、補助 DLL は生成しません。

前述の拒否規則は既定の復元に適用されます。この明示的モードは捕獲時の `runtime_state` 診断を残し、新しいプロセスでのインポート探索を省きます。固定アドレス、選択した DLL 転送、捕獲した引数と環境が引き続き必要です。過去の直接システム呼び出し数は保持しますが、その番号や未到達経路の移植性は認証しません。動的 TLS、開いたハンドル、マップされたセクション、中断中の例外状態、他のゲスト DLL の状態は未対応です。未対応状態や初期化コードの構築失敗では出力しません。`restored` はこの条件での構築を意味し、全ネイティブ経路の正しさの証明ではありません。

## 実行時状態と解析用スナップショット

転送の受理時に、プロセスプロファイルは生存中のヒープ割り当て一覧を提供します。回復処理は、捕捉したイメージと現在のスレッドの TLS バイト内の全ポインタ幅の値を保守的に走査し、非整列の値や割り当て内部のアドレスも調べます。一致は整数や未使用データかもしれず、型付きポインタや再配置の根拠ではありません。一覧の出所が不明、または参照の可能性がある場合、受理済みの `entry` があっても既定では `unsupported_state` となります。CLI と C API は出力を作成・切り詰めしません。

`runtime_state.heap_inventory_known` は既知の空一覧と出所不明を区別します。`possible_heap_references` は全一致数、`heap_references` は最大で最初の 64 件です。イメージ、TLS の順で、各々 `offset` 順に記録します。各記録には `storage`（`image` または `thread_local`）、アドレスと割り当て範囲があります。`rva` はイメージでは十六進値、TLS では null です。アドレスとオフセットは十六進文字列です。

`runtime_state.direct_service_calls` は入口観測とインポート探索中に実行された直接モデルサービス呼び出しを数えます。ネイティブ Windows 用の番号束縛を復元していないため、取得した入口の後で初めて実行される場合も `unsupported_state` を返します。明示的な `snapshot_only` は件数と診断を保持します。コピーされたシステムコールは修復可能なインポート関数呼び出しとは扱いません。 `no_entry` のレポートでもこの件数は保持されます。入口を取得できなかった場合、ヒープ一覧は不明のままです。

`runtime_state.encoded_pointer_inventory_known` は、プロセスプロファイルが観測済みのポインター符号化値を提供するかを示します。`possible_encoded_pointers` は、取得したイメージとメインスレッド TLS 内のポインター幅の完全一致を、非整列の格納も含めて数えます。`encoded_pointer_references` は最初の 64 件の `storage`、`offset`、`rva`、`value` を保持します。Windows は完了した `EncodePointer`/`RtlEncodePointer` の戻り値と `DecodePointer`/`RtlDecodePointer` の入力を提供します。一覧が不明または一致があれば `unsupported_state` となり、明示的なスナップショットも診断を保持します。一致は整数や未使用データの場合もあり、再符号化の根拠にはなりません。取得前に消去された値や取得後に初めて生成した符号化はこの拒否を起こしません。独自符号化、部分値や変換済みの値、レジスター、スタック状態、未到達経路は対象外です。

`runtime_state.dynamic_thread_local_inventory_known` は取得時の動的スレッド／ファイバー局所スロット状態をプロファイルが提供するかを示します。`live_dynamic_tls_slots` と `live_dynamic_fls_slots` は PE 静的 TLS とは別の件数です。割り当て済みスロットは値がゼロでも数え、割り当て記録のない非ゼロ TLS セルも数えます。一覧が不明、または状態が残る場合は `unsupported_state` となり、明示的スナップショットにも件数と診断を保持します。取得前に解放されたスロット、ゼロに戻した未割り当て TLS セル、取得後に初めて作成された状態はこの拒否を起こしません。件数は所有権、値、コールバックを再構築せず、他のスレッドやファイバーの状態を保証しません。

現在のファイバーでは、`FlsFree` は非ゼロのスロット値を先にゼロにし、ゲスト ABI で登録済みコールバックを呼び出します。コールバックが別の非ゼロ値を書き込むと、その値で処理を繰り返し、完了後にインデックスを解放します。モデル化済み API の呼び出しや別スロットの解放は可能ですが、処理中の同一スロットの再帰的な解放は `unsupported_service` で停止します。入口の正常な復帰と `ExitProcess` は DLL／TLS のプロセス切り離し通知の前に残りのコールバックを実行します。終了処理では開始時点の過去の割り当て上限を固定します。その範囲内の未走査インデックスは初期化や再利用が可能ですが、それを超える新規割り当ては走査範囲を拡張しません。終了コールバックは元の値を読み取れます。完了時に書き込みをクリアし、インデックスの割り当ては保持します。すべてのコールバックはプロセスの実行予算を共有します。終了処理中のローダー操作は引き続き明示的に非対応です。

`--options='{"snapshot_only":true}'` は解析用バイトを明示的に要求します。入口が受理され再構築に成功すると結果は常に `snapshot` で、実行時状態の診断は残ります。ヒープの復元、再配置の推定、ネイティブ実行の保証、仮想化解除は行いません。参照数ゼロも他の OS 状態や未実行経路を保証しません。

## エントリの確定方法

世代ゼロはゲストローダーが入力をマップした時点のイメージです。転送は新しいコードの実行開始です。`transfers` は RVA、`generation`、スタック一致（`stack_balanced`）、入力の入口呼び出しへの帰属（`program_invocation`）を記録します。DLL ではプロセスアタッチを指します。その呼び出し前は最初の初期化処理のスタックを基準にします。

1. 既定の入口には `stack_balanced` と `program_invocation` の両方が必要です。スタブが入力入口呼び出しのスタックを返したことを示し、`entry_source` は `transfer` です。
2. OS 所有の TLS コールバック、依存 DLL の入口、デタッチ呼び出しは、スタックが一致しても既定入口にはなりません。深いゲスト呼び出しは続行します。コールバックを省略せず、スタブ署名から入口を予測しません。
3. `transfer` は初期化コールバックや段階的な転送も含め、一覧の位置で明示的に選択します。初期化コールバックを選択した場合も、現在のスレッドの TLS と、それ以前に完了した初期化の記録を取得します。

コンパイラのスタートアップコードの形からエントリを推測することはありません。先に実行が停止した場合は、`no_entry` とプロセスの `stop_reason` が報告されます。

一度実行した 4 KiB ページも監視対象から永久には除外しません。コミット済みのゲスト RAM 書き込みは物理エイリアスを通じて訪問済みページの記録を無効化し、プロセスモデルは OS サービス後の再開前にもページを再検査します。転送の証拠は CPU デコーダーが示す実際の命令範囲だけを比較するため、隣接データの変更だけでは入口になりません。新旧コードの混在や再書き込み、同一ページの古いスタブへ戻るコールバックも監視を維持します。

## 再構築されたイメージ

セクションは RVA、観測したメモリ（実行済み初期化の効果を含む）とページ権限を保持します。追加の `.neverd` セクションにインポートディレクトリと、エクスポート呼び出しとアドレス読み込みの修復用の新しい IAT セルを置き、元のゼロ領域を保ちます。`imports` の `origin` は入力から束縛された `static` と、ゲストが書いた、または修復で追加した `runtime` を区別します。生成内容の再配置は観測していないため、観測ベースに固定し、再配置ディレクトリを削除して `IMAGE_FILE_RELOCS_STRIPPED` を設定します。

ユーザーモードのセクション範囲は `VirtualSize`（ゼロなら `SizeOfRawData`）をゲストページ単位に切り上げます。`SectionAlignment` は RVA の配置だけを決めます。最後の有効ページ内のファイル末尾データは保持し、範囲外のバイトはマップしません。再構築では `FileAlignment` を維持し、セクション間の隙間から読み取らず、ファイルのパディングをゼロで埋めます。この規則のネイティブ検証は x64 Windows DLL のみです。実行時の受け入れ、メタデータ読み取り、固定イメージ検証は、ページに丸める前の論理範囲を共有します。ゼロの `VirtualSize` には `SizeOfRawData` を使い、非ゼロ値は引き続きメタデータの上限になります。ローダーは LLVM 互換性のために専用の読み取りビューを使い、実行、デバッグ識別情報、バイト検証には元のデータを保持します。ドライバーマッピングはユーザーモードのページ規則の対象外です。

デバッグデータのファイルオフセットを書き換えるには、デバッグディレクトリと保持する各データ領域の全体がファイル内に存在する必要があります。`AddressOfRawData == 0` でデータ全体が保持するオーバーレイ内にある場合、オーバーレイの新しいファイル位置からの相対オフセットを維持します。無効な非ゼロ RVA をオーバーレイへの参照として扱うことはありません。

書き込み可能なインポートセルにはネイティブ IAT の保護範囲は不要ですが、各セルは引き続きインポート記述子によってバインドされます。読み取り専用セルには、読み取り専用かつ実行不可のセクションからなる連続した範囲が必要です。書き込み可能または実行可能なセクションをまたぐ範囲は、メモリ保護を変更せず明示的に失敗します。

既存の実行時 IAT 候補には、同じ提供モジュールの連続したエクスポートポインター配列と、元のセクション内の完全なゼロ終端が必要です。隣の提供モジュールの終端は使用できません。

ローダーの割り当て識別情報と一致する元の TLS ディレクトリでは、コールバック配列が存在しない場合や空の場合も認めます。完全に検証された元のディレクトリは、コールバック実行の証拠がなくても保持できます。取得した TLS は引き続き検証し、必要に応じて復元しますが、未完了のコールバックを完了済みとは数えません。走査で見つけた代替レコードには、完全なゼロ終端コールバック表と実際のコールバック実行の証拠が引き続き必要です。候補が複数なら明示的に失敗します。プロテクター固有の名前やバイト列は使いません。ディレクトリ選択では、生成されたコールバックの実行証拠を、完了したローダー初期化処理より優先します。 プログラムが完了済みのローダー初期化コールバックを再度呼び出しても、そのコールバックが書き換えられている場合を含め、補助的な証拠として扱います。代替ディレクトリを復元できず、元の TLS ディレクトリも無効な場合は、`unpacked` を返さず明示的に失敗します。

`materialized_tls_callbacks` はキャプチャ前に正常に戻った入力イメージの TLS プロセスアタッチコールバックを数えます。完了には OS の呼び出し記録、または引数 `(image_base, 1, 0)` による生成コードへの入口と、その ABI 戻り先および戻りスタックポインターの復元を観測した証拠が必要です。メモリへの効果は既にスナップショットに含まれます。新しい `.neverd` セクションのアダプターは、その重複するプロセス接続呼び出しだけを省き、他の通知では元のコールバックへ末尾呼び出しします。ディレクトリ、コールバック表、アダプターには新しい領域を使い、元のバイト列を保ちます。アダプターがある場合は実行可能で、新しい IAT セルが必要な場合だけ書き込み可能です。完了証拠のないゲスト内部のコールバックは変更しません。プロセス接続時、取得済みのメインスレッド TLS がテンプレートと異なる場合は、完了したコールバックがゼロでもアダプターがそのデータを独立して復元します。実行中の TLS の証拠が欠けるかサイズが合わない場合は明示的に失敗します。元のテンプレートは後続スレッド用に保ち、他の通知では取得済みブロックを復元しません。

遅延ロードでは、先行する初期化処理がコードを生成するゼロ埋めメモリを、実行可能なコールバックや入口の対象にできます。コールバック配列と TLS 割り当てメタデータには検証済みのファイル内容が必要で、通常の厳格ロードはファイル裏付け検査を維持します。OS モデルは呼び出しの帰属を示し、呼び出しの準備時や中断した呼び出し元の復元時に観察器へ通知します。これらの境界で転送監視を再設定し、コールバックと生成された入口が同じページにある場合も扱います。

`import_repair` は入口取得後の追加の有限実行 2 回を扱います。まずエクスポート呼び出しを発見し、次に補助ルーチンの状態を観測します。各回に独立したプロセス上限を適用します。命令数とイベント数は飽和加算し、`stop_reason` と診断は最後の実行、呼び出し数は発見段階だけを示します。継続アドレスがなければ状態観測を省略します。エクスポートの同一性が競合する箇所は変更しません。対象は到達経路だけで、`unpacked` は全インポートや実行成功を保証しません。

インポートのバインド順序によってエクスポートアドレスは変わり得ます。修復は証明時の識別情報を保持し、エントリ後に解決されるエクスポートも監視します。別の実行のアドレスは書き換えの根拠になりません。

発見段階はモデル化呼び出しログだけでなく、停止を起こす未モデル化エクスポートを含むディスパッチを観測します。ABI 戻り位置が読めなければ補助ルーチンの証拠に使えません。不透明エクスポートへの純粋な呼び出しを復元しても、未対応サービスによる明示的停止を維持します。

実際のエクスポート呼び出しの継続位置より前の 256 バイトから最大 256 個の開始候補を観測します。GPR PUSH/POP を前置できる `CALL rel32` は観測境界だけを示し、CALL 後のバイトを署名には使いません。6～8 バイトの呼び出し領域を `call [rip+IAT]` に変えるには、API 入口で戻りアドレスが 1 個だけ積まれ、他のレジスタ（フラグと SIMD を含む）、マッピング、永続 RAM が不変で、途中に OS 呼び出しがないことが必要です。先頭の NOP で API の正確な戻りアドレスを維持します。7～8 バイトの領域が単一 GPR に既知のエクスポートを返し、スタックと同じ保存条件を満たせば `mov r64, [rip+IAT]` にできます。結果レジスタは状態比較で決め、RSP 以外の全 GPR（R8-R15 を含む）を認めます。8 バイト領域には末尾 NOP を残します。除外するのは呼び出し元 SP より下の一時領域だけで、呼び出し元スタックは比較します。後の副作用、未解決、未完了の呼び出しは先の証拠を無効にします。実行開始位置の証拠が必要で、直前バイトを REX とみなしたり、戻り位置を共有する重複開始を認めたりしません。競合する継続位置が拒否された後も、その検証済み領域はすべて重なり合う修復を阻止し、証拠の順序には依存しません。`observed_loads` と `repaired_loads` はアドレス読み込みを別に数えます。

`ImportObserver` は途中の実行停止でも外側のスナップショットを一つ保持します。内側の候補には独立したスナップショットがないため、その候補の以前の証拠を取り消します。外側の呼び出しにもレジスタ、マッピング、永続メモリ、OS 呼び出しの完全な比較が必要です。再帰、中断、未完了の呼び出しは証拠を取り消します。`ProcessImportsTests.cpp` と独立してリンクした DLL フィクスチャがこれらの境界を検証します。 内側の停止をまたいでスナップショットを保持するのは、観測済みのエクスポート継続位置を持つ候補だけです。

元のセクションテーブル、インポートディレクトリの配置、再配置テーブルは再構築されません。パッカーはそれらをメモリ上に復元しないためです。

## 識別

互換フィールド `packer.kind` と `packer.evidence` は `unidentified` と空配列を返します。プロテクター登録、圧縮ヘッダー解析、スタブ署名は削除しました。従来の識別 API はコンテナだけを検証します。

## 制限

検査付き実行は命令単位です。x64 Unicorn/KVM/WHP は時間とイベントで制限する `direct-user-x64-v1` に対応し、命令数を計測しません。世代の混在と繰り返しの書き込みでは追加のプロセッサステップが必要になる場合があります。復元対象は入力イメージで到達した経路であり、その外部に生成されたコードを入口にはしません。入口前の初期化が作る外部状態は移植できない場合があり、TLS コールバックの再実行にも副作用があります。未モデル化 API は明示的に停止します。修復は検証済みの 6～8 バイト x64 呼び出し領域と 7～8 バイトアドレス読み込みを扱い、他形式と未到達経路は未解決です。仮想化コードはそのままです。

RVA 形式の遅延インポートは未解決のイメージ内サンクを保持し、観測済みのエクスポート識別情報で解決済みセルを再バインドします。これによりプログラムのヘルパーが完了済みの処理を繰り返しません。独立した終端付きルックアップ表がバインド数を制限し、後続の未解決 IAT セルを保持します。再構築はプロセス固有の DLL ハンドルとバインドキャッシュ参照を消去し、遅延インポートのメタデータを通常の IAT 検出から除外します。記述子とポインター配列の終端、名前、範囲、格納領域の所有者を検証します。不明なターゲット、不正なサンク、旧式 VA 記述子、領域の競合は明示的なエラーになります。

## 検証

`NeverDUnpackTests` はコンテナ、安全な IAT 割り当て、競合と TLS 拒否を検証します。`NeverDUnpackExecutionTests` は Unicorn/KVM/WHP の共通経路で UPX NRV2B/NRV2D/NRV2E/LZMA と CRT を検証し、独立にリンクしたプログラム自身の初期化後のセクションと比較して、利用可能なバックエンドの出力一致を要求します。`UnpackGeneratedTests.cpp` は x86-64/ARM64 の独立プログラムを生成し、転送、段階的ロード、インポート修復、x64 Unicorn/KVM/WHP 直接実行を検証します。ネイティブ CI の必須ケースはスキップできません。`NeverDUnpackPublicTests` は C ABI と CLI を検証します。`unittests/unpack/fixtures/Makefile` で UPX 検体を再生成できます。ネイティブ KVM/WHP CI の一覧（`NativeCPUTests.def`）では、主要な PE、TLS、インポート、転送の単体テストも必須です。CPU とドライバーのエミュレーションを両方無効にしても、形式のみの単体テストは利用できます。


`UnpackLibraryTests.cpp` は独立した x64/ARM64 DLL をテスト内でパックし、依存順序、通常・生成 TLS コールバック、アタッチ失敗の後処理、入力とホストの識別、自身のファイルアクセス、名前・序数・データ・転送エクスポート、自己インポートの不在を確認します。ネイティブ Windows は別 EXE で元の DLL と再構築 DLL をロードし、宣言済みエクスポートを呼びます。検査付き・直接 WHP ケースは必須です。`CompletedGeneratedTLSCallsRequireTheAttachABI` は入口・引数の変更を拒否し、`GeneratedCallsNeedTheirReturnedStackAtTheContinuation` は誤った戻りスタックを拒否します。対象はアンパックであり、仮想化解除ではありません。

`ExportObserver` は常駐ゲスト依存モジュールの実行可能エクスポートも監視します。モデル化プロバイダーはサービス分配で観測し、入力自身のエクスポートは除外します。モジュール変更で監視を更新し、修復には現在のエクスポート識別を必要とします。記録数は宣言済みインポート上限以内です。DLL テストはシステム API とゲスト依存関数の両ヘルパーを修復し、ネイティブロードでエミュレートされたアドレスが残らないことを検証します。


`WrappedEntriesRequireExplicitTransferEvidence` は DLL ラッパーが深いスタックで復元入口を呼ぶ場合を扱います。既定は `no_entry` のままです。観測済み呼び出しを `transfer` で選ぶとロード可能な DLL を再構築できます。深い呼び出しだけでは入口と初期化処理を区別できません。

復元した DLL 入口が元の PE 入口と異なる場合、ライターはローダー通知アダプターを生成します。プロセスのアタッチは選択した入口へ、デタッチとスレッド通知は元の実行可能な入口へ送られ、外側のラッパーによる後始末を保持します。元の入口が利用できなければ再構築は失敗します。報告の `entry_rva` は選択した入口を示し、PE ヘッダーはアダプターを指す場合があります。独立した DLL テストで、両エミュレーションアーキテクチャとネイティブ Windows の後始末を検証します。

`runtime_state.additional_state_inventory_known` と `has_additional_dependencies` は OS 所有者に残るプライベートヒープ、仮想予約、ロック、ハンドル、ビュー、例外状態を報告します。情報欠落や資源の残存は、ヒープポインター一致がなくても既定の復元を拒否します。明示的スナップショットは診断を保持し、実行時復元は対応する所有者を再構築します。
